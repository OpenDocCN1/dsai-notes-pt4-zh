
# Tool use：有效地利用外部工具

“`tool use`”（工具使用）是 AI **Agent 工作流**中的另一个关键设计模式，这个模式主要关注 AI Agent 如何有效地利用外部工具来增强其执行任务的能力。这可能包括使用计算器来执行精确的数学运算、搜索引擎来获取信息、或者调用`API`来实现特定的功能。这种设计模式超越了传统的仅依赖预训练变换器（`transformer`）生成输出的方式，通过赋予`LLM`额外的工具和能力，使其能够执行更复杂的任务和提供更丰富的输出。

在实际应用中，"tool use"可以体现在以下几个方面：

+   **网络搜索**：AI Agent可以通过执行网络搜索来获取关于特定主题的信息，例如，根据用户询问“根据评论者的评价，哪款咖啡机最好？”，AI Agent可能会调用搜索引擎并分析下载的网页内容来提供答案。

+   **代码执行**：AI Agent可以执行代码来完成计算任务，例如，在回答“如果我以7%的复利投资100美元，12年后我会得到多少钱？”时，AI Agent可以运行一个Python命令来计算最终金额。

+   **多源信息检索**：AI Agent可以使用不同的工具来从多个来源（如互联网、维基百科、arXiv等）检索信息，以及与生产力工具（如发送电子邮件、读写日历条目等）进行交互。

+   **图像处理**：AI Agent可以生成或解释图像，这通常涉及到调用图像处理API或其他视觉工具。

+   **自动选择功能**：AI Agent可以根据给定的上下文自动选择正确的功能来执行任务。这可能涉及到对功能的详细描述和期望参数的理解。

+   **大规模工具集成**：在某些系统中，AI Agent可以访问数百种工具。在这种情况下，可能会使用启发式方法来选择在当前处理步骤中最相关的功能子集。

## 实际示例：咖啡机推荐

基于上述内容，我们可以举一个实际的例子来说明"tool use"在AI Agent中的应用：

> 假设你正在使用一个基于大型语言模型（`LLM`）的在线聊天系统，你向这个系统提出了一个问题：“根据评论者的评价，哪款咖啡机最好？”在这个场景中，AI Agent会采取以下步骤来使用工具来回答问题：

1.  **理解请求**：AI Agent首先理解用户的问题是关于咖啡机的评论和评价。

1.  **决定使用工具**：AI Agent识别到为了回答这个问题，它需要访问最新的用户评论和评分，这超出了其预训练知识的范围。因此，它决定使用网络搜索工具来获取相关信息。

1.  **生成搜索请求**：AI Agent被训练或提示生成一个特殊的字符串，例如`{tool: web-search, query: "coffee maker reviews"}`。这个字符串是一个指令，告诉系统执行一个网络搜索，并使用查询字符串“coffee maker reviews”。

1.  **执行搜索**：后处理步骤会寻找类似上述的特殊字符串。当找到这样的字符串时，系统会调用网络搜索功能，并使用相关的参数（在这个例子中是查询字符串）来执行搜索。

1.  **获取并处理结果**：搜索功能返回的结果会被传递回AI Agent，作为额外的输入上下文。然后，AI Agent可以进一步处理这些信息，比如提取最受欢迎和评分最高的咖啡机型号。

1.  **生成回答**：基于搜索结果，AI Agent生成一个回答，告诉用户根据评论者的评价，哪款咖啡机最受欢迎。

通过这种方式，"tool use"使得AI代理能够超越其预训练知识的限制，利用外部工具来提供更准确、更丰富的信息和回答。

## 相关论文

以下是三篇与"Tool use（执行）"相关的论文，它们探讨了AI Agent如何通过使用工具来提高其性能和效率：

### Gorilla

《[Gorilla: Large Language Model Connected with Massive APIs](https://arxiv.org/pdf/2305.15334.pdf）》：这篇论文介绍了`Gorilla`，这是一个基于`LLaMA`模型的AI Agent，它通过与大量`API`的连接来提高其在编写`API`调用方面的表现。当结合文档检索器时，`Gorilla`展示了适应测试时文档变更的强大能力，允许灵活的用户更新或版本变更，并显著减少了直接提示`LLM`时常见的幻觉问题。

![](img/fecabfd7f10fd33947d3c71d5d8a29e7.png)

论文中提出的方法通过以下几个关键步骤，利用自我指令微调（self-instruct fine-tuning）和检索机制来提升大型语言模型（`LLMs`）在处理庞大且重叠的`API`工具集时的准确性和适应性：

1.  **自我指令微调**：

    +   利用`GPT-4`等预训练模型生成合成指令数据，这些数据包括`API`调用的上下文示例和参考文档。

    +   通过提供具体的`API`使用场景和相应的代码实现，训练模型理解`API`的功能和正确的调用方式。

    +   特别强调在生成指令时不使用具体的`API`名称或提示，以促使模型学习从自然语言描述中识别任务并生成准确的`API`调用。

2.  **构建`APIBench`数据集**：

    +   从`TorchHub`、`TensorHub`和`HuggingFace`等公共模型中心抓取机器学习`API`（模型），构建一个包含复杂且经常重叠功能的`API`的大型数据集。

    +   使用自我指令方法生成的指令-`API`对作为数据集中的条目，每个`API`条目都关联一个或多个可能的用户指令。

3.  **检索机制的整合**：

    +   在`Gorilla`模型的训练过程中，将检索系统整合到模型的推理流程中。

    +   通过检索最相关的`API`文档，模型学会了在生成`API`调用时参考最新的文档信息。

    +   这种检索器aware的训练方法使得`Gorilla`能够适应`API`文档的更新和变化，从而保持其输出的准确性和适用性。

4.  `AST`树匹配技术：

    +   采用抽象语法树（`AST`）子树匹配技术来评估生成的`API`调用的功能正确性。

    +   通过比较生成的代码的`AST`树与数据集中`API`调用的`AST`树，验证模型生成的`API`调用是否正确。

### MM-REACT

《[MM-REACT: Prompting ChatGPT for Multimodal Reasoning and Action](https://arxiv.org/pdf/2303.11381.pdf）》：这篇文章提出了`MM-REACT`系统，它通过将`ChatGPT`与一系列视觉专家整合，实现了多模态推理和行动。`MM-REACT`通过设计文本提示来表示文本描述、文本化的 spatial coordinates 和对齐的文件名，使得语言模型能够接受、关联和处理多模态信息。

![](img/68f94f9a34dab178a61e5ff11d26c8e9.png)

`MM-REACT`系统通过结合多模态推理和行动来解决复杂的视觉理解问题，主要依靠以下几个关键组件和流程：

+   **视觉专家和语言模型的组合**：`MM-REACT`将各种视觉专家（如图像标注、`OCR`、名人识别、对象检测模型等）与大型语言模型（如`ChatGPT`）结合起来，使得语言模型能够调用特定的视觉专家来处理图像或视频内容。

+   **文件路径作为输入**：`MM-REACT`使用文件路径作为非文本输入（如图像和视频）的表示。文件路径本身是无效的，它起到一个占位符的作用，允许语言模型将其视为一个黑盒。

+   **指令和上下文示例**：为了将视觉专家的使用知识注入到语言模型中，`MM-REACT`在提示语言模型时添加了关于每个专家的能力、输入参数类型和输出类型的说明，以及每个专家的几个上下文示例。

+   **正则表达式匹配**：`MM-REACT`使用正则表达式匹配来解析专家名称和文件路径，以调用相应的视觉专家。

+   **多轮对话系统**：`MM-REACT`是一个多轮对话系统，可以整合强大的问答模型作为其视觉专家之一。语言模型可以生成推理文本和操作文本，以分解复杂问题并为解决这些步骤分配`NLP`工具。

+   **输出标准化**：视觉专家的输出被标准化为文本格式，以便语言模型可以理解。例如，对象检测模型的输出是一个对象名称与边界框坐标的列表，这些坐标被连接起来并附加一个文本描述来解释最后四个数字的含义。

`MM-REACT`系统实现图片识别的流程：

+   **用户输入图片**：用户通过提供图片的文件路径来输入非文本信息。对于`ChatGPT`来说，文件路径相当于一个占位符，它本身并不包含视觉内容，而是指向视觉内容的标识。

+   **`ChatGPT`响应**：`ChatGPT`根据用户输入的文件路径，生成一个包含特定关键词的行动请求文本来请求视觉专家的帮助。这个行动请求文本是一个特殊的提示词，用于明确告诉`ChatGPT`需要调用的视觉专家类型。

+   **特殊提示词**：特殊提示词，如“Assistant, what objects do you see in this image? ”，其中“”是用户输入的图片路径。这个提示词通过正则表达式匹配来触发相应的视觉专家模型。

+   **调用视觉专家**：根据`ChatGPT`生成的行动请求文本，系统解析出需要调用的视觉专家类型和相应的文件路径，然后执行对应的视觉专家模型来处理图片。

+   **视觉专家处理**：视觉专家模型根据其专长对图片进行分析，例如图像描述、对象检测、名人识别等，并生成相应的文本输出。

+   **输出结果**：视觉专家的文本输出被反馈给`ChatGPT`，`ChatGPT`结合这些信息继续与用户进行对话，提供问题的答案或执行进一步的行动。

### Chain-of-Abstraction (CoA)

《[Efficient Tool Use with Chain-of-Abstraction Reasoning](https://arxiv.org/pdf/2401.17464.pdf）》：这篇文章提出了一种新的方法，即`Chain-of-Abstraction`（`CoA`），训练`LLMs`首先解码带有抽象占位符的推理链，然后再调用领域工具来实现每个推理链的具体知识。

这种方法将`LLM`（大型的语言模型）的一般推理与从外部工具获得的特定领域的知识进行解耦。

具体步骤：

1）用抽象占位符（如`y1`、`y2`、`y3`等）微调`LLM`生成推理链；

2）用特定领域的知识（如计算器结果，网络搜索相关文章等）替换占位符以具体化推理链；

3）基于具体化的推理链回答问题。

![](img/b5614894b270dc3a756d1460757dd997.png)

这种方法的优势在于，它鼓励`LLM`学习如何规划抽象的多步推理，这些推理对分布外知识的变动更具弹性。此外，由于`LLM`的推理链生成与工具的使用（即知识检索）是解耦的，因此在生成整个推理链后一次性使用工具，这样可以并行地生成多个推理链和调用工具，从而提高了多步推理的效率。

作者在数学推理和维基百科`QA`两个代表性领域对微调后的模型进行了评估，结果表明，与基线方法相比，`CoA`方法在准确性和推理效率上都取得了显著改进。

大型语言模型（`LLMs`）如`ChatGPT`可以通过`Chain-of-Abstraction`（`CoA`）方法更高效和准确地进行多步推理。然而，`CoA` 方法并不是直接应用于用户输入的问题，而是在模型训练阶段使用。在训练过程中，`CoA`方法利用以下步骤来提升模型的性能：

1.  **生成抽象推理链**：首先，模型被训练生成包含抽象占位符的推理链。这些占位符代表了需要通过外部工具获取的具体信息。

1.  **调用领域工具**：随后，模型会调用相应的领域工具来填充这些占位符，具体化推理链，并得出最终答案。

1.  **训练与优化**：通过这种方式，`LLMs`学习如何构建有效的推理策略，同时适应领域知识的变动，并提高工具使用的效率。

当用户输入一个问题时，训练有素的`ChatGPT`或其他`LLMs`会根据其训练期间学到的知识和推理策略来生成答案。`CoA`方法在训练阶段为模型提供了一种结构化的方式来理解和解决问题，但这并不意味着在实际应用中不需要任何提示或上下文。

实际上，为了使`ChatGPT`能够有效地处理用户的输入，通常需要提供一些上下文或提示词来引导模型正确地理解问题并生成相关的回答。这些提示词可能包括问题的类型、相关的领域知识、预期的答案格式等。`CoA`方法在训练阶段为模型提供了这种结构化提示，帮助模型学习如何构建推理链并有效地使用工具。

简而言之，`CoA`方法是一种训练技巧，用于提升`LLMs`在多步推理任务中的表现，而不是直接应用于用户输入的处理。在实际应用中，仍然需要适当地引导模型，以便它能够准确地回应用户的查询。

这些论文共同探讨了AI Agent如何通过工具使用来增强其执行任务的能力。具体来说，它们究了如何设计和训练AI系统以便它们能够调用外部`API`、使用搜索引擎、执行多模态推理以及与其他代理协作。这些研究展示了通过工具使用，AI Agent可以更有效地解决问题、提高任务执行的准确性，并在多步骤推理任务中表现出更好的性能。
