
| `Qwen-VL` / `Qwen3-VL` | 文本、图片、图表、文档 | 极强 | ✅ | 中文图文理解、表格语义、RAG集成 | 不支持视频、英文弱 |

| `DeepSeek-OCR` / `VL` | 图片→文本（OCR特化） | 强 | ✅ | OCR精度高、结构化输出快 | 仅限文档类，通用视觉差 |

| `InternVL2` | 文本、图片、表格 | 强 | ✅ | 中文问答、国产生态、开放源码 | 模型稍慢、视频支持弱 |

| `LLaVA-Next` / `MiniGPT-4` | 文本、图片 | 一般 | ✅ | 框架清晰、易微调 | 中文弱、文档结构理解差 |

| `Yi-VL` | 文本、图片 | 强 | ✅ | 中文语言流畅、稳定 | 生态未成熟、训练资源少 |

## 按场景选模型

| 企业场景 | 推荐模型 | 主要优势 | 为什么选择它 | 不适合用谁 |

| --- | --- | --- | --- | --- |

| 票据、发票、回单类 OCR | `DeepSeek-OCR` + 轻量 `LLM` 后处理 | 识别速度快、版面适配广、结构输出稳定 | 专注OCR领域，吞吐大；可接`LLM`转结构化 | `GPT-4V`、`LLaVA`（识别慢、结构不稳） |

| 财务/经营报表识别 | `DeepSeek-OCR`（上游）+ `Qwen-VL`（下游） | 精准提取字段并理解语义 | `DeepSeek`读得准、`Qwen`理解字段关系强 | `LLaVA`、`InternVL`（对中文表格语义弱） |

| 合同/规章/说明书抽取 | `Qwen-VL` 或 `InternVL2` | 中文长文档问答好、能识别结构 | 支持分页理解与跨页问答，可微调私有化 | `GPT-4V`（贵且不可控）、`LLaVA`（对中文长文档弱） |

| 图表理解/ChartQA | `Qwen-VL` / `UniChart` / `LLaVA-Next` | 图表结构解析、数值计算能力强 | 支持图表OCR+语义推理；`Qwen`对中文图表特化 | `DeepSeek-OCR`（仅识别不理解） |

| 图像问答/客服识图 | `LLaVA-Next` / `Yi-VL` | 轻量、响应快、支持图像语义问答 | 适合嵌入式或在线客服应用 | `DeepSeek-OCR`（过重） |

| 文档/报告问答（`RAG`类） | `Qwen-VL` + 向量库（`Milvus`/`Faiss`） | 可读PDF+理解内容并回答 | 可本地化，中文表现稳定 | `GPT-4V`（成本高）、`LLaVA`（长文档弱） |

| 视频摘要/会议纪要 | `Gemini 1.5 Pro` / `GPT-4o` | 具备原生视频理解和语音识别 | 当前唯一成熟的视频多模态方案 | `Qwen`、`InternVL`（无视频能力） |

| 工业质检/制造视觉 | `YOLO` / `SAM` 系列 + `Qwen-VL`（描述层） | 检测+解释组合，效率高 | `CV`模型负责检测，`VLM`负责说明 | `GPT-4V`（推理慢、成本高） |

| 教育/科研/多模态课程演示 | `LLaVA` / `InternVL2` | 代码开源、可快速训练 | 可展示`VLM`原理与微调流程 | `GPT-4V`（闭源） |

## 如果企业要做“自建多模态能力”

| 目标 | 推荐生态组合 | 理由 |

| --- | --- | --- |

| 中文文档/表格智能解析平台 | `DeepSeek-OCR`（识别） + `Qwen-VL`（语义） | 可控、可微调、处理量大 |

| 企业知识问答（图文`RAG`） | `Qwen-VL` / `InternVL2` + `LangChain` | 兼容知识库系统，易部署 |

| 结构化数据抽取系统 | `DeepSeek-OCR` + 微调`LoRA` | 只调输出头即可，训练快 |

| 多模态AI助手（客服/办公） | `Yi-VL` / `LLaVA-Next` | 模型轻、可内嵌 |

| 视频+语音会议理解 | `Gemini 1.5 Pro` / `GPT-4o`（API） | 视频语音模态目前闭源领先 |

## 微调与部署层面的选择思路

| 需求类型 | 微调重点 | 推荐方式 |

| --- | --- | --- |

| OCR/报表结构化 | 视觉投影层 + 输出格式`SFT` | `LoRA` / `QLoRA` |

| 图表问答 | 跨模态对齐层 + 指令数据 | `SFT` + 数据增强 |

| 合同/文档问答 | 语言层指令微调 | 轻`SFT`或`DPO` |

| 工业检测说明 | 结合`CV`特征层 | 多任务微调 |

| 视频摘要 | 需专门`Video Encoder` | 建议API托管 |

## 总结一句话

> 多模态模型的选型，核心不是“谁最强”，而是“谁最适合你的场景”：

+   通用理解选 `GPT-4V` / `Gemini`；

+   中文文档选 `Qwen-VL` / `DeepSeek-OCR`；

+   可控可微调选 `InternVL` / `Yi-VL`；

> 企业要做的是根据输入模态 + 输出目标 + 部署要求，选择一个最合适、可控、可扩展的多模态生态，而不是盲目追最前沿。

# 6. `llama_factory`支持的数据结构

`dataset_info.json` 包含了所有经过预处理的本地数据集以及在线数据集。如果希望使用自定义数据集，务必在 `dataset_info.json` 文件中添加对数据集及其内容的定义。

目前支持 `Alpaca` 格式和 `ShareGPT` 格式的数据集。

## Alpaca

指令监督微调(`Instruct Tuning`)通过让模型学习详细的指令以及对应的回答来优化模型在特定指令下的表现。

`instruction` 列对应的内容为人类指令，`input` 列对应的内容为人类输入，`output` 列对应的内容为模型回答。下面是一个例子

```
"alpaca_zh_demo.json"
{
  "instruction": "计算这些物品的总费用。 ",
  "input": "输入：汽车 - $3000，衣服 - $100，书 - $20。",
  "output": "汽车、衣服和书的总费用为 $3000 + $100 + $20 = $3120。",
},
```

在进行指令监督微调时，`instruction` 列对应的内容会与 `input` 列对应的内容拼接后作为最终的人类输入，即人类输入为 `instruction\ninput`。而 `output` 列对应的内容为模型回答。在上面的例子中，人类的最终输入是：

```
计算这些物品的总费用。
输入：汽车 - $3000，衣服 - $100，书 - $20。
```

模型的回答是：

```
汽车、衣服和书的总费用为 $3000 + $100 + $20 = $3120。
```

`history` 列是由多个字符串二元组构成的列表，分别代表历史消息中每轮对话的指令和回答。注意在指令监督微调时，历史消息中的回答内容也会被用于模型学习。

指令监督微调数据集格式要求如下：

```
[
  {
    "instruction": "人类指令（必填）",
    "input": "人类输入（选填）",
    "output": "模型回答（必填）",
    "system": "系统提示词（选填）",
    "history": [
      ["第一轮指令（选填）", "第一轮回答（选填）"],
      ["第二轮指令（选填）", "第二轮回答（选填）"]
    ]
  }
]
```

```
[
  {
    "instruction": "今天的天气怎么样？",
    "input": "",
    "output": "今天的天气不错，是晴天。",
    "history": [
      [
        "今天会下雨吗？",
        "今天不会下雨，是个好天气。"
      ],
      [
        "今天适合出去玩吗？",
        "非常适合，空气质量很好。"
      ]
    ]
  }
]
```

对于上述格式的数据，`dataset_info.json` 中的数据集描述应为：

```
"数据集名称": {
  "file_name": "data.json",
  "columns": {
    "prompt": "instruction",
    "query": "input",
    "response": "output",
    "system": "system",
    "history": "history"
  }
}
```

## 偏好数据集

偏好数据集用于奖励模型训练、`DPO` 训练和 `ORPO` 训练。对于系统指令和人类输入，偏好数据集给出了一个更优的回答和一个更差的回答。

一些研究 表明通过让模型学习“什么更好”可以使得模型更加迎合人类的需求。 甚至可以使得参数相对较少的模型的表现优于参数更多的模型。

偏好数据集需要在 `chosen` 列中提供更优的回答，并在 `rejected` 列中提供更差的回答，在一轮问答中其格式如下

```
[
  {
    "instruction": "人类指令（必填）",
    "input": "人类输入（选填）",
    "chosen": "优质回答（必填）",
    "rejected": "劣质回答（必填）"
  }
]
```

```
"数据集名称": {
  "file_name": "data.json",
  "ranking": true,
  "columns": {
    "prompt": "instruction",
    "query": "input",
    "chosen": "chosen",
    "rejected": "rejected"
  }
}
```
