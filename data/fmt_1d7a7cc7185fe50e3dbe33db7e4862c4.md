### 17.2.2 计费模型

#### API 计费的挑战

OpenClaw API 的计费面临独特挑战：底层 LLM 成本的不可预测性。一个简单的任务可能消耗很少的 token，而复杂任务可能消耗大量 token。

#### 主流计费模型

1. **基于调用次数**

   + 最简单直接的模型
   + 每次 API 调用收费固定金额
   + 优点：可预测性强
   + 缺点：不反映实际成本差异
   + 适合：任务复杂度相对均匀的场景

   定价示例：

   + 免费层：1,000 次调用/月
   + 基础层：$0.01/调用，$49/月（5,000 次）
   + 专业层：$0.008/调用，$199/月（25,000 次）
   + 企业层：定制定价

2. **基于 Token 消耗**

   + 按实际 LLM token 使用量计费
   + 更公平地反映成本
   + 优点：成本透明，按需付费
   + 缺点：用户难以预测费用
   + 适合：高级用户和大规模使用

   定价示例：

   + 输入 token:$0.01/1K tokens
   + 输出 token:$0.03/1K tokens
   + 包含一定的免费配额
   + 批量折扣

3. **混合模型**

   + 基础费用 + 使用量计费
   + 平衡可预测性和公平性
   + 优点：稳定收入 + 弹性扩展
   + 缺点：计费逻辑复杂
   + 适合：大多数商业场景

   定价示例：

   + 基础费用：$99/月
   + 包含：10,000 次调用或 1M tokens
   + 超出部分：$0.01/调用或 $0.01/1K tokens
   + 可选附加包

4. **基于价值的定价**

   + 按业务结果收费
   + 例如：每个处理的文档、每个生成的代码文件
   + 优点：与客户价值直接关联
   + 缺点：需要精确的价值度量
   + 适合：特定垂直场景

   定价示例：

   + 文档处理：$0.10/文档
   + 代码生成：$1.00/文件
   + 客服对话：$0.05/对话
   + 数据分析：$0.50/查询

#### 成本加成策略

确定合理的加成倍数：

##### 成本分析

+ 直接成本：LLM API 费用
+ 间接成本：基础设施、开发、支持
+ 目标毛利率：60-80%

##### 加成计算

+ 如果 LLM 成本为 $0.01/调用
+ 目标毛利率 70%
+ 定价应为 $0.033/调用
+ 考虑市场竞争，定为 $0.03-0.05/调用

#### 动态定价优化

实施智能定价策略：

##### 模型路由

+ 简单任务使用便宜模型
+ 复杂任务使用高级模型
+ 自动选择最优性价比
+ 降低整体成本

##### 缓存和优化

+ 缓存常见查询结果
+ 批量处理降低成本
+ Prompt 优化减少 token
+ 节省的成本提高利润率

##### 阶梯定价

+ 使用量越大，单价越低
+ 鼓励大规模使用
+ 提高客户粘性
+ 增加总收入
