
总而言之，通过执行“4 S”原则确保了提示的清晰度、焦点和丰富的上下文，而采用样本学习方法（尤其是单样本和少样本）则提供了具体的期望和要求，这些都有效地指导 LLM （Copilot） 优化其代码生成功能，使其建议更加准确、相关和实用。

### 利用代理 （Agents） 进行上下文建议

为了获得更准确、更相关的建议，开发人员可以在聊天界面中使用代理功能，从而提供选择性上下文。代理允许你指示 Copilot 重点关注项目中的特定部分（如整个工作区、终端输出或特定文件）。

若要使用代理，只需在问题前加上代理名称作为前缀。

常用的代理包括：

+ `@workspace` 代理：了解你的整个工作区或项目，允许你询问有关整个项目的问题。

+ 有效利用示例： 请求 Copilot 基于整个项目上下文生成 Dockerfile，例如：`@workspace I need to create a Dockerfile for this project, can you generate one that will help me package it?`。你还可以要求其使用特定的步骤或环境，例如：`@workspace help me create a Dockerfile to package this project but make sure you are using a Virtual Environment for Python.`。

+ `@terminal` 代理：根据终端输出提供建议。

+ 有效利用示例： `@terminal 如何修复我看到的错误消息？`。

+ `@file` 代理：重点关注特定文件的内容。

+ 有效利用示例： `@file 能否在 `main.py` 中帮助重构此函数？`。

+ `@directory` 代理：考虑特定目录的内容。

+ 有效利用示例： `@directory 如何优化 `utils` 目录中的脚本？`。

请注意，虽然你可以具体说明 `@workspace`，但默认情况下，GitHub Copilot 会将文本编辑器中打开的文件用作附加上下文。

## 使用 GitHub Copilot 进行管理和自定义时的注意事项

### GitHub Copilot 不同的订阅计划

GitHub Copilot 提供多种定价计划，以满足不同开发者和组织的需求，主要包括 Free 和 Pro、Business（企业）和 Enterprise（企业版）。

*注：GitHub Copilot Free 有使用限制。免费层每月提供 2,000 次代码自动完成和 50 条聊天信息。教师、学生和被选定的开源维护人员可以免费获得 Copilot Pro。

在自定义功能方面，这些计划也存在差异：

+ Free 和 Pro 以及 Business 计划均支持与 Copilot 扩展（公共 Beta 版）无限集成，并支持为内部工具（公共 Beta 版）构建专用扩展。

+ Enterprise 计划独有功能：

+ 定制专用代码库的聊天对话。

+ 将知识库附加到聊天中以提供组织上下文。

在选择定价计划时，应考虑 Business 和 Enterprise 版 是唯一提供更可靠隐私控制的计划。

### 安全功能

GitHub Copilot 允许开发人员和组织在开发和创新时优先考虑安全性、隐私、合规性和透明度。

合同保护 （Contract Protection）

为了帮助组织遵守法律要求，GitHub Copilot 提供以下合同保护措施：

1. 知识产权 （IP） 赔偿：GitHub Copilot 商业和企业计划包括 IP 赔偿。如果 Copilot 提出的任何建议被质疑侵犯第三方知识产权，GitHub 会承担法律责任。前提是“`匹配公共代码`”设置被阻止。

1. 数据保护协议 （DPA）：GitHub 提供 DPA，概述了为保护数据和确保遵守数据隐私法规所采取的措施。

1. GitHub Copilot 信任中心： 该中心详细介绍了 Copilot 的工作原理，包括安全、隐私、合规性和知识产权保护。

### 数据隐私与策略管理

+ 隐私控制：Business 和 Enterprise 版提供更可靠的隐私控制。这些控制措施包括从 GitHub Copilot 分析中排除特定文件、访问详细的审核日志，以及提供 IP 赔偿的功能。

+ 策略管理：Business 和 Enterprise 版计划允许在组织级别进行全面的策略管理，这有助于确保根据组织的隐私策略处理敏感数据。

+ 数据收集和保留：单个订阅者可以选择 GitHub 是否收集并保留他们的提示和 Copilot 建议。

### 筛选匹配公共代码

GitHub Copilot 可以帮助识别并 筛选掉与公开提供的代码匹配的代码建议。此功能对于保持代码库的原创性和安全性至关重要。它能降低将不安全或不合规代码纳入项目的风险。用户可以通过组织或企业的设置将“`匹配公共代码`”下的建议设置为“阻止”。

![](img/cadf15ab18c921d5af9a4e4ec845bfd8.png)

### 内容排除

GitHub Copilot 中的内容排除功能旨在通过阻止将特定文件、目录或存储库用于代码完成建议来帮助保护敏感信息。

![](img/1ae051d06b7a11efc3da7f43fb6f05ea.png)

### 内容排除的配置和范围

+ 配置方式：存储库管理员和组织所有者可以配置内容排除策略。配置可以在存储库的“`设置`”下的“`Copilot`”部分中完成，或在组织的“`设置`”下的“`Copilot 内容排除`”部分中进行。

+ 适用范围： 在组织或存储库中定义的内容排除设置适用于作为 GitHub Copilot Business 或 GitHub Copilot Enterprise 订阅一部分获得许可的所有成员。

### 对代码建议的影响

当内容从 GitHub Copilot 中排除时：

+ 代码完成功能在受影响的文件中不再可用。

+ 受影响文件中的内容不会用于其他文件中的代码完成建议。

+ 受影响文件中的内容不会用于 GitHub Copilot Chat 的响应。

内容排除可以帮助得到更安全且合规的代码建议，但也会 减少 Copilot 整体可用的上下文，这可能会影响建议的准确性和用处。

### 内容排除的限制

在某些情况下，内容排除可能不完全有效：

+ IDE 限制：在某些 IDE 中，使用某些功能（如 Copilot Chat）时，内容排除可能不适用。例如，在 Visual Studio Code 和 Visual Studio 中，使用问题中的 `@github` 聊天参与者时，不会应用内容排除。

+ 语义信息： 如果信息由 IDE 在未排除的文件中提供，Copilot 仍可能使用排除文件中的语义信息，包括代码中使用的符号或函数调用的类型信息和悬停定义。

+ 策略范围： 内容排除设置仅适用于配置了排除的组织的成员。访问指定文件的任何其他人员仍可能看到代码完成建议和引用指定文件的 Copilot Chat 响应。

## 故障排除

### 缺少代码建议

如果 GitHub Copilot 未在编辑器中提供代码建议，可以尝试以下操作：

+ 检查 Internet 连接：确保具有稳定的 Internet 连接，因为 GitHub Copilot 需要可用连接才能正常运行。

+ 更新 Copilot 扩展：确保使用最新版本的 GitHub Copilot 扩展。旧版本可能无法与 Copilot 服务器有效通信。

+ 验证 IDE 兼容性：确认 IDE 与 GitHub Copilot 兼容。某些 IDE 可能需要特定配置或更新。

+ 查看内容排除：如果某些文件被排除在 Copilot 的分析之外，则可能不会显示建议。检查内容排除设置以确保正确配置它们。

执行这些操作通常可解决与缺少的代码建议相关的问题。

### 内容排除未按预期工作

如果内容排除功能未能按预期阻止 GitHub Copilot 使用特定文件或目录：

+ 排除项的延迟应用：添加或更改内容排除项后，可能需要长达 30 分钟才能在已加载设置的 IDE 中生效。若要立即应用更改，请在 IDE 中重新加载内容排除设置。

+ 排除范围不充分：内容排除设置仅适用于配置了排除的组织的成员。

+ 检查状态栏图标：如果文件适用于内容排除，GitHub Copilot 图标上会有一条对角线穿过。将鼠标悬停在图标上可查看组织或父存储库是否禁用了该文件的 GitHub Copilot。

+ 特定于 IDE 的限制：在某些 IDE 中，使用某些功能（如 GitHub Copilot Chat）时，内容排除可能不适用。

### 代码建议令人不满意

如果 GitHub Copilot 生成的建议质量不佳，可以使用以下技术来提示 Copilot 提供更好的结果：

+ 提供清晰的上下文：确保代码为 Copilot 提供明确的上下文，例如编写描述性注释和使用有意义的变量名称。

+ 使用 Copilot 命令：在某些 IDE 中，可以使用特定命令来提示 Copilot 生成建议。例如，在 Visual Studio Code 中，可以使用 `Ctrl+Enter` 快捷方式触发 GitHub Copilot。

+ 调整提示长度：尝试使用不同的提示长度。有时，提供更长或更详细的提示可以帮助 Copilot 生成更好的建议。

#### 自动化机制：减少重复工作和加速交付

GitHub Copilot 擅长处理常规和重复性的编码任务，从而实现了广泛的自动化。

GitHub Copilot 可以快速生成各种常见功能的样板代码，从而节省了设置任务的时间。

+ 基础结构自动化：快速生成设置 `REST API` 或创建类结构等功能。

+ 高级模板自动化：可以根据简单的实体说明生成完整的数据库模型、迁移文件、`ORM` 配置、`API` 终结点基架，以及测试基础结构。

Copilot 可以将高级功能要求或用户情景直接转换为可投入生产的代码实现。

+ 功能基架：将高级功能说明转化为完整的代码结构，正确分离关注点，包括数据库模型、`API` 终结点和前端组件。

Copilot 自动化了软件开发中两个通常被认为乏味的但至关重要的任务：

1. 代码重构和优化

Copilot 协助维护健康的代码库，这在维护阶段尤其重要。

+ 模式识别和优化：识别代码中的常见模式并推荐更高效或更简洁的替代方案。

+ 跨语言翻译：有助于在不同编程语言之间翻译概念或代码片段。

+ `Bug` 修复建议：根据错误消息和周围代码建议报告问题的潜在修补程序。

GitHub Copilot 的主要优势在于其与开发环境和开发流程的深度集成，最大程度地减少了上下文切换。

GitHub Copilot 被设计为原生集成到热门开发环境中，符合开发人员对“它只工作”工具的偏好。

+ 最小化上下文切换：直接在 IDE 中提供代码建议，减少了不断引用外部文档或在线搜索解决方案的需求。

+ 上下文感知和学习模式：分析开发环境和项目结构，提供更准确且相关的代码补全，并学习开发人员的编码模式和偏好以定制建议。

1. 协调的 AI 工作流（高级集成）

在现代开发中，Copilot 可以作为协调的 AI 工作流的一部分，与其他 AI 功能协同工作，处理更复杂的开发任务。

+ 多代理开发模式：例如，Copilot 可以充当草稿代理生成初始实现，而查看代理则分析代码质量、安全漏洞并确保符合体系结构模式。

+ 高级推理：针对复杂的开发场景，Copilot 提供了`高级推理模式`，能够分析更大的代码库，提供高级体系结构建议，并协调多个文件中的更改（`多文件协调`）。

Copilot 改进了拉取请求过程，加快了从开发到部署的速度。

+ 智能代码审查辅助：在创建 PR 之前进行`提交前质量检查`，并帮助起草建设性的、具体的评审注释，从而显著减少所需的评审轮数。

### 衡量 Github Copilot 效率
