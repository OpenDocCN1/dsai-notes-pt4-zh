
## Microsoft Purview 电子数据展示（eDiscovery）

### 功能概述

+ **响应诉讼：** 在公司面临法律诉讼时，快速、合规地响应对方的证据开示要求。

+ **内部调查：** 调查内部的违规行为，如员工不当行为、数据泄露事件等。

+ **监管机构问询：** 响应来自政府或行业监管机构的数据提供要求。

### 最佳实践

+ **使用高级版处理复杂案件：** 对于涉及大量数据和多位保管人的复杂案件，强烈建议使用 eDiscovery (Premium)，其分析和审阅功能可以节省大量的人工审阅时间和成本。

+ **建立标准化的工作流程：** 为常见的调查类型（如员工离职调查）建立标准化的 eDiscovery 流程和搜索查询模板，以提高效率和一致性。

+ **权限分离：** 使用基于角色的访问控制，确保只有被授权的法务和合规人员才能访问和管理 eDiscovery 案例，保护调查的机密性。

## Microsoft Purview 通信合规性（Communication Compliance）

Microsoft Purview 通信合规性是一个内部风险解决方案，它通过捕获和分析组织内的数字通信（如电子邮件、Microsoft Teams 消息等），帮助组织检测、调查和处理不当或违规的内容，从而最大限度地降低通信风险。

### 核心组件

#### 策略模板（Policy Templates）

+ **定义：** 提供一系列针对常见通信风险的预置策略模板，例如“攻击性、骚扰性和威胁性语言”、“共享敏感信息”以及特定于行业的监管要求（如金融行业的 FINRA 规定）。

+ **自定义策略：** 管理员也可以创建完全自定义的策略，定义自己的关键词、条件和要监控的用户群体。

#### 内容捕获连接器（Content Capture Connectors）

+ **定义：** 用于捕获需要被策略扫描的通信内容。

+ **支持范围：** 原生支持 Microsoft 365 通信渠道，包括 Exchange Online 邮件、Microsoft Teams 聊天和频道消息、Yammer 以及 Skype for Business Online。此外，还支持导入第三方来源（如 Twitter、Slack、Zoom）的通信数据进行分析。

#### 智能检测引擎（Intelligent Detection Engine）

+ **定义：** 这是策略的核心，负责扫描捕获到的内容以识别潜在的违规行为。

+ **检测方法：**

+ **可训练分类器：** 内置和自定义的机器学习模型，用于识别骚扰、威胁、亵渎等复杂的语言模式，而不仅仅是简单的关键字匹配。

+ 敏感信息类型（SITs）和关键字： 检测通信内容中是否包含特定的敏感数据（如信用卡号、项目代号）或自定义的关键字列表。

+ **条件匹配：** 可以基于通信的元数据进行检测，例如通信的大小、方向（内部/外部）或发件人/收件人属性。

#### 调查与补救工作流（Investigation and Remediation Workflow）

+ **定义：** 一个安全的、集中的仪表板，供指定的调查人员和审阅者对策略匹配项（警报）进行审查和处理。

+ **功能：**

+ **警报仪表板：** 集中展示所有待处理的警报。

+ **对话视图：** 以对话的完整上下文来呈现匹配的消息，而不仅仅是孤立的一条。

+ **内容屏蔽与注释：** 在审阅过程中可以屏蔽敏感信息或添加注释。

+ **处理操作：** 审阅者可以对警报进行标记（如“合规”、“可疑”）、解决、上报给其他人员，或通知用户。

### 工作机制

1. **配置策略：** 管理员选择一个模板或创建新策略，定义要监控的用户或组、要扫描的通信渠道，以及触发警报的条件（例如，包含攻击性语言或特定的敏感信息类型）。

1. **近实时捕获：** 系统在后台持续捕获指定用户的通信内容。

1. **内容分析：** 捕获到的每条消息都会通过智能检测引擎进行扫描，与所有激活的策略条件进行比对。

1. **生成警报：** 一旦有消息匹配了策略条件，系统就会生成一个警报，并将其发送到调查与补救工作流的仪表板中。

1. **审查与处理：** 被授权的审阅者登录仪表板，对警报进行分类、调查。他们可以查看消息的完整上下文，并根据组织的流程采取适当的措施，例如升级到人力资源部门或法务部门。

### 关键适用场景

+ **营造健康的企业文化：** 主动检测并处理工作场所中的网络欺凌、骚扰或歧视性言论。

+ **保护敏感信息：** 监控并防止员工通过电子邮件或 Teams 聊天无意或恶意地泄露公司机密、客户个人信息（PII）或知识产权。

+ **满足监管监督要求：** 对于金融、医疗等受严格监管的行业，该工具可以帮助满足法律规定的对员工通信进行监督和存档的要求。

+ **调查不当行为：** 在进行内部调查时，可以作为收集相关通信证据的有效工具。

### 最佳实践

+ **明确目标，精准监控：** 避免创建过于宽泛的“监控所有人所有事”的策略。应针对特定的风险（如新产品保密）和特定的人群（如项目团队）来创建目标明确的策略。

+ **建立严格的审阅流程：** 制定清晰的指导方针，定义谁有权审阅警报、审阅的标准是什么，以及如何处理不同类型的违规行为。利用基于角色的访问控制来严格限制审阅者权限。

+ **保护员工隐私：** 优先使用可训练分类器而非宽泛的关键字列表，以减少误报，避免审查不相关的个人通信。在策略中明确告知员工其公司通信可能会受到监控。

+ **定期优化策略：** 定期回顾策略的运行效果，分析误报和漏报的情况，并根据反馈对关键字列表、分类器或条件进行调整，以提高准确性。

## Microsoft Purview 审计（Audit）

Microsoft Purview 审计是一个基础性的合规与安全功能，它详细记录了在 Microsoft 365 组织中发生的数千种用户和管理员活动，并将这些记录保存在一个统一的审计日志中，以便进行搜索和调查。

### 核心组件

#### 统一审计日志（Unified Audit Log）

+ **定义：** 一个集中的、受保护的存储库，用于收集和存储来自多个 Microsoft 365 服务和解决方案的审计记录。

+ **日志内容：** 每条审计记录都包含事件发生的时间、执行操作的用户或应用、操作的对象（如文件、文件夹、用户账户）以及客户端 IP 地址等详细信息。

#### 广泛的活动覆盖

+ **定义：** Purview 审计能够捕获数千种不同的活动。

+ **涵盖的服务：** 包括但不限于 SharePoint Online，OneDrive for Business，Exchange Online，Microsoft Teams，Azure Active Directory，Power BI，Dynamics 365，Microsoft Purview 解决方案本身（如 DLP 策略变更）等。

#### 审计日志搜索工具（Audit Log Search Tool）

+ **定义：** 在 Microsoft Purview 合规门户中提供的一个图形化界面，允许管理员根据多种条件（如活动类型、用户、日期范围、文件或文件夹）来搜索审计日志。

+ **PowerShell 支持：** 同时提供强大的 PowerShell cmdlet（`Search-UnifiedAuditLog`），支持更复杂的脚本化查询和自动化任务。

#### 审计保留策略（Audit Retention Policies）

+ **定义：** 决定审计日志记录在统一审计日志中保留多长时间的策略。

+ **版本差异：**

+ **审计（标准版）：** 默认保留 90 天。

+ **审计（高级版）：** 提供更长的默认保留期（通常为一年），并允许创建自定义的保留策略，将特定用户或特定活动的审计日志最多保留 10 年。

### 工作机制

1. **默认启用：** 对于大多数 Microsoft 365 订阅，审计功能是默认启用的。

1. **记录生成：** 当用户或管理员在任何受支持的 Microsoft 365 服务中执行一项可审计的活动时（例如，在 SharePoint 中查看文件、在 Exchange Online 中永久删除邮件、管理员重置用户密码），该服务会生成一条详细的审计记录。

1. **日志聚合：** 这条审计记录会被安全地发送到统一审计日志中进行存储和索引。

1. **搜索与导出：** 当需要进行调查时，授权管理员可以使用门户网站的搜索工具或 PowerShell 来查询统一审计日志。搜索结果可以在线查看，也可以导出为 CSV 文件进行离线分析或存档。

### 关键适用场景

+ **安全事件调查：** 在发生数据泄露或账户被盗等安全事件后，通过审计日志可以追溯攻击者的活动轨迹，例如他们访问了哪些文件、修改了哪些权限、发送了哪些邮件。

+ **合规性审计：** 向内外部审计员提供证据，证明组织已经实施了适当的访问控制和变更管理流程。例如，可以提供报告显示“谁在过去 90 天内访问过某个包含财务数据的敏感 SharePoint 网站”。

+ **故障排查：** 当出现意外的配置更改或数据丢失时，可以通过审计日志快速定位是“谁”在“什么时间”执行了“什么操作”导致的。

+ **监控管理员活动：** 对拥有高权限的管理员账户进行监控，确保其所有操作都是经过授权且合规的。

### 最佳实践

+ **熟悉关键活动：** 了解对您的组织最重要的审计活动是什么。例如，`FileAccessed`（文件访问）、`MailItemsAccessed`（邮件项目访问）和 `UserLoggedIn`（用户登录）等都是调查中常用的关键事件。

+ **使用精确的搜索条件：** 统一审计日志的数据量非常庞大。在搜索时，应尽可能使用精确的筛选条件（如具体的文件名、用户和狭窄的时间范围），以加快搜索速度并获得更相关的结果。

+ **考虑高级版审计：** 如果组织有严格的合规要求，需要将审计日志保留超过 90 天，或者需要对关键事件（如邮件访问）进行更深入的取证分析，应评估并启用审计（高级版）。

+ **与 SIEM 集成：** 为了实现更高级的威胁检测和关联分析，建议将 Microsoft 365 审计日志与 Microsoft Sentinel 或其他第三方安全信息和事件管理（SIEM）工具集成。

## Microsoft Purview 数据生命周期管理（Data Lifecycle Management）

Microsoft Purview 数据生命周期管理（原名信息治理）提供了一套工具，用于通过实施保留和删除策略来智能地管理组织内容的整个生命周期，从创建或接收开始，到最终成为记录或被永久删除。

### 核心组件

#### 保留策略（Retention Policies）

+ **定义：** 一种宽泛的、基于位置的策略，用于对整个位置（如所有 Exchange 邮箱、所有 SharePoint 网站或所有 Teams 聊天）中的内容应用统一的保留或删除规则。

+ **工作方式：** 管理员创建一个策略，例如“对所有 OneDrive 账户中的内容保留 5 年”，系统会在后台自动将此策略应用于指定位置的所有内容。

#### 保留标签（Retention Labels）

+ **定义：** 一种更精细的、可应用于单个项目（如一份文档、一封电子邮件）的标记。它允许对不同类型的内容应用不同的生命周期管理规则。

+ **应用方式：**

+ **手动应用：** 用户可以从 Office 应用的菜单中手动选择一个标签应用到文件上。

+ **自动应用：** 可以配置策略，根据内容的敏感信息类型、关键字或可训练分类器来自动应用标签。

+ **默认应用：** 可以为某个文档库、文件夹或邮箱设置一个默认标签。

#### 事件驱动的保留（Event-based Retention）

+ **定义：** 这是保留标签的一项高级功能，它允许内容的保留期限从某个特定业务事件发生之日开始计算，而不是从文件的创建或最后修改日期开始。

+ **示例：** 可以为所有项目合同应用一个“项目结束”保留标签，当项目正式结束时，管理员触发一个“项目结束”事件，所有相关合同的 7 年保留期才开始计时。

#### 处置评审（Disposition Review）

+ **定义：** 在保留期结束后、内容被永久删除之前，可以设置一个或多个阶段的手动评审流程。

+ **工作方式：** 当内容的保留期到期时，它不会被立即删除，而是会出现在一个处置评审仪表板中。指定的评审员会收到通知，来决定是批准删除、延长保留期还是重新标记该内容。

### 工作机制

1. **策略/标签创建：** 管理员在 Purview 合规门户中定义保留策略或保留标签，明确规定保留期限、保留期结束后的操作（删除、不执行任何操作或触发处置评审），以及是否需要将内容声明为不可变的“记录”。

1. **发布与应用：** 保留策略被应用于选定的位置。保留标签被发布到这些位置，然后通过手动、自动或默认的方式应用到具体的内容项上。

1. **后台处理：** 后台的计时器作业会定期检查所有内容，并根据其应用的策略或标签来管理其生命周期。

1. **强制执行：**

+ **保留期间：** 如果一个项目处于保留期内，系统会阻止用户（甚至管理员）永久删除它。文件的副本会保存在一个受保护的位置（如保留库）。

+ **保留期结束：** 当保留期结束后，系统会根据策略设置自动执行删除操作，或将其提交给处置评审员。

### 关键适用场景

+ **满足法规遵从：** 确保财务、法律、人事等类型的记录按照法律法规要求保留足够长的时间，例如，将所有税务相关文件至少保留 7 年。

+ **降低数据风险（可防御性删除）：** 主动并自动地删除那些已经没有业务价值且已超过保留期的旧数据。这可以减少组织的存储占用，更重要的是，减少了在发生数据泄露或诉讼时需要审查和承担风险的数据量。

+ **管理记录（Records Management）：** 将重要的合同、政策或最终报告声明为“记录”，使其在保留期内不可更改和删除，以保证其作为证据的完整性和真实性。

+ **简化项目数据管理：** 使用事件驱动的保留，将项目相关的所有文档的生命周期与项目的结束日期绑定，实现项目数据的批量、自动化清理。

### 最佳实践

+ **规划先于配置：** 在创建任何策略或标签之前，务必与法务、合规和业务部门合作，制定全公司的文件保留计划（File Plan），明确不同类型数据的保留要求。

+ **“保留优先”原则：** 牢记 Microsoft 365 的“保留优先”原则。如果一个文件同时受到保留和删除策略的影响，系统将始终优先执行保留操作。

+ **策略与标签结合使用：** 使用保留策略来设置一个覆盖所有内容的基线或最低保留期限。然后，使用保留标签来处理需要更长保留期或特殊处理（如声明为记录）的特定内容类型。

+ **清晰地向用户传达：** 对用户进行培训，让他们了解保留标签的含义以及何时应该手动应用它们，确保策略能够被有效执行。

## 总结

Microsoft Purview 的核心在于其数据映射，它为所有数据资产创建了统一的元数据视图。在此基础上，统一目录为数据使用者提供了发现、理解和追溯数据的工具。同时，一套强大的数据安全和风险与合规功能，确保组织能够在保护敏感信息和满足监管要求的同时，充分利用其数据资产。通过将这些原本孤立的功能整合到一个统一的平台下，Purview 实现了从数据治理到数据保护再到合规管理的全方位覆盖。
