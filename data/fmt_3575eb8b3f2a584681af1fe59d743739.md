
# MixLLM: LLM Quantization with Global Mixed-precision between Output-features and Highly-efficient System Design

贡献人：

https://arxiv.org/abs/2412.14590

ResearchFlow链接：https://rflow.ai/flow/0ee55b23-44e7-47ce-b8d0-febe3bdf9e74

`LLM`在多种任务中取得了显著成绩，但其庞大的内存消耗和计算成本已成为高效部署的障碍。量化技术通过以较低的比特宽度表示权重或激活来压缩`LLM`，成为减少其大小的有效解决方案。然而，现有的量化方法仍存在精度下降或系统效率低下的问题。量化效率的优化涉及精度、内存消耗和系统执行效率之间的平衡，我们称之为量化的“有效性三角”。现有的量化方案在这三者之间有不同的侧重点和权衡。

现有方法中，权重量化方法解决了内存消耗问题，并能加速小批量解码的执行，但对于精度要求较高的生产任务（例如`4-bit`量化可能导致的精度下降），以及在大批量工作负载中的系统性能降低，依然存在挑战。权重激活量化方法通过对激活进行低比特量化来提高系统效率，但其精度下降较为严重，且会增加去量化的开销，影响系统效率。使用异常值分离和混合精度技术的方案试图通过不同的精度分配来提高低比特量化的精度，但其系统效率和精度提升仍然有限。

为了解决这些问题并平衡三者的需求，本文提出了`MixLLM`。`MixLLM`通过以下贡献解决了现有方法的不足，并有效优化了量化过程：

首先，`MixLLM`在权重量化中采用了输出特征的混合精度量化，基于全局显著性识别，为不同的输出特征（即输出通道）使用不同的比特宽度。对于显著性较高的输出特征，采用`8-bit`量化；对于其他输出特征，则采用`4-bit`量化。这种全局显著性识别方法超越了以往基于单层估计的显著性方法，能够更精准地根据不同层次的重要性调整量化配置。此外，`MixLLM`的混合精度量化设计比输入特征的量化更容易实现，因为输出特征的计算通常是互不干扰的子问题。

其次，`MixLLM`还通过量化配置和`GPU`内核优化的联合设计，实现了精度与系统效率的双重提升。`MixLLM`使用`8-bit`量化激活，因为这种配置能够保持较好的精度。由于矩阵乘法执行通常更多地受到较大权重张量的限制，而不是较小激活张量的限制，因此减少激活的量化精度并不显著影响系统效率。`MixLLM`在`8-bit`量化和`4-bit`量化上采用对称量化和非对称量化配置，以保持良好的精度。为了优化系统效率，`MixLLM`采用了两步去量化策略，并利用快速的`int8`张量核心和整数浮点转换来减少去量化的开销。

### 万卡集群`LLM`训练模拟`SimAI`，大模型训练通信计算仿真

贡献人：

https://zhuanlan.zhihu.com/p/13786416568

`SimAI`是阿里巴巴开发的一个高精度模拟器，专门用于大规模模拟`LLM`（大语言模型）的训练过程，主要包括集群计算和通信仿真。由于训练`LLM`需要上万个`GPU`，传统的训练方式难以高效验证新设计、调优和优化方案，因此需要一个高效的模拟工具来测试和规划。`SimAI`通过精确模拟训练框架、计算和集体通信库，提供了一个可以反映真实世界训练工作负载的工具，帮助提高资源利用率并确保基础设施投资回报。

`SimAI`的目标包括：首先，生成反映真实训练场景的工作负载；其次，提供高保真的通信仿真，特别是集体通信的高精度模拟；再者，实现高效的计算模拟，以便为大规模模拟提供精度和可扩展性；最后，确保模拟速度足够快，能够应对大规模集群的需求。

`SimAI`的核心组成部分之一是`AICB`（Artificial Intelligence Communication Benchmark），一种新的基准测试套件，用于生成与实际应用一致的通信负载模式，特别适用于`GPU`集群通信系统的基准测试、通信模式分析和工作负载描述。`AICB`的两个主要功能是记录实际训练过程中的通信和计算耗时，并生成通信计算及其约束的工作负载文件，这些数据用于后续的仿真分析和优化。

除了`AICB`，`SimAI`还包括两个重要的仿真器：`SimAI-CM`（计算仿真器）和`SimAI-CCL`（通信仿真器）。`SimAI-CM`通过使用数据库中的实测数据或估算系数，模拟计算过程，以达到高效且准确的仿真效果。`SimAI-CCL`则专注于集体通信仿真，模拟大规模集群中的数据传输过程，帮助优化和提升通信效率。通过这两个仿真器，`SimAI`能够高精度地模拟大模型训练中的计算和通信需求，从而有效地支持集群规划和性能调优。

### 大模型逻辑推理学习的思考和展望(2024)

贡献人：

https://zhuanlan.zhihu.com/p/14002760900

这篇文章探讨了当前训练大型语言模型（`LLM`）中面临的挑战与思考，主要集中在从`SFT`（监督学习微调）到`PPO`（策略优化）的转变以及模型的扩展性和推理能力。首先，`SFT`面临着对细粒度指令和复杂任务（如数学和编程）处理能力不足的问题。尽管通过`PPO`能够在更精细地跟随人类偏好方面获得显著提升，尤其是在文科领域，但其在处理逻辑推理任务时仍然受限。随着训练规模的扩展，人们期望通过增加模型参数来解决问题，但问题依然存在，特别是当训练数据量没有同步增加时，模型的效果不再显著提高，预训练的边际效应逐渐减弱。

文章进一步探讨了`Scaling Law`的局限性，强调即使在资源充足的情况下，预训练阶段的提升也会受到数据质量和数量的限制，特别是在多模态数据的应用上，仍然缺乏明确的结论。随着模型逐渐成熟，推理过程的扩展（例如推理时间的扩展）可能成为提升逻辑推理能力的有效途径。在此背景下，思维链的生成与优化成为关键议题。类似人类思维过程中的“框架化”与“思维链”，如果能够被有效模拟和训练，可能会对复杂推理任务产生重大影响。

在具体实现方面，文章建议通过高质量的思维链数据进行冷启动，然后通过模型生成和强化学习逐步优化思维链的生成能力，进而提高模型在数学、编程等领域的推理能力。此外，`OpenAI`提出的领域精调（`RFT`）方法，作为一种微调技术，也被视为一种高效的思维链训练方式，通过强化学习结合思维链的生成进一步推动模型的性能提升。

对于未来的探索方向，文章提出了几个具有高价值的领域。首先是推理优化，利用技术手段减少训练和推理的资源消耗；其次是对强化学习（`RL`）的更深入探索，尤其是在`RL`的各个环节仍有优化空间时；最后，针对特定领域的推理学习（如法律、金融、医学等）也被认为是未来具有高商业价值的研究方向，尤其是结合`OOD`（Out-of-Distribution）和泛化能力来实现低成本高效能的模型训练。

### 大语言模型（`LLM`）评价指标小汇总

贡献人：

https://zhuanlan.zhihu.com/p/641416694

在统计和评估大型语言模型（`LLM`）性能时，研究者常用多个基准和评价方法，以量化模型的能力、鲁棒性和效率。以下是对当前几种主要评估方法的简要总结。

首先，`C-EVAL`主要用于中文考试，使用选择题评估，注重模型的准确性（`Acc`）。`KoLA`是一个季度更新的全球知识评估榜单，涉及知识记忆、理解、应用等领域，评估方法包括`EM`（`Exact Match`）、`F1`、`ROUGE`、`BLEU`等传统方法，数据集为`KoLA`。`SuperGLUE`是一个经典的基准，评估包括词义消歧、自然语言推理、`QA`等任务，使用`EM`、`F1`、`Acc`等指标，且包含多个任务和领域。`NL2Code`则针对代码生成任务，使用`pass@k`作为评估标准。`HELM`是一个更为细化的评估框架，覆盖任务、领域、语言等维度，评估指标包括传统的`Acc`、`F1`、`ROUGE`以及针对鲁棒性、公平性、毒性等特性的方法。`CUGE`聚焦中文`NLP`，评估范围广泛，包括语言理解、对话理解、信息获取等，使用`Acc`、`F1`、`BLEU`等常见指标。`HC3`通过人类与`ChatGPT`的回答对进行人工评估，重点分析不同方法与人类评估的相关性。

评估方法可以分为两大类：文本对比方法和模型/分布评估方法。在文本对比类方法中，`BLEU`、`ROUGE`、`METEOR`、`CIDEr`等是常用的基于重叠度的评估指标，这些方法主要用于机器翻译、文本生成等任务。此外，`EM`、`F1`、`MCC`等常用于问答和分类任务。`pass@k`是评估代码生成的常用指标，类似的，也可以用于多次输出的任务。鲁棒性评估（如`Invariance`、`Equivariance`）和偏见检测（如性别和种族偏见）也成为关键方向。对于对话系统，指标如`JGA`、`Inform Rate`、`Slot Accuracy`等被广泛使用来评估对话状态跟踪和实体识别。

在模型/分布评估方法方面，常见的技术包括`BERTScore`、`T5`、`Sentence Movers Similarity`等，这些方法主要基于文本相似性计算。对于毒性评估，`Perspective API`是一个常用的工具，它基于机器学习模型评估文本输出的毒性。此外，还有专门的对话系统评估工具，如`ADEM`、`DEAM`，以及一些基于负样本的对话系统评估方法。

最后，人类评估作为最直接的评估方法，常常作为其他方法的对照。尽管如此，一些方法（如`ADEM`、`HUSE`）试图模仿人类评估的方式，以期减少人工标注的成本。

综上所述，当前的`LLM`评估方法涵盖了广泛的领域，包括准确性、鲁棒性、公平性、效率等维度。随着基准测试的不断发展，新的方法和数据集不断涌现，为模型的优化和比较提供了更为丰富的手段和指标。

### MoE 训练到底是开 `TP` 还是 `EP`？

贡献人：

https://zhuanlan.zhihu.com/p/13997146226

`EP`和`TP`各有优劣，具体选择取决于训练场景和需求：

+ 计算效率：`EP`在`expert`计算上更高效，减少了`kernel launch`次数，适合大矩阵计算。

+ 通信开销：在`topk=2`且`token`均匀分配时，`EP`和`TP`通信量相当，但在`topk>2`或负载不均衡时，`EP`的通信开销高于`TP`。

+ 显存占用：`TP`显存占用低且稳定，适合长序列训练或显存敏感场景，而`EP`在负载不均衡时可能导致`OOM`。

+ 数据并行性：`EP`不会减少`DP`数量，可以在固定资源下处理更多数据。

### o1复现的一点点心得

贡献人：

随着`o3`和`Gemini-Flash-Thinking`版本的推出，推理模型的能力在常见基准测试上达到了前所未有的高水平，尤其是在数学、代码和推理等领域取得显著进展。例如，`o3`模型在`AIME24`上达到了29/30的高分，在`Code-Force`中也达到了99.99%的优秀成绩。推理增强模型显著提升了这些高推理需求场景的表现，但对于常见的翻译、对话等任务，这种推理能力未必是必要的。真正能释放这些增强模型潜力的场景可能是`agent`系统，通过让增强推理模型作为指挥者调度低级模型，既能降低推理成本，又能更合理地利用老旧模型。

对于如何在现有资源下构建推理增强模型，本文总结了外部工作及作者的复现（蒸馏）经验。当前，国内推出了许多类似`o1`的模型，如`Deepseek-r1`、`Kimi-math`、`Macro-o1`等，学术界也提出了不同的方法。总体来说，有两大派系：树搜索派系通过树搜索和多智能体合成数据；蒸馏派系通过`jailbreak`、`prompt-hack`等手段破解`o1`的限制，进而提升模型能力。蒸馏方法能帮助我们更好理解`long-cot`（长推理链）训练方法，树搜索派系则能为新场景（如`agent`和`tool`）提供快速数据生成方案。

作者最初倾向于树搜索，但发现`self-critic`任务较为困难，且预训练阶段并未充分提供推理链信息。于是转向数据蒸馏路径，通过从`Deepseek-r1`和`Qwen-Qwq`中采样，结合`long-cot`方法，生成了一个小规模的`1.3k-prompt`、`4.4k`数据集。实验表明，少量难度较高的数据就能显著提升模型的数学能力，并且这些数据能对其他任务（如代码）产生一定的迁移效应。
