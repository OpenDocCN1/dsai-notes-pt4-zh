
# BWArea Model 训练与实验

该模型通过预训练、监督微调和强化学习（RL）三个阶段进行训练。特别是在RL阶段，固定语言世界模型的参数，基于策略模型采样`action`并在生成的内容上进行优化，从而更高效地对齐生成目标。`BWArea Model`通过这种高层次意图控制，使语言生成更加多样化且更加符合预期，并且在实验中展示出对脏数据的更强适应能力。

实验结果表明，`BWArea Model`在文本世界游戏等任务中优于标准LLM，还在说服任务中展示了其语言能力的优势。同时，模型可以容纳多样甚至低质量的数据，在政策对齐上表现更好。这种分离建模方式，使得RL对齐过程中语言能力的退化问题得到缓解，并且能够高效利用探索和利用的策略优化过程。

## vLLM源码之分离式架构

https://zhuanlan.zhihu.com/p/1933647687

本文分析了vLLM框架中的分离式架构原理，重点介绍了Proxy API、`prefill`和`decode`的模块协作，及其在推理过程中对计算任务的分离。当前的vLLM社区实现了简单的分离式架构，代码简洁，适合初学者学习。架构整体流程包括：请求首先进入Proxy API server，经过`prefill`阶段生成KV cache，随后转发至`decode`阶段进行进一步处理。Proxy API server最终将所有token结果从`decode`中获取，`prefill`仅负责生成KV cache。

技术细节包括：

1. **核心组件：** vLLM `prefill`和`decode`阶段通过通信通道（`kv_pipe`）和缓存（`kv_buffer`）交换计算结果。`kv_pipe`负责分发和接收张量（`Torch`的`Tensor`），`kv_buffer`则进一步抽象处理KV缓存，如插入、删除等操作。

2. **模型执行流程：** `Prefill`阶段通过`send_kv_caches_and_hidden_states`发送KV cache和隐藏状态，`decode`阶段通过`recv_kv_caches_and_hidden_states`接收这些数据，后续用于解码token。此分离式架构在vLLM推理中实现了`prefill`和`decode`的独立处理。

3. **通信与调度：** `kv_pipe`采用异步发送机制，`prefill`端会提前记录元数据（数据类型、维度）以便`decode`阶段能够正确接收与处理数据。

4. **缓存管理：** 在`prefill`过程中，缓存会被持续插入，而后台线程通过`drop_select_handler`处理这些缓存，并与`decode`的请求进行配对，实现解码操作。

该分离式架构的实现是一个基础版本，还没有完全实现`layer-wise`通信、前缀缓存等功能。未来版本可能会进一步优化性能与可扩展性。

## Mooncake：将 P / D 分离进行到底

https://zhuanlan.zhihu.com/p/1711346141

这篇内容深入探讨了Mooncake框架中的P/D（`Prefill`/`Decode`）分离技术，特别是在大规模分布式推理系统中的应用和优化。作者首先介绍了P/D分离的几个层级，从单卡融合到在异构集群上的完全分离，并详细解释了每个层级的技术特点及其实现难点。Mooncake通过彻底分解硬件资源（如CPU、DRAM、SSD、RDMA）建立资源池，并设计了高度优化的调度器（`Conductor`），以最大化系统的资源利用率。

技术细节中提到，`KV Cache`在`Prefill`和`Decode`阶段的传输是Mooncake的核心挑战之一，优化方法包括尽可能复用`KV Cache`和增大`batch`内的`token`数以提升`Model FLOPs Utilization`（`MFU`）。然而，这也带来了一些权衡问题，比如`TTFT`（Time to First Token）和`TPOT`（Time per Output Token）的平衡。此外，Mooncake采用了`chunked pipeline parallelism`（`CPP`）技术，通过将长序列请求分解为多个`chunk`，实现跨节点的并行计算，以减少网络开销并提高`MFU`。

在服务超载时，Mooncake实现了`early rejection`策略，通过预测下一阶段的服务器负载，尽早拒绝可能无法完成的请求，从而减少资源浪费。为了进一步提升效率，Mooncake团队还开发了基于启发式的热块迁移方案，优化`KV Cache`的分布。
