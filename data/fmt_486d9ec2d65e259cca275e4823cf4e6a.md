## RAG 的价值与应用

- **提高准确性：** 基于检索到的事实回答，减少捏造信息的可能。
- **知识时效性：** 可以接入实时更新的数据库或文档库。
- **私有数据利用：** 让模型能回答关于特定领域或内部文档的问题。
- **可解释性：** 可以追溯答案来源于哪些检索到的信息。
- **常见应用：** 企业智能问答机器人、基于文档的摘要生成、客服助手、个性化内容推荐等。

## 简化与局限

这个示例非常基础，实际的 RAG 系统通常更复杂，涉及：

- 文档预处理与分块（`Chunking`）：将长文档切分成合适大小、包含连贯信息的块。
- 向量数据库（`Vector Database`）：使用如 `Faiss`、`Milvus`、`ChromaDB`、`Pinecone` 等专门的数据库来高效存储和检索大量的向量。
- 检索策略：可能需要检索多个（`Top-K`）相关块，并进行排序或合并。
- 更复杂的提示工程：设计更精妙的提示来指导模型如何结合上下文。
- 无相关信息处理：当检索不到相关信息或相似度很低时，需要有备用策略（如直接回答或告知用户无法回答）。

# 实操项目：构建基于本地知识库的智能客服助手

## 项目需求描述

我们需要构建一个智能问答系统，充当“易速鲜花”的客服助手。该系统应具备以下能力：

1. **知识来源：** 能读取并理解指定本地文件夹（`./OneFlower/`）下的多种格式文档（`.txt`、`.md`、`.pdf`、`.docx`），这些文档构成了客服的知识库。

2. **信息处理：** 自动将文档内容分割成合适的知识片段（`Chunk`），并利用硅基流动（Silibase Flow）提供的 `BAAI/bge-m3` 嵌入模型将这些片段转换为向量。

3. **持久化存储：** 将知识片段及其向量索引存储在本地的 `ChromaDB` 向量数据库中，以便快速检索，并且只在数据库为空时进行首次索引。

4. **智能问答：**
   - 提供一个简洁的 `Gradio` Web 界面，供用户输入问题。
   - 接收用户问题后，使用相同的嵌入模型将其转换为向量。
   - 在 `ChromaDB` 中检索与问题向量最相似的 Top-K 个知识片段。
   - 对检索结果进行简单的相关性过滤，剔除可能不相关的片段。
   - 将检索到的相关信息作为上下文，连同用户原始问题一起，提交给 DeepSeek 的 `deepseek-chat` 大语言模型。
   - 由 DeepSeek 模型生成基于所提供知识的回答。
   - 若知识库中未找到相关信息，应能恰当回复。

5. **用户体验：** 界面简洁易用，能反馈处理状态和最终结果。

## 实现思路分析

我们将按以下步骤实现该系统：

### 环境设置

- 安装所需 Python 库：`openai`、`numpy`、`chromadb`、`python-dotenv`、`gradio`、`PyMuPDF`、`python-docx`。
- 配置环境变量：`SILICONFLOW_API_KEY`（硅基流动）和 `DEEPSEEK_API_KEY`。

### 全局配置

定义常量，如 API 地址、模型名称、数据库路径、知识库目录、检索数量、分块设置等。

### 核心函数实现

- `initialize_chromadb()`：初始化 `ChromaDB` 客户端，加载或创建指定名称的 `Collection`。
- `load_and_chunk_data(data_dir)`：遍历指定目录，读取支持的文件类型，提取文本内容，按段落分割成文本块（`chunks`），过滤掉过短的块，并为每个块生成元数据（来源文件名）和唯一 `ID`。
- `get_embeddings_from_silibase(texts)`：创建一个函数，使用配置了硅基流动 API Key 和 URL 的 `openai` 客户端（`client_sf`）调用 `embeddings.create` 接口，指定模型为 `BAAI/bge-m3`，获取文本列表的嵌入向量。包含错误处理。
- `index_knowledge_base(chunks, metadatas, ids)`：调用 `get_embeddings_from_silibase` 获取所有 `chunks` 的向量，然后将文本、向量、元数据和 `ID` 批量添加到 `ChromaDB` `Collection` 中。包含对嵌入失败的检查。
- `get_rag_answer(query)`：（`Gradio` 接口调用的核心函数）
  - 获取用户查询 `query`。
  - 调用 `get_embeddings_from_silibase` 获取查询的嵌入向量。
  - 使用查询向量在 `ChromaDB` `Collection` 中执行 `query`，获取 Top-K（`N_RESULTS_RETRIEVAL`）个最相似的文档及其距离（`distance`）。
  - 对检索结果进行相关性过滤：设定一个距离阈值（`distance_threshold`），只保留距离小于该阈值的文档作为有效上下文。（注意：对于余弦距离，距离越小越相似，范围通常 0 到 `sqrt(2)`）。
  - 格式化有效上下文，准备默认的“未找到信息”文本。
  - 构建 `Prompt`，将上下文和用户问题清晰地呈现给 `LLM`，并指导其如何回答。
  - 使用配置了 DeepSeek API Key 和 URL 的 `openai` 客户端（`client_ds`）调用 `chat.completions.create` 接口，指定模型为 `deepseek-chat`，发送构建好的 `Prompt`。
  - 返回 `LLM` 生成的回答，包含对 API 调用错误的 graceful handling。

### 主程序逻辑（`if __name__ == "__main__":`）

- 加载环境变量。
- 初始化 `ChromaDB`。
- 检查 `Collection` 是否为空，如果为空则执行一次性的加载、分块和索引流程。处理索引失败的情况。
- 检查必要的 `API Key` 是否配置。
- 启动 `Gradio` 界面，将其 `fn` 参数指向 `get_rag_answer` 函数。
