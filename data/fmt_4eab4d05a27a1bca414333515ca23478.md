
# RAG 从原理到入门

> 来源：[https://qqs7y1hozd1.feishu.cn/docx/VClQdpbT1oP8FKxiDIUchxHwnzc](https://qqs7y1hozd1.feishu.cn/docx/VClQdpbT1oP8FKxiDIUchxHwnzc)

模型算法的进步、基础模型的发展以及高质量数据集的获取推动了人工智能生成内容（AIGC）的演变。尽管 AIGC 取得了显著的成功，但它仍面临一些挑战，例如知识更新、处理长尾数据、减轻数据泄露风险以及管理高昂的训练和推理成本。

检索增强生成（RAG）最近作为一种应对这些挑战的范式出现。特别是，RAG 引入了信息检索过程，通过从可用的数据存储中检索相关对象来增强生成过程，从而提高了准确性和鲁棒性。

在本文中，将全面回顾将 RAG 技术整合到 AIGC 场景中的现有努力，根据检索器如何增强生成器对 RAG 的基础进行了分类，提炼了各种检索器和生成器增强方法的基本抽象。统一的视角涵盖了所有 RAG 场景，阐明了有助于未来进展的关键技术和进步，总结了 RAG 的附加增强方法，以促进 RAG 系统的有效工程和实施。

## 简介

> 近年来，人工智能生成内容（AIGC）引起了广泛关注。各种内容生成工具被精心设计，以生成涵盖多种模态的多样化输出，如用于文本和代码的 `GPT` 系列和 `LLAMA` 系列的大型语言模型（LLMs），用于图像的 `DALL-E` 和 `Stable Diffusion`，以及用于视频的 `Sora`。术语“AIGC”强调内容是由先进的生成模型生成的，而不是人类或基于规则的方法。这些生成模型通过利用新颖的模型算法、基础模型的爆炸性规模以及大量高质量数据集，取得了显著的性能表现。

具体来说，序列到序列的任务已经从使用 `LSTM` 网络过渡到基于 `Transformer` 的模型，而图像生成任务也从生成对抗网络（`GANs`）转向潜在扩散模型（`LDMs`）。值得注意的是，基础模型的架构从最初包含数百万参数，现已增长到数十亿甚至数万亿参数。这些进步还得益于丰富的高质量数据集的可用性，这些数据集提供了大量的训练样本以充分优化模型参数。

信息检索是计算机科学领域内的另一项重要应用。与生成不同，检索的目标是从庞大的资源池中定位相关的现有对象。检索的最常见应用在于网络搜索引擎，其主要任务是文档检索。

一个典型的 RAG 过程如图所示。

> 给定一个输入查询，检索器识别出相关的数据源，检索到的信息与生成器互动，以改进生成过程。

根据检索结果如何增强生成，可以划分出几种基础范式（简称为“基础”）：

1. 它们可以作为增强的输入提供给生成器
1. 它们可以在生成的中间阶段作为潜在表示加入
1. 它们可以以 `logits`（对数几率）的形式对最终生成结果做出贡献
1. 它们甚至可以影响或省略某些生成步骤

尽管近年来关于 RAG 的研究快速增长，应用也在蓬勃发展，但目前尚缺乏一份系统性的综述，涵盖所有基础、增强方法及其应用，这阻碍了该领域的发展。

一方面，缺乏对 RAG 基础的讨论显著削弱了该领域研究的实际价值，使 RAG 的潜力未得到充分挖掘。尽管大多数研究兴趣，特别是在大型语言模型（LLM）研究人员中，集中于基于查询的文本生成任务中的 RAG，但必须承认，其他 RAG 基础也同样有效，且具有重要的应用潜力和进一步发展的可能性。

另一方面，缺乏对 RAG 应用的综述使得研究人员和从业者忽视了 RAG 在多种模态中的进展，也不了解 RAG 如何被有效应用。尽管文本生成通常被认为是 RAG 的主要应用，但我们强调，RAG 在其他模态中的发展也已开始流行，并取得了有前景的进展。某些模态与检索技术有着丰富的历史渊源，为 RAG 注入了独特的特性。受此启发，本文的目标是呈现一份全面的综述，提供 RAG 的系统性概览。

## RAG

### RAG 架构

#### A. 概述

整个 RAG 系统由两个核心模块组成：检索器、生成器。

检索器从数据存储中搜索相关信息，而生成器则生成所需的内容。

> RAG 过程如下展开：

+ （i） 检索器首先接收输入查询并搜索相关信息
+ （ii）然后，通过特定的增强方法将原始查询和检索结果输入生成器
+ （iii）最后，生成器生成所需的结果

#### B. 生成器

> 在 RAG 系统中，生成模块起着至关重要的作用，不同的生成模型应用于不同的场景，如用于文本到文本任务的 `Transformer` 模型，用于图像到文本任务的 `VisualGPT`，用于文本到图像任务的 `Stable Diffusion`，用于文本到代码任务的 `Codex`。

这里介绍四种在 RAG 中常用的典型生成器：`Transformer` 模型、`LSTM`、扩散模型和 `GAN`。

![](img/178e781fcad653f7d6129a072fe9ba7a.png)

### Transformer 模型

`Transformer` 模型是自然语言处理（NLP）领域中表现最好的模型之一，由自注意力机制、前馈网络、层归一化模块和残差网络组成。在每个生成步骤中，通过对从标记化和嵌入生成的潜在表示序列执行词汇分类，最终输出序列。

### LSTM

长短期记忆（`LSTM`）是一种特殊的递归神经网络（RNN）模型。它通过引入单元状态和门控机制，解决了长时间依赖处理中的梯度爆炸/消失问题。该模型包括三个门（输入门、遗忘门和输出门），用于过滤信息，中央的单元状态模块则保留和管理信息。它使用与 `Transformer` 模型相同的词汇分类方法，自回归地生成输出。

### 扩散模型

扩散模型是一类深度生成模型，能够生成逼真且多样化的数据样本（包括图像、文本、视频、分子等），扩散模型通过逐渐向数据中添加噪声，直到数据变得随机，然后逆转过程，从噪声中生成新的数据。这个过程基于概率建模和神经网络。

### GAN

生成对抗网络（`GANs`）是高度期待的深度学习模型，能够模拟并生成逼真的图像、音频和其他数据。典型的 `GAN` 由两个主要组件组成：生成器和判别器。这两个部分通过对抗学习相互竞争，使生成器不断提高生成逼真样本的能力，而判别器则不断提高区分真实和虚假样本的能力。

## RAG 拆解

### A. RAG 基础

根据检索器增强生成器的方式，将 RAG 基础分为四类，如图所示：

![](img/2a54e80c2080089139d2f1c9b1b432ad.png)

#### 1. 基于查询的 RAG

源自提示增强的理念，基于查询的 RAG 将用户的查询与检索到的信息相结合，直接输入到生成器的初始阶段。这种方法在 RAG 应用中非常普遍。在检索之后，获取的内容与用户的原始查询合并，形成复合输入，然后由生成器处理以创建响应。

> 基于查询的 RAG 广泛应用于各种模态：

+ `REALM` 使用双 `BERT` 框架简化知识检索和集成，将预训练模型与知识提取器结合起来。利用 `DPR` 进行信息检索，并使用 `BART` 作为生成器，以有效增强生成
+ `SELF-RAG` 使用一个评估模块来决定是否需要检索。除了与本地生成器兼容外，基于查询的 RAG 还适用于通过 API 调用使用 LLM 的场景
+ `REPLUG` 通过将语言模型视为“黑箱”，有效地将相关外部文档整合到查询中
+ `In-Context RALM` 使用 `BM25` 进行文档检索，并训练一个预测排序器重新排序和整合排名靠前的文档

#### 2. 基于潜在表示的 RAG

在基于潜在表示的 RAG 框架中，检索到的对象作为潜在表示纳入生成模型中。这增强了模型的理解能力，提高了生成内容的质量。

#### 3. 基于 Logit 的 RAG

在基于 `Logit` 的 RAG 中，生成模型在解码过程中通过 `Logit` 整合检索信息。通常，`Logit` 通过简单的求和或模型组合来计算逐步生成的概率。

#### 4. 投机性 RAG

投机性 RAG 寻求通过检索而非纯生成来实现机会，以节省资源并加快响应速度，`REST` 用检索替代了投机性解码中的小模型，使草稿生成成为可能。

+ `GPTCache` 通过构建语义缓存来存储 LLM 响应，从而解决了使用 LLM API 时高延迟的问题
+ `COG` 将文本生成过程分解为一系列复制和粘贴操作，从文档中检索词语或短语而不是生成

总之，投机性 RAG 目前主要适用于顺序数据。它解耦了生成器和检索器，使得可以直接将预训练模型作为组件使用。在这一范式中，我们可以探索更广泛的策略，以有效利用检索到的内容。

### B. RAG 增强方法

增强构建 RAG 系统性方法分为五类：输入、检索器、生成器、结果以及整个流程。

#### 输入增强

输入最初被送入检索器，它对检索阶段的最终结果产生重大影响。在本节中，我们介绍了两种输入增强方法：查询转换和数据增强。

+ 查询转换：查询转换通过修改输入查询来增强检索结果。`Query2doc` 和 `HyDE` 使用原始查询生成一个伪文档，后者被用作检索的查询。伪文档包含更丰富的相关信息，有助于检索到更准确的结果。`TOC` 利用检索到的内容将模糊查询分解为多个清晰的子查询，这些子查询被发送到生成器并聚合生成最终结果。对于复杂或模糊的查询，`RQ-RAG` 将其分解为清晰的子查询以进行细粒度检索，并综合响应以提供对原始查询的连贯答案
+ 数据增强：数据增强在检索前改进数据，包括去除无关信息、消除歧义、更新过时文档、合成新数据等技术。`Make-An-Audio` 使用字幕生成和音频-文本检索为无语言音频生成字幕以减轻数据稀疏性，并添加随机概念音频以改善原始音频。`LESS` 通过分析梯度信息优化下游任务的数据集选择，旨在增强模型对指令提示的响应性能。`ReACC` 通过数据增强（包括重命名和插入无用代码）来预训练代码检索模型。`Telco-RAG` 通过应用“3GPP 规范词汇”并使用路由器模块将其与用户查询匹配，提高了检索准确性

#### 检索器增强

在 RAG 系统中，检索内容的质量决定了输入生成器的信息质量。较低的内容质量会增加模型幻觉或其他性能下降的风险。

+ 递归检索：递归检索是指执行多次搜索以检索更丰富和更高质量的内容。`ReACT` 使用 `Chain-of-Thought`（`CoT`）将查询分解以进行递归检索，提供更丰富的信息。`RATP` 使用蒙特卡罗树搜索进行模拟，以选择最佳检索内容，然后将其模板化并转发给生成器输出
+ 块优化：块优化是指调整块大小以改进检索结果。`LlamaIndex` 结合了一系列块优化方法，其中之一基于“小到大”原则。其核心概念是定位更细粒度的内容，但返回更丰富的信息。例如，句子窗口检索提取小的文本块并返回围绕检索段的相关句子的窗口。在自动合并检索中，文档被排列成树结构。该过程通过首先获取子节点来检索父节点，从而封装其子节点的内容。为了应对缺乏上下文信息的问题，`RAPTOR` 使用递归嵌入、文本块的聚类和总结，直到进一步聚类不可行，从而构建多层次的树结构。`Prompt-RAG` 通过预生成目录来增强检索准确性，使模型能够根据查询自主选择相关章节

![](img/80bd82c8e5299fa625bdc637e271cdd3.png)

+ 检索器微调：在 RAG 系统中，检索器是核心组件，依赖于高效的嵌入模型来表示相关内容并输入生成器，从而增强系统性能。此外，具有强大表达能力的嵌入模型可以使用特定领域或任务相关的数据进行微调，以提高在目标领域的表现。`REPLUG` 将语言模型视为黑箱，并根据最终结果更新检索器模型。`APICoder` 使用 `Python` 文件和 API 名称、签名、描述微调检索器。`EDITSUM` 微调检索器以减少检索后摘要之间的 `Jaccard` 距离。`SYNCHROMESH` 在损失函数中添加 `AST` 的树距离，并使用目标相似性调优（`TST`）微调检索器。`R-ConvED` 使用与生成器相同的数据微调检索器
+ 混合检索：混合检索指的是同时使用多种检索方法或从多个不同来源提取信息。`RAP-Gen`、`BlendedRAG` 和 `ReACC` 使用了密集检索器和稀疏检索器以提高检索质量。`Rencos` 在语法级别上使用稀疏检索器检索相似的代码片段，并在语义级别上使用密集检索器检索相似的代码片段。`BASHEXPLAINER` 首先使用密集检索器捕捉语义信息，然后使用稀疏检索器获取词汇信息。`RetDream` 先通过文本检索，再通过图像嵌入进行检索。`CRAG` 具有一个检索评估器，可以评估文档与查询的相关性，根据置信度提供三种检索响应：如果准确则直接使用结果进行知识精炼，如果错误则进行网络搜索，对于模棱两可的情况采用混合方法。通过在检索阶段引入 `DKS`（密集知识相似性）和 `RAC`（检索器作为答案分类器）来改进问答系统，评估答案的相关性和知识的适用性。`UniMS-RAG` 引入了一种新型标记，称为“行为标记”，该标记决定从哪个来源检索信息。通过整合草图和文本进行细粒度检索，改进了图像检索的效果

#### 重排序

重排序技术指的是对检索到的内容进行重新排序，以实现更大的多样性和更好的结果。

+ `Re2G` 在传统检索器之后应用了一个重排序模型，以减少将文本压缩为向量所导致的信息损失。`AceCoder` 使用选择器对检索到的程序进行重排序，以减少冗余程序并获取多样化的检索程序。`XRICL` 在检索后使用基于蒸馏的示例重排序器。`Rangan` 使用量化影响测量评估查询与参考之间的统计偏差，以评估数据子集的相似性并重排序检索结果。`UDAPDR` 使用 LLMs 生成合成查询，训练特定领域的重排序器，然后应用多教师知识蒸馏来开发一个一致的检索器。`LLM-R` 通过使用静态 LLM 进行文档排序和奖励模型训练来逐步优化其检索器，每个训练周期逐渐改善检索器，实现渐进优化。Finardi 等人将互惠排名整合到检索过程中，以增强文本块的相关性，并使用 `monoT5` 作为重排序器来优化结果质量。将重排序模块整合到他们的端到端 RAG 系统中，提高了 LLMs 的检索质量和事实准确性

#### 检索转化

检索转化涉及重构检索到的内容，以更好地激发生成器的潜力，从而改善输出。

+ `FILCO` 高效清除检索文本中的多余材料，只保留相关的支持内容，从而简化生成器的任务并促进准确的答案预测。`FiD-Light` 最初使用编码器将检索到的内容转换为向量，然后对其进行压缩，显著减少延迟时间。`RRR` 通过模板将当前查询与每轮中的前 k 个文档整合在一起，然后通过预训练的 LLMs（如 `GPT-3.5-Turbo` 等）重新构建这些文档

#### 其他方法

除了上述优化方法，还有一些其他针对检索过程的优化方法。

+ 例如：元数据过滤是一种帮助处理检索文档的方法，它使用元数据（如时间、目的等）过滤检索到的文档，以获得更好的结果。`GENREAD` 和 `GRG` 引入了一种新方法，其中通过提示 LLM 生成文档以响应给定问题来取代或改进检索过程。`Multi-Head-RAG` 采用多个嵌入模型将相同的文本块投射到不同的向量空间，并利用多头注意力层捕捉不同的信息方面，从而提高了检索过程的准确性
