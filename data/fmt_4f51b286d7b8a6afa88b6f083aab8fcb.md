## 新闻看了这么久，麻了没？

从去年11.30号到现在也有差不多半年时间了，其实最开始还只是在科技圈小范围火热。直到今年2.2号因为一个"关于`ChatGPT`两个月达到上亿月活，成为历史上最快蹿红应用″的新闻才真正让`ChatGPT`破圈，进入大众视野。不过这也才过了大概不到4个月，但是你是不是已经有很强的麻木感了呢？为啥呢？

## 我的解法：建立自己的理解框架

下面以文本生成领域为例，说明我自己是如何吸收这些海量涌入的AI发展的。

> 为什么挑文本生成领域：

+   文本是当前多种信息承载形式中压缩率最高的信息承载方式，文本更合当下智能最高的人类自然表达最方便简洁的形式，更容易实现人机协作，

+   文本暂时最适合作为各种其他模态的转换媒介，你听了很多文生图，文生视频，文生音频，文生一切，所以在多模态成熟前是最有杠杆效应的领域，比如我不会`stable diffusion`的提示词但是可以通过`GPT`提示词生成个中等水平版本

+   因为这个领域场景足够多，大家都很卷，有足够多应用可参考，容易产出相关结论

### 应用方式

#### `ChatGPT`

这里的`ChatGPT`不专指open AI提[💬GPT教程](https://seigy6zzam.feishu.cn/wiki/wikcnGJ7hLs6GzD8IasIKSai7cg#KeAcdCQg0ouU8IxIhbBcnXmRnxc)的产品，虽然因为先发优势，基本上在在很多人的心里，现在这个`ChatGPT`的名字就已经代表了他们的产品，但是就像这里分享的一样  ，其实针对Chat跟`GPT`我们应该分开来看，Chat只是现在最火热的交互形式，而这种形式的火热主要因为他的交互方式更符合人类通过自然语言沟通的习惯，就像IM聊天工具的火热一样，在社交和办公场景都变成了标配。而这次更加革命性的突破在于`GPT`的部分。

因此我愿称所有在大语言模型之上直接增加聊天交互应用入口的都算作这种方式，这种方式的应用能力的上限主要在于依赖的`GPT`模型的能力上限，因Chat部分，我们常用的IM工具都已经卷到不行了，所以其实不管是基于别人大模型API还是开源模型自己炼丹，接入了现存的IM工具也算是这种类型。

总结下，这种类型就是就是下面的公式

> `Chat`聊天界面 + `GPT` = `ChatGPT`

这种类型大家比较纯粹，主要在卷的主要在下面三个方面

+   **智能引擎：**基于最底层`GPT`模型的智能程度（**拉开差距的部分**）

+   **场景模板：**提供丰富的内置场景模板或者建立社区，通过UGC生成更多的场景模板（其实就是预制`prompt`，感觉国外不重视这块，给了`prompt`分享社区一些机会）

+   **对话功能：**对齐原生IM工具的原生聊天功能（如果是独立新的产品，基本都比较简单，钉钉和飞书说会集成，除了分享呢能力，原生对话体验都比这些独立新产品高很多个级别）

#### 应用市场

其实即使是只需要自然语言聊天就可以跟最新的`GPT`模型沟通，获得解决问题的思路和具体方法，但是仍然存在一定的门槛，这个门槛我觉得可能在于大家对于之前搜索引擎的使用惯性，觉得类似搜索引擎对话`GPT`主要对于问题关键词的提取就够了，但是其实如果希望`GPT`给更加详细的结果，需要提供包括角色、信息上下文，输出格式设定等更加详细信息。另外可能就因人而异了，针对特定场景可能很多人并不知道应该如何提问，或者提什么问题来解决问题。我觉得可能会通过下面这几个痛点展开：

+   **“被集成”的****工作流****生态：**传统做自动化的思路主要是RPA或者是说叫BPM，因为很多时候我们要完成一个工作，单独一个平台工具或者服务是不够的，所以可以以绘制流程的方式，来将多个原子的服务通过我的任务目标串联起来，形成一个工作流，之前这种工具面向企业用户比较多就叫BPM，后来很多公司发现了C端用户或者本身不了解BPM的非科技公司这块的需求，包装出了RPA的概念，帮助他们完成工作流程的自动化。之前`OpenAI`插件生态出来的时候，我本来推测对于他们的冲击会很大，但是考虑到现在`GPT`对于工具使用的训练样本仍然没有那么充分，其实还有一定的生存空间，特别发现第一批内测插件有个叫`zapier`的公司，就是做这个的。所以发现可能另外的出路，那就是把`OpenAI`的能力作为传统RPA流程绘制的一个节点。但是这种形式毕竟是一种对现有模式的改良，其实如果大家对于`prompt`工程有更深度的应用会发现其实单轮对话的结果未必是最优的，所以其实可能需要`prompt`的多轮流程设计，而且这次`GPT`的火热也带动了之前其他AI垂直能力的繁荣，比如文生图，`TTS`，`ASR`，`DeepFace`等，因此串联多个原子的AI服务，也可以定义所谓新的“AI流程引擎”。

总结一下，我觉得针对垂直领域定义的`GPT`应用可能主要会有下面四种形式，而且现在基本上市面上都已经有公司在探索，而且有些可能已经拿到不错的收入

> 应用市场形式：

+   **投喂定制数据：**通过`Embedding`的技术，再重点自己`finetune`开源模型给通用`GPT`模型领域知识

+   **定制`Prompt`：**通过设定角色，给定上下文以及指定输出格式的更详细`prompt`定制小场景AI

+   **插件市场：**通过定制对`GPT`进行`SEO`，在`GPT`完成任务的细分流程任务中，提供原子能力集成，扩展`GPT`自身的能力边界，来实现通过自然语言对话解决问题

+   **工作流****集成：**将这波AI热潮涌现的各种新的能力包装成原子服务，然后通过传统工作流可视化拖拽的方式定义AI工作流，也可以作为原子节点集成到现存RPA工具中

> 基本上面的能力不同产品都是分开来做的，哪怕是有部分产品都有涉及，也是会分成不同的类型，有个别会融合多个，比如我的目标就是做一个AI，上面这些都只是生产AI的手段，我可以既给他我的自定义`prompt`又可以喂知识给他，还可能我只选择某个手段，其他默认关闭，但是暂时还没有看到类似的产品

#### 工作台

最近的AI产品繁荣发展，各种网页或者客户端的工具都在涌现，但是大部分都是实现相对单一的目标，但是比如一些复杂性工作，比如作为一个自媒体视频的up主，如果希望制作一个视频，我需要做的事情包括不限于：

+   书写文字版逐字稿

+   结合逐字稿收集图片或者视频素材

+   在视频编辑器比如必剪，进行素材编辑调整以及插梗

+   如果要自己发声需要根据逐字稿和素材录音，如果使用逐字稿自动用AI发声也需要对齐音频跟视频的时间轴

+   选择合适的背景音乐，调整到合适的音量

+   检验视频效果以及可能的内容风险

+   制作引发用户点击的封面图片

+   思考吸睛的视频标题

+   选择合适的视频标签

+   整理有用的视频描述

+   上传视频内容查看实际上传效果和shenhe结果

这些工作其实现在很大一部分工作都可以通过AI辅助来完成，但是因为不同场景使用的工具不一样（因为你现在还不能实现，只通过告诉`ChatGPT`“给我发一个B站热门视频”，视频就发布了），如果要实现上面的工作，你需要在多个平台工具之间切换，而工作台的思路，其实就是把上面提到的分散的`ChatGPT`和小应用整合在一起，提供一站式体验，无需在多个tab切换，通过自定义布局并且跨网页共享中间数据，这块其实门槛比较低，之前卷的比较厉害的低代码开发平台理论上都可以做到这个事情

### 应用形态

| 应用形式 | 核心特色 | 场景劣势 |

| --- | --- | --- |

| 浏览器插件 | 可以定制现存三方网页应用界面，实现更优融合体验，无需用户cookie整合三方网页接口定制集成专制界面 | 用户打开率未必会很高，局限在浏览器中使用，虽然基本 chrome 内核大一统，但是还是有不少兼容性问题要解决 |

| 桌面应用 | 不局限在网页使用，可以通过全局悬浮，快捷键或者快速启动栏调起，理论可以覆盖浏览器插件专属界面场景 | 覆盖不了浏览器增强三方网页应用的场景，因为要增强功能需要直接全部重写界面 |

| 网页应用 | 容易通过链接分享和访问，适合传播内容 | 会存在一些特定的限制，比如要集成多个模型定制界面的话，需要特别开发解决跨域名访问的接口 |

| 手机应用 | 在线率高，不可能一直带电脑，但是一定带手机 | 不过基本可能主要局限在闲聊和单次使用的小应用浅层使用场景，或者参考桌面的in cotext调起或者全局通知栏应用，但始终感觉不是深度应用场景 |

| 各种IM集成 | 在形式上就是Chat，常规聊天功能齐全 | IM平台每个形式都不一样， 暴露的方式也不同，需要大量的适配工作，IM内信息孤岛一般不提供跨应用分享 |
