
# 04-每阶段核心提示词-复制即驱动

> 来源：[https://kq4b3vgg5b.feishu.cn/docx/WkBXd2wu0ocKsmxZ5LYcZjzPnYd](https://kq4b3vgg5b.feishu.cn/docx/WkBXd2wu0ocKsmxZ5LYcZjzPnYd)

## AI 全栈交付 · 每阶段核心提示词

> 配套视频：《从"会用工具"到"能交付项目"——AI 驱动全栈开发实战》

> 作者：木羽Cheney （VibeCoding 实战课主讲老师）· 赋范大模型技术社区

> 用法：按路线图的 6 个阶段，每阶段复制对应的提示词给 Claude Code / Cursor

---

### 使用原则

1.  每个阶段一条核心提示词，不要一次给 AI 太多任务

1.  确认当前阶段产出后再进入下一阶段，不要跳步

1.  提示词中的 `[方括号]` 部分需要替换为你的实际内容

1.  每条提示词都附带"验收标准"，告诉 AI 什么算做完

---

### 阶段 1 提示词：技术调研

```
我要做一个 [项目描述，例如：企业内部知识库问答系统]。

请帮我做技术选型调研，对比至少 2 套可行方案，每套方案覆盖：
- 前端框架
- 后端框架
- 数据库
- 部署方式

对比维度包括：
1. 学习成本（我是 [你的技术背景，例如：有 Python 基础但不会前端] ）
2. AI 编程工具对该技术栈的支持程度
3. 开发效率（MVP 阶段，不是生产级）
4. 社区活跃度和文档质量

最后给出你的推荐方案和理由。
如果有"不推荐但很多人用"的选项，也说明为什么不推荐。
```

**验收**：拿到选型报告后，确认你理解并认同选型理由。不认同的地方追问 AI。

---

### 阶段 2 提示词：生成规范文档

```
技术栈已确定：
- 前端：[例如：Next.js 14 + Tailwind CSS]
- 后端：[例如：Next.js API Routes]
- 数据库：[例如：SQLite + Prisma]
- AI/LLM：[例如：OpenAI 兼容 API，接入通义千问]

请生成一份项目规范文档，必须包含以下章节：

1. 项目概述（名称、一句话描述、目标用户、核心功能 3 条）
2. 技术栈表（锁定版本号）
3. 目录结构（精确到核心文件）
4. API 接口定义（至少 3 个核心接口，每个写明请求体和响应体的完整字段）
5. 统一响应格式（成功和错误各一个模板）
6. 数据模型（每张表的字段、类型、约束）
7. 架构约束（必须遵守的规则 5 条 + 非目标/本阶段不做的事 5 条）
8. 启动命令
9. 环境变量清单

输出格式为 Markdown。我会把这个文档放到 `CLAUDE.md` 中，
后续所有开发会话都必须遵循这份文档。

特别注意"非目标"部分——写清楚本阶段不做的事，
防止你在后续开发中自作主张添加功能。
```

**验收**：

+   每个 API 接口的请求体和响应体字段是否完整？

+   "非目标"是否覆盖了你不想做的功能？

+   启动命令是否可执行？

---

### 阶段 3 提示词：搭后端 MVP

```
请严格按照 `CLAUDE.md` 中的规范文档，搭建后端 MVP。

要求：
1. 按目录结构创建文件
2. 实现数据库 Schema（按 §5 数据模型定义）
3. 实现以下核心 API 接口（按 §4 接口定义）：
   - [接口1名称]
   - [接口2名称]
   - [接口3名称]
4. 每个接口的响应格式必须严格遵循 §4.1 的统一格式
5. 创建种子数据（至少 3 条测试数据）
6. 创建 `.env.example` 文件

实现完成后，自行测试每个接口：
- 用 `curl` 或 `fetch` 发送请求
- 确认响应格式和字段名与规范文档完全一致
- 如果有不一致的地方，以规范文档为准修改代码

不要做规范文档中"非目标"部分列出的任何功能。
```

**验收**：

+   `npm run dev` 能正常启动？

+   用 `curl` 测试每个接口，返回格式和规范文档一致？

+   种子数据能正常查询？

### 阶段 4 提示词：输出 PRD

```
后端 MVP 已搭建完成，以下 API 接口可用：
[列出你已验证通过的接口，例如：
  - `POST /api/chat` — 问答
  - `POST /api/upload` — 上传文档
  - `GET /api/documents` — 获取文档列表
]
```

请基于这些已有的后端能力，输出一份 PRD（产品需求文档），包含：

1. 页面清单（每个页面的用途和 URL 路径）
2. 每个页面的核心元素（标题、输入框、按钮、列表等）
3. 每个页面的数据来源（调用哪个 API、展示哪些字段）
4. 页面间的跳转逻辑（用户在 A 页面点什么按钮跳到 B 页面）
5. 交互行为描述（按钮点击→调接口→展示结果→错误处理）
6. 不需要做的页面/功能（和规范文档的"非目标"保持一致）

每个页面的描述要详细到：前端开发时只看 PRD 就知道该做什么，
不需要再回头问后端"这个接口返回什么字段"。
```

**验收**：

+   每个页面都标注了数据来源（对应的 API 端点）？

+   页面间跳转无死路？

+   前端开发时是否可以只看 PRD 就开始做？

### 阶段 5 提示词：前端开发

```
请严格按照 PRD 文档和 `CLAUDE.md` 规范，开发前端页面。

工作方式：
1. 按 PRD 中的页面清单，逐页开发（不要一次全做）
2. 每开发完一个页面，立刻对接后端 API 验证：
   - 发送真实请求（不要用 Mock 数据）
   - 确认页面能正确展示后端返回的数据
   - 确认错误状态有合理的提示（不能白屏）
3. 验证通过后再开发下一个页面

必须处理的三种状态：
- 加载中状态（Skeleton 或 Loading 指示器）
- 空数据状态（友好的空状态提示，不是空白页面）
- 错误状态（用户可理解的错误消息，不是报错堆栈）

技术约束：
- UI 组件只用 `CLAUDE.md` §2 中指定的组件库
- 不引入规范文档中没有的依赖
- 不实现"非目标"中列出的功能

每完成一个页面告诉我：
1. 页面 URL
2. 对接了哪些 API
3. 是否有未解决的问题
```

**验收**：每个页面手动操作一遍，确认数据展示正确、交互流畅。

### 阶段 6 提示词：联调验证

```
前后端都已开发完成。请做一次完整的端到端验证：

【功能验证】
1. 按照核心业务流程，从用户视角完整走一遍：
   [描述你的核心流程，例如：
   打开首页 → 上传一个文档 → 等待处理完成 → 
   在问答页提问 → 确认收到带引用的回答]
2. 每一步记录：操作→预期结果→实际结果→是否通过

【边界验证】
3. 测试以下边界情况：
   - 空输入（提交空表单会怎样？）
   - 超长输入（输入 5000 字的问题会怎样？）
   - 重复操作（连续点击两次提交会怎样？）
   - 后端不可用（停掉后端，前端的错误提示是否友好？）

【部署准备】
4. 确认以下文件完整：
   - `.env.example`（包含所有需要的环境变量）
   - `README.md`（安装步骤 + 启动命令 + 功能说明）
   - `package.json` scripts 中有 `dev/build/start` 命令

给我一个验证报告：通过/未通过/需修复，每项标注状态。
```

**验收**：所有核心流程通过 + 边界情况有合理处理 + 部署文件齐全。

### 附加提示词：中途纠偏

当 AI 执行过程中跑偏了，用这条：

```
停一下。你刚才做的 [描述问题] 偏离了规范文档的要求。

规范文档 §[章节号] 中明确规定了 [正确的做法]。
请撤销刚才的修改，按规范重新来。

不要改动 [不应该被改动的文件/模块]。
```

**关键**：你不需要停掉会话重来。Claude Code 支持中途打断和纠偏，直接在当前会话中输入新指令即可。

### 提示词使用流程图

```
阶段1 技术调研提示词
  ↓ 产出：选型报告 
阶段2 规范文档提示词
  ↓ 产出：CLAUDE.md 
阶段3 后端MVP提示词
  ↓ 产出：可运行后端 
  ↓ （如果跑偏 → 纠偏提示词）
阶段4 PRD提示词
  ↓ 产出：页面清单+交互说明 
阶段5 前端开发提示词
  ↓ 产出：完整前端 
  ↓ （如果跑偏 → 纠偏提示词）
阶段6 联调验证提示词
  ↓ 产出：验证报告 
  ↓
   项目交付完成
```
