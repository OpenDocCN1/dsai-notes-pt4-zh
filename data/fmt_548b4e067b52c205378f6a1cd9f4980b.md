
### 5.5.1 Temperature 参数

- `Temperature` 接近 0（如 0.1-0.3）：大幅增加高概率 token 的权重，输出更加确定和一致
- `Temperature = 1.0`：使用原始概率分布，平衡随机性和确定性
- `Temperature > 1.0`：平滑概率分布，增加低概率 token 被选中的机会，输出更加多样和创意

#### 实际效果对比

以“完成句子：人工智能的未来是”为例：

```
# Temperature = 0.0（最确定）
response = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=100,
    temperature=0.0,
    messages=[{"role": "user", "content": "完成句子：人工智能的未来是"}]
)
# 输出（多次运行结果相同）：
# "人工智能的未来是充满希望和挑战的。随着技术的不断进步，AI将在医疗、教育、交通等领域发挥越来越重要的作用..."

# Temperature = 0.5（中等）
response = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=100,
    temperature=0.5,
    messages=[{"role": "user", "content": "完成句子：人工智能的未来是"}]
)
# 输出（每次略有不同）：
# "人工智能的未来是令人兴奋的。我们将看到更智能的助手、更精准的医疗诊断、更高效的生产流程..."

# Temperature = 1.0（最随机）
response = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=100,
    temperature=1.0,
    messages=[{"role": "user", "content": "完成句子：人工智能的未来是"}]
)
# 输出（变化很大）：
# "人工智能的未来是一个充满无限可能的领域。也许我们会看到意识的诞生，或者发现全新的智能形式..."
```

#### 常见误区

1. **误区**：“`Temperature` 越高越好，因为更智能”
   - **真相**：高 `Temperature` 只是增加随机性，不会提高智能水平，反而可能导致输出不连贯

2. **误区**：“所有任务都用 `Temperature = 0` 以确保准确性”
   - **真相**：某些任务（如创意写作）需要适度的随机性，`Temperature = 0` 会让输出过于机械

3. **误区**：“`Temperature` 和 `Top P` 应该同时调整”
   - **真相**：官方建议只调整其中一个参数，不要同时修改

### 5.5.2 Max Tokens 限制

Max Tokens 参数控制模型生成的最大长度，是成本控制和输出管理的关键工具。

#### 参数定义

- **作用**：限制模型生成的最大 token 数量
- **取值范围**：1 - 8,000（Haiku 4.5）、1 - 64,000（Sonnet 4.6）、1 - 128,000（Opus 4.6）
- **默认值**：通常为 4,096
- **重要提示**：模型可能在达到 `max_tokens` 之前就停止生成（遇到自然结束点或 `stop_sequences`）

#### Token 与文本的关系

- **英文**：1 token ≈ 0.75 个单词（即 100 tokens ≈ 75 个单词）
- **中文**：1 token ≈ 0.5-1 个汉字（即 100 tokens ≈ 50-100 个汉字）
- **代码**：1 token ≈ 0.5-1 个字符（取决于语言和格式）

#### 示例

- `"Hello, how are you?"` ≈ 6 tokens
- `“你好，最近怎么样？”` ≈ 8-10 tokens
- `def hello(): print("Hi")` ≈ 12 tokens

#### 成本优化策略

Max Tokens 直接影响输出成本。合理设置可以显著节省开支：

```
# 成本对比（Claude Sonnet 4.6）
# 假设输入 1000 tokens

# 场景 1：Max Tokens = 4096（但实际只需要 200）
# 成本：$0.003（输入）+ $0.003（200 输出）= $0.006
# 浪费：设置过高不会直接增加成本，但可能导致冗余输出

# 场景 2：Max Tokens = 200（精确控制）
# 成本：$0.003（输入）+ $0.003（200 输出）= $0.006
# 优势：避免不必要的长输出

# 场景 3：Max Tokens = 50（过度限制）
# 风险：输出可能被截断，需要重新调用
# 成本：$0.003（输入）+ $0.0008（50 输出）= $0.0038
# 但如果需要重试：$0.0038 × 2 = $0.0076（更贵）
```

#### 最佳实践

1. **根据任务类型设置合理的上限**
   - 不要一刀切地使用最大值
   - 为不同任务类型创建配置模板

2. 使用 `stop_sequences` 提前终止

   ```
   response = client.messages.create(
       model="claude-sonnet-4-6",
       max_tokens=1024,
       stop_sequences=["\n\n---\n\n", "总结:", "结论:"],  # 遇到这些就停止
       messages=[{"role": "user", "content": "..."}]
   )
   ```

3. **监控实际使用情况**

   ```
   response = client.messages.create(...)

   print(f"Input tokens: {response.usage.input_tokens}")
   print(f"Output tokens: {response.usage.output_tokens}")
   print(f"Max tokens: {max_tokens}")
   print(f"Utilization: {response.usage.output_tokens / max_tokens * 100:.1f}%")

   # 如果利用率持续很低（<30%），考虑降低 max_tokens
   # 如果经常达到上限（>90%），考虑提高 max_tokens
   ```

4. **处理截断情况**

   ```
   response = client.messages.create(
       model="claude-sonnet-4-6",
       max_tokens=512,
       messages=[{"role": "user", "content": "写一篇长文章..."}]
   )

   # 检查是否被截断
   if response.stop_reason == "max_tokens":
       print("Warning: Output was truncated. Consider increasing max_tokens.")
       # 可以选择继续生成
       continuation = client.messages.create(
           model="claude-sonnet-4-6",
           max_tokens=512,
           messages=[
               {"role": "user", "content": "写一篇长文章..."},
               {"role": "assistant", "content": response.content[0].text},
               {"role": "user", "content": "请继续"}
           ]
       )
   ```

### 5.5.3 Top P 采样参数

`Top P`（也称为 Nucleus Sampling，核采样）是另一种控制输出随机性的方法，与 `Temperature` 互补但作用机制不同。

#### 参数定义

- **作用**：限制模型只从累积概率达到 `top_p` 的 token 集合中采样
- **取值范围**：0.0 - 1.0
- **默认值**：通常为 1.0（不限制）
- **重要提示**：官方建议只调整 `Temperature` 或 `Top P` 其中之一，不要同时修改

#### 工作原理

`Top P` 通过以下步骤工作：

1. 模型计算所有可能 token 的概率
2. 按概率从高到低排序
3. 累加概率，直到总和达到 `top_p`
4. 只从这个子集中采样，忽略其余 token

#### 示例

假设下一个 token 的概率分布：

- Token A: 40%
- Token B: 30%
- Token C: 15%
- Token D: 10%
- Token E: 5%

`Top P = 0.7`：

- 累积：A（40%）+ B（30%）= 70% ≥ 0.7
- 只从 A 和 B 中选择，忽略 C、D、E

`Top P = 0.9`：

- 累积：A（40%）+ B（30%）+ C（15%）= 85% < 0.9
- 累积：A + B + C + D（10%）= 95% ≥ 0.9
- 从 A、B、C、D 中选择，忽略 E
