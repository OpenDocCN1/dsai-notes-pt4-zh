
## 技能风险与质量考量

存在团队在不了解底层流程的情况下依赖 Skills 的风险。初级 PM 可能会使用"功能规格"Skill，而不学习什么构成了好的规格。

### 质量取决于说明的质量

垃圾进，垃圾出。编写不当的 Skill 说明会产生不一致的结果。这需要深思熟虑的文档。

### 限于可用计划

Skills 仅在 Pro、Max、Team 和 Enterprise 计划上可用。免费层用户无法访问它们。

## 11、PM 的隐私和安全考虑

作为产品经理，我们需要考虑安全影响：

### Skills 可以访问的内容

+ 您对话中的内容
+ 您上传或创建的文件
+ MCP 连接的工具（如果获得许可）
+ 代码执行环境

### 需要小心的地方

+ 不要在 Skill 说明中包含敏感凭证
+ 注意您将哪些机构知识封装到 Skills 中
+ 对于 Enterprise 计划，使用组织范围的 Skills 管理来控制访问
+ 在安装之前从目录中审查 Skills——了解它们的用途

### 最佳实践

+ 仅从受信任的来源安装 Skills
+ 在全组织范围内共享之前审查自定义 Skills
+ 适当使用代码执行沙箱
+ 遵循您公司的 AI 使用和数据政策

Anthropic 对这些风险明显透明，我很欣赏。他们没有美化赋予 AI 扩展能力的力量（和潜在危险）。

## 12、未来：Skills 的发展方向

基于 Anthropic 的路线图信号和当前轨迹，我认为这是发展方向：

### 短期（2025 年）

+ 来自主要 SaaS 公司的更多预构建 Skills
+ 简化的 Skills 创建（需要较少的技术设置）
+ Skills Directory 中更好的发现和搜索
+ 与 Cowork 和 Claude Code 的更紧密集成

### 中期

+ Skills 市场，个人可以在其中分享/销售 Skills
+ AI 辅助 Skills 创建（Claude 帮助您构建 Skills）
+ 跨平台 Skills 采用（其他 AI 工具支持该标准）
+ 特定行业的 Skills 包（PM Skills 包、Legal Skills 包等）

### 长期推测

+ 从使用中学习和改进的 Skills
+ 团队可以贡献和细化的协作 Skills
+ Skills 作为 AI 平台之间的核心差异化
+ Skills 成为我们为特定角色定制 AI 的主要方式

## 13、你应该开始使用 Skills 吗？

这是我的诚实建议：

### 绝对开始，如果

+ 您有经常向 Claude 解释的重复工作流程
+ 您在 Team/Enterprise 计划上，并希望扩展最佳实践
+ 您在从特定领域流程中受益的专业领域工作
+ 您在格式化文档或遵循模板上花费大量时间

### 也许等待，如果

+ 您仍在探索 Claude，尚未建立明确的使用模式
+ 您的工作流程变化太频繁，无法让 Skills 有价值
+ 您在免费计划上（Skills 尚不可用）
+ 您的组织对代码执行有严格的限制

从小开始：不要尝试一次创建 20 个 Skills。选择一个让您烦恼的重复任务。为此创建一个 Skill。使用它一周。完善它。然后移动到下一个。

## 14、我的个人 Skills 设置（作为一个 PM）

为了具体一点，以下是我目前使用的：

### 日常使用

+ “PRD 模板”——我的产品需求文档格式
+ “用户研究综合”——我分析和展示用户见解的方式
+ “利益相关者更新”——每周利益相关者沟通的格式
+ “会议记录”——捕获和分发会议记录的结构

### 每周使用

+ “竞争分析”——跟踪竞争对手举措的框架
+ “数据分析标准”——我们如何评估指标和实验
+ “路线图演示”——路线图可视化的模板

### 每月使用

+ “季度规划”——OKR 和目标设定格式
+ “产品发布清单”——上市流程
+ “回顾模板”——我们如何构建团队回顾

### 来自目录

+ Notion Skill（用于在我们工作区中格式化文档）
+ Figma Skill（用于生成设计规格）
+ Excel Skill（Anthropic 用于处理电子表格的预构建 Skill）

设置这些的总时间：一个月内可能 6-8 小时。每周节省的时间：轻松 3-4 小时。

## 15、最后的想法：Skills 作为生产力倍增器

Skills 代表了我们与 AI 交互方式的转变。我们不再将 Claude 视为一个需要持续指导的非常聪明的实习生，而是将其视为一个了解我们工作流程并能半自主运营的专家。

对于产品经理来说，这很重要，因为我们的工作通常是综合信息、遵循流程和与不同受众有效沟通。Skills 使 Claude 在所有三个方面都显著更好。

真正的力量不在于任何单个 Skills——而在于拥有 10-15 个 Skills 来处理您最常见工作流程的累积效应。突然，您不再花数小时在文档、格式化和管理工作上。您花时间在实际需要人类判断的战略思考上。

这完美吗？不。有风险和限制吗？绝对有。但在过去两个月内每天使用 Skills 后，我深信这是多年来我采用的最重要的生产力改进之一。

我们仍然处于早期阶段。随着 Skills 变得更加复杂、更广泛采用且更容易创建，生产力收益只会复合。

如果您是尚未使用 Skills 的产品经理，我鼓励您尝试一下。从一个令人烦恼的重复任务开始。为此创建一个 Skill。看看它是否为您节省时间。

我猜您会在一周内创建您的第二个 Skill。
