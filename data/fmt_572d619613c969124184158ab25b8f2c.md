## 17.5 开源商业化路径

### 17.5.1 开源许可选择

#### 开源许可基础

选择正确的开源许可是商业化的第一步：

##### 宽松许可（Permissive Licenses）

###### MIT License

+ 最宽松的许可之一
+ 允许商业使用、修改、分发
+ 无需开源衍生作品
+ 优点：最大化采用和贡献
+ 缺点：难以防止竞争对手利用

###### Apache License 2.0

+ 类似 MIT，但包含专利授权
+ 明确的商标使用限制
+ 贡献者许可协议（CLA）
+ 优点：专利保护，企业友好
+ 缺点：仍然允许闭源衍生品

###### BSD License

+ 类似 MIT，有多个变体
+ 简单明了
+ 优点：灵活性高
+ 缺点：保护较少

##### Copyleft 许可（Copyleft Licenses）

###### GPL(GNU General Public License)

+ 强 Copyleft：衍生作品必须开源
+ 传染性：链接的代码也需开源
+ 版本：GPLv2、GPLv3
+ 优点：保护开源生态
+ 缺点：限制商业采用

###### AGPL(Affero GPL)

+ 更强的 Copyleft
+ 网络使用也触发开源要求
+ 适合 SaaS 场景
+ 优点：防止“SaaS 漏洞”
+ 缺点：企业通常避免使用

###### MPL(Mozilla Public License)

+ 弱 Copyleft：仅修改的文件需开源
+ 可以与闭源代码混合
+ 优点：平衡开源和商业
+ 缺点：复杂性较高

##### 商业友好的开源许可

###### BSL(Business Source License)

+ 延迟开源：X 年后转为开源
+ 限制商业使用
+ 例如：MariaDB、CockroachDB
+ 优点：保护商业利益
+ 缺点：不是真正的开源（OSI 不认可）

###### SSPL(Server Side Public License)

+ MongoDB 创建
+ 要求 SaaS 提供商开源整个堆栈
+ 有争议性（OSI 不认可）
+ 优点：防止云厂商竞争
+ 缺点：企业抵制

#### 许可选择策略

##### 考虑因素

+ 商业模式（SaaS、支持、双授权）
+ 目标用户（开发者、企业）
+ 竞争环境（云厂商威胁）
+ 社区建设目标
+ 长期战略

##### 常见组合

+ 核心：Apache 2.0（最大化采用）
+ 企业版：商业许可（额外功能）
+ 插件：MIT（鼓励生态）

### 17.5.2 双授权模式

#### 双授权概念

双授权（Dual Licensing）是指同一软件在两种不同许可下分发：

#### 典型模式

+ 开源许可（如 GPL）：免费，但有限制
+ 商业许可：付费，无开源要求

#### 工作原理

##### 开源版本（GPL）

+ 任何人可以免费使用
+ 如果修改和分发，必须开源
+ 适合：开源项目、个人用户、GPL 兼容项目

##### 商业版本

+ 付费购买商业许可
+ 可以闭源使用和分发
+ 包含额外功能或支持
+ 适合：商业产品、专有软件、企业客户

#### 成功案例

##### MySQL

+ 开源版：GPL
+ 商业版：Oracle 商业许可
+ 策略：开源版驱动采用，商业版服务企业
+ 结果：被 Oracle 以数十亿美元收购

##### Qt

+ 开源版：LGPL/GPL
+ 商业版： Qt Commercial License
+ 策略：开源版支持社区，商业版服务企业
+ 结果：可持续的商业模式

##### MongoDB（曾经）

+ 开源版：AGPL
+ 商业版： MongoDB Commercial License
+ 策略：AGPL 限制云厂商，商业版服务企业
+ 演变：后来改为 SSPL

#### 双授权的优势

##### 商业角度

+ 稳定的收入来源
+ 保护商业利益
+ 服务企业客户
+ 可持续发展

##### 社区角度

+ 保持开源可用性
+ 鼓励社区贡献
+ 广泛的采用
+ 生态系统发展

#### 实施双授权

##### 法律要求

+ 必须拥有所有代码的版权
+ 贡献者许可协议（CLA）
+ 版权转让或授权
+ 清晰的许可文档

##### 贡献者许可协议（CLA）

+ 要求贡献者签署 CLA
+ 授予项目使用贡献代码的权利
+ 允许双授权
+ 例子：Apache CLA、Google CLA

##### 版本差异化

###### 功能差异

+ 开源版：核心功能
+ 商业版：高级功能（企业级、性能、安全）

###### 支持差异

+ 开源版：社区支持
+ 商业版：专业支持、SLA

###### 服务差异

+ 开源版：自助服务
+ 商业版：托管服务、咨询

##### 定价策略

###### 商业许可定价

+ 开发者许可：$500-2,000/开发者/年
+ 部署许可：$5,000-50,000/部署/年
+ 企业许可：$50,000-500,000+/年
+ OEM 许可：定制定价

###### 价值定位

+ 强调商业版的额外价值
+ ROI 计算
+ 风险降低（支持、保证）
+ 合规性和法律保护

#### 挑战和风险

##### 社区摩擦

+ 社区可能反对商业化
+ 贡献者可能不愿签 CLA
+ 可能导致分叉（Fork）

##### 竞争压力

+ 云厂商可能提供托管开源版
+ 开源版可能满足大多数需求
+ 需要持续创新差异化

##### 法律复杂性

+ CLA 管理复杂
+ 许可合规性
+ 国际法律差异
