### 2.5.4 常见失败原因与规避

**❌ 失败原因 1：技术能力不足**

- 问题：不会调试 Prompt，系统经常出错
- 规避：从简单案例开始，逐步积累经验；加入 OpenClaw 社区学习

**❌ 失败原因 2：没有客户渠道**

- 问题：系统搭好了，没人用
- 规避：先找到客户需求，再开发系统；利用现有人脉冷启动

**❌ 失败原因 3：定价过低**

- 问题：接单很多，但不赚钱
- 规避：计算真实成本（时间+API 费用），合理定价；提供增值服务

**❌ 失败原因 4：过度自动化**

- 问题：追求 100% 自动化，反而效果差
- 规避：人机协作，AI 处理 80%，人工把关 20%

**❌ 失败原因 5：忽视合规风险**

- 问题：医疗、金融等领域触碰红线
- 规避：了解行业法规，必要时咨询律师；不要过度承诺

#### 3.1.3 技术选型背景

为什么选择 TypeScript + Node.js?

OpenClaw 的核心是用 TypeScript 编写的，运行在 Node.js 22+ 上。这个选择基于几个考虑：

1. **跨平台兼容性** - Node.js 可以在 Windows、macOS、Linux 上无缝运行
2. **生态系统成熟** - npm 生态提供了丰富的库和工具
3. **WebSocket 支持** - Node.js 对实时通信的原生支持
4. **开发效率** - TypeScript 提供类型安全，同时保持开发速度
5. **社区友好** - JavaScript/TypeScript 是最流行的语言，降低贡献门槛

为什么选择 WebSocket 架构？

OpenClaw 的核心是一个 WebSocket 服务器（`Gateway`），这个设计有深刻的技术考量：

- **实时双向通信** - 客户端和服务器可以随时互相推送消息
- **持久连接** - 避免 HTTP 的频繁握手开销
- **统一控制平面** - 所有客户端（CLI、Web UI、移动端）通过同一个 WebSocket 连接
- **事件驱动架构** - 适合 AI Agent 的异步任务执行模式

**为什么不用 Python?**

虽然 Python 是 AI 领域的主流语言，但 OpenClaw 选择了 TypeScript，原因包括：

- Python 的并发模型（GIL）不适合高并发场景
- Node.js 的事件循环更适合 I/O 密集型任务
- TypeScript 的类型系统更适合构建复杂的系统架构
- Peter 本人更熟悉 JavaScript 生态
