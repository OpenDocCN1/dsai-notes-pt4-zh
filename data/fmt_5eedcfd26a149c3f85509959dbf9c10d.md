# 用 Claude Agent Skill 写现实题材类短篇小说 - 让故事灵感快速落地

这套方案主要解决一个问题：有了故事灵感后，从构思到完成一个完整短篇小说往往需要几天甚至更久。传统流程是想大纲、设计人物、规划章节、写正文，每一步都需要反复打磨，效率很低。

所以我们通过 Claude 的 `Skill` 功能搭建了一个专业的创作助手。把现实题材的创作方法论、文档模板、写作风格、实战示例都打包进 Claude `Skill`，让 Claude 在每个创作环节都能调用这些专业知识。你只需要回答几个问题，剩下的大纲、人物、章节就由 AI 按照专业标准自动生成。

工作流程按照小说创作的自然顺序推进：故事大纲 → 人物小传 → 章节目录 → 章节正文。`CLAUDE.md` 负责整体流程管控，`skill` 提供创作标准。从有灵感到生成完整初稿，整个过程可以在一两小时内完成。

这个方案让故事灵感从脑海里的想法变成可以直接阅读的小说初稿，大幅提升创作效率。不过要注意，生成的内容是初稿，还需要根据个人风格润色调整。

---

## 核心功能模块

### Skill调用机制

通过 `skill` 技能包为 Claude 提供专业创作知识。每个创作阶段开始前，主Agent会自动调用对应的资源文件：大纲阶段读取 `outline-method.md`（方法论）+ `outline-template.md`（模板）+ `outline-example.md`（示例），章节阶段读取 `output-style.md`（写作风格）+ `chapter-template.md`（模板）。这种模块化设计让 Claude 不是凭感觉写作，而是基于明确的创作标准和范式进行输出。

### 分阶段创作流程

创作严格遵循"故事大纲 → 人物小传 → 章节目录 → 章节正文"的流程，每个阶段对应独立文档。用户通过 `/character`、`/catalog`、`/write` 命令推进流程，系统会自动读取前序文档确保连贯性。比如创作章节时，会同时读取 `outline.md`、`character.md`、`chapter_index.md`，确保情节不偏离大纲、人物行为符合设定。这种阶段性管理避免了一次性生成导致的前后矛盾。

### 模板驱动生成

所有文档格式由 `templates/` 目录下的模板文件定义，包括大纲、人物小传、章节目录、章节正文四类。Claude 创作时严格遵循模板结构，确保输出格式统一、信息完整。比如人物小传必须包含"主要角色→重要配角→其他角色"的层级。

### 上下文连贯性

每个阶段创作前都会读取已有文档内容。人物创作基于大纲设定，章节创作基于大纲+人物+目录，形成递进式上下文积累。系统通过文档驱动而非对话记忆来维护上下文，即使对话被清空，只要文件还在，就能通过 `/status` 命令查看进度并继续创作。

### 文档结构管理

项目采用标准化目录结构：`outline.md`（大纲）、`character.md`（人物）、`chapter_index.md`（目录）、`chapters/Chapter-XX.md`（各章节）。固定5章结构对应起承转合布局，每章2000-3000字。这种结构化存储让创作过程可追溯、可修改，文档本身就是交付物，而不需要从对话记录中复制粘贴整理。

> **注**：AI生成的是初稿，能帮你快速把故事框架搭起来，但最终还需要人工润色才能达到发布标准。输入质量直接决定输出质量——你在Q1-Q3提供的核心创意、冲突设定越详细具体，生成的大纲和人物就越贴合预期。AI的工作是基于你的创意进行填充和扩展，而不是100%从零创造，所以前期构思越清晰，后期调整成本越低。另外，固定的5章结构适合短篇，如果需要更长篇幅，需要调整模板和方法论。

## 如何配置

### 配置步骤

#### 方式一：在 Claude.ai 网页版配置（推荐新手）

![](img/a584fc7251bb17033597609288dbac24.png)

1. 进入 Skills 设置

   选择 "Settings" → "Capabilities" → "Skills"

   点击 "Upload file" 按钮

1. 上传技能包

   选择 `zip` 压缩包文件

   系统会自动解压并识别 `skill` 结构

1. 启用技能包

   在 Skills 列表中找到新创建的技能

   确保状态为 `Enabled`（已启用）

1. 开始创作

   回到对话界面，开始新对话

   直接向 Claude 说明你的创作需求即可

   Claude 会自动调用进行创作

#### 方式二：在 Claude Code 中配置（适合熟练）

请按照以下步骤配置创作系统，配置完成后，你的项目结构应该是这样：

```
project/
├── outline.md                           # 故事大纲（创作后生成）
├── character.md                         # 人物小传（创作后生成）
├── chapter_index.md                     # 章节目录（创作后生成）
├── chapters/                            # 章节正文目录（创作后生成）
│   ├── Chapter-01.md
│   ├── Chapter-02.md
│   └── ...
└── .claude/
    ├── CLAUDE.md                        # 项目规则和主Agent配置（必须创建）
    └── skills/
        └── xianshi-skill/               # 现实题材创作技能包（必须创建）
            ├── SKILL.md                 # 技能包核心配置
            ├── outline-method.md        # 大纲创作方法论
            ├── output-style.md          # 写作风格
            ├── templates/               # 文档格式模板
            │   ├── outline-template.md
            │   ├── character-template.md
            │   ├── chapter-index-template.md
            │   └── chapter-template.md
            └── examples/                # 创作示例
                ├── outline-example.md
                ├── character-example.md
                └── chapter-example.md
```

1. 创建项目规则

   在 `.claude/` 目录下创建 `CLAUDE.md` 文件

   粘贴完整的项目规则内容，包含角色定义、工作流程、指令集

   确保包含初始化脚本和所有创作阶段的流程定义

1. 创建 Skill 技能包

   在 `.claude/skills/` 目录下创建 `xianshi-skill/` 文件夹

   创建 `SKILL.md` 作为技能包核心配置

   粘贴技能包说明和执行流程

1. 添加创作方法论

   在 `xianshi-skill/` 目录下创建 `outline-method.md`

   粘贴大纲创作方法论，包含起承转合结构、人物塑造、爽点设计等内容

1. 配置写作风格

   创建 `output-style.md` 文件

   粘贴写作风格定义和具体行为规范

1. 添加文档模板

   在 `xianshi-skill/templates/` 目录下创建四个模板文件

   包括大纲、人物小传、章节目录、章节正文的格式定义

   这些模板会严格约束 AI 的输出格式

1. 添加创作示例

   在 `xianshi-skill/examples/` 目录下创建示例文件

### 重要配置细节

+ **Skill调用**：`CLAUDE.md` 中定义了何时调用 `xianshi-skill`，每个创作阶段会自动调用对应资源

+ **模板约束**：`templates/` 中的格式是强制性的，AI 必须按照模板结构输出

+ **方法论指导**：`outline-method.md` 是核心，定义了起承转合、人物塑造、冲突设计等创作标准

+ **风格一致性**：`output-style.md` 确保文白相济风格贯穿全文，避免出现现代口语

+ **示例学习**：`examples/` 提供具体范式，让 AI 理解什么是符合标准的输出

+ **固定结构**：短篇固定5章对应起承转合，不支持自定义章节数

+ **人工润色**：AI生成初稿后仍需人工调整细节、润色语言、补充情节

## 核心设计理念

```
┌─────────────────────────┐
│  skill                  │ ← 知识层：提供专业创作指导
│  ├─ outline-method.md   │    方法论、风格、模板、示例
│  ├─ output-style.md     │
│  ├─ templates/          │
│  └─ examples/           │
├─────────────────────────┤
│  CLAUDE.md              │ ← 流程层：控制创作流程
|                         │    定义工作流和指令集
├─────────────────────────┤
│  Main Agent             │ ← 创作层：调用Skill进行创作
|                         │    读取资源→生成内容→写入文档
├─────────────────────────┤
│  outline.md             │ ← 文档层：结构化存储
│  character.md           │    故事大纲
│  chapter_index.md       │    人物小传
│  chapters/*.md          │    章节目录
|                         │    章节正文
└─────────────────────────┘
```

## 工作流程

1. **需求收集** - 主Agent询问核心创意、核心冲突、故事调性三个问题

1. **调用 `skill`** - 根据创作阶段，调用 `skill` 读取对应的方法论、模板、示例

1. **内容创作** - 基于 `Skill` 提供的指导和用户需求，生成符合标准的内容

1. **文档写入** - 将创作内容写入对应的结构化文档（`outline.md` / `character.md` 等）

1. **流程推进** - 通知用户当前阶段完成，引导进入下一个创作阶段

## 关键特性

+ **Skill驱动** - 每个阶段自动调用对应资源，确保创作有章可循

+ **模板约束** - 严格遵循 `templates/` 定义的格式，保证输出规范统一

+ **阶段递进** - 按照"大纲→人物→目录→正文"顺序推进，后续阶段基于前序文档

+ **上下文积累** - 通过文档驱动而非对话记忆维护上下文，支持长期创作

+ **结构化存储** - 所有内容分文件管理，便于查看、修改和复用

+ **快速落地** - 从灵感到初稿，整个流程可在1-2小时内完成

+ **固定框架** - 5章结构对应起承转合，适合快速产出标准化短篇

# 👀 先睹为快

我们用这套系统测试了 Claude Sonnet 4.5 模型，从提出故事创意到生成完整的5章短篇小说，整个过程用了半小时左右。所有内容都是基于框架直接生成的初稿，未经人工润色。这样你可以直观地看到这套系统在实际应用中能达到什么效果。

## 使用时的注意事项

1. **输入质量决定输出质量**。Q1-Q3 回答得越详细，生成的内容就越贴合你的预期。比如核心冲突如果只写"职场困境"，生成的内容会很空泛；但如果写"38岁HR在裁员名单上看到恩师名字，签字保住职位但违背良心，不签则面临失业和房贷断供"，生成的内容就会具体很多。

1. **这是初稿，不是成品**。AI生成的内容能帮你快速搭起框架，但语言细节、情节逻辑、人物对话还需要人工润色。特别是情感表达部分，AI有时会写得过于直白或抒情，需要调整成更克制、更贴近日常的自然表达。

1. **及时反馈和调整**。如果大纲阶段就发现内容偏离预期，直接提出修改意见，不要等到写完5章再推倒重来。每个阶段都可以修改，改得越早成本越低。

1. **注意版权问题**。虽然这套系统是基于方法论和模板创作，但如果你的故事创意本身借鉴了某部作品，还是要注意避免抄袭。建议用自己的原创构思，或者对经典题材进行充分的改编创新。

## 故事大纲

## 小说信息

+ **书名**: 《老汤》

+ **类型**: 现实题材

+ **故事调性**: 市井烟火·温情治愈

## 主要人物

+ **陈默**: 42岁, 原某互联网公司产品经理, 被优化后在菜市场32号摊位卖卤味

+ **小鱼**: 24岁, 短视频创作者, 拍摄陈默走红, 鼓励他持续制造内容

+ **张姨**: 58岁, 退休工人, 陈默的第一批老顾客, 每天买半斤鸭脖

+ **林薇**: 陈默的妻子, 小学教师, 支持丈夫但对家庭收入焦虑

## 核心梗概

> 42岁的前产品经理在菜市场卖卤味，意外成为短视频"励志模板", 在流量带来的快钱与摊位原有的慢生意之间, 他选择关掉直播, 守住一门老手艺。

## 导语

> 2024年10月, 杭州北郊菜市场32号摊位前排起长队。42岁的陈默正在卤锅前忙活, 手机支架上的直播亮着红点——18.7万人在线观看"中年失业者的逆袭"。三个月前, 他还是互联网公司的产品经理, 现在他得在镜头前解释为什么这锅老汤要熬72小时。张姨站在队尾, 手里攥着保温袋, 等了40分钟还没轮到她。她想起三个月前, 这个摊位从没排过队, 陈默会多送她两块豆干, 还记得她孙子不吃姜。今天下午5点, 陈默要决定: 是续签 MCN 公司的合约, 还是把那个直播支架拆掉。

## 故事大纲

### 起: 摊位与流量的相遇 (第1章)

> 杭州北郊菜市场, 早上6点。陈默在32号摊位前支起卤锅, 这是他失业后的第94天。42岁, 前互联网公司产品经理, 上一份工作年薪38万, 现在每天收入300到500不等。

> 摊位生意平淡。老卤是岳父留下的, 陈默用了三个月才摸清火候——文火慢炖, 老汤不能断。张姨是第一批固定顾客, 每天早上买半斤鸭脖, 带走时陈默会多装两块豆干, 记得她孙子不吃姜。还有李叔, 退休的泥瓦匠, 爱吃卤藕, 每次都在摊前坐着啃完再走。这些人认摊不认人, 三个月下来, 陈默记住了十几张脸, 也记住了他们的口味习惯。

> 妻子林薇在电话里提醒: 这个月房贷还差8000, 女儿学钢琴的续费也快到期了。陈默看着卤锅里滚着的汤汁, 算账——一斤卤鸭脖成本12元, 卖28元, 毛利60%, 但每天只能卖出去不到20斤, 扣掉摊位费和材料损耗, 一天净赚300出头。照这个速度, 连房贷都吃力。

> 下午3点, 一个女孩举着手机对准摊位。小鱼, 24岁, 短视频创作者, 3万粉丝, 专门拍"城市底层的温暖故事"。她看中了陈默——"中年失业者在菜市场重新开始", 完美的励志叙事。陈默犹豫, 但小鱼说: "叔, 你不试试怎么知道呢? 现在就是流量时代。"

> 视频发出去, 当晚播放量破10万。评论区全是"励志""真实""向生活低头也是一种勇气"。第二天, 摊位前排起了队, 有人专程开车来买"网红卤味", 还有人要求和陈默合影。陈默手忙脚乱, 张姨在队尾等了一个小时。

> 小鱼趁热打铁, 建议陈默开直播: "叔, 你边卤边聊, 讲讲你的故事, 肯定火。"陈默想起林薇说的房贷缺口, 点了头。

### 承: 流量的快车与代价 (第2-3章)

#### 第2章

> 直播开通第一周, 在线人数从800涨到5.8万。陈默在镜头前讲"产品经理到卤味师傅的转型", 讲"中年人的韧性", 讲"一锅老汤的人生哲学"。观众刷礼物, 小鱼帮他接广告——卤料品牌、围裙品牌、保温箱品牌, 一个月进账2.3万, 比他之前三个月的总收入还高。

> MCN 公司找上门, 开出条件: 签约三年, 保底月收入1.5万, 平台分成五五开, 但要配合公司制作内容——每天直播2小时, 每周发3条短视频, 标题要带"逆袭""中年""不认输"等关键词。陈默犹豫, 林薇说: "先试试, 钱能解决很多问题。"

> 流量改变了摊位的节奏。陈默得在早上5点半就开播"晨间卤味时刻", 下午3点再来一场"下班后的治愈"。为了满足在线观众的猎奇心理, 他得表演"失业者的励志日常"——在镜头前感叹生活不易, 讲前公司裁员时的细节, 分享"中年人如何放下身段"。

> 老顾客开始流失。张姨来了三次, 每次都因为排队太长放弃了。李叔也不来了, 他说: "这锅卤味变了味, 急了。"陈默知道, 为了提高产量配合直播节奏, 他把老汤的熬制时间从72小时压缩到48小时, 火候也调大了——快出货, 赶直播, 迎合流量。

> 小鱼的要求越来越多: "叔, 你得哭一次, 观众爱看这个。" "能不能讲讲你老婆怎么看你失业的?" "拍一条 '前同事来买卤味' 的视频, 肯定爆。" 陈默照做, 数据确实好看, 但他开始失眠。

> 林薇发现家里的卤味不好吃了, 问他怎么回事。陈默说: "没事, 可能是天气变了。"

#### 第3章
