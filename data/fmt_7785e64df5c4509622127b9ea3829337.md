# 第一部分：GitHub Copilot 的基础知识

## 负责任 AI 与 GitHub Copilot

负责任的 AI 原则提供了一套关键的指导方针，用于确保人工智能系统的开发、评估和部署过程是安全、可靠且合乎道德的。这些原则将人员及其目标置于系统设计决策的核心，并尊重诸如公平性、可靠性和透明度等持久的价值观。

Microsoft 和 GitHub 确定了六项核心原则，它们从以下方面具体指导了系统开发和实际应用：

1. 公平性 （Fairness）

在系统开发和应用中，公平性要求 AI 系统对所有人都一视同仁，并避免对处境相似的群体产生不同的影响（例如在医疗、贷款申请或就业方面）。

应用指导和实践：

+ 数据和模型层面：应该审查训练数据，并在多样化的和均衡的数据上训练 AI 模型，以帮助降低偏差，促进公平。

+ 测试和监控层面：使用均衡的人口统计样本测试模型。

+ 部署和干预层面：跨用户群体监视模型性能，并实施控制措施来替代不公平的模型分数。此外，还可以使用对抗性去偏差方法来缓解不公平带来的影响。

1. 可靠性和安全性 （Reliability and Safety）

为了建立信任，AI 系统必须可靠、安全、一致地运行。安全性侧重于尽量减少意外伤害，包括对个人和社会造成的身体、情感和经济伤害。可靠性则指 AI 系统能够按照预期一致地运行，不会出现不必要的可变性或错误。

应用指导和实践：

+ 设计和测试：系统需要按设计方式运行，并且其行为必须反映开发人员在设计和测试期间的预见。

+ 稳健运行：安全可靠的系统在正常情况下应该是稳健、准确且行为可预测的。

+ 应对意外：系统需要安全地响应意外情况，并能够抵御有害操作。

1. 隐私和安全性 （Privacy and Security）

保护用户隐私和数据安全至关重要，旨在阻止滥用和维护用户信任。

应用指导和实践：

+ 数据收集和使用：在收集用户数据之前必须获得用户的许可，并清楚地说明 AI 会如何使用其数据。

+ 选择权和透明度：必须让用户选择是否愿意分享个人数据，并通过明确的提示和政策告知他们，不能秘密收集数据。

+ 数据最小化：仅收集 AI 运行所需的数据。一旦使用 AI，就应避免收集额外信息并删除敏感数据。应定期检查数据输入，确保只收集必要的数据。

+ 数据保护技术：将个人数据匿名化，例如使用假名化（用随机标识符替换个人详细信息）和聚合（将数据分组成摘要）等方法来保护标识。

+ 加密和访问控制：在传输和存储过程中对敏感数据进行加密，使用强加密方法和安全密钥，并使用硬件安全模块 （HSM） 或安全保管库存储密钥。组织应对谁可以访问密钥和模型进行控制，并限制员工对敏感模型和数据的访问。应定期轮换密钥，安全备份密钥，并定期进行安全审核。

1. 包容性 （Inclusiveness）

包容性要求 AI 系统公平、可访问，并成为所有人的得力助手。这意味着 AI 创建者（包括 GitHub）必须主动设计 AI，以涵盖所有人员、社区和地区，尤其是那些历史上代表性不足的社会领域。

应用指导和实践：

+ 用户群覆盖：AI 系统应适用于各种不同的用户和群体，不会对某些人不利。

+ 可访问性：确保任何人都可以轻松使用 AI 系统，无论身体能力或心智能力如何（例如为视障人士提供屏幕阅读器支持的界面）。

+ 替代交互模式：提供替代性的交互模式，例如语音控制、字幕和屏幕阅读器。

+ 全球和文化适应：AI 系统应该在全球范围内可用，即使在发展中国家/地区也是如此，不能排除某些地理区域。系统应支持适应不同的语言和本地文化背景（例如支持小众区域方言的语言翻译）。

+ 基础设施适应：必须能够在连接和计算资源受限时正常工作，能够脱机工作。

+ 开发团队组成：寻求来自不同背景和社区的人们为 AI 系统的发展提供意见。

1. 透明度 （Transparency）

透明度原则强调 AI 系统必须是可理解的和可解释的。透明度对于建立信任、确保问责、促进公平、增强安全和支持包容性至关重要。

应用指导和实践：

+ 系统说明：通过清晰的验证框架清楚地说明其系统如何运行。

+ 设计选择：证明 AI 系统背后的设计选择的合理性。

+ 坦诚局限性：坦陈 AI 系统的功能和局限性。

+ 可审核性工具：实现可审核性，涉及文档化数据和模型、创建解释界面、使用 AI 调试工具、构建测试仪表板以及启用日志记录和审核功能。

1. 问责 （Accountability）

问责原则规定 AI 创建者应对其系统的运行方式负责。部署 AI 系统的公司必须对其 AI 系统的运行负责。

应用指导和实践：

+ 风险管理和监控：AI 创建者需要持续监视系统性能并降低风险。

+ 治理框架：为了缓解 AI 可能带来的风险（如带有偏见的决策或侵犯隐私），必须实施可靠的治理框架，确保 AI 流程的透明度，并纳入人工监督。

## GitHub Copilot 简介

GitHub Copilot 是一款 AI 结对程序员服务，由 Microsoft 与 OpenAI 协作开发，并由 OpenAI Codex 系统提供支持。它为所有常用编程语言提供 AI 配对程序员，并通过一系列功能集成到开发工作流中，使其成为一个易于访问的 AI 助手。

以下是 GitHub Copilot 的主要功能，这些功能使其不仅是一个编辑器工具，还提高了开发人员的整体工作效率（根据研究，开发人员整体工作效率提高了 55%）：

### 核心代码生成和辅助功能

Copilot 最初和最核心的功能是自动化代码编写，帮助开发人员保持工作流的连贯性：

1. 内联建议 （Inline Suggestions）： 这是 Copilot 最直接的协助形式。在你输入时，Copilot 会分析你的代码和上下文，以实时提供代码补全建议，这些建议在光标前显示为灰显文本。

+ 接受/拒绝建议：可以使用 `Tab` 键或 `>` (向右箭头) 键接受建议，或继续键入/选择 `Esc` 键拒绝建议。

+ 此功能在处理重复性任务或需要快速样本代码时特别有用。

1. 注释转代码：Copilot 利用自然语言处理 （NLP） 将注释转换为代码。你可以在注释中描述所需的功能，当选择 `Enter` 键时，Copilot 会根据说明生成代码。这种方法适用于快速起草代码，尤其是在任务简单明了的情况下。

1. 多项建议 （Multiple Suggestions）： 对于复杂的代码片段，Copilot 可以提供多个替代方法。开发人员可以循环浏览替代项（例如使用 `Alt+]` 或 `Option+]`）来探索不同的编码方法，并选择最合适的方法。

### 交互式 AI 助手和聊天功能

Copilot 将类似于 ChatGPT 的聊天界面引入了编辑器，支持开发人员使用自然语言进行通信，并与 IDE（如 VS Code 和 Visual Studio）进行原生集成。

1. Copilot Chat：这是一种交互式功能，允许开发人员提出问题或请求代码片段。它深层嵌入到 IDE 中，能够识别开发人员输入的代码和显示的错误消息。开发人员可以：

+ 深入分析和解释代码块要执行的操作。

+ 生成单元测试。

+ 获得针对 bug 的建议修复。

+ 适用场景：非常适合探索新的编码概念或在遇到不熟悉的语法时获取帮助。

1. 内联聊天 （Inline Chat）： 此功能直接在代码编辑器中启用上下文特定的对话。你可以使用键盘快捷方式 （`Ctrl+I` 或 `Cmd+I`） 打开内联聊天，请求代码修改或解释，而无需切换上下文。

+ 斜杠命令：内联聊天支持使用斜杠命令作为快捷方式进行高效交互。例如：

+ `/explain`：提供所选代码的说明。

+ `/suggest`：根据当前上下文提供代码建议。

+ `/tests`：为所选函数或类生成单元测试。

+ `/comment`：将注释转换为代码片段。

### 代码理解和质量功能

1. 说明 （Explanations）： 开发人员可以使用“解释此”功能来获取代码片段的说明。这对于学习目的以及查看他人编写的代码至关重要。

1. 自动测试生成 （Automated Test Generation）： Copilot 可以为函数或类生成单元测试，从而节省时间和精力，有助于在开发过程中保持代码完整性并捕获 bug。可以使用命令面板选择 `Copilot：生成单元测试` 来触发此功能。

### 集成和企业级功能

1. 对拉取请求 （Pull Requests） 的支持： Copilot 增添了通过 GitHub 应用在拉取请求说明中使用 AI 支持的标记的支持。Copilot 会根据更改的代码自动填充这些标记，开发人员可以查看或修改建议的说明。此功能由 OpenAI 的 GPT-4 模型提供支持。

1. 命令行接口 （CLI）： GitHub Copilot CLI 可以编写命令和循环，甚至可以抛出模糊的 `find` 标志来满足查询，帮助开发人员避免滚动浏览多个页面来记住精确的语法。

1. 企业级功能 （Enterprise）： 对于大型组织，GitHub Copilot Enterprise 提供高级功能，包括：

+ 基于内部/专用代码的个性化代码建议。

+ 基于 AI 的搜索和跨代码库的文档生成。

+ 对 Copilot 模型进行组织范围的自定义和微调。

+ 提供集中式管理和策略控制，以及安全漏洞筛选、IP 赔偿和企业级安全性、安全和隐私功能。

## GitHub Copilot 提示工程简介

GitHub Copilot 是由大语言模型 （LLM） 提供支持的。它的工作原理是一个动态的、多步骤的过程，涉及用户提示的接收、广泛上下文的收集、安全筛选以及最终使用经过优化的 LLM 生成相关的代码建议。

以下是 GitHub Copilot 使用 LLM 工作的核心原理和流程：

### LLM 的基础作用与优化

LLM 是人工智能模型，通过接受大量文本数据的训练，旨在理解、生成和操作人类语言。这些模型基于机器学习和人工智能原理，是具有数百万甚至数十亿个参数的神经网络。

1. 核心作用：上下文感知建议

GitHub Copilot 利用 LLM 提供上下文感知代码建议。LLM 的主要工作是：

+ 理解上下文：LLM 能够生成上下文相关且连贯的文本。

+ 动态分析：LLM 不仅考虑用户正在编辑的当前文件，还会考虑 IDE（集成开发环境）中的其他开放文件和选项卡，以生成定制化和相关的代码完成。

1. LLM 的优化：微调和 LoRA

为了使 LLM 更好地满足特定的编码要求，GitHub 会对其进行微调：

+ 微调 （Fine-tuning）： 这是一个关键过程，旨在针对特定任务或领域定制预先训练的 LLM。它涉及在一个较小的、特定于任务的数据集（目标数据集）上训练模型，同时利用从大型预训练数据集（源模型）中获取的知识。

+ LoRA 微调： GitHub 采用 LoRA （低秩自适应） 微调方法。与传统的完全微调（训练神经网络的所有部件，耗费资源且慢）不同，LoRA 是一种替代方法。

+ 工作原理： LoRA 不会更改原始模型的所有内容。相反，它在预先训练的模型每一层中添加较小的可训练部分。

+ 优点： 原始模型保持不变，从而节省了时间和资源。这使得 LLM 能够更有效地适应特定的编码要求。

### 上下文限制

虽然 Copilot 能够理解和响应提示，但在操作中必须注意上下文窗口的限制。上下文窗口是指模型为生成建议可以同时处理的周围代码和文本量。

+ 限制范围： GitHub Copilot 上下文窗口的范围通常从大约 200-500 行代码到多达几千个令牌。

+ Copilot Chat 窗口： Copilot 聊天目前使用 4k 个令牌的上下文窗口运行，提供了更广阔的范围。

用户在创建提示时，应注意这些限制，将复杂问题分解为更小、更集中的查询，或提供相关代码片段，以增强模型提供准确响应的能力。

提示工程的“4 S”原则和不同的学习方法是优化 GitHub Copilot 性能的核心策略，因为 Copilot 是由大语言模型 （LLM） 提供支持的，其建议的质量直接取决于接收到的指令和上下文。

以下是关于提示工程的“4 S”原则和学习方法如何优化 Copilot 性能的详细说明：

### 提示工程的“4 S”原则如何优化性能

提示工程是制作清晰指令的过程，旨在指导 AI 系统（如 GitHub Copilot）根据项目的特定需求生成符合上下文的代码，从而确保代码在语法、功能和上下文方面都是正确的。

“4 S”原则是创建有效提示的基础核心规则，遵循这些原则可以直接提高 Copilot 提供的代码建议的准确性和相关性：

1. Single（单一）

+ 优化作用：确保从 Copilot 获得准确且有用的答复。

+ 原则内容：始终将提示的重点放在单个明确的任务或问题上。

1. Specific（具体）

+ 优化作用：帮助获得更适用和精确的代码建议。

+ 原则内容：确保指令明确且详细。例如，“编写 Python 函数以筛选和返回给定列表中的偶数”就是既侧重于单一问题又非常具体的提示。

1. Short（简短）

+ 优化作用：确保清晰度，同时又不会使 Copilot 负担过重或使交互复杂化。

+ 原则内容：在具体的同时，保持提示简明扼要，即在细节和简洁性之间取得平衡。

1. Surround（有上下文）

+ 优化作用：为 Copilot 提供了丰富的上下文，从而产生更有针对性的代码建议。

+ 原则内容：利用描述性文件名并使相关文件保持打开状态。Copilot 会利用代码编辑器中并行打开的选项卡来获取有关代码要求的更多上下文。

#### 基于 4 S 的高级优化实践

除了遵循 4 S 原则外，还有一些基于这些原则的最佳实践可以进一步增强与 Copilot 的交互，确保生成的代码完全符合项目的特定需求和上下文：

+ 提供足够的上下文（细节）：按照“有上下文”（Surround）原则，通过在代码顶部添加注释等方式详细说明你想要实现的目标，为 Copilot 提供更丰富的上下文，使其能够提供更合适的代码建议。

+ 断言和迭代：释放 Copilot 潜力的关键在于迭代实践。如果第一次提示没有产生完美的结果，应将其视为对话中的一步。用户应清除建议的代码，使用添加的详细信息和示例来丰富初始注释，并再次向 Copilot 提示。

#### 上下文窗口限制的管理

在使用提示优化 Copilot 性能时，必须注意上下文窗口（模型为生成建议可以同时处理的周围代码和文本量）的限制。

+ GitHub Copilot 上下文窗口的范围通常从大约 200-500 行代码到多达几千个令牌（token）。Copilot 聊天目前使用 4k 个令牌的上下文窗口。

+ 优化方法：创建提示时，应注意上下文窗口限制，将复杂问题分解为更小、更集中的查询或提供相关的代码片段，可以显著增强模型提供准确且有用的响应的能力。

### 学习方法（样本）如何优化性能

GitHub Copilot 依靠使用大量数据训练的 AI 模型。通过在提示中提供示例，可以阐明用户的要求和期望，说明抽象概念，从而为 Copilot 提供更切实的指导，增强其对特定代码上下文的理解。

这些方法根据提供的示例数量，分为零样本学习、单样本学习和少样本学习，它们有效地提高了代码生成的精确性：

1. 零样本学习（Zero-Shot Learning）

+ 优化作用：仅依赖于 Copilot 的基础训练来生成代码。

+ 方法：无需任何特定示例。例如，用户只需写一条注释描述需求（如创建摄氏度和华氏度相互转换的函数），Copilot 即可根据其预训练的知识生成代码。

1. 单样本学习（One-Shot Learning）

+ 优化作用：通过提供一个示例，帮助模型生成更能感知上下文的答复。

+ 方法：用户提供一个相关函数的示例，然后要求 Copilot 创建另一个类似的函数。

1. 少样本学习（Few-Shot Learning）

+ 优化作用：通过提供多个示例，在零样本的不可预测性和微调的精确性之间取得了平衡，增强了模型处理复杂或特定场景的能力。

+ 方法：用户在提示中提供多个示例，以指导 Copilot 更好地理解并满足要求。例如，提供多个根据一天中不同时间发送问候语的代码示例。
