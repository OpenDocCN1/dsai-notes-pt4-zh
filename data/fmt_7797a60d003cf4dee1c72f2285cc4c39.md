每个模型都有 Token 限制：

**Token 是如何累积的？**

``` 
一个典型的会话:
- System Prompt: ~2,000 tokens
- 对话历史(20轮): ~15,000 tokens
- 当前用户消息: ~500 tokens
- 工具调用结果: ~5,000 tokens
- Skills 指令: ~3,000 tokens
```

### 6.2.3 超时重试策略

问题： API 超时和网络不稳定

**症状：**

``` 
Error: Request timeout after 60000ms
Error: ETIMEDOUT
Error: socket hang up
```

**根本原因：**

+   API 服务器响应慢（高负载时段）
+   网络不稳定（特别是国内访问国外 API）
+   请求过大（大文件、长上下文）
+   服务器临时故障

**默认超时设置：**

``` 
# OpenClaw 默认配置
providers:
  anthropic:
    timeout: 60000  # 60秒
    connect_timeout: 10000  # 10秒
```

**解决方案：**

**方案 1: 增加超时时间**

``` 
# 适合处理大文件或长任务
providers:
  anthropic:
    timeout: 180000  # 3分钟
    connect_timeout: 30000  # 30秒
```

**方案 2: 配置智能重试**

``` 
agents:
  defaults:
    retry:
      enabled: true
      max_attempts: 3
      
      # 指数退避
      initial_delay: 1000    # 1秒
      max_delay: 60000       # 60秒
      multiplier: 2          # 每次翻倍
      
      # 可重试的错误类型
      retryable_errors:
        - "ETIMEDOUT"
        - "ECONNRESET"
        - "ENOTFOUND"
        - "socket hang up"
        - "502"
        - "503"
        - "504"
      
      # 不可重试的错误
      non_retryable_errors:
        - "401"  # 认证错误
        - "403"  # 权限错误
        - "400"  # 请求格式错误
```

**重试时间计算：**

``` 
第1次失败: 等待 1秒 后重试
第2次失败: 等待 2秒 后重试
第3次失败: 等待 4秒 后重试
第4次失败: 放弃,返回错误
```

**方案 3: 使用流式响应**

``` 
# 流式响应可以更快开始接收数据,减少超时风险
agents:
  defaults:
    streaming: true  # 启用流式响应
```

**方案 4: 配置代理（国内用户）**

``` 
# 使用代理加速访问
providers:
  anthropic:
    proxy: "http://127.0.0.1:7890"  # HTTP 代理
    # 或
    proxy: "socks5://127.0.0.1:1080"  # SOCKS5 代理
```

**方案 5: 健康检查和自动切换**

``` 
providers:
  anthropic:
    health_check:
      enabled: true
      interval: 60000  # 每分钟检查一次
      timeout: 5000    # 5秒超时
      
    fallback_on_timeout: true  # 超时时自动切换到备用模型
```

## 6.3 Prompt 工程常见误区

### 6.3.1 指令不清晰

问题： AI 理解错误或输出不符合预期

**症状：**

+   AI 回答了错误的问题
+   输出格式混乱
+   遗漏关键信息
+   过于啰嗦或过于简短

**根本原因：**

**不清晰的指令示例：**

``` 
❌ 坏例子:
"帮我处理一下这个文件"

问题:
- "处理"是什么意思?分析?修改?转换?
- 期望的输出是什么?
- 有什么具体要求?
```

**清晰的指令示例：**

``` 
✅ 好例子:
"请分析 data.csv 文件,完成以下任务:
1. 统计总行数和列数
2. 识别缺失值(显示每列的缺失率)
3. 生成数值列的描述性统计(均值、中位数、标准差)
4. 以 Markdown 表格格式输出结果"

优点:
- 明确了任务(分析)
- 列出了具体步骤
- 指定了输出格式
```

---

**改进指令的 5 个原则：**

原则 1: 具体化（Specific）

``` 
❌ "写一个函数"
✅ "用 Python 写一个函数,接收一个整数列表,返回去重后的列表,保持原始顺序"

❌ "优化这段代码"
✅ "优化这段代码的性能,重点关注:
   1. 减少循环嵌套
   2. 使用更高效的数据结构
   3. 添加类型注解"
```

原则 2: 结构化（Structured）

````
# 在 System Prompt 中定义输出模板
systemPrompt: |
  When analyzing code, always use this structure:
  
  ## Summary
  [One-line summary]
  
  ## Issues Found
  - [Issue 1]
  - [Issue 2]
  
  ## Recommendations
  1. [Recommendation 1]
  2. [Recommendation 2]
  
  ## Code Example
  ```language

  [Example code]

```
````

原则 3: 上下文化(Contextual)

``` 
❌ “这个 bug 怎么修？”

✅ “我在运行 Python 脚本时遇到 TypeError: ‘NoneType’ object is not subscriptable。

错误发生在第 42 行： result = data[‘key’]

data 变量来自 API 响应。

请分析可能的原因并提供修复方案。“
```

原则 4: 约束化(Constrained)

```yaml
# 添加约束条件
systemPrompt: |
  Constraints:
  - Keep responses under 200 words
  - Use simple language (avoid jargon)
  - Provide code examples when relevant
  - Never execute destructive commands without confirmation
```

原则 5: 示例化（Exemplified）

``` 
# Few-shot Learning
systemPrompt: |
  When asked to generate commit messages, follow this format:
  
  Example 1:
  Input: "Added user authentication"
  Output: "feat(auth): implement JWT-based user authentication"
  
  Example 2:
  Input: "Fixed login bug"
  Output: "fix(auth): resolve session timeout issue in login flow"
  
  Now generate commit messages following this pattern.
```
