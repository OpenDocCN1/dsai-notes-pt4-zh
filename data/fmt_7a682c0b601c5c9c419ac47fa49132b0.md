
# Claude Skills详解：最优雅的AI能力系统

> 来源：[https://my.feishu.cn/docx/Tf25datVIorpQixnzPBc5JrQnjd](https://my.feishu.cn/docx/Tf25datVIorpQixnzPBc5JrQnjd)

## Claude Skills 是什么

Claude Skills上线几天，老金今天要先把一句话摆在最前面：

这玩意儿，本质上是上下文工程真正落地的第一步。

以前咱老说 提示词工程，对吧？

靠一句长提示词去让AI理解、执行、发挥，但每次都得重新解释。

Claude Skills不一样，它直接把这些上下文变成结构化、可管理、可执行的文件包。

AI不光能记住你说的，还能自己调用、自己执行，这才叫工程。

先看Skill是个啥。

一个Skill其实就是一个文件夹，里面放三样东西：

Instructions（指令）告诉Claude要干嘛，

Scripts（脚本）写具体逻辑，

Resources（资源）放素材、模板或数据。

这三个东西合起来，就是完整的上下文工程：

`逻辑＋素材＝任务可复现。`

每次Claude执行任务时，不再靠人手动补充背景，而是自动加载Skill里的上下文。

更厉害的是，它是按需加载的。

Claude先加载元数据，大约一百词，

再读Skill主体（`SKILL.md`），最后才读具体资源文件。

这让它既省token，又快，算是Anthropic在性能和成本上的一次漂亮设计。

## 使用示例：markdown-summarizer

老金上手试的第一个Skill，是官方示例的 `markdown-summarizer`。

官方地址：

`https://github.com/anthropics/skills`

用法特别简单：

先去Anthropic官方GitHub下载`markdown-summarizer`整个文件夹。

把它放进Claude的`skills`目录，然后在Claude里直接输入一句话：

```
总结这个Markdown文档内容。
```

Claude立刻反应，它会加载这个Skill，然后自动识别标题、摘要、分级内容。

结果出来的一份结构化总结，不光干净，还能识别列表、代码块、段落层级。

这就是上下文工程的力量：

AI不再靠“理解你想说什么”，而是执行你定义好的上下文规则。

从开发者角度看，这设计简直太合理了。

软件的本质就是程序和资源两部分。

程序定义逻辑，资源承载内容。

Skills正好把这两者有机结合，没有多余复杂度。

不像以前那种插件要注册API、调外部服务、处理权限，

Skill只用一个Markdown就能定义完整行为。

你甚至可以理解成——写Skill就像给Claude写入职手册。

告诉它你的职责、可用资源、该怎么判断任务类型。

Skill写完之后，还能打包、分享，别的用户一复制就能用。

这让AI能力第一次变得像软件包一样可复用。

## 当前局限性

当然，它还不完美。

老金踩过几个坑：

有的Skill要`apt-get`装依赖，对Windows用户来说直接卡死。

像老金这种懒人只希望点一下就能用，不想折腾环境。

还有，现在Skills 没有自己的存储能力，不能记长期状态。

比如想做个工作日志Skill帮你持续追踪任务，还得自己接`sqlite`或外部存储。

这两点是目前最大短板。

## 上下文工程的意义

说回那个关键词——上下文工程。

为什么说Claude Skills是这个概念的代表？

因为它把 上下文 从语言输入变成了工程组件。

以前AI理解上下文靠你说得清楚；

现在Claude理解上下文靠Skill定义得清楚。

Prompt工程是人类解释问题；

上下文工程是AI自己复用知识。

Skill就是这个桥梁，让AI能把知识、逻辑、资源、状态都封装成一个能反复用的包。

再往前想一步，

当AI的能力可以像Skill一样组合、调用、共享——

它就不只是个聊天机器人，而是能独立完成工作的智能体。

老金看完这次Claude Skills更新，真心觉得这方向走对了。

它没搞大而全，也没学OpenAI那套复杂嵌入，反而回到了简洁的力量。

只要程序和资源定义清晰，AI就能少费口舌，多干实事。

AI的未来，不在于写更聪明的提示词，而在构建能自己理解上下文的系统。

当AI开始读懂Markdown，开始主动选工具、执行脚本，人机协作的边界就变了。

这不是AI进步一小步，而是AI从被问到会干的转折。

时代变了。

当一句话能触发一整套定义好的流程，

我们得重新定义什么叫协作。

老金我有预感：

Skill这条路，会把AI推向 可编程认知 的时代。

到那时候，Prompt只是开场白，Skill才是舞台。
