
# Dockerfile 镜像构建与分析

## 第一个 Dockerfile 解析

这是一个 `Dockerfile`，它是一种文本文档，用于自动化 Docker 镜像的构建过程。下面是这个 `Dockerfile` 的逐行解析：

1. `FROM nvcr.io/nvidia/pytorch:23.06-py3`：这行指定了基础镜像，所有后续的操作都在这个基础镜像上进行。这里的基础镜像是 NVIDIA 提供的包含 `PyTorch` 的镜像，版本是 `23.06`，并且使用的 `Python` 版本是 `3`。

1. `RUN pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple && \`：这行设置了 `pip` 的全局源为清华大学的源，这可以提高在中国大陆的下载速度。

1. `pip install accelerate==0.21.0 bitsandbytes==0.40.2 gradio==3.37.0 protobuf==3.20.3 scipy==1.11.1 sentencepiece==0.1.99 transformers==4.31.0`：这行使用 `pip` 安装了多个 Python 包，包括 `accelerate`、`bitsandbytes`、`gradio`、`protobuf`、`scipy`、`sentencepiece` 和 `transformers`。每个包都指定了具体的版本号。

1. `WORKDIR /app`：这行设置了工作目录为 `/app`。这意味着后续的命令都将在 `/app` 目录下执行，如果这个目录不存在，Docker 将会自动创建它。

总的来说，这个 `Dockerfile` 创建了一个包含 `PyTorch` 和其他几个 Python 包的环境，这个环境可以用于运行需要这些包的 Python 程序。

## Python 依赖包概述

> 以下是第三行涉及的 Python 包的简单概述：
>
> 1. `accelerate`：这是由 `Hugging Face` 开发的一个用于加速 `PyTorch` 模型训练的库。它提供了简单的 API 来运行在任何硬件（如 `CPU`、单个 `GPU`、多个 `GPU`、`TPU` 等）上的 `PyTorch` 代码。
>
> 2. `bitsandbytes`：这是一个用于深度学习训练中优化计算的库。它提供了一些优化算法，如优化的 `Adam` 实现，可以在深度学习训练中提高效率。
>
> 3. `gradio`：这是一个用于创建机器学习模型的交互式 UI 的库。它可以让开发者快速地为他们的模型创建一个 web 界面，以便于测试和演示。
>
> 4. `protobuf`：这是 `Google` 开发的一种数据序列化协议（Protocol Buffers）。它可以用于结构化数据的存储或远程过程调用。
>
> 5. `scipy`：这是一个用于科学计算和技术计算的库。它提供了很多用于数学、科学、工程的函数，如线性代数、最优化、插值、特殊函数、快速傅里叶变换等。
>
> 6. `sentencepiece`：这是一个用于神经网络模型中的文本处理的库。它提供了一种简单的、可灵活使用的新型分词工具，尤其适合于神经网络模型中的文本处理。
>
> 7. `transformers`：这是由 `Hugging Face` 开发的一种用于自然语言处理（NLP）的库。它提供了大量预训练的模型，如 `BERT`、`GPT-2`、`RoBERTa` 等，以及对应的训练和微调工具。

## 第二个 Dockerfile 分析：soulteary/llama2:7b

`soulteary/llama2:7b` 镜像分析

```
FROM soulteary/llama2:base

COPY llama2-7b/* ./

CMD ["python", "app.py"]
```

这是一个简单的 `Dockerfile`，用于创建一个 Docker 镜像。下面是对每一行的解释：

+ `FROM soulteary/llama2:base`：这行指定了基础镜像，所有的操作都会在这个镜像的基础上进行。这里使用的基础镜像是 `soulteary/llama2` 的 `base` 标签版本。

+ `COPY llama2-7b/* ./`：这行将主机上的 `llama2-7b` 目录下的所有文件复制到镜像的工作目录中（`./` 表示当前工作目录）。注意这里的源路径是相对于构建上下文的，通常构建上下文就是 `Dockerfile` 所在的目录。

+ `CMD ["python", "app.py"]`：这行指定了容器启动时要运行的命令。这里是运行 `python app.py`。`CMD` 只能在 `Dockerfile` 中出现一次，如果有多个 `CMD`，只有最后一个会生效。

这个 `Dockerfile` 创建的镜像会运行 `app.py`，并且在运行之前，会把你的 `llama2-7b` 目录下的所有文件复制到镜像中。这个 `app.py` 应该是一个 Python 应用程序的入口点。

+ `app.ny`：这个 Python 脚本主要用于创建一个交互式的聊天机器人界面，使用了 `Gradio` 库和 `Hugging Face` 的模型。这个聊天机器人模型是基于 `Meta` 的 `Llama-2-7b` 模型，一个拥有 70 亿参数并且经过聊天指令微调的模型。

以下是这个脚本的主要功能：

> 1. **设置模型参数和提示**：脚本设定了一些默认的模型参数，如 `DEFAULT_SYSTEM_PROMPT`、`MAX_MAX_NEW_TOKENS`、`DEFAULT_MAX_NEW_TOKENS` 等。这些参数用于控制模型的生成行为。
>
> 2. **定义交互功能**：脚本定义了一系列的函数，如 `clear_and_save_textbox`、`display_input`、`delete_prev_fn`、`generate` 等，这些函数用于处理用户的输入和模型的输出，以及一些交互动作，如提交消息、删除之前的消息、清空聊天历史等。
>
> 3. **创建 Gradio 界面**：脚本使用 `Gradio` 库创建了一个交互式的聊天机器人界面，包括一个文本输入框，一个提交按钮，一个聊天机器人的显示区域，以及一些高级选项（如模型的系统提示、最大新生成的 token 数量、生成温度等）。
>
> 4. **处理用户交互**：脚本定义了一系列的事件处理函数，这些函数将在用户进行某些操作（如提交消息、点击按钮等）时被触发。这些函数会处理用户的输入，调用模型进行生成，然后将生成的结果显示在聊天机器人的显示区域。
>
> 5. **启动 Gradio 应用**：最后，脚本启动了 `Gradio` 应用，使得用户可以在 Web 界面上与聊天机器人进行交互。

总的来说，这个 Python 脚本创建了一个交互式的聊天机器人，用户可以在 Web 界面上输入消息，聊天机器人会根据用户的输入和模型的参数生成响应，然后将响应显示在界面上。

+ `model.py`：这个 Python 脚本是一个基于 `Hugging Face` 的 `transformers` 库和 `PyTorch` 的聊天机器人模型的实现。它使用了 `Meta` 的 `Llama-2-7b` 聊天模型，并提供了一些功能来生成聊天响应。

以下是这个脚本的主要功能：

> 1. **模型和分词器的加载**：脚本首先检查是否有可用的 `CUDA` 设备（也就是 `GPU`），如果有，就在 `GPU` 上加载模型，否则，模型为 `None`。然后，脚本加载了模型对应的分词器。
>
> 2. **生成聊天提示**：`get_prompt` 函数用于生成聊天提示，它将系统提示、之前的聊天历史以及用户的当前输入组合成一个字符串，用于输入到模型中。
>
> 3. **生成聊天响应**：`run` 函数用于生成聊天响应。它首先调用 `get_prompt` 函数获取聊天提示，然后使用分词器将提示转换为模型可以处理的输入形式。然后，它创建了一个 `TextIteratorStreamer` 对象，用于从模型生成的输出中获取文本。最后，它在一个新的线程中调用模型的 `generate` 方法生成聊天响应，并将生成的响应返回。

> 这个脚本的主要功能就是提供了一个聊天机器人，用户可以输入消息，然后聊天机器人会生成响应。这个聊天机器人使用了 `Meta` 的 `Llama-2-7b` 模型，并且可以在 `GPU` 上运行，以提高生成响应的速度。

>
> 1. `IMAGE`：这列显示了每个层的 ID。镜像是由多个层（layers）堆叠起来形成的，每个层都是由前一个层的状态和当前指令的结果形成的。`<missing>` 表示这个层的 ID 没有被保留，这通常是因为这个层是中间层，不需要被直接引用。
>
> 2. `CREATED`：这列显示了每个层的创建时间。
>
> 3. `CREATED BY`：这列显示了创建每个层的 Docker 指令。
>
> 4. `SIZE`：这列显示了每个层的大小。注意这个大小是相对于前一个层的，也就是说，这个大小是执行当前指令后增加的大小。
>
> 5. `COMMENT`：这列显示了关于每个层的额外信息。
>
> 这个输出的具体解析如下：
>
> 1. `5248e57678a2   20 hours ago   CMD ["python" "app.py"]                         0B        buildkit.dockerfile.v0`：这一行表示在 20 小时前，执行了 `CMD ["python" "app.py"]` 指令，这个指令设置了镜像的默认命令为运行 `app.py`。这个操作没有增加镜像的大小。
>
> 2. `<missing>      20 hours ago   COPY llama2-7b/* ./ # buildkit                  9.97kB    buildkit.dockerfile.v0`：这一行表示在 20 小时前，执行了 `COPY llama2-7b/* ./` 指令，这个指令将主机上的 `llama2-7b` 目录下的所有文件复制到了镜像的当前工作目录。这个操作增加了镜像的大小约 9.97 KB。
>
> 3. `<missing>      20 hours ago   WORKDIR /app                                    0B        buildkit.dockerfile.v0`：这一行表示在 20 小时前，执行了 `WORKDIR /app` 指令，这个指令设置了镜像的工作目录为 `/app`。这个操作没有增加镜像的大小。
>
> 4. `<missing>      20 hours ago   RUN /bin/sh -c pip config set global.index-u…   603MB     buildkit.dockerfile.v0`：这一行表示在 20 小时前，执行了一个 `RUN` 指令，这个指令运行了一个 shell 脚本来配置 `pip` 和安装一些 Python 包。这个操作增加了镜像的大小约 603 MB。

对比两个映像的 history，可以发现 `base` 提供了完整的模型运行环境，`7b` 针对特定的版本的模型提供交互式聊天界面，所以 `7b` 的构建过程就是拷贝了两个文件（大小为 9.97 KB），并设置了容器启动的时候自动运行 `app.py`。

因此版本对应的映像构建都很快，且版本映像占据硬盘的空间只有新增部分，并不是显示出来的 20 GB。这一点大家不用担心硬盘的空间会被新映像耗尽。空间上的焦虑来自下一节
