## 一、子句

在标准的 SQL 查询中，子句的顺序通常是固定的，但当涉及到 `LIMIT` 或 `OFFSET` 时，情况会稍有不同。以下是更准确的顺序：

1.  `SELECT`：指定要返回的列。
1.  `FROM`：指定数据来源的表。
1.  `WHERE`：指定过滤条件。
1.  `GROUP BY`：对结果进行分组。
1.  `HAVING`：对分组后的结果进行过滤。
1.  `ORDER BY`：对结果进行排序。
1.  `LIMIT` / `OFFSET`：限制返回的行数或跳过行数。

### 1.1 SELECT子句

#### 1.1.1 DISTINCT 关键词

+   `SELECT DISTINCT ids FROM employees;`

⚠️ `DISTINCT` 关键字作用于所有的列，不仅仅是跟在其后的那一列。

例如，你指定 `SELECT DISTINCT ids, salary`，除非指定的两列完全相同，否则所有的行都会被检索出来。

### 1.3 WHERE子句

`WHERE` 子句用于过滤记录，只返回满足指定条件的结果集。在 `WHERE` 子句中有一些常用的条件和关键词。

#### 1.3.1 比较运算符

示例：

+   `SELECT name, salary FROM employees WHERE name = 'JOhn';`

+   `SELECT name, salary FROM employees WHERE name <> 'JOhn';`

#### 1.3.2 逻辑运算符

逻辑运算符支持 `WHERE` 子句的组合，即以 `AND` 子句或 `OR` 子句的方式使用。

`WHERE` 子句可以包含任意数目的 `AND` 和 `OR` 操作符。允许两者结合以进行复杂、高级的过滤。

示例：

+   `SELECT name, salary FROM employees WHERE name = 'Amy' AND salary <= 10;`

+   `SELECT name, salary FROM employees WHERE name = 'Amy' OR salary <= 10;`

+   `SELECT name, salary FROM employees WHERE NOT name = 'John';`

使用逻辑运算符需要注意的点：

1.  优先级：在 SQL 中，`AND` 运算符的优先级高于 `OR` 运算符。如果没有适当使用括号来明确指定运算的顺序，可能会导致逻辑错误

1.  括号要使用得当：不正确使用括号可能导致逻辑运算符的优先级被误解，从而得到错误的结果

1.  性能问题：复杂的 `WHERE` 子句可能导致查询性能下降，特别是当涉及到多个表的连接和大量的数据时

1.  逻辑短路：在某些数据库系统中，`AND` 和 `OR` 运算符可能表现出“短路”行为，即如果前面的条件足以确定整个表达式的结果，后面的条件可能不会被评估

#### 1.3.3 范围运算符

示例：

+   `SELECT name, salary FROM employees WHERE salary BETWEEN 5 AND 10;`

+   `SELECT name, salary FROM employees WHERE name IN （'John','Amy'）;`

+   `SELECT name, salary FROM employees WHERE salary IS NULL;`

#### 1.3.4 模式匹配运算符

`LIKE` 操作符不是针对已知值进行过滤的

+   通配符（wildcard）：用来匹配值的一部分的特殊字符。

+   搜索模式（search pattern）：由字面值、通配符或两者组合构成的搜索条件。

通配符：

百分号（%）：任何字符出现任意次数

下划线（_）：它只匹配单个字符，而不是多个字符

方括号（[]）：指定一个字符集，它必须匹配指定位置（通配符的位置）的一个字符

+   `SELECT name FROM employees WHERE name LIKE 'FISH%';`

+   `SELECT name FROM employees WHERE name LIKE '%FISH%';`

+   `SELECT name FROM employees WHERE name LIKE '__FISH';`

+   `SELECT name FROM employees WHERE name LIKE '[JM]%';`

+   `SELECT name FROM employees WHERE name LIKE '[^JM]%';`

⚠️ 子句 `WHERE prod_name LIKE '%'` 不会匹配产品名称为 `NULL` 的行。

```
SELECT *

/*
select *
```

> `EXISTS` 和 `IN` 的区别：

> `EXISTS` 子句：执行 `employees.length` 次，指定一个子查询，检测行的存在。

> 执行流程：遍历循环外表，然后看外表中的记录有没有和内表的数据一样的。匹配上就将结果放入结果集中。

> `IN` 子句：执行 1 次，确定给定的值是否与子查询或列表中的值相匹配。

> 执行流程：在查询的时候，首先查询子查询的表，然后将内表和外表做一个笛卡尔积，然后按照条件进行筛选。所以相对内表比较小的时候，`in` 的速度较快。

> 在大数据量时，比 `IN` 更高效

### 1.4 GROUP BY子句

基本概念：它用于将数据按照一个或多个列的值分成不同的组，然后对每一组进行聚合计算

与 `GROUP BY` 配合使用的聚合函数（如 `SUM`、`AVG`、`COUNT`、`MAX`、`MIN` 等）可以对每个组进行计算，从而实现对数据的汇总和分析。

```
SELECT column1, column2, ..., aggregate_function(column3)
FROM table
WHERE condition
GROUP BY column1, column2, ...
HAVING condition
ORDER BY column;
```

#### 1.4.1 GROUP BY 子句使用的重要规则和注意事项

1.  `GROUP BY` 子句可以一个列或者多个列

```
SELECT column1, column2, COUNT(*)
FROM table_name
GROUP BY column1, column2;
```

1.  如果在 `GROUP BY` 子句中存在多个列，数据将在最后指定的分组上进行汇总

1.  `GROUP BY` 子句中列出的每一列都必须是检索列或有效的表达式（但不能是聚合函数）。如果在 `SELECT` 中使用表达式，则必须在 `GROUP BY` 子句中指定相同的表达式。不能使用别名

```
SELECT column1, column2, (column1 + column2) AS expr, COUNT(*)
FROM table_name
GROUP BY column1, column2, (column1 + column2);
```

1.  在 `SELECT` 列表中，除了聚合函数外的所有列都必须出现在 `GROUP BY` 子句中。如果某个列是聚合函数的一部分，则不需要出现在 `GROUP BY` 子句中

```
/*
！！正确写法！！
column1 出现在 SELECT 和 GROUP BY 子句中，
而 COUNT(*) 是聚合函数，不需要出现在 GROUP BY 子句中。
*/
SELECT column1, COUNT(*)
FROM table_name
GROUP BY column1;
/*
！！这种写法是错误的！！
column3 没有出现在 GROUP BY 子句中，但它也不是聚合函数的一部分。
根据标准 SQL 规则，这可能会导致问题，因为 column3 的值在每个由 column1 和 column2 定义的组内可能不是唯一的。
*/
SELECT column1, column3, COUNT(column2)
FROM table_name
GROUP BY column1, column2;
```

1.  如果分组列中包含具有 `NULL` 值的行，则 `NULL` 将作为一个分组返回。如果列中有多行 `NULL` 值，它们将分为一组

#### 1.4.2 GROUP BY 子句常见用法

用法一：单列分组

```
SELECT department, COUNT(*) AS employee_count
FROM employees
GROUP BY department;
```

用法二：多列分组

```
SELECT department, job_title, COUNT(*) AS employee_count
FROM employees
GROUP BY department, job_title;
```

用法三：结合多子句

```
/* 按department列分组，统计每个部门的员工数量，并按员工数量降序排列 */
SELECT department, COUNT(*) AS employee_count
FROM employees
GROUP BY department
ORDER BY employee_count DESC;
```

### 1.5 HAVING子句

`HAVING` 和 `WHERE` 子句的本质差别：

1.  `WHERE` 在数据分组前进行过滤，`HAVING` 在数据分组后进行过滤。

1.  性能优化：尽量在 `WHERE` 中过滤掉无关数据，减少 `GROUP BY` 处理的数据量

PS：`GROUP BY` 子句：分组数据

`HAVING` 子句在 SQL 中用于筛选分组后的聚合结果。它通常与 `GROUP BY` 子句一起使用，用于过滤那些不满足特定条件的组。

```
SELECT column1, column2, ..., aggregate_function(column3)
FROM table
WHERE condition
GROUP BY column1, column2, ...
HAVING condition
ORDER BY column;
```

`HAVING` 支持所有 `WHERE` 操作符

过滤 `COUNT(*) >= 2`（两个以上订单）的那些分组：`SELECT ids, COUNT(*) AS orders FROM Orders GROUP BY id HAVING COUNT(*) >= 2;`

#### 1.5.1 HAVING 子句常见用法

`HAVING` 子句必须与 `GROUP BY` 子句一起使用。`HAVING` 子句用于在分组后筛选聚合结果，而 `GROUP BY` 子句用于将数据分成组。如果没有 `GROUP BY` 子句，`HAVING` 子句将没有任何意义，因为没有分组的聚合结果无法进行筛选。

用法一：基本用法

```
/*
按部门分组，并计算每个部门的平均薪资。
HAVING AVG(salary) > 50000 筛选出平均薪资大于50000的部门
*/
SELECT department, AVG(salary) AS average_salary
FROM employees
GROUP BY department
HAVING AVG(salary) > 50000;
```

用法二：结合 WHERE 子句

```
/*
WHERE hire_date > '2020-01-01' 筛选出2020年1月1日之后入职的员工。
HAVING AVG(salary) > 50000 筛选出这些员工中平均薪资大于50000的部门
*/
SELECT department, AVG(salary) AS average_salary
FROM employees
WHERE hire_date > '2020-01-01'
GROUP BY department
HAVING AVG(salary) > 50000;
```

用法三：多筛选条件并使用别名

```
/*
这个查询将员工按部门分组，并计算每个部门的员工数量和最高薪资
HAVING 子句筛选出员工数量大于10且最高薪资大于100000的部门
*/
SELECT department, COUNT(*) AS employee_count, MAX(salary) AS max_salary
FROM employees
GROUP BY department
HAVING employee_count > 10 AND max_salary > 100000;
```

用法四：结合子查询

```
/*
这个查询将员工按部门分组，并计算每个部门的平均薪资
HAVING 子句筛选出平均薪资大于公司整体平均薪资的部门
*/
SELECT department, AVG(salary) AS average_salary
FROM employees
GROUP BY department
HAVING AVG(salary) > (SELECT AVG(salary) FROM employees);
```

#### 1.5.2 HAVING 子句和窗口函数

`HAVING` 子句的功能

+   `HAVING` 子句用于在分组后筛选聚合结果

+   它通常与 `GROUP BY` 子句一起使用

+   `HAVING` 子句中的条件可以涉及聚合函数（如 `SUM`、`AVG`、`COUNT` 等）

窗口函数的功能

+   窗口函数用于在不隐藏原始数据的情况下进行复杂的计算和分析

+   可以在查询中进行排名、累计和、移动平均等操作

+   窗口函数可以结合 `PARTITION BY` 和 `ORDER BY` 子句进行更灵活的计算

**转换的可能性**

1.  `HAVING` 子句转换为窗口函数

在某些情况下，`HAVING` 子句的功能可以通过窗口函数来实现，但通常需要更复杂的查询结构。例如，可以使用窗口函数计算聚合值，然后在外部查询中进行筛选。

1.  窗口函数转换为 `HAVING` 子句

窗口函数的功能通常无法直接用 `HAVING` 子句来实现，因为窗口函数可以在不隐藏原始数据的情况下进行更复杂的计算，而 `HAVING` 子句只能在分组后的聚合结果上进行筛选。

### 1.6 ORDER BY子句

`ORDER BY` 子句在 SQL 中用于对查询结果进行排序。它可以按照一个或多个列的值进行升序或降序排列。默认情况下，`ORDER BY` 按升序排列，如果需要降序排列，可以使用 `DESC` 关键字。

在多列排序中，允许你在第一列的值相同时，根据第二列（或更多列）进行进一步排序。

但是当第一列的值是唯一的（即没有重复值）时，那么第二列（或更多列）的排序规则不会生效，因为第一列已经完全决定了排序顺序。

> 升序排序（从A到Z）：默认的排序顺序，关键字是 `ASC`

> 降序排序（从Z到A）：必须指定 `DESC` 关键字

> 如果想在多个列上进行降序排序，必须对每一列指定 `DESC` 关键字

基本语法如下：
