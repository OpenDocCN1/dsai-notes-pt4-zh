
# Memory 不等于 Log，也不等于 History

应该记录什么内容、不记录什么内容。过度记录也会导致信息冗余、误唤醒。

Memory 是否要分多级处理；什么场景召回，召回哪些；如何做筛选、提炼，做权重更新；尤其是，能否“被看到”、“被编辑”也很重要，对比 ChatGPT，豆包属于是典型的设计上偷懒了，当然，也可能是在排期，或者，当下有更重要的事情。

## 多模态感知 Context

在 AI 应用的设计中，或许“模型能力不是瓶颈，获取用户上下文才是”。

单靠对话很难足够了解用户，需要借助系统集成或其他方式，获取更多用户行为上下文。

## 从「算力分布与通信整合」看 AR / AI 眼镜的两条架构演进路径：一体化 vs 分体式

+ **高集成式架构**：将算力、显示、输入输出等模块集成于一体，类似笔记本电脑的形态，强调“单设备即完整体验”。
+ **分体式架构**：通过有线或无线方式将主机与显示模组、交互装置分离部署，更像是“终端 + 背包主机”的组合，强调灵活性与模块演进能力。

可预见的趋势，技术演进将推动以下核心变量持续优化：

+ **应用场景不断拓宽**
+ **电池能量密度增加**（平均每 12 个月翻一番），配件体积持续缩小
+ **算力提升**，芯片与软件功耗同步下降

### 北极星指标：衡量真正的创新价值

雷鸟创新团队提出的北极星指标是： 每位用户获得的增量价值 × 被服务的用户数量

> 这限制了其从“语音助手”跃迁为“生产力工具”的能力边界。

+ **推理（Reasoning）**：无法对复杂语境进行多步逻辑推导
+ **规划（Planning）**：缺乏多目标任务的执行链设计能力
+ **记忆（Memory）**：短期交互强，长期记忆缺失，无法持续理解用户上下文
+ **工具调用（Tools Use）**：API 工具链生态仍未标准化，调用效率低下
