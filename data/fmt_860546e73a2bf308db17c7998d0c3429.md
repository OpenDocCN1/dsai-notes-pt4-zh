本节关注的重点在针对长文本的序列并行（Sequence Parallelism, SP 或者 Context Parallelism, CP）。在当前 SP 又分为两个技术流派，即 `DeepSpeed-Ulysses` 和 `Ring-Attention`，而这两种路线的底层原理恰好又分别对应着 TP 和 PP，下面来让我们一探究竟。

+ [`DeepSpeed-Ulysess`](https://link.zhihu.com/?target=https%3A//arxiv.org/pdf/2105.13120)：沿序列长度切分 `Q`、`K`、`V` 并分发到不同 GPU 上，在计算全局信息时通过 `allgather` 获取全局信息，通过 `reduce-scatter` 分发，由于这两个通信原语的通信量只与数据量有关，因此随着 GPU 数量增加并不会增加通信量。其思想类似于 TP，在该方法出现之前，`Megatron-LM` SP, `ColossalAI` SP 也采用了类似的方案。

+ `Ring-Attention`：同样沿序列长度切分切分 `Q`、`K`、`V`，但是其计算并不是在空间上并行的，而是在时间上并行，核心是通信和计算重叠。其思想类似于 PP，在此之前最经典的算法是 `FlashAttention`。

![](img/604ab4ac4376a0ab05f926fdd03d637f.png)

即然 PP 和 TP 可以结合使用，以上两种方法也可以结合使用，这就是 `UNIFIED SEQUENCE PARALLELISM`。更多的分析还需要做更多实验，待续。

## 3.2 模块并行与算子并行

首先声明，该节的称谓并非行业通行的叫法，而是笔者为了简洁描述而做的“发明”，读者只需理解其中精髓即可。

在 LLM 中，模块并行其实相当普遍，下面仅举其中比较典型的几例：

+ 最常见和容易被忽略的是 `Transformer` 的原生设计，即 `multi-head` 机制，这一个可以理解为 `attention` 内部的并行；

+ 在 `decoder layer` 中，除了 `attention` 模块之外，另一个主要部分就是 `MLP`，在 `MLP` 内部的并行设计方案最主流的就是 `MoE`，事实上 `MoE` 兼具了并行和稀疏双重特征；

+ 在以上两个模块之间同样可以进行并行计算，最经典的就是 `GPT-J` 和 `Simplified Transformer` 的设计，如下图。该设计尽管确实提高了并行效率，但是这种做法割裂了 `attention` 和 `MLP` 的前后关联性，精度上有所损失，因此未被广泛接受。

![](img/efb2e50da222593df53944917ca028b6.png)

算子并行则是在更细的粒度上提高并行程度，这种做法相当普遍，在此仅举一例，即 `FLASHDECODING++` 中的 `softmax` 的设计。在标准的 `softmax` 中，最大值是按维度进行全局统计或者分布统计计算得到的，其特点就是每一行的最大值是独有的，互相之间并不影响，但是需要单独计算。而 `Asynchronized softmax` 的做法则是，首先统计能够覆盖全模型大部分(99.99%)的值分布的统一最大值，这样再结合上与 `V` 的矩阵乘，就可以减少一个算子的同时提高并行度，如下所示：

![](img/dab26cdd17b892a0ed23c8e8bdc229e4.png)

总结一下，在本文中笔者从并行计算的基础理论出发，系统梳理和总结了 LLM 中不同层次的并行计算方法，提供了一个更宏观的角度审视当前的主流并行计算方法。由于篇幅所限，其中方法的介绍比较浅显，感兴趣的可以更加深入对其中细节进行研究。
