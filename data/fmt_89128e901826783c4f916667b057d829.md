# 《大模型 Agent 开发实战》（体验课）

# 1. 什么是 Agent + Function-Calling + RL

## 概念

> Agent + Function Calling + RL = 让AI从“会说话”变成“会办事、会学习”的组合。

## 以前的 AI：只能“聊天”

以前的大模型（比如早期的 ChatGPT）本质上是一个会说话的文本生成器：

+ 它只能“回答问题”；
+ 它不会真正“操作”或“执行”；
+ 它说的结果很多时候是假想的、模糊的、没法验证的。

比如你问：

> “帮我分析一下我今天支出的 Excel 文件。”

它也许能“假装分析”，但实际上根本打不开你的 Excel。

所以——只能聊天，不能办事。

## Function Calling：让 AI“能动手”

于是人们发明了 Function Calling（函数调用）。

这是一个桥梁，让AI能真正去：

+ 查数据库
+ 调用API
+ 运行代码
+ 操作文件

### 简单理解：

Function Calling 就是“给AI一套工具箱”，它不再只是瞎说，而是能去真的调用工具办事。

### 好处：

+ 输出更可靠：有数据、有结果，不靠想象。
+ 可控：你决定AI能用哪些工具，不会乱跑。
+ 可追踪：每次操作都有记录。

## Agent：让 AI“能自己想”

有了 Function Calling，AI能“动手”了；但还缺一个“决策大脑”——谁来决定先干啥、再干啥？这就需要 Agent。

### Agent 是什么？

就是一个“会自己规划、自己决定要用哪个工具”的AI。

它能：

1. 理解用户意图
2. 规划任务步骤
3. 选择合适的工具调用
4. 判断结果是否满意
5. 如果不对，再想别的办法

### 好处：

+ 能完成多步骤任务（不只是问答）
+ 能自动重试、调整策略
+ 更像一个“有执行力的助手”，而不是“聊天机器人”

## RL（强化学习）：让 AI“越用越聪明”

现在AI已经会：

+ “想步骤”（Agent）
+ “用工具”（Function Calling）

但它还不会总结经验。

这时候，强化学习（RL）登场了。

### RL 是什么？

就是用“奖励”和“惩罚”机制训练AI，让它知道什么行为是好的，什么是不好的。

### 好处：

+ AI能根据结果自动改进策略
+ 长期运行后，错误越来越少
+ 成本更低、成功率更高
+ 能不断优化“办事效率”和“判断能力”

## 三者的关系

| 部分 | 作用 | 比喻 |
| --- | --- | --- |
| Agent | 负责思考、规划、决策 | 大脑 |
| Function Calling | 负责执行、动手 | 手 |
| RL | 负责学习、优化 | 经验积累 |

合在一起，就是一个“有大脑、有双手、会成长”的智能体。

# 2. 什么是 Agent？

大家可能都用过 ChatGPT、Claude、文心一言、通义千问这类 AI 聊天机器人。

它们很强大，能写文案、写代码、回答问题。

但你有没有发现——它们其实只能说，不能做。

比如你让它：

> “帮我查查明天北京的天气，然后订一间 400 元以内的酒店。”

ChatGPT 会告诉你：

> “明天北京 9℃左右，建议选择靠近地铁的酒店。”

但它不会真的去查天气 API，更不会帮你打开携程下单。

——这就是普通大模型的局限：只能聊天，不能行动。

## Agent 出现的背景：让 AI 从“会说”变成“会做”

于是人们就在想：

如果 AI 不只是能聊天，还能自己规划任务、调接口、执行命令、看结果再调整，那它就真的像一个“数字员工”了。

这种能“想→做→检查→再想”的智能体，我们就叫它 Agent。

## Agent 的核心定义

一句最精确又通俗的话：

> Agent 是一个有目标、能自己做决策、能实际执行、能根据结果调整行为的智能系统。

换成人话就是：

> 它不是你问一句它答一句，而是能自己想、自己干、自己判断对不对。

## Agent 的四个关键特征

要判断一个系统是不是 Agent，看这四个点：

1️⃣ 有目标：

它知道要达成什么任务。比如“生成周报”、“找最便宜的机票”、“整理文件并发邮件”。

2️⃣ 会决策：

它不是等你一步步指挥，而是能自己决定下一步干啥。比如：“要写报告→那先查数据库→再画图→再总结”。

3️⃣ 能执行：

它不是光说，而是能真的动手。调用接口、运行脚本、发请求、改文件、甚至下订单。

4️⃣ 会反思和调整：

它能看执行结果对不对，不对就重试或换路子。比如查不到数据，它会想“是不是日期错了？那我换个时间再试”。

这四个条件齐全，才叫真正的 Agent。

## 和传统聊天机器人有什么区别？

| 对比点 | 聊天机器人 | Agent |
| --- | --- | --- |
| 目标 | 模糊（聊天为主） | 明确（任务导向） |
| 行为 | 只输出文字 | 能执行真实动作 |
| 决策 | 被动响应 | 主动规划 |
| 验证 | 没有 | 有反馈和自检 |
| 流程 | 一问一答 | 多步自动化闭环 |

简单说：

> 聊天机器人是“被问才答”，> Agent 是“知道要干嘛，并能自己干到完”。

## 那 Agent 里面“大模型”是干什么的？

这里很多人会混淆。

Agent ≠ 大模型，大模型只是 Agent 的“大脑”。

我们来拆一下：

+ 大模型（LLM）：擅长“理解语言、推理、生成计划”。它能听懂任务、制定步骤、写提示词、写代码。
+ Agent（智能体）：是一个“行动系统”，它拿着大模型的想法去执行。它有自己的记忆、工具、日志、状态判断和策略。

所以两者的关系是：

> 大模型负责想清楚，Agent 负责干到底。

## 例子

假设我们要做一个“自动生成销售报告的 Agent”。

### 1️⃣ 用户说：

> “帮我生成上周的销售分析图。”

### 2️⃣ 普通大模型会：

+ 直接写个 Python 代码给你看；
+ 但它并不会真的执行；
+ 最后结果只是“理论上可以”。

### 3️⃣ Agent 会：

1. 理解任务：需要取上周销售数据 → 生成可视化 → 输出报告
2. 调用工具：
   + 调用数据库接口 `get_sales_data(日期)`
   + 调用图表工具 `plot_chart(数据)`
   + 调用报告生成工具 `create_pdf(标题, 图表)`
3. 拿到结果后判断：
   + 数据为空？那可能是日期错了 → 自动换日期重试
   + 图表生成报错？那换一个模板
4. 任务完成后：输出可下载的报告 + 日志。

这时候 AI 不是在“聊天”，而是在执行完整的任务链条。

这就是 Agent。

## Agent 的五个组成部分

1️⃣ 目标（Goal）：我到底要完成什么？

2️⃣ 决策（Reasoning/Planning）：该怎么做？

3️⃣ 执行（Action）：调什么工具去做？

4️⃣ 记忆（Memory）：上一步做了啥？结果如何？

5️⃣ 反馈（Feedback/Evaluation）：任务完成了吗？要不要调整？

这一整套循环，就是 Agent 的闭环系统。

## 为什么现在大家都在做 Agent？

因为 Agent 能让企业或个人：

+ 自动化重复工作（报表、比价、问答、运维、客服）
+ 降低人力成本（一个 Agent 顶几个人的体力活）
+ 提高准确率和可控性（可追踪、可回放、有日志）
+ 让大模型落地到真实场景（从能说到能干）

举个例子：

+ 电商：自动比价、自动选品；
+ 企业：自动生成周报、项目跟踪；
+ 客服：自动处理退换货；
+ 程序开发：自动修 bug、部署、测试。

这些都在靠 Agent 落地。

## 那 Function Calling 和 RL 又怎么配合？

+ Function Calling 就是给 Agent 一堆“工具”。比如查天气、读数据库、写文件。Agent 通过这些“手”去完成动作。
+ RL（强化学习）是让 Agent“越做越聪明”。做对了给奖励，做错了扣分，长期训练下来，它就知道哪种行为最有效。

所以整套体系是：

> 大模型提供思考力 → Function Calling 提供执行力 → RL 提供学习力。

# 3. 什么是 Function Calling

以前我们用 ChatGPT 或大模型时，经常会出现这样的情况：

> 你问：“帮我查一下明天北京的天气。”
> 它回答：“抱歉，我无法访问实时数据。”

为什么？

因为大模型只是一个语言模型，它懂语言，但不会真的去上网查、不会执行命令。

这就像一个特别聪明的学生，你问啥他都能推测、能猜，但他就是动不了手。

于是——

人们给这个学生发明了一双“手”——这双手就叫 Function Calling（函数调用）。

## 定义

> Function Calling 是让大模型能“使用工具”的机制。

它把 AI 从“光说不练”，变成“会动手”的状态。模型不再只输出文字，而是能根据任务自动调用你给它的函数或接口，拿到真实结果后，再把结果转成自然语言告诉你。

## 为什么要有 Function Calling？

三个问题：

1️⃣ 模型虽然聪明，但它回答的很多内容是“想象的”——我们叫它幻觉。
2️⃣ 模型不知道外部世界的实时信息，比如“股票价格”“天气”“数据库数据”。
3️⃣ 模型不能执行动作，比如“运行脚本”“发邮件”“生成文件”。

👉 Function Calling 就是为了解决这三个问题。

## Function Calling 到底怎么工作？

想象大模型是一个秘书，而你给秘书准备了一整套工具箱：

+ 查天气的工具
+ 发邮件的工具
+ 生成图表的工具
+ 查询数据库的工具

秘书（模型）平时你跟它说话，它听懂后如果觉得要动手，就会在后台写下一段“指令”：

```json
{
  "name": "get_weather",
  "arguments": {
    "city": "北京",
    "date": "2025-11-14"
  }
}
```

系统拿到这个结构化请求后，去执行你定义的真实函数 `get_weather()`，查完结果再返回给模型，比如：

```json
{
  "temperature": 9,
  "summary": "小雨"
}
```

模型再根据结果生成自然语言回答：

> “明天北京小雨，9℃左右，记得带伞。”

就这样，一个“光说不练”的模型变成了一个会用工具的智能体。

Function Calling = 模型与外部世界的桥梁。

模型以前只能在“文字世界”里推理；有了 Function Calling，它就能“伸手”去做事。

所以现在很多公司都会说：

> “我们做了 AI Agent。”
> 其实背后最核心的一环，就是 Function Calling。

## Function Calling 带来的 3 个巨大好处

### 1️⃣ 让模型结果真实可验证

以前它回答“北京明天下雨”，只是猜；现在是通过真实接口查来的数据，可验证。

### 2️⃣ 让模型能力无限扩展

大模型本身不会算汇率、不会发邮件、不会跑 Python。但你给它接上相应的函数，它就瞬间拥有这些能力。相当于“装插件”一样。

### 3️⃣ 让模型安全可控

Function Calling 不是让模型“随便上网”，而是只允许它调用你定义好的函数、传固定参数。你决定它能干什么、不能干什么。

这样既能动手，又不会乱搞。

## 场景代入

### 场景一：报表生成

用户说：“帮我出一份上周销售数据的柱状图。”

→ 模型分析任务

→ 调用函数 `query_sales_data(start_date, end_date)`

→ 调用函数 `generate_chart(data, type='bar')`

→ 输出最终图表。

这里整个报表都是 AI 真实生成的，而不是想象的。

### 场景二：智能客服

用户问：“我上次订单什么时候发货的？”

→ 模型理解到需要查数据库

→ 调用函数 `get_order_status(order_id)`

→ 查询结果返回：“已发货，顺丰单号 123456”。

这时客服机器人就是一个有 Function Calling 的 Agent。

### 场景三：AI 助理自动发邮件

你说：“帮我把会议纪要发给张三。”

→ 模型调用 `compose_email(to, subject, body)`

→ 再调用 `send_email()`

→ 完成任务。

## Function Calling 在 Agent 体系里的位置

在 Agent 这个“自动化助手”体系中，Function Calling 扮演的是“手”的角色。

| 模块 | 作用 | 类比 |
| --- | --- | --- |
| 大模型（LLM） | 理解、思考、制定计划 | 大脑 |
| Function Calling | 按计划执行任务 | 双手 |
| Memory/Feedback | 记忆和复盘 | 经验 |
| RL（强化学习） | 持续优化策略 | 学习能力 |

大模型想好“该做什么”，Function Calling 就负责“去做这件事”。

没有 Function Calling，Agent 就只是“说得好听但做不成”的理论家。

## Function Calling 的设计思想

它其实建立在三个核心理念上：

### 1️⃣ 结构化输入输出

→ 模型不再只生成自然语言，而是输出结构化 JSON。

→ 系统根据 JSON 去调用真实函数。

### 2️⃣ 受控执行

→ 模型不能随意执行命令，只能在你提供的工具范围内操作。

### 3️⃣ 结果回传机制

→ 执行完后把结果再反馈给模型，模型重新思考下一步要干啥。

这就形成了一个“感知—行动—反馈”的小闭环。

# 4. 什么是 RL？

RL（强化学习）：给模型设定“奖惩规则”，让它在试错与反馈中学会做出更符合目标的决策；不是背答案，而是学策略。

## 1. 放在大模型训练全景里看

把“让模型变好用”分三层理解：

1. 预训练（PT）：海量无标数据，学语言常识与泛化能力。
2. 监督微调（SFT）：用人工写的“输入→理想输出”对，教它按范例回答。
3. 强化学习（RL）：设目标与奖励，让它为了结果优化行为策略（例如更有用、更安全、更简洁、更高通过率）。

> 类比：

+ 预训练=学词汇与语法；
+ SFT=背标准答案；
+ RL=给规则与评分标准，让它为了“高分/高通过率”自己摸索更优做法。

## 2. SFT 与 RL 的本质差异（避免混淆的关键）

| 维度 | SFT（监督微调） | RL（强化学习） |
| --- | --- | --- |
| 学习目标 | 拟合“老师提供的理想答案” | 最大化“奖励函数”（偏好/成功率/成本等） |
| 训练信号 | 逐词交叉熵，跟着参考答案学 | 标量“好/坏”的奖励（可以没有标准答案） |
| 适用场景 | 有成体系的高质量标注数据（客服话术、格式化输出等） | “结果好不好”可度量但标准答案不唯一（多步工具调用、对齐人类偏好、安全性） |
| 优势 | 收敛稳定、实现简单、成本可控 | 目标导向强、能突破“照抄答案”的上限 |
| 局限 | 学“像答案”，但不一定“最有用/最省钱/最安全” | 训练不稳定、奖励难设计、易投机取巧 |

### 一句话：

SFT 让模型更像老师写的答案；RL 让模型“更符合目标（更有用/更安全/更高通过率）”。

## 3. RL 家族常见名词与边界

+ RLHF（Reinforcement Learning from Human Feedback）：人类打分/偏好 → 训练“奖励模型” → 用 RL（常见 PPO）优化策略模型。
+ RLAIF（from AI Feedback）：用强模型当“评审”替代人工，降成本，但风险是评审偏差被放大。
+ PPO（一种 RL 优化算法）：约束更新幅度，避免模型“漂移太狠”。RLHF 落地时最常见。
+ DPO / IPO / KTO（偏好优化的“无奖励模型”方法）：不显式训练奖励模型，直接用偏好对做“离线对比学习”。

👉 常被称为“无 RL 的 RL”（严格说是偏好监督，工程稳定、性价比高）。

### 边界清晰点：

+ 严格的在线 RL：有策略—环境交互、显式奖励最大化（PPO 类）。
+ 偏好优化（DPO/IPO/KTO）：更接近“监督学习形式”的对比目标，但优化方向与 RL 的“对齐目标”一致，因此经常被放在“RL 类方法”同一篮子里用于效果与成本折中。

## 在线 RL vs 离线偏好优化
