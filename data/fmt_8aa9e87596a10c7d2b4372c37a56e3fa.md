## 藏师傅的 Vibe Coding 15 条建议 ——把本文全部经验压缩成一份「拿来就能用」的清单

1. **聚焦单一核心功能：** 第一次动手就先做一个功能点，别妄想一口气复刻完整抖音。
2. **写需求＝写产品说明书：** 用「我想开发一个…」模板，把目标用户、场景、功能逐条写清楚，越细越好。
3. **珍惜第一次提示词：** 首轮提示词决定成败，别用“帮我写个网页”这种含糊表达。
4. **IDE 规则先配置：** 在 Trae 的 Rule 面板贴上前端最佳实践规则，让 AI 自动遵守编码规范。
5. **选顶级模型再开干：** Claude 3.5 、 GPT-o4 mini等大模型才压得住复杂项目，别拿小模型硬撑。
6. **全链路测试清单：** 功能完整性 → 边界数据 → 响应式 → 用户可用性，按表格逐项勾。
7. **一次只改一个问题：** 每轮对话聚焦单 Bug / 单功能，验证通过再进入下一轮。
8. **发现跑偏立即回滚：** Trae 里的“回到发起前”就是 Ctrl‑Z，别让错误分支越走越远。
9. **用 # 文件锚点精准定位：** “`#src/components/Card.tsx` 第 42 行按钮颜色改为 #3366FF”——越精确，AI 改得越准。
10. **报错信息完整贴给 AI：** 控制台红字别截半张图，一起贴上上下文和操作步骤。
11. **把业务数据抽成 JSON：** 内容与代码分离，后期只维护数据文件，无需频繁重编译。
12. **敏感信息留到运行时填：** API Key、密码用环境变量或输入框，别硬写进源码。
13. **越改越糟就重开项目：** 成本是时间不是面子，早放弃＝少痛苦。
14. **选最省心的部署方式：** 文件拖到 yourware → 自动上线；进阶用户 Netlify / Vercel + 自定义域名。
15. **持续收集真实反馈：** 找 3‑5 个目标用户试玩，记录每个“卡壳”瞬间再迭代。
