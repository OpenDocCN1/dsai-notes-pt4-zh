
## GitHub Codespaces

+ JetBrains 插件：在 JetBrains IDE 中使用 Codespace 时，从 JetBrains Marketplace 添加插件。

### 使用场景

GitHub Codespaces 适用于多种开发工作流，尤其适合需要计算资源和终端访问的“更繁重”的工作。

1. 新项目启动：通过 GitHub 模板或任何模板存储库启动新项目。

1. 新功能开发：从存储库中的分支进行新功能工作。

1. 探索进行中的工作：从打开的拉取请求中探索正在进行的工作。

1. bug 调查：从存储库历史记录中的提交调查特定时间点的 bug。

1. 代码测试：暂时使用 Codespace 来测试代码。

1. 长时间功能开发：返回到同一 Codespace 处理长时间运行的功能工作。

1. 加速创建：存储库管理员可以为存储库启用 GitHub Codespaces 预生成，以加快 Codespace 的创建速度。

1. 替代本地环境：它提供了个人虚拟机 （VM） 的强大功能，具有终端访问权限，就像在使用自己的本地环境一样，只是在云中。

### 计费

GitHub Codespaces 采用基于使用的计费模式：

1. CPU 费用：只有正在运行的 Codespace 才会产生 CPU 费用。

1. 存储成本：停止的 Codespace 仅产生存储成本。

1. 免费使用配额：个人帐户每月有免费使用配额。

1. 成本管理：通过设置超时期限（默认 30 分钟）和配置自动删除（最长 30 天）可以帮助管理 CPU 和存储成本。

### Codespace 与 GitHub.dev 的对比

以下是它们之间的主要区别：

1. 核心用途和计算能力

+ `GitHub.dev`：主要用于导航文件和源代码存储库，以及进行代码更改并提交代码更改。它没有关联的计算资源，因此无法用于构建、运行或调试代码。它更适合于轻量级的浏览和编辑。

+ GitHub Codespaces：适用于更繁重的工作，如测试代码。它具有关联的计算资源，可以让你生成代码、运行代码并具有终端访问权限。它提供了个人虚拟机 （VM） 的强大功能，就像在使用自己的本地环境一样，只是在云中。

1. 成本

+ `GitHub.dev`：免费使用。

+ GitHub Codespaces：个人账户每月有免费使用配额。只有正在运行的 Codespace 才会产生 CPU 费用，而停止的 Codespace 仅产生存储成本。

1. 启动时间

+ `GitHub.dev`：按下按键时立即打开，可以马上开始使用，无需等待配置或安装。

+ GitHub Codespaces：创建或继续 Codespace 时，需要分配虚拟机和存储，创建一个容器，建立连接，并执行创建后设置。这个过程需要几分钟时间来创建开发环境。

1. 终端访问

+ `GitHub.dev`：不提供终端访问。

+ GitHub Codespaces：默认提供一组通用工具的集成终端访问，可以像在本地环境一样使用终端。

1. 扩展支持

+ `GitHub.dev`：在扩展视图中，只有可以在 Web 中运行的扩展子集会显示并可以安装。

+ GitHub Codespaces：可以使用 Visual Studio Code Marketplace 中的大部分扩展。

1. 持久性与生命周期

+ `GitHub.dev`：没有持久的云环境的概念。

+ GitHub Codespaces：拥有一个从创建到删除的生命周期，可以断开连接并重新连接，停止并重启，而不会丢失更改。你的工作会保存到云中的虚拟机上。当 Codespace 处于非活动状态或未显式停止时，它会在一段时间后超时并停止运行，但数据会被保留。

尽管两者有所不同，但你可以在 `GitHub.dev` 中启动工作流，并在需要“运行和调试”视图或终端等计算功能时，选择“继续处理...”，在 Codespace 中继续工作。

## GitHub Projects

GitHub Projects 是一个功能强大的规划和追踪工具，提供灵活的视图选项，帮助团队组织工作并掌握全局。它可以让团队在一个位置轻松地组织、设置优先级和跟踪所有的功能需求和其他内容。

### 核心功能与组件

GitHub Projects 旨在提供更丰富的体验，以跟踪工作和办公位置。其核心功能和组件包括：

1. 灵活的视图选项：

+ 表格视图 （Tables）：可以按自定义字段（如文本、数字、日期、迭代和单选）对项目进行排序、设置级别和分组。

+ 看板视图 （Boards）：用于直观地查看和管理任务，支持自定义卡片和分组。

+ 时间轴视图 （Timelines）：作为一种布局选项，帮助可视化工作进度。

1. 数据与自定义字段 （Data and Custom Fields）：

+ 可以定义多种类型的自定义字段，包括文本、数字、日期、迭代和单选。

+ 迭代字段支持灵活的日期范围和中断，可用于表示冲刺 （sprint）、周期或季度路线图。

+ 支持草稿问题，包含详细说明和元数据。

+ 在表格和看板视图中查看已链接的拉取请求和审阅者。

1. 见解 （Insights）：

+ 提供当前图表和历史图表，用于创建视觉效果以加强对工作的理解，帮助了解项目的趋势和进度。

+ 可以创建和配置自定义的条形图、柱形图、折线图和堆积面积图。

+ 支持使用 `sum`、`count`、`average`、`min` 和 `max` 等聚合函数获取见解。

+ 图表可以保存并使用 URL 共享。

1. 自动化 （Automation）：

+ 内置的自动化工作流可帮助自动组织和更新项目项。

+ 支持通过 `GraphQL ProjectsV2 API` 和 GitHub Actions 进行高度自定义的自动化。

+ Webhook 事件用于项目项元数据更新。

1. 任务分解与跟踪：

+ 支持将清单项转换为子问题，以便更好地进行任务分解和跟踪。这会在项目视图中创建一个关联的问题，具有自身的状态和元数据。

1. 项目可见性和访问权限 （Visibility and Access Control）：

+ 可以控制项目是公共还是专用。

+ 组织拥有项目的管理员可以管理整个组织、团队、单个组织成员和外部协作者的访问权限（不允许访问、读取、写入、管理员）。

+ 个人拥有项目的管理员可以邀请单个协作者和管理其访问权限（读取、写入、管理员）。

### 使用方法

GitHub Projects 的使用方法涵盖了从创建到管理和自动化等多个方面：

1. 创建项目：

+ 在 GitHub.com 的右上角选择个人资料照片，然后选择“你的组织”或直接导航到“项目”选项卡。

+ 选择“新建项目”按钮。

+ 可以选择从头开始并选择“表”模板来创建项目。

+ 项目可以在组织级别创建，也可以通过选择个人资料照片并导航到“项目”来创建个人项目。

+ 还可以直接从存储库创建项目，这会自动将存储库链接到项目。

1. 设置项目信息：

+ 导航到新创建的项目，选择右上角的三点图标，然后选择“设置”。

+ 可以编辑项目名称、添加简短说明和编写自述文件，以便团队了解项目目的和目标。

1. 添加问题和拉取请求：

+ 添加现有项：复制现有问题或拉取请求的 URL，粘贴到项目底行的 `+` 旁边。

+ 搜索现有项：在项目底行输入 `#` 搜索存储库，然后键入问题或拉取请求的标题进行查找。

+ 批量添加：选择项目底行中的 `+`，然后选择“从存储库添加项”，可以全选或选择特定项。

1. 组织项目：

+ 创建自定义字段：在表视图最右侧的字段标题中选择 `+`，选择“新建字段”，键入名称（如“优先级”），选择字段类型（如“单一选择”），然后添加选项（如“紧急”、“高”、“中”、“低”）。

+ 按优先级分组：选择当前打开的视图名称旁边的向下箭头，选择“分组依据”，然后选择“优先级”。

+ 添加迭代字段：在表视图中选择 `+`，选择“新建字段”，添加字段名称（如“项目阶段”），在“字段类型”下选择“迭代”，设置“开始”日期和“持续时间”。

+ 创建看板视图：在当前打开的视图中，选择向下箭头，然后在“布局”下选择“版块”。可以将问题和拉取请求拖放到各个列中。

1. 自动化项目：

+ 启用内置工作流：打开项目，选择右上角的三点菜单，然后选择“工作流”。

+ 选择触发器（如“添加到项目的项”），设置值（如 `Status: Todo`），然后选择“保存并开启工作流”。

+ 对于更高级的自定义自动化，可以使用 GitHub Actions 和 `GraphQL` API。

1. 管理项目可见性和访问权限：

+ 控制可见性：导航到项目，选择右上角的三点图标，选择“设置”，在“危险区域”下更改“可见性”为“专用”或“公开”。

+ 邀请协作者和更改角色：在项目设置中选择“管理访问权限”，通过搜索栏邀请个人和团队，并更改其角色。

+ 将项目添加到团队：在组织设置的“团队”选项卡下，选择团队名称，然后选择“项目”和“链接项目”。

+ 将项目添加到存储库：导航到存储库主页，选择“项目”选项卡，然后选择“链接项目”。

1. 将清单项转换为子问题：

+ 打开包含清单的问题，将鼠标悬停在清单项上，点击 ... 菜单，然后选择“转换为子问题”。

1. 关闭和删除项目：

+ 导航到项目，选择右上角的三点图标，然后选择“设置”。

+ 在“危险区域”部分，选择“关闭项目”（保留内容，可重新打开）或“删除项目”（永久移除所有内容）。

## 在 Github 使用 Markdown

Markdown 和 GitHub-Flavored Markdown （GFM） 通过提供精简且易于编辑的方法来简化内容创建，并相较于 HTML 具有显著优势。

Markdown 和 GFM 如何简化内容创建：

Markdown 通过保护内容创建者免受 HTML 的繁琐影响，提供了一种精简的内容编辑方法。它在内容描述的 HTML 功能与易于编辑的纯文本之间取得了有效的折衷。GFM 则通过集成 GitHub 功能的扩展进一步增强了内容创建。

具体来说，它们通过以下方式简化内容创建：

+ 强调文本：使用单个星号 `*` 或下划线 `_` 实现斜体，使用双星号 `**` 或双下划线 `__` 实现粗体。还可以混合使用不同的强调效果，例如 This is italic and bold text。如果需要显示星号或下划线本身，可以使用反斜杠转义字符 `\`。

+ 声明标题：通过 `#` 符号实现 HTML 的 `<h1>` 到 `<h6>` 标题功能，从一个 `#` 到六个 `#` 分别对应不同级别的标题。

+ 链接图像和站点：图像链接遵循 `![Link an image.](/path/to/image.png)` 的结构，而网站链接则使用 `[Link to Microsoft Training](/training)`。

+ 创建列表：可以定义有序列表（以数字开头）和无序列表（使用星号 `*` 或破折号 `-`），并通过缩进创建嵌套项。

+ 构建表格：使用竖线 `|` 作为分栏符，并使用破折号 `-` 将上一行指定为标题来构造表格。

+ 引用文本：使用大于号 `>` 字符来创建块引用。
