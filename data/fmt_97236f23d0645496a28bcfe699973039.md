# Perform hyperparameter tuning with a sweep job

https://github.com/MicrosoftLearning/mslearn-azure-ml/blob/main/Instructions/09-Hyperparameter-tuning.md

## 实验特点与知识点分析 （基于 `Instructions/09-Hyperparameter-tuning.md`）

### 核心目标

这个实验的核心目标是让你从“手动、串行”的超参数试错方式，升级为“自动化、并行”的智能搜索。你将学会如何定义一个超参数的搜索空间和采样方法，然后将繁重的、重复的训练任务外包给 Azure ML 平台。平台会利用其强大的并行计算能力，高效地探索大量超参数组合，并自动找出性能最佳的那一组。

### 流程分析

这个实验在 Jupyter Notebook 中完成，其流程展示了如何构建和提交一个复杂的扫描作业（Sweep Job）：

1. **准备基础组件（Prepare Base Component）**：首先，像之前的实验一样，创建一个标准的命令作业（Command Job）。这个命令作业就是我们进行超参数搜索的“模板”或“蓝图”。它的特殊之处在于，它的命令行参数（如 `--reg_rate`）不再被赋予一个固定的值，而是作为后续扫描过程中的变量。

1. 定义搜索空间（Define the Search Space）：这是流程的核心。你需要告诉 Azure ML 要在哪个范围内搜索超参数。例如，为正则化率 `reg_rate` 定义一个从 0.01 到 0.1 的均匀分布。

1. 配置扫描作业（Configure the Sweep Job）：将上述所有部分组合成一个 `sweep` 对象：

   + **目标（Trial）**：指定使用第一步中创建的“命令作业模板”作为每一次尝试的基础。

   + 搜索空间（Search Space）：关联第二步中定义的参数范围。

   + 采样算法（Sampling Algorithm）：选择一种搜索策略，例如随机采样、网格采样或更智能的贝叶斯采样。

   + 目标指标（Objective）：明确告诉扫描作业要最大化或最小化哪个指标（例如，最大化 AUC）。这是它用来评判“好坏”的唯一标准。

1. 设置限制与策略（Set Limits and Policies）：

   + **限制（Limits）**：设置总尝试次数、最大并行尝试次数等，以控制成本和时间。

   + 早停策略（Early Termination Policy）：（可选）配置一个智能策略，如果一个尝试在早期就表现不佳，就提前终止它，从而节省计算资源。

1. 提交并监控（Submit and Monitor）：将配置好的 `sweep` 作业提交到 Azure ML。你会看到一个父运行（Parent Run）被创建，它会陆续启动大量的子运行（Child Runs），每个子运行都代表着用一组特定超参数进行的一次训练尝试。

1. 获取最佳结果（Get the Best Trial）：作业完成后，你可以通过 SDK 或 UI 轻松地查询到父运行，并直接获取到性能最好的那个子运行及其对应的超参数组合和产出的模型。

### 关键知识点介绍

+ 超参数（Hyperparameter）：在模型训练开始之前就需要手动设置的参数，它们控制着学习过程本身（例如，学习率、正则化强度、树的数量）。超参数的选择对模型最终性能有至关重要的影响。

+ 扫描作业（Sweep Job）：这是 Azure ML SDK v2 中用于执行超参数搜索的专用作业类型。它本质上是一个“元作业（Meta-Job）”，负责管理和调度大量的、由“命令作业模板”定义的子作业。

+ 搜索空间（Search Space）：对每个你想要调优的超参数，定义其取值范围和分布。例如：

  + `uniform(0.01, 0.1)`： 在 0.01 到 0.1 之间均匀取值。

  + `choice(16, 32, 64)`： 从 16， 32， 64 这几个离散值中选择一个。

  + `loguniform(0.001, 0.1)`： 在对数尺度上均匀取值，适用于学习率等参数。

+ 采样算法（Sampling Algorithm）：定义了如何从搜索空间中抽取参数组合进行尝试的策略：

  + 网格采样（Grid Sampling）：尝试所有参数值的笛卡尔积组合，非常彻底但计算成本高。

  + 随机采样（Random Sampling）：在搜索空间中随机抽取组合，通常比网格采样更高效。

  + 贝叶斯采样（Bayesian Sampling）：一种智能采样方法。它会根据已完成的尝试结果，来动态地、有偏好地选择下一组最有可能带来性能提升的参数组合，通常能以更少的尝试次数找到更好的结果。

+ 目标（Objective）：扫描作业的优化目标，由一个目标指标（Metric）和一个优化方向（Goal）（maximize 或 minimize）组成。例如，`Objective(goal="maximize", primary_metric="AUC")`。

+ 尝试（Trial）：扫描作业启动的每一次独立的训练运行，即一个子运行。

### 核心步骤分解

#### 1. `command_job = command(...)`：定义“蓝图”

+ 这一步与上一个实验非常相似，我们首先定义一个基础的 `command` 作业。

+ **关键不同点：** 在 `command` 字符串中，`--learning_rate` 这个参数的值被设置为一个占位符 `${{inputs.learning_rate}}`。我们没有在 `inputs` 字典中为它提供一个具体的值。这使得它成为了一个“可配置的变量”，等待 `sweep` 作业来填充。

#### 2. `sweep_job = command_job.sweep(...)`：配置扫描作业

+ 这是整个流程的核心。我们直接在“命令作业蓝图”（`command_job`）上调用 `.sweep()` 方法来构建扫描作业。这种链式调用使得代码非常直观。

+ `sampling_algorithm="random"`： 如何搜索？ 指定使用随机采样算法。

+ `primary_metric="AUC"` 和 `goal="Maximize"`： 目标是什么？ 明确指示扫描作业的目标是最大化脚本中记录的名叫 AUC 的指标。

+ `search_space={...}`： 在哪里搜索？ 这是最关键的配置。

+ `"learning_rate": Uniform(min_value=0.01, max_value=0.1)`： 这个配置将 `search_space` 中的 `learning_rate` 键，与 `command_job` 中那个名为 `learning_rate` 的占位符输入关联了起来。它告诉扫描作业：对于每一次尝试，你需要从 0.01 到 0.1 的均匀分布中抽取一个值，然后用这个值去填充 `command_job` 的 `learning_rate` 输入。

+ `limits=...`： 设置边界。

+ `max_total_trials=4`： 总共最多运行 4 次尝试。

+ `max_concurrent_trials=2`： 在计算集群上，最多同时并行运行 2 次尝试。

+ `timeout=1200`： 整个扫描作业（父运行）在 1200 秒（20 分钟）后会自动超时。

**总结一下：** 这个流程的精髓在于分层定义。你首先定义了一个“单次运行该如何执行”的模板（`command_job`），然后在此基础上，定义了一个“如何多次、智能地、并行地执行这个模板”的元流程（`sweep_job`）。这是一种非常强大和模块化的工作模式。

> **Q：** 能否解释一下超参数的作用，因为我觉得这似乎是一种自动调参数的设计？我总是以为它和 AutoML 是一回事，对不起，我对 ML 的原理所知甚少，请给我一个浅显的解释，谢谢！

> **A：** 当然，这是一个非常好的问题，也是很多初学者都会混淆的地方。您的感觉是对的，它们都是“自动调参”的设计，但它们“自动”的范围和层次完全不同。

> 让我用一个尽可能浅显易懂的比喻来解释。

### 设想你在烤一个蛋糕

在这个比喻中：

+ 蛋糕 = 你最终得到的机器学习模型。

+ 食材（面粉， 鸡蛋， 糖） = 你的数据。

+ 烤箱 = 你的算法（例如，逻辑回归、决策树等）。

+ 烤箱的旋钮（温度、时间） = 超参数（Hyperparameters）。

#### 什么是超参数？

超参数就像是你家烤箱上的那些旋钮——“烘烤温度”和“烘烤时间”。

1. 你必须在使用前设定它们：在你把蛋糕糊放进烤箱之前，你必须先决定好要用多少度来烤、烤多久。你不能等蛋糕烤到一半再去调温度。同样，在模型开始“学习”（训练）之前，你也必须先把学习率、正则化率这些超参数设定好。

1. 它们控制着“学习”的过程：

   + 温度太低、时间太短：蛋糕烤不熟，里面还是生的（这叫欠拟合（Underfitting），模型太简单了，什么都没学会）。

   + 温度太高、时间太长：蛋糕烤焦了，外面糊了，里面也硬邦邦的（这叫过拟合（Overfitting），模型学得太过火了，把数据中的一些偶然噪声都当成了规律）。

   + 只有恰到好处的温度和时间组合，才能烤出一个完美的蛋糕（得到一个性能最好的模型）。

> 所以，超参数调优，就是“为了找到能烤出最好蛋糕的‘温度’和‘时间’组合，而反复试验、调整旋钮的过程”。

## 超参数调优（Hyperparameter Tuning） vs。 AutoML

> 现在，我们来看看这两种“自动调参”的区别。

### 超参数调优（Lab 09） - 你是“专业的蛋糕师”

+ 你知道用哪个烤箱：你已经自己选好了要用哪个牌子、哪个型号的烤箱（你自己选定了要用“逻辑回归”这个算法）。

+ 你只想让机器帮你试旋钮：你的工作是把蛋糕糊放进烤箱。但你不想自己一次次地去试“180 度烤 30 分钟”、“190 度烤 25 分钟”……这个过程太繁琐了。

+ 于是，你雇佣了一个聪明的机器人助手：你对机器人说：“我的烤箱是这个型号（你提供了 `CommandJob`），你帮我把温度在 150 到 200 度之间、时间在 20 到 40 分钟之间，多试几种组合。每烤出一个蛋糕，你就尝一下，告诉我哪个最好吃（`primary_metric`）”。

**结论：** 超参数调优是你指定了算法，然后让机器帮你在这个算法的“旋钮”（超参数）上做大量的、智能的实验，来找到最佳设置。你仍然在主导，只是将“调旋钮”这个重复性工作自动化了。

### AutoML（Lab 06） - 你是“餐厅老板”

+ 你连用哪个烤箱都不知道：你只知道你想做一个“巧克力蛋糕”（你定义了问题和数据），但你不知道是用普通烤箱、微波炉烤箱、还是空气炸锅烤箱（你不知道该用逻辑回归、决策树、还是神经网络）。

+ 你想让机器帮你搞定一切：你不想当蛋糕师，你只想得到一个完美的蛋糕。

+ 于是，你直接承包了一个全自动的“智能厨房”：你对厨房的中央电脑说：“这是我的食材（数据），我的目标是做一个最好吃的巧克力蛋糕（`primary_metric`）。给你 24 小时，你自己看着办吧！”

+ 然后，这个智能厨房开始疯狂工作：

   1. 它拿出各种各样的烤箱（尝试不同的算法）。

   1. 对于每一种烤箱，它都自动地去尝试各种旋钮组合（自动进行超参数调优）。

   1. 它甚至还会自动地对你的食材进行一些预处理（自动进行特征工程）。

   1. 最后，它把所有成品比较了一下，直接把最好吃的那一个端到你面前。

**结论：** AutoML 是一个更高层次的自动化。你基本上只提供数据和目标，它不仅会帮你自动调超参数，还会帮你自动选择用哪个算法，甚至还会自动做一些数据准备工作。你放弃了大部分的控制权，以换取极高的自动化和效率。
