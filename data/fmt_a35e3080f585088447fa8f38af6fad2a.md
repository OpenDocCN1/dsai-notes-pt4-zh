### 3.2.2 核心组件说明

#### Gateway （网关） - 系统心脏

**定义：**

Gateway 是 OpenClaw 的核心，一个长期运行的 Node.js 进程，作为整个系统的单一控制平面（Single Control Plane）。

**核心职责：**

**① 连接管理**

```
// Gateway WebSocket 服务器配置
const gateway = new WebSocketServer({
  host: '127.0.0.1',  // 默认仅本地访问(安全考虑)
  port: 18789,         // 默认端口
  maxConnections: 10   // 最大并发连接数
});

// 支持的客户端类型
enum ClientMode {
  OPERATOR = 'operator',  // 控制端(CLI、Web UI)
  NODE = 'node'           // 能力节点(执行端)
}
```

**② 会话管理**

+ 每个用户/渠道维护独立的会话（Session）
+ 会话状态持久化到 JSONL 文件（纯文本，易于审计）
+ 支持会话恢复（系统重启后对话历史不丢失）

```
会话文件结构:
~/.openclaw/
  ├── sessions/
  │   ├── whatsapp-user123.jsonl    # WhatsApp 用户会话
  │   ├── telegram-user456.jsonl    # Telegram 用户会话
  │   └── cli-local.jsonl           # 本地 CLI 会话
  └── gateway.pid                   # Gateway 进程 ID
```

**③ 消息调度 - Lane Queue 机制**

OpenClaw 的一个**核心创新**是 Lane Queue（车道队列）系统，默认采用串行执行来防止竞态条件：

```
传统并发模型的问题:
用户: "创建文件 test.txt"
用户: "删除文件 test.txt"  (几乎同时发送)

并发执行可能导致:
- 删除先执行 → 文件不存在 → 创建成功(错误状态)
- 两个操作同时访问文件系统 → 冲突

Lane Queue 解决方案:
消息进入队列 → 按顺序执行 → 前一个完成后再执行下一个
```

这种设计牺牲了一些性能，但换来了：

+ ✅ 状态一致性
+ ✅ 可预测的行为
+ ✅ 更容易调试

**④ 协议版本控制**

Gateway 使用严格的协议版本控制，确保客户端和服务器兼容：

```
// 客户端连接时必须声明支持的协议版本
{
  "type": "req",
  "method": "connect",
  "params": {
    "minProtocol": 3,  // 最低支持版本
    "maxProtocol": 3,  // 最高支持版本
    "client": {
      "id": "cli",
      "version": "1.2.3",
      "platform": "macos"
    }
  }
}

// 服务器验证版本,不匹配则拒绝连接
```

**⑤ 安全机制**

+ **Token 认证** - 通过 `OPENCLAW_GATEWAY_TOKEN` 环境变量设置
+ **本地绑定** - 默认只监听 `127.0.0.1`，不暴露到公网
+ **权限控制** - 区分 `operator`（控制者）和 `node`（执行者）角色
+ **命令审批** - 危险操作（如 `rm -rf`）需要人工确认

#### Channels （渠道层） - 多平台适配

**定义：**

Channels 负责将不同平台（WhatsApp、Telegram、Slack 等）的消息格式统一转换为 Gateway 可以理解的标准格式。

支持的渠道（截至 2026 年 3 月）:

**消息平台：**

+ WhatsApp
+ Telegram
+ Slack
+ Discord
+ Signal
+ iMessage
+ Microsoft Teams
+ Matrix
+ IRC
+ Zalo
+ LINE
+ Feishu（飞书）

**控制界面：**

+ Web UI（浏览器访问）
+ CLI（命令行）
+ macOS App（原生应用）
+ iOS App
+ Android App

**Channel 的工作原理：**

```
1. 接收原始消息
   WhatsApp 消息格式:
   {
     "from": "+1234567890",
     "body": "帮我创建一个文件",
     "timestamp": 1234567890
   }

2. 标准化转换
   Gateway 标准格式:
   {
     "type": "chat",
     "payload": {
       "userId": "whatsapp:+1234567890",
       "text": "帮我创建一个文件",
       "timestamp": 1234567890,
       "channel": "whatsapp"
     }
   }

3. 发送到 Gateway
   通过 WebSocket 发送标准化消息

4. 接收响应并转换回原始格式
   Gateway 响应 → WhatsApp 消息格式 → 发送给用户
```

**路由规则：**
