
# 数据中心基础设施挑战

冷却系统的耗水问题主要源于液冷技术的使用，这种技术通过水的蒸发潜热来降温，相较于传统风冷，液冷的热交换效率更高。液冷分为冷板液冷和浸没液冷，而前者在主流`GPU`中应用广泛。由于液冷消耗大量水，一些地区的环保抗议愈发严重，影响当地水资源的可用性和质量。

在供电方面，随着功率密度的提升，供电系统的占地面积成为一大挑战。传统供电设备需要大量空间，而新型的交流直流供配电一体化方案则能够减少30%的占地面积。为了提高电能传输效率，行业内也在积极采用碳化硅和多晶合金等新技术。

面对快速增长的算力需求，数据中心建设速度也需提升。一些创新方案如使用正交胶合木（CLT）材料的木质数据中心，通过预制化方法显著缩短建设时间。综上所述，AI时代的数据中心在冷却、供电和建设速度等方面都面临重大的技术挑战和转型机遇。

## 芯片互连取得进展

`https://zhuanlan.zhihu.com/p/4765531373`

文章探讨了分解系统级芯片（`SoC`）并通过异构方式将其组成部分组合的技术进展，强调了互连、复杂分区以及业界对可行性的理解。实现即插即用的愿景比预期更复杂，受到应用程序、工作负载、封装类型、调度和互连类型的影响。

互连被视为连接各部分的“粘合剂”，包括片上网络（`NoC`）和芯片间连接（如`UCIe`）。互连的设计需要解决如何有效地划分计算和数据流的问题。不同的互连技术（如电缆和潜在的光互连）在性能上有所不同，物理特性如直径、密度和绝缘性也需考虑。

芯片互连的挑战在于如何处理跨芯片的时序接口，以优化信号的传输速率。设计时通常会隔离跨芯片边界的时序接口，以避免复杂的收敛问题。`D2D`（芯片到芯片）互连的效率关键在于降低功耗和面积，并确保电路复杂性与性能之间的平衡。

多个协议（如`AMBA CHI`和`UCIe`）被用于实现芯片间数据传输。芯片互连的设计需要考虑到信号处理、数据包传输和系统内存映射的性能影响。正确的互连选择和架构设计至关重要，尤其是在高数据速率下，保证各部分的协同工作。

此外，随着`Chiplet`系统的发展，设计和测试新的`D2D`接口成为一大挑战，特别是在支持多供应商互操作性方面。文章指出，芯片设计需要围绕系统发现进行标准化，确保各个芯片能有效地互连和协作。

## 在昇腾Ascend 910B上运行Qwen2.5推理

1. 驱动确认：通过命令 `npu-smi info` 检查昇腾`NPU`驱动是否已安装。

2. CANN Toolkit与`Kernel`安装：

   下载相应的`CANN Toolkit`与`Kernel`包：

   ```
   wget [Toolkit URL]
   wget [Kernel URL]
   ```

   安装`Toolkit`和`Kernel`：

   ```
   sudo chmod +x [Toolkit Filename] && sudo ./[Toolkit Filename] --install --install-for-all
   sudo chmod +x [Kernel Filename] && sudo ./[Kernel Filename] --install --install-for-all
   ```

   配置环境变量：

   ```
   echo "source /usr/local/Ascend/ascend-toolkit/set_env.sh" >> /etc/profile
   source /usr/local/Ascend/ascend-toolkit/set_env.sh
   ```

### 安装GPUStack

`GPUStack`是一个开源大模型即服务平台，支持多种`NPU`/`GPU`类型，安装命令如下：

```
curl -sfL https://get.gpustack.ai | sh -
```

如网络受限，使用腾讯云下载：

```
curl -sfL https://get.gpustack.ai | sh - --tools-download-base-url "https://gpustack-1303613262.cos.ap-guangzhou.myqcloud.com"
```

安装完成后，通过以下命令获取初始密码并登录：

```
cat /var/lib/gpustack/initial_admin_password
```

### 纳管NPU资源

通过获取`Token`，可以将其他昇腾`NPU`服务器纳入`GPUStack`集群：

```
cat /var/lib/gpustack/token
```

在其他节点上执行：

```
curl -sfL https://get.gpustack.ai | sh - --server-url http://YOUR_IP_ADDRESS --token YOUR_TOKEN
```

### 部署Qwen 2.5模型

`GPUStack`支持从HuggingFace、`ModelScope`等多种源部署模型。需确保模型为`GGUF`格式，当前`CANN`算子对`FP16`精度和`Q8_0`、`Q4_0`量化模型支持较为完善。推荐使用`FP16`模型。

在昇腾910B上测试`Qwen 2.5`的推理性能如下：

+ `Qwen2.5 72B FP16`：6 tokens/s，`NPU`利用率10-60%

+ 其他模型（如0.5B、1.5B等）在性能与内存利用上表现不一，详细数据见原文。

测试表明，当前硬件性能未得到充分发挥，`CANN`算子和推理引擎仍有优化空间，期待`GPUStack`后续版本提供更佳支持。

## 提出Rectified Diffusion, 重新思考Rectified Flow

`https://zhuanlan.zhihu.com/p/880760492`

在2023年，基于rectified flow和flow-matching的扩散模型在生成任务中获得了显著关注。然而，许多关于这些模型的误解仍然存在，尤其是在网络平台和学术论文中。本文旨在澄清这些概念，并提供对rectified flow的深入分析。

首先，flow-matching与传统的扩散模型（`DMs`）在本质上有所不同。早在2021年，变分扩散模型（Variational Diffusion Models）就已经提出了一种通用的扩散模型表达式，许多后续研究（如`DPM-Solver`）基于此进行了改进。不同扩散模型（如`DDPM`、`EDM`）的表现与它们的超参数设置有很大关系，而不是模型形式本身的优越性。

关于flow-matching的“直线轨迹”误解较多。尽管从数学形式上看，flow-matching的采样步骤可以视为直线前进，实际操作中，因模型训练过程中的随机配对，最终的采样轨迹往往是曲线。模型每一步的denoise尽管为直线，但因每次采样的方向不同，整体路径实际上是折线。

rectified flow的创新在于通过重训练和rectification操作改善模型的性能。具体来说，rectified flow的三个核心思想包括：

1. Flow-matching：提出了一种简化的扩散形式，使用中间噪声状态来定义模型，简化了训练过程。

2. -预测：模型学习预测特定状态，减少了数值不稳定性，提高了去噪效率。

3. Rectification：通过渐进式重训练提升生成质量，将随机噪声和样本转化为确定性配对，改善了低步长生成的灵活性。

这些改进使得rectified flow能够在生成过程中实现“轨迹直线化”，在多次rectification后，采样轨迹逐渐趋近于直线。

## o1 系列：过程监督-Process Reward Model

`https://zhuanlan.zhihu.com/p/4757394529`

1. Process Reward Model (`PRM`)

`o1`在2024年9月12日发布，其内部研发周期超过一年半。最早的相关工作可以追溯到2023年5月的“Let's verify step by step”。`PRM`的核心在于提升多步推理任务中的反馈精度，减少逻辑错误。该模型探讨了两种监督方法：结果监督和过程监督。结果监督为当前`RLHF`模型常用方法，通过拟合整个响应的评价来提供反馈；而过程监督则是对模型每一步进行打分，提升模型的输出质量。

2. 过程监督的实现

“Let's verify step by step”研究了通过步骤打分来监督模型，强调了在标注过程中的资源投入。`PRM800K`数据集的开源显示了OpenAI的开放态度。与人工标注相比，该方法的优势在于成本较低，但依赖预先提供的参考答案，从而限制了应用范围。

3. MATH-SHEPHERD

该工作旨在无需人工注释，通过训练过程监督奖励模型提升多步数学推理能力。采用`SFT`模型解码解题路径，并验证最终答案是否与参考答案匹配。优点在于成本低，缺点则是依赖于参考答案的可用性。

4. 改进的过程监督

Google DeepMind提出了更高效的数据构造方法，利用二分搜索快速定位错误位置，优化了错误定位效率，将时间复杂度从`O(kM)`降至`O(klogM)`。通过构建状态-动作树和选择阶段的统计信息更新，提升了效率。

5. 奖励进展 (`PAV`)

此研究改进了`PRM`的模型，提出拟合`Advantage`函数以提升效果。相较于传统的`Q`函数，`Advantage`函数能更好地判断特定步骤对最终答案概率的影响。实验显示，`PAV`模型在计算效率和准确性上均有显著提升。

## 计算之比特位宽

`https://zhuanlan.zhihu.com/p/4396044480`

### 比特位宽定义

比特位宽是整数和浮点数在计算机中的表示长度，直接影响表示范围和精度。

1. 整数类型：使用二进制补码表示，符号位决定正负，范围为 `-2^(n-1)` 到 `2^(n-1) - 1`。例如，8位补码中，`0110 1100` 表示108，`1111 0011` 表示-13。

2. 浮点数类型：依据 `IEEE 754` 标准，分为单精度（32位）和双精度（64位）。单精度由符号位、指数部分（8位）和尾数部分（23位）组成；双精度指数部分为11位，尾数为52位。浮点数的表示方式包括规格化、非规格化及特殊值（如零和`NaN`）。

### AI中的数据类型

常见的浮点数格式包括 `FP32`、`TF32`、`FP16`、`BF16` 和新兴的 `FP8`。`FP32` 适用于大范围数据表示，`TF32` 提升了计算速度而不显著损失精度；`FP16` 和 `BF16` 则在深度学习中提供混合精度训练的便利，`FP8` 旨在减少内存占用并提高计算吞吐量，特别适用于大型模型。

### FP8应用案例

`FP8` 数据类型在最近的 GPU 设计中得到支持，例如英伟达的 `H100` GPU。`FP8` 有两种设计：`E4M3` 提供更好的精度，而 `E5M2` 则在动态范围上表现更佳。在前向传播中，通常使用 `E4M3`，反向传播时使用 `E5M2`。微软的研究显示，`FP8` 在训练大型语言模型时，相较于 `BF16` 提升了速度和内存效率。

### 降低比特位宽的优势

在资源有限的背景下，降低比特位宽能有效降低计算和存储成本，减轻能耗负担。通过降低 `MAC` 的数据位宽，能够减少数据搬运和存储开销，提高能效。不同位宽的数据类型适应不同精度需求，使硬件设计更具灵活性和经济性。

## 序列并行2，DeepSpeed Ulysses

`https://zhuanlan.zhihu.com/p/4496065391`

`Ulysses`的基本运作流程如下：

1. 数据切分：将输入数据`X = (N, d)`切分成若干个`seq_chunk`，每个尺寸为`(N/P, d)`，`P`为`GPU`数量。

2. 计算`q/k/v`值：每个`GPU`独立计算其维护的`seq_chunk`的`q/k/v`值，保留完整的模型参数。

3. `All2All`通信：进行`All2All`操作，使每个`GPU`获得所有序列的某个`head`的`q/k/v`值。

4. 执行`Attention`：在每个`GPU`上执行`Attention`计算，输出结果尺寸为`(N, d/P)`。
