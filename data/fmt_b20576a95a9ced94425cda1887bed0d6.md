### 1.2 基本术语

> 基于统计学视角，对西瓜书相关概念的解读

1. **样本：**判断西瓜是否好吃的任务中，每个西瓜是样本。编号为 1 的西瓜及特征记录为一个样本。

|  | 划分依据 | 补充解释 |
| --- | --- | --- |
| 来源 | 随机样本 | 从西瓜地随机抽取，编号后借随机数生成器确定，能代表总体 |
|  | 非随机样本 | 如瓜农凭经验选的判断样本，或路边随手挑的方便样本，易有偏差 |
| 性质 | 独立样本 | 从不同西瓜地分别抽取，各地西瓜间无关联 |
|  | 相关样本 | 对同一批西瓜成熟前、后分别品尝所得样本，具相关性 |
| 数量特征 | 大样本 | 抽取 30 个及以上西瓜，便于用正态分布等统计方法去分析 |
|  | 小样本 | 抽取少于 30 个西瓜，用小样本方法 |

1. **样本空间：**所有可能西瓜的集合，含不同颜色、大小、声音组合的西瓜。

|  | 划分依据 | 补充解释 |
| --- | --- | --- |
| 构成元素 | 单一特征样本空间 | 只考虑西瓜某一个特征，如颜色。 |
|  | 复合特征样本空间 | 包含多种特征组合，像颜色、大小、声音组合的西瓜集合 |
| 范围 | 有限样本空间 | 比如限定了西瓜的一些条件，比如只考虑某块特定西瓜地的西瓜，且颜色、大小、声音的取值范围有限 |
|  | 无限样本空间 | 理论上，西瓜的颜色、大小、声音可以有无数种变化和组合，不做任何限制时，所有可能的西瓜组合构成无限样本空间 |
| 研究目的 | 好吃西瓜样本空间 | 侧重于包含那些可能好吃的西瓜组合 |
|  | 普通西瓜样本空间 | 不一定突出是否好吃，用于整体了解西瓜的多样性情况 |

1. **数据集：**为研究西瓜，收集的多个西瓜特征记录，如 100 个西瓜的记录。

|  | 划分依据 | 补充解释 |
| --- | --- | --- |
| 数据来源 | 实地采集数据集 | 这类数据真实性高，能反映实际情况 |
|  | 二手数据集 | 虽然获取便捷，但可能存在数据偏差或与研究需求不完全匹配的问题 |
| 数据完整性 | 完整数据集 | 包含所研究西瓜的全部关键特征记录 |
|  | 不完整数据集 | 部分特征缺失的西瓜记录集合，可能会影响分析的准确性和全面性，在数据分析时需要特殊处理，如数据填充或剔除缺失严重的数据 |
| 数据规模 | 大规模数据集 | 记录了大量西瓜（如数千甚至上万个）特征的集合，能挖掘出更复杂的规律和潜在关系，不过对存储和计算能力要求较高 |
|  | 小规模数据集 | 像仅记录了几十或几百个西瓜特征的集合，虽然数据量有限，但在初步探索性研究或资源受限的情况下仍有价值 |

1. **模型：**学习西瓜数据集得到的判断规则，如深绿、适中、清脆的西瓜大概率好吃。

|  | 划分依据 | 补充解释 |
| --- | --- | --- |
| 模型复杂度 | 简单模型 | 基于少量关键特征建立的判断规则，比如仅依据西瓜颜色和敲击声音来判断是否好吃 |
|  | 复杂模型 | 综合考虑众多特征，如颜色、大小、纹理、甜度、生长环境等，它能更全面地分析西瓜，但计算成本高，解释性相对较差。 |
| 学习方式 | 监督学习模型 | 利用带有标记（好吃或不好吃）的西瓜数据集进行学习，从而得出判断规则 |
|  | 无监督学习模型 | 在没有明确标记的西瓜数据集中寻找规律，比如将西瓜按特征聚类，再进一步分析哪些类别的西瓜更可能好吃，不需要事先知道西瓜是否好吃 |
| 模型用途 | 预测模型 | 为消费者挑选西瓜或瓜农评估收成提供参考 |
|  | 解释模型 | 能解释判断依据，即说明哪些特征对判断结果影响较大，帮助人们更好地理解西瓜品质的影响因素 |

1. **标记：**西瓜是否好吃即标记，好吃为 “好”（或 1），不好吃为 “坏”（或 0）。

|  | 划分依据 | 补充解释 |
| --- | --- | --- |
| 标记类型 | 标签型标记 | 将西瓜标记为 “好” 或 “坏” |
|  | 数值型标记 | 用 “1” 表示好吃，“0” 表示不好吃 |
| 标记的来源 | 人工标记 | 例如生活中的自动售卖机，许多都是人工标注（互联网小黑工） |
|  | 自动标记 | 利用计算机视觉、光谱分析等，自动对西瓜的特征进行分析 |
| 标记的用途 | 训练标记 | 这些标记帮助模型学习西瓜特征与是否好吃之间的关系，使模型能够不断调整参数，提高判断的准确性 |
|  | 测试标记 | 通过将模型对测试数据集中西瓜的判断结果与测试标记进行对比，可以计算出模型的准确率、召回率等评估指标，从而了解模型的性能表现 |

1. **泛化：**模型对新西瓜也能准确判断好吃与否的能力。

|  | 划分依据 | 补充解释 |
| --- | --- | --- |
| 泛化的对象 | 不同品种西瓜的泛化 | 模型在学习了某几种西瓜品种的数据集后，能够对其他未见过的西瓜品种准确判断其是否好吃 |
|  | 不同生长环境西瓜的泛化 | 西瓜的生长环境多样，一个具有良好泛化能力的模型，应该能够对来自不同生长环境的西瓜进行准确判断 |
| 泛化能力的影响因素 | 数据集对泛化的影响 | 足够大且包含各类西瓜特征信息的训练数据集，能让模型学习到更多规律提升泛化。  过小或有偏差（如仅含特定地区、品种西瓜数据）的数据集，易导致模型过拟合 |
|  | 模型复杂度对泛化的影响 | 简单模型难以捕捉复杂关系，泛化弱  复杂模型容易过拟合，对新数据适应性差 |
|  | 特征工程对泛化的影响 | 选择与西瓜好吃程度紧密相关的关键特征进行转换和组合，让模型更易发现特征与好吃程度的关系 |

1. **分布：**如好吃西瓜中深绿占 80%，不好吃中深绿占 20%，是特征概率分布。

|  | 划分依据 | 补充解释 |
| --- | --- | --- |
| 分布类型 | 离散型分布 | 离散型特征：西瓜的颜色（深绿、浅绿、黄绿等）、好吃和不好吃 |
|  | 连续型分布 | 连续型特征：西瓜的甜度、重量 |
| 分布的范围 | 总体分布 | 指的是所有西瓜（无论是否被纳入研究）的特征在好吃和不好吃这两个类别中的真实分布情况。这是一种理想状态下的分布 |
|  | 样本分布 | 是从总体中抽取**的样本数据所呈现出**的特**征**分布。  比如我们抽取了 1000 个西瓜作为样本，统计这些样本中不同特征在好吃和不好吃西瓜中的占比，得到的就是样本分布  样本分布是我们实际能够获取和分析的，通过对样本分布的研究来推断总体分布，但样本分布可能会因为抽样的随机性和局限性与总体分布存在一定的偏差。（倘若你在某个教程或者文档看到“总体分布”，大概率指的是“样本的总体分布”。这是一个很重要、易混淆的概念） |
| 分布的稳定性 | 稳定分布 | 数据分布随时间或条件变化而保持一致性或相似性的状态。 |
|  | 不稳定分布 | 假设今年的气候条件与去年相比有显著不同，西瓜的重量分布分布可能有显著变化 |

### 1.3 假设空间

#### 案例分析：假设空间与版本空间

> 在判断苹果是否新鲜时，通常从苹果的色泽（鲜艳、暗淡）、硬度（硬、软）、存放时间（短、长）这几个特征进行考虑。

> 假设空间就是包含所有这些特征组合可能性的集合，具体如下：

+ 基于特征组合的假设

+ 色泽鲜艳、硬度硬、存放时间短的苹果是新鲜的。

+ 色泽鲜艳、硬度硬、存放时间长的苹果是新鲜的。

+ 色泽鲜艳、硬度软、存放时间短的苹果是新鲜的。

+ 色泽鲜艳、硬度软、存放时间长的苹果是新鲜的。

+ 色泽暗淡、硬度硬、存放时间短的苹果是新鲜的。

+ 色泽暗淡、硬度硬、存放时间长的苹果是新鲜的。

+ 色泽暗淡、硬度软、存放时间短的苹果是新鲜的。

+ 色泽暗淡、硬度软、存放时间长的苹果是新鲜的。

+ 极端假设

+ 无论苹果的色泽、硬度、存放时间如何，所有苹果都是新鲜的。

+ 无论苹果的色泽、硬度、存放时间如何，所有苹果都不是新鲜的。

> 即假设空间涵盖了关于苹果新鲜与否的各种可能判断情况。是一个理论上的全集，包含了各种可能的判断规则，为后续模型学习提供了所有潜在的假设。

> 在实际机器学习过程中，我们会收集一些已知新鲜与否的苹果样本（即带标记的训练数据）。

> 现在，对水果店内的苹果进行观察和判断：

+ 发现一批色泽鲜艳、硬度硬、存放时间短的苹果，经检查确实新鲜。

+ 遇到一批色泽暗淡、硬度软、存放时间长的苹果，发现不新鲜。

> 基于这些实际观察到的样本情况，我们要检验假设空间中的各种假设与样本数据（即观察结果）的一致性。那些与已知样本数据不冲突的假设，就构成了版本空间。比如， “色泽暗淡、硬度软、存放时间长的苹果是新鲜的” 这一假设就不符合我们的观察，会被剔除。

> 经过这样的筛选后，留下来的符合实际观察样本情况的假设集合，就构成了版本空间。

> 例如，可能包含 “色泽鲜艳、硬度硬、存放时间短的苹果是新鲜的”“色泽鲜艳、硬度硬、存放时间长的苹果是新鲜的” 等满足我们已有的新鲜或不新鲜判断的假设 。

> 版本空间里的假设是与现有样本数据一致的，可用于对新的苹果样本是否新鲜进行推断 。

### 1.4 归纳偏好

+ **归纳偏好定义**：机器学习算法在学习过程中对某种类型假设的偏好

+ **一般原则**：遵循奥卡姆剃刀（Ocam' s zazor）原则，即 “如无必要，勿增实体”，在机器学习中倾向于选择更简单的假设，因为简单的模型通常具有更好的泛化能力，不易过拟合

+ **重要性：**任何一个有效的机器学习算法都有其归纳偏好，并且算法的归纳偏好与问题本身是否匹配，在大多数情况下直接决定了算法能否取得良好的性能。如果算法偏好的假设类型与实际问题的数据分布和内在规律相符，算法就能更好地学习和预测 。

> 哪个算法更好？有没有“一招鲜，吃遍天”的算法呢？

> NFL 定理，即 “没有免费的午餐” 定理（No Free Lunch Theorem）。

> **NFL 定理成立的关键前提：所有问题出现的概率相同，或者所有问题同等重要。**

> 但在实际中，我们往往只聚焦于特定问题，并非所有问题都有相同的关注度和出现机会。所以，离开具体问题，单纯讨论哪种算法更好是没有意义的，需结合具体问题场景选择合适的算法 。

> 以预测明天是否下雨为例，详细解释 NFL 定理

#### 场景设定

我们有两个预测明天是否下雨的算法：算法A根据当天的云层厚度、气压变化来预测，算法B根据最近一周的天气趋势和湿度来预测。

+ 假设空间 是两个算法可能得出的所有预测假设，比如“明天会下雨”“明天不会下雨” ；

+ 样本空间 包含了所有影响天气的因素组合，比如不同的云层厚度、气压值、湿度值等。

#### 符号对应含义

+ `\mathcal{H}`：假设空间。算法预测结果的集合，如{明天会下雨，明天不会下雨} 。

+ `\mathcal{X}`：样本空间。所有可能影响是否下雨的天气因素组合构成的样本空间，如（云层厚度，气压，湿度 ，……）的各种取值组合。

+ `P(h|X, \mathfrak{L}_a)`：算法A（ ）基于当前收集到的（即训练数据）天气数据 （如今天的云层厚度、气压等），得出预测假设 （下雨或不下雨）的概率。例如算法A基于今天云层厚、气压低的数据，有80%的概率得出“明天会下雨”的假设。

+ `f`：要学的目标函数。真实的明天是否下雨的情况，是我们希望通过算法去逼近的真实结果。比如实际上明天下雨了，那么 的值就对应“下雨”。

+ `\mathbb{I}(h(\boldsymbol{x}) \neq f(\boldsymbol{x}))`：指示函数。如果算法预测的结果 （如预测下雨）和真实情况 （实际没下雨）不一样，它的值就是1；一样则为0。

+ `P(\boldsymbol{x})`：某种天气因素组合 （如云层厚度为…毫米，气压为…百帕 ）出现的概率。

`E_{ote}(\mathfrak{L}_a|X, f) =\sum_{h} \sum_{\boldsymbol{x} \in \mathcal{X} - X} P(\boldsymbol{x}) \mathbb{I}(h(\boldsymbol{x}) \neq f(\boldsymbol{x})) P(h | X, \mathfrak{L}_a)`

1. 假如算法A有两种可能的预测结果（ ，即下雨或不下雨）。我们要计算算法A在未用到的天气因素组合 ，即除了当前已收集数据对应的天气因素组合外的其他组合）上的预测误差。

1. 对于每一种可能未用到的天气因素组合 （比如不同的云层厚度和气压组合），乘以它出现的概率 。

1. 然后看算法A基于已有数据得出的预测 和真实结果 是否不一样，用  判断。

1. 再乘以算法A得出该预测  的概率 。最后把所有这些情况加起来，就是算法A在训练数据之外的预测总误差。
