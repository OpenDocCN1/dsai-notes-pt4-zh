## 1、私域主动添加，一个被大家容易忽视的引流方式

首先，我觉得主动加人引流是被大家忽略的一种引流方式，可以和常见的被动加人引流结合起来，达到引流效果最大化。

🛰️私域引流，大家一直都是通过话术、通过钩子诱饵引导用户主动添加我们的🛰️，这种是最为常见的运营被动引流手段。

当然我们也可以主动去添加用户🛰️达到引流的目的，比如常见的场景就是，销售人员每天都会主动批量去添加潜在用户的🛰️。一个销售人员一般一两个🛰️主要来做业务，一个销售团队可能几个销售到几十人销售不等，这就相当于每天有几个🛰️到几十个🛰️都在主动引流的。

只不过我们人工每天去一个个添加，这效率太低了。而且当我们有多个🛰️，有几十个、上百个🛰️的时候，这里面存在大量重复、效率低下的工作。

所以通常情况下，大家都喜欢用常见的运营被动引流方式，很少用主动加人引流方。我在赚钱扫了大量贴子，也就仅仅见过一篇我们圈友分享的主动加人引流的内容：《用RPA机器人，30天时间加到2000个同城线下门店老板的🛰️》。

主要是主动加人的方式，有两个缺点：

1. 主动加人，每个🛰️每天最多仅30个，觉得引流量偏低（而被动加人，每个🛰️每天可以180个）。

1. 如果单纯是人工去添加，那这主动添加引流的价值意义就不大了。如果用技术去批量自动添加，很多人不知道市面上有没有相关成熟的技术，能不能拿来就用的。所以更是进一步导致主动加人的引流方式不被使用。

所以，我们如果技术层面解决主动加人的问题，然后我们用技术控制多个🛰️去批量自动添加（自动化模拟人工操作），基本上就解决主动添加引流的两个缺点。

哪怕单个🛰️号每天只能加几个🛰️好友（能主动加多少，跟🛰️权重有关），但是我们是用多个🛰️，累积一个月、两个月、三个月等不停歇的去加，最终这也是一个不小的流量。

### 2.5、各种🛰️群主动引流

## 3、🛰️号采集（爬虫）技术的选型

那用什么技术把🛰️号从庞大的网页内容中自动的筛选提取出来呢？答案就是：数据采集技术即爬虫技术。但数据采集技术很多，那我们具体要采用哪个？

对应我们需求，我对常见的爬虫技术调研实践对比汇总如下：

从新人上手、采集范围、灵活应变程度、免费程度、采集速度这五个方面划分，重要系数是越重要的我会给分给的高一点。

我们需求是从网页中采集🛰️号，站在需求角度，老板思维，对技术的选择考虑是：

+ 我们要选择简单的技术，能快速的完成我们需求，这是我们重中之重，所以新手上手的重要系数权重我给的权重很高。

+ 我们需求也没有特别高的采集要求（只是把🛰️号从正文内容和评价内容中过滤出来）

+ 灵活要求也不高

+ 免费程度要求也不高，如果付费能直接解决我需求，那更加省时省心。

+ 采集速度要求也不高，不管多慢，在技术层面，都比人工效率最起码高个几十倍，足以满足需求。

而传统技术思维，对技术的选择考虑是（误区）：

+ 要选择最难的技术，只有最难的技术才能衬托出自己的技术的牛逼！

+ 采集范围当然越广越好！

+ 灵活当然是越灵活越好！

+ 付费那是不可能的，我宁愿24小时不吃不喝的🪜研究，我也不愿意付给你1块钱！

+ 采集速度，单线程已经满足不了我对速度的渴望，多线程才是我的要求！

所以上来我就先把Python和Web Scraper给排除掉了，Python要编码，耗时太久，也太复杂，对小白友好度几乎为零。

Web Scraper对我们懂技术的人员来说配置使用还算是简单的，不过对非技术人员来说，学习起来难度还是不小的，所以并不是很建议。

## 4、怎么把🛰️号给过滤筛选出来？

### 4.1、🛰️号筛选匹配原理

虽然我们找到了🛰️号聚集的页面（采集入口），但怎么把🛰️号从这些内容页中给过滤筛选出来呢？那肯定是用正则表达式来进行匹配筛选了。

> 正则表达式(regular expression)描述了一种字符串匹配的模式（pattern），可以用来检查一个串是否含有某种子串、将匹配的子串替换或者从某个串中取出符合某个条件的子串等。

🛰️号的命名规则是：仅支持6-20个字母、数字、下划线或减号，以字母开头。🛰️如果绑定了手机号（11数字）、🐧号（5位-11位数字），对应手机号和🐧号也算是🛰️号，很多人留🛰️号也直接留手机号或者🐧号。

所以匹配🛰️的正则表达式是：

```
[a-zA-Z\d][a-zA-Z\d_-]{5,19}
```

### 4.2、脏数据匹配清洗

到这里，大家觉得这个正则表达式能不能把我们🛰️号精准的从帖子内容中过滤出来？肯定是没想象中这么容易。

在上面八爪鱼内容抓取配置实战中，🛰️的正则表达式，会额外匹配到以下非🛰️号的内容：

1. 昵称名字中是字母/数字，也能被正则匹配到，误认为是🛰️。

1. 内容和评价中有http链接地址的，里面的数字+字母的组合，也会被匹配到，误认为是🛰️号。

1. 类似日期“2023-01-21”也会被匹配到，误认为是🛰️号。

1. 内容和评价中大量包含的英文单词、拼音等也会被匹配到，误认为是🛰️号。

所以想要单纯一个正则表达式，就想要精准把🛰️号匹配出来，是有点不可能的。那我们只能通过多个表达式，逐个过滤筛选出我们想要的🛰️号。

首先，我们把日期单独匹配出来，并且过滤拿掉：

```
\d{4}-\d{1,2}-\d{1,2}[\s]*\d{1,2}:\d{1,2}
```

然后，我们把http链接匹配出来，并且过滤拿掉：

```
https?://([a-zA-Z].)+([a-zA-Z])+(/([a-zA-Z])+)+(([a-zA-Z])+)?
```

其次，就是我们的重点，内容中包含英文和拼音，这些我们是没办法让正则去分辨的。虽然我们肉眼一眼就能分辨出哪些内容是🛰️号，哪些是英文、哪些是拼音。但是用正则去匹配的话，是没有具体规则完成这个分辨。

这时候我们要反向思考，我们人眼是怎么判断内容和评价中的内容就是🛰️号的？这就是我们匹配到🛰️号具体的规则：

1、内容出现1开头的11位手机号，基本上多半是🛰️号，正则表达式如下：

```
1\d{10}
```

2、冒号（分中文冒号和英文冒号）后面跟的英文+数字的内容，基本上多半是🛰️号，正则表达式如下：

```
[:|\uff1a][\s]?[a-zA-Z\d][a-zA-Z\d_-]{5,19}
```

3、包含“联系”或者“合作”内容，后面跟的英文+数字的内容，基本上多半是🛰️号，正则表达式如下：

```
[\u52a0|\u5fae].{0,10}[a-zA-Z\d][a-zA-Z\d_-]{5,19}
```

```
(\u5fae\u4fe1|\u8054\u7cfb|\u5408\u4f5c).{0,10}[a-zA-Z\d][a-zA-Z\d_-]{5,19}
```
