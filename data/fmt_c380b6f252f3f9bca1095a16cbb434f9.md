
### Agent Runtime （代理运行时） - 智能核心

**定义：**

Agent Runtime 是 OpenClaw 的“大脑”，负责将用户请求转换为 LLM 可以理解的 Prompt，并协调工具调用。

**核心子系统：**

① System Prompt Builder （系统提示构建器）

动态生成发送给 LLM 的系统提示，包含：

+   Agent 的身份和角色定义

+   可用工具列表及其使用说明

+   当前激活的 Skills

+   相关的记忆片段（从 Memory 中检索）

+   安全规则和限制

```
生成的 System Prompt 示例:

You are a helpful AI assistant named "Molty".

Current date: 2026-03-12
User timezone: UTC+8

Available tools:
- shell_exec: Execute shell commands
- file_read: Read file contents
- file_write: Write to files
- browser_navigate: Control browser

Active skills:
- code-reviewer: Review code and suggest improvements
- email-manager: Manage emails

Memories:
- User prefers Python over JavaScript
- User's project directory: ~/projects/myapp

Safety rules:
- Always ask before deleting files
- Never execute commands with sudo without confirmation
```

② Session History Loader （会话历史加载器）

从 JSONL 文件中加载历史对话，提供上下文：

```
{"role":"user","content":"帮我创建一个 Python 脚本","timestamp":1234567890}
{"role":"assistant","content":"好的,请问脚本要实现什么功能?","timestamp":1234567891}
{"role":"user","content":"读取 CSV 文件并统计行数","timestamp":1234567892}
```

③ Context Window Guard （上下文窗口守卫）

监控 Token 使用量，防止超出模型限制：

```
// 伪代码
if (totalTokens > maxTokens * 0.8) {
  // 触发总结机制
  summarizeOldMessages();
} else if (totalTokens > maxTokens) {
  // 停止循环,提示用户
  throw new Error("Context window full");
}
```

④ Tool Orchestration （工具编排）

协调多个工具的调用，支持：

+   单步工具调用

+   多步工具链（Tool Chain）

+   并行工具调用（需要时）

+   工具调用结果缓存

```
示例:用户请求"分析这个 GitHub 仓库"

步骤 1: browser_navigate → 打开 GitHub 页面
步骤 2: browser_extract → 提取仓库信息(stars、forks、语言)
步骤 3: shell_exec → git clone 仓库
步骤 4: file_read → 读取 README.md
步骤 5: shell_exec → 运行代码分析工具
步骤 6: 汇总结果,生成报告
```

⑤ Memory Management （记忆管理）

OpenClaw 采用 **简单但有效** 的记忆系统，避免过度复杂：

**记忆类型：**

+   **短期记忆** - 当前会话的对话历史（JSONL）

+   **长期记忆** - 跨会话的重要信息（SQLite + 向量数据库）

**检索策略：**

+   **向量搜索** - 语义相似度匹配（用于模糊回忆）

+   **关键词搜索** - SQLite FTS5 全文搜索（用于精确匹配）

+   **混合检索** - 结合两者，提高准确率

```
用户:"上次我们讨论的那个认证 bug 怎么样了?"

检索过程:
1. 向量搜索 "认证 bug" → 找到语义相关的对话
2. 关键词搜索 "authentication bug" → 找到精确匹配
3. 合并结果,按相关性排序
4. 将 Top 3 结果注入到 System Prompt
```

### Skills System （技能系统） - 可扩展能力

**定义：**

Skills 是 OpenClaw 的“插件系统”，允许用户和社区扩展 Agent 的能力。

**Skill 的结构：**

每个 Skill 是一个包含 `SKILL.md` 文件的目录：

```
my-skill/
├── SKILL.md          # Skill 元数据和指令
├── package.json      # 依赖声明(可选)
├── index.js          # 执行脚本(可选)
└── README.md         # 说明文档(可选)
```

[`SKILL.md`](http://SKILL.md) **格式：**

```
---
name: code-reviewer
version: 1.0.0
author: example@email.com
description: Review code and suggest improvements
requires:
  env:
    - GITHUB_TOKEN
  tools:
    - file_read
    - shell_exec
---

# Code Reviewer Skill

When the user asks to review code:

1. Read the file using file_read tool
2. Analyze code quality, style, and potential bugs
3. Run linters if available (shell_exec)
4. Generate a detailed review report

Example usage:
- "Review the code in src/app.py"
- "Check this file for bugs"
```

**Skill 加载优先级：**

```
1. Workspace Skills (工作区技能)
   路径: ./skills/
   优先级: 最高(覆盖其他同名 Skill)

2. Global Skills (全局技能)
   路径: ~/.openclaw/skills/
   优先级: 中等

3. Bundled Skills (内置技能)
   路径: /usr/local/lib/openclaw/skills/
   优先级: 最低
```

MCP (Model Context Protocol) 集成：

OpenClaw 支持 MCP 协议，可以将 MCP Server 作为 Skill 使用：

```
// MCP Skill 配置
{
  "mcpServers": {
    "trello": {
      "command": "node",
      "args": ["./mcp-servers/trello/index.js"],
      "env": {
        "TRELLO_API_KEY": "your-key",
        "TRELLO_TOKEN": "your-token"
      }
    }
  }
}
```

当 Agent 启动时：

1.  OpenClaw 启动 MCP Server 作为子进程

2.  通过 stdio 通信发现可用工具

3.  将工具注册到 Agent Runtime

4.  LLM 可以调用这些工具

这意味着：为 Claude Desktop 开发的 MCP Server 可以直接在 OpenClaw 中使用！

### LLM Provider Layer （模型层） - 统一接口

**定义：**

Provider Layer 提供统一的接口来对接不同的 LLM 服务商。

+   **Google Gemini** - Gemini 2.0 Flash, Gemini 1.5 Pro

+   **DeepSeek** - DeepSeek V3

+   **Moonshot Kimi** - Kimi K2.5

开源模型（通过 Ollama）:

+   Llama 3.1, Llama 3.2

+   Qwen 2.5

+   Mistral

+   Phi-3

**Provider 接口设计：**

```
interface LLMProvider {
  // 发送消息,获取响应
  chat(messages: Message[], options: ChatOptions): Promise<response>;
  
  // 流式响应
  chatStream(messages: Message[], options: ChatOptions): AsyncIterator<chunk>;
  
  // 获取模型信息
  getModelInfo(): ModelInfo;
  
  // Token 计数
  countTokens(text: string): number;
}
</chunk></response>
```

### 3.2.3 数据流转机制

让我们通过一个完整的例子来理解 OpenClaw 的数据流转：

**场景：用户通过 Telegram 发送 “帮我分析 `app.py` 的代码质量”**

步骤 1：消息接收（Telegram Channel）

```
// Telegram Bot 接收消息
telegramBot.on('message', (msg) => {
  const rawMessage = {
    from: msg.from.id,
    text: msg.text,
    timestamp: msg.date
  };
  
  // 转换为标准格式
  const standardMessage = {
    type: 'chat',
    payload: {
      userId: `telegram:${msg.from.id}`,
      text: msg.text,
      timestamp: msg.date,
      channel: 'telegram'
    }
  };
  
  // 通过 WebSocket 发送到 Gateway
  gatewayWs.send(JSON.stringify(standardMessage));
});
```

步骤 2: Gateway 接收并路由

```
// Gateway 接收消息
gateway.on('message', async (msg) => {
  const { userId, text, channel } = msg.payload;
  
  // 查找或创建会话
  const session = await sessionManager.getOrCreate(userId);
  
  // 加入 Lane Queue(串行队列)
  await laneQueue.enqueue(session.id, async () => {
    // 调用 Agent Runtime 处理
    await agentRuntime.process(session, text);
  });
});
```

步骤 3: Agent Runtime 构建上下文
