# Sigmoid 自注意力的理论、分析和最佳实践

贡献人：

链接：http://arxiv.org/abs/2409.04431v1

摘要：`Transformer`架构的关键部分是注意力。它是将每个序列元素转换为值的加权和的序列到序列映射。权重通常是通过键和查询之间的点积的`softmax`获得的。最近的研究探索了在`Transformer`中替代`softmax`注意力的选择，如`ReLU`和`sigmoid`激活。在这项工作中，我们重新审视了`sigmoid`注意力，并进行了深入的理论和经验分析。在理论上，我们证明了具有`sigmoid`注意力的`Transformer`是通用的函数逼近器，并受益于与`softmax`注意力相比的改进的规则性。通过详细的实证分析，我们发现在训练初期稳定大型初始注意力规范是成功训练具有`sigmoid`注意力模型的关键因素，超越了先前的尝试。我们还介绍了`FLASHSIGMOID`，这是一种硬件感知和内存高效的`sigmoid`注意力实现，在`H100` GPU上比`FLASHATTENTION2`提供了17%的推理内核加速。跨语言、视觉和语音的实验表明，适当归一化的`sigmoid`注意力在各种领域和规模上能够匹配`softmax`注意力的强大表现，而以前的`sigmoid`注意力尝试无法完全实现。我们的工作统一了之前的研究成果，并确立了将`sigmoid`注意力作为`Transformer`中`softmax`的替代品的最佳实践。

## FLUX.1 中国山水画 LoRA 的训练心得

贡献人：

https://zhuanlan.zhihu.com/p/718128887?utm_psn=1816385095235416064

这篇文章总结了基于南宋画家刘松年风格的`LoRA`模型训练经验，重点分享了技术细节。主要使用了20张不同分辨率的山水画图像数据集，像素接近512，借助`FLUXTrainer`插件进行训练。图像标注分为无标注、简单标注和复杂标注三种方式，其中复杂标注利用`ComfyUI`的`Joy Caption`节点结合`Meta`的`Llama`模型生成详细描述。训练中涉及到多个关键参数，如重复次数（`num_repeats`）、批次大小（`batch_size`）和总训练步数（`max_train_steps`），并采用`Adafactor`优化器，学习率设置为0.0002，训练步数为2000。

作者针对不同的标注和训练步数进行了测试，发现2000步时效果最佳，能够较好体现刘松年的风格。文章还指出，针对不在训练集内的元素，使用无标注的`LoRA`具有更强的灵活性，而复杂标注则能更准确反映训练集细节。此外，文中强调了图像细节处理的改进空间，如提高图像分辨率、去除训练图像中的红色印章等。

## 使用Nsight Profiling工具对大模型进行性能调优

https://zhuanlan.zhihu.com/p/718956195?utm_psn=1816383332088430592

`Nsight Systems` 是 `NVIDIA` 提供的系统级性能分析工具，专注于优化 `CUDA` 代码和模型性能。它具备以下主要功能：

1. **系统级分析**：捕获整个系统的性能数据，包括 `CPU` 和 `GPU` 活动、内存使用、线程调度和 `I/O` 操作。

2. **时间轴视图**：展示系统中各组件的执行时间，如 `CPU` 和 `GPU` 的任务、数据传输等，帮助定位性能瓶颈。

3. **API 跟踪**：支持跟踪 `CUDA` API、`NVTX` 标记、线程调度等，便于分析应用程序的执行流程。

深度学习任务分析

深度学习任务复杂，可能涉及计算密集、数据密集或内存密集型工作负载，且瓶颈会随着优化而变化。分析时应从宏观到微观，使用 `Profiler` 工具，检查 `GPU` 利用率、显存和内存占用等指标。

常见优化策略包括：

1. **减少不必要的同步**，避免频繁的 `CPU-GPU` 切换。

2. **使用多个 `CUDA` 流**，并行处理内核计算和内存传输。

3. **优化内存传输**，使用 `Pinned` 内存、异步传输和零拷贝技术，提高性能。

4. **优化 `Kernel` 访存**，通过合并访存、减少 `Bank` 冲突等手段提升访存效率。

## AMD MI300X生成式AI加速器与平台架构解读

https://zhuanlan.zhihu.com/p/718955551?utm_psn=1816383169835978752

`AMD Instinct MI300X` 是一款为高性能计算和 `AI` 推理设计的最新加速器，从技术上显著提升了计算和内存性能。它采用了台积电的5nm/6nm `FinFET`技术，集成了1530亿个晶体管，配备8个`HBM3`内存，提供192GB的容量，每个`HBM3`的带宽为6 TB/s，整个平台的总带宽达到了42.4 TB/s。这使得 `MI300X` 在处理大模型推理和训练任务时表现出色，尤其在处理需要大量内存和带宽的任务时，比如大型语言模型（`LLM`）的推理，最多支持680B参数的模型。

`MI300X` 的架构基于`CDNA 3`，支持`TF32`和`FP8`的计算精度，相较于前代`MI250`，性能提升显著。`FP64`和`FP32`的矩阵计算能力分别提升了1.7倍和3.4倍，而`FP8`计算能力更是前代的6.8倍。在大模型推理的吞吐量方面，`MI300X` 在8卡环境下比`NVIDIA H100`高1.3倍，在单卡推理中也有1.2倍的优势。

内存架构方面，`MI300X`不仅提供更大的容量和更高的带宽，其层级内存系统（包括`L1`、`L2`、`Infinity Cache`等）也优化了数据搬运效率，进一步提升了整体系统性能。此外，`MI300X`支持裸金属和虚拟化分区，具备灵活的虚拟化功能，每个`GPU`最多支持64个虚拟功能（`VF`），适用于大规模并发任务。

3. 通过强化学习过程，模型不断优化输入观察值和输出动作，使机器人在各种地形上行走时保持平衡。

## 解决RAG中的上下文缺失问题

https://d-star.ai/solving-the-out-of-context-chunk-problem-for-rag

在`RAG`（Retrieval-Augmented Generation）中，开发者常遇到的问题在于单个块（`chunk`）缺乏足够的上下文信息，导致无法有效地为检索系统或`LLM`（大语言模型）提供支持。这不仅会使简单问题得不到解答，还可能引发“幻觉”（`hallucinations`）问题。

### 问题示例

1. 块中的隐式引用和代词使其难以被正确检索或理解。

2. 单个块无法包含完整答案，答案可能分散在相邻块中。

3. 相邻块顺序被打乱时，容易导致混淆和幻觉。

4. 粗略分块会在“思维中断”时截断文本，导致每个块都缺乏有用的上下文。

5. 个别块可能只有在整个段落或文档的上下文中才有意义，单独查看可能产生误导。

### 解决方案

增加上下文块标题

为每个块添加更高级别的上下文，例如文档标题、简要摘要或章节标题，以提升块的可理解性和检索精度。通过将块标题与块内容组合进行嵌入和排序，解决了块内的隐式引用和代词问题，提高了模型的检索准确性。

从块到段

大块提供更好的上下文，但检索特定信息时，小块更为有效。一个理想的系统应能够根据查询动态调整检索的块大小，小查询使用小块，大查询使用大块。

分段处理文档

首先，将文档按语义划分为连贯的段落，然后根据需要将这些段落拆分为小块。这种方法确保每个块包含完整的上下文信息，减少了“思维中断”带来的问题。

动态构建相关段落

通过对相关块进行聚类，可以为`LLM`提供比单个块更完整的上下文信息。聚类方法通过解决最大子数组问题，动态构建最优段落，提高检索的相关性和完整性，并减少模型排序错误对检索结果的影响。

## 数据库专题研究

https://mp.weixin.qq.com/s/w_k071GbPpYVbp-vN5TCWw

### 数据库技术的重要性

随着数据量的爆炸性增长，数据库技术成为处理和分析大量数据的关键工具。数据库系统不仅要能够高效地存储数据，还要能够快速检索和分析数据，以支持企业的决策制定。

### 行业挑战

+ **数据安全**：随着数据泄露事件的增加，数据库系统的安全性受到重视。需要确保数据在存储、处理和传输过程中的安全性。

+ **性能优化**：数据库系统需要处理的数据量不断增加，性能优化成为提升用户体验的关键。这包括查询优化、索引设计和硬件加速等方面。

+ **可扩展性**：随着业务的发展，数据库系统需要能够灵活扩展以适应不断变化的数据需求。

### 技术发展趋势

+ **分布式数据库**：为了处理大规模数据集，分布式数据库技术成为趋势。它通过在多个节点上分布数据来提高系统的可扩展性和可靠性。

+ **云数据库服务**：云服务提供商提供的数据库服务，如`Amazon RDS`和`Google Cloud SQL`，允许用户按需扩展资源，降低了维护成本。

+ **新型数据库管理系统**：包括`NoSQL`数据库、`NewSQL`数据库和时间序列数据库等，它们针对特定类型的数据和查询模式进行了优化。

### 行业竞争态势

+ **多样化解决方案**：市场上出现了多种数据库解决方案，以满足不同行业和应用场景的需求。

+ **技术创新**：企业通过技术创新来获得竞争优势，如引入机器学习算法来优化数据库性能。

### 行业应用

+ **金融行业**：需要高性能、高安全性的数据库系统来处理交易数据。

+ **电信行业**：需要能够处理大量用户数据和实时数据的数据库系统。

+ **互联网行业**：需要可扩展性强、能够处理高并发请求的数据库系统。
