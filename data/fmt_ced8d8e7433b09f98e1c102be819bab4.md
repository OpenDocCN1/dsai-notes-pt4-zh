
# 大厂都在招的自动驾驶端到端到底是啥？

> 来源：`https://v11enp9ok1h.feishu.cn/docx/FrgMdCAotoItPfxJ3NOcVEP5nGb`

![](img/b67fc5c130e64e1acd9bf0431867215c.png)

> **摘要：**
> “端到端”只是一个算法架构的概念被用到自动驾驶软件架构中，并不是新技术。
> 端到端的出现和发展，依托的是数据和算力的提高，各大厂端到端未来的的核心竞争在于数据。
> 作为`AI`领域的应用分支，自动驾驶的技术突破更依赖于上级领域的技术进步，例如大模型和具身智能。

## 经典架构

![](img/4d1df05d692f8ea86fb19c029a26498e.png)

上图是自动驾驶经典架构，虽说被称为经典，但从其出现到达成共识，其实仅用了十几年的时间。无奈行业发展太快，有些厂商已经把这个架构叫做“传统”架构了~

该架构沿袭自机器人领域，更多的模拟了人类驾驶时的思考模式。图中灰色是传感器硬件部分，承担着外界环境的信号输入，可以类比人类的眼睛、耳朵等感觉器官；彩色的部分则是模拟人类大脑驾驶时的思维模块，将自动驾驶的过程主要分为四大功能：感知（Perception）、预测（Prediction）、规划（Planning）和控制（Control），还有地图和定位模块（机器人领域更习惯按感知->决策->控制三大模块划分）。接下来我们就逐一认识下这些模块：

### 感知（Perception）

自动驾驶系统通过多种传感器获取车辆周围的环境信息。这些传感器包括摄像头（单目、双目、事件相机等）、激光雷达（`LiDAR`）、毫米波雷达（Radar）、超声波传感器等。感知模块负责将传感器传递的信号处理成后续模块可以使用的信息。感知的结果通常是按照人类驾驶过程定义常见的道路信息，包含物体和事件，动态的如障碍物、机动车、自行车、行人、三轮车……静态的如车道线、交通标识和红绿灯等。同时，对于感知到的物体，还需要给出对应的状态，如可移动的机动车和行人的位置、方向、速度等，静态红绿灯当前灯的颜色、甚至是倒计时读秒的信息。

![](img/35f4614c6108225180760211442a174e.png)

同一场景不同传感器不同视角的检测结果，从上到下分别为 4D 毫米波雷达、摄像头、激光雷达

早期的感知模块主要基于信号处理和传统计算机视觉算法，使用的特征检测（例如霍夫曼变换）和逻辑规则都是人工定义的，受限于算法能力，只能识别特定环境条件的特定模板（清晰的车辆、车道线）或事件（如距离范围），精度和准确率不高，泛化能力差，基本只用于 L0 和少部分 L1 功能。

随着深度学习，特别是卷积神经网络（`CNN`）的兴起和可用算力的增长，感知模块能够识别更接近于人类认知的输出，例如能够识别更多物体的种类、颜色、位置、速度、天气等等。由此，越来越多的感知目标和任务被加入感知模块，从人类的理解出发，定义感知需要输出的内容，然后根据传感器类型或者任务分别搭建神经网络进行独立的检测，常见的有：

+   2D 目标检测
+   3D 目标检测
+   车道线检测
+   路标检测
+   红绿灯检测
+   融合（`Fusion`）
+   ...

可以说，`感知模块`率先应用了 “端到端” 技术，即利用 `CNN` 为主的深度神经网络，以图像作为输入端，输入的语义级的感知结果作为输出端。现在自动驾驶的感知模块，无论是 L0 还是 L4 级别，基本都以这种范式为主。尽管让感知模块有了更精确和强大的泛化能力，但仍然存在很多问题：

首先，是这种以枚举为主增加任务的方式，依然受限于人类的认知和数据。许多在 A 地的常见场景在 B 地是难以想象的，比如澳大利亚的道路可能出现袋鼠、中国东北的道路可能遇见东北虎……相比较这些小概率事件，更难的情况是相同语义的场景却有完全不同的感知需求，例如停车场这一对人类来说非常容易识别的场景，对于欧洲的感知需求更多的是超市外的露天停车场，而对于中国城市可能是大型建筑下的地下停车场。再涉及到停车位的话，形态更是千姿百态、五光十色。

这些真实世界的场景差异除了考验产品定义和技术能力，更考验的是数据能力。深度学习神经网络是基于数据驱动的，目标增加，就需要增加相应的训练数据。在实际开发过程中，随着场景需求的增加会不断遇到小概率物体和事件，和没有训练过、识别不出来、识别出错的场景，长尾效应依然是制约感知泛化的瓶颈。

其次是 `Fusion` 困难，同一目标可能收到来自多个传感器的感知结果，如何平衡多个结果的置信权重，不同场景（国家、天气、光线等都会影响）需要的融合方案也有细微的差别，传统方法是依靠手工规则或概率模型（如卡尔曼滤波）来进行目标级别的后融合，近来的趋势是采用深度学习为主的前融合（信号级别）或特征融合，来应对开放场景的多样性。

### 预测（Prediction）

预测模块是根据感知模块获取的实时数据和历史数据，预测车辆和周围物体在未来一段时间内的行为和轨迹。预测模块主要分为三个部分：行为预测、轨迹预测和交互预测：行为预测通过分析感知模块提供的数据，预判其他交通参与者（如车辆、行人、非机动车等）的未来行为；轨迹预测则需要根据行为预测的判断，结合实时和历史感知信息，给出其他交通参与者未来一段时间的可能轨迹；交互预测则是需要考虑自车与周围环境中的其他运动物体（如车辆、行人等）的协同交互问题。

![](img/adc9b01a18df9f7b5052ba0d08dd8ec8.png)

早期的预测多是采用基于规则的行为规划，通过引入地图的辅助和约束，例如车道线、道路可行驶区域以及道路的连接关系等几何和拓扑信息，从语义的层面对物体的运动模式进行描述，例如车辆在十字路口的变道、左转、直行、右转等，这种预测方式无法解决复杂场景（特别是交互密集场景）的预测需求。

现在的预测模块越来越多的采用了基于深度学习的方法，从实际驾驶行为数据中提取各种可能的行为模式，作为某种先验，使预测结果更接近目标实际的意图和轨迹，帮助后续模块更好的进行自车行驶的路径规划。

以丰富的交通参与者数据为输入端，直接输出对每个行为参与者的轨迹预测，预测模块似乎也可以说应用了端到端技术？

### 规划（Planning）

作为核心组件之一，自动驾驶规划模块负责综合感知和预测模块提供的环境信息，结合车辆的当前状态和导航信息，计算出一条合适的轨迹供车辆行驶。该模块通常包括多个子模块，以实现复杂的决策和规划功能。以下是自动驾驶规划模块的主要组件和技术：

![](img/bef434b698095011b1e647472d68d52a.png)

+   路径规划（Path Planning）：负责计算从当前位置到目的地的最优路径。这通常包括全局路径规划和局部路径规划。全局路径规划需要考虑从起点到终点的整体路线，通常基于地图进行；而局部路径规划则是在当前局部区域内，根据实时环境和障碍物情况，调整路径以确保安全行驶。
+   行为规划（Behavior Planning）：负责处理复杂的交通环境中的决策问题。例如，当遇到交通信号灯、行人、车辆等障碍物时，行为规划模块需要决定是否停车、绕行或加速等行为。这一模块通常基于规则或机器学习算法来实现。
+   运动规划（Motion Planning）：将行为规划的结果转化为具体的轨迹。这包括车辆的速度、加速度、转向等控制指令。运动规划模块需要考虑车辆的动态特性，如惯性、转向限制等，以确保生成的轨迹是可执行的。

经典的规划算法主要有基于贪心策略的 `Dijkstra` 算法、启发式搜索的 `A*` 算法和曲线插值生成安全、可行、较为平坦、曲率变化连续的路径。近年来，深度学习和强化学习在路径规划中的应用逐渐增多。这些技术能够从大量历史数据中提取模式和规律，动态调整路径选择策略，提高规划的精度和效率。

#### 决策模块（Decision Making）

决策模块负责综合感知模块提供的环境信息，结合车辆的当前状态和导航信息，做出驾驶决策。这包括选择行驶车道、避障、超车等决策。决策模块通常基于规则、模型预测或强化学习等方法来实现。

![](img/5fb6dd7b1f5b551b813ad2aa72c69a04.png)

+   基于规则的决策主要使用有限状态机（`FSM`）或决策树这种方法简单直观，但需要离线定义状态和决策网络，难以应对复杂的动态环境。
+   基于知识的推理包括基于规则的推理系统、基于案例的推理系统和基于神经网络的映射模型。前两种方法依赖于规则库和案例库的完备性和准确性，适用于适用于规则明确、变化不大的场景，比较适合有重复性和相似性的封闭场景。而基于神经网络的决策方法将驾驶场景特征映射到驾驶动作上，虽然需要大量的训练数据和计算资源，但因为可以处理复杂的驾驶场景，也正在成为主流趋势。
+   基于搜索的决策制定则是采用经典的规划算法（如 `Dijkstra` 和 `A*`）直接选择合适的形式路径。采用早期机器人的功能区分，省略决策这一步骤。这也是为什么许多架构中决策归于规划模块的原因。

现代自动驾驶中，通常会采用多种策略的规划制定方法，深度学习也被用于路径和决策的输出中。可以认为，端到端在规划模块中也已经实现。

另外，还有基于强化学习和基于智能体的博弈论决策制定方法，都属于较新的研究领域，就简单提一下，后面专题进行讨论。

### 控制（Control）

控制模块负责将规划模块生成的轨迹转换为具体的控制指令，如转向、加速、制动等，以实现车辆的自主驾驶。控制模块通常包括车辆动力学模型和控制算法，以确保车辆能够平稳、准确地跟随规划轨迹。控制模块主要涉及下列几种控制方：

![](img/9729ecb434ec6de44ca986e97dfcbdc5.png)

+   模型预测控制（Model Predictive Control, `MPC`）：`MPC`是一种基于模型的控制方法，通过建立车辆的动力学模型，根据未来的预测来优化控制输入。这种方法通过预测车辆在未来一段时间内的行为，并基于这些预测来调整当前的控制输入，从而实现对车辆运动的精确控制。`MPC`在自动驾驶中的应用非常广泛，特别是在高速和复杂交通环境中。
+   基于反馈的控制（Feedback Control）：基于反馈的控制方法根据当前的传感器反馈进行实时控制。这种方法通过实时监测车辆的状态和环境信息，并根据这些信息调整控制输入，以确保车辆在各种条件下的稳定性和安全性。基于反馈的控制方法在自动驾驶中同样非常重要，特别是在低速度和复杂的城市环境中。
+   主动悬架控制（Active Suspension Control）：主动悬架控制通过调整悬架阻尼系数和刚度系数等参数，改善车辆的行驶平顺性和操控稳定性。这种技术可以显著提高车辆在复杂路面条件下的舒适性和安全性，特别是在高速行驶和恶劣天气条件下。
+   线控底盘（By-Wire Chassis）：线控底盘是一种通过电子信号和电线来控制车辆底盘的系统。这种技术可以实现对车辆的各种动力学参数（如加速度、转向角度等）的精确控制，从而提高车辆的响应速度和操控性能。线控底盘在自动驾驶中的应用非常广泛，特别是在需要高精度控制的场景中。
+   车辆动力学仿真（Vehicle Dynamics Simulation）：车辆动力学仿真通过计算机模拟车辆在各种条件下的运动，以验证和优化车辆的动力学控制策略。这种技术在自动驾驶的开发和测试中非常重要，可以帮助工程师在实际道路测试之前发现和解决潜在的问题。
+   强化学习（Reinforcement Learning, `RL`）：在后面端到端内容中单独讨论

控制模块只需要把规划模块下发的动作指令在车上实现，相对其他模块来说，主要解决的是车辆执行过程中的实时和稳定性操作，无需应对复杂的环境。因此在端到端模型的应用和需求上也是最弱的。相反，清晰、可解释的传统模型能够更好的帮助工程师对控制模块进行验证和调教。

> 规划和控制模块经常会归到一起，称作规控模块（`PnC`）。

## 地图和定位 (Map & Localization)

地图和定位模块用于路径规划和行为决策。这些信息包括车道线、交通标志、障碍物等，有助于车辆更好地理解道路环境和交通规则。车载传感器并非是车辆唯一的环境信息来源，地图，特别是 高精地图（`HDMap`），也为车辆提供提供详细的道路信息，如车道线、交通标志、路灯等，帮助车辆进行路径规划，并提高导航的准确性。虽然最近各大厂家都在推“无图”方案，但最基础的地图信息仍然是必要的。

![](img/963ed8d6018dee815dce440bd6e42e58.png)

定位模块的作用则是准确判定当前车辆位于地图上的位置。规划模块根据用户的意图、定位的结果和周围的环境来决定车辆的行驶轨迹。初级的定位信息一般来源于 `GNSS`（`GPS`、北斗等）、`IMU`（惯性测量单元）、轮速计等专业导航设备。普通车载导航的定位精度一般在米级，对于自动驾驶来说，需要分米级（车道线）甚至厘米级别的定位精度，除了采用实时动态测量技术（`RTK`），还可以利用摄像头、激光雷达或毫米波雷达的感知结果进行特征匹配（如车道线匹配或点云匹配）。

## 端到端自动驾驶

从算法层面上说，从算法层面来看，每个模块都已实现了内部的端到端能力。即用一个神经网络处理该模块输入，并输出下一模块所需信息。既然已经实现了模块内的端到端，各大厂宣传的 “端到端” 又是什么呢？

![](img/9471edf4d64c85e6649c1bbd154d4e56.png)

经典自动驾驶vs端到端自动驾驶

其实，端到端模型是深度学习中的一个概念，其核心思想是输入原始数据（如传感器数据），直接输出最终结果（如车辆控制信号）。在自动驾驶领域，这意味着模型可以直接从摄像头、雷达等传感器获取数据，并输出车辆的转向、加速和制动等控制信号。

### 真·端到端

在 2016 年就已经由 [NVIDIA](http://arxiv.org/abs/1604.07316) 公司在论文《End to End Learning for Self-Driving Cars》中，将端到端概念引入自动驾驶并实施。

![](img/85b3509967cf1921210d439118560108.png)

数据采集系统

在这次实验中，团队仅使用了各种道路、光照和天气条件下收集了约 72 小时的驾驶数据，训练了一个由包括归一化层、卷积层和全连接层的 9 层神经网络。通过训练网络权重来最小化输出转向命令与实际命令之间的误差。

在模拟测试的结果表明 `CNN` 能够很好地完成车道和道路跟踪任务，即使在少量训练数据的情况下，汽车也能在多种条件下稳定运行。而且，通过对 `CNN` 内部状态的可视化，我们可以看到它能够自动学习到有用的道路特征。可以说这篇论文开启了 `CNN` 在自动驾驶领域的应用，也带来了端到端自动驾驶的新思路和方法，具有重要的影响力。

这可以说是真正的端到端方案，看起来前景令人激动，但也面临着不小的挑战：

![](img/64925e8dac6e11792acf840d6867469a.png)

+   可解释性问题：端到端模型由于其复杂的内部结构和大量参数，存在可解释性差的问题。这意味着研究人员难以理解模型的决策过程，难以定位和解决模型中的问题，增加了安全风险。
+   数据需求量大：端到端模型需要大量的高质量训练数据，包括各种驾驶场景、天气条件和交通情况的图像、视频和传感器数据。这些数据的收集、标注和维护是一项挑战。
+   算力需求高：端到端模型训练和运行需要大量的计算资源，尤其是在处理海量数据时，算力需求非常高。这需要强大的计算基础设施支持。

因此，当年并没有太多的研究和应用延续这种方案，反而开启了模块内采用深度神经网络的探索。

### 模块间端到端

在经典架构中，无论模块内部采用何种算法，模块间传递的信息始终是由规则制定的。这些人工制定的规则面临着完备性的泛化挑战，和信息传递过程的损失。

举例来说，感知与预测间的输出多为人类定义的交通参与者，如车辆、行人、常见的障碍物等等。然后预测模型推测这些输出的轨迹给到规划模块进行自车轨迹的输出。但在复杂的真实驾驶环境下，总有未被定义的障碍物（如上文所述的袋鼠）和人工难以描述的影响行驶的物品出现，这些障碍物的信息也许被传感器捕获，但因为模块间定义的缺失，而导致预测模块没有预测其运动轨迹，后续的规划模块也可能因为没有该障碍物的信息而规划出导致碰撞的轨迹……

模块间的端到端可以较好的解决这个问题。模块间的端到端是一种通过明确设计各模块中间表示，简单来说，在各模块间传递的不再是人工规则的结果，而是经过设计的每一个模块的可导特征输出。这种设计既保留原有模块的可解释性，同时也将各模块并入同一个网络，形成端到端自动驾驶，既提高了系统的性能，也保证了的安全性和稳定性。

`ST-P3`

上海 AI 实验的 [`ST-P3: End-to-end Vision-based Autonomous Driving via Spatial-Temporal Feature Learning`](https://arxiv.org/abs/2207.07601) 和 [`Planning-oriented Autonomous Driving (UniAD)`](https://arxiv.org/abs/2212.10156) 为例，前者通过对齐的 `BEV` 特征层和场景表征，将感知、预测和规划模型统一为一个网络，该网络的损失函数包括感知损失、预测损失和规划损失。在训练时不仅可以联合训练，也可以分模块进行训练。
