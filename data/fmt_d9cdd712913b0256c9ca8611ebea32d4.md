### 基础镜像分析

基础镜像提供运行环境的基准，`scripts/make-sdxl-base.sh`

```bash
#!/bin/bash

docker build -t soulteary/sdxl:base . -f docker/Dockerfile.base
```

这个命令的含义是：在当前目录下，使用`docker/Dockerfile.base`这个`Dockerfile`文件，构建一个新的Docker镜像，镜像的名字是`soulteary/sdxl`，标签是`base`。

分析`docker/Dockerfile.base`看看具体的构建细节

```dockerfile
FROM nvcr.io/nvidia/pytorch:23.07-py3

RUN pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple

RUN pip install accelerate transformers diffusers gradio ftfy invisible_watermark

WORKDIR /app
```

以下是对这个Dockerfile的解释：

+ `FROM nvcr.io/nvidia/pytorch:23.07-py3`: 这一行指定了基础镜像，所有后续的命令都在这个基础镜像的基础上执行。在这个例子中，基础镜像是NVIDIA的官方PyTorch镜像，版本是23.07，并且使用Python 3。

+ `RUN pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple`: 这一行设置了Python的`pip`包管理器的全局索引URL为清华大学的镜像站，这可以加速在中国大陆的下载速度。

+ `RUN pip install accelerate transformers diffusers gradio ftfy invisible_watermark`: 这一行使用`pip`安装了六个Python包：`accelerate`、`transformers`、`diffusers`、`gradio`、`ftfy`和`invisible_watermark`。

+ `WORKDIR /app`: 这一行设置了后续命令的工作目录为`/app`。如果这个目录不存在，Docker会自动创建它。

所以，这个Dockerfile的作用是：基于NVIDIA的官方PyTorch镜像，设置`pip`的全局索引URL为清华大学的镜像站，然后安装六个Python包，最后设置工作目录为`/app`。

以下是基础镜像包含的六个Python包的介绍：

+ `accelerate` - 一个用于加速PyTorch模型训练和推理的库。它可以利用GPU/TPU进行加速,并支持混合精度训练等。

+ `transformers` - 一个由Hugging Face开发的自然语言处理库,提供了许多预训练语言模型,如`BERT`、`GPT`等。它使得这些模型可以方便地用于下游任务。

+ `diffusers` - OpenAI开源的用于图像生成的库,基于diffusion模型。它可以生成高质量的图像。

+ `gradio` - 一个用于快速构建基于Python的GUI应用的库。它可以把Python函数或模型通过GUI展示出来。

+ `ftfy` - 一个用来修复编码问题的Python库,如非UTF-8编码、无效Unicode等。它可以处理文本编码错误。

+ `invisible_watermark` - 一个用于给图像添加隐形水印的库。水印信息可以是文本或图片,并可以可逆地嵌入到图像中。

### 运行时镜像分析

`scripts/make-sdxl-runtime.sh`

```bash
#!/bin/bash

docker build -t soulteary/sdxl:runtime . -f docker/Dockerfile.runtime

docker build -t soulteary/sdxl:runtime-xformers . -f docker/Dockerfile.runtime-xformers
```

这个脚本的作用是：使用`docker/Dockerfile.runtime`和`docker/Dockerfile.runtime-xformers`这两个`Dockerfile`，分别构建`soulteary/sdxl:runtime`和`soulteary/sdxl:runtime-xformers`这两个Docker镜像。

可以看到这个脚本会创建两个运行时容器

+ `soulteary/sdxl:runtime`:使用`diffusion-pipeline`环境

+ `soulteary/sdxl:runtime-xformers`:使用`transformer`环境

我们后续的demo以`diffusion-pipeline`为主

先看看`docker/Dockerfile.runtime`

```dockerfile
FROM soulteary/sdxl:base

RUN pip uninstall transformer-engine -y

COPY src/diffusion-pipeline/*.py ./
```

以下是这段代码的解释：

+ `FROM soulteary/sdxl:base`: 这个指令表示基础镜像是`soulteary/sdxl:base`。Docker会从这个镜像开始构建新的镜像。

+ `RUN pip uninstall transformer-engine -y`: 这个指令表示在新的镜像中运行一个命令，这个命令是`pip uninstall transformer-engine -y`。这个命令的作用是卸载`transformer-engine`这个Python包。`-y`参数表示在卸载过程中自动确认所有的提示。

+ `COPY src/diffusion-pipeline/*.py ./`: 这个指令表示将`src/diffusion-pipeline/`目录下的所有`.py`文件复制到新的镜像的工作目录中。这个指令的源路径是相对于构建上下文的路径，目标路径是相对于工作目录的路径。

所以，这个Dockerfile的作用是：基于`soulteary/sdxl:base`这个镜像，卸载`transformer-engine`这个Python包，然后将`src/diffusion-pipeline/`目录下的所有`.py`文件复制到新的镜像中。
