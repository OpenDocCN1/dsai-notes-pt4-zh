## Github 代码扫描

代码扫描可以通过多种方式整合到现有开发工作流程中，以显著提高软件安全性。其核心目标是发现、分类并优先修复代码中现有的安全漏洞和编码错误，并防止开发者引入新的问题。

以下是代码扫描如何整合到开发工作流程中的具体方法：

### 选择合适的设置方式

- 默认设置（Default Setup）：这是最快的配置方式，适用于希望快速启用 `CodeQL` 分析的仓库。它会自动选择分析语言、查询套件以及触发扫描的事件。默认设置将代码扫描作为 `GitHub Actions` 运行，无需手动维护工作流文件。

- 高级设置（Advanced Setup）：此选项提供更高的灵活性。它会生成一个可定制的工作流文件（通常是 `codeql-analysis.yml`），您可以直接提交到您的仓库。通过高级设置，您可以精确控制扫描的频率、要扫描的语言或目录、`CodeQL` 在代码中查找的内容，甚至编译代码的特定命令。如果已使用默认设置，可以切换到高级设置以获得更多控制。

- 在外部 CI 系统运行 `CodeQL CLI` 并上传结果（Run CodeQL CLI in an external CI system）：如果您有现有的持续集成（CI）系统，可以在其中直接运行 `CodeQL CLI` 进行代码分析，并将生成的静态分析结果交换格式（SARIF）文件上传到 GitHub。

### 配置扫描触发事件和频率

- 按推送扫描（Scan on Push）：默认 `CodeQL` 分析工作流使用 `on:push` 事件，在每次代码推送到仓库的默认分支和任何受保护分支时触发代码扫描。扫描结果会显示在仓库的“安全”选项卡中。当检测到的问题可以映射到开放的拉取请求时，这些警报也会自动出现在拉取请求中。

- 按拉取请求扫描（Scan on PR）：默认 `CodeQL` 分析工作流使用 `on:pull_request` 事件，在针对默认分支的拉取请求被创建时触发代码扫描。扫描结果会作为警报显示在拉取请求检查中。扫描拉取请求的合并提交通常比每次推送都扫描分支头更高效和准确。

- 定期扫描（Scheduled Scan）：除了事件触发的扫描外，默认 `CodeQL` 分析工作流每周会以随机生成的时间表扫描一次代码。您可以修改工作流中的 `cron` 值来调整此计划，例如，将其设置为每周一特定时间运行。定期扫描有助于发现 GitHub、安全研究人员和社区发现的最新漏洞和错误，即使开发者不经常维护仓库也是如此。

- 避免不必要的扫描：可以通过在代码扫描工作流中指定 `on:pull_request:paths-ignore` 或 `on:pull_request:paths` 来避免对特定文件更改（例如 `.md` 或 `.txt` 文件）的拉取请求进行扫描。

### 集成第三方工具

- 上传 SARIF 文件：您可以将外部生成或使用 `GitHub Actions` 生成的 SARIF 文件上传到 GitHub，以便在仓库中查看来自第三方工具的代码扫描警报。GitHub 使用 SARIF 文件中的信息来创建代码扫描警报，且结果必须使用 SARIF 版本 2.1.0。

- 通过 `CodeQL CLI` 上传：`CodeQL CLI` 是一个独立的工具，可以生成代码库的数据库表示，然后运行查询生成 SARIF 格式的结果，并将其上传到 `GitHub.com`。

- 通过 `代码扫描 API` 上传：`代码扫描 API` 允许您检索和更新代码扫描警报、分析、数据库和默认设置配置，也可以用于上传使用离线代码扫描工具生成的分析结果。

- 通过 `GitHub Actions` 上传 SARIF：可以使用 `github/codeql-action` 仓库中的 `upload-sarif` 动作来上传第三方 SARIF 文件。该动作可以在 `push` 和 `scheduled` 事件发生时运行。这对于将外部生成的 SARIF 文件提交到仓库后进行上传，或作为 CI 工作流的一部分生成 SARIF 文件并进行上传非常有用，例如与 `ESLint` 等静态分析工具结合使用。

### 管理警报和拉取请求检查

- 定义导致拉取请求检查失败的严重级别：默认情况下，只有严重级别为“错误”或安全严重级别为“关键”或“高”的警报才会导致拉取请求检查失败。拉取请求失败会阻止代码合并，但不会停止代码扫描。您可以在仓库设置中更改这些级别。

- 去重机制：每次上传新的代码扫描结果时，GitHub 会处理这些结果并将警报添加到仓库。它使用指纹识别（`partialFingerprints` 字段）来匹配不同运行中的相同问题，以防止重复警报。

通过将代码扫描配置为在关键开发事件（如代码推送和拉取请求）发生时自动运行，或者根据预设的时间表定期运行，开发团队可以在代码更改进入生产环境之前捕获潜在的安全漏洞和编码错误。这有助于早期发现并解决问题，从而提高整体软件安全性。

`GitHub Actions` 对于公共存储库是免费使用的。

对于私有存储库，每个 GitHub 账户会根据其所使用的产品获得一定数量的免费分钟数和存储空间。超出这些免费额度的使用将受消费限额控制。

`CodeQL` 作为 GitHub 代码扫描的核心分析引擎，其分析结果也会作为代码扫描警报显示在 GitHub 中。`CodeQL CLI` 对于在 `GitHub.com` 上维护的公共存储库是免费使用的。对于客户拥有的私有存储库，使用 `CodeQL CLI` 则需要 GitHub Advanced Security 许可证。

运行 `GitHub Actions` 中的代码扫描工作流会消耗 `GitHub Actions` 的分钟数。

## Github Copilot

GitHub Copilot 是一款由 Microsoft 与 OpenAI 合作开发的 AI 结对程序员服务，由 `OpenAI Codex` 系统提供支持，该系统在包含公共源代码的数据集上进行训练，对人们如何使用代码有广泛的了解，并且在代码生成方面比 `GPT-3` 更强大。GitHub Copilot 作为 VS Code、Visual Studio、Vim/Neovim 和 JetBrains IDE 套件的扩展提供。

### 工作机制

GitHub Copilot 的工作原理主要基于其底层的人工智能系统和其与开发环境的深度集成。

### 核心技术支持

- GitHub Copilot 是由 Microsoft 与 OpenAI 合作开发的。

- 它由 `OpenAI Codex` 系统提供支持。

- `OpenAI Codex` 在包含公共源代码的数据集上进行训练，这使其对人们如何使用代码有广泛的了解。

- 在代码生成方面，`OpenAI Codex` 比 `GPT-3` 更强大，部分原因是它在一个更集中的公共源代码数据集上进行了训练。

### AI 编程助手

- GitHub Copilot 被设计为一款 AI 结对程序员或 AI 编程助手。

- 它作为 VS Code、Visual Studio、Vim/Neovim 和 JetBrains IDE 套件的扩展提供，使其能够深度融入开发者的工作流程。

### 核心交互机制

- 实时上下文感知：当开发者输入代码时，Copilot 会分析当前代码和上下文，以灰显文本的形式实时提供代码补全建议。它能够识别开发者输入的代码以及显示的错误消息。

- 自然语言处理：Copilot 利用自然语言处理技术将代码注释转换为实际的代码。开发者可以在注释中描述所需的功能，然后 Copilot 会根据描述生成代码。

- 多功能辅助：Copilot 不仅仅是自动完成。它能够解释代码块的功能、生成单元测试，甚至为 bug 提供建议修复。

- 学习与适应：Copilot 会从上下文和用户的交互中学习。保持代码结构清晰并添加注释有助于 Copilot 提供更准确和相关的帮助。用户与 Copilot 的交互越多，它就越能理解用户的编码风格和偏好。

总的来说，GitHub Copilot 通过强大的 `OpenAI Codex` 模型，结合对大量公共源代码的训练，实现了对代码的高度理解和生成能力。它实时分析开发者的输入和上下文，提供智能的代码建议、解释、测试生成和错误修复建议，从而成为开发者在整个开发生命周期中的得力助手。

### 主要功能

GitHub Copilot 的主要功能涵盖了开发生命周期的多个方面，旨在提高开发人员的工作效率和体验：

### AI 支持的自动完成

这是 GitHub Copilot 的起点功能，通过自动完成注释和代码来帮助开发人员保持工作流的连贯性。在输入时，Copilot 会分析代码和上下文，以灰显文本的形式实时提供代码补全建议。开发人员可以通过 `Tab` 键或 `>` 键接受建议，或通过继续键入或 `Esc` 键拒绝建议。此功能特别适用于重复任务或需要快速示例代码时。

- 多项建议：对于复杂的代码片段，Copilot 可以提供多个替代方法，帮助开发人员探索不同的编码方法并选择最合适的。

### Copilot Chat（聊天功能）

- 编辑器内聊天界面：将类似 ChatGPT 的聊天界面引入编辑器，专注于开发人员场景，并与 VS Code 和 Visual Studio 本机集成。

- 上下文感知：它深度嵌入到 IDE 中，能够识别开发人员输入的代码和显示的错误消息。

- 功能：开发人员可以深入分析和解释代码块的功能、生成单元测试，甚至获得针对 bug 的建议修复。

- 自然语言交互：用户可以使用自然语言提出问题或请求代码片段，Copilot 会根据输入提供响应。

- 内联聊天：可以直接在代码编辑器中进行上下文特定的对话，无需切换上下文，用于请求代码修改或解释。内联聊天还支持斜杠命令（例如 `/explain` 用于解释代码，`/suggest` 用于提供代码建议，`/tests` 用于生成单元测试，`/comment` 用于将注释转换为代码片段），以实现更高效的交互。

### Copilot for Pull Requests（拉取请求功能）

利用 OpenAI 的 `GPT-4` 模型，通过 GitHub 应用支持在拉取请求说明中使用 AI 支持的标记。GitHub Copilot 会根据更改的代码自动填充这些标记，开发人员可以查看或修改建议的说明。

### Copilot for CLI（命令行接口功能）

可以在终端中编写命令和循环，还能找出模糊的 `find` 标志来满足用户的查询。

### 命令面板访问

通过 Visual Studio Code 中的命令面板，可以快速访问 Copilot 的各种函数，只需几个按键即可执行复杂的任务，例如 `解释此` 或 `生成单元测试`。

### 将代码注释转换为代码

Copilot 利用自然语言处理将注释转换为代码。开发人员可以在注释中描述所需的功能，按 `Enter` 键后，Copilot 会根据说明生成代码。

### 解释代码

通过“`解释此`”功能，用户可以获取选定代码片段的说明，这对于学习目的和查看他人编写的代码非常有帮助。

### 自动测试生成

Copilot 可以通过为函数或类生成单元测试来帮助开发人员节省时间和精力，有助于在开发过程中保持代码完整性并捕获 bug。

### 订阅计划

不同订阅计划下的功能差异：GitHub Copilot 提供多种订阅计划，每个计划为个人、团队和组织提供不同的功能。

- GitHub Copilot Free：包括每月 2000 个代码完成、每月 50 个聊天请求，以及访问 `GPT-4o` 和 `Claude 3.5 Sonnet` 模型。

- GitHub Copilot Pro：专为需要增强功能的个人开发人员设计，提供无限的代码完成和聊天请求、优先访问最新的 AI 模型、高级代码建议和说明、与支持的 IDE 集成以及自动测试生成和代码说明功能。

- GitHub Copilot Pro+：包含 Copilot Pro 的所有功能，并额外提供付费请求容量和在高需求资源上的优先性能。

- GitHub Copilot Business：适用于组织，提供所有 Pro 和 Pro+ 功能，以及集中式管理和策略控制、安全漏洞筛选、代码引用和公共代码筛选、IP 赔偿和企业级安全性、安全和隐私，以及在 IDE 和移动设备中聊天。

- GitHub Copilot Enterprise：专为大型组织和企业设计，包含所有业务功能，并额外提供基于内部/专用代码的个性化代码建议、与 `GitHub Enterprise Cloud` 集成、基于 AI 的搜索和跨代码库的文档生成、增强的拉取请求支持（结合 AI 驱动的标记和摘要）、对 Copilot 模型进行组织范围的自定义和微调，以及与 GitHub 进行深度集成以进行聊天和代码库探索。Enterprise 版本可以为组织的代码库编制索引，以提供更深入的见解和定制建议。

GitHub 和 Microsoft 的研究发现，开发人员在使用 GitHub Copilot 处理实际项目和任务时，工作效率显著提升，例如 46% 的新代码由 AI 编写，开发人员整体工作效率提高 55%，74% 的开发人员更专注于令人满意的工作。

## Codespaces 概述

### 运作机制

### 可配置的开发环境

GitHub `Codespaces` 旨在为项目创建可配置的自定义开发环境，确保所有项目用户都能获得可重复的 `Codespace` 配置。它的生命周期从创建开始，到删除结束。

### 创建流程

创建 `Codespace` 时，会发生四个主要进程：

- 分配虚拟机（VM）和存储。

- 创建一个容器。

- 建立与 `Codespace` 的连接。

- 执行创建后设置。这个过程可能需要几分钟来创建开发环境。

### 持久性与保存

你的工作保存到云中的虚拟机上。

- 通过 Web 连接到 `Codespace` 时，自动保存会自动启用。

- 通过桌面版 Visual Studio Code 连接时，需要手动启用自动保存。你可以关闭并停止 `Codespace`，之后返回到保存的工作，不会丢失对项目所做的更改。

### 恢复与重新连接

你可以断开连接并重新连接到活动的 `Codespace`，而不会影响其正在运行的进程。可以随时从 `GitHub.com`、JetBrains IDE、Visual Studio Code 或通过 `GitHub CLI` 重新打开任何活动或已停止的 `Codespace`。

### 超时与停止

如果 `Codespace` 处于非活动状态或未显式停止，它会在一段时间（默认 30 分钟）后超时并停止运行。停止的 `Codespace` 仅产生存储成本。当 `Codespace` 超时时，将保留上次保存更改时的数据。

### 网络连接

`Codespace` 需要 Internet 连接。如果连接丢失，你将无法访问 `Codespace`，但所有未提交的更改都会保存。重新建立连接后，可以访问 `Codespace`。

### 重新生成

你可以重新生成 `Codespace` 以实施对开发容器配置的更改。在重新生成时，`/workspaces` 目录中的更改（包括存储库克隆）会得到保留，而该目录之外的更改会被清除。

### 删除

完成任务并将更改推送到远程分支后，可以安全地删除 `Codespace`。如果 `Codespace` 包含未推送的 `Git` 提交，编辑器会通知你，你可以选择推送、删除（并丢失未提交更改）或将代码导出到新分支。非活动的已停止 `Codespace` 也会在指定时间后自动删除（默认 30 天，可自定义保留间隔）。

### 主要功能

GitHub Codespaces 提供了一系列功能来支持和个性化开发体验：

### 高度可定制

作为一个为你量身打造的专用环境，可以通过多种方式进行自定义。

### 创建灵活性

可以在 `GitHub.com`、Visual Studio Code 或通过 `GitHub CLI` 创建 `Codespace`。可以为每个存储库甚至每个分支创建多个 `Codespace`（但数量有限制）。

### 计算能力与终端访问

与 `GitHub.dev` 不同，`Codespaces` 具有关联的计算资源，可以构建、运行和调试代码，并提供完整的集成终端访问，预装了一组通用工具。

### 个性化设置

- 开发容器配置：使用开发容器配置存储库，定义默认环境。

- 设置同步：在桌面应用和 VS Code Web 客户端之间同步 Visual Studio Code（VS Code）设置，包括扩展、设置、主题和键盘快捷方式。

- `Dotfiles`：使用 `Dotfiles` 存储库指定脚本、`shell` 首选项和其他配置，以个性化开发体验。

- 重命名 `Codespace`：更改 `Codespace` 的自动生成显示名称，以便区分。

- 更改 Shell：在 `Codespace` 中更改 shell，以保留习惯设置。

- 更改计算机类型：更改运行 `Codespace` 的 VM 类型，以匹配所需的资源。

- 设置默认编辑器：在个人设置页中设置 `Codespace` 的默认编辑器，支持 Visual Studio Code（桌面或 Web 客户端）、JetBrains Gateway 或 JupyterLab。

- 设置默认区域：在 GitHub `Codespaces` 配置文件设置页面中设置默认区域，个性化数据保存位置。

- 设置超时：自定义非活动状态后停止 `Codespace` 的默认超时期限。

- 配置自动删除：设置已停止的 `Codespace` 的保留时间间隔，最长为 30 天。

### 扩展和插件

- VS Code 扩展：从 Visual Studio Code Marketplace 添加所需的任何扩展。
