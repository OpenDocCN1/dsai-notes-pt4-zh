## 通信协作的消息机制

目前在MetaGPT中的消息协作机制如下所示

![](img/e007d26c5028ae62912c0bbfb37e9d75.png)

在通信/协作环境中注册的agent将观察环境中的消息(`message`)，根据对消息来源和指定参数的过滤，将新增的感兴趣的消息(`news`)添加到agent自己的记忆中，并根据当前`news`进行自我任务的规划和执行。

消息的转发和路由通过每个环境中的`message` 广播给每个agent，每个agent根据自己订阅的`action`类型进行消息的接收和筛选。

如下所示，`observed`为根据注册的观察列表进行过滤

```python
async def _observe(self) -> int:
    """Observe from the environment, obtain important information, and add it to memory"""
    if not self._rc.env:
        return 0
    env_msgs = self._rc.env.memory.get()

    observed = self._rc.env.memory.get_by_actions(self._rc.watch)
    self._rc.news = self._rc.memory.remember(observed)  # remember recent exact or similar memories
    
    if len(self._rc.news) > 0:
        logger.info(self._rc.news)
        
    for i in env_msgs:
        self.recv(i)

    news_text = [f"{i.role}: {i.content[:20]}..." for i in self._rc.news]
    if news_text:
        logger.info(f'{self._setting} observed: {news_text}')
    return len(self._rc.news)
```

每个agent完成任务后，都在自己的`_act()`中将自己任务结果封装为消息，并通过`_publish_message`发送到环境中，进行广播

```python
def _publish_message(self, msg):
    """If the role belongs to env, then the role's messages will be broadcast to env"""
    if not self._rc.env:
        return
    self._rc.env.publish_message(msg)
```

### `_observe`改造

由于所有消息都存在于环境记忆中，持续的多轮学习存在多个相关的action类型，agent仅根据注册过的观察的action类型（存在action类型重复）进行过滤无法满足获取当前轮次action信息筛选的需求，因此增加agent对轮次消息的过滤，通过`message`的`round_id`进行轮次消息的筛选

```python
async def _observe(self) -> int:
    await super()._observe()
    for msg in self._rc.news:
        logger.info(f"check msg round :{msg.round_id}")
    self._rc.news = [
        msg for msg in self._rc.news if msg.round_id == self.round_id
    ]  # only relevant msgs count as observed news
    return len(self._rc.news)
```

### 状态维护 `maintain_actions`

Minecraft的agent都可维护自己action完成数量的计数。针对一个agent在单轮流程中进行不同任务的处理和状态流转，我们新增了`finish_state`的参数，用于统计当前轮次每个agent已完成的任务数。当agent的`finish_state`为0时，说明agent的全部action都已执行完成，当前agent在当前轮次的完成状态可被更新。

该函数在agent每次执行任务，调用`_act()`时进行记录

```python
def maintain_actions(self, todo):
    logger.info(f"{self._setting.name}:{self.finish_state}")
    if todo in self._actions:
        self.finish_state -= 1
    if self.finish_state <= 0:
        self.finish_step = True
    logger.info(f"{self._setting.name}:{self.finish_state}")
```

每个agent都根据自己注册的待完成actions进行`finish_state`初始值设定。

## 终身学习 & 持续经验累积

### 多轮学习

在Minecraft游戏中，为了给Minecraft玩家持续发布游戏任务和持续进行游戏，我们改造了MetaGPT中的环境运行机制，让MetaGPT的控制环境能持续产生多轮任务，触发actions进行持续进行。

#### `Environment` `run`的改造

在环境中启动各个角色/agent的运行时，我们注入了`round_id`，`round_id`将跟随系统的消息广播，给每一个环境中的`message`打上对应轮次的标签，便于agent进行消息的过滤。

在每一轮游戏开始时，都将更新`round_id`，并发布消息到环境中，所有角色将根据当前轮次进行任务执行

#### 轮次更新

如前所述，在所有actions执行（包括内循环结束）结束后，一个任务的轮次将结束，我们通过`round_id`进行轮次的更新。具体来说，即根据所有环境中注册的agent的任务完成状态进行判断，当所有agent都处于任务完成状态时，说明当前环境中的一个轮次已全部结束，任务轮次增加1。

```python
def check_complete_round(self):
    complete_round = []
    for role in self.environment.roles.values():
        status = role.finish_step
        complete_round.append(status)
    complete_round_tag = all(complete_round)
    logger.info(f"complete_round {complete_round}")
    return complete_round_tag
```
