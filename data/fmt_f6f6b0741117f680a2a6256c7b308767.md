# 自然语言

Azure AI 语言是基于云的服务，它提供自然语言处理 (NLP) 功能，可用于理解和分析文本。使用此服务可帮助使用基于 Web 的 Language Studio、REST API 和客户端库生成智能应用程序。

# 学习路径

## 使用 Azure AI 语言分析文本

每天，世界都会生成大量数据；大部分内容基于文本，其形式包括电子邮件、社交媒体文章、在线评论、业务文档等。通过应用统计和语义模型的人工智能技术，可以创建从基于文本的数据中提取含义和见解的应用程序。

Azure AI 语言为可轻松集成到你自己的应用程序代码中的常见文本分析技术提供 API。Azure AI 语言旨在帮助从文本中提取信息。它提供可用于以下各项的功能：

+ 语言检测 确定编写文本所用的语言。
+ 关键短语提取 标识文本中指示要点的重要单词和短语。
+ 情绪分析 量化文本的正负面情绪程度。
+ 命名实体识别 检测对实体的引用，包括人员、位置、时间段、组织等。
+ 实体链接 通过提供指向维基百科文章的参考链接来标识特定实体。

### 语言检测

+ **核心功能与应用**：Azure AI语言检测API能够评估文本输入并返回每个文档的语言标识符和置信度分数，适用于处理未知语言的文本和聊天机器人中的语言识别。

+ **请求与响应格式**：用户需以JSON格式提交文档集合，每个文档包含唯一ID和文本。API返回JSON响应，包含预测的语言和置信度分数，置信度分数介于0到1之间，越接近1表示置信度越高。

+ **文档大小与集合限制**：单个文档的字符数需小于5,120个，每个集合限制为1,000个项。可以通过提供`countryHint`来提高预测性能。

+ **多语言内容处理**：当文档包含多语言内容时，API会返回代表性最强但置信度可能较低的语言，反映文本中的主要语言。

+ **异常情况处理**：如果提交的文本内容无法分析，如因字符编码问题，API将返回`Unknown`作为语言名称和ISO代码，置信度分数为0。

### 提取关键短语

+ **功能描述**：关键短语提取是评估一个或多个文档的文本，并识别出围绕文档上下文的要点的过程。

+ **适用性与限制**：最适合大型文档，可分析的最大大小为5,120个字符。

+ 通过REST接口提交一个或多个文档进行分析。

+ **请求格式**：提供了一个JSON格式的示例，展示如何提交包含文档ID、语言和文本的请求。

+ **响应内容**：响应包含每个文档中检测到的关键短语列表。

### 分析情绪

+ **功能描述**：情绪分析用于评估文本文档的正负面情绪程度，适用于多种工作场景，如基于评论量化情绪、确定客户服务响应的优先级等。

+ **应用场景**：
  + 评估电影、书籍或产品的评论。
  + 确定客户服务对电子邮件或社交媒体消息的响应优先级。

+ **分析内容**：Azure AI情绪分析提供每个文档的总体情绪和单个句子的情绪。

+ **请求格式**：提供了一个JSON格式的示例，展示如何提交包含文档ID、语言和文本的请求。

+ **响应内容**：响应包含每个文档的情绪分类（正面、中性、负面）和置信度分数，以及每个句子的情绪分析。

+ **置信度分数**：句子情绪基于0到1之间的正面、负面和中性分类值的置信度分数。

+ **总体文档情绪确定**：
  + 如果所有句子都为中性，则总体情绪为中性。
  + 如果句子分类仅包括正面和中性，则总体情绪为正面。
  + 如果句子分类仅包括负面和中性，则总体情绪为负面。
  + 如果句子分类包括正面和负面，则总体情绪是混合的。

### 提取实体

+ **功能描述**：命名实体识别（NER）用于识别文本中提及的实体，并将它们按类别和子类别进行分组。

+ **实体类别**：实体包括人员、位置、日期时间、组织、地址、电子邮件和URL等。

+ **请求格式**：提供了一个JSON格式的示例，展示如何提交包含文档ID、语言和文本的请求。

+ **响应内容**：响应包含每个文档中找到的分类实体的列表，包括实体文本、类别、子类别、偏移量、长度和置信度分数。

+ **置信度分数**：每个识别的实体都附带一个置信度分数，表示模型对其识别准确性的信心。

### 提取链接的实体

+ **功能描述**：实体链接用于区分同名实体，通过引用知识库中的文章来确定文本中特定实体的链接。

+ **知识库来源**：维基百科作为文本分析服务的知识库，用于根据实体上下文确定特定文章链接。

+ **请求格式**：提供了一个JSON格式的示例，展示如何提交包含文档ID、语言和文本的请求。

+ **响应内容**：响应包含文本中标识的实体以及指向相关文章的链接，包括实体的Bing ID、名称、匹配文本、偏移量、长度、置信度分数、语言、ID、URL和数据源。

+ **模型版本**：响应中包含了使用的模型版本信息。

## 使用 Azure AI 语言创建问题解答解决方案

“智能”应用程序的常见模式是使用户能够使用自然语言提问并收到相应的答案。实际上，此类解决方案将对话智能引入传统的常见问题解答 (FAQ) 发布。本模块介绍如何使用 Azure AI 语言创建可支持应用程序或机器人的问答对知识库。

### 问题解答

借助包括问题解答功能的 Azure AI 语言，可以定义可使用自然语言输入查询的问答对知识库。知识库可以发布到 REST 终结点，并供客户端应用程序（通常是机器人）使用。

可以从现有源创建知识库，其中包括：

+ 包含常见问题解答 (FAQ) 文档的网站。
+ 包含结构化文本的文件，如手册或用户指南。
+ 内置的闲聊问题和用于封装常见对话交流的答案对。

### 比较问题解答和 Azure AI 语言理解

### 创建知识库

若要创建问题解答解决方案，可以使用 REST API (https://language.azure.com/) 或 SDK 编写用于定义、训练和发布知识库的代码。不过，更常见的是使用 Language Studio Web 界面来定义和管理知识库。

### 实现多回合对话

+ **多回合对话的定义**：多回合对话是指在知识库中，除了单个问答对外，还包含一系列的跟进提示和响应，以便进行更深入的交互。

+ **多回合对话的必要性**：有时需要在提供明确答案之前通过询问后续问题来获取更多用户信息。

+ **实现多回合对话**：
  + 可以从现有网页或文档中导入问答对，并启用多回合响应。
  + 可以为现有问答对显式定义跟进提示和响应。

+ **应用场景示例**：以旅行预订知识库为例，初始问题可能是“如何取消预订？”，由于预订可能指酒店或航班，需要跟进提示来获取详细信息。

+ **答案和跟进提示**：答案可能包含一些初步信息，并提供跟进提示，以及指向取消航班和取消酒店的具体答案链接。

+ **定义跟进提示**：
  + 在定义多回合对话的跟进提示时，可以链接到知识库中的现有答案，或定义新答案。
  + 可以限制链接答案，使其仅在由原始问题发起的多回合对话上下文中显示。

+ **视觉辅助**：页面提供了多回合对话的示意图，帮助理解对话流程。

### 测试并发布知识库

定义知识库后，可以训练其自然语言模型并测试该模型，然后发布，以便在应用程序或机器人中使用。

![](img/8eddc0a7a100904c1c351a1a2aee427a.png)

如果对知识库的性能满意，可以将其部署到 REST 终结点，客户端应用程序可以使用该函数来提交问题和接收答案。可以直接从 Language Studio 部署它。

若要使用已发布的知识库，可以使用 REST 接口。

### 提高问题解答性能

+ **主动学习的目的**：主动学习有助于随着时间的推移更好地正确回答用户问题，特别是当用户以不同措辞提出相同问题时。

+ **主动学习的状态**：主动学习默认处于启用状态。

+ **创建问答对**：在Language Studio中创建问题和答案对，也可以批量上传包含问答对的文件。

+ **审阅建议的备选问题**：主动学习为每个问题提供备选问题，用户可以在“查看建议”窗格中审阅这些建议，并选择接受或拒绝。

+ **批量操作**：用户可以批量接受或拒绝所有建议的备选短语。

+ **手动添加备选问题**：在“编辑知识库”窗格中，用户可以手动为问答对添加备选问题。

+ **定义同义词的用途**：当用户提交的问题可能包含多个不同的字词来表示相同内容时，通过定义同义词，问题解答服务可以找到相应的答案。

+ **定义同义词的方法**：使用REST API提交JSON格式的同义词，例如将`reservation`和`booking`定义为同义词。

## 生成对话语言理解模型

自然语言处理 (NLP) 是一个常见的 AI 问题，即软件必须能够以人类用户书写或说话所用的自然语言形式处理文本或语音。在更广泛的 NLP 领域中，自然语言理解 (NLU) 处理从自然语言确定语义含义的问题，通常使用训练的语言模型来确定。

自然语言理解解决方案的常见设计模式如下所示：

![](img/d38e877f0c35c5843c692f651f60ae45.png)

在此设计模式中：

1. 应用接受来自用户的自然语言输入。
2. 语言模型用于确定语义含义（用户的意向）。
3. 应用执行相应操作。

Azure AI 语言使开发人员能够基于可使用数量相对较少的示例训练的语言模型来生成应用，从而识别用户的预期含义。

### 了解用于生成对话语言理解模型的资源

当然，我们可以将要点整合到更少的分类下。以下是将要点归类到三个主要标题下：

+ **资源创建与管理**
  + **Azure 语言资源创建**：在 Azure 中创建语言资源，用于开发 NLP 解决方案，包括创作模型和处理预测请求。
  + **Azure 门户操作**：在 Azure 门户中搜索并选择“语言服务”，创建资源，并获取密钥和终结点。

+ **模型构建与部署**
  + **模型构建、训练和部署**：需要生成、训练并部署模型，以便用于预测。Azure AI 语言服务通过这些步骤学习要查找的内容。
  + 使用 Language Studio：Language Studio 提供了一个直观的界面来生成、训练和部署模型。
  + **使用 REST API**：通过 REST API 生成模型，包括创建项目、导入数据、训练、部署和使用模型。
  + **身份验证**：对于每个调用 Azure AI 语言资源的请求，通过 `Ocp-Apim-Subscription-Key` 标头进行身份验证。
  + **部署模型**：提交部署作业并检查部署作业状态，使用特定的 REST API 终结点和请求体。
  + **获取部署状态**：使用 GET 请求查询部署状态，检查模型训练和部署是否成功。

+ **模型查询与预测**
  + **查询模型**：使用 C# 或 Python 中的 SDK，或者 REST API 来查询模型进行预测。
  + **SDK 查询**：创建客户端并使用它调用相应的终结点，例如提取关键短语。
  + **REST API 查询**：创建对相应 URL 的 POST 请求，使用 `Ocp-Apim-Subscription-Key` 标头进行身份验证，并在请求正文中指定 `kind` 参数。
  + **示例响应**：SDK 和 REST API 的查询响应将以 JSON 格式返回，包括关键短语提取结果或对话语言理解结果。

### 定义意向、言语和实体

+ **定义意向（Intents）**：**意向**表示用户想执行的任务或操作，或言语的含义。需要定义模型能够理解的意向，并将其与一个或多个言语关联。每个模型包括`无`意向，用于标识不需要执行特定操作的言语（如问候语）。

+ **收集言语（Utterances）**：
  + 为每个意向捕获各种不同的示例言语。
  + 包括含义相同但用不同方式构造的言语。
  + 采用不同长度的言语：短、中、长。
  + 使言语中的名词或主体位于不同位置。
  + 在不同的言语中使用正确的和不正确的语法。

+ **标记数据的精度、一致性和完整性**：
  + **精确标记**：始终将每个实体标记为正确的类型。
  + **一致标记**：同一实体在所有语句中都应具有相同的标记。
  + **完全标记**：标记所有语句中实体的所有实例。

+ **定义实体（Entities）**：实体用于向意向添加特定上下文。实体可以是学习实体、列表实体或预生成的实体。
  + **学习实体**：最灵活，用于定义后在训练言语中将单词或短语与该实体关联。
  + **列表实体**：适用于具有一组特定可能值的实体，如一周中的几天。
  + **预生成的实体**：适用于数字、日期/时间和名称等常见类型。

### 使用模式区分相似的言语

+ **模式的应用**：**模式**用于区分具有相似言语的意向，同时减少示例言语的数量。

+ **相似言语的问题**：在多个意向中，言语可能在语法上相似，但在单词或标点符号上有所不同，表示不同的意向。

+ **意向示例**：提供了三个意向`TurnOnDevice`、`GetDeviceStatus`、`TurnOffDevice`的示例言语，这些言语在结构上相似，但表示不同的操作。

+ **模式的使用**：使用模式可以指定不同格式的言语，如：
  + `TurnOnDevice`：使用“Turn on the {DeviceName}”、“在 {DeviceName} 上切换”、“Turn the {DeviceName} on”等模式。
  + `GetDeviceStatus`：使用“Is the {DeviceName} on[?]”模式。
  + `TurnOffDevice`：使用“Turn the {DeviceName} off”、“Switch off the {DeviceName}”、“Turn off the {DeviceName}”等模式。

+ **训练模型**：通过使用每种不同类型的言语来训练模型，Azure AI 语言服务可以学习如何根据格式和标点正确地对意向进行分类。

### 使用预生成的实体组件

可以通过定义所需的所有意向和语句来创建自己的语言模型，但通常可以使用预生成组件来检测常见实体，例如数字、电子邮件、URL 或选择。

[有关 Azure AI 语言服务](https://learn.microsoft.com/zh-cn/azure/ai-services/language-service/conversational-language-understanding/prebuilt-component-reference) 可以检测的预生成实体的完整列表，请参阅受支持的预生成实体组件列表。

使用预生成组件，可以让 Azure AI 语言服务自动检测指定类型的实体，且不必使用该实体的示例来训练模型。

若要添加预生成组件，可以在项目中创建实体，然后选择该实体的“添加新预生成”以检测某些实体。

每个实体最多可以包含 5 个预生成组件。使用预生成模型元素可以显著减少开发对话语言理解解决方案所需的时间。

### 训练、测试、发布和查看对话语言理解模型

创建模型是一个迭代过程，包括以下活动：

![](img/da0d263481dc6ec1f9bfe153616245e8.png)

1. 训练模型以从示例言语中学习意向和实体。
2. 以交互式方式或使用带有已知标签的测试数据集测试模型
3. 将经过训练的模型部署到公共终结点以供客户端应用使用
4. 查看预测并迭代访问语句以训练模型

通过遵循此迭代方法，你可以根据用户输入随着时间的推移而改进语言模型，从而帮助开发反映用户使用自然语言指示其意向的方式的解决方案。

## 创建自定义文本分类解决方案

### 了解分类项目的类型

+ **自定义文本分类**：将标签（类）分配给文本文件。
