## 3、常见的指令类型

研究了市面上大量的Prompts，我发现基本可以分为三类:交互型(直接问答型)、模板型（形成一个框架)、引导型(逐步给出提问内容)

### (1)交互型

> 这种Prompt通常是根据应用场景来预设交互模式，比如头脑风暴、角色扮演、绘画咒语生成器家庭医生、私人教练等等。通常是先给AI预设一些"场景、身份、任务、目标、风格、能力、规则"以便于创建一个交互场景，然后进行提问交流，解决各种问题

交互型派Prompt示例示例:小红书种草文！

交互型Prompts非常简单使用，市面上有太多大多这种Prompts，但是使用效果不佳的原因是设定场景太发散，没有更细致

### (2)模板结构型

> 这种Prompts诵常是把各种方法论转化为标准模板，比如标题创作、文案创作、方案策划、各种信息处理等，这种Prompts通常效率非常高，只要训练的好，提升十倍以上效率都是很轻松的事情比如做方案策划，一个训练好的Prompts几分钟就可以出10套方案出来，吊打传统策划。

当然，这种Prompts需要一些专业有效的方法论和经验，去不断打磨和迭代至完美。

> 方法论:是作为一个领域的专家思想，比如你是专业写小红书种草文的，一个非常有经验的小红书编导，知道怎么爆文的结构要素去吸引用户，把这些思想和概念调教给AI这个就称之为方法论

成熟的"方法论”不会偏离大框架，且生成内容的稳定性可控

### (3)引导型

这种Prompts主动权在于使用者，通过一些思维模式来驾驭AI，AI就像是一个学完了人类所有的知识的应届毕业生，它需要一些思维模型，把这些知识有机的组织调用起来，生成更有价值的结果

## 4、指令框架

> 提示词工程师已经发展出了多种提示词框架，它们为 Prompt 的构建提供了一种高度概括和结构化的方法。可以将这些框架看作是构建有效提示词的方法论或"元结构"，所以的指令设计都可以套用这四个框架

### (1)ICIP框架

+   指令(Instruction):这是最基础且必须的部分。在任何项目或任务中，我们都需要明确的指示或指导。它告诉我们应该做什么。

+   背景信息(Context):背景信息可以帮助理解为什么要执行某项任务，以及这项任务在大环境下的位置。虽然它

是选填的，但在很多情况下，了解背景可以帮助我们更好地完成任务。

+   输入数据(Input Data):这是执行任务所需的信息或数据。有些任务可能需要特定的信息才能完成，而这就是

输入数据的角色。

+   输出指示器(Output Indicator):这是衡量任务完成的指标或标准。它可以告诉我们任务是否已经完成，以及完

成的如何。

### (2)BROKE框架(陈财猫)

+   背景(Background):在开始任何项目或任务之前，了解背景是非常重要的。背景可以告诉我们这个任务来自哪里，以及为什么它是重要的。

+   角色定义(Role):在任何团队或项目中，每个人都有自己的角色。明确每个人的角色可以确保任务能够高效地

完成。

+   目标设定(Objectives):这告诉我们要达到的目标或期望的结果是什么。设置明确的目标可以帮助团队保持方

向和动力。

+   关键成果展示(Key Result):这是衡量目标是否已达到的具体标准或指标。

+   持续的试验与优化(Evolve):这意味着我们总是在学习和改进，不断地试验新方法，并优化现有的方法。

### (3)CRISPE框架

+   上下文(Context):就像背景一样，上下文提供了任务的大环境，帮助我们理解任务的重要性和位置。

+   角色(Role):定义每个人在任务或项目中的职责和角色。

+   说明(Instruction):提供执行任务所需的具体指导。·主题(Subject):这是任务或项目的核心内容或焦点。

+   预设(Preset):这是事先设定或决定的条件、设置或参数，有助于任务的执行。

+   例外(Exception):这表示可能出现的偏差或特殊情况，以及如何处理它们。

希望这个简单的解释可以帮助小白更好地理解这三个框架!如果有任何其他问题，请随时提问。

### (4) LangGPT框架

+   Role:角色(定位角色，方便后续输出的内容更专业十聚焦)

+   author:作者名称（保护创作者权益)

+   version:版本(设置Prompt 版本号，记录迭代版本)

+   language:语言(设置语言信息，一般是中文/英文)

+   description:角色描述（—句话简要介绍角色设定，技能等)

+   Goals:目标（设置该指令想要实现的目标，建议一开始就确定好，确保后续的指令是围绕着目标进行，不会偏离原目标)

+   Constrains:约束条件，建议分点描述（把不想要/禁止做的信息内容填写在该处，确保输出的质量符合预期

+   Rules:规则，建议分点描述（可理解为:我们想要AI做的事情,也是确保输出的质量符合预期)

+   Skills:技能，建议分点描述（重要!!描述技能项,强化对应领域的信息权重)

+    Example:参考例子(这个建议设置，方便AI借鉴输出符合内容)

+   Workflows:工作流程1.流程a 2.流程b 3.流程c

+   Initialization:冷启动时的对白（强调需注意重点的机会+告诉用户关于该指令的信息)

## 5、指令应用原则

指令应用原则是设计指令的最基本的思想，这样能让AI更了解你的需求，生成的内容质星更高，这里用抖

> 指令应用原则是设计指令的最基本的思想，这样能让AI更了解你的需求，生成的内容质星更高，这里用抖音短视频文案举例

### (1）明确具体

指令需要尽可能明确并具体表达你的需求,避免模糊或抽象的描述

示例:请帮我创作一段抖音短视频文案,主题是中秋节全家团圆

### (2)提供背景

对任务的背景进行必要的解释,让AI理解语境

示例:这个文案是帮一个因工作外派而与家人分离的人准备的,想在中秋表达想念家人的心情

### (3)重点突出

指出最重要的需求或限制,不要包含非关键信息

示例:主要是表达思念之情,文案应该能触动人心

### (4)语气友好

使用礼貌并积极的措辞,有请有谢

示例:能否请您帮忙为我创作这样—段短视频文案,需要您发挥才能,谢谢!

### (5)排除歧义

避免可能引起不同解释的模糊表述

示例:这个文案的主人公是一名外派工作的年轻人

### (6)格式规范

针对生成的内容提供必要的长度、样式等格式要求

示例:时长控制在25秒左右,适合搭配温馨的视频镜头

### (7)提供示例

如果可能,给出任务的示例会更好地表达需求

示例:可以展现祝福全家团圆的文字卡片或剪影

### (8)验证理解

让AI重复或概述指令,确认它的理解是否正确

示例:能否请您重复一下我的文案创作需求

### (9)给予反馈

根据输出结果给AI正面或纠正性的反馈

示例:第一次的文案略显正式,能否用更亲情的语气表达思念之情

### (10)不断优化

观察结果,并持续调整指令来改善AI的表现

示例:根据反馈继续调整完善文案,直到表达出期待的感人效果

指令从来都不是一次就能设计好，输出的内容也不是一次就能达到我们的效果，我们需要逐步调试逐步分析，多一些耐心，其中分析和调优才是一条好的指令最重要的环节。至于为什么我设计的大多用结构化指令，因为在我的不断测试下结构化指令的效果最佳，当然还有各种各样的指令和很重要的指令细节需要大家去探索和测试，没有最好的指令模板，只有最适合自己的指令模板.
