## 为什么使用 GPU?

`大模型`（如 `GPT`、`BERT` 等）依赖 `GPU` 的核心原因在于其海量参数与计算需求与 `GPU` 的并行架构、高吞吐能力高度契合。以下是具体解析：

### 大模型的核心计算特征

- **参数量巨大**：如 `GPT-3` 有 1750 亿参数，训练需处理 PB 级数据。

- **矩阵运算密集**：神经网络每一层的权重更新涉及大规模矩阵乘法（如 `batch_size × hidden_dim` 矩阵运算）。

- **高度并行性**：同一批次（batch）内的样本计算互不依赖，可并行处理。

### GPU 如何满足大模型的需求？

#### 并行计算加速

**海量核心应对矩阵运算**：

`GPU` 的数千个 `CUDA` 核心（如 `NVIDIA A100` 有 6912 核心）可同时处理矩阵的多个元素，相比 `CPU`（几十核）提速数十至数百倍。

示例：单个矩阵乘法 `A×B` 在 `GPU` 上可分解为数千个子任务并行执行。

#### 高带宽显存（VRAM）

**大模型参数存储**：

训练时模型参数需全部加载到显存中（如 `GPT-3` 需数百 GB 显存）。`GPU` 显存（如 `HBM2e`）带宽可达 1.5 TB/s 以上，远超 `CPU` 内存（约 50 GB/s），避免数据搬运瓶颈。

#### 专用加速硬件

**`Tensor Core` 加速混合精度**：

`NVIDIA` 的 `Tensor Core` 支持 `FP16`/`FP8` 混合精度计算，提升训练速度（如 `A100` 的 `TFLOPS` 达 312 `TFLOPS`，远超 `CPU` 的 1-2 `TFLOPS`）。

案例：使用 `Tensor Core` 训练 `ResNet-50`，速度比纯 `FP32` 快 3 倍。

#### 软件生态支持

**`CUDA` 与深度学习框架深度集成**：

`PyTorch`、`TensorFlow` 等框架底层调用 `CUDA` 和 `cuDNN` 库，自动将计算任务映射到 `GPU`，开发者无需手动优化并行代码。

### 为什么不用 CPU？

- **核心数量少**：`CPU` 通常仅几十核，无法并行处理数十亿参数的计算。

- **内存带宽低**：`CPU` 内存带宽难以支撑大模型参数的高速存取。

- **计算效率低**：`CPU` 针对通用任务优化，缺乏针对矩阵运算的硬件加速单元。

对比实验：训练 `BERT` 模型，8 卡 `GPU` 集群需 1 天，同等 `CPU` 集群需数月。

### GPU 在大模型中的具体应用场景

#### 训练阶段

**分布式训练**：多 `GPU` 通过 `NVLINK` 或 `InfiniBand` 互联，并行处理数据（数据并行）或模型（模型并行）。

如：Meta 训练 `LLaMA-65B` 使用 2048 块 `A100` `GPU`。

**混合精度训练**：`Tensor Core` 支持 `FP16`/`FP32` 混合计算，节省显存并加速收敛。

#### 推理阶段

**实时响应需求**：`GPU` 的并行能力支持高并发推理（如 `ChatGPT` 同时服务百万用户）。

**量化与优化**：通过 `TensorRT` 等工具将模型转换为 `GPU` 专用格式，进一步提升推理速度。

### 未来挑战与替代方案

**显存容量限制**：

当前最大单卡显存（如 `H100` 94 GB）仍无法容纳万亿参数模型，需依赖模型并行与显存优化技术（如 `ZeRO`、梯度检查点）。

**替代硬件探索**：

- **`TPU`**：Google 专为矩阵运算设计的张量处理器，但生态封闭。
- **`Chiplet` 与存算一体**：未来可能突破显存带宽瓶颈。

## GPU 是什么

`GPU`（Graphics Processing Unit，图形处理器）是一种专门设计用于高效处理并行计算任务的处理器，尤其在图形渲染、科学计算和人工智能领域表现突出。以下是 `GPU` 的核心要点解析：

### GPU 与 CPU 的区别

- **`CPU`**（中央处理器）：

  具备少量高性能核心（通常 4-16 核），擅长处理复杂逻辑和顺序任务，如操作系统管理、程序控制等。

- **`GPU`**：

  拥有成百上千的小型核心（如 `NVIDIA` 的 `CUDA` 核心、`AMD` 的流处理器），专为并行计算设计，适合同时处理大量简单任务（如图形像素渲染、矩阵运算）。

### GPU 的核心优势：并行架构

- **`SIMD` 架构**：单指令多数据（SIMD）模式，同一指令同时作用于多个数据点，适合图形渲染（处理数百万像素/顶点）和科学计算（如大规模矩阵乘法）。

- **高吞吐量**：通过海量核心同时工作，`GPU` 在数据并行任务中速度远超 `CPU`，例如训练神经网络时性能可提升数十倍。

### GPU 的关键组件

- **流处理器/`CUDA` 核心**：执行计算任务的基本单元，数量从数百到上万不等。

- **显存（`VRAM`）**：高带宽内存（如 `GDDR6`/`HBM`），专为快速存取大规模数据设计，显存容量直接影响可处理的数据量。

- **专用加速单元**：如 `NVIDIA` 的 `Tensor Core`（加速 AI 训练）和 `RT Core`（光线追踪），`AMD` 的 `Infinity Cache`（提升数据访问效率）。

### GPU 的应用场景

- **图形渲染**：游戏、影视特效、3D 建模（如 `DirectX`、`OpenGL`/`Vulkan` API）。

- **科学计算**：气候模拟、分子动力学（`CUDA`/`OpenCL` 编程）。

- **人工智能**：深度学习训练与推理（`TensorFlow`/`PyTorch` 框架依赖 `GPU` 加速）。

- **加密货币挖矿**：并行计算哈希函数（现多被 `ASIC` 矿机取代）。

- **数据中心与云计算**：提供大规模算力支持（如 `NVIDIA A100`、`AMD Instinct` 系列）。

### 主流 GPU 厂商与技术

- **`NVIDIA`**：

  - **`CUDA` 生态**：行业标准并行计算平台，支持深度学习库（如 `cuDNN`）。
  - 架构演进：从 `Fermi` 到 `Ampere`，集成 `Tensor Core` 和光线追踪技术。

- **`AMD`**：

  - **`RDNA` 架构**：专注游戏显卡（如 `Radeon RX` 系列）。
  - **`CDNA` 架构**：面向计算（如 `MI` 系列加速器），支持 `ROCm` 开源生态。

- **其他**：`Intel` 推出 `Xe` 架构（如 `Arc` 显卡），进军独立 `GPU` 市场。

### GPU 编程与挑战

- **编程模型**：需将任务分解为并行线程（如 `CUDA` 的线程块/网格），使用特定语言（`CUDA C++`、`OpenCL`）或框架（`PyTorch` 自动优化）。

- **瓶颈与优化**：

  - **数据传输**：`CPU` 与 `GPU` 间通过 `PCIe` 总线交换数据，需减少传输延迟。
  - **功耗与散热**：高性能 `GPU` 功耗可达数百瓦，需强散热方案。
  - **适用性**：非并行任务（如串行逻辑）难以受益于 `GPU` 加速。

### 未来趋势

- **`AI` 与异构计算**：`GPU` 与 `CPU`、`FPGA` 等协同工作，优化 `AI` 推理与边缘计算。

- **光追与实时渲染**：游戏/影视迈向电影级画质（如虚幻引擎 5）。

- **量子计算辅助**：`GPU` 加速量子模拟，推动材料科学、药物研发。

### 价格波动与市场因素

- **供需失衡**：`AI` 大模型热潮导致 `GPU` 需求激增，英伟达 `A100`/`H100` 等高端型号供应短缺，价格涨幅达 50%-200%。

- **出口管制**：美国对华禁售 `A100`/`H100`，导致中国特供版 `A800`/`H800` 价格水涨船高。

- **国产替代**：国产 `GPU` 如摩尔线程 `S80` 价格稳定，但性能尚无法完全替代英伟达高端型号。
