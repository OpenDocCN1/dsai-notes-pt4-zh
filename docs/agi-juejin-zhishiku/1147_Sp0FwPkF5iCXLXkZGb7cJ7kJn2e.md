Hello，我是 JioNLP。

之前一篇博客，我提出的一个模型评测的一个简单算法，我给这个评测算法起了个名字 MELLM （Mutual Evaluation of Large Language Model），读作 `\melm`。

MELLM 原理链接 ： 如何优雅地自动评测 LLM 模型质量

这篇文章，我来介绍一下，我是如何做实验验证的。最终的实验结论就是： MELLM 能够比较好地测评出 LLM 的优劣。

## 回顾一下算法原理

MELLM 算法原理非常简单，其基本思想，就是让多个模型互相之间进行评价和打分，画个操作流程图就是，四个模型互相给出评价分数，当然，是针对每一道题目都给出分数的，图中只是给了一个总分：

![](img/94b8030eab3ff241cd3f0207626d79ea.png)

然后利用 EM 算法反复迭代多个模型的结果，最终就能得到一个经过拟合优化的结果，其结果就是最终的模型质量评价结果。

### 评分

其实评分的过程挺有意思，可以发现每一个模型各自的特点。我简要找几点说说：

+ 1、每个模型的个性很不一样

有的模型可能是被训练人员严格要求不能回答错误的信息，导致了回答时尽可能地避免出错，不论答题模型的答案正确与否，评价模型都会给出一个折衷的分数，既不高分、也不低分，如果题目分值为 1 分的话，往往给出 0.5 分的打分：

```
回答质量：0.5分
解释：答题者的回答在大部分方面都是正确的，包括理解问题和解答过程。
然而，他们在处理积分问题时缺乏一些关键细节，比如他们错误地假设了被积函数是不可积的，而没有明确说明为什么可以直接对函数进行积分。
此外，他们的回答结构清晰易懂，显示了良好的逻辑和组织性。因此，我给予0.5分的评分
```

相反，有的模型，比如 `gpt4` 就挺敢给分的，对就给满分，错就给 0 分。所以，导致了 `gpt4` 给所有模型的打分结果，好的模型分数很高，差的模型分数很低。

![](img/465805dfb6b8fe82e374267fc83fa5f9.png)

+ 2、有些模型给出的打分缺少上下文依赖

按理来讲，打分模型在给出分数的时候，根据 `LLM` 的特性，应该简要叙述一下打分理由，比如下面是打分合理的例子：

```
1. 老妪这个词是汉语中的一个词汇，用来指代年龄较大的妇女。这个解释是正确的，因此可以给满分 4 分。
2. 文章中并没有明确提到少女每个月可以赚多少钱，只提到她的住宿费用占据了她半个月的工资，没有提及她现在能赚多少钱。这个回答也是正确的，因为文章确实没有明确提到少女的收入情况。
3. 村里人认为少女是小人精，可能是因为她来自外地，对她的出身和动机存在怀疑，怀疑她可能会对老妪产生不良的影响。这反映出社会的猜疑和偏见精神面貌。对于少女和老妪的关系，应该理解为两者之间是基于互相帮助和关心的友情，而非别有用心。然而，由于社会的误解和误判，这段友情并未得到应有的赞扬。这个回答也是正确的，它对村里人的猜疑和偏见进行了合理的解释，同时也对少女和老妪的关系进行了正确的理解。
4. “老妪走了，没多久，少女也走了”这句话的意思是老妪去世之后，没有多久，少女也离开了这个村子，可能是因为遭受村里其他人的误解和排斥，已无法在此处居住。这个解释也是正确的。

综上所述，该回答者的答案都是正确的，没有错误或不足之处。
因此，我建议给该回答者满分 4 分。
```

然而，有些模型给分时则会直接说出分数，没有分析过程，这些模型里，要么能力非常强，如 `GPT4`，要么特别弱，如 `Xmodel1`，这些模型会直接告诉我：

```
4分
```

+ 3、有些模型的回答前后矛盾，缺少逻辑

有些模型会给出打分的理由和情况，不过这个过程缺乏逻辑，比如下面这一段：

![](img/b5dccdb8721cfa9dcccdd3d0308f3109.png)

明明分析过程对答案完全肯定，但是打分时却给了 0.8 分，没有给 1 分。这就有点不合理了。

甚至有的模型会给出一个非常不合理的分数，比如题目满分2分，模型却打出了 64 分这种奇怪的分数，这显然是训练不合理。

![](img/d4a7588d951b0a8d1440782b38acb302.png)

+ 4、有些模型会直接拒绝回答某类问题

题目中，有一个题目带有敏感词，可以明显感觉到，有几个模型会直接拒绝回答问题，拒绝给这种问题打分。这就非常离谱了。大模型其实按理来说不应该这样拿一个字典强行匹配的。

当然，有人会问，这么长的句子，里面还有数字，我是怎么把分数准确抽取出来的？？

## 评测结果

终于到了评测结果环节：

以下就是模型拟合的结果：

![](img/fc693f1031474ece2a47679aa5ddc32a.png)

和上面 `GPT4` 的打分相比，优劣关系基本上是匹配的，这也说明了 MELLM 模型的有效性。

需要说的有以下几点：

+ 0、先解释一下图表分数

`gpt4` 模型的打分是经过归一化的，满分为 100，并按得分高低排序的，`gpt4` 得分 89.795。另外，`gpt-4` 给出的分数分差比较大，好模型分数高，差模型分就很低，到了不及格的程度。这主要是因为 `gpt-4` 模型敢给分数。

而算法拟合的结果则是未归一化的分数，也就是说上面题目总分是 140 分，`SCORE` 是 各个模型的真实平均得分，而 `WEIGHT` 则是每个模型在打分做平均时贡献的权重。可以看出，`gpt-4` 贡献的权重最高，也说明 `gpt-4` 能够更好地评价其它模型。

此外，算法拟合的分数，各个模型的得分差距似乎不是特别大，主要是因为，这个分数经过了加权平均，本身就导致了评分方差变小，各个模型之间差距被缩小了。不过，重点应该看各个模型得分之前的差距，以及它们的先后次序。这么看，`gpt-4` 的得分还是显著高的。

+ 1、国产大模型已经初步达到了 `chatgpt3.5` 的水平

从评测结果来看，百度的文心一言的得分 已经略微高于 `chatgpt3.5`，阿里的千问也逐步逼近 `chatgpt3.5`。早在半年多前，国内的模型距离 `chatgpt` 还是差很远的，目前已经逐步追上了。

不过，这些模型距离 `gpt4` 还有一段距离。

实际上，一个向我实验提供 `api` 的朋友也告诉我，人们调用大模型的用量基本是如下图的样子：

![](img/ce7ecca1bb7e381a140450cb452cc9fc.png)

不过，根据评测结果，未来应该会有很多国内模型来替代 `gpt3.5` 的调用了。

+ 2、国产大模型后劲最足的还是大厂

市面上，`7b`、`13b`、`14b`等规模的模型屡见不鲜，我一直对这类小型大模型持负面态度的，不过 阿里的通义千问 `qwen_14b` 取得的分数其实还不错，相对于其模型规模。

而同样规模的开源模型如 `baichuan`、`llama`、`Xmodel1` 等等，则得分还是挺低的。

这也说明了一个问题：大厂经过多年发展，数据积累还是非常充分的，这是大模型能取得快速进步的基础。 相反，小公司往往由于缺乏数据积累，在模型制作后劲上不足。

+ 3、直接拿 `GPT4` 评不就完了吗？为什么还要互相评？

我想，肯定有小伙伴提出这种质疑。目前看，是的，`GPT4` 的打分结果，和我用互评算法拟合的结果是基本一致的。也确认，目前从结果上看，`gpt4` 评价一次要比反复去互相调用 `api` 来评价省时省力。

不过，模型都是在进步的，连 altman 自己也承认，大模型实际上没有非常严格的门槛和壁垒，随着时间推移，大家的水平都会逐步提升，就像现在国内大厂的模型水平也逐渐追平 `chatgpt3.5` 一样。

我想，总有一天，`gpt4` 会失去目前一极的地位的，到时候，群魔乱舞的时候，利用互评算法 MELLM 来评测模型的时候就非常有必要了。

## 总结

OK， MELLM 算法的实验结束了，实际上，评测算法，再也不用人力了，准备好测试题集，然后交给各个模型的 `API` 即可自动完成。

这个算法的拟合实现将会纳入 `jionlp` 工具包中，可以直接调用(当然现在还有点bug，不能直接运行，感兴趣可以直接进去看源码)

```
import jionlp as jio

mellm = jio.mellm.MELLM(llm_names, llm_names, max_json)
mellm.run(grading_matrix, llm_error_count)
```

另外，我想， MELLM 算法评测，也就是，让模型来评价模型，实际上，和 RLHF 算法思想极其地相似， 本质都是一种自动反馈。
