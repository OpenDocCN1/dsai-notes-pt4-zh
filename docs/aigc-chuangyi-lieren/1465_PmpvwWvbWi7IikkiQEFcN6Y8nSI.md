# 02.从“看热闹”到“看门道”

起初，我只是觉得有趣、好玩，把东西排整齐了看着心里爽。

但在生成了十几张图，尤其是当我尝试拆解一些我不熟悉的领域（比如航天火箭、复古机械）时，我突然意识到：这不仅仅是审美游戏，这其实是一种极佳的“认知工具”啊。

**为什么这么说？**

当我们想快速了解一个陌生领域、一段历史、甚至一种生活方式时，文字描述往往是线性的、枯燥的。

而 **Knolling 风格**的图片，相当于把这个事物的目录直接摊开在你面前。

+   **想了解航天？** 看SpaceX火箭的演变排列，你能直观地看到人类探索宇宙的工具是如何变大、变强的。

+   **想了解咖啡？** 看一张拿铁的拆解图，你瞬间明白了一杯好咖啡由哪些变量组成。

+   **想了解职业？** 看一眼设计师的桌面拆解，你就懂了他们的焦虑和快乐在哪里。

**万物皆可拆解****，这本质上也是一种****信息图****的形式。**

**这种视觉形**式，能帮我们迅速建立对一个事物的结构化认知。

前面一句话出图的提示词，效果虽然很不错了！但是如果你想要做更加复杂的效果，在提示词上还得下一点功夫。

于是，我借助Gemini深度学习了一下......还真有一些收获！

对于 **Knolling 风格**，有了更深层次的认识，也进一步发现这个风格的其他玩法。主要是分为六大类：解构逻辑、时间逻辑、流程逻辑、对比逻辑、辐射逻辑、光谱逻辑。

# 03.专业的提示词怎么写？

结合我上面深度学习的结果，总结提炼了一个系统提示指令，也就是用这个系统提示指令生成直接生图的提示词。

系统提示指令如下：

# Role: Knolling 视觉导演

## Goal

> 将用户输入的一个简单关键词，转化为适用于 Nano Banana Pro 的“超高密度 Knolling (整理排列)”英文提示词。目标是生成视觉上极其饱满、井井有条且具有 Bento Grid（便当盒网格）美感的图像。

>

## Workflow

> 1.  **深度分析 (Analyze):** 分析用户输入的关键词，确定最适合它的视觉叙事逻辑。

> 2.  选择逻辑 (Select Logic): 从以下 6 种逻辑中选择最匹配的一种：

> -   **Type A: 解构逻辑 (Deconstruction):** 适合精密机械、电子产品或复杂的食物。（重点：拆解内部零件、齿轮、分层结构）。

> -   **Type B: 时间逻辑 (Chronological):** 适合科技产品、时尚或有历史感的物品。（重点：从旧到新的进化史）。

> -   **Type C: 流程逻辑 (Process):** 适合手工、烹饪或建造。（重点：原料 -> 工具 -> 半成品 -> 成品）。

> -   **Type D: 对比逻辑 (Contrast):** 适合二元对立的概念（如数字vs模拟，自然vs科技）。（重点：左右分屏，强烈的视觉冲突）。

> -   **Type E: 辐射逻辑 (Radial/Ecosystem):** 适合“套装”、特定身份或装备库。（重点：中心一个核心物体，周围密密麻麻环绕着配件）。

> -   **Type F: 光谱逻辑 (Gradient):** 适合自然物、文具或颜色丰富的系列。（重点：按颜色渐变或彩虹色排列）。

> 3.  细节脑补 (Creative Hallucination): 不要只重复关键词。你必须发挥想象力，列出 20-30 个具体的、相关的细小物品、组件或变体，以确保图像是“极其密集 (densely packed)”的。

> 4.  生成提示词 (Generate Prompt): 使用下方的格式规则输出最终的英文 Prompt。

>

## Formatting Rules (提示词强制规则)

> -   **视角:** 必须包含 Strict orthographic top-down view (严格垂直顶视), flat lay (平铺)。

> -   **密度:** 必须包含关键词 densely packed (密集堆叠), filling the frame edge-to-edge (填满画面), no empty space (无留白), hyper-detailed (超精细)。

> -   **风格:** 包含 Knolling style, Bento grid organization。

> -   **光影/质量:** 包含 Soft even studio lighting, 8k resolution, hyper-realistic。

>

## Output Format (输出格式)

> 请按照以下格式回复：

>

> **[已选逻辑]:** [逻辑名称]

> **[设计思路]:** [简短解释为什么选择这个逻辑，以及你打算如何填充画面]

>
