### 再进化 coze 联动飞书多维表格

> 第二个工作流再进化，coze 结合飞书多维表格。coze 执行任务，飞书做管理记录。

> 我本意是希望直接在飞书多维表格列单元格输入文章链接就可以调动 coze 工作流执行任务，直接生成到👸号草稿箱的。

> 但无奈，飞书多维表格输入链接到单元格后居然是字典形式，无法通过调用字段捷径【coze 工作流调用】直接将链接传入到 coze 工作流的开始节点，还需要转化为 `string`，但是这个转化需要用 coze 工作流来转化，嗯陷入了死循环。

> 如果飞书多维表格对于输入的链接能直接是 `string` 格式那就好了，或者能在飞书表格快速转化为 coze 工作流开始节点能接受的样式。

> 所以，只能退而求其次，将输入到 coze 链接，上传到飞书表格，并把原标题、原正文都上传上来。

> 呼，把我们刚刚一次生成 `N` 篇文章的工作流，复制一个副本，我们在新的副本里面增加节点：这个节点在 2 号员工节点和结束节点之间的任何地方添加都可以。

> 我们选取在 2 号和 3 号员工之间增加一个代码节点，之后再增加一个 `add_records` 节点。

> 代码节点的作用：将 `LinkReaderPlugin` 插件读取出来的标题、内容和开始节点输入的链接，转化为符合 `add_records` 插件能接受+处理的样式。具体可看详情文档：`https://www.coze.cn/store/plugin/7395043460165779483`

> `add_records` 的作用：在多维表格数据表中新增多条记录，即把我们要的链接、标题、正文、统计的正文字数都上传到飞书多为表格。

> 代码节点的输入变量

> `title`：输入 `LinkReaderPlugin`（即 2 号员工）读取出来的文章标题

> `content`：输入 `LinkReaderPlugin`（即 2 号员工）读取出来的文章标题的正文

> `linkURL`：输入开始节点的链接

> 输出变量命名为 `records`，变量类型为 `Array<String>`，然后把其他变量都删掉。

> 如果不知道代码是什么意思，不知道节点是什么意思，不知道插件是什么意思，那就万事问 AI。

```
import _ from 'lodash';

async function main({ params }: Args): Promise<Output> {
    // 从上游params中获取对应的变量（与图1的变量名完全一致）
    const { title, content, linkURL } = params;
    
    // 统计content的字数（确保是整数类型）
    const wordcount = content.length; // length本身是整数，直接赋值
    
    // 处理linkURL为空的兜底情况（避免字段缺失）
    const finalLinkURL = linkURL || "无链接";
    
    // 构造飞书表格对应的字段（键名与飞书列名完全一致）
    const records = [{
        fields: {
            "title": title,        // 对应飞书表格title列
            "content": content,    // 对应飞书表格content列
            "linkURL": finalLinkURL, // 对应飞书表格linkURL列
            "wordcount": wordcount  // 对应飞书表格wordcount列（整数类型）
        }
    }].map(JSON.stringify); // 保持Coze要求的JSON字符串格式
    
    return { records };
}
```
