
然后，服务器用产生的数据对被欺骗的地址进行响应。

目标的IP地址收到响应后，周围的网络基础设施就会被大量的流量所淹没，从而导致拒绝服务。

解决：减少支持 `monlist` 的 `NTP Server`，或者认证 `src IP`，防止 `spoofed packet` 离开子网。

![](img/868f6f9d1aad5045f69ea412de6cff21.png)

#### 2.2.2.4 Memcached Attack

> Memcached攻击的操作与所有DDoS放大攻击类似，如NTP放大和DNS放大。该攻击的工作原理是向一个易受攻击的服务器发送欺骗性请求，然后用比初始请求更大的数据量进行响应，放大流量。

Memcached服务器是一种用于缓存数据的开源软件，可用于提高Web应用程序的性能和响应速度。它通常用于缓存数据库查询、API调用和页面渲染等数据，以减少应用程序对数据库和其他后端资源的请求。

`Memcached` 服务器提供通用的缓存服务以提高网站访问速率。`Memcached` 服务使用 `UDP`，因此发送前并不需要握手（前面几个也一样）。攻击者预先加载一些信息，然后伪装成 `victim` 向 `server` 请求。

一个memcached攻击发生在4个步骤中。

+ 攻击者在暴露的memcached服务器上植入大量的有效载荷的数据。

+ 接下来，攻击者用目标受害者的IP地址伪造一个`HTTP GET`请求。

+ 收到请求的易受攻击的memcached服务器，试图通过响应来提供帮助，向目标发送一个大的响应。

+ 目标服务器或其周围的基础设施无法处理从memcached服务器发送的大量数据，导致合法请求过载和拒绝服务。

解决：禁用 `UDP` 或者屏蔽 `Memcached server` 或者认证 `IP` 或者对 `Memcached server` 发送 `flush_all` 命令。

#### 2.2.2.5 SSDP Attack

`Simple Service Discovery Protocol`（简单服务发现协议）是 `Universal Plug and Play`（`UPnP`）即插即用设备技术的基础，大意是即插即用设备会维护一个列表。

`SSDP`（`Simple Service Discovery Protocol`）攻击是一种利用`UPnP`（`Universal Plug and Play`）协议的漏洞进行攻击的方式。`UPnP`是一种网络协议，它允许设备自动发现并配置其他设备，从而实现设备的自动化交互。`SSDP`是`UPnP`协议中的一个重要组成部分，它通过`UDP`广播的方式，在网络上发现和识别其他设备。

1. 攻击者进行扫描，寻找可用作放大因素的即插即用的设备。

2. 当攻击者发现联网设备时，他们创建一个所有响应设备的列表。

3. 攻击者用目标受害者的欺骗性`IP`地址创建一个`UDP`数据包。

4. 然后，攻击者使用僵尸网络向每个即插即用设备发送一个欺骗性的发现包，要求通过设置某些标志，特别是`ssdp:rootdevice`或`ssdp:all`，获得尽可能多的数据。

攻击者可以利用`UPnP`协议开放的`SSDP`端口（一般是`UDP 1900`端口），向网络中发送大量的`SSDP`请求，从而产生大量的网络流量，导致目标系统的瘫痪。`SSDP`攻击通常用于分布式拒绝服务（`DDoS`）攻击，攻击者可以通过控制大量的僵尸设备（如`IoT`设备）来发动攻击。

攻击者伪造成 `victim` 的地址，发送 `ssdp:rootdevice`和 `ssdp:all` 等请求以获得全部设备列表。

解决：关闭 `UDP` 端口 `1900`。

为了防范`SSDP`攻击，管理员可以通过限制`UPnP`协议的使用、配置防火墙规则来阻止不必要的`UDP`广播、升级设备的固件以修补已知的漏洞等安全措施来加强系统的安全性。

#### 2.2.3.0 SSL/TLS Handshake

![](img/8c5479ed3eeaa33218b45a7cfc03eab1.png)

`SSL`（`Secure Sockets Layer`）和`TLS`（`Transport Layer Security`）是一种用于保护网络通信安全的协议，用于对网络通信中的数据进行加密和解密操作。`SSL`是`TLS`的前身，现在已经逐渐被`TLS`所取代，但是两者在实现上非常类似。

`SSL/TLS`协议主要通过使用公开密钥加密（`Public Key Encryption`）技术和对称密钥加密（`Symmetric Key Encryption`）技术来保护数据的机密性和完整性。在`SSL/TLS`握手过程中，客户端和服务器会进行一系列的加密解密操作，用于建立安全通信的密钥，从而保护数据的安全。

在`SSL/TLS`握手过程中，客户端会向服务器发送一个`Client Hello`消息，包括支持的加密套件、随机数等信息。服务器会回应一个`Server Hello`消息，包括选定的加密套件、随机数等信息。在此基础上，客户端和服务器会进行一系列的握手操作，包括发送和接收证书、生成对称密钥、交换加密密钥等步骤。在这个过程中，加密解密操作会被频繁使用，用于对数据进行加密和解密，从而保证数据在传输过程中的机密性和完整性。

需要进行加密解密操作的原因在于，网络通信中的数据很容易被黑客截取和窃取，为了保护数据的机密性和完整性，需要对数据进行加密。而为了能够解密数据，需要使用密钥进行解密操作。因此，在`SSL/TLS`协议中，客户端和服务器需要进行一系列的加密解密操作，用于保护数据的安全。

![](img/97b1f0808426564af5aad6ac2e1d9147.png)

> 对称加密算法通常比非对称加密算法更快。

> `RSA`是非对称加密

在`SSL/TLS`握手过程中，客户端和服务器需要进行多次通信，进行加密和解密等操作，这些操作会消耗服务器的资源。攻击者可以通过控制大量的僵尸设备（如`IoT`设备）来发动攻击，从而形成分布式的攻击效果，使目标系统无法正常运作。

为了防范`SSL/TLS flood`攻击，管理员可以采取多种措施，例如限制来自同一`IP`地址的请求、使用防火墙来过滤恶意的`SSL/TLS`请求、使用`SSL/TLS`加速器、升级`SSL/TLS`协议的版本、使用负载均衡技术等。此外，还可以对系统进行优化，如通过增加`CPU`、`内存`、`带宽`等硬件资源、优化操作系统内核参数等来提高系统的抗压能力。

`HTTP Flood`攻击通常利用了`HTTP`协议中的漏洞，例如`HTTP`请求中的虚假信息、`HTTP`请求中的合法信息超过服务器的处理能力等。攻击者可以通过控制大量的僵尸设备（如`IoT`设备）来发动攻击，从而形成分布式的攻击效果，使目标系统无法正常运作。

#### 2.2.3.2 Fragmented HTTP Flood

![](img/5f2d135abc2ec1e2b5229090a893ef79.png)

攻击者将`HTTP`请求分解成多个小分段的数据包，并通过不同的源`IP`地址发送给目标服务器，从而使服务器无法正常处理请求。

攻击者使用的`HTTP`请求通常会包含大量的`HTTP`头信息和无效数据，这会占用服务器的资源并降低服务器的性能。而将`HTTP`请求分解成多个小分段的数据包，则可以使服务器需要更多的资源来处理这些小数据包，并且更难以检测和过滤。

为了防范`Fragmented HTTP Flood`攻击，可以采取多种安全措施，如使用反向代理服务器、配置防火墙规则、使用网络流量分析工具等。此外，还可以加强服务器的抗压能力，例如增加带宽、升级服务器硬件、使用负载均衡技术等。

#### 2.2.3.3 Payment DDoS

`Payment DDoS`是一种网络攻击方式，攻击者通过向在线支付系统发送大量的虚假支付请求来消耗系统资源和造成拒绝服务。`Payment DDoS`攻击通常会导致在线支付系统崩溃，无法正常处理合法用户的支付请求，从而给商家和消费者带来不必要的经济损失。

在`Payment DDoS`攻击中，攻击者通常使用大量的僵尸设备（如感染的计算机、路由器、`IoT`设备等）来模拟合法用户，发送虚假的支付请求。这些请求可能会包含大量的无效信息，例如假的信用卡信息、错误的付款金额、无效的付款方式等。由于在线支付系统需要对每个请求进行验证和处理，因此大量的虚假请求会占用系统的资源并降低系统的性能，最终导致系统的崩溃。

为了防范`Payment DDoS`攻击，商家和支付系统可以采取多种安全措施，例如实施反欺诈技术、使用网络流量分析工具、配置防火墙规则等。此外，商家和支付系统还应该加强自身的安全防护能力，例如采用多因素认证、加强用户身份验证、监控异常交易等措施，以提高支付系统的安全性和可靠性。

`SDN CrossPath Attack`（`SDN`跨路径攻击）是一种网络安全攻击方式，针对软件定义网络（`SDN`）中的跨路径流规则进行攻击。`SDN`是一种基于控制平面（`Control Plane`）和数据平面（`Data Plane`）分离的网络架构，它允许网络管理员通过控制器来管理和控制整个网络。在`SDN`中，跨路径流规则用于在不同的交换机之间实现数据流的路由，攻击者可以利用跨路径流规则的特性进行攻击。

> 发现某个`link`是给`router`和`controller`用的，就可以制造大规模的数据传输，瘫痪

为了防范`SDN CrossPath Attack`，可以采取多种安全措施，例如对`SDN`控制器进行安全配置、对流规则进行验证和过滤、使用网络流量分析工具等。此外，还可以使用入侵检测系统（`IDS`）和入侵防御系统（`IPS`）等安全技术来监测和阻止`SDN CrossPath Attack`。

### 2.3.1 Ingress Filtering

`Ingress Filtering`（入口过滤）是一种网络安全技术，用于在网络入口处对数据包进行过滤和检查，以防止来自非法来源的攻击流量进入网络。`Ingress Filtering`通常是一种针对`IP`地址欺骗（`IP Spoofing`）攻击的一种防御措施。

`IP`地址欺骗攻击是一种网络攻击方式，攻击者伪造源`IP`地址发送攻击流量，以模拟合法的网络流量。这种攻击方式可以伪装攻击者的身份，避免被网络防御系统检测和追踪。`Ingress Filtering`技术通过检查网络流量的源`IP`地址和目标`IP`地址，对非法的源`IP`地址进行阻止和过滤，从而防止攻击者通过`IP`地址欺骗攻击进入网络。

`Ingress Filtering`技术通常在网络边界处（如路由器、防火墙等）部署，对网络流量进行过滤和检查。在网络流量进入网络之前，`Ingress Filtering`会检查源`IP`地址是否合法，如果源`IP`地址是非法的，则会拒绝流量，并向网络管理员发出警告。

需要注意的是，`Ingress Filtering`虽然可以防止`IP`地址欺骗攻击，但它并不能完全解决网络安全问题。攻击者可以使用其他技术来规避`Ingress Filtering`的检查，因此需要采用多种安全技术和措施来提高网络的安全性和可靠性。

`IP Traceback`

`IP`追踪是一种技术，可用于确定网络攻击的源头。它允许网络管理员在攻击发生时追踪攻击者的位置，并采取必要的措施来阻止攻击。

`IP`追踪的基本原理是在数据包中插入特殊标识符，该标识符将在传输过程中一直保留，并记录经过每个路由器的信息。当攻击发生时，管理员可以使用这些信息来确定攻击者的位置。

有几种不同的`IP`追踪技术可供选择。一种常见的方法是使用源地址验证（`SAV`）技术，该技术验证传入数据包的源地址，并跟踪数据包的路径。另一种方法是使用跳数限制（`TTL`）技术，该技术限制数据包在网络中传输的最大跳数，并记录每个路由器的信息。还有一种称为`Packet Marking`的技术，它可以在数据包中插入标识符并记录传输路径

Limitations: requires space in packet; path can be long; no extra fields in current IP format (changes to packet format too much to expect)

Sample and Merge: store one link in each packet; router probabilistically stores own address; fixed space regardless of path length
