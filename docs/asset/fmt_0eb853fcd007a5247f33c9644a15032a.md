# 论文

### 使用大型语言模型混合进行零样本机器生成文本检测

贡献人：

链接：`https://arxiv.org/abs/2409.07615`

大型语言模型（`Large Language Models`，`LLMs`）的广泛传播，这些模型经过大规模训练，具备强大的文本生成能力，大幅增加了生成式AI技术带来的威胁，因为它降低了生产有害、毒性、伪造或篡改内容的成本。为此，已经提出了各种自动区分人工生成文本与人类书写文本的方法，通常将问题框定为分类问题。大多数方法通过精心选择的检测器`LLM`来评估输入文档，假设低困惑度（`perplexity`）得分可靠地标识机器生成的内容。然而，使用单一检测器可能导致性能的脆弱性，因此我们考虑使用多个检测器，并推导出一种新的、理论上有依据的方法来结合它们各自的优势。我们的实验使用了各种生成器`LLM`，表明我们的方法有效地提高了检测的鲁棒性。

### 通过减少`Embedding`变异性实现稳定的语言模型预训练

贡献人：

链接：`https://arxiv.org/abs/2409.07787`

稳定的预训练对于实现性能更优的语言模型至关重要。然而，由于显著的计算成本，无法通过在每一步计算梯度方差来跟踪预训练的稳定性。鉴于浅层网络更容易出现梯度爆炸（见第2.2节），我们探讨了`Token Embedding Variability`（`TEV`）作为一种简单且高效的代理方法，用于评估具有预层归一化的语言模型的预训练稳定性。此外，我们提出了`Multi-head Low-Rank Attention`（`MLRA`）架构，通过限制输出嵌入方差的指数增长，从而缓解这种不稳定性，防止梯度爆炸（见第3.2节）。在`GPT-2`模型上应用`MLRA`的实验证明，尤其是在更深层的模型中，稳定性得到了提高，困惑度（`perplexity`）降低。

### OneEdit：一种神经-符号协作知识编辑系统

贡献人：

链接：`https://arxiv.org/abs/2409.07497`

自人工智能诞生以来，知识表示一直是其核心目标。符号知识图谱（`Knowledge Graphs`，`KGs`）和神经大型语言模型（`Large Language Models`，`LLMs`）都可以用于表示知识。`KGs` 提供了高度准确和明确的知识表示，但在可扩展性方面存在问题；而`LLMs`则提供了广泛的知识覆盖，但训练成本显著，并且在精确和可靠的知识操作方面存在困难。为此，我们引入了`OneEdit`，一种用于协作知识编辑的神经-符号原型系统，利用自然语言实现易用的知识管理，结合`KG`和`LLM`的优势。`OneEdit`由三个模块组成：1. 解释器（`Interpreter`）：负责与用户进行自然语言交互；2.控制器（`Controller`）：管理来自不同用户的编辑请求，利用`KG`进行回滚以处理知识冲突，并防止有害知识攻击；3.编辑器（`Editor`）：利用控制器的知识对`KG`和`LLM`进行编辑。我们在两个新的`KG`数据集上进行了实验，结果表明，`OneEdit`能够实现优越的性能。

### 重新构想线性探测：迁移学习中的`Kolmogorov-Arnold`网络

贡献人：

链接：`https://arxiv.org/abs/2409.07763`

本文介绍了`Kolmogorov-Arnold Networks`（`KAN`），作为迁移学习中传统线性探测方法的增强。线性探测通常应用于预训练模型的最后一层，其局限在于无法对数据中的复杂关系进行建模。为了解决这一问题，我们提出用`KAN`替代线性探测层，`KAN`利用基于样条的表示来近似复杂函数。在本研究中，我们将`KAN`与在`ImageNet`上预训练的`ResNet-50`模型集成，并在`CIFAR-10`数据集上评估其性能。我们进行了系统的超参数搜索，重点优化`KAN`的灵活性和准确性，主要关注网格大小和样条度数（`k`）。结果表明，`KAN`在多种配置下持续优于传统线性探测，实现了准确性和泛化能力的显著提升。这些发现表明，`KAN`在迁移学习中提供了比传统线性探测技术更强大和适应性更高的替代方案。

### 衡量神经架构训练效率的框架

贡献人：

链接：`https://arxiv.org/abs/2409.07925`

在神经网络系统开发中，衡量效率是一个开放的研究问题。本文提出了一个实验框架，用于衡量神经架构的训练效率。为了展示我们的方法，我们分析了卷积神经网络（`Convolutional Neural Networks`，`CNNs`）及其贝叶斯等效模型（`Bayesian Convolutional Neural Networks`，`BCNNs`）在`MNIST`和`CIFAR-10`任务上的训练效率。我们的结果显示，随着训练的进行，训练效率呈下降趋势，并且在给定的神经模型和学习任务下，不同的停止标准会导致训练效率的变化。我们还发现，训练停止标准、训练效率、模型规模之间存在非线性关系。

![](img/3e9395670eb839b9dc46be0322289f67.png)

此外，我们展示了过度训练在衡量神经架构训练效率时可能产生的混杂效应。关于不同架构之间的相对训练效率，我们的结果表明，在这两个数据集上，`CNNs`的训练效率优于`BCNNs`。更一般地说，随着学习任务变得更加复杂，不同架构之间的训练效率相对差异变得更加显著。

### `Pai-Megatron-Patch`：围绕`Megatron-Core`打造大模型训练加速生态

贡献人：

`https://zhuanlan.zhihu.com/p/719667921?utm_psn=1818307403264966656`

1. 模型权重转换与精度对齐：

+ 实现`Huggingface`和`MCore`模型权重的高精度双向转换，确保在继续预训练或微调时的精度对齐。

+ 解决权重转换时的误差问题，主要涉及`RMS Norm`等六个方面的差异。消融实验表明，`MCore`模型的误差主要源自`Bias SwiGLU Fusion`和`RMSNorm`，并且逐层累积影响输出`logits`。

1. 显存优化技术：

+ `Optimizer CPU Offloading`:

+ 在CPU上进行参数更新，以减少显存占用。该技术基于`ZeRO-Offload`，并进行了改进，允许用户手动或半自动控制优化器卸载比例。

+ 引入了`Chunk Manager`模块，将多个参数、优化器状态和梯度打包成`chunk`，减少拷贝次数及显存碎片。

+ `HybridAdam`: 自研的优化器，支持在CPU和GPU上同时进行参数更新，采用`SIMD/CUDA`实现加速，并通过`Chunk Manager`管理内存。

+ 静态和自动卸载策略:

+ 静态策略根据用户设定的卸载比例，选择部分参数在CPU上更新。实验表明，在`LLaMA3.1-8B`模型中，采用65%卸载比例可将显存占用降低至77GiB，训练吞吐达到188.0。

+ 自动策略通过实时追踪显存使用情况，动态调整各GPU的卸载比例，实现更均衡的显存负载。

1. 激活/权重卸载技术（`Activation/Weight CPU Offloading`）：

+ `Transformer Engine 1.3`支持在前向-反向过程中卸载中间激活及权重，减少显存占用。实验显示，该技术在减少显存的同时会带来吞吐损失，建议仅启用1-2层的卸载。

1. `FlashAttention-3`:

+ 通过`Warp-Specialization`等三种主要技术，优化`H100` GPU上的注意力计算，将最大`FLOPs`利用率从35%提升至75%。

+ 支持`FP8`低精度训练，实现更高效的数据处理和更长上下文信息的处理能力。实验表明，`FlashAttention-3`相比`FlashAttention-2`性能提升1.5-2倍，但开启`FP8`后训练精度有所损失。

1. 通信优化（`Communication Overlapping`）：

+ 通过与计算的重叠方式优化数据并行（`DP`）、张量并行（`TP`）和流水线并行（`PP`）中的通信。实验表明，开启`TP`通信重叠可提升约10%的训练吞吐。

1. `LLM`训练加速应用指南：

+ 提供了`LLama3.1`等模型的预训练和微调示例，展示如何综合运用这些加速技术进行高效训练。

### `GPU`渲染之路：从图形引擎到内核驱动(三、用户态图形驱动层)

`https://zhuanlan.zhihu.com/p/651364842?utm_psn=1818309623779827712`

1. 图形系统分层结构：

+ 应用层：包含各种图形应用，如游戏、模拟器、设计工具，通过下层服务和硬件实现交互和图形渲染。

+ 跨平台层：包括图形引擎和工具（`Unity`、`Unreal Engine`、`bgfx`），提供跨平台支持以及高级功能（物理模拟、光照、动画等）。

+ 用户态图形驱动层：涉及操作系统和图形API（`OpenGL`、`DirectX`），为开发者提供与图形硬件交互的接口。用户态驱动在不直接与硬件交互的情况下，通过API函数将渲染任务下发给硬件驱动。

+ 内核态驱动层：连接操作系统与硬件，负责硬件初始化、资源管理、设备指令转换等。

+ 硬件层：包括GPU、显示器和输入设备，负责执行并行计算和图形渲染。

1. 图形编程历史：

+ 早期图形编程需要直接与硬件交互，难以移植。为此，70年代出现了图形API的雏形，80年代ISO发布`PHIGS`标准，解决跨平台绘图问题。`OpenGL`在90年代出现，使得图形编程跨平台化、标准化。

+ `GPU`的诞生：随着图形处理需求激增，NVIDIA在1999年发布了`GeForce 256`，开启GPU专门负责并行计算的时代，提高了图形渲染效率。

1. GPU驱动体系：

+ 用户态图形驱动：在用户态与图形API（`OpenGL`、`Vulkan`）进行交互，实现了API标准，并将其转化为硬件指令。核心工作在GPU厂商开发的硬件驱动程序中完成，以`OpenGL`为例，通过`gl_context`结构体和`dd_function_table`函数表调用特定GPU的驱动实现。
