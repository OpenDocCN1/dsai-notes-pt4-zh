## Deploy a model to a batch endpoint

`https://github.com/MicrosoftLearning/mslearn-azure-ml/blob/main/Instructions/11-Deploy-batch-endpoint.md`

这个实验标志着机器学习生命周期从“模型开发”阶段到“模型运维与生产化（MLOps）”阶段的一个关键跨越。我们不再是构建或优化模型，而是将已经选定的“冠军”模型发布成一个可用的服务。

### 实验特点与知识点分析 （基于 `Instructions/11-Deploy-batch-endpoint.md`）

#### 核心目标

这个实验的核心目标是让你学会如何将一个已经注册好的模型，部署成一个批量推断服务。你将创建一个批量终结点，它能够接收大量输入数据，在后端启动一个异步的计算作业来处理这些数据，并将预测结果保存下来供后续使用。这适用于那些不需要实时响应、但需要处理大规模数据的业务场景。

#### 流程分析

这个实验在 Jupyter Notebook 中完成，其流程清晰地展示了创建、部署和调用批量终结点的完整步骤：

1.  准备工作 （Preparation）:

+   获取模型： 从 Azure ML 模型注册表中获取一个之前已经注册好的、特定版本的模型。

+   准备数据： 准备一批用于批量推断的、无标签的输入数据，并将其注册为一个数据资产。

+   准备计算资源： 确保有一个用于执行批量推断作业的计算集群。

1.  创建批量终结点 （`Create Batch Endpoint`）: 首先，创建一个终结点 （`Endpoint`） 本身。终结点是一个持久的 HTTPS URL，它是所有批量部署的“入口”或“地址”。一个终结点可以托管多个部署。

1.  创建评分脚本 （`Create Scoring Script`）: 编写一个 Python 脚本 （`batch_driver.py` 或类似名称），这个脚本定义了如何使用模型进行预测。它的核心逻辑是：

+   `init()` 函数： 在作业开始时被调用一次，负责从指定的路径加载模型到内存中。

+   `run()` 函数： 接收一小批输入数据文件，使用已加载的模型对数据进行预测，并返回预测结果。

1.  创建批量部署 （`Create Batch Deployment`）: 这是流程的核心。你会创建一个部署 （`Deployment`），它将模型、评分脚本、软件环境和计算配置绑定在一起，并将其“挂载”到之前创建的终结点下。

1.  调用终结点 （`Invoke the Endpoint`）: 使用 `ml_client.batch_endpoints.invoke()` 命令来调用批量终结点，并发起一个批量推断作业。在调用时，你需要指定：

+   要使用的终结点名称。

+   要处理的输入数据。

1.  监控作业并获取结果 （`Monitor Job and Get Results`）: 调用终结点会异步地启动一个后端作业。你需要通过代码或 UI 来监控这个作业的运行状态。作业完成后，预测结果会被保存在云端存储中，你可以下载并查看这些结果。

#### 关键知识点介绍

+   批量推断 （`Batch Inference`）: 一种异步的、离线的模型预测模式。它旨在高效地处理大量数据，并且不要求立即返回结果。典型的应用场景包括：每日客户流失预测、每周产品推荐生成、对新上传的一批图片进行分类等。

+   终结点 （`Endpoint`）: 一个稳定的、持久的 URL，它为外部客户端提供了一个调用部署在其下的一个或多个服务的统一入口。终结点的存在将服务的调用接口与服务的具体实现（部署）解耦了。

+   部署 （`Deployment`）: 服务的具体实现。它是一个将模型、代码（评分脚本）、环境和计算资源打包在一起的单元。一个终结点可以有多个部署，这使得实现蓝绿部署或 A/B 测试等高级部署策略成为可能（例如，将 90% 的流量发给旧的 v1 部署，10% 的流量发给新的 v2 部署）。

+   评分脚本 （`Scoring Script`）: 部署的“大脑”。这是一个遵循特定结构（`init()` 和 `run()`）的 Python 脚本，它定义了从接收数据、使用模型进行预测到返回结果的完整逻辑。对于批量部署，`run()` 方法通常处理的是一个文件列表。

+   异步调用 （`Asynchronous Invocation`）: 与实时服务不同，调用批量终结点不会立即返回预测结果。它会立即返回一个作业 ID，并告诉你“好的，我已经收到了你的请求，正在后台处理，你可以用这个 ID 稍后来查询结果”。这种异步模式是处理长时间运行的大规模任务的关键。

+   作业输出 （`Job Output`）: 批量推断作业的输出（即预测结果）会被保存在 Azure Blob Storage 中。你需要通过作业对象来获取输出文件的路径，然后才能下载和查看。

1.  创建终结点

from azure.ai.ml.entities import BatchEndpoint

# configure the endpoint
endpoint = BatchEndpoint(

1.  创建部署

```
from azure.ai.ml.entities import BatchDeployment, Model, Environment

# Get the registered model
model = ml_client.models.get(name="mlflow-diabetes-model", version="1")
# Get the environment
env = ml_client.environments.get(name="AzureML-sklearn-1.0-ubuntu20.04-py38-cpu", version="1")

deployment = BatchDeployment(
    name="diabetes-batch-deployment-v1",
    description="A batch deployment for the diabetes classifier.",
    endpoint_name=endpoint.name,
    model=model,
    code_configuration={"code": "./src", "scoring_script": "batch_driver.py"},
    environment=env,
    compute="aml-cluster",
    instance_count=2,
    max_concurrency_per_instance=2,
    mini_batch_size=10,
    output_file_name="predictions.csv"
)

ml_client.batch_deployments.begin_create_or_update(deployment)
```

+   这是核心配置步骤。`BatchDeployment` 对象将所有必要的部分“粘合”在一起：

+   `endpoint_name`: 指定这个部署要挂载到哪个终结点下。

+   `model=model`: 关联要部署的模型资产。

+   `code_configuration`: 指定评分脚本的位置。

+   `environment=env`: 指定运行评分脚本所需的软件环境。

+   `compute="aml-cluster"`: 指定使用哪个计算集群来执行作业。

+   `instance_count=2`: 作业运行时，请求在集群上使用 2 个计算节点。

+   `max_concurrency_per_instance=2`: 每个计算节点上的最大并发数。

+   `mini_batch_size=10`: 每次调用 `run()` 函数时，`mini_batch` 列表的大小为 10 个文件。

1.  调用终结点

```
# get the input data asset
input_data = ml_client.data.get(name="diabetes-batch-data", version="1")

# invoke the endpoint
job = ml_client.batch_endpoints.invoke(
    endpoint_name=endpoint.name,
    input=input_data
)
```

+   `ml_client.batch_endpoints.invoke(...)` 是“启动按钮”。

+   它告诉 Azure ML：“请使用 `diabetes-batch-endpoint` 这个终结点（它会自动路由到默认的部署），去处理 `diabetes-batch-data` 这份数据”。

+   这个调用会立即返回一个 `job` 对象，你可以用它来监控后端作业的执行情况。

## Deploy a model to a managed online endpoint

`https://github.com/MicrosoftLearning/mslearn-azure-ml/blob/main/Instructions/11-Deploy-online-endpoint.md`

这个实验与上一个“批量终结点”形成了鲜明的对比，共同构成了模型生产化部署的两种主要模式。

### 实验特点与知识点分析 （基于 `Instructions/11-Deploy-online-endpoint.md`）

#### 核心目标

这个实验的核心目标是让你学会如何将一个模型部署成一个实时的、低延迟的 Web 服务。你将创建一个在线终结点，它会暴露一个 REST API 接口，任何经过授权的外部应用程序（如网站、移动 App、业务系统）都可以通过发送 HTTP 请求，同步地获取模型的预测结果。这适用于那些需要即时响应的交互式业务场景。

#### 流程分析

这个实验在 Jupyter Notebook 中完成，其流程与批量部署有相似之处，但在关键环节有本质不同：

1.  准备工作 （Preparation）:

+   获取模型： 从模型注册表中获取要部署的模型。

+   准备计算资源： 在线部署不使用临时的计算集群，而是需要一个永久在线的计算资源。这个实验会创建一个托管在线终结点 （`Managed Online Endpoint`），Azure ML 会在后台自动为你预配和管理所需的计算基础设施。

1.  创建评分脚本 （`Create Scoring Script`）: 编写一个评分脚本 （`score.py`）。它的结构与批量部署的脚本非常相似，但处理逻辑有本质区别：

+   `init()` 函数： 同样是在服务启动时被调用一次，负责加载模型。

+   `run()` 函数： 它的输入不再是文件列表，而是原始的请求数据（通常是 JSON 格式的字符串）。它需要解析这些数据，用模型进行预测，然后将预测结果以 JSON 格式返回。它的设计目标是快速处理单个或少数几个请求。

1.  创建在线终结点 （`Create Online Endpoint`）: 创建一个在线终结点。与批量终结点一样，它也是一个持久的 HTTPS URL，是服务的入口。
