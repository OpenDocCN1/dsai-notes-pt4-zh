
# 使用 LMDeploy Pipeline 进行多轮对话

```
# 导入必要的库和模块
from lmdeploy import pipeline, TurbomindEngineConfig, GenerationConfig
from lmdeploy.vl import load_image

# 创建一个图像处理管道，指向一个特定的模型文件夹
pipe = pipeline('/root/models/InternVL-Chat-V1-5',
                backend_config=TurbomindEngineConfig(session_len=8192))

# 定义一个包含图片URL的列表
image_urls = [
    '/root/test2.jpg',  # 第一个图片的路径
    '/root/test3.jpg'   # 第二个图片的路径
]

# 使用列表推导式和load_image函数加载列表中的每个图片
images = [load_image(img_url) for img_url in image_urls]

# 创建一个生成配置，用于控制生成文本的参数
gen_config = GenerationConfig(top_k=40, top_p=0.8, temperature=0.8)

# 创建一个会话（session），准备与模型进行交互
sess = pipe.chat(('请分别叙述这两张图片,并加以细节填充与描写。', images), gen_config=gen_config)

# 打印模型对第一张图片的描述
print(sess.response.text)

# 继续与模型交互，询问模型是否可以提供更细节的描述
sess = pipe.chat('你能给我一些更细节的描述吗？', session=sess, gen_config=gen_config)

# 打印模型对第二张图片的更细节的描述
print('\n', sess.response.text)  # 在描述前添加一个换行符

# 再次与模型交互，请求模型根据之前的结果写一个战争小故事
sess = pipe.chat('能否依据这些结果帮我写一个战争小故事？', session=sess, gen_config=gen_config)

# 打印模型编写的战争小故事
print('\n', sess.response.text)  # 在故事前添加一个换行符
```

再让我们接着来运行`pipeline_Multi-turn.py`。

```
python /root/pipeline_Multi-turn.py
```

这里有必要针对以下语句单独做一个解释。

```
gen_config = GenerationConfig(top_k=40, top_p=0.8, temperature=0.8)
```

这段代码行是用来创建一个`GenerationConfig`对象，这是一个用于控制生成文本的参数的配置对象。在`lmdeploy`库中，这通常与图像描述或问答等功能有关。

具体来说，`GenerationConfig`对象包含以下三个关键参数：

1. `top_k`：这是一个整数，它决定了在生成文本时考虑前`top_k`个最可能的单词。这个参数可以帮助控制生成的文本的多样性和创造性。较高的`top_k`值可能会生成更保守、更接近输入的文本，而较低的`top_k`值可能会生成更独特、更不确定的文本。

1. `top_p`：这是一个浮点数，它决定了在生成文本时只考虑概率分布的前`top_p`部分。这个参数可以用来控制生成文本的连贯性和多样性。较高的`top_p`值可能会生成更连贯、更相似的文本，而较低的`top_p`值可能会生成更多样、更不连贯的文本。

1. `temperature`：这是一个浮点数，它决定了在生成文本时的温度系数。这个参数可以用来控制生成文本的随机性和确定性。较高的`temperature`值可能会生成更随机、更不确定性的文本，而较低的`temperature`值可能会生成更确定、更连贯的文本。

在这段代码中，`gen_config`对象被创建并设置了`top_k=40`、`top_p=0.8`和`temperature=0.8`。这些参数的值是根据需要生成的文本的特定要求来设置的。例如，如果你想要生成更独特、更不确定的文本，你可以将`top_k`设置得较低，将`top_p`设置得较高，将`temperature`设置得较高。

# LMDeploy API部署InternVL-Chat-V1-5

在上一章节，我们都是在本地直接部署`InternVL-Chat-V1-5`。而在实际应用中，我们有时会将大模型封装为API接口服务，供客户端访问。

## 3.1 启动API服务器

通过以下命令启动API服务器，部署`InternVL-Chat-V1-5`模型：

```
lmdeploy serve api_server \
    /root/models/InternVL-Chat-V1-5 \
    --model-format hf \
    --quant-policy 0 \
    --server-name 0.0.0.0 \
    --server-port 23333 \
    --tp 1
```

命令解释：

1. `lmdeploy serve api_server`：这是`lmdeploy`库中的一个命令，用于启动一个API服务器。这个命令告诉`lmdeploy`库，你想要通过一个API服务器来访问模型。

1. `/root/models/InternVL-Chat-V1-5`：这是模型的路径，指定了模型文件夹的位置。这个文件夹包含了模型的所有相关文件和配置。

1. `--model-format hf`：这个参数指定了模型的格式。在这里，`hf`代表“Hugging Face”格式。这告诉`lmdeploy`库如何加载和处理模型。

1. `--quant-policy 0`：这个参数指定了量化策略。量化是将模型从浮点数转换为整数的过程，这可以减少模型的内存使用和计算时间。

1. `--server-name 0.0.0.0`：这个参数指定了服务器的名称。在这里，`0.0.0.0`是一个特殊的IP地址，它表示所有网络接口。

1. `--server-port 23333`：这个参数指定了服务器的端口号。在这里，`23333`是服务器将监听的端口号。

1. `--tp 1`：这个参数表示并行数量（GPU数量）。

总的来说，这段代码的目的是启动一个API服务器，以便通过网络接口访问一个位于指定路径的模型。这个服务器将监听所有网络接口上的指定端口，并且可能使用特定的模型格式和量化策略。

# LMDeploy Lite

不知道大家还记不记得[当初圈起来的内容](https://kaxojqwlrks.feishu.cn/wiki/GkhEwMCREiFtX2kZPWxcHltRnnb?larkTabName=space#part-KlDpdlEBHobx3dxQ5vBc14vInOg)，对，就是`InternVL-Chat-V1-5`运行时会吃掉73G的显存，而经过前面几回合的学习，大家也会发现峰值时候吃掉80G显存简直轻而易举。而针对此种情况，`LMDeploy`为大家提供了两种方法，一种是`KEY-VALUE(KV) CACHE`量化，一种是模型量化。

## 4.1 kv cache量化

`key-value (kv) cache`量化是一种将内存中的键值缓存（`kv cache`）从高精度浮点数转换为低精度整数的技术，以减少内存使用和提高访问速度。

模型在运行时，占用的显存可大致分为三部分：模型参数本身占用的显存、`kv cache`占用的显存，以及中间运算结果占用的显存。`LMDeploy`的`kv cache`管理器可以通过设置`--cache-max-entry-count`参数，控制`kv`缓存占用剩余显存的最大比例。默认的比例为0.8。

首先我们先来回顾一下`InternVL-Chat-V1-5`正常运行时占用显存。

![](img/2c1a4f01d6bc1fe61f056b06f5c9fec9.png)

占用了73G，那么试一试执行以下命令，再来观看占用显存情况。

```
lmdeploy chat /root/models/InternVL-Chat-V1-5 --cache-max-entry-count 0.4
```

稍待片刻，观测显存占用情况，可以看到减少了约17G的显存。

![](img/e5b3e76459266b087742dddb81ff2621.png)

接着试一试把`--cache-max-entry-count`参数设置为0.01，约等于禁止`kv cache`占用显存。

```
lmdeploy chat /root/models/InternVL-Chat-V1-5 --cache-max-entry-count 0.01
```

稍待片刻，观测显存占用情况，减少了约35G的显存，但是代价就是会降低模型推理速度。

![](img/733b36eab5d36f8fb5329e8cdcf2cef0.png)

## 4.2 在线 kv cache int4/int8 量化

自`v0.4.0`起，`LMDeploy` 支持在线 `kv cache` `int4`/`int8` 量化，量化方式为 `per-head per-token` 的非对称量化。此外，通过 `LMDeploy` 应用 `kv` 量化非常简单，只需要设定 `quant_policy` 和`cache-max-entry-count`参数。目前，`LMDeploy` 规定 `qant_policy=4` 表示 `kv int4` 量化，`quant_policy=8` 表示 `kv int8` 量化。

我们通过3. LMDeploy API部署`InternVL-Chat-V1-5`的实践为例，输入以下指令，启动API服务器。

```
lmdeploy serve api_server \
    /root/models/InternVL-Chat-V1-5 \
    --model-format hf \
    --quant-policy 4 \
    --cache-max-entry-count 0.4\
    --server-name 0.0.0.0 \
    --server-port 23333 \
    --tp 1
```

稍待片刻，显示如下即代表服务启动成功。

## 4.3 `W4A16` 模型量化和部署

准确说，模型量化是一种优化技术，旨在减少机器学习模型的大小并提高其推理速度，通常用于移动和边缘设备。量化通过将模型的权重和激活从高精度（如32位浮点数）转换为低精度（如16位浮点数、8位整数、甚至二值网络）来实现。

展开来说说模型量化。

1. 为何量化？

+ 减小模型大小：量化可以显著减少模型的大小，使其更容易部署到资源受限的设备上。

+ 提高推理速度：低精度计算通常比高精度计算更快，尤其是在专用硬件（如GPU、TPU）上。

+ 降低能耗：低精度运算通常消耗更少的能耗。

1. 量化类型：

+ 动态量化：在运行时动态地量化权重和激活。通常用于权重分布变化较大的模型。

+ 静态量化：在训练后量化权重和激活。通常用于权重分布相对稳定的模型。

+ 量化感知训练（QAT）：在训练过程中模拟量化效果，以适应量化带来的损失。

1. 量化精度：

+ `FP32`：32位浮点数，标准精度。

+ `FP16/BF16`：16位浮点数/Brain Float16，低精度浮点数。

+ `INT8`/`INT4`：8位/4位整数，非常低的精度。

+ 二值网络：权重和激活只有两个值（+1或-1）。

1. 量化挑战：

+ 精度损失：量化可能会导致模型性能下降。

+ 饱和问题：在量化过程中，极值可能会被“饱和”，导致信息丢失。

+ 校准：找到正确的缩放因子和零点以最小化量化误差。

让我们回到`LMDeploy`上，在最新的版本中，已经支持对`InternVL-Chat-V1-5`模型进行推理量化了。

![](img/a5f66a5233830b9bf2c849af32c3661c.png)

`LMDeploy`使用的是`AWQ`算法，能够实现模型的`4bit`权重量化。输入以下指令，执行模型的量化工作。

```
lmdeploy lite auto_awq \
   /root/models/InternVL-Chat-V1-5 \
  --calib-dataset 'ptb' \
  --calib-samples 128 \
  --calib-seqlen 1024 \
  --w-bits 4 \
  --w-group-size 128 \
  --work-dir /root/models/InternVL-Chat-V1-5-w4a16-4bit
```

命令解释：

1. `lmdeploy lite auto_awq`: `lite`是`LMDeploy`的命令，用于启动量化过程，而`auto_awq`代表自动权重量化（auto-weight-quantization）。

1. `/root/models/InternVL-Chat-V1-5`: 这是模型文件的路径，指出模型的位置。

1. `--calib-dataset 'ptb'`: 这个参数指定了一个校准数据集，这里使用的是`'ptb'`（指的是Penn Treebank，一个常用的语言模型数据集）。

1. `--calib-samples 128`: 这指定了用于校准的样本数量，这里是128个样本。
