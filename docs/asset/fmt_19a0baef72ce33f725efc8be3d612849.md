优化一下设计风格## 设计要求: ### 新视觉风格：具备高交互性的科技感设计（Neumorphism） 1. **视觉特征**     1.1 **色彩风格**         - 以冷色系为主导，常选用蓝色、紫色、黑色、银色等冷色调，搭配高亮的霓虹色（如蓝绿、紫粉、橙黄）作为视觉点缀，以形成鲜明的色彩对比和独特的视觉感受。         - 广泛运用渐变色、发光效果和高光线条，借助这些元素营造出强烈的未来感和浓厚的科技氛围。         - 采用暗黑背景，通过突出内容和发光元素，有效增强用户的沉浸体验。     1.2 **材质与纹理**         - 运用玻璃拟态（Glassmorphism）设计手法，呈现半透明的玻璃质感，并搭配模糊效果，进一步增强科技感和画面层次感。         - 赋予元素表面金属质感或光泽反射效果，以此提升整体设计的高级感。         - 在背景或装饰部分巧妙使用网格、几何线条或动态粒子，突出科技元素，强化科技氛围。 2. **动效设计**     1.1 **高交互动画**         - 针对按钮、滑块、图标等交互元素，在用户进行点击、滑动操作时，提供相应的反馈动画，如轻微弹跳、缩放或发光效果，增强用户操作的反馈感和趣味性。         - 采用动态线条、旋转粒子或数据流效果作为加载动画，有效减少用户等待过程中的无聊感。         - 在页面切换时，运用平滑过渡、翻页或层叠动画，提升页面切换的流畅感。     1.2 **数据动态展示**         - 实现数据图表（如折线图、柱状图）的动态更新，模拟流畅的数据流动效果，使用户能够直观地观察数据变化。         - 当数字发生变化时，采用滚动或渐变效果，突出科技感和数据的动态性。     1.3 **3D动态效果**         - 引入3D模型或动态图形（如旋转地球、立体图标），增强页面的空间感和立体感。         - 当用户滑动页面时，设置前景和背景以不同速度移动，实现视差滚动效果，进一步增加用户的沉浸感。 3. **文字设计**     3.1 **字体风格**         - 选用简洁现代的无衬线字体，如Roboto、SF Pro、Futura等具有强烈未来感的字体，确保文字的可读性和现代感。         - 标题文字采用较粗的字体样式，正文文字采用较细的字体样式，通过字体粗细对比突出内容的层次感。         - 在字体设计中融入几何线条或断笔效果，进一步增强文字的未来感。     3.2 **字体颜色**         - 在深色背景下，使用亮白、霓虹蓝、荧光绿等高亮颜色的文字，保证文字与背景之间的高对比度，提高文字的可读性。         - 部分标题或装饰性文字采用渐变色处理，增加科技氛围和视觉吸引力。         - 为文字添加发光、闪烁或滚动效果，增强文字的动感和科技感。 4. **交互设计**     4.1 **手势操作**         - 支持多种手势操作（如滑动、长按、双击），提升用户操作的自由度和趣味性。         - 确保动画反馈与手势操作紧密结合，为用户提供自然流畅的交互体验。     4.2 **语音与AI交互**         - 集成专业的语音助手或AI功能，支持语音指令、智能推荐和个性化服务，提升用户与APP的交互便捷性。     4.3 **实时反馈**         - 在用户进行操作后，立即提供反馈信息，如按钮变色、数据更新、动态提示等，让用户及时了解操作结果。 5. **布局与信息架构**     5.1 **模块化布局**         - 对界面进行清晰的分区设计，将数据和功能以卡片或模块的形式进行展示，便于用户快速浏览和操作。         - 采用网格布局或分层布局方式，体现科技感的秩序美和逻辑性。     5.2 **信息层次**         - 通过字体大小、颜色或动态效果突出重要信息，对次要信息进行淡化处理，帮助用户快速聚焦关键内容。         - 合理运用留白和对齐方式，优化用户的阅读体验，避免信息过载。 6. **技术感元素**     - 在背景或交互环节中融入动态粒子（如光点、数据流），进一步增强科技氛围和视觉效果。     - 使界面元素模拟全息投影的透明、悬浮效果，提升界面的科技感和独特性。     - 对图标进行简洁而富有未来感的设计，可能带有光效或动态变化，增强图标的辨识度和科技感。

### GPT-4.1 提示词指南

GPT-4.1 系列模型在编码、指令遵循和长上下文处理能力方面，相较于 GPT-4o 代表了一个显著的进步。在这份提示词指南中，我们收集了一系列源自大量内部测试的重要提示词技巧，以帮助开发者充分利用这一新模型系列提升后的能力。

许多典型的最佳实践在 GPT-4.1 上仍然适用，例如提供上下文示例、使指令尽可能具体和清晰，以及通过提示词诱导规划，以最大化模型智能。然而，我们预计，要充分发挥该模型的能力，需要进行一些提示词迁移。GPT-4.1 被训练得比其前辈们更紧密、更字面地遵循指令，而前辈模型往往会更自由地根据用户和系统提示推断意图。但这也意味着，GPT-4.1 对于明确指定的提示词具有极高的可引导性和响应性 —— 如果模型行为与你的预期不同，仅用一句坚定明确的句子澄清你想要的行为，几乎总是足以将模型引导回正轨。

请继续阅读以下提示词示例，供你参考。同时请记住，尽管这些指导具有广泛适用性，但没有哪条建议是放之四海而皆准的。AI 工程本质上是一个经验性学科，大语言模型本质上也是非确定性的；因此，除了遵循本指南之外，我们还建议你构建有信息量的评估，并频繁迭代，以确保你的提示词工程更改确实在你的用例中带来了好处。

---

#### 1. 代理式工作流

GPT-4.1 是构建代理式（Agentic）工作流的绝佳平台。在模型训练中，我们强调了提供多样化的代理式问题解决轨迹，并且我们的代理式工具链在非推理模型中，在 SWE-bench Verified 测评上达到了最先进的表现，解决了 55% 的问题。

##### 系统提示词提醒

为了充分利用 GPT-4.1 的代理式能力，我们建议在所有代理提示词中包含三种关键类型的提醒。以下提示词特别针对代理式编码工作流进行了优化，但也可以轻松地修改用于一般代理式场景。

+   持续性（Persistence）：这确保模型理解它正在进入一个多轮消息回合，并防止它过早地将控制权交还给用户。我们的示例如下：

你是一个代理 —— 请持续执行，直到用户的请求被完全解决之后，再结束你的回合并将控制权交还给用户。只有当你确信问题已经解决时，才结束你的回合。

+   调用工具（Tool-calling）：这鼓励模型充分使用其工具，减少模型产生幻觉或猜测答案的可能性。我们的示例如下：

如果你不确定与用户请求相关的文件内容或代码库结构，请使用你的工具读取文件并收集相关信息：不要猜测或捏造答案。

+   规划（Planning）[可选]：如果需要，这确保模型在每次调用工具之前在文本中明确规划和反思，而不是仅通过一连串的工具调用完成任务。我们的示例如下：

你必须在每次函数调用之前进行充分的规划，并在之前的函数调用结果上进行充分反思。不要仅仅通过调用函数来完成整个过程，因为这样可能会损害你解决问题和深入思考的能力。

GPT-4.1 被训练成在代理式场景下非常紧密地响应用户指令和系统提示。模型紧密遵循了这三条简单指令，使我们在内部 SWE-bench Verified 测评中的得分提高了近 20% —— 因此我们强烈建议，在任何代理提示词开头都要用清晰的提醒涵盖上述三大类别。总体上，我们发现这三条指令将模型从一个类聊天机器人状态转变成了一个更加“积极”的代理，能够自主且独立地推进交互。

---

##### 工具调用（Tool Calls）

与之前的模型相比，GPT-4.1 在有效利用以 OpenAI API 请求参数传递的工具方面进行了更多训练。我们鼓励开发者仅使用`tools`字段来传递工具，而不是像过去一些人报告的那样，将工具描述手动注入到提示词中，并编写单独的解析器来解析工具调用。

这是最小化错误并确保模型在工具调用轨迹中保持在训练分布内的最佳方式 —— 在我们的实验中，当使用 API 解析的工具描述而不是手动注入 schema 到系统提示时，SWE-bench Verified 的通过率提升了 2%。

开发者应该清晰地命名工具以表明其用途，并在工具的`description`字段中添加清晰详细的描述。类似地，对于每个工具参数，也应依靠良好的命名和描述以确保恰当使用。如果你的工具特别复杂，想要提供工具使用示例，我们建议你在系统提示中创建一个`# 示例（Examples）`部分，并将示例放在那里，而不是塞进`description`字段，后者应保持详细但相对简洁。提供示例可以帮助模型了解何时使用工具、在工具调用时是否附带用户文本、以及不同输入对应的合适参数。

记住，你可以在 Prompt Playground 中使用“生成任意内容（Generate Anything）”功能，为你的新工具定义获取一个良好的起点。

---

##### 提示词诱导的规划与思维链（Chain-of-Thought）

如前所述，开发者可以选择通过提示词诱导，促使基于 GPT-4.1 的代理在工具调用之间进行规划和反思，而不是静默地连续调用工具。GPT-4.1 不是推理模型 —— 也就是说，它在回答前不会自动生成内部思维链 —— 但开发者可以在提示词中诱导模型生成一个显式的、逐步的计划。这可以被视作模型“自言自语”。

在我们针对 SWE-bench Verified 的代理式任务实验中，诱导显式规划使得通过率提升了 4%。
