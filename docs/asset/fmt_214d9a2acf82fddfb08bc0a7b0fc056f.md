
### 第四阶段：代理协作与工具交互

+ **任务：** 扩展实验 4.2，为 `Critic` Agent 注册嵌套对话 （`register_nested_chats`）。当 `Writer` 提交初稿时，`Critic` 先去咨询多个“专家”评审员（SEO、法务、伦理），然后汇总意见反馈给 `Writer`。

+ **核心概念：** 嵌套对话、动态咨询、模块化协作。

+ **实验 4.4 （源自 `ds06`）：`AutoGen` - 使用工具与环境交互 （国际象棋）**

+ **任务：** 创建两个 `Player` Agent 和一个 `Board Proxy` Agent。定义 `get_legal_moves` 和 `make_move` 工具函数，并使用 `register_function` 和 `function_map` 进行配置。让 `Player` Agent 通过调用工具与全局棋盘状态交互，进行对弈。

+ **核心概念：** Agent 使用工具与外部状态交互、`register_function` vs `function_map`。

### 第五阶段：代码生成、多角色群聊与 Agent 应用 （Code Generation， Group Chat & Applications）

+ **目标：** 体验 Agent 生成和执行代码的能力，构建复杂的多角色协作群聊，并实践基于平台的 Agent 应用构建。

+ **实验 5.1 （源自 `ds06`）：`AutoGen` - 代码生成与执行 （金融图表）**

+ **任务：** 创建一个 Code Writer Agent 和一个 Code Executor Agent（配置 `LocalCommandLineCodeExecutor`，需要人工确认）。让 `Writer` 根据任务（例如，获取并绘制股票数据）生成 Python 代码，`Executor` 执行代码，`Writer` 根据结果（或错误）进行可能的修正。

+ **核心概念：** 代码生成、代码执行、执行器配置、生成-执行-反馈循环。

+ **实验 5.2 （源自 `ds06`）：`AutoGen` - 使用 UDF 优化代码生成**

+ **任务：** 将实验 5.1 中的核心数据获取和绘图逻辑封装成用户自定义函数 （`UDFs`）。配置 `Executor` 使其能直接调用这些 `UDFs`。修改 `Writer` 的系统消息告知其可用 `UDFs`。重新执行任务，观察代码生成和执行过程的变化。

+ **核心概念：** 用户自定义函数 （`UDFs`）、提高代码生成可靠性与效率。

+ **实验 5.3 （源自 `ds06`）：`AutoGen` - 多角色群聊协作 （金融报告）**

+ **任务：** 创建一个包含 `Admin`， `Planner`， `Engineer`， `Executor`， `Writer` 角色的群聊 （`GroupChat` 和 `GroupChatManager`）。由 `Admin` 发起任务（如生成 Nvidia 股价分析报告），观察各 Agent 如何通过自动发言人选择（或自定义规则）进行协作，完成从规划、编码、执行到写作的完整流程，并由 `Admin` 进行最终审批。

+ **核心概念：** 群聊、多角色协作、`GroupChatManager`、自动/手动发言者选择。

+ **实验 5.4 （源自 `ds07`）：`Dify` - 构建 Agent 应用 （热点综述/美股分析）**

+ **任务：** （平台实践） 在 `Dify` 中，创建 Agent 类型的应用。配置 Agent 使用内置工具（如搜索、雅虎财经）。设计 Agent Prompt，指导其按流程调用工具，完成信息收集和报告生成的任务。测试 Agent 的执行效果。

+ **核心概念：** 使用 LLMOps 平台构建带工具的 Agent、可视化 Agent 配置。

### 第六阶段：探索高级概念 （场景思路与讨论） （Exploring Advanced Concepts - Scenarios & Discussion）

+ **目标：** 针对课程中介绍的高级理论，设计（不一定完全编码实现）或讨论实践场景。

+ 场景 6.1 （思路）: 实践 Plan-and-Act 模式

+ **任务：** 设计一个 Agent 系统模拟 Plan-and-Act 架构。场景： “研究并总结三种不同品牌的智能手表的主要优缺点”。

+ **思路：**

+ **`Planner` Agent:** 接收任务，输出计划步骤，例如：["1。 搜索品牌 A 手表评测"， "2。 提取品牌 A 优缺点"， "3。 搜索品牌 B 手表评测"， "4。 提取品牌 B 优缺点"， "5。 搜索品牌 C 手表评测"， "6。 提取品牌 C 优缺点"， "7。 汇总并生成对比总结"]。

+ **`Executor` Agent:** 接收一个计划步骤。配置搜索工具和文本摘要/信息提取工具。执行步骤（如调用搜索工具获取评测文章，再调用摘要工具提取优缺点）。将结果记录下来。

+ **流程：** 依次执行计划步骤。可以模拟 `Executor` 执行失败（如摘要工具未能提取有效信息），这时需要将失败信息反馈给（一个简化的）`Planner`，`Planner` 可能需要调整后续计划（例如，尝试不同的搜索词或跳过该品牌）。

+ **核心概念：** 规划与执行分离、任务分解、基于执行结果的（模拟）重规划。

+ 场景 6.2 （思路）: 探索结构化记忆 （知识图谱）

+ **任务：** 构建一个能回答关于“公司组织架构和项目成员”问题的 Agent。

+ **思路：**

+ **数据准备：** 手动创建一个简单的知识图谱（可以用 `networkx` 在内存中表示，或存入简单的图数据库如 `Neo4j` 本地实例），包含员工、部门、项目节点以及“属于部门”、“参与项目”、“同事”等关系。

+ **工具定义：** 创建一个 `query_knowledge_graph(query)` 工具，该工具能接收自然语言问题，将其（可以简单地通过关键字匹配或让另一个 LLM 转换）转化为图查询语句（如 `Cypher`），执行查询并返回结果。

+ **Agent:** 配置一个 Agent，让它知道有这个知识图谱查询工具。

+ **测试：** 提问多跳问题，如“与张三在同一个项目（Project X）工作的李四，他属于哪个部门？” 观察 Agent 是否能成功调用工具并整合图谱返回的信息来回答。

+ **核心概念：** 结构化记忆、知识图谱查询、处理关系数据。

+ 场景 6.3 （思路/讨论）: Agent 评估实践

+ **任务：** 对之前某个实验（例如实验 5.3 的金融报告群聊）的输出结果进行评估。

+ **思路：**

+ **定义评估维度：** 针对该任务，定义几个评估维度，例如：信息准确性（股价数据是否真实？）、完整性（是否覆盖了任务要求的所有点？）、分析深度、语言流畅度、格式规范性。

+ **人工评估：** 选择几份 Agent 生成的报告，根据维度进行人工打分。

+ **LLM-as-a-Judge:** 设计一个详细的评估 Prompt，将报告和评估维度/标准提供给一个强大的 LLM（如 `GPT-4` 或 `Claude 3 Opus`），让它进行打分和评价。

+ **对比与分析：** 比较人工评估和 LLM 评估的结果，分析 LLM 作为评估者的优点和局限性。讨论如何改进评估 Prompt 以获得更可靠的 LLM 评估结果。

+ **核心概念：** Agent 评估指标、人工评估 vs LLM 评估、评估 Prompt 设计。

+ 场景 6.4 （讨论）: 生产化考量

+ **任务：** 假设要将实验 5.3 的“金融分析报告”群聊 Agent 部署为公司内部使用的服务，讨论需要考虑哪些生产化因素。

+ **讨论点：**

+ **部署架构：** 选择哪种模式（微服务？）? 如何处理状态（如果需要跨多轮交互）？

+ **可观测性：** 需要监控哪些关键指标？如何记录日志和追踪来帮助调试？

+ **成本优化：** 如何控制 `DeepSeek API` 的调用成本？（例如，缓存常用数据？使用更经济的模型进行部分步骤？）

+ **安全性：** 如何管理 `API Key`？如何防止内部员工滥用？如何处理报告中可能出现的敏感信息？

+ **可靠性：** 如何处理 `yfinance API` 不可用或返回错误的情况？如何确保流程在某个 Agent 失败时能恢复或优雅降级？

+ **核心概念：** `AgentOps` 思维、部署架构、可观测性、成本、安全、可靠性。
