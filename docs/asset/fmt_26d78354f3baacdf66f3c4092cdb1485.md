
此外，苹果的《LLM in a Flash》论文展示了在内存受限设备上运行大型语言模型的关键技术。苹果通过“窗口化”和“行列打包”策略，减少从闪存传输的数据量，实现了4-5倍的推理速度提升。这一技术使得内存优化模型的推理成本大幅下降，特别适用于端侧设备的AI模型部署。

## 一文讲明白大模型分布式逻辑（从GPU通信原语到Megatron、Deepspeed）

https://zhuanlan.zhihu.com/p/721941928

分布式训练是解决单个GPU显存不足而采用的模型或数据在多GPU间分配的策略。常见的分布式训练方法包括数据并行和模型并行。数据并行适用于模型能够放在单个GPU上的情况，通过将数据分割并分配给多个GPU训练，以加速训练过程；模型并行则用于模型太大而无法放入单卡时，将模型切分为多块，并分配到不同GPU上运行。模型并行又细分为流水线并行（将模型按层分配到不同GPU）和张量并行（将单层模型的参数按张量切分），以应对不同模型规模和显存需求。

`DeepSpeed`是一个支持大模型训练的分布式训练框架，使用Zero（Zero Redundancy Optimizer）技术对显存进行优化，主要分为三个阶段：

+   `Zero1`：切分优化器状态，将优化器的参数分配到各个GPU，从而降低显存占用。训练过程通过`Ring AllReduce`进行通信更新，每个GPU只需处理其对应的部分优化器参数。

+   `Zero2`：进一步切分梯度，减少GPU上的梯度冗余存储。在训练过程中，通过`ReduceScatter`操作将梯度分散到不同GPU，并在需要更新时再聚合，从而大幅降低梯度的显存占用。

+   `Zero3`：切分模型权重，实现最小化的显存占用。Zero3在训练过程中动态地加载和释放模型权重，将权重分散到各个GPU进行计算，再通过`AllGather`操作在需要时聚合。与前两种优化策略相比，Zero3的通信量更大，但显存优化效果最佳，可支持更大规模的模型训练。

`Megatron`是另一个3D混合并行框架，结合了数据并行、流水线并行和张量并行三种方式：

+   `张量并行（Tensor Parallelism）`：将模型的线性层按权重矩阵切分为不同的块，并分配到不同GPU处理，从而减小每个GPU的负载。在Transformer结构中，Embedding层、前馈层和多头注意力层都可以按维度进行切分。

+   `流水线并行（Pipeline Parallelism）`：将模型按层级结构划分，不同GPU负责不同层的计算，通过前向和反向传播依次传递数据。使用微批次流水线（`Micro-Batching`）策略，可以显著减少GPU闲置时间，提升利用率。

+   `数据并行（Data Parallelism）`：在多个GPU上复制模型，并对不同数据进行并行训练。数据并行主要用于加速训练，但在大模型场景下由于显存限制常与模型并行结合使用。

Megatron的3D并行策略中，张量并行优先在单节点内进行通信，以降低带宽消耗，而数据并行和流水线并行则可跨节点通信。

### 分布式通信与NCCL库

分布式训练依赖GPU间的数据通信，包括广播（`Broadcast`）、散射（`Scatter`）、规约（`Reduce`）、聚合（`Gather`）、全规约（`AllReduce`）、全聚合（`AllGather`）和散射规约（`ReduceScatter`）等操作。`NCCL`（NVIDIA Collective Communication Library）是用于多GPU、多节点通信的高效通信库，它提供了常用的通信原语，支持数据的传递和同步。对于大规模分布式训练，通信效率是决定性能的关键因素，因此选择合适的通信策略尤为重要。

在模型并行中，`Ring AllReduce`是一种去中心化的通信方式，它通过环状传递的方式将数据分散到每个GPU，并在每个节点上独立进行计算和聚合，从而实现了负载均衡和高效的通信。相比传统的参数服务器模型，`Ring AllReduce`在多机多卡场景中表现出更高的通信效率。

综上，分布式训练方法是应对大模型时代GPU显存瓶颈的有效解决方案。通过数据并行、流水线并行、张量并行和混合并行策略，以及`DeepSpeed`的`Zero`优化技术和`Megatron`的3D并行策略，现代分布式训练框架能够显著提升大规模模型的训练效率。`NCCL`库提供的高效通信原语进一步优化了多GPU、多节点间的通信性能，使得大模型训练成为可能。

## 大模型推理加速与KV Cache（五）：Prefix Caching

https://zhuanlan.zhihu.com/p/739669365?utm_psn=1823426418282983425

`Prefix Caching` 是一种用于提升大模型推理性能的优化策略，主要针对跨请求的KV Cache复用。在多轮对话场景中，下一轮的Prompt通常是上一轮Prompt加上Completion，如果能够复用上一轮计算好的KV Cache，就可以大幅提升prefill阶段的性能，降低首次Token生成的时间（`TTFT`）。该方法的核心是缓存系统提示和历史对话中的键值（KV）对，并在后续请求中重复利用，从而减少重复计算，提升推理效率。以下是几种系统中Prefix Caching的具体实现与优化策略：

1.  `SGLang`中的Prefix Caching

`SGLang`通过`RadixAttention`算法实现了Prefix Caching。该算法将每次请求中的KV Cache保留在GPU显存中，并将序列Token到KV Cache的映射关系保存在`RadixTree`数据结构中。新请求到来时，`SGLang`的调度器通过`RadixTree`进行前缀匹配，判断是否可以命中缓存并复用KV Cache。这种方法可以减少不必要的计算，提升模型推理的效率。此外，`SGLang`引入了`LRU`（Least Recently Used）策略用于管理显存中的缓存淘汰，并设计了一种名为`cache-aware scheduling`的调度算法，对同一时间段内的多个请求进行优化调度，从而最大化缓存的复用率。

1.  vLLM中的Prefix Caching

`vLLM`采用了一种名为`Hash RadixAttention`的策略进行Prefix Caching。它通过哈希码将Prefix Tokens和KV Block唯一映射，并以此在物理KV Block中定位对应缓存。这种方法相比`RadixTree`更为简单，易于工程实现。启用该功能时，只需在模型初始化时设置`enable_prefix_caching=True`即可实现KV Cache的跨请求复用，有效降低模型在多轮对话场景中的`TTFT`。

1.  DeepSeek中的Prefix Caching

`DeepSeek` API中称该技术为“`Context Caching`”，采用了上下文硬盘缓存而非GPU显存缓存。它将可能被重复使用的内容缓存在分布式硬盘阵列中，通过降低对显存的需求来减少缓存系统的传输带宽和存储容量。`DeepSeek`基于`64 Tokens`为单位进行缓存管理，未满`64 Tokens`的内容不进行缓存，且缓存命中部分费用较低。由于采用硬盘缓存的方式，`DeepSeek`在KV Cache的管理上更加灵活，适合对存储成本和传输带宽要求较高的场景，但不能保证100%缓存命中。

### 注意事项与局限性

`Prefix Caching` 的优化仅作用于prefill阶段，降低`TTFT`，而对解码阶段（`TPOT`）没有帮助。因此，在Prompt较短而Completion较长的场景下，`Prefix Caching`的整体性能提升效果有限。此外，如果不同请求之间的Prompt没有公共前缀，也无法发挥缓存复用的优势。因此，在实际应用中需要根据具体任务的特性来判断`Prefix Caching`的效果。总之，`Prefix Caching`在多轮对话和含有公共前缀的请求中可以显著提升推理性能，是优化大模型推理的一种有效策略。

## 什么！SFT完全没用！

https://zhuanlan.zhihu.com/p/744847498?utm_psn=1823739555360157696

Google DeepMind提出了一种新的方法`SCoRe`（Self-Correction via Multi-Turn Reinforcement Learning），旨在提升大型语言模型（LLM）在缺乏强外部反馈任务中的自我矫正能力。传统的提示工程和监督微调（`SFT`）常依赖于静态数据分布进行训练，导致模型在实际应用中自我修正能力较弱。在没有外部反馈信号（如代码执行或验证器）的任务中，现有方法无法有效提升模型性能。`SFT`方法的局限性在于其倾向于学习微小的修改策略，并在数据分布存在偏移时无法发挥自我矫正能力。

为了解决这些问题，`SCoRe` 采用了两阶段的多轮强化学习框架。

第一阶段是初始化训练，目标是防止模型在第二次尝试中发生策略崩塌。通过引入`KL`散度约束，该阶段显式训练模型在第二次尝试时生成高奖励的修订，同时保持第一次尝试的响应尽可能接近基础模型的初始分布。这种做法通过在静态的第一次尝试分布下扩大模型在第二次尝试的覆盖范围，使模型能够在后续强化学习中更稳健地进行自我纠正。

第一阶段的优化目标为：

```
\mathcal{L} = \mathbb{E}_{\pi} [R(\tau)] - \lambda KL (\pi_1 | \pi_{baseline})
```

其中，\(\pi_1\) 是第一次尝试的策略分布，\(\pi_{baseline}\) 是基础模型的分布，\(\lambda\) 是`KL`惩罚的权重系数。此目标的目的是在第二次尝试中获得较高奖励的修订，并防止第一次尝试的响应与基础模型的分布产生较大偏差，从而减少模型在后续`RL`训练中陷入局部最优。

第二阶段则是在第一阶段训练好的初始化模型上进行多轮强化学习。该阶段旨在联合优化两次尝试的响应，并通过奖励机制激励模型在第二次尝试时进行有效的自我修正，而不是简单地在第一次尝试中生成最优响应，再在第二次尝试中进行微小的修订。通过基于策略梯度的强化学习方法，`SCoRe`能够在多轮交互中优化策略，并利用自适应的`KL`正则化项控制第一次尝试的策略偏移。在训练过程中，模型能够自动生成与基础模型策略偏差较大的第一次尝试，进一步扩展状态覆盖范围，从而提升策略的泛化能力。

`SCoRe` 的核心思想在于使模型在自生成的轨迹（`traces`）上进行训练，避免数据分布偏移对策略学习的影响。在自我纠正训练中，模型必须通过实际多轮交互学习有效的自我修正策略，而非采取简化策略（如第一次尝试生成最优响应，第二次尝试进行微小修订），以防止模型坍塌到一种无法泛化的行为模式。

实验结果表明，与传统`SFT`方法相比，`SCoRe`在多种任务场景中均显著提高了模型的自我修正能力，并能够有效应对分布偏移问题。通过分阶段的多轮强化学习策略，`SCoRe` 解决了LLM在缺乏强外部反馈任务中的自我矫正困难，并展示了在多种任务中提升策略泛化性的潜力。
