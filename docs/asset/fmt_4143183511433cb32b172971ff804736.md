
# 单独同意的落地案例讨论

> 来源：[https://docs.feishu.cn/docx/G0bPdOw5DoGNmPx9hMLcf7ZZn1e](https://docs.feishu.cn/docx/G0bPdOw5DoGNmPx9hMLcf7ZZn1e)

## 问题

**-问：**大家怎么看这个UI界面设置，必需五个全部勾选才能用。

![](img/3c4243f8dcb2a4236499415c48e4f539.png)

## 回答

**-答1：**我不是儿童，为什么要强制勾选儿童hhh

**-答2：**不哈哈哈哈过年的时候看到，我觉得manner法务牛了，一个勾选5个选项的弹窗，业务没有反弹影响用户体验，也是牛。

**-答3：**敏感个人信息处理，需要触发场景需要单独同意的，提前获取没用吧。

**-答4：**可是必须勾选全部协议才能进入功能，感觉还是不太符合“单独”的要求吧。分几个勾一起捆绑授权了，感觉失去了分开勾选的意义，全选就是一揽子同意了。

**-答5：**这样依然是一揽子同意，而不是在收集敏感个人信息时再按照合法性基础的选择获取单独同意。“单独同意”的核心要义之一就是“单独”，不能与其他协议或同意捆绑进行。

1. 单独同意需要即时触发，而不是提前一揽子获取。

对第三方处理者（不是受托处理者）提供个人信息是需要单独同意（如果没有其他合法性基础），但并不应该在开启服务之前一揽子强制用户授权，而是实际触发哪个场景、需要向该场景下的第三方提供，此时才能申请“单独同意”，即单独同意也应该是“即时”的，而不是提前一揽子先申请一堆授权，这样也违背了“单独同意”的本意。

2. 这种勾选同意向第三方（不知其中是否区分了处理者和单独处理者）提供个人信息的说明，不仅不能构成真正的“单独同意”，且一揽子授权给清单中的全部外部第三方，比一揽子授权给运营方自身，可能风险更大、数据流转链条更复杂和难控制。

3. 当然，也许，这个《向第三方提供个人信息的说明》本身只是一个“告知”——用词是“说明”，放在服务入口处也只是为了增强告知、强化突出，本意仅是想让用户通过点击来表达“我知道了”，并非就真的马上会把用户信息都提供给第三方。但当前这种交互页面设计本身确实会极大引发用户误解，产生隐私保护的焦虑和担心。

在国外产品的入口交互同意机制中，最多见过同一界面中三个勾选框，也是针对通用功能全量用户（非针对单独功能或儿童等特定用户）。这里的“五个勾选”连连看，确实是比较，呃…除了韩国那边大部分做法确实是入口就逐个勾选，用户也没啥体现出流失率等摩擦情况，但注册前的勾选同意不涉及同意“隐私政策”、是个单独的清单，倒还好。
