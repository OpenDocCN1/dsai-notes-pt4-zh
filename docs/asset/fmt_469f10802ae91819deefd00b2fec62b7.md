# LLama简介

从下图可以看出，对于`Llama2`模型而言，其有三个尺寸，分别为`7B`、`13B`和`70B`（B代表Billon个参数，`7B`就是70亿参数，`13B`就是130亿个参数，以此类推）。那这些没有经过后续`Instruction Tuning`（指令微调）的模型都是被我们称为是`base model`（基座模型）。这其实就与我们前两节课所呼应上了，第一节课我们学习的预训练模型其实就是讲述如何训练出一个好的基座模型，然后第二节课所讲述的重点之一就是如何通过指令微调来让模型听得懂人话以及能说人话。为了更好的体现模型的能力，那我们这门课将会使用的也就是那些`Llama 2 7B Chat`这类型模型。

![](img/1df40593e53eded20618c6fff637da02.png)

从`Llama2`官方给出的模型效果看出，整体而言，`Llama2`已经远超其中比较好的开源模型`Falcon 40B`，甚至能力已经接近于2021年爆火的`GPT3.5`的能力与水平了。并且相比于`GPT3.5，Llama`是开源了自己的全部权重和代码，假如我们的算力资源满足要求，我们可以在`Huggingface`、`ModelScope`以及`OpenXLab`上直接进行下载。

顺带提一句就是，其实正是由于`Llama`模型从一开始的开源开放，国产的各种“自研”大模型就像雨后春笋一般生长了起来。确实一个能力媲美于`GPT3.5`的模型其实是能够给各行各业注入一股新的能力。但这也正是Meta希望看到的，Meta通过开源`Llama`模型系列，不仅推动了AI技术的普及和发展，也巧妙地扩大了自身在AI领域的影响力。通过让更多企业和开发者参与到模型的改进和应用中来，Meta实际上在构建一个庞大的AI生态系统。因此你可以说Meta在做慈善，给全世界的AI开发者注入强心剂，那你也可以说Meta图的是整个生态的构建与Meta公司自身的商业价值。要知道Meta之前说All in元宇宙时股价跌到谷底，现在开源`Llama`后股价可是节节攀升的，所以或许这也就是开源的魅力吧。

![](img/f0b74405344a9d231f05d8719e5356c1.png)

除了正常对话的`Chat`模型以外，`Llama`家族中还有一款专门用于代码撰写的模型`Code Llama`。这款模型也是基于预训练出来的`Llama 2 7B/13B/34B`制作而成，并且所有的模型都经过了大量的代码文件进行训练。

那`Code Llama`分为了三个不同的版本，分别是只经过了长文本微调的基础版本（`Code Llama`）。其目的使其能够处理更长的输入序列。这样可以提高模型理解和生成长文本或代码的能力，使其在处理需要更多上下文信息的任务时表现更好。

然后进阶版本（`Code Llama - Instruct`）就是在假如长文本理解的基础上还添加了指令微调的模块，使其能够更好地跟随者我们的提示词完成任务。还有一个`Code Llama - Python`就是专精于回答`Python`的问题。除了代码训练以外额外添加了大量的`Python`代码训练，使得模型在处理`Python`相关任务时会有更出色的表现。

![](img/6f9e88d2ffccbc374e8da3aa4d049293.png)

最后，`Llama2`还提供了一个专注于生成式AI安全性的模型——`Purple Llama`。其主要要解决的问题就是AI生成的代码是安全的且没有信息攻击的风险。并且还有就是希望`LLM`输出的内容是安全的、诚实的以及无害的。

我们可以通过`CyberSecEval`的工具来评估`LLM`的输出是否安全，并且我们也可以利用一个名为`Llama Guard`的分类器来判断内容是否安全。

![](img/f434c1b53b4391226c52fcc9e436ec1b.png)

## 使用方式

我们有多种方式可以接触到`Llama`模型，我们可以通过相关托管平台提供的`API`上付费使用`Llama2`模型，也可以通过自己在云服务器上配置好模型然后给出`API`在本地连接。假如本地算力足够的话，我们其实也可以直接在本地电脑上直接配置。在这里面，看似在本地电脑部署不怎么需要花钱，但是实际上，在本地部署的前提是你的本地电脑已经有足够的算力资源了，比如说一个`7B`的模型可能就需要一张4080以上的显卡才能流程的运行起来。而且真正部署的时候其实会遇到有很多的问题，因此前两种直接调用`API`的方式是更适合于刚入门者使用。

## 查看提示词结构（Verbose）

首先我们需要知道的是，我们输入给大语言模型的提示词并非是我们原来的句子。在当我们输入提示词给到`Llama`模型的时候，为了能够让模型更清楚理解我的的内容和信息，我们的提示词会自动加上一个开头 `<tool_call>` 和一个结尾的特殊符号 `<tool_call>`，这些符号也被称为是`Instruction Tags`。

![](img/30ca023133621726722b57e90d2a4400.png)

当然，对于用户而言，这些其实并不太需要考虑。因为假如我们是通过这种商业`API`调用的话一般都是会自动帮我们加上的。我们可以通过代码看得更加清晰。只要我们加上`verbose=True`，我们就能够看到我们完整输入的提示词（`prompt`）以及所使用的模型（`model`）。默认情况下，直接调用`llama`所使用的模型就是`llama-2-7b-chat`模型。

![](img/28e01ba871806c6ec2b673c23a3bb963.png)

## 指定模型（Model）

我们也可以感受一下预训练模型的样子。我们可以通过设置`model="xxx"`来指定模型，这里我们选择的是`"togethercomputer/llama-2-7b"`来进行测试。当我们问“法国的首都在哪里”的时候，其回答的是`"what is the capital of Germany"`这样的答复，因此可以看出对于这种没有经过指令微调的基座模型，指令跟随的能力是非常差的。

![](img/fd92e0aeaac26eb97385152b82d9f711.png)

## 随机性控制（Temperature）

假如我们希望回复是连续的，而不是有一定随机性的话，我们也可以考虑在代码中加入一个参数`temperature`来进行控制。当我们将`temperature`的值调为`0`（可以理解为模型回复随机性为`0`）时，只要我们问的是同一个问题，无论在什么时候问都会得到同样的答复。

```
prompt = """
Help me write a birthday card for my dear friend Andrew.
Here are details about my friend:
He likes long walks on the beach and reading in the bookstore.
His hobbies include reading research papers and speaking at conferences.
His favorite color is light blue.
He likes pandas.
"""
response = llama(prompt, temperature=0.0)
print(response)
```

> `Temperature` 是一个用于控制语言模型输出随机性的关键参数。它通常是一个介于 0 到 1 之间的数值，影响模型在生成文本时的"创造性"程度。较低的 `temperature` 会使模型倾向于选择最可能的词，产生更加保守和一致的输出；而较高的 `temperature` 则会增加低概率词被选中的机会，导致更加多样化但可能不那么连贯的结果。

> [`temperature`，`topk`傻傻分不清？一文带你读懂LLM推理超参](https://larkcommunity.feishu.cn/wiki/Vyl1wWDFNi0jdRkBeyVcvNHbnLh)一步理解`temperature`可以阅读我们往期文章

## 控制最长输出（Max_Token）

对于`llama2`模型而言，输入输出的尺寸也是有限制的，其输入输出的总和不能够超过`4097`个`token`。就比如下面这个例子，我们给的输入是`3974`个`token`，那我们剩下给输出的`token`就只剩下`4097-3974=123`个`token`了，假如我们设置的输出超过`123`个`token`的话，这个程序就会报错。

![](img/c29246797130c124b5795c141db4a796.png)

因此我们需要设定`response`的`max_token`为`123`才能保证程序的正确运行。因此的话，我们也可以自动为模型添加一个检查输入的`token`然后用`4097`减去它，这样除非输入本身就大于`4097`个`token`了，不然就能够保证程序不会出现报错。

```
# set max_tokens to stay within limit on input + output tokens
prompt = f"""
Give me a summary of the following text in 50 words:\n\n
{text}
"""
response = llama(prompt,
                max_tokens=123)
```

## 记忆

对于我们直接调用的模型，其实是不会记得我们之前输入的上下文的。

![](img/a90e316bc9195287b5dbd4b85d8381e7.png)

这主要是因为我们并没有将之前的内容输入作为上下文输入给模型让其为我们回复。

![](img/5b762bcd6b6ffadc09d4033198da4320.png)

但是这里所说的上下文并不是直接把对话输入进去即可，其实理论上我们是需要加上`start tags`和`end tags`以及`prompt`相关的 `<tool_call>` 这种特殊符号才能让模型完全看懂这是上下文的内容。不然的话模型就只是看到了一大段话而看不懂这是一轮轮的对话。

![](img/737bf04af1a567ec16b063c4c925dd24.png)

那其实我们可以在代码层面上手动添加。比如下面这样，我们设定好了第一个`prompt`以及回复`response`，然后再添加第二个想要其回答的问题。接下来我们自己构建起一个`chat_prompt`把这两个都囊括进去，并且添加上这些特殊符号后，统一作为新的`prompt`传给模型。这个时候模型也会基于我们之前的回复给予我们答案。

```
prompt_1 = """
    What are fun activities I can do this weekend?
"""
response_1 = llama(prompt_1)

prompt_2 = """
Which of these would be good for my health?
"""

chat_prompt = f"""
<s> <tool_call> {prompt_1} <tool_call>
{response_1}
</s>
<s> <tool_call> {prompt_2} <tool_call>
"""
print(chat_prompt)

response_2 = llama(chat_prompt,
                 add_inst=False,
                 verbose=True)
                 
print(response_2)
```

除此之外，我们其实可以直接从`Together.AI`中的一个名为`llama_chat`的库调用一些方法让我们不用手动添加这些特殊符号。

我们从代码中可以看到，我们只需要输入`prompts = [prompt_1, prompt_2]`（也就是之前所有输入的`prompt`）以及`responses = [response_1]`（之前所有输出的`response`）就可以让系统自动为我们加上特殊符号，然后在输入到模型的时候把这些`prompts`和`responses`放进去即可。

```
# 之前是from utils import llama
from utils import llama_chat

prompt_1 = """
    What are fun activities I can do this weekend?
"""
response_1 = llama(prompt_1)

prompt_2 = """
Which of these would be good for my health?
"""

prompts = [prompt_1,prompt_2]
responses = [response_1]

# Pass prompts and responses to llama_chat function
response_2 = llama_chat(prompts,responses,verbose=True)

print(response_2)
```

当然，随着我们聊天得越多，上下文其实也会越来越长，可能就会超过模型规定的最大上下文数，导致模型无法使用。而且越长的长下文代表需要花费的算力或者说金钱就越多，因此如何选择合适的记忆方式是一个非常值得考究的话题。

之前在`Langchain`里就有过几个方案，一个就是和这个一样全部保留，还有就是总结一些这些上下文然后进行传递，另外还有就是只保留上一次的对话内容，最后还有就是只保留`500`个`token`的内容。这些都是可选择的方案，大家也可以根据情况酌情选择。

# LLama简介

从下图可以看出，对于`Llama2`模型而言，其有三个尺寸，分别为`7B`、`13B`和`70B`（B代表Billon个参数，`7B`就是70亿参数，`13B`就是130亿个参数，以此类推）。那这些没有经过后续`Instruction Tuning`（指令微调）的模型都是被我们称为是`base model`（基座模型）。这其实就与我们前两节课所呼应上了，第一节课我们学习的预训练模型其实就是讲述如何训练出一个好的基座模型，然后第二节课所讲述的重点之一就是如何通过指令微调来让模型听得懂人话以及能说人话。为了更好的体现模型的能力，那我们这门课将会使用的也就是那些`Llama 2 7B Chat`这类型模型。

![](img/1df40593e53eded20618c6fff637da02.png)

从`Llama2`官方给出的模型效果看出，整体而言，`Llama2`已经远超其中比较好的开源模型`Falcon 40B`，甚至能力已经接近于2021年爆火的`GPT3.5`的能力与水平了。并且相比于`GPT3.5，Llama`是开源了自己的全部权重和代码，假如我们的算力资源满足要求，我们可以在`Huggingface`、`ModelScope`以及`OpenXLab`上直接进行下载。

顺带提一句就是，其实正是由于`Llama`模型从一开始的开源开放，国产的各种“自研”大模型就像雨后春笋一般生长了起来。确实一个能力媲美于`GPT3.5`的模型其实是能够给各行各业注入一股新的能力。但这也正是Meta希望看到的，Meta通过开源`Llama`模型系列，不仅推动了AI技术的普及和发展，也巧妙地扩大了自身在AI领域的影响力。通过让更多企业和开发者参与到模型的改进和应用中来，Meta实际上在构建一个庞大的AI生态系统。因此你可以说Meta在做慈善，给全世界的AI开发者注入强心剂，那你也可以说Meta图的是整个生态的构建与Meta公司自身的商业价值。要知道Meta之前说All in元宇宙时股价跌到谷底，现在开源`Llama`后股价可是节节攀升的，所以或许这也就是开源的魅力吧。

![](img/f0b74405344a9d231f05d8719e5356c1.png)

除了正常对话的`Chat`模型以外，`Llama`家族中还有一款专门用于代码撰写的模型`Code Llama`。这款模型也是基于预训练出来的`Llama 2 7B/13B/34B`制作而成，并且所有的模型都经过了大量的代码文件进行训练。

那`Code Llama`分为了三个不同的版本，分别是只经过了长文本微调的基础版本（`Code Llama`）。其目的使其能够处理更长的输入序列。这样可以提高模型理解和生成长文本或代码的能力，使其在处理需要更多上下文信息的任务时表现更好。

然后进阶版本（`Code Llama - Instruct`）就是在假如长文本理解的基础上还添加了指令微调的模块，使其能够更好地跟随者我们的提示词完成任务。还有一个`Code Llama - Python`就是专精于回答`Python`的问题。除了代码训练以外额外添加了大量的`Python`代码训练，使得模型在处理`Python`相关任务时会有更出色的表现。

![](img/6f9e88d2ffccbc374e8da3aa4d049293.png)

最后，`Llama2`还提供了一个专注于生成式AI安全性的模型——`Purple Llama`。其主要要解决的问题就是AI生成的代码是安全的且没有信息攻击的风险。并且还有就是希望`LLM`输出的内容是安全的、诚实的以及无害的。

我们可以通过`CyberSecEval`的工具来评估`LLM`的输出是否安全，并且我们也可以利用一个名为`Llama Guard`的分类器来判断内容是否安全。

# 开始尝试Llama2

## 使用方式

我们有多种方式可以接触到`Llama`模型，我们可以通过相关托管平台提供的`API`上付费使用`Llama2`模型，也可以通过自己在云服务器上配置好模型然后给出`API`在本地连接。假如本地算力足够的话，我们其实也可以直接在本地电脑上直接配置。在这里面，看似在本地电脑部署不怎么需要花钱，但是实际上，在本地部署的前提是你的本地电脑已经有足够的算力资源了，比如说一个`7B`的模型可能就需要一张4080以上的显卡才能流程的运行起来。而且真正部署的时候其实会遇到有很多的问题，因此前两种直接调用`API`的方式是更适合于刚入门者使用。

## 查看提示词结构（Verbose）

首先我们需要知道的是，我们输入给大语言模型的提示词并非是我们原来的句子。在当我们输入提示词给到`Llama`模型的时候，为了能够让模型更清楚理解我的的内容和信息，我们的提示词会自动加上一个开头 `<tool_call>` 和一个结尾的特殊符号 `<tool_call>`，这些符号也被称为是`Instruction Tags`。

![](img/30ca023133621726722b57e90d2a4400.png)

当然，对于用户而言，这些其实并不太需要考虑。因为假如我们是通过这种商业`API`调用的话一般都是会自动帮我们加上的。我们可以通过代码看得更加清晰。只要我们加上`verbose=True`，我们就能够看到我们完整输入的提示词（`prompt`）以及所使用的模型（`model`）。默认情况下，直接调用`llama`所使用的模型就是`llama-2-7b-chat`模型。

![](img/28e01ba871806c6ec2b673c23a3bb963.png)

## 指定模型（Model）

我们也可以感受一下预训练模型的样子。我们可以通过设置`model="xxx"`来指定模型，这里我们选择的是`"togethercomputer/llama-2-7b"`来进行测试。当我们问“法国的首都在哪里”的时候，其回答的是`"what is the capital of Germany"`这样的答复，因此可以看出对于这种没有经过指令微调的基座模型，指令跟随的能力是非常差的。

## 随机性控制（Temperature）

假如我们希望回复是连续的，而不是有一定随机性的话，我们也可以考虑在代码中加入一个参数`temperature`来进行控制。当我们将`temperature`的值调为`0`（可以理解为模型回复随机性为`0`）时，只要我们问的是同一个问题，无论在什么时候问都会得到同样的答复。

```
prompt = """
Help me write a birthday card for my dear friend Andrew.
Here are details about my friend:
He likes long walks on the beach and reading in the bookstore.
His hobbies include reading research papers and speaking at conferences.
His favorite color is light blue.
He likes pandas.
"""
response = llama(prompt, temperature=0.0)
print(response)
```

> `Temperature` 是一个用于控制语言模型输出随机性的关键参数。它通常是一个介于 0 到 1 之间的数值，影响模型在生成文本时的"创造性"程度。较低的 `temperature` 会使模型倾向于选择最可能的词，产生更加保守和一致的输出；而较高的 `temperature` 则会增加低概率词被选中的机会，导致更加多样化但可能不那么连贯的结果。

> [`temperature`，`topk`傻傻分不清？一文带你读懂LLM推理超参](https://larkcommunity.feishu.cn/wiki/Vyl1wWDFNi0jdRkBeyVcvNHbnLh)一步理解`temperature`可以阅读我们往期文章

## 控制最长输出（Max_Token）

对于`llama2`模型而言，输入输出的尺寸也是有限制的，其输入输出的总和不能够超过`4097`个`token`。就比如下面这个例子，我们给的输入是`3974`个`token`，那我们剩下给输出的`token`就只剩下`4097-3974=123`个`token`了，假如我们设置的输出超过`123`个`token`的话，这个程序就会报错。

![](img/c29246797130c124b5795c141db4a796.png)

因此我们需要设定`response`的`max_token`为`123`才能保证程序的正确运行。因此的话，我们也可以自动为模型添加一个检查输入的`token`然后用`4097`减去它，这样除非输入本身就大于`4097`个`token`了，不然就能够保证程序不会出现报错。

```
# set max_tokens to stay within limit on input + output tokens
prompt = f"""
Give me a summary of the following text in 50 words:\n\n
{text}
"""
response = llama(prompt,
                max_tokens=123)
```

## 记忆

对于我们直接调用的模型，其实是不会记得我们之前输入的上下文的。

![](img/a90e316bc9195287b5dbd4b85d8381e7.png)

这主要是因为我们并没有将之前的内容输入作为上下文输入给模型让其为我们回复。

![](img/5b762bcd6b6ffadc09d4033198da4320.png)

但是这里所说的上下文并不是直接把对话输入进去即可，其实理论上我们是需要加上`start tags`和`end tags`以及`prompt`相关的 `<tool_call>` 这种特殊符号才能让模型完全看懂这是上下文的内容。不然的话模型就只是看到了一大段话而看不懂这是一轮轮的对话。

![](img/737bf04af1a567ec16b063c4c925dd24.png)

那其实我们可以在代码层面上手动添加。比如下面这样，我们设定好了第一个`prompt`以及回复`response`，然后再添加第二个想要其回答的问题。接下来我们自己构建起一个`chat_prompt`把这两个都囊括进去，并且添加上这些特殊符号后，统一作为新的`prompt`传给模型。这个时候模型也会基于我们之前的回复给予我们答案。

```
prompt_1 = """
    What are fun activities I can do this weekend?
"""
response_1 = llama(prompt_1)

prompt_2 = """
Which of these would be good for my health?
"""

chat_prompt = f"""
<s> <tool_call> {prompt_1} <tool_call>
{response_1}
</s>
<s> <tool_call> {prompt_2} <tool_call>
"""
print(chat_prompt)

response_2 = llama(chat_prompt,
                 add_inst=False,
                 verbose=True)
                 
print(response_2)
```

除此之外，我们其实可以直接从`Together.AI`中的一个名为`llama_chat`的库调用一些方法让我们不用手动添加这些特殊符号。

我们从代码中可以看到，我们只需要输入`prompts = [prompt_1, prompt_2]`（也就是之前所有输入的`prompt`）以及`responses = [response_1]`（之前所有输出的`response`）就可以让系统自动为我们加上特殊符号，然后在输入到模型的时候把这些`prompts`和`responses`放进去即可。

```
# 之前是from utils import llama
from utils import llama_chat

prompt_1 = """
    What are fun activities I can do this weekend?
"""
response_1 = llama(prompt_1)

prompt_2 = """
Which of these would be good for my health?
"""

prompts = [prompt_1,prompt_2]
responses = [response_1]

# Pass prompts and responses to llama_chat function
response_2 = llama_chat(prompts,responses,verbose=True)

print(response_2)
```

当然，随着我们聊天得越多，上下文其实也会越来越长，可能就会超过模型规定的最大上下文数，导致模型无法使用。而且越长的长下文代表需要花费的算力或者说金钱就越多，因此如何选择合适的记忆方式是一个非常值得考究的话题。

之前在`Langchain`里就有过几个方案，一个就是和这个一样全部保留，还有就是总结一些这些上下文然后进行传递，另外还有就是只保留上一次的对话内容，最后还有就是只保留`500`个`token`的内容。这些都是可选择的方案，大家也可以根据情况酌情选择。

# 提示词工程技巧

`Prompt Engineering` 是一种技术，允许你通过特定指令或包含不同类型的信息（即"上下文"）来引导模型改善其对你任务的响应。有几种方法可以实现这一点：

1. 提供你正在尝试执行的任务的示例

2. 指定模型如何格式化响应

3. 要求模型在创建响应时假设特定的"角色或人格"

4. 包含额外的信息或数据供模型在其响应中使用
