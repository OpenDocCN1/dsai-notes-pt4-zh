
# SDK就是受托处理吗

> 来源：[https://docs.feishu.cn/docx/RFuZdT7tNoAetSxAbkDcFleKnXd](https://docs.feishu.cn/docx/RFuZdT7tNoAetSxAbkDcFleKnXd)

- **问：**请教下SDK和普通的受托处理有啥区别啊？比如说，委托第三方做短信验证，这个算SDK吗？还是就是普通的受托处理？还有比如说在线支付。我看到有的当SDK列，有的就是普通的受托处理列

- **答1：**sdk会变成数据共享的。可委托，可共享。不交代清楚，谁都不知道最后是什么。

- **答2：**SDK并不必然对应一种处理关系吧？SDK是指调用技术，不是处理关系。

- **答3：**我感觉，关键还是SDK和APP的关系吧，SDK的全称为：Software Development Kit，想要了解SDK，得先了解一些基础概念，重要的是API以及APP；SDK跟处理关系是不对应的，需要看SDK的具体实现的功能。这是一文介绍，了解一下基础概念先：`https://zhuanlan.zhihu.com/p/93764518`。

- **答4：**粗鲁点说，SDK是老王跑家里了 ，Api是老婆去老王家了。所以App 有对SDK审核的责任。Sdk 产生的目的是减少开发成本，不一定对外传输，还有本地化部署的。比如是bugly 正常不应该对外传输。

- **追问：**如何识别是不是SDK呢？怎么查？

- **答5：**你注册一个免费的阿里云账号 他们就有免费的app合规机器检测扫描服务。

- **答6：**（补一句，api还有其他用处，跟sdk不是一对一关系

- **答7：**SDK和APP及API的关系，知识库中都有。

![](img/4a8f88930c623cae406add4d4fa2feed.png)

- **答8：**从应用角度来讲，sdk或者插件，组件，架包，其实指的都是一类意思。他们可以做应用能做的一切事情，但是他们不能独立运行。他们只能投靠一个爸爸，就是APP来实现功能的调用。在标准应用里面，其实sdk没那么可怕，因为宿主，就是爸爸是可以管制这个投靠的干儿子的。让他干嘛就干嘛，让他滚蛋就滚蛋。但是在安卓系统里面却不是。你只要APP初始化了sdk，后面sdk做任何事情都不受APP管控了，说白了就是失控状态了。所以就隐私保护这块，监管不得不强调sdk也要合规。因为太多的APP只管引入，等到发现失控后(个人信息获取严重违规)，监管去处罚APP，很难奏效。最棘手的问题就是APP也不知道sdk哪里在做坏事。除非彻底不用。而且头部企业的sdk是带头违规的，就是根本没有谁做的合规一说，市场就乱糟糟了。通过2、3年的APP整改，大部分sdk能能基本合规，这时候总算可以单独查查他们了。否则法不责众，板子打不下去。另外再哪个国标里面，插件，sdk都在描述里面。所以监管说sdk只是个统称，真要查插件一样可以查的。

![](img/cee8700c1095371aea256a12e19eda86.png)

而且sdk的使用情况五花八门。企业里面同一个APP，有些就是写成模块代码，有些就是把代码封装成sdk，给大家公用。因为公共代码或者基础功能，可能是专门一个研发部门开发的。对于业务研发部门，他们不需要了解太多功能实现，也不想因为集成这些代码，很复杂的每次去更新代码。所以就把他们做成sdk了。

- **答9：**35273里讲共同控制者的时候就是用插件的表述，然后sdk在插件里面。

### 总结

法律背景的朋友做数据合规还是要多多了解技术基础知识，不然和技术和产品沟通，会很困难。
