
### 使用场景

+ 复杂问题解答：法律咨询、医疗诊断建议

### 优点

+ 信息完整性高，减少理解偏差

+ 结构化设计提升指令清晰度

### 缺点

+ 要素较多，构建成本较高

+ 简单任务使用时可能过于繁琐

### 示例

```
Task：撰写AIGC技术在教育领域的应用前景报告
Request：包含智能辅导系统、个性化学习内容生成、作业自动批改等应用场景分析
Action：收集近三年相关学术论文与企业案例，进行技术成熟度与市场渗透率分析
Context：中国教育数字化转型政策推动，K12阶段AI教育产品使用率年增长25%
Example：参考《2024年全球教育科技趋势报告》中关于生成式AI的章节结构
```

## 15. ERA 框架

### 原理

+ 包含期望（Expectation）、要求（Requirement）、行动（Action）三要素

+ 通过结果期望、具体要求与执行行动的明确界定，构建简洁高效的 Prompt 框架

### 功能

+ 快速明确任务目标与执行标准

+ 简洁结构适用于日常任务交互

### 使用场景

+ 内容生成：文章创作、报告撰写

+ 智能问答：信息查询、知识检索

### 优点

+ 轻量化设计便于快速使用

+ 目标与要求的明确对应提升效率

### 缺点

+ 复杂任务的细节描述不足

+ 缺乏场景化背景支撑

### 示例

```
Expectation：生成关于量子计算商业应用的科普文章
Requirement：包含金融建模、药物研发、密码学三个应用领域的通俗解释
Action：采用类比说明（如&quot;量子计算与传统计算的速度差异相当于飞机与自行车&quot;），避免专业术语堆砌
```

## 16、STAR 框架

### 原理

+ 源自情境面试方法论，包含情境（Situation）、任务（Task）、行动（Action）、结果（Result）

+ 通过场景还原、任务定义、行动规划与结果评估，构建叙事型 Prompt

### 功能

+ 适用于需要故事化表达的场景，如案例撰写、经验分享

+ 逻辑链条完整，便于模型生成结构化叙事内容

### 使用场景

+ 案例复盘与经验沉淀：企业内部最佳实践总结（如危机处理案例、项目成功经验）、个人履历 / 面试素材整理（行为面试问题回答框架）。

+ 叙事型内容创作：品牌故事撰写、用户成功案例包装、营销文案中的场景化叙事（如产品使用场景还原）。

+ 问题解决过程可视化：技术故障排查报告、运营活动复盘分析、跨部门协作问题处理记录。

### 优点

+ 逻辑闭环性：从场景到结果的完整链条，确保叙事逻辑清晰，符合人类认知习惯。

+ 细节引导力：通过四要素强制拆解任务，避免内容空洞（如 Action 需具体到可执行步骤）。

+ 跨场景通用性：既适用于技术、运营等专业领域，也可用于日常沟通（如工作总结汇报）。

### 缺点

+ 创作成本较高：需完整还原场景细节，复杂案例的要素填充耗时较长。

+ 灵活性不足：严格的四步结构可能限制创意表达，不适合开放式头脑风暴场景。

+ 结果量化依赖：若缺乏可量化的 Result（如 “用户满意度提升” 需具体数据支撑），叙事说服力可能减弱。

### 示例

```
Situation：某电商平台在大促期间遭遇服务器崩溃
Task：制定应急响应与用户安抚方案
Action：①启动备用服务器集群 ②向用户推送补偿方案公告 ③组建专项客服团队处理咨询
Result：4小时内恢复系统，用户满意度回升至90%，后续3天销售额追回85%
```

## 17、PDCA 框架

### 原理

+ 质量管理循环框架，包含计划（Plan）、执行（Do）、检查（Check）、处理（Act）

+ 用于构建迭代优化型 Prompt，支持持续改进的任务流程

### 功能

+ 适用于需要分阶段实施与优化的任务，如产品迭代、流程改进

+ 闭环设计确保任务持续优化

### 使用场景

+ 产品与流程迭代：软件版本迭代规划、运营活动优化（如促销策略调整）、服务流程改进（如客服响应效率提升）。

+ 实验性任务管理：A/B 测试方案设计、用户增长黑客策略、市场调研结论验证（如新品定价测试）。

+ 质量管理体系：制造业流程优化、内容审核标准迭代、项目风险控制（如分阶段里程碑检查）。

### 优点

+ 科学闭环性：遵循 “计划 - 执行 - 检查 - 改进” 的科学方法论，降低决策盲目性。

+ 数据驱动性：Check 环节强制要求数据验证，避免主观判断导致的偏差。

+ 持续进化性：Act 阶段支持经验沉淀与策略升级，适合长期优化场景（如季度 OKR 迭代）。

### 缺点

+ 周期较长：完整循环需经历四个阶段，不适用于紧急或短期任务（如突发公关事件）。

+ 数据依赖度高：Check 环节需充足数据支撑，若数据采集困难（如小众市场调研），框架效果会打折扣。

+ 初期规划压力大：Plan 阶段需明确目标与方案，对未知领域（如全新业务线）的规划难度较高。

### 示例

```
Plan：设计用户增长实验方案，测试A/B版落地页转化率
Do：在20%用户群体中部署A版与B版落地页
Check：对比两周内两组用户的注册转化率与跳出率
Act：根据测试结果，将转化率提升15%的版本全量推广，并规划下一阶段实验
```

# 五、Prompt 框架应用策略

### 框架选择矩阵

| 任务类型 | 推荐框架 | 核心优势 |
| --- | --- | --- |
| 目标管理 | BROKE、OKR 融合框架 | 量化指标与迭代优化 |
| 复杂问题解决 | COAST、ROSES | 全要素拆解与场景化分析 |
| 创意内容创作 | CRISPE、RACE | 角色定位与风格控制 |
| 数据分析 | ICIO、CREATE | 数据驱动与精准输出 |
| 流程规划 | RISE、TAG | 步骤化指导与目标对齐 |
| 个性化服务 | CHAT、CARE | 场景共鸣与示例参考 |

### 多框架组合技巧

1. **目标-执行联动**：BROKE 框架设定目标，结合 RISE 框架规划执行步骤

2. **创意-规范平衡**：CRISPE 框架定义创作风格，通过 RTF 框架规范输出格式

3. **复杂任务拆解**：COAST 框架进行全景分析，配合 TRACE 框架构建详细指令

4. **持续优化循环**：PDCA 框架驱动迭代，结合 CREATE 框架进行 Prompt 优化
