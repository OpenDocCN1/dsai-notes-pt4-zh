
# AI 视频技术概述

## 技术趋势
技术趋势方面，AI视频模型在性能迭代上，动态效果更自然流畅，通过运镜增加画面动感。例如，快手可灵1.5模型在动态质量上显著提升，字节豆包视频模型在动作连贯性和运镜表现上突出。此外，AI视频功能创新，如视频编辑、音效匹配、个性化视频和视频特效等，提高视频生成的可控性和趣味性。

## 应用落地
应用落地方面，随着API接口的密集发布，AI视频技术有望在C端社交娱乐、中短视频内容创作和专业级影视创作三大场景加速落地。例如，Meta Movie Gen提出新的技术路线，采用Transformer+流匹配架构，相比传统的扩散模型，新方法训练更高效，计算成本更低，生成结果在时间维度上具有更好的连续性和一致性。

## 技术创新
技术创新方面，Meta Movie Gen发布了92页的技术报告，详细披露了训练方法、架构设计等，为其他厂商提供了新的视频模型开发思路。报告中提到，Movie Gen由两个模型组成，包括300亿参数的视频模型和130亿参数的音频模型，沿用了Llama3的架构设计。Meta还开源了多个基准测试数据集，为AI视频领域的进步提供了评测工具和方法。

## GPT4o Realtime voice功能的复现路径

https://zhuanlan.zhihu.com/p/1387019285

网络架构：

+ `Speech Encoder` 使用`Whisper-Large-3`的编码器功能，将语音转化为语音表示（speech representations）。

+ `Speech Adaptor` 通过下采样匹配LLM的输入嵌入空间。

+ LLM部分 使用`LLaMA-3.1-8b`模型处理语音指令和生成文本回应。

+ `Speech Decoder` 通过上采样将LLM的输出转换为适合语音解码的格式。

+ `Vocoder` 最终将离散单元转换为语音。

训练过程分为两个阶段：

+ 第一阶段 冻结大部分参数，训练Speech Adaptor和LLM的集成，使得语音输入能够顺畅地通过下采样进入LLM。

+ 第二阶段 只训练Decoder部分，将LLM的文本输出转化为语音，通过上采样恢复到合适的语音格式，使用`CTC`损失函数来优化生成的语音单元。

流式处理：

+ 流式非自回归语音解码技术确保在LLM生成文本的同时，逐步生成对应的语音单元，提升响应速度。

+ 通过调整单元块大小来权衡系统的延迟和语音质量，优化后的延迟可低至226毫秒，优于GPT-4o的320毫秒。

数据集：使用`InstructS2S-200K`数据集，包括语音指令、文本回复和语音回复，通过TTS模型生成自然的语音数据。

## 训练大语言模型时公式表格等数据如何进行预处理和微调?

https://www.zhihu.com/question/625122736/answer/3636496581

数据预处理：

+ 文本分词与词嵌入：对于文本数据，首先需要对文本进行分词，将文本分割为单词或子词（token），并将这些token映射到对应的ID，然后生成嵌入向量（word embeddings）。传统方法如`Word2Vec`通过上下文预测生成词向量，但在LLM中，词嵌入通常与模型训练同时进行。

+ 特殊字符处理：分词后会将特殊符号、标点符号保留为单独的token，如逗号、句号等。此外，像`BPE（Byte Pair Encoding）`这种算法能有效压缩词汇表，是GPT系列模型中常用的分词方式。针对公式、表格中的特殊字符或数学符号，可以用特殊的token进行标注，如`<|unk|>`表示未知字符。

非文本数据处理：

+ 对于公式、表格等数据，需通过特殊的标记方式处理。例如，公式中的变量和操作符可以分成token，并将其转化为对应的嵌入向量。同时，特殊结构如表格中的行列信息需通过特殊符号（如`<|row_start|>`和`<|col_start|>`)标记以确保模型能够理解其结构。

数据加载与采样策略：

+ 为了提升训练效率，文本被划分为多个输入块，模型通过滑动窗口策略生成输入-输出对。这种方法对LLM非常重要，因为其训练任务是基于上下文预测下一个token。

+ 数据采样通常采用滑动窗口的方式，并使用`PyTorch`等深度学习框架将输入文本转化为张量，确保在大规模数据处理时高效运行。

位置编码：

+ 由于LLM无法感知序列中token的位置关系，需要通过位置编码（`position embedding`）增强模型的空间感知能力。位置编码可以是绝对或相对形式，帮助模型理解文本中词语的顺序。

## 再论MindSpore——桎梏篇

https://zhuanlan.zhihu.com/p/1471462968

历史回顾：`MindSpore`诞生于昇腾芯片，早期以支持昇腾硬件为主，强调整图编译与算子优化，尽管在某些领域取得了成功，如鹏城盘古项目。但ChatGPT的出现带来了LLM的训练热潮，国内AI生态迅速追赶国际，但受制于硬件限制（如英伟达禁运），昇腾910的局限性暴露无遗。此时，`Pytorch`开始支持昇腾，使得`MindSpore`逐渐失去市场吸引力。

1. 动态图 vs 静态图：`MindSpore`最初强调静态图编译，适合算子融合和性能优化，但开发调试困难。相比之下，`Pytorch`的动态图模式因其易用性占据主导地位。作者指出，虽然两者在技术实现上殊途同归，都通过`ByteCode`动态修改进行子图优化，但`MindSpore`的静态图路线失去了开发者的青睐。

1. 核心竞争力与局限：

+ 自动并行：`MindSpore`旨在通过自动并行解决大规模分布式训练的难题，让算法工程师专注于算法和配置。然而，框架复杂的错误调试和算子级并行实现的糟糕选择使得这一优势未能充分发挥。

+ 融合计算：`MindSpore`试图通过`AI4Science`扩展其应用范围，兼容`Pandas`、`NumPy`等，但由于性能和兼容性问题，其发展受到限制。

## Trainer系列2-保存、恢复、监控、日志

https://zhuanlan.zhihu.com/p/1457715203

Trainer系列1：训练与评估：介绍了基本的训练与评估功能。

Trainer系列2：保存、恢复、监控、日志（本节重点）：详细讨论了如何控制训练状态，包括日志记录、检查点保存以及如何从检查点恢复训练。关键内容包括：

+ 训练状态控制：通过`TrainerState`和`TrainerControl`来管理训练中的`epoch`、`step`、`batch_size`、`metrics`等信息，确保能够进行检查点保存和恢复训练。

+ 回调与事件处理：`TrainerCallback`允许用户定义在不同阶段（如`epoch`、`step`、评估等）的事件处理。`CallbackHandler`负责协调回调，并在训练过程中适时触发。
