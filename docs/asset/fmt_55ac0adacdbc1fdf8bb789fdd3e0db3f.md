## 模型选型考量因素 —— 从需求出发的综合决策

### 脉络

将前面的评估维度和模型比较，落地到用户自身的实际需求和约束条件上，形成一个决策流程。

### 决策框架/清单

#### ① 定义核心任务（Task Needs）

首要问题：你想用 LLM 做什么？（聊天机器人？代码助手？文档分析？创意写作？多模态应用？）

匹配模型特长：选择在你的核心任务上表现突出的模型。

#### ② 明确性能要求（Performance Req.）

需要 SOTA 级别的准确率吗？还是“足够好”即可？

对响应速度（Latency）有要求吗？

对输出的创造性/多样性有要求吗？

#### ③ 评估成本预算（Cost Budget）

API 调用成本：预估 Token 消耗量和费用。

自部署成本（若考虑开源）：硬件购置/租赁、运维人力。

总拥有成本（TCO）。

#### ④ 审视数据隐私与安全（Data Privacy & Security）

**关键问题：** 是否处理敏感数据（用户隐私、商业机密）？

**决策影响：** 若是，则强烈倾向于选择可私有化部署的开源模型，或有严格数据处理协议、可信赖的企业级闭源服务。

#### ⑤ 盘点开发与运维资源（Dev Resources）

团队是否有能力部署、配置、微调、监控开源 LLM？

是否有能力进行复杂的 API 集成和应用开发？

#### ⑥ 确定开源/闭源策略倾向（Strategic Preference）

是否希望掌握核心技术，避免供应商锁定？

是否需要高度定制化？

对快速获得最新能力 vs。长期可控性的权衡。

### 最终决策

通常是以上因素的综合权衡，没有绝对最优，只有最适合当前需求和条件的选择。可能需要进行小范围测试（PoC）来验证。

回顾模块三中对 LLM 市场格局的概览，DeepSeek AI 作为国内乃至国际上一个重要的玩家，其独特性在哪里？与 OpenAI、Google、Meta 等巨头相比，它的聚焦点有何不同？

**对比：** 不同于一些快速将模型能力封装成各类应用的公司，DeepSeek AI 将其核心资源投入到攻克基础模型的技术难题上。这包括更先进的模型架构（后续会讲到的 MoE）、更高效的训练与推理方法（如 FP8 应用）、以及更优化的底层算法。这一定位决定了其产出往往具有更强的技术“硬核”属性。

**关联：** 这直接关系到模块二将要深入探讨的 V3/R1 核心技术原理，其技术创新并非空中楼阁，而是源于对基础研究的持续投入。

**对比与意义：** 在模块三我们讨论了开源与闭源的战略差异。DeepSeek AI 不仅选择了开源其强大的 V3/R1 模型，更重要的是，它超越了仅仅开放模型权重的层面，将支撑模型高效运行的关键基础设施库（如 `DeepEP`、`DeepGEMM` 等）也无私地贡献给社区。这是一种更彻底、更“授人以渔”的开放模式。

**影响：** 这种深度的开源极大地降低了其他研究者和开发者复现、改进和应用先进技术的门槛，真正践行并推动了 AI 民主化，也体现了其对技术生态发展的责任感。这是理解 DeepSeek 行业地位和影响力的关键。
