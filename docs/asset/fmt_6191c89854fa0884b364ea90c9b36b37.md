### 6.3.2 上下文管理不当

**问题: AI "忘记"之前的对话或混淆信息**

**症状:**

- AI 重复询问已经提供的信息
- 引用错误的上下文
- 混淆不同项目/任务的信息
- 性能下降(因为上下文过长)

**根本原因:**

**问题 1: 上下文累积过多**

```
会话开始： 2,000 tokens

10 轮对话后： 25,000 tokens

50 轮对话后： 150,000 tokens

100 轮对话后： 超出限制！ ❌
```

**问题 2: 重要信息被"遗忘"**

```
早期对话（被压缩）：

用户： “我的项目叫 MyApp，用 Python 写的”

[…… 50 轮对话 ……]

后期对话：

用户： “帮我优化项目性能”

AI: “请问你的项目是什么语言？” ← 忘记了！
```

**问题 3: 多项目信息混淆**

```
项目 A: Python Web 应用

项目 B: Go 微服务

项目 C: React 前端

AI 可能混淆：

“你的 Go 应用可以使用 Flask 框架……” ← 错误！
```

---

**解决方案:**

**方案 1: 使用 Memory 系统**

```markdown
# 让 AI 主动写入 Memory
用户: "我的项目叫 MyApp,技术栈是 Python + FastAPI + PostgreSQL"

AI: "明白了,我会记住这些信息。"
[AI 调用 memory_write 工具]

# 之后 AI 可以检索
用户: "帮我优化数据库查询"
AI: [调用 memory_search "MyApp database"]
    "根据我的记录,MyApp 使用 PostgreSQL..."
```

**配置 Memory:**

```
# ~/.openclaw/openclaw.yaml
agents:
  defaults:
    memory:
      enabled: true
      backend: "sqlite"  # 或 "qmd"
      
      # 自动记忆触发条件
      auto_remember:
        - pattern: "my project is"
        - pattern: "I'm working on"
        - pattern: "remember that"
      
      # 检索配置
      search:
        max_results: 5
        min_similarity: 0.7
```

方案 2: 使用 Workspace 隔离

```
# 为不同项目创建独立 Workspace
mkdir -p ~/projects/myapp/.openclaw
cd ~/projects/myapp

# 在项目目录启动 OpenClaw
openclaw gateway --workspace ./.openclaw

# 每个 Workspace 有独立的:
# - 会话历史
# - Memory 数据库
# - 配置文件
```

**方案 3: 定期压缩和总结**

```
# 配置自动总结
agents:
  defaults:
    contextPruning:
      mode: "summarize"
      trigger: 0.7  # 70% 时触发
      
      summarization:
        prompt: |
          Summarize the conversation so far, focusing on:
          1. Key decisions made
          2. Important facts about the project
          3. Ongoing tasks and their status
          
          Keep the summary under 500 tokens.
```

方案 4: 使用结构化 Memory 文件

```
# ~/.openclaw/workspace/memory/project-info.md
---
project: MyApp
tech_stack:
  backend: Python + FastAPI
  database: PostgreSQL
  frontend: React
deployment: AWS ECS

- Microservices architecture
- API Gateway: Kong
- Message Queue: RabbitMQ

- Optimizing database queries

```

**方案 5: 显式引用上下文**

```
❌ 不好的做法:
用户: "优化它"
AI: "优化什么?" ← 上下文不清

✅ 好的做法:
用户: "优化 user_service.py 中的 get_users() 函数"
AI: "好的,我会优化 user_service.py 的 get_users() 函数..."
```

### 6.3.3 输出格式不稳定

问题： AI 输出格式不一致，难以解析

**症状：**

+   有时返回 JSON，有时返回纯文本

+   表格格式混乱

+   代码块缺少语言标记

+   列表格式不统一

**根本原因：**

+   没有明确指定输出格式

+   System Prompt 不够严格

+   模型的“创造性”导致格式变化

**解决方案：**

方案 1: 使用 JSON Schema 约束

```
tools:
  - name: "analyze_code"
    description: "Analyze code quality"
    output_schema:
      type: "object"
      required: ["summary", "issues", "score"]
      properties:
        summary:
          type: "string"
          maxLength: 200
        issues:
          type: "array"
          items:
            type: "object"
            properties:
              severity: 
                type: "string"
                enum: ["low", "medium", "high"]
              line:
                type: "integer"
              description:
                type: "string"
        score:
          type: "integer"
          minimum: 0
          maximum: 10
```

方案 2: 在 Prompt 中强制格式

````
# System Prompt
You MUST respond in the following JSON format. Do NOT deviate from this structure:

```json
{
  "status": "success" | "error",
  "data": {
    // Your response here
  },
  "metadata": {
    "timestamp": "ISO 8601 timestamp",
    "tokens_used": number
  }
}
```

Example:

```
{
  "status": "success",
  "data": {
    "result": "Analysis complete"
  },
  "metadata": {
    "timestamp": "2026-03-12T12:00:00Z",
    "tokens_used": 1234
  }
}
```

**IMPORTANT**:

+   Always return valid JSON

+   Do NOT include markdown code fences

+   Do NOT add explanatory text outside the JSON
````

**方案 3: 使用模板系统**

```typescript
// 在 Skill 中定义模板
const outputTemplate = `
## Analysis Report

**Summary**: {{summary}}

**Issues Found**: {{issues.length}}

{{#each issues}}
- [{{severity}}] Line {{line}}: {{description}}
{{/each}}

**Quality Score**: {{score}}/10

**Recommendations**:
{{#each recommendations}}
{{@index}}. {{this}}
{{/each}}
`;
```

**方案 4: 后处理和验证**

```
// 验证 AI 输出
function validateOutput(output: string): ParsedOutput {
  try {
    const parsed = JSON.parse(output);
    
    // 验证必需字段
    if (!parsed.summary || !parsed.issues || !parsed.score) {
      throw new Error("Missing required fields");
    }
    
    // 验证数据类型
    if (typeof parsed.score !== 'number' || parsed.score < 0 || parsed.score > 10) {
      throw new Error("Invalid score");
    }
    
    return parsed;
  } catch (error) {
    // 如果解析失败,重新请求
    return retryWithCorrectedPrompt(output, error);
  }
}
```

方案 5: 使用 Function Calling

```
# 利用模型的 Function Calling 能力
tools:
  - name: "report_analysis"
    description: "Report code analysis results"
    parameters:
      type: "object"
      required: ["summary", "issues", "score"]
      properties:
        summary:
          type: "string"
          description: "Brief summary of the analysis"
        issues:
          type: "array"
          description: "List of issues found"
          items:
            type: "object"
            properties:
              severity: 
                type: "string"
                enum: ["low", "medium", "high"]
              line: 
                type: "integer"
              description: 
                type: "string"
        score:
          type: "integer"
          minimum: 0
          maximum: 10
          description: "Code quality score"
```

当使用 Function Calling 时，模型会严格按照 Schema 返回结构化数据。
