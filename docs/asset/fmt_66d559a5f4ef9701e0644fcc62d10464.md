### 零热刀分词器转移（ZeTT）

语言模型（LMs）与其分词器紧密相关，后者将原始文本映射为一系列词汇项（token）。这限制了它们的灵活性：例如，主要在英语上训练的LMs可能在其他自然和编程语言中仍表现良好，但由于其专注于英语的分词器而效率大为降低。为了缓解这一问题，我们应该能够在不降低性能的情况下实时交换原始LM分词器与任意分词器。因此，在这项工作中，我们定义了一个新问题：`ZeTT`。`ZeTT`核心挑战在于为新分词器词汇中的token找到嵌入。由于以前的启发式方法在`ZeTT`场景中通常表现为随机水平，我们提出了一个新解决方案：我们训练一个超网络，以分词器为输入，预测相应的嵌入。我们在实验证明，超网络可泛化到具有编码器（例如，`XLM-R`）和解码器LMs（例如，`Mistral-7B`）的新分词器。我们的方法在跨语言和编码任务中接近原始模型的表现，同时大幅减少了token化序列的长度。我们还发现，剩余差距可以通过对少于10亿个token进行持续训练迅速缩小。最后，我们展示了为基础（L）LM训练的`ZeTT`超网络也可应用于精调变体而无需额外训练。总的来说，我们的结果在将LMs与其分词器分离方面取得了重大进展。

### 课程数据排序：通过课程学习提升大语言模型性能

贡献人：

链接：`http://arxiv.org/abs/2405.07490v1`

大语言模型（LLMs）的快速发展提高了文本理解和生成能力，但也带来了计算资源方面的挑战。本研究提出了受课程学习启发的数据中心训练策略，从简单任务开始，逐渐过渡到更复杂的任务，利用提示长度、注意力分数和损失值等标准来构建训练数据。使用`Mistral-7B`和`Gemma-7B`模型进行的实验表明，课程学习与传统的随机数据洗牌相比略有改善性能。值得注意的是，我们观察到，基于我们提出的注意力标准对数据进行排序通常会导致更好的性能。这种方法提供了一种可持续的方法来提高LLM的性能，而不增加模型大小或数据集体积，解决了LLM训练中的可扩展性挑战。

### CoRE: LLM作为自然语言编程、伪代码编程和AI智能体编程的解释器

贡献人：

链接：`http://arxiv.org/abs/2405.06907v1`

自编程语言诞生以来，趋向于更易读性和降低程序员的难度。自然语言可能是一种有前途的编程语言类型，提供了极大的灵活性和可用性，有助于编程的民主化。然而，自然语言固有的模糊性、歧义性和冗长性给开发一个能准确理解编程逻辑并执行自然语言指令的解释器带来了显著挑战。最近大语言模型技术的进展表现出了在理解复杂自然语言方面出色的能力。本文受此启发，开发了一个新颖的代码表示和执行系统（`CoRE`），利用大语言模型作为解释器来解释和执行自然语言指令。提出的系统统一了自然语言编程、伪代码编程和流程编程，使用相同的表示形式来构建语言智能体，而大语言模型则作为解释器来解释和执行智能体程序。在本文中，我们首先定义了一种以逻辑方式结构自然语言指令的编程语法。在执行过程中，我们加入外部存储器以最小化冗余。此外，我们赋予设计的解释器调用外部工具的能力，以弥补大语言模型在专门领域或访问实时信息时的局限性。这项工作是开源的，网址为`https://github.com/agiresearch/CoRE`。

### 通过自然语言将静态调度器自动转换为动态调度器

贡献人：

链接：`http://arxiv.org/abs/2405.06697v1`

### Word2World: 通过大语言模型生成故事和世界

贡献人：

链接：`http://arxiv.org/abs/2405.06686v1`

### 开放SQL框架：在开源大语言模型上增强文本到SQL的能力

贡献人：

链接：`http://arxiv.org/abs/2405.06674v1`

尽管大型语言模型（LLMs）在文本转SQL任务中取得了成功，但开源LLMs在上下文理解和响应连贯性方面面临挑战。为了解决这些问题，我们提出了`\ours`，这是一种专门为文本转SQL与开源LLMs定制的系统方法论。我们的贡献包括全面评估开源LLMs在文本转SQL任务中的性能，`\openprompt`策略用于有效的问题表示，以及监督微调的新策略。我们探讨了链式推理在逐步推断中的好处，并提出了用于增强少样本学习的`\openexample`方法。此外，我们引入了高效利用token的技术，如`可变长度开放DB模式`，`目标列截断`和`示例列截断`，解决了大规模数据库面临的挑战。我们的发现强调了进一步研究监督微调对上下文学习能力的影响的必要性。值得注意的是，我们的方法将`Llama2-7B`的性能从2.54%提高到了41.04%，将`Code Llama-7B`的性能从14.54%提高到了48.24%在`BIRD-Dev`数据集上。值得注意的是，`Code Llama-7B`的性能在`BIRD-Dev`数据集上超过了`GPT-4`（46.35%）。

### 训练更快，表现更好：超参数模型中的模块化自适应训练

贡献人：

链接：`http://arxiv.org/abs/2405.07527v1`

尽管过参数化模型在深度学习社区中很常见，但为了进行适当的训练，这些模型需要高昂的计算成本。本文研究了过参数化模型的细粒度、模块级的学习动态，以实现更高效和富有成效的训练策略。实证证据表明，当缩减网络模块，如自注意力模型中的头部时，我们可以观察到与每个模块的可训练性相关的不同学习模式。为了描述这种模块级学习能力，我们引入了一个名为`mNTK`的新概念，并展示了模块学习质量与其`mNTK`的主特征值`λmax`紧密相关。大的`λmax`表示模块以更好的收敛性学习特征，而那些微小的特征可能会对泛化产生负面影响。受到这一发现的启发，我们提出了一种名为`MAT`的新的训练策略，以选择性地更新那些超过动态阈值的模块的`λmax`，使模型集中于学习共同特征并忽略不一致的特征。与大多数现有的训练方案不同，`MAT`通过其部分更新策略可以显著节省计算量，并且可以进一步提高性能。实验表明，`MAT`几乎将模型训练的计算成本减少了一半，并且胜过了基线的准确性。

### 如何评价 OpenAI 2024 Spring 发布的支持实时语音对话的模型 GPT-4O?

`https://www.zhihu.com/question/655916303`

陈雄辉的回答：商业化影响

1. **产品边界拓展**：`GPT-4o`模型的发布可能会直接推动商业化进程，尤其是在生成类应用领域，如游戏和角色扮演等。这些领域的应用潜力和上限将变得更加广阔，对于像Minimax这样的公司，其估值可能会因此而提升。

2. **推理成本降低**：`GPT-4o`模型可能会使得单次推理的成本下降速度比预期的要快，且成本降低的途径可能更加多样化。之前普遍认为成本的降低将依赖于OpenAI创始人Sam Altman（被称为“黄教主”）的努力，但`GPT`模型本身的优化潜力也不容小觑。

3. **对决策精度场景的影响**：对于目前产品化过程中决策精度是瓶颈的场景，`GPT-4o`模型的发布可能暂时不会带来直接影响。

4. **资本对商业模式的考量**：随着生成类应用的潜力扩大，投资者在考察商业模式时可能会对基于大型语言模型（LLM）的商业化成本回收时间表现出更高的容忍度。这可能导致互联网时代通过烧钱来占领市场心智的策略再次变得有效。

5. **决策类/生产力类产品**：对于依赖决策精度和生产力提升的产品，`GPT-4o`模型的发布在当前阶段可能不会带来显著影响。

苏洋在的回答：对创业的影响

1. **创业赛道的加速**：如果`GPT-4o`模型的实时语音对话效果确实如演示的那样出色，这意味着其背后的推理速度非常快，音频生成能力也很强。这将推动创业公司采用流式处理(`streaming`)技术，而不仅仅是API调用，从而实现交互形态的改变。

2. **情绪识别和判断的应用**：`GPT-4o`模型的这些能力不仅限于聊天机器人(`ChatBot`)，还可以扩展到教育、医疗辅助、信息推荐和广告推荐等多个领域。

3. **对某些行业的影响**：苏洋提到，有些不便明说的行业可能会利用这项技术来实现盈利，这可能指的是一些灰色地带或监管不明确的领域。

4. **对创业团队的影响**：苏洋表达了对那些与OpenAI同期推出类似技术或产品的创业团队的同情，因为与OpenAI这样的大型研究机构相比，他们可能面临更大的市场竞争压力。

### cuda的ldmatrix指令的详细解释

贡献人：

`https://zhuanlan.zhihu.com/p/697228676?utm_psn=1773758643311529985`

`ldmatrix` 是 CUDA 中的一个 PTX 指令，用于在 warp 级别上从 shared memory 加载数据到线程寄存器。它支持同步加载，确保数据对齐，并且能够一次性为 32 个线程加载多个矩阵元素。例如，`ldmatrix.sync.aligned.m8n8.x4.shared.b16` 指令能够让每个线程加载 4 个 8x8 的 `bf16` 矩阵，即每个线程处理 8x8/32 个元素，共 4 个 32 位寄存器。这种指令与 `mma` 指令配合，优化了矩阵计算的效率，特别是在使用 NVIDIA 的 GPU 进行深度学习时，能够充分发挥 GPU 的并行计算能力。通过示例代码，文章展示了如何在 CUDA 代码中使用 `ldmatrix` 指令，并且强调了 shared memory 中数据布局的重要性，要求 `B` 矩阵为列主序。这些技术细节的掌握对于编写高效的 CUDA 程序至关重要。

### OpenAI的光环出现裂痕：谈GPT4o的token词表更新问题

贡献人：

`https://zhuanlan.zhihu.com/p/697675593?utm_psn=1773758040057384961`

OpenAI 的 `GPT-4o` 模型在 token 词表更新方面遇到了技术挑战，主要体现在新词汇的滞后识别、词义变化的适应延迟以及词汇间关系表达的不准确性。这些问题源于中文语言特性的复杂性以及词表更新机制的局限性。技术细节上，`GPT-4o` 可能缺乏对中文新词汇的及时融入，以及对词义演变的灵活响应能力。此外，模型在处理多义词和语境相关的词汇时，可能无法准确捕捉到不同上下文中的含义变化。为了解决这些问题，建议采取更为动态的词表更新策略，提高模型对语境的理解能力，并通过持续的数据训练来优化模型性能。这些措施有助于提升 `GPT-4o` 在中文文本处理方面的准确性和实用性。

### GPU算子计算与调度技术
