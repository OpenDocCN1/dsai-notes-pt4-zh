
# AI 组队了，你还在单干

> 来源：[https://feicaiclub.feishu.cn/docx/DdWddwBe7oofnxx8fracBmU1n1e](https://feicaiclub.feishu.cn/docx/DdWddwBe7oofnxx8fracBmU1n1e)

![](img/415f82980e602eec48b4464f1bcf998c.png)

如果你到现在还在拿"`人机协作`"这个词安慰自己，大概率已经慢了一拍。

不是因为 AI 又出了什么新模型，也不是因为某个跑分榜又被刷新了——这种事每周都在发生，早就不值得大惊小怪。

真正值得你停下来好好想想的是另一件事：AI 开始学会组队了。

不是一个 AI 变得更强了。是一群 AI 开始像团队一样干活——分工、沟通、互相质疑、共享任务清单、干完一件自动去领下一件。`Claude Code` 最近搞了一个叫 `Agent Teams` 的东西，就是这个方向上的一颗信号弹。一个 `session` 当队长，负责拆活儿、派活儿；其他 session 各干各的，干完了自动汇报，甚至能互相发消息挑战对方的结论。

这不是什么实验室里的论文概念。这是你今天就能在终端里跑起来的东西。

但如果你只是觉得"哦，又一个新功能"，然后接着刷下一条推送，那你大概率会错过这个变化背后真正重要的三件事。

这篇文章不短。

但如果你对自己在 AI 时代到底站在哪儿这件事，有过哪怕一秒钟的焦虑，建议你读完。

## I — 你以为的"人机协作"，正在变成一剂过时的安慰药

过去两年，整个行业都在讲一个很好听的故事：`Human-in-the-Loop`。

人在回路中。AI 是工具，你是驾驶员。AI 提建议，你拍板。AI 写初稿，你来把关。

这套说法让很多人长舒了一口气——因为它意味着你还握着方向盘。你还是被需要的。AI 再厉害，没你点头它什么也干不了。

我不是说这个说法是错的。在之前，它确实没毛病。

但"之前"这个词放在 AI 领域，保质期大概也就半年。

当你面对的是一个 AI 的时候，`Human-in-the-Loop` 说得通。你给它指令，它执行，你审核，来回循环。说白了就像带一个实习生——你说什么它干什么，干完了你检查一遍。

但现在的情况不一样了。`Claude Code` 的 `Agent Teams` 让你面对的不再是一个实习生。

是一支队伍。

一个盯安全审查，一个盯性能评估，一个盯测试覆盖率。它们各自有独立的上下文窗口，各自独立思考，通过共享的任务清单来对齐进度，干完了自动通知队长做汇总。如果一个 agent 提了一个假设，另一个 agent 可以主动跳出来反驳——文档原话叫"像科学辩论一样互相推翻对方的理论"。

好，那我现在问你一个很直接的问题：

你打算怎么同时审核十几个 agent 的产出？

你还在看第三个 agent 的安全报告呢，第七个已经把架构重构提交了，第十一个正在跑第二轮测试。它们不会停下来等你。它们有自己的节奏、自己的任务队列、自己的协作逻辑。

问题就出在这儿：`Human-in-the-Loop` 的前提，是人能跟得上这个 Loop。 当 Loop 的速度和并行度超过了你处理信息的带宽，你就不是在"参与"了——你是在"拖后腿"。

别误会我的意思。我不是说人变得不重要了。恰恰相反，人从来没有比现在更重要过。

但你重要的方式，变了。

其实行业已经在悄悄换说法了：从 `Human-in-the-Loop` 变成 `Human-on-the-Loop`。差别在哪？In the loop 是你参与每一步。On the loop 是你定好规矩、划好边界、设好审批节点，然后让系统自己跑——你只在关键时刻伸手。

`Claude Code` 的 `Agent Teams` 其实已经在按这个思路设计了。你仔细看它的机制：

`Delegate mode`——队长不写一行代码，只管拆活儿、分配、审核结果。

`Plan approval`——队友在动手之前必须先交方案，队长看了同意才能执行，不同意就打回去改。

`Hooks 质量闸门`——你可以挂一些自动检查规则，队友完成任务的时候自动触发，不达标直接拦住。

这些设计都在告诉你同一件事：人的角色不是消失了，而是从操作层被推到了治理层。 你不再是那个亲手写代码、逐行检查的人了。你是那个定义"什么叫合格"、"什么情况必须停下来"、"哪些操作绝对不能碰"的人。

说得再直白一点：你从干活的，变成了定规矩的。

如果你到现在还在用"我能亲手做这件事"来衡量自己的价值，那你得重新想想了。因为"亲手做"这件事，很快就不再是什么稀缺能力了。

## II — "写过代码的都知道"——这句话正在失去它的分量

"亲手做"不再稀缺，但很多人还在用另一种方式捍卫自己的位置——经验。

你一定见过这种话术：

"写过代码的都知道，AI 根本搞不定复杂逻辑。"

"做过项目管理的都知道，需求拆解不是 AI 能干的事。"

"搞过安全的都知道，这种漏洞只有人才能发现。"

这些话有一个共同点：它们把说话者的经验，当成了 AI 能力的天花板。

一年前这么说，也许还算合理。那会儿 AI 确实有很多搞不定的事。你拿自己踩过的坑去校准 AI 的边界，是一种务实的态度。

但现在，这种校准方式本身在失效。

原因说穿了就一句话：经验的价值，是建立在"人必须亲自上手"这个前提上的。 这个前提一旦松动，经验的权威就跟着松动。

我说具体点。

"写过代码的都知道"这句话，背后的隐含假设是什么？是代码得一行一行写出来，bug 得一步一步踩过来，架构得一层一层搭上去。所以你积累的直觉、形成的判断、踩过的坑——这些东西不可替代。

但 `Agent Teams` 是怎么干活的？五个 agent 同时跑五条不同的假设路径，互相辩论，互相推翻，最后把活下来的结论交给队长汇总。文档里举了一个例子特别生动：查一个 bug 的时候，建议让五个 agent 分头调查不同的假设，然后互相较劲，试着证伪对方的理论——活下来的那个，大概率才是真正的根因。

这种方式不是在复制人类的经验。它在绕开人类的经验。

当一个系统可以在几分钟内并行跑十种架构方案，而你需要好几天才能评估完其中三种——"做过架构的都知道"这句话的分量就变了。它不再是权威的来源，反而变成了一个速度瓶颈的信号。

我知道这么说不太好听。

但先别急着反驳，请注意，我不是在说经验完全没用了。那是另一种同样危险的极端。

真正在发生的事情是：**经验的落点在迁移**。

以前经验值钱，是因为"我知道怎么做"——我知道这段代码怎么写，这个参数怎么调，这个边界情况怎么处理。

现在经验值钱，是因为"我知道做到什么程度才算对"——我能定验收标准，能判断结果是不是真的合格，能闻出来那些 AI 输出的东西看着对、但其实有坑的地方。

前者叫**执行型经验**。后者叫**评估型经验**。

这两种经验需要的能力完全不同。执行型经验靠的是肌肉记忆、流程熟练度、对细节的掌控。评估型经验靠的是全局判断力、对风险的嗅觉、制定标准的能力。

一个能写出漂亮代码的工程师，和一个能判断"这段代码在生产环境里会不会炸"的工程师，是两种人。以前你必须先成为前者，才有资格成为后者。现在的趋势是：后者的价值在飙升，前者的价值正在被 agent 团队稀释。

这不是我在瞎猜。全球能力中心（GCC）里已经冒出了一批新岗位：AI orchestration architect、agent governance engineer、AI compliance specialist。这些岗位要的核心能力不是"写代码"，而是"定义 agent 应该怎么写代码，以及怎么判断它写得对不对"。

如果你到现在还在用"我能做"来证明自己的价值——你的证明方式本身，就在贬值。

真正值钱的问题早就变了："我能判断这件事做没做对，以及做到什么程度才够好。"

## III — 你愿意给 AI 多大的权限，取决于你愿意扛多大的风险

前两节聊的是认知层面的转变：你的角色在变，你的经验在迁移。

**这一**节要聊一个更实在、更扎手的东西：权限。

以前的 AI 是一个对话框。你问它问题，它给你一段文字。就算它说错了，你关掉窗口，啥事没有。

现在不一样了。AI 能读你的代码，改你的文件，跑你的测试，调你的 API，访问你的生产环境——只要你给它权限。

`Claude Code` 的 `Agent Teams` 里有个设置叫 `--dangerously-skip-permissions`。名字已经够直白了：危险地跳过权限检查。 更要命的是，如果队长开了这个选项，所有队友都会自动继承。

一个人人的冒险决定，瞬间变成整个团队的默认行为。

**我**说这些不是为了吓你。是为了让你看清一个结构性的问题：当 AI 从"回答问题"变成"动手干活"，安全的边界就不再是一个聊天窗口了——它扩展到了整条工具链和整条权限链。

而当 AI 从"一个 agent 干活"变成"一群 agent 协作干活"的时候，这个风险还会再往上翻一层。

道理很简单：多个 agent 之间存在信任传递。`Agent A` 的输出，会变成 `Agent B` 的输入。如果 `Agent A` 被塞了一条恶意指令——哪怕只是代码注释里藏了一句话——`Agent B` 可能就会基于这个被污染的上下文去执行敏感操作。安全研究者管这个叫二阶提示注入：一个低权限的 agent 诱导一个高权限的 agent 去做它本来不该做的事。

这不是理论推演。最近 OpenClaw 的爆火就是一面现成的镜子。

这个开源 AI agent 能帮你订机票、回邮件、管日历、跑脚本——听起来完美。但为了让它真的能替你干活，你得把 shell 权限、文件读写、浏览器控制全交出去。它自己的官方文档都承认："不存在完美安全的配置。" Cisco 的安全团队看完直接下了定论——"安全灾难"。

结果也不意外：2026 年 2 月，一个 CVSS 8.8 的高危漏洞被公开披露，用户点一个恶意链接，攻击者就能劫持 agent 的全部权限——装恶意软件、擦硬盘，全程零提示。VirusTotal 扫描了它的社区技能包市场，数千个技能包里几百个被标记为恶意。Trend Micro 的报告更是直接指出：因为配置错误和缺乏审核，已经有数百万条记录被暴露。

OpenClaw 不是个案。它只是把整个 agentic AI 范式的结构性问题摆到了台面上：当你把"能干活"的权限交出去，你同时也把"能搞破坏"的权限交出去了。 而多 agent 编排会让这个问题成倍放大——一个 agent 被攻破，整条协作链都可能跟着沦陷。

传统系统里，权限模型是基于角色的（`RBAC`）：你是管理员就干管理员的事，你是普通用户就只能碰普通用户的东西。边界清楚，静态可控。

但多 agent 系统里，权限边界不再是静态的了。因为 agent 是靠推理来决定下一步动作的——它不是在跑一段写死的脚本，而是在根据上下文、目标和当前状态来判断"我接下来该干什么"。这就意味着它有可能顺着推理链走到一个你压根没预想到的操作上去。TechRadar 给这种现象起了个名字叫 contextual privilege escalation——语境型越权推断。不是因为它被授权了，而是因为它自己"推理"出来觉得自己应该有这个权限。

所以问题来了：**你到底该给 AI 多大的权限？**

这个问题没有标准答案。但有一个思考框架。

关键不是"给多少"，而是"**怎么给**"。

还记得第一节提到的那些 `Agent Teams` 的设计吗？`Delegate mode`、`Plan approval`、`Hooks` 闸门——第一节我们是从协作的角度看它们，看到的是"人的角色在上移"。但换到安全的角度再看一遍，你会发现它们同时也是一套权限治理体系：

**默认最小权限。** 队友继承队长的权限设置，但你可以单独调整每个人的权限范围。

**高风险操作卡审批。** 队友必须先交方案，队长批了才能动手。闸门在任务完成时自动跑检查，不过关就拦住。

**全程可追溯。** 共享任务清单和消息系统让每一步操作都有据可查，出了事能溯源。

这三层——最小权限、审批闸门、可追溯性——恰好对应 OWASP 对 agentic AI 安全风险的核心缓解思路。NIST的 AI 风险管理框架说得更直接：自治程度越高，需要的人类监督就越不能少——只是监督的方式要变。

所以真正的权衡不是"给权限"还是"不给权限"。

真正的权衡是：你愿意在治理基础设施上投入多少，来换自动化执行带来的效率。

什么治理都不做就把权限全开——你不是在拥抱未来，你是在赌命。

什么权限都不给、什么都非得自己过一遍——你也不是在保安全，你是在拿 2024 年的办法应对 2026 年的局面。

## IV — 一个你迟早要面对的选择

前面三节拆开来看，是三个不同的问题。但叠在一起，它们指向同一道选择题：

**你到底要站在这个系统的哪一层？**

站在执行层——亲手写代码、亲手审每一行、亲手管每一个权限——你会被速度淹没。十几个 agent 并行跑的时候，你就是那个瓶颈。

站在治理层——定规矩、定标准、定边界，让系统在你划的框里自己跑——你才有可能驾驭这个速度，而不是被它拖着走。

这不是什么抽象的职业规划建议。这是一个正在被市场定价的现实。

Gartner 预测到 2026 年底，40% 的企业应用会接入任务型 AI agents。但同时也发了警告：到 2027 年底，超过 40% 的 agentic AI 项目可能因为成本失控或价值不清晰而被砍掉。

两个数字放一起看，信号很明确：**不是所有人都能顺利完成这次迁移**。 搞不清自己该站哪一层的人、拿旧经验去套新系统的人、要么把权限全开要么全锁死的人——他们主导的项目，就是那被砍掉的 40%。

`Agent Teams` 目前还只是 `Claude Code` 的一个实验性功能。它有一堆限制：不支持 session 恢复，任务状态有时会卡住，不能嵌套组队，队长没法转让。

但这些都是工程问题。工程问题迟早会被解决。

真正不会自动解决的，是你脑子里那个问题——"我该站在哪一层？"

那个问题只有你自己能答。

而你回答它的速度，决定了你是在驾驭这个变化，还是被它碾过去。

## V — 给还在观望的人

如果你读到这儿，还是觉得"这跟我没太大关系"或者"还早呢"——我只说一件事。

多 agent 编排不是某一家公司的产品发布。它是整个基础设施层正在发生的重构。协议在标准化，治理平台在产品化，互操作框架在被推进立项。这条路不是"有人在试"，而是"所有人都在铺"。

你可以等路铺完了再慢慢走上去。但到那时候，站位早就被分完了。

所以现在就值得想清楚一件事：

当 agent 们组成了团队，你在这个团队里到底是什么角色？

如果你想了半天，发现自己的答案是"我还在做 agent 做的事"——

那你不是在观望。你是在等着被替换。
