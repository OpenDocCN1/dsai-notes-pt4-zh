生成式 AI 统计数据 显示，Gen AI 工具和模型（例如 ChatGPT）可以自动化知识密集型 NLP 任务，这些任务占员工时间的 60% 到 70%。然而，56% 的企业领导者认为人工智能生成的内容存在偏见或不准确，从而降低了LLM的采用率。

检索增强生成（RAG）是一种人工智能框架，旨在提高 LLM 响应质量。它通过将人工智能与外部信息连接起来来改进其答案。当我们在人工智能问答系统中使用 RAG 时，会发生两件事：

1. 人工智能获取最新、最可靠的事实。
2. 用户可以看到人工智能从哪里获取信息，确保其正确且值得信赖。

然而，企业领导者可能不知道这个术语，因为 RAG 是一个最近新兴的领域（见图 1）。

## 有哪些可用的 RAG 模型和工具？

RAG模型和工具可以分为三类。第一类涵盖已经采用 RAG 来提高输出准确性和质量的LLM。第二个是指可以应用于 LLM 的 RAG 库和框架。最后一类包括可以相互组合或与 LLM 组合来构建 RAG 模型的模型和库。

### LLM RAG

LLM获得插件和适配器来优化他们的模型。提供 RAG 的LLM包括：

1. Azure 机器学习： Azure 机器学习允许你使用 Azure AI Studio 或使用带有 Azure 机器学习管道的代码将 RAG 合并到 AI 中。
2. ChatGPT 检索插件：OpenAI 提供了一个检索插件，将 ChatGPT 与基于检索的系统结合起来，以增强其响应。您可以设置文档数据库并使用检索算法来查找相关信息以包含在 ChatGPT 的响应中。
3. HuggingFace Transformer 插件： HuggingFace 提供了一个转换器来生成 RAG 模型。
4. IBM Watsonx.ai： 该模型可以部署 RAG 模式来 生成事实上准确的输出。
5. Meta AI：Meta AI Research（前 Facebook Research）直接将检索和生成结合在一个框架内。它专为需要从大型语料库中检索信息并生成连贯响应的任务而设计。

### RAG 库和框架

1. FARM：Deepset 的内部框架，用于构建基于 Transformer 的 NLP 管道（包括 RAG）。
2. Haystack： Deepset 提供的用于文档搜索的端到端 RAG 框架
3. REALM：检索增强语言模型 (REALM) 训练是一个用于使用 RAG 进行开放域问答的 Google 工具包。

### 集成框架

集成框架（例如Langhcain 和Dust）简化了由语言模型支持的上下文感知和推理应用程序的开发。这些框架提供模块化组件和预配置链，以满足特定应用程序需求，同时定制模型。用户可以将这些框架与向量数据库结合起来，在LLM中使用 RAG。

### 矢量数据库

矢量数据库 (VD) 旨在存储多维数据，包括与患者相关的信息，例如症状、血液检测结果、行为和整体健康状况。某些 VD 软件应用程序（例如 Deep Lake）提供对大型语言模型 (LLM) 操作的支持，使处理此类数据变得更加容易。

### 其他检索模型

由于 RAG 基于序列到序列和 DPR 模型，因此 ML/LLM 团队可以结合这两个模型来确保检索增强生成。其中一些模型包括：

1. BART with Retrieval
2. BM25
3. ColBERT Model
4. DPR (Document Passage Retrieval) Model.

## 什么是检索增强生成？

2020 年，Meta Research 引入了 RAG 模型来精确操纵知识。Lewis 及其同事将 RAG 称为一种通用微调方法，可以将预先训练的参数内存生成模型与非参数内存结合起来。

简而言之，检索增强生成（RAG）是一种自然语言处理（NLP）方法，它结合了检索和生成模型的元素，以提高生成内容的质量和相关性。这是一种混合方法，利用两种技术的优势来解决纯粹生成或纯粹基于检索的方法的局限性。这是关于 RAG 的简短视频：

## RAG 模型如何工作？

RAG系统分两个阶段运行：检索和内容生成。

在 检索阶段：

算法使用 BM25 等技术根据用户的提示或问题主动搜索和检索相关信息片段。检索到的信息是生成连贯且上下文相关的响应的基础。

+ 在开放域消费环境中，这些事实可以来自互联网上的索引文档。在封闭域企业环境中，通常使用一组更受限制的源来增强内部知识的安全性和可靠性。例如，RAG 系统可以查找：当前的上下文因素，例如实时天气更新和用户的精确位置以用户为中心的详细信息、他们之前在网站上的订单、他们与网站的互动以及他们当前的帐户状态 检索到的文档中的相关事实数据 要么是私有的，要么是在LLM训练过程后更新的。

在 内容生成阶段：

+ 检索相关嵌入后，生成语言模型（例如 GPT 等基于转换器的模型）将接管。它使用检索到的上下文来生成自然语言响应。可以根据检索到的内容进一步调整或微调生成的文本，以确保其与上下文一致并且上下文准确。该系统可能包含出于透明度和验证目的而咨询的来源的链接或引用。

RAG LLM 使用两个系统来获取外部数据：

+ 矢量数据库： 矢量数据库 有助于使用相似性搜索查找相关文档。他们可以独立工作，也可以成为LLM应用的一部分。
+ 特征存储： 这些是用于管理和存储机器学习和人工智能应用程序中使用的结构化数据特征的系统或平台。它们为LLM等机器学习模型中的训练和推理过程提供有组织且可访问的数据。

## 什么是大型语言模型中的检索增强生成？

RAG 模型生成的解决方案可以解决大型语言模型 (LLM) 面临的挑战。这些主要问题包括：

+ 有限的知识获取和操作： LLM很难保持他们的世界知识是最新的，因为他们的训练数据集更新是不可行的。此外，它们在精确操纵知识方面也存在局限性。这种限制影响了它们在知识密集型任务上的性能，通常导致它们落后于特定于任务的架构。例如，LLM缺乏特定领域的知识，因为他们接受的是通用任务的培训。
+ 缺乏透明度： LLM很难提供有关他们如何决策的透明信息。很难追踪它们如何以及为何得出具体的结论或答案，因此它们通常被认为是“黑匣子”。
+ 答案中的幻觉： 语言模型可以回答看似准确或连贯但完全捏造或不准确的问题。解决和减少幻觉是提高LLM生成内容的可靠性和可信度的关键挑战。

## 检索增强生成有哪些好处？

RAG 公式可应用于各种 NLP 应用，包括聊天机器人、问答系统和内容生成，其中正确的信息检索和自然语言生成至关重要。RAG 提供的主要优势包括：

+ 提高相关性和准确性： 通过合并检索组件，RAG 模型可以访问外部知识源，确保生成的文本基于准确和最新的信息。这会导致更加上下文相关和准确的响应，减少回答问题和内容生成中的幻觉。
+ 上下文连贯性： 基于检索的模型为生成过程提供上下文，使生成连贯且上下文适当的文本变得更加容易。这会导致更有凝聚力和更容易理解的响应，因为生成组件可以基于检索到的信息进行构建。
+ 处理开放域查询： RAG 模型擅长处理所需信息可能不在训练数据中的开放域问题。检索组件可以从庞大的知识库中获取相关信息，从而使模型能够提供答案或生成各种主题的内容。
+ 减少生成偏差： 结合检索可以帮助减轻纯生成模型中的一些固有偏差。通过依赖各种来源的现有信息，RAG 模型可以生成更少偏见和更客观的响应。
+ 高效计算： 对于知识库已经可用且结构化的任务，基于检索的模型可以在计算上高效。他们无需从头开始生成响应，而是可以检索和调整现有信息，从而降低计算成本。
+ 多模态功能： RAG 模型可以扩展以处理多种模态，例如文本和图像。这使他们能够生成与文本和视觉内容上下文相关的文本，为图像字幕、内容摘要等应用开辟了可能性。
+ 定制和微调： 可以针对特定领域或用例定制 RAG 模型。这种适应性使它们适用于各种应用程序，包括特定领域的聊天机器人、客户支持和信息检索系统。
+ 人机协作： RAG模型可以通过快速总结和呈现知识库中的相关信息来协助人类完成信息检索任务，减少手动搜索所需的时间和精力。

## 微调与检索增强生成

通常，基础模型可以通过两种主要方法获取新知识：

1. 微调： 此过程需要根据训练集和模型权重调整预先训练的模型。
2. RAG： 此方法通过模型输入引入知识或将信息插入上下文窗口。

微调是一种常见的方法。然而，通常不建议增强事实记忆，而是改进其在专门任务上的表现。以下是两种方法的综合比较：

| **类别** | **RAG** | **微调** |
| --- | --- | --- |
| 功能性 | 结合检索和内容生成 | 采用预先训练的模型来创建内容 |
| 知识获取 | 根据需要检索外部信息 | 仅限于预训练模型内的知识。 |
| 最新数据 | 可以纳入最新信息 | 知识是静态的，难以更新。 |
| 使用案例 | 适合知识密集型任务 | 通常用于特定的任务驱动的应用程序。 |
| 透明度 | 由于来源信息透明 | 决策可能缺乏透明度。 |
| 资源效率 | 可能需要大量的计算资源 | 可以更加有效地利用资源。 |
| 领域特异性 | 可以适应各种领域和来源 | 必须针对特定领域进行微调。 |
