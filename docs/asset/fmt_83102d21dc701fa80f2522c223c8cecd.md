## DeepGEMM

项目地址：`https://github.com/deepseek-ai/DeepGEMM`

![](img/e4e6bd8bdea6819fc88d72e5453a3740.png)

DeepGEMM 是一个专为清晰高效的 FP8 一般矩阵乘法（`GEMM`，`General Matrix Multiply`）设计的库，支持精细的缩放功能，正如 DeepSeek-V3 中所提议的那样。它支持常规 `GEMM` 和 `Mix-of-Experts` (`MoE`) 分组 `GEMM`。该库使用 `CUDA` 编写，在安装时无需编译，通过使用轻量级的即时编译（`JIT`）模块，在运行时编译所有内核。

目前，DeepGEMM 仅支持 NVIDIA Hopper 张量核心。为了解决 FP8 张量核心累加精度不足的问题，它采用了 `CUDA` 核心的两级累加（提升）。尽管它借鉴了 `CUTLASS` 和 `CuTe` 中的一些概念，但避免了对它们的模板或代数的过度依赖。相反，库的设计简洁，核心内核功能只有大约 300 行代码。这使得它成为学习 Hopper FP8 矩阵乘法和优化技术的清晰而易于访问的资源。

> `CUTLASS` 和 `CuTe` 都是与 NVIDIA GPU 计算相关的开源库，专门用于加速矩阵乘法等线性代数操作。它们都在 `CUDA` 环境下进行高性能计算优化，尤其是在深度学习和高性能计算（`HPC`）领域中广泛应用。

### CUTLASS

> `CUTLASS` 是 `NVIDIA` 提供的一个高性能矩阵乘法和线性代数运算的库，它为矩阵乘法（`GEMM`）操作提供了一个高效的实现。`CUTLASS` 的核心思想是利用 `Tensor Cores`（`Tensor` 计算核心）来加速计算，这些硬件加速单元在 `NVIDIA` 的 `Volta`、`Turing` 和 `Ampere` 系列 `GPU` 中得到了广泛的应用。

> 主要特点：

+ 高效的矩阵乘法实现：`CUTLASS` 提供了针对不同数据类型（包括浮点数、整数等）的矩阵乘法实现，支持 `FP16`、`FP32`、`INT8` 等。

+ 灵活的设计：使用模板编程方式提供可定制的矩阵运算，用户可以根据具体需求调整性能。

+ 充分利用 `NVIDIA` `GPU` 特性：通过利用 `Tensor Cores`、共享内存和寄存器等 `GPU` 资源，`CUTLASS` 可以大幅度提高矩阵计算的性能。

+ 支持各种计算模式：包括标准的矩阵乘法、批量矩阵乘法、向量和矩阵运算等。

### CuTe

> `CuTe` 是一个较新的库，主要用于简化 `GPU` 上的张量计算。它通过使用 `C++` 和 `CUDA` 技术，让复杂的张量表达式变得更加简洁和高效。`CuTe` 提供了一些新的概念和接口，允许用户更方便地进行张量操作的优化。

> 主要特点：

+ 优化的张量运算：`CuTe` 旨在提供高效的张量计算，特别是针对深度学习中的矩阵和张量操作进行优化。

+ 与 `CUTLASS` 配合使用：`CuTe` 可以与 `CUTLASS` 配合使用，借助 `CUTLASS` 提供的底层高性能矩阵运算，`CuTe` 可以让开发者更容易构建复杂的张量操作。

+ 简化开发流程：`CuTe` 提供了一些高级抽象，能够简化张量操作的开发，提高代码的可读性和可维护性。

尽管设计简洁，`DeepGEMM` 在各种矩阵形状下的性能能够与专家调优的库相媲美，甚至超过它们。

`M`、`N`、`K` 这三列就是矩阵相乘时的 行列维度，分别表示矩阵的不同维度。更具体地讲，它们是标准的矩阵乘法公式中常见的维度标记，通常用来描述矩阵乘法操作。

### 矩阵乘法回顾

假设我们有两个矩阵：

+ `矩阵 A` 的维度是 `M x K`

+ `矩阵 B` 的维度是 `K x N`

那么矩阵乘法 `C = A × B` 的结果矩阵 `C` 的维度将是 `M x N`。这里的 `K` 是 `A` 的列数和 `B` 的行数，它们需要相等才能进行矩阵乘法。

解释：

1. `M`（行数）：矩阵 `A` 的行数，也就是结果矩阵 `C` 的行数。

1. `K`（内积维度）：矩阵 `A` 的列数和矩阵 `B` 的行数，矩阵相乘时，内积的维度，这两个数必须相等才能进行乘法操作。

1. `N`（列数）：矩阵 `B` 的列数，也就是结果矩阵 `C` 的列数。

举个例子：

假设有两个矩阵：

+ `矩阵 A` 是一个 `(3x5)` 的矩阵（即3行5列）

+ `矩阵 B` 是一个 `(5x2)` 的矩阵（即5行2列）

那么它们的乘法 `A × B` 会得到一个 `(3x2)` 的矩阵，因为 `A` 的列数（5）与 `B` 的行数（5）匹配，结果矩阵的行数来自于 `A` 的行数（3），列数来自于 `B` 的列数（2）。

### 在 DeepGEMM 中的意义

在 `DeepGEMM` 中，这三列的设置（`M`、`N`、`K`）用于描述不同矩阵乘法的维度，也就是具体进行 `FP8 GEMM`（矩阵乘法）计算时，针对矩阵的维度进行优化。

例如：

+ `M` 可能代表 左边矩阵 的行数（例如，批处理中的样本数量），

+ `N` 代表 右边矩阵 的列数（比如输出的维度），

+ `K` 代表 内积维度，也就是 `A` 的列数与 `B` 的行数。

这些维度控制了计算的规模和矩阵乘法的具体实现方式，因此在设计时需要根据模型的需求来优化这些维度，确保硬件（如 `GPU`）能够高效处理这些计算。

### 在大模型和注意力机制中的应用

在 `Transformer` 等基于自注意力（`self-attention`）的模型中，通常会涉及到类似矩阵乘法的操作，特别是在计算查询（`Q`）、键（`K`）和值（`V`）的过程中。这些计算可以通过矩阵乘法来高效处理，而 `DeepGEMM` 就是为这种高效矩阵计算而设计的。

我们来具体分析一下：

#### M、N、K 和注意力机制中的关系

在自注意力机制中，假设有三个矩阵：

+ `Q`（查询矩阵，`Query`）尺寸是 `(batch_size, num_queries, embedding_size)`

+ `K`（键矩阵，`Key`）尺寸是 `(batch_size, num_keys, embedding_size)`

+ `V`（值矩阵，`Value`）尺寸是 `(batch_size, num_keys, value_size)`

在计算 `Q × K^T` 时，我们实际上在进行的是一个矩阵乘法，得到一个 `(batch_size, num_queries, num_keys)` 的注意力分数矩阵。

+ `M`：对应的是 `num_queries`（查询的数量），在推理时，这通常是每次输入的 `token` 数量。

+ `N`：对应的是 `num_keys`（键的数量），在推理时，这通常是整个上下文中存在的 `token` 数量。

+ `K`：对应的是 `embedding_size`（嵌入维度），即每个 `token` 的表示长度。注意，这个维度通常在模型设计时是固定的。

#### KVCache 和 M、N、K 的对应

在大模型推理（如 `Transformer`）时，为了提高计算效率，尤其是在处理长文本时，`KVCache` 作为一种优化策略被广泛使用。`KVCache` 的核心思想是缓存 `K` 和 `V`（键值对），避免重复计算，从而节省计算资源。

+ `KVCache` 中存储的是已经计算过的键值对（`K`、`V`），通常是 `(num_keys, embedding_size)`。

+ 当新的查询（`Q`）进入时，模型只需要计算 `Q × K^T`，然后基于计算结果从缓存中获取相应的 `V`，从而大大提升推理速度。

#### 在 DeepGEMM 中的优化

在 `DeepGEMM` 这样的高性能库中，我们可以用 `M`、`N` 和 `K` 来优化矩阵计算的方式：

+ `M` 可能对应于一个批次中要处理的查询数（例如在 `Transformer` 中的单个输入序列长度或批处理大小），

+ `N` 对应于缓存中的键值对数量（即上下文中的 `token` 数量），

+ `K` 对应的是每个 `token` 的嵌入维度（即 `K` 和 `V` 的维度）。

通过 `DeepGEMM` 的矩阵计算优化，能够更高效地处理这样的 `Q × K^T` 计算，尤其是在 `FP8` 精度下，它能够大幅度减少内存使用，并提升计算速度。

## 快速开始

### 要求

+ `Hopper` 架构的 `GPU`，必须支持 `sm_90a`

+ `Python 3.8` 或以上版本

+ `CUDA 12.3` 或以上版本

+ 为了获得最佳性能，我们强烈推荐使用 `12.8` 或以上版本

+ `PyTorch 2.1` 或以上版本

+ `CUTLASS 3.6` 或以上版本（可以通过 `Git` 子模块克隆）

### 开发

+ 必须克隆子模块

```
git clone --recursive git@github.com:deepseek-ai/DeepGEMM.git
```

![](img/d95b3bf72871b0026fb6fb45b973a40f.png)

---

+ 若出现 `fatal: Could not read from remote repository.` 问题，该错误通常是由于 `Git` 使用 `SSH` 方式克隆仓库时，无法验证你的 `SSH` 公钥所导致的。错误信息显示为 `Permission denied (publickey)`，意味着 `GitHub` 无法识别你本地的 `SSH` 密钥。

+ 解决方法：

1. 确保你已配置 `SSH` 密钥：

+ 你需要在本地生成一个 `SSH` 密钥，并将公钥添加到 `GitHub` 账户中。

+ 生成 `SSH` 密钥的命令：

```
ssh-keygen -t rsa -b 4096 -C "your_email@example.com"
```

+ 然后按提示生成密钥。

1. 将 `SSH` 公钥添加到 `GitHub`：

+ 获取公钥内容：

```
cat ~/.ssh/id_rsa.pub
```

+ 复制输出的公钥。

![](img/e7d4641068d4aff354c4482a4966f3ee.png)

+ 登录到 `GitHub`，进入 `Settings` → `SSH and GPG keys` → `New SSH key`，然后粘贴公钥并保存。

![](img/d515a1e3daea890ca9f7b2be38c6202e.png)

![](img/60b193913fca5a6c12891b0df97c4e54.png)

![](img/6430b5d7f3a6440deef924cfa7d75934.png)

![](img/ee20c3713fca5a6c12891b0df97c4e54.png)

1. 检查你的 `SSH` 连接：

+ 验证是否能够成功连接到 `GitHub`：

```
ssh -T git@github.com
```

+ 如果成功，你会看到类似于：

```
Hi <username>! You've successfully authenticated, but GitHub does not provide shell access.
```

![](img/01893310b7d7f1a3dc30609e70cf1fbc.png)

+ 然后再运行 `git clone` 命令即可。

cd ./DeepGEMM

```
python setup.py install
```

然后，在你的 `Python` 项目中导入 `deep_gemm`，享受使用吧！
