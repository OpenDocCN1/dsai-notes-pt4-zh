# 学习

## 如何通过指令级并行隐藏GPU Share Memory Bank Conflict

贡献人：

https://zhuanlan.zhihu.com/p/689748284

文章讨论了在CUDA编程中如何优化share memory访问以减少bank conflict，从而提高GPU性能。Share memory由多个bank组成，每个bank每周期只能处理一个地址行的数据。当一个warp内的不同线程访问同一个bank的不同entry时，会产生bank conflict，导致数据返回需要串行处理，降低效率。作者通过一个实例展示了如何触发4-way bank conflict，并提出了通过在share memory中引入padding来避免bank conflict的解决方案。此外，还讨论了指令级并行(latency hiding)如何帮助隐藏由bank conflict带来的额外时延，即通过连续的无bank conflict指令执行来掩盖由bank conflict引起的延迟，从而在系统级别上实现性能提升。

![](img/c10ef298967308fb7fd68ce021c68bba.png)

## 搞懂 CUDA Shared Memory 上的 bank conflicts 和向量化指令（`LDS.128` / `float4`）的访存特点

贡献人：

https://zhuanlan.zhihu.com/p/690052715

文章详细讨论了在CUDA编程中，优化算子（如GEMM）时如何高效利用shared memory。特别强调了通过广播机制和避免bank conflicts来提升性能。文章深入分析了使用`LDS.64`或`LDS.128`指令（或直接使用`float2`、`float4`）进行数据访问时的内存访问特性，包括memory transaction的数量和bank conflict的条件。通过大量博客、问答和Nsight Compute测试，总结出在访问shared memory时，如何根据warp内线程的组织（如4x8或8x4布局）和访问模式（如连续访问`uint2`或`uint4`）来优化性能。这包括理解为什么在特定情况下可以通过减少memory transaction数量和避免bank conflicts来显著提升性能。

## CUTLASS 3.x 异构编程随感

贡献人：

https://zhuanlan.zhihu.com/p/689829403?utm_psn=1757913209187926016

文章探讨了NVIDIA GPU（`NvGPU`）异构化对CUDA单指令多线程（SIMT）编程的影响，特别是在新发布的Blackwell架构GPU背景下。文中详细讲述了如何通过`CUTLASS` 3.x实现高效的CUDA算子，尤其是矩阵乘法（GEMM）、卷积和Flash Attention（FMHA）2.0等在深度学习模型中占主导地位的计算。`CUTLASS`是一个基于CUDA C++的模板库，用于实现高性能的GEMM及相关计算。文章通过分析`CUTLASS`在不同NVIDIA GPU架构（如Volta、Ampere和Hopper）上的应用，突出了GPU访存层级和结构对优化GEMM算子的重要性。特别地，Hopper架构引入了新的异构指令，如Tensor Memory Accelerator（`TMA`）和4代TensorCores，显著提高了性能并改变了SIMT编程模式。此外，文章还介绍了`CUTLASS` 3.x中的优化技巧，如使用`CuTe`进行Tiling、利用`TMA`和`WGMMA`指令，以及软件流水和Warp-Specialization来适应GPU异构化的发展。

## Mamba模型解析

贡献人：

https://thegradient.pub/mamba-explained/

Mamba通过引入状态空间模型（SSMs）来解决Transformer模型在处理长序列时遇到的“二次瓶颈”问题。它通过消除注意力机制中的二次计算复杂度，实现了对长序列的有效处理，最高可处理长达100万个标记的序列。Mamba不仅运行速度快达5倍，而且在多种模态任务中表现出色，包括语言、音频和基因组学。此外，Mamba的性能在大规模序列上的提升归功于其快速推理能力和序列长度的线性缩放能力。Mamba采用选择性状态压缩机制，能够动态地将输入过滤到序列状态中，这种机制允许Mamba在避免Transformer的内存和计算限制的同时，保持最先进的性能水平。

## 知名压缩软件 `xz` 被发现有后门，影响有多大？如何应对？

贡献人：

https://www.zhihu.com/question/650826484

这个知乎问题探讨了`xz-utils` 5.6.0和5.6.1版本被维护者Jia Tan注入后门的事件。后门引入方式极其隐秘，仅因Andres Freund发现`sshd`进程CPU占用异常才被发现。后门通过修改构建脚本，利用`grep`命令隐蔽地引用恶意文件名，以及利用`sed`和`tr`命令处理特定文件内容来执行恶意代码。此后门只在Linux系统上执行感染操作，其复杂性和隐蔽性凸显出现代软件供应链安全的脆弱性。
