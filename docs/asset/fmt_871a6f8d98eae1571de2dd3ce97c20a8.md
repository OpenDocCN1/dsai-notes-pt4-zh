
> 在上述“部分参数微调”方法的基础之上，研究人员提出了Adapter方法，通过添加一个灵活的即插即用的可训练适配模块（Adaper Module），我们可以改变模型某一层（或某几层）的数据分布，从而让模型可以适用于各种各样的任务和领域。典型的做法就是每一任务或者每一领域对应了一个Adapter Module，训练的时候只更新对应任务Adapter的参数，推理的时候激活对应任务/领域的Adapter，其它任务/领域的Adapter直接忽视。和“部分参数微调”方法相比，Adapter方法的优势有（1）更轻量级（2）同样比例的参数效果更好。

### 基于重参数化的方法 Reparametrization-based PEFT

[【arXiv】](https://arxiv.org/pdf/2012.13255.pdf) INTRINSIC DIMENSIONALITY EXPLAINS THE EFFECTIVENESS OF LANGUAGE MODEL FINE-TUNING

基于重参数化的PEFT方法（reparametrization-based PEFT）利用的是低秩矩阵表示来减少可训练参数数量。目前使用最多的基于重参数化的方法是低秩适配（Low-Rank Adaptation, LoRA）。LoRA这个名儿很多读者，尤其是关注Diffusion算法的读者肯定不会陌生！在很多应用中，Low-Rank Adaptation技术已经被证明非常有效。例如，在图像处理领域，利用低秩结构可以实现图像去噪、图像复原、图像分割等任务。在推荐系统中，Low-Rank Adaptation技术可以提高推荐算法的准确性和鲁棒性。不过我还没有想好要不要在这篇文章里介绍LoRA。

### 对上述方法的评价

在12.3.2.2～12.3.2.4中，我们提到了很多参数高效的学习方法，他们用于解决LLM变得越来越大所以难以训练的问题。但是，我们可以看到，以上方法都是基于“预训练-微调”的范式的方法，无论多么轻量级，每个任务都还是有一套特定的参数（即使大部分参数可以共享）。

> 说到这里，大多数人其实并没有意识到，它的致命缺点正是：任务本身需要人为进行定义。但是现实生活中的知识，并不是完全地按照任务进行分类的，现实中大多数任务会涉及到多个任务的能力: 比如一个中国人阅读了一篇英文的文章，最后用中文写了个总结 --- 这就涉及到 翻译+总结 两个任务。而Prompting可以做到模糊任务的界限---不需要人为对任务进行划分，相反，任务的描述会作为输入的一部分直接输入预训练模型。

> 这其实就是为什么Prompting范式是“通往真正大一统语言模型的关键一步”。

![](img/4712f36aa97a2fb40aea9a7fd78debea.png)

图源: [Pre-train, Prompt, and Predict: A Systematic Survey of Prompting Methods in Natural Language Processing](https://arxiv.org/pdf/2107.13586.pdf)，这张图总结了NLP发展过程中出现的四种范式。右下角最后的两张图是Fine-tune范式和Prompt范式的鲜明对比：让预训练模型服从于下游任务，还是让下游任务服从于预训练模型。

### Prompting / Prompt Learning的定义

读完[12.2.2.1](https://s3tlxskbq3.feishu.cn/docx/NyPqdCKraoXz9gxNVCfcIFdnnAc#KUW4dyCAyo442wx04r0cAT6Fnvd)后，我们应该能够理解，Prompt的目的是将Fine-tuning的下游任务目标转换为Pre-training的任务，（即各种子任务都可以用基于下一词预测的Question Answering来表达）；且与此同时，我们不可以给下游任务构建特定的输入结构，不能添加额外的特殊符号。

提示学习这种方式拉近了测试分布与预训练分布的距离，进而可以利用大规模预训练语言模型在预训练过程中习得的强大语言建模能力，使其不经过微调就可以在各种下游任务上取得很好的结果。

采用Prompt的范式之后，Pre-train，Fine-tune的范式变成了Pre-train，prompt & predict。

> 融入了Prompt的新模式大致可以归纳成“pre-train, prompt, and predict”，在该模式中，下游任务被重新调整成类似预训练任务的形式。例如，对于一个预训练的GPT，我们在文本情感分类任务中，对于 "I love this movie." 这句输入，可以在后面加上prompt "The movie is ___" 这样的形式，然后让预训练语言模型用表示情感的答案填空如 "great"、"fantastic" 等等，最后再将该答案转化成情感分类的标签，这样一来，通过选取合适的prompt，我们可以控制模型预测输出，从而让一个完全无监督训练的PLM可以被用来解决各种各样的下游任务。

> ——【知乎】[NLP新宠——浅谈Prompt的前世今生](https://www.zhihu.com/people/dou-hong-jian-44) By AI Box专栏，作者：闵映乾@RUC

在数学上区分fine-tune和prompt：

+ 我们知道，Fine-tuning的过程是一个有监督学习的过程。基于输入 ，以 为参数的模型会预测输出 的概率分布： ，而后这个概率分布再会和我们标注的输出做比较，计算损失函数。

+ 相比之下，Prompting的目的就是避开用标注数据做有监督的微调。因此，是没有输入输出pair（ 与 ）的。在数学上，它是这么做的：基于我们输入的input，模型会建模 的概率分布: ，而后用这个 的概率分布再去预测（Predict）模型的输出`y`。

+ 这样说话可能会比较Confusing。更清晰的说法我觉得是，模型能够做到理解我们的意图，并把我们输入的 稍加改造。被改造后的 ，姑且称为 吧，会是一个模型更熟悉的东西，模型基于 去预测`y`。

+ 可以看到，上述的过程是无监督的，而基于 去预测`y`是语言模型本身就具有的能力。因此，关键在于怎么去设计把输入的 改造成 的这个机制。

### Prompt最早还不叫Prompt，它只是一种模版（Template）

13.2.2.1提到，关键在于怎么去设计把输入的 改造成 的这个机制。这就让人不禁想到一个方法——用模版。

[其实Prompt最早不叫这个名，他](https://arxiv.org/pdf/2005.14165.pdf)无非是一种模版。所以我们可以看到，整个提出GPT-3的论文Language Models are Few-Shot Learners（2020.5）里，Prompt这个词只出现了27词。但到了InstructGPT（2022.3）的时候，Prompt在论文中的词频就超过300次了。

Prompt最早是研究者们为了下游任务设计出来的一种输入形式或模板，它蕴含了不同的下游任务的信息，且输入形式和大语言模型进行预训练时的输入很像，因此能够帮助预训练语言模型“回忆”起自己在预训练时“学习”到的东西。

> 提示工程 Prompt Engineering：指设计提示函数 ，从而在下游任务中取得好的性能的过程。

### Prompt的一般工作模式（最General的一款）

13.2.2.2中其实已经讲明白了基于Template的Prompt具体是怎么工作的。现在我们来整理一下整个过程。

1. 首先我们基于海量的无标签数据通过自监督学习来预训练出一个语言模型。（Pre-train）

2. 向模型输入文本 。就像现在我们在给ChatGPT写输入一样，输入文本可以写的比较随意；但懂技术的我们肯定知道，不同的文本会有非常不同的效果，精心的、按照一定规则去写的prompt更能发挥模型的能力。

（这里 本身也可以是一个语言模型，把我们的输入填到模版里这件事本身也可以是基于概率分布的。）

> 回答工程 Answer Engineering：指的是设计回答 ，以让`z`填充`[Z]`的机制的工程。

> 1、这里的 可以是一个有限的选择，尤其是在分类任务中，例如我们之前做情感分类时的崩、典、急、孝、麻五种。也可以生成任何文本用于填充`[Z]`，尤其是在生成式任务中（like GPT）。

## Prompt Engineering & Prompt Tuning

设计指令和模版看起来很容易，但是在实际使用过程中，预训练模型很难“理解”这些指令。

> Prompt engineering is the process of creating a prompting function `fprompt(x)` that results in the most effective performance on the downstream task. In many previous works, this has involved prompt template engineering, where a human engineer or algorithm searches for the best template for each task the model is expected to perform.

提示工程 Prompt Engineering：指设计提示函数 ，从而在下游任务中取得好的性能的过程。

### 手动设计提示模版与自动模版学习

#### 手工Prompt

+ 在最开始的研究中，这涉及到提示模板工程，即由人类工程师或算法为模型预期执行的每项任务寻找最佳模板。背后的思维在于，人类有自己的先验知识，包括对模型的理解和对语言的理解，因此手动[去设计模版是](https://s3tlxskbq3.feishu.cn/docx/NyPqdCKraoXz9gxNVCfcIFdnnAc#GuCCdWSoQooEGexSu1zcN2eXntg)一件非常顺直觉的事。（Perhaps the most natural way to create prompts is to manually create intuitive templates based on human introspection）13.4.2中的表格里的prompt都属于这一范畴。

参考下表，手动去设计一个我们知道，`[X1]`。那么，“`[X2]`”的说法是`[Z]`的这样的模版是完全顺直觉的，而且模版往往也由自然语言构成。

> 自然语言推理 | `[X1]`故事发生在一个名叫提瓦特大陆的地方。 | 我们知道，`[X1]`。那么，“`[X2]`”的说法是`[Z]`的。 | 正确

> 但手动设计模版这件事还是存在很多局限性：首先，模版很难设计，背后需要工程经验甚至天马行空的沾点艺术的灵感，颇有些以往的“专家系统”的味道，从历史发展的角度看，这注定会被淘汰；其次，研究机器学习的人懂个屁的机器，符合人类直觉的提示词不一定是最能激发机器的潜能的。Optimal prompts可能是在人类看来很诡异的token组合，只靠人类自己拍脑袋的话，一辈子都想不出来。

> (1) creating and experimenting with these prompts is an art that takes time and experience, particularly for some complicated tasks such as semantic parsing (Shin et al., 2021); (2) even experienced prompt designers may fail to manually discover optimal prompts (Jiang et al., 2020c).

#### 参数化Prompt/自动 Prompt

哼哼，我们都有GPT-3这么牛逼的东西了，为什么不干脆让模版也由机器来写呢？

+ 于是，就有了自动模版学习（Automated Template Learning），也就是说不再由人类拍脑袋来设计Template，Template也由机器来自动生成，机器决定Template有哪些文字，input slot在哪，answer slot在哪。

+ 一旦把格局打开，让语言模型去写模版后，就有了许多新的可能性：首先是可以发挥神经网络的优势，去做试错学习，不断挖掘、迭代和优化 ，让性能不断变好。其次是可以发挥人工智能具有的自动化的能力，例如实现为每个输入生成一个自定义模板，而不是一个模版走天下。从而，自动模版学习产生了两种分类方式：

+ 离散型提示（discrete prompts）和连续型提示（continuous prompts）。前者就是文本构成的模版，后者则还是在LLM嵌入层的向量空间里的向量组合。

+ 静态提示Static Prompt和动态提示Dynamic Prompt。静态的Prompt对每个输入使用基本相同的提示模板，而动态的为每个输入生成一个自定义模板。静态和动态策略都被用于不同种类的离散和连续提示。

> In particular, the automatically induced prompts can be further separated into discrete prompts, where the prompt is an actual text string, and continuous prompts, where the prompt is instead described directly in the embedding space of the underlying LM。
