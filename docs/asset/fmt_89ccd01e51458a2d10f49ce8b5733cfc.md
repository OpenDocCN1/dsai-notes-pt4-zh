
# 第三章 Linux 平台安装部署与避坑全解

| 坑点现象 | 核心原因 | 解决方案 |
| --- | --- | --- |
| 非 `root` 用户安装，提示“`npm` 权限不足”“无法写入全局目录” | `npm` 全局目录默认归属 `root` 用户，非 `root` 用户无写入权限 | 1. 配置 `npm` 全局目录到用户目录，执行`npm config set prefix ~/.npm-global`；2. 将该目录加入环境变量，执行`echo 'export PATH=~/.npm-global/bin:$PATH' >> ~/.bashrc && source ~/.bashrc`；3. 重新执行安装命令，无需 `sudo` 权限 |
| 安装完成后，关闭终端服务就停止，无法后台运行 | `Gateway` 服务未配置守护进程，终端关闭后进程被终止 | 1. 初始化时执行`openclaw onboard --install-daemon`，自动安装 `systemd` 守护进程，实现开机自启、后台运行；2. 使用 `PM2` 管理进程，执行`npm install -g pm2`，再执行`pm2 start openclaw -- gateway start`，设置`pm2 startup`实现开机自启 |
| 服务启动正常，但公网无法访问 Web 面板 | 防火墙/安全组未放行端口，或 IP 绑定错误 | 1. 检查云服务器安全组，放行 18789 端口；2. 检查系统防火墙，放行端口；3. 检查 `Gateway` 配置文件，是否绑定了 `127.0.0.1`，改为 `0.0.0.0` 允许全网访问；4. 检查服务器是否有公网 IP，端口是否被运营商封禁 |
| 安装过程中提示“Out of memory”，进程被杀死 | 服务器内存不足，安装时依赖编译占用大量内存，被系统 OOM 终止 | 1. 增加服务器内存，至少 2GB，推荐 4GB 以上；2. 临时增加 `swap` 分区，缓解内存压力；3. 关闭服务器上其他占用内存的进程，再执行安装 |
| 执行 `sudo` 命令后，`Node.js` 版本回退，提示版本过低 | `nvm` 安装的 `Node.js` 版本仅对当前用户生效，`sudo` 调用的是系统 `root` 用户的 `Node.js` | 1. 配置 `sudo` 保留用户环境变量，修改`sudoers`文件，添加`Defaults env_keep += "PATH"`；2. 使用 `nvm` 的 `root` 用户安装相同版本的 `Node.js`；3. 避免使用 `sudo` 执行 `npm` 和 `openclaw` 命令，提前配置好用户目录权限 |
| `libvips` 依赖缺失，`sharp` 库编译失败 | 系统未安装 `libvips-dev`/`vips-devel` 包，`sharp` 库无法编译 | 1. 按照 3.1 节的命令，安装对应发行版的 `libvips` 开发包；2. 配置 `sharp` 镜像源，使用预构建的二进制文件，无需本地编译；3. 执行`sudo ldconfig`更新系统库缓存，重新安装 `sharp` |

> Linux 生产环境部署的最佳实践与避坑红线

1. 禁止使用 `root` 用户运行 `OpenClaw`：`root` 用户权限过高，若 `OpenClaw` 被恶意利用，会导致整个服务器被入侵，必须创建专用的普通用户运行 `OpenClaw`，仅分配必要的权限。

1. 配置反向代理与 HTTPS：公网部署时，禁止直接将 18789 端口暴露在公网，使用 `Nginx` 反向代理，配置 HTTPS 证书，添加身份认证，避免未授权访问。

1. 数据目录持久化备份：`OpenClaw` 的配置文件、技能数据、日志默认存储在`~/.openclaw`目录，必须定期备份，避免重装系统、误操作导致数据丢失。

1. 限制资源占用：使用 `systemd` 或 `cgroup` 限制 `OpenClaw` 的 CPU、内存占用，避免进程异常占用大量资源，导致服务器卡顿、其他服务无法运行。

1. 开启日志审计：配置 `OpenClaw` 的日志输出到系统日志，开启审计功能，记录所有任务执行、API 调用、用户登录操作，便于故障排查和安全审计。

# 第四章 macOS 按照 OpenClaw 适配避坑全解

macOS 平台的兼容性仅次于 Linux，得益于 Unix 底层架构，`OpenClaw` 的运行稳定性极佳，但 Apple Silicon（M1/M2/M3/M4）系列芯片的架构适配、macOS 的严格安全权限机制，是新手用户的主要踩坑点。

![](img/cf61707f8dc836802b809920ed0cc1c4.png)

## 4.1 macOS 平台安装的核心前提：架构适配与系统要求

### 架构适配避坑指南

macOS 平台分为两种 CPU 架构，必须提前确认，否则会出现依赖编译失败、进程无法启动的问题：

1. Apple Silicon 架构（M 系列芯片）：M1/M2/M3/M4 等芯片，采用 `arm64` 架构，是目前 macOS 的主流架构，`OpenClaw` 原生支持，无需额外配置，但部分老旧依赖需要 Rosetta2 转译。

1. **Intel `x86_64` 架构**：2020 年之前的 Mac 电脑，采用 Intel 芯片，`OpenClaw` 原生支持，无架构兼容问题。

**核心避坑提醒**：M 系列芯片用户，必须提前安装 Rosetta2，否则部分 `x86` 架构的依赖包无法运行，安装时会报错“架构不兼容”，执行以下命令安装 Rosetta2：

```
softwareupdate --install-rosetta --agree-to-license
```

### 系统版本与前置依赖要求

1. **系统版本**：必须是 macOS 12.0 Monterey 及以上版本，低于该版本会出现系统 API 不兼容，无法安装 `Node.js` 22.x，`OpenClaw` 启动失败。

1. **必装前置依赖**：

+   `Xcode Command Line Tools`（CLT）：`OpenClaw` 的依赖编译、`Git` 操作都需要该工具链，是必装组件，新手极易遗漏。

+   `Homebrew`：macOS 的包管理器，用于安装系统依赖、`Node.js` 等，推荐所有用户安装。

**CLT 安装命令**：打开终端，执行以下命令，按照提示完成安装：

```
xcode-select --install
```

**避坑提醒**：若执行命令提示“已安装”，但安装依赖时仍报错，执行`sudo xcode-select --reset`重置工具链路径，避免 `Xcode.app` 与 CLT 的路径冲突。

**Homebrew 安装命令**：国内用户使用镜像安装脚本，避免下载超时：

```
/bin/bash -c "$(curl -fsSL https://gitee.com/cunkai/HomebrewCN/raw/master/Homebrew.sh)"
```

安装完成后，执行`brew --version`验证安装是否成功。

## 4.2 macOS 平台分步安装流程与避坑

### 4.2.1 前置环境配置（必做，缺一不可）

1. 步骤 1：安装 `Node.js` 22 LTS

推荐使用 `nvm` 管理 `Node.js` 版本，避免系统自带 `Node.js` 的权限问题，执行以下命令安装：

```
# 安装nvm
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.0/install.sh | bash
# 重启终端后，安装Node.js 22 LTS
nvm install --lts 22
# 设置为默认版本
nvm use 22
# 验证版本
node -v
```

1. **步骤 2：配置国内镜像源**

国内用户必须配置 `npm`、`sharp`、`Homebrew` 的国内镜像，否则下载必超时：

```
# npm镜像配置
npm config set registry https://registry.npmmirror.com
# sharp库镜像配置
npm config set sharp_binary_host https://npmmirror.com/mirrors/sharp
npm config set sharp_libvips_binary_host https://npmmirror.com/mirrors/sharp-libvips
# Homebrew镜像配置，参考安装脚本的提示完成
```

1. 步骤 3：配置终端完全磁盘访问权限

macOS 的安全机制会限制终端的文件访问权限，若不开启，`OpenClaw` 无法操作本地文件、访问桌面、下载等目录，执行任务时会提示“权限被拒绝”。

**开启步骤**：

1. 打开系统设置→隐私与安全性→完全磁盘访问权限

1. 点击左下角的锁图标，输入密码解锁

1. 在右侧列表中，找到你使用的终端（`Terminal`、`iTerm2`、`Warp` 等），打开开关

1. 重启终端，权限即可生效

**避坑提醒**：这是 macOS 平台安装后功能异常的第一大坑，90%的“文件操作失败”问题，都源于终端没有完全磁盘访问权限，必须提前开启。

### 4.2.2 一键脚本安装（新手首选）

环境配置完成后，执行一键安装脚本，国内用户使用镜像脚本：

```
curl -fsSL https://open-claw.org.cn/install.sh | bash
```

海外用户使用官方脚本：

```
curl -fsSL https://openclaw.ai/install.sh | bash
```

**避坑提醒**：

+   执行脚本时，若提示需要 `sudo` 权限，输入你的 Mac 用户密码，输入时终端不显示字符为正常现象，输入完成后回车即可。

+   安装过程中，若弹出 macOS 防火墙提示，点击“允许”，否则 `Gateway` 服务会被拦截，局域网其他设备无法访问。

+   安装时长取决于网络速度，通常 2-5 分钟，安装完成后会自动启动初始化引导。

### 4.2.3 npm/pnpm 安装（推荐有基础的用户使用）

```
# 使用npm安装
npm install -g openclaw@beta
# 或使用pnpm安装（推荐，速度更快）
pnpm add -g openclaw@beta
# 完成后执行初始化引导
openclaw onboard --install-daemon
```

> **避坑提醒**：安装完成后，必须执行`openclaw onboard --install-daemon`安装守护进程，否则重启电脑后，`OpenClaw` 不会自动启动，服务会停止。

## 4.3 macOS 平台专属高频坑点与解决方案

| 坑点现象 | 核心原因 | 解决方案 |
| --- | --- | --- |
| M 系列芯片下，依赖安装失败，提示“`npm ERR！ code EBADPLATFORM`”“不兼容的架构” | 依赖包仅提供 `x86` 架构的预构建文件，`arm64` 架构不兼容，未安装 Rosetta2 | 1. 执行`softwareupdate --install-rosetta --agree-to-license`安装 Rosetta2；2. 终端右键→显示简介，勾选“使用 Rosetta 打开”，重启终端后重新执行安装命令；3. 配置镜像源，下载支持 `arm64` 架构的依赖包 |
| 安装完成后，重启终端，`openclaw` 命令提示“`command not found`” | 环境变量未写入终端配置文件，重启后失效 | 1. 确认你使用的终端 shell 类型，执行`echo $SHELL`，`zsh` 对应`~/.zshrc`，`bash` 对应`~/.bash_profile`；2. 执行`echo 'export PATH="$HOME/.nvm/versions/node/v22.x.x/bin:$PATH"' >> ~/.zshrc`（替换为你的 `Node.js` 版本路径）；3. 执行`source ~/.zshrc`刷新环境变量，重启终端验证 |
| 执行任务时提示“无法访问文件/目录”“`Operation not permitted`” | 终端没有开启完全磁盘访问权限，macOS 安全机制拦截了文件操作 | 1. 打开系统设置→隐私与安全性→完全磁盘访问权限，开启终端的权限开关；2. 重启终端，重新执行任务；3. 若仍无法访问，检查文件/目录的权限，执行`chmod 755` 目标路径修改权限 |
| macOS 防火墙拦截，局域网其他设备无法访问 Web 面板 | macOS 防火墙默认禁止外来连接，拦截了 18789 端口 | 1. 打开系统设置→网络→防火墙，点击“选项”；2. 点击“+”号，将 `Node.js` 和终端加入允许列表，开启“允许传入连接”；3. 或暂时关闭防火墙，测试是否能正常访问；4. 检查 `Gateway` 服务是否绑定了 `0.0.0.0`，允许局域网访问 |
| `Homebrew` 安装的 `Node.js`，执行 `sudo` 命令后版本回退 | `sudo` 调用的是系统自带的 `Node.js`，而非 `Homebrew` 安装的版本 | 1. 避免使用 `sudo` 执行 `npm` 和 `openclaw` 命令，提前配置好用户目录权限；2. 执行`which node`查看 `Homebrew` 的 `Node.js` 路径，使用绝对路径执行 `sudo` 命令；3. 使用 `nvm` 管理 `Node.js` 版本，避免与 `Homebrew` 版本冲突 |
| 安装完成后，服务启动正常，但 Web 面板加载空白、报错 | 前端资源 CDN 无法访问，国内网络加载失败 | 1. 配置国内镜像源，重新安装 `OpenClaw`，使用国内 CDN 的前端资源；2. 检查网络代理是否正常，关闭系统代理后重试；3. 手动执行`openclaw ui:build`，在本地构建前端资源，无需依赖 CDN |
| `Python` 版本不兼容，部分技能无法运行，提示“`Python not found`” | 系统自带的 `Python` 版本过低，或未配置 `Python` 环境变量 | 1. 使用 `Homebrew` 安装 `Python` 3.10+，执行`brew install python@3.10`；2. 配置 `Python` 环境变量，将`/opt/homebrew/bin/python3`加入 `PATH`；3. 执行`ln -s /opt/homebrew/bin/python3 /usr/local/bin/python`创建软链接，让系统能识别 `python` 命令 |
| 升级 macOS 系统后，`OpenClaw` 无法启动，提示“依赖损坏” | 系统升级后，CLT 工具链失效，`Node.js` 版本被重置 | 1. 重新执行`xcode-select --install`安装 CLT 工具链；2. 使用 `nvm` 重新切换到 `Node.js` 22 LTS 版本；3. 重新执行安装命令，修复损坏的依赖；4. 执行`openclaw repair`修复安装 |

> macOS 平台安装的最佳实践

1. 使用 `nvm` 管理 `Node.js` 版本：彻底避免系统自带 `Node.js` 的权限问题、版本冲突问题，是 macOS 平台最稳定的 `Node.js` 管理方案。

1. **提前配置所有系统权限**：安装前开启终端的完全磁盘访问权限、允许防火墙传入连接，避免安装后功能异常，无需反复修改系统设置。

1. 使用 `Homebrew` 管理系统依赖：所有系统级依赖（`libvips`、`python`、`git` 等）都通过 `Homebrew` 安装，避免手动编译的坑，`Homebrew` 会自动处理架构适配和依赖关系。

1. **配置开机自启**：初始化时执行`openclaw onboard --install-daemon`，自动安装 `launchd` 守护进程，实现 Mac 开机后 `OpenClaw` 自动启动，后台稳定运行，无需手动开启。

1. **定期备份配置**：`OpenClaw` 的所有配置、技能、数据都存储在`~/.openclaw`目录，定期备份该目录，避免重装系统、误操作导致数据丢失。

# 第五章 OpenClaw 安装后异常的排查与修复方案

很多用户安装过程无报错，但安装完成后出现服务无法启动、Web 面板无法访问、功能异常等问题，本章将提供全链路的排查流程，帮你精准定位故障原因，实现 100%修复。

![](img/64794c4fef24077c08deb65751b83e59.png)

## 5.1 安装成功的标准验证流程，避免“假安装成功”

很多用户以为执行完安装命令就是安装成功了，其实不然，必须完成以下 4 步验证，全部通过才算真正的安装成功，任何一步不通过，都说明安装存在问题，需要排查修复。

### 第一步：CLI 命令行工具验证

打开终端，执行以下命令：

```
openclaw --version
```

**验证标准**：正常输出 `OpenClaw` 的版本号，无任何报错，无“`command not found`”提示。

**异常排查**：若提示命令未找到，参考对应平台的环境变量修复方案；若输出报错，参考 5.2 节的 CLI 异常排查。

### 第二步：Gateway 核心服务启动验证

执行以下命令，启动 `Gateway` 服务：

```
openclaw gateway start
```

**验证标准**：终端输出“`Gateway started successfully on http://0.0.0.0:18789`”，无报错，进程持续运行，不会自动退出。

**异常排查**：若启动报错、进程自动退出，参考 5.3 节的 `Gateway` 启动失败排查。

### 第三步：Web 管理面板访问验证

打开浏览器，访问`http://127.0.0.1:18789`（本地安装）或`http://服务器IP:18789`（服务器安装）。

**验证标准**：正常打开 `OpenClaw` 的登录页面，页面加载完整，无空白、无报错，能正常输入账号密码登录。

**异常排查**：若无法访问、页面加载空白，参考 5.4 节的 Web 面板访问异常排查。

### 第四步：核心功能对接验证

登录 Web 面板后，配置大模型 API Key，发送一条简单的指令，如“列出当前目录的文件”。

**验证标准**：模型正常响应，指令正常执行，无报错，能返回正确的执行结果。

**异常排查**：若模型无响应、任务执行失败，参考 5.5 节的功能异常排查。

## 5.2 安装完成后，CLI 命令异常的排查与修复
