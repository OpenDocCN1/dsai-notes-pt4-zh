
## 2.1 WSL2 环境前置准备

+   若重启后提示“虚拟化未启用”，需要进入电脑 BIOS，开启 Intel VT-x（Intel CPU）或 AMD-V（AMD CPU）虚拟化功能，不同品牌主板的开启方式不同，可参考对应品牌的官方教程。

+   若已安装 WSL1，必须升级到 WSL2，执行`wsl --set-default-version 2`，将默认版本设置为 WSL2，否则会出现网络、文件系统兼容性问题。

1.  步骤 2：配置 Ubuntu 系统

安装完成后，会自动弹出 Ubuntu 终端，提示设置用户名和密码，必须设置纯英文用户名，禁止使用中文，密码输入时不显示字符，输入完成后回车即可。

**高频避坑点**：

+   用户名必须为纯英文，否则会触发中文路径的坑，后续安装 OpenClaw 必然失败。

+   设置完成后，执行`sudo apt update && sudo apt upgrade -y`，更新系统源和软件包，避免因源老旧导致依赖安装失败。

+   提前安装必需的系统依赖：`sudo apt install curl git build-essential python3 python3-pip -y`，这些依赖是 OpenClaw 源码编译、技能运行的必需组件，新手极易遗漏。

## 2.2 方案一：WSL2 环境下 OpenClaw 一键脚本安装（官方推荐，新手首选）

WSL2 环境配置完成后，在 Ubuntu 终端中执行安装命令，这是 Windows 平台成功率最高的安装方式，避坑后安装成功率接近 100%。

### 分步安装流程与每步避坑

1.  步骤 1：配置国内镜像源（国内用户必做，否则必超时）

在 Ubuntu 终端中执行以下命令，配置 `npm` 国内镜像和 sharp 依赖镜像：

```
# 配置npm淘宝镜像
npm config set registry https://registry.npmmirror.com
# 配置sharp库国内镜像
npm config set sharp_binary_host https://npmmirror.com/mirrors/sharp
npm config set sharp_libvips_binary_host https://npmmirror.com/mirrors/sharp-libvips
```

1.  **步骤 2：执行一键安装脚本**

国内用户优先使用国内镜像脚本，执行以下命令：

```
curl -fsSL https://open-claw.org.cn/install.sh | bash
```

```
curl -fsSL https://openclaw.ai/install.sh | bash
```

+   执行命令时，若提示需要 `sudo` 权限，输入你的 Ubuntu 用户密码，回车即可。

+   安装过程会自动检测并安装 Node.js 22 LTS 版本，无需手动安装，全程等待即可，不要手动关闭终端。

+   安装时长取决于网络速度，通常 3-8 分钟，若长时间卡在依赖安装，检查网络是否稳定，镜像是否配置正确。

1.  **步骤 3：完成初始化引导**

安装完成后，脚本会自动启动初始化引导，执行`openclaw onboard`命令，按照引导完成以下配置：

1.  设置管理员账号和密码，用于登录 Web 管理面板

1.  配置大模型 API Key（可先跳过，后续在 Web 面板中配置）

1.  安装系统必备的基础技能包

1.  配置开机自启的守护进程

**避坑提醒**：

+   初始化引导必须完成，否则 Gateway 服务不会自动启动，Web 面板无法访问。

+   若不小心跳过了引导，手动执行`openclaw onboard --install-daemon`即可重新启动引导。

1.  **步骤 4：验证安装成功**

执行以下命令，验证安装是否成功：

```
# 验证CLI命令是否正常
openclaw --version
# 验证Gateway服务是否正常运行
openclaw gateway status
```

**避坑提醒**：WSL2 环境下，Windows 主机可直接通过 127.0.0.1 访问 Web 面板，无需额外配置 IP，若无法访问，检查 Ubuntu 防火墙是否关闭，Gateway 服务是否正常启动。

## 2.3 方案二：Windows 原生 PowerShell 安装（不推荐，仅适合无法使用 WSL2 的用户）

若你的 Windows 系统无法启用 WSL2，只能使用原生 PowerShell 安装，必须严格按照以下步骤操作，否则极易出现兼容性问题。

### 前置必做准备（缺一不可）

1.  必须以管理员身份运行 PowerShell，否则权限不足会导致安装失败。

1.  必须修改 PowerShell 执行策略，否则无法运行安装脚本，执行以下命令：

```
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

1.  必须提前安装 Node.js 22.x LTS 版本，从 Node.js 官网下载 64 位安装包，安装时必须勾选“Automatically install the necessary tools”和“Add to PATH”，安装完成后重启终端，执行`node -v`验证版本。

1.  必须提前配置 `npm` 国内镜像，执行 1.3 节中的镜像配置命令，否则依赖下载必超时。

### 分步安装流程

1.  **步骤 1：执行一键安装脚本**

国内用户使用镜像脚本：

```
iwr -useb https://open-claw.org.cn/install-cn.ps1 | iex
```

```
iwr -useb https://openclaw.ai/install.ps1 | iex
```

1.  **步骤 2：完成初始化引导**

安装完成后，执行`openclaw onboard`命令，按照引导完成配置，步骤与 WSL2 环境一致。

1.  **步骤 3：验证安装成功**

执行`openclaw --version`验证 CLI 命令，执行`openclaw gateway start`启动服务，浏览器访问http://127.0.0.1:18789，能正常打开面板即为安装成功。

## 2.4 Windows 平台安装高频报错与秒解方案

以下是 Windows 平台安装过程中出现频率最高的 20+报错，均提供实测有效的解决方案。

| **报错现象** | **核心原因** | **秒解方案** | **预防措施** |

| --- | --- | --- | --- |

| PowerShell 提示“无法运行脚本，因为在此系统上禁止运行脚本” | PowerShell 默认执行策略禁止运行外部脚本 | 以管理员身份执行`Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser`，输入 Y 确认 | 安装前先修改执行策略，再执行安装命令 |

| 执行`openclaw`命令提示“无法将&#x27;`openclaw`&#x27;识别为 cmdlet、函数、脚本文件或可运行程序的名称” | 环境变量未配置，或安装未完成，npm 全局目录未加入系统 `PATH` | 1. 执行`npm config get prefix`查看 npm 全局目录，将该目录路径加入系统环境变量 `PATH`；2. 重启终端，重新执行安装命令；3. 若使用 nvm，确保当前终端使用的 Node.js 版本与安装时一致 | 安装 Node.js 时勾选“Add to PATH”，安装完成后重启终端 |

| 安装过程中提示“network timeout”“下载失败”“fetchMetadata 卡住” | 网络无法访问海外 npm 仓库，下载超时 | 1. 配置 npm 淘宝镜像和 sharp 镜像；2. 切换稳定的网络环境；3. 使用国内镜像安装脚本 | 国内用户安装前必须先配置镜像源 |

| 明明安装了 Node.js 22.x，仍提示“Node.js version is too low” | 系统存在多版本 Node.js 冲突，终端调用的版本不对 | 1. 执行`$env:NODE_PATH`查看当前 Node.js 路径；2. 控制面板卸载所有非 22.x 版本；3. 重启终端，重新验证`node -v` | 安装前卸载所有不兼容的 Node.js 版本，使用 nvm 管理单一版本 |

| 启动服务提示“Address already in use: 127.0.0.1：18789” | 默认端口 18789 被其他程序占用 | 方式 1：关闭占用端口的进程，执行`netstat -ano | findstr :18789`查看 PID，在任务管理器中结束该进程；方式 2：修改配置文件，更换为其他未占用端口 |

| 安装过程中提示“Permission denied”“权限被拒绝”“文件写入失败” | 终端没有管理员权限，或杀毒软件拦截了文件写入 | 1. 以管理员身份重新运行 PowerShell；2. 暂时关闭杀毒软件实时防护，将安装目录加入白名单；3. 检查安装路径是否有写入权限 | 必须以管理员身份运行终端，安装前关闭杀毒软件实时防护 |

| sharp 库安装失败，提示“prebuilt binary download failed” | sharp 库的预构建二进制文件无法从海外服务器下载 | 1. 配置 sharp 库国内镜像源；2. 执行`npm install --platform=win32 --arch=x64 sharp`手动安装对应架构的版本 | 安装前先配置 sharp 镜像源 |

| WSL2 环境下，Windows 浏览器无法访问 Web 面板 | WSL2 网络桥接异常，或 Ubuntu 防火墙拦截了端口 | 1. 执行`sudo ufw disable`关闭 Ubuntu 防火墙；2. 重启 WSL 服务，执行`wsl --shutdown`，重新打开 Ubuntu 终端；3. 检查 Gateway 服务是否正常启动`openclaw gateway status` | WSL2 安装完成后先关闭防火墙，避免端口拦截 |

| 中文用户名导致的“配置文件写入失败”“ENOENT: no such file or directory” | 系统用户名为中文，配置文件路径含非 ASCII 字符 | 1. 新建一个纯英文的 Windows 管理员用户；2. 在新用户环境下重新安装；3. 手动指定纯英文的配置文件路径，设置环境变量`OPENCLAW_HOME=C:\openclaw` | 安装前检查系统用户名，必须为纯英文 |

| 安装完成后重启电脑，`openclaw` 命令失效 | 环境变量在重启后丢失，或 Node.js 版本回退 | 1. 检查系统 `PATH` 环境变量，确认 npm 全局目录已加入；2. 若使用 nvm，执行`nvm alias default 22`设置默认版本；3. 重新执行安装命令，修复环境变量 | 安装完成后不要修改 Node.js 版本，使用 nvm 设置默认版本 |

| WSL2 安装时提示“WSL 2 需要更新其内核组件” | 缺少 WSL2 Linux 内核更新包 | 1. 从微软官网下载 WSL2 内核更新包并安装；2. 重启电脑，重新执行`wsl --install`命令 | 安装 WSL2 前先完成 Windows 系统更新，安装所有可选更新 |

# 第三章 Linux 安装 OpenClaw 问题避坑指南

Linux 是 OpenClaw 服务器部署、生产环境运行的首选平台，兼容性最好，性能最优。但不同发行版的包管理器、系统依赖、安全策略差异较大，新手极易在环境配置、权限管理、防火墙设置上踩坑。

## 3.1 Linux 平台安装的核心前提：发行版适配与环境准备

### 官方支持的发行版与适配优先级

1.  一级适配（官方优先支持，无兼容问题）：Ubuntu 20.04+/22.04+/24.04 LTS、Debian 11+/12+

1.  二级适配（社区支持，需手动配置依赖）：CentOS Stream 8+/9+、RHEL 8+/9+、Fedora 38+

1.  不推荐适配（兼容性差，易出现依赖问题）：Arch Linux、OpenSUSE、Alpine Linux（Alpine 需使用 musl 编译的依赖，官方无预构建包）

### 安装前必装的系统依赖

无论哪个发行版，都必须提前安装以下系统依赖，否则会出现依赖编译失败、技能无法运行的问题，新手极易遗漏：

```
# Ubuntu/Debian系列
sudo apt update && sudo apt install -y curl git build-essential python3 python3-pip libvips-dev
# CentOS/RHEL系列
sudo dnf update -y && sudo dnf install -y curl git gcc gcc-c++ make python3 python3-pip vips-devel
# Fedora系列
sudo dnf update -y && sudo dnf install -y curl git @development-tools python3 python3-pip vips-devel
```

**核心避坑提醒**：`build-essential`（开发工具链）和`libvips-dev`（sharp 库的系统依赖）是必装组件，缺少这两个包，sharp 库必然安装失败，OpenClaw 无法正常启动。

## 3.2 主流发行版分步安装流程与专属避坑

### 3.2.1 Ubuntu/Debian 系列安装（官方首选，新手推荐）

Ubuntu/Debian 是官方适配最完善的发行版，安装流程最简单，踩坑概率最低，推荐所有新手用户使用。

1.  **步骤 1：环境预检与镜像配置**

执行`node -v`检查 Node.js 版本，若未安装或版本不符，使用 nvm 安装 Node.js 22 LTS，步骤参考 1.3 节。

国内用户必须配置 `npm` 国内镜像和 sharp 镜像，避免下载超时。

1.  **步骤 2：执行一键安装脚本**

国内用户使用镜像脚本：

```
curl -fsSL https://open-claw.org.cn/install.sh | bash
```

```
curl -fsSL https://openclaw.ai/install.sh | bash
```

1.  **步骤 3：完成初始化与验证**

安装完成后，自动执行初始化引导，按照提示完成配置，执行`openclaw --version`和`openclaw gateway status`验证安装，浏览器访问http://服务器IP:18789即可打开 Web 面板。

### 3.2.2 CentOS/RHEL 系列安装专属避坑

CentOS/RHEL 系列的核心坑点集中在 `yum` 源老旧、SELinux 权限拦截、防火墙规则三个方面，必须提前处理，否则安装后无法访问。

1.  **前置避坑处理**

+   关闭 SELinux（临时关闭，重启后恢复，可永久关闭）：执行`sudo setenforce 0`，永久关闭需修改`/etc/selinux/config`文件，将`SELINUX=enforcing`改为`SELINUX=disabled`，重启系统生效。

+   配置防火墙放行端口：执行以下命令，放行默认端口 18789，否则公网无法访问：

```
sudo firewall-cmd --zone=public --add-port=18789/tcp --permanent
sudo firewall-cmd --reload
```

+   升级系统源：CentOS 8 已停止官方维护，需更换为阿里云或腾讯云的 Vault 源，否则无法安装依赖，参考国内镜像站的 CentOS 源配置教程。

1.  **安装流程**

与 Ubuntu 系列一致，先安装系统依赖，再执行一键安装脚本，完成初始化引导。

### 3.2.3 云服务器部署专属避坑指南

绝大多数 Linux 用户会在云服务器（阿里云、腾讯云、华为云等）上部署 OpenClaw，90%的公网无法访问问题，都源于云服务器的安全组配置，这是云服务器部署的第一大坑。

**核心避坑步骤**：

1.  **安全组端口放行**：登录云服务器控制台，进入安全组配置，添加入方向规则，放行 TCP 端口 18789，授权对象为 0.0.0.0/0（全网可访问）或指定 IP 段，否则防火墙会直接拦截公网访问请求。

1.  **公网 IP 绑定**：确保云服务器已绑定弹性公网 IP，否则无法通过公网访问。

1.  **带宽配置**：云服务器带宽至少 1M，否则依赖下载会超时，模型 API 调用会卡顿。

1.  **内存配置**：云服务器内存至少 2GB，推荐 4GB 以上，否则安装过程会因内存不足被系统 OOM 终止。

1.  禁止使用轻量应用服务器的封禁端口：部分云厂商的轻量应用服务器会封禁高危端口，若 18789 无法访问，可更换为其他端口，如 8080、9090 等。

## 3.3 Linux 平台安装高频坑点与解决方案

| **坑点现象** | **核心原因** | **解决方案** |

| --- | --- | --- |

| `apt`/`yum` 源老旧，无法安装符合要求的 Node.js 版本 | 系统默认源中的 Node.js 版本过低，无法满足≥22.0.0 的要求 | 1. 不要使用 `apt`/`yum` 直接安装 Node.js，使用 nvm 管理版本；2. 配置 NodeSource 官方源，安装 22.x 版本；3. 更换国内镜像源，更新系统软件包 |
