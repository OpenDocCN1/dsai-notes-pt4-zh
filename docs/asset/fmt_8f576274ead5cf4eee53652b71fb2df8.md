
1. **依赖全量下载避坑**：必须下载所有的依赖包，包括间接依赖，否则安装时会提示依赖缺失，无法继续，推荐使用`npm pack --all`或`pnpm fetch`全量下载依赖。

1. **本地模型避坑**：离线部署必须使用本地大模型（如 Ollama 部署的开源模型），无法使用公网云端 API，提前在内网环境中部署好本地模型，配置好 API 地址。

1. **前端资源避坑**：离线部署必须提前构建前端资源，将前端资源打包到本地，避免依赖公网 CDN，导致面板加载空白。

## 6.3 企业级部署的安全避坑红线

企业级部署 OpenClaw，必须严格遵守以下安全避坑红线，避免数据泄露、未授权访问、系统入侵等安全事故。

1. 禁止直接将 OpenClaw 暴露在公网：公网部署必须使用 Nginx 反向代理，配置 HTTPS 证书，添加 HTTP Basic 身份认证、双因素认证，禁止直接将 18789 端口暴露在公网。

1. **最小权限原则**：使用专用的普通用户运行 OpenClaw，禁止使用 `root`/管理员用户运行，仅分配必要的文件访问权限，禁止赋予系统级权限。

1. **API 密钥安全管理**：大模型 API 密钥禁止明文写在配置文件中，使用环境变量或密钥管理工具存储，定期轮换 API 密钥，避免密钥泄露。

1. **网络隔离**：将 OpenClaw 部署在企业内网隔离网段，禁止直接访问互联网，仅开放必要的模型 API 地址访问权限，配置防火墙白名单。

1. **日志审计与监控**：开启全量日志审计，记录所有用户登录、任务执行、API 调用、系统操作，对接企业监控系统，监控服务运行状态、资源占用、异常操作，设置告警规则，及时发现安全事件。

1. **定期安全更新**：及时更新 OpenClaw 到最新稳定版本，修复安全漏洞，定期更新系统依赖、`Node.js` 版本，修复已知的安全漏洞。

1. **数据加密**：配置文件、用户数据、任务日志必须加密存储，敏感信息禁止明文存储，传输过程必须使用 HTTPS 加密，避免数据被窃听。

# 第七章 OpenClaw 长期运行的维护指南

安装成功只是第一步，长期稳定运行需要做好日常维护，避开长期运行中的高频坑点，本章将讲解版本升级、日常维护、故障预警的全流程方案。

## 7.1 版本升级的正确方式与避坑

OpenClaw 目前处于快速迭代阶段，每周都会发布新版本，修复 bug、新增功能，很多用户升级时会出现版本不兼容、数据丢失、功能异常的问题，必须按照正确的方式升级。

### 不同安装方式的正确升级步骤

1. **一键脚本安装的升级**：直接重新执行最新的一键安装脚本，脚本会自动覆盖旧版本，保留配置文件和数据，无需额外操作。

1. **npm/pnpm 安装的升级**：

```
# npm升级
npm install -g openclaw@latest
# pnpm升级
pnpm add -g openclaw@latest
# 升级完成后，重启Gateway服务
openclaw gateway restart
```

1. **源码安装的升级**：

```
# 进入源码目录
cd openclaw
# 拉取最新代码
git pull
# 安装最新依赖
pnpm install
# 重新构建
pnpm build
# 重启服务
pnpm run gateway:restart
```

### 版本升级的核心避坑点

### 升级前必须备份数据

升级前备份`~/.openclaw`目录，避免跨版本升级导致配置文件不兼容、数据丢失，升级失败可随时回滚到旧版本。

### 跨大版本升级避坑

跨大版本升级（如从 `0.1.x` 升级到 `0.2.x`），必须查看官方更新日志，确认是否有破坏性更新，是否需要手动修改配置文件，避免升级后服务无法启动。

### 升级后必须重启服务

升级完成后，必须重启 Gateway 服务，否则运行的还是旧版本的代码，新功能无法生效，bug 无法修复。

### 依赖同步升级

源码安装升级时，必须重新执行`pnpm install`，安装最新的依赖，否则会出现依赖版本不兼容，服务启动失败。

### 回滚方案

若升级后出现严重问题，可直接安装旧版本，恢复备份的配置目录，即可快速回滚到升级前的状态，避免业务中断。

## 7.2 日常维护的核心事项

1. **日志清理**：OpenClaw 的日志文件默认存储在`~/.openclaw/logs`目录，长期运行会占用大量磁盘空间，必须定期清理。可配置日志轮转，自动删除 7 天前的日志文件，避免磁盘空间占满。

1. **依赖安全更新**：定期更新系统依赖、`Node.js` 版本、`npm` 依赖包，修复已知的安全漏洞，避免被恶意利用。

1. **性能监控**：定期监控 OpenClaw 的 CPU、内存占用，若出现内存持续上涨，说明存在内存泄漏，重启 Gateway 服务即可修复，避免进程占用大量内存导致系统卡顿。

1. **技能包维护**：定期更新已安装的技能包到最新版本，修复 bug，新增功能，删除不使用的技能包，减少资源占用。

1. **配置备份**：定期备份`~/.openclaw`目录，尤其是 `config.yaml` 配置文件、技能数据、用户数据，避免误操作、系统崩溃导致数据丢失。

## 7.3 长期运行的高频坑点与解决方案

| **坑点现象** | **核心原因** | **解决方案** |

| --- | --- | --- |

# 第八章 OpenClaw 核心模型对接全场景避坑指南

OpenClaw 本身不具备大语言模型能力，所有的逻辑判断、任务规划、指令生成都依赖对接的大模型，超 60%的新手用户在安装完成后，会卡在模型对接环节，出现“模型无响应”“指令不执行”“API 调用报错”等问题。本章将覆盖云端 API 模型、本地开源模型的全场景对接坑点，提供可直接落地的避坑方案。

![](img/6ebfa8c1012f5303abfe31fc2865cb23.png)

## 8.1 模型对接的核心认知红线，90%的报错都源于认知偏差

在对接模型前，必须先明确 3 条核心红线，避免无效调试：

1. **模型能力边界红线**：OpenClaw 的任务执行效果，完全取决于对接模型的能力。任务规划、代码生成、复杂逻辑处理，需要强推理能力的模型（`Claude 3.5 Sonnet`、`GPT-4o`、`DeepSeek V3` 等），`7B` 以下的本地小模型无法完成复杂任务，强行使用会出现“指令听不懂、步骤乱执行、代码全报错”的问题，不是 OpenClaw 安装失败，而是模型能力不匹配。

1. **API 权限红线**：所有云端模型的 API Key，必须具备对应的模型调用权限，且账户有充足的余额/额度。很多用户申请的是测试 Key，有调用次数、模型类型限制，超出限制后会直接被拦截，OpenClaw 不会显示详细的封禁原因，只会提示“模型调用失败”。

1. **网络连通性红线**：绝大多数海外模型 API（`OpenAI`、`Anthropic`）在国内无法直连访问，必须通过合规的网络代理访问，否则会出现“请求超时”“连接被拒绝”的报错，不是 API Key 错误，而是网络无法到达 API 服务器。

## 8.2 云端 API 模型对接高频坑点与秒解方案

云端模型是新手用户的首选，无需本地算力，开箱即用，但也是坑点最集中的环节，以下是出现频率最高的核心坑点，均提供实测有效的解决方案。

| **报错现象/坑点** | **核心原因** | **秒解方案** | **避坑红线** |

| --- | --- | --- | --- |

| 提示“API Key 无效”“Invalid API Key”，但确认 Key 是正确的 | 1. API Key 复制时带了空格、换行符；2. Key 所属的平台与配置的模型不匹配；3. Key 的权限被平台封禁/撤销；4. 配置文件中 Key 的格式错误 | 1. 手动删除 Key 前后的空格、换行符，纯文本粘贴；2. 确认模型与平台匹配（如 `GPT` 模型必须用 `OpenAI` 的 Key，`Claude` 模型必须用 `Anthropic` 的 Key）；3. 登录对应平台的控制台，查看 Key 的状态，确认未被封禁，且有调用权限；4. 检查 `config.yaml` 配置文件，Key 的引号必须为英文双引号，不能有中文引号、缩进错误 | 禁止将 API Key 分享给他人，禁止提交到公开的代码仓库，否则会被平台自动扫描封禁，造成财产损失 |

| 模型调用提示“请求超时”“timeout”，但 Key 和网络都正常 | 1. 代理配置错误，OpenClaw 的进程没有走代理；2. API 服务器地域与代理节点不匹配；3. 超时时间设置过短，复杂任务的生成时间超过阈值；4. 代理节点被平台封禁，无法访问 API | 1. 给 OpenClaw 配置全局代理，执行`export HTTPS_PROXY=http://127.0.0.1:端口号`（macOS/Linux），Windows 在系统环境变量中添加 `HTTPS_PROXY` 变量，重启终端生效；2. 配置与 API 服务器同地域的代理节点（如 OpenAI API 用美国节点，Anthropic API 用日本/美国节点）；3. 修改配置文件，将`model.timeout`从默认的 `30s` 改为 `60-120s`，适配长文本生成；4. 更换代理节点，避免使用公共节点，公共节点大多已被平台封禁 | 禁止使用免费公共代理调用付费 API，不仅稳定性极差，还可能导致 API Key 被窃取 |

| 提示“模型不存在”“model not found”，但模型名称正确 | 1. 模型名称拼写错误，大小写不匹配；2. API Key 没有该模型的调用权限；3. 平台的 API 端点配置错误；4. 模型已被平台下线/更新版本 | 1. 严格复制平台官方文档中的模型名称，注意大小写、连字符，比如`gpt-4o`不能写成`gpt4o`，`claude-3-5-sonnet-20240620`不能简写；2. 登录平台控制台，确认你的账户有权限调用该模型，很多新账户默认没有 `GPT-4`、`Claude 3 Opus` 的调用权限；3. 检查`model.base_url`配置，必须与平台的官方 API 端点一致，比如 Azure OpenAI 的端点与官方不同，必须单独配置；4. 查看平台官方文档，确认模型是否仍在服务中，更换为最新的模型版本 | 优先使用平台的稳定版模型，避免使用预览版/即将下线的模型，防止接口突然失效 |

| 模型能正常对话，但无法执行任务，只会回复文本内容 | 1. 模型不支持工具调用（Function Call）能力；2. 配置文件中未开启工具调用功能；3. 模型能力不足，无法理解任务执行指令 | 1. 必须选择支持工具调用的模型，比如 `GPT-3.5 Turbo` 及以上、`Claude 3` 系列及以上、`DeepSeek V3`、通义千问 Plus 等，很多轻量化模型不支持工具调用，无法执行任务；2. 打开配置文件，确认`model.enable_function_call`设置为 `true`，开启工具调用能力；3. 更换为推理能力更强的模型，`7B` 以下的本地小模型基本无法完成工具调用逻辑 | 工具调用能力是 OpenClaw 执行任务的核心，不支持该能力的模型，只能当聊天机器人用，无法实现自动化操作 |

| 频繁提示“限流”“rate limit exceeded”，任务执行中断 | 1. API 调用频率超过平台的限流阈值；2. 短时间内发起了大量的并发请求；3. 免费账户的限流阈值极低，无法满足连续任务执行 | 1. 修改配置文件，调整`model.max_concurrent_requests`，降低并发数，默认是 `5`，免费账户建议改为 `1-2`；2. 开启请求重试机制，配置`model.retry.max_retries=3`，`model.retry.retry_delay=2000`，触发限流后自动延迟重试；3. 升级为付费账户，付费账户的限流阈值会大幅提升；4. 配置多个 API Key，实现轮询调用，分摊限流压力 | 禁止短时间内发起大量并发请求，否则会被平台判定为恶意调用，直接封禁 API Key |

## 8.3 本地开源模型对接专属避坑指南

本地开源模型（通过 Ollama、LM Studio 等部署）是隐私敏感场景的首选，无需联网、无 API 费用，但对本地算力、配置适配要求极高，新手极易踩坑。

### 8.3.1 本地模型部署的前置避坑红线

1. **算力红线**：本地模型必须满足对应的算力要求，否则会出现模型加载失败、生成速度极慢、响应超时的问题：

+ `7B` 模型：至少 `16GB` 内存，`8GB` 以上显存，推荐 `NVIDIA` 显卡，支持 `CUDA` 加速；

+ `13B` 模型：至少 `32GB` 内存，`16GB` 以上显存；

+ `34B+`模型：至少 `64GB` 内存，`24GB` 以上显存，无对应算力的用户，禁止使用大参数模型。

1. **兼容性红线**：必须使用支持 OpenAI 兼容 API 接口的本地部署工具，优先选择 Ollama，OpenClaw 对 Ollama 做了原生适配，兼容性最好，LM Studio、`Text Generation WebUI` 需要手动开启 OpenAI 兼容 API 服务。

1. **工具调用能力红线**：必须选择支持工具调用的开源模型，否则无法执行任务，推荐模型：`DeepSeek V2`、`DeepSeek V3`、`Llama 3.1`、`Qwen 2.5`、`Yi 1.5` 等，这些模型原生支持工具调用，适配 OpenClaw 的执行逻辑。

### 8.3.2 Ollama 模型对接高频坑点与解决方案

Ollama 是目前最主流的本地模型部署工具，一键安装、操作简单，也是新手踩坑最多的工具，以下是核心坑点：

| **坑点现象** | **核心原因** | **解决方案** |

| --- | --- | --- |

| OpenClaw 无法连接到 Ollama，提示“连接被拒绝” | 1. Ollama 服务未启动；2. Ollama 的 API 服务未绑定 `0.0.0.0`，仅能本机访问；3. 端口被占用，或防火墙拦截了 `11434` 端口；4. OpenClaw 与 Ollama 不在同一网络环境 | 1. 执行`ollama serve`启动 Ollama 服务，Windows 用户打开 Ollama 客户端即可自动启动服务；2. 配置 Ollama 的环境变量，开启全网访问：macOS/Linux 执行`export OLLAMA_HOST=0.0.0.0:11434`，Windows 在系统环境变量中添加 `OLLAMA_HOST` 变量，值为 `0.0.0.0:11434`，重启 Ollama 生效；3. 检查 `11434` 端口是否被占用，关闭防火墙，或放行 `11434` 端口；4. 确认 OpenClaw 与 Ollama 在同一局域网，能正常 ping 通主机 IP |

| 模型能正常连接，但生成速度极慢，几十秒才返回结果 | 1. 没有开启 GPU 加速，纯 CPU 运行模型；2. 显存不足，模型被加载到内存中运行；3. 模型参数过大，超出本地算力范围；4. 未开启量化，模型体积过大 | 1. 安装对应显卡的驱动，`NVIDIA` 显卡安装 `CUDA Toolkit`，`AMD` 显卡安装 `ROCm`，Ollama 会自动识别 GPU 加速；2. 执行`ollama ps`查看模型的显存占用，若显存不足，更换为更小参数的模型，或开启更高的量化级别；3. 按照算力红线选择对应参数的模型，不要强行运行超出算力的大模型；4. 使用量化版模型，比如 `Q4_K_M` 量化版，体积减少 `75%`，性能损失极小，推荐新手使用 |

| 模型能对话，但无法执行任务，不会调用工具 | 1. 所选的模型不支持工具调用能力；2. 配置文件中未开启工具调用；3. 提示词配置错误，模型无法理解工具调用指令 | 1. 更换为原生支持工具调用的开源模型，比如 `DeepSeek V2`、`Llama 3.1`、`Qwen 2.5`，禁止使用不支持工具调用的模型；2. 打开配置文件，确认`model.enable_function_call=true`，`model.local_mode=true`，开启本地模型适配；3. 在 Web 面板的模型设置中，添加本地模型工具调用专用的系统提示词，引导模型正确调用工具 |

## 8.4 多模型管理与负载均衡避坑指南
