
# 研究论文

优质的预训练数据通常被视为高性能语言模型的关键。然而，由于数据选择实验需要昂贵的预训练运行，我们对预训练数据的理解进展缓慢。我们提出了一个框架，避免了这些成本，并在没有进行任何LLM训练的情况下选择高质量的预训练数据。我们的工作基于一个简单的观察：许多预训练文本上的LLM损失与下游基准性能相关，并选择高相关文档是一种有效的预训练数据选择方法。我们构建了一个围绕困惑度-基准相关性估计的新统计框架，并使用来自开放LLM排行榜的90个LLM样本在数万个Web域的文本上进行数据选择。在8个基准的160M参数规模的受控预训练实验中，我们的方法在每个基准上都优于DSIR，同时与DataComp-LM中找到的最佳数据选择器相匹配，后者是一个手工设计的双字分类器。

## OneGen：LLM的高效一遍式统一生成和检索

贡献人：

链接：http://arxiv.org/abs/2409.05152v1

尽管大语言模型（LLMs）最近取得了显著进展，极大增强了各种自然语言处理任务的生成能力，但LLMs仍然面临直接处理检索任务的限制。许多实际应用需要无缝集成检索和生成。本文介绍了一种新颖高效的单次生成和检索框架（OneGen），旨在提高LLMs在需要生成和检索的任务中的性能。该框架通过自回归地引入检索token，将生成和检索的传统训练方法融合，使单个LLM能够在统一的前向传递中同时处理两个任务。我们在RAG和Entity Linking两种不同类型的综合任务上进行实验，验证了OneGen在训练和推断中的可插拔性、有效性和效率。此外，我们的结果表明，在相同上下文中集成生成和检索可以同时保留LLMs的生成能力并提高检索性能。据我们所知，OneGen是第一个使LLMs能够在生成过程中进行向量检索的框架。

## 探索简单的对话式红队操作

贡献人：

链接：http://arxiv.org/abs/2409.04822v1

大语言模型（LLMs）在商务对话系统中被广泛使用，但存在安全和道德风险。多轮对话中，上下文影响模型的行为，可能会被利用产生不良响应。本文研究了利用现成的LLMs在直接红队战术中的有效性，其中攻击者LLM旨在从目标LLM获取不良输出，比较了单轮和会话式红队战术。我们的实验提供了各种使用策略的见解，这些策略会显著影响它们作为红队成员的表现。他们认为，现成的模型可以作为有效的红队成员，甚至可以根据过去的尝试调整攻击策略，尽管随着对齐度的增加，它们的有效性会降低。

## Untie the Knots：语言模型长文本预训练的高效数据增强策略

贡献人：

链接：http://arxiv.org/abs/2409.04774v1

大型语言模型（LLM）优先考虑扩展上下文窗口，以便模型能够纳入更多信息。然而，训练模型处理长上下文存在显著挑战，包括高质量自然长上下文数据的稀缺，可能导致短上下文任务性能下降，以及与注意力机制相关的训练效率降低。在本文中，我们引入了Untie the Knots（UtK），这是一种新的数据增强策略，用于在继续预训练阶段实现LLM有效获取长上下文能力，而无需修改现有数据混合。具体地，我们对文档进行分块，打乱这些块，并创建一个复杂且纠结的长文本结构；然后训练LLM解开这些结，识别看似混乱的token序列中的相关片段。这种方法极大地改善了模型的性能，准确关注长上下文中的相关信息，训练效率也大大提高。我们在具有7B和72B参数的模型上进行了大量实验，训练20亿个token，结果表明UtK在128K上下文长度的RULER上达到了75%和84.5%的准确率，明显优于其他长上下文策略。训练好的模型将进行开源以供进一步研究。

## 代码预训练如何影响大语言模型任务表现？

贡献人：

链接：http://arxiv.org/abs/2409.04556v1

大语言模型越来越多地在包含自然语言和非语言数据（如源代码）的语料库上进行训练。除了帮助与编程相关的任务外，有传闻称，在预训练语料库中包含代码可能会提高在其他无关任务上的性能，但迄今为止没有工作能够通过控制语言和代码数据之间的关系来建立因果关系。在这里，我们做到了这一点。我们在交替自然语言和代码的数据集上对语言模型进行预训练，在两种不同的设置中：加法，其中在预训练期间看到的数据总量保持恒定；竞争，其中语言数据的量保持恒定。我们研究了预训练混合物如何影响（a）BigBench基准测试中包含的各种任务的性能以及（b）组成性，通过语义解析和句法变换上的泛化精度来衡量。我们发现，在更高比例的代码预训练可以提高涉及结构化输出（如语义解析）和数学的组合任务的性能。相反，增加代码混合可能会损害其他任务的性能，包括需要对语言结构敏感的任务，如语法或形态，以及衡量现实世界知识的任务。

## BIOSer必读：AMD开源芯片初始化代码openSIL，计划替代AGESA

https://zhuanlan.zhihu.com/p/719156174?utm_psn=1816656201729064960

随着计算机硬件的不断发展，固件在硬件性能优化、系统稳定性及安全性方面扮演着至关重要的角色。在这一背景下，固件领域正经历一场静默的变革，核心是“开源开放”。这场变革不仅涉及系统固件，还涵盖周边设备的固件。Intel和AMD分别提出了新的固件策略，Intel推出了USF（Unified System Firmware），聚焦BootLoader中立，AMD则选择开源其芯片初始化代码，并推出openSIL。

2023年8月，AMD宣布了其开源计划openSIL，旨在逐步取代传统的AGESA（AMD Generic Encapsulated Software Architecture），这是AMD长期以来用于处理器启动初始化的核心代码。AGESA虽然功能强大，但随着技术发展，面临复杂性和维护难度等问题。openSIL的目标是通过完全开源的方式，让开发者能深入了解、修改固件代码，推动固件生态的创新。

AMD计划在2025-2026年间完成openSIL的产品化，最初将在其EPYC “Zen 6”处理器上实现原型验证。随着openSIL的推进，AGESA将逐步被淘汰，openSIL将成为固件的主流方案。openSIL代码目前已在GitHub上开源，虽内容尚不完善，但展示了未来的固件开发趋势。相比之下，Intel的FSP固件仍然闭源，这使得AMD的开源策略对行业产生了重大影响。
