### 技巧3：让模型访问特定函数

`Chat completions API` 允许在请求中传递函数描述列表。这样，模型就能根据提供的模式生成函数参数。生成的函数参数由 `API` 以 `JSON` 格式返回，可用于执行函数调用。然后，函数调用提供的输出可以在下一个请求中反馈到模型中，以结束循环。这是使用 `GPT` 模型调用外部函数的推荐方式。

### 6）系统地测试每一个prompt变更

有时，很难说清一项改变（如新指令或新设计）会使系统变好还是变坏。通过观察一些示例可能会发现哪个更好，但在样本量较小的情况下，很难区分是真正的改进还是随机的运气。也许改变有助于提高某些输入的性能，但会降低其他输入的性能。

评估有助于优化系统设计。好的“评估”包括：

+ 能代表真实世界的使用情况（或至少具有多样性）
+ 包含许多测试用例 ，以提高统计能力（准则见下表）
+ 易于自动化或重复

| --- | --- |
| 30% | ~10 |
| 10% | ~100 |
| 3% | ~1,000 |
| 1% | ~10,000 |

对输出结果的评估可以由计算机、人工或混合方式完成。计算机可以根据客观标准（例如只有一个正确答案的问题）以及一些主观或模糊标准自动进行评估，其中模型输出由其他模型查询进行评估。`OpenAI Evals` 是一个开源软件框架，提供创建自动 evals 的工具。

当存在一系列被认为质量同样高的可能输出时（例如，对于答案较长的问题），基于模型的 evals 就会非常有用。哪些内容可以通过基于模型的评估进行实际评估，哪些内容需要人工评估，这两者之间的界限是模糊的，并且随着模型能力的提高而不断变化。我们鼓励通过实验来了解基于模型的评估在您的使用案例中的效果如何。

# Prompt开发调试工具

对于大模型应用来讲， prompt 至关重要，前面介绍了prompt的相关技术理论和编写技巧，然而，prompt是一个强实验性的技术，需要多次迭代比对，评估从而找出最适合的提示词。“工欲善其事，必先利其器”，要想更高效的迭代提示词，那么优秀的提示词管理和开发工具就成了关键。

![](img/a754fd2e7058e5d2a82ccb82d1c3b30b.png)

从功能角度讲，一个prompt调试工具最基本的能力就是能够根据通过界面选择不同的模型和参数，能够观察prompt的输出。 在此基础上，能够支持多个模型的比较，并且由于prompt的修改频繁，需要有类似代码变更那样的prompt库,包含prompt版本、历史、收藏、分享等常规功能。 进一步的，提供不同prompt技术的编写模版， 如`few-shot` 及参数化方法，可以根据前面提到的prompt结构分块迭代优化，进行专业性赋能。 对于一些复杂的场景，还涉及到精心构造prompt调 起 工具或者函数执行等能力的集成调试。 结合最佳实践，能够自动 地 对prompt进行优化，如字符长度，完整性。 为了评估prompt在场景中普遍效果，需要能够有单条及批量的评估能力。 最后，支持将prompt封装为服务或脚本，以便进一步地 编排集成形成`LLM`场景应用。 其整个过程可以简单理解为是一个手动或自动不断优化的过程，并逐步固化为`LLM`应用的核心构件的过程。

相对于`chatgpt`作为面向普通用户的产品，不用特别区分prompt的结构和作用，并且默认已经支持了多轮会话，而对于面向开发者的`playground`来说，`openAI`对prompt进行了分解，以便于编程，将提交给服务器的信息分为`System Message`，`User Message`和`Assistant Message`。通常，`System Message`为与用户输入无关的模型角色定义及上下文信息，`User Message`为用户的输入，包含问题或者对话信息。`Assistant Message`为模型的回复。

![](img/d2eab8cb73810858e915070a994f5a79.png)

### 其他参数含义

`Temperature`：温度，控制生成的随机性或创造性，取值在0-2之间，默认值为1，越接近0，回答的结果越确定，越集中，简短，自信，`temperature`越高，创造性越强，更多样，更话痨，设置该值可根据其应用场合来设置。

`Maximum length`：输出的最大`token`数量，在 `GPT-3.5` 中，允许的最大长度为 2048 或大约 1,500 个单词。

`Stop sequences`：停止序列用于告诉模型何时停止生成输出。通过它们，您可以隐式地控制生成内容的长度。例如，如果您只想要一个单句的问题答案，可以使用 .作为停止序列。或者，如果想要一个段落的答案，可以使用新行作为停止序列。

`Top P`:另一种 随机因子，温度采样的替代方案，对应机器学习中的核采样，其思路是，将生成的词案概率高低排序，然后选择阈值P以内的候选词，然后再根据`temperature`进 行采样。

`Presence penalty` 和 `Frequency penalty` ：这两个参数都是通过影响模型的预测输出的概率分布来控制下一个生成的词，进而控制生成的多样性和质量。这两个参数的范围都在 [-2,2] 之间。值大于 0 表示文本生成将尽量减少出现重复的 `token`。

+ `F requency_penalty` （频率惩罚）是通过`token` 训练时出现的频率来控制高频词输出。值越大，训练过程中看到的高频次词汇被生成出来的概率就越低，从而降低模型逐字重复同一行的可能性。

+ `Presence penalty`（存在惩罚） 是通过前文 `token` 是否出现了来控制重复 `token` 的出现，值越大，在 预测生成的`token`中出现的词被生成出来的概率就越低，从而增加模型谈论新主题的可能性。

`OpenAI Playground`是基于`GPT 3.5`或`4.0`模型开发的最基础prompt调试工具，里面的功能和参数概念是当前`LLM`开发的事实标准，值得大家学习掌握。

## 小结

除此之外，市场上还有很多prompt相关的工具，如`PromptDrive`， `Promptify` ， `Fusion` ，以及在热门的`Prompt Engineering`学习网站（`https://www.promptingguide.ai/tools`）中整理了很多Prompt 相关的工具，感兴趣的读者可以深入了解。

但prompt开发并非`LLM`应用的全部，因此，在这类工具上都存在一个问题，就是无法完成整个`LLM`应用的业务流程，这也为后面的编排框架提供了生存的土壤。因此，实际的`LLMOPS`平台设计中，将prompt作为一个模块嵌入到整个`LLMOPS`平台中是最佳的方案。

# 基于Prompt催生的一些新的编程范式

`LLM`技术的兴起，带来的是`AI`应用开发范式的改变。而这一切的变化来自于`LLM`独特的操作模式。通过Prompt可以让大模型完成各种不同的任务，从传统的`NLP`任务，如情感分析，摘要总结，到大模型特有的逻辑推理不一而足。正是如此，`MLOPS`到`LLMOPS`的应用开发方式转变来自于以数据为中心的模型训练推理的闭环构建向以`finetune`模型为中心的应用构建转变。

![](img/7bff7ddf5970790976151845acd31d35.png)

在这样的大背景下，业内结合大模型的能力特点及层出不穷的Prompt技术，在此形成了一些工程化应用的架构范式。所谓架构范式，就是一种将一些共性的场景问题用一种共识性的解决框架，在此框架上解决问题可以提高成功率，降低实现难度。最典型的基于Prompt技术构建的`LLM`应用架构模式为`RAG`和`Agent`，在接下来内容中将分别对这两种模式进行介绍。

## RAG

当前`LLM`应用最火的实现方式莫过于`RAG`，`RAG`最火的核心原因在于做到了大模型的能力与场景需要的结合。受限于大模型的`context window`大小限制、性能，信息的及时性以及难以克服的幻觉，内容可信等多方面技术要求，加之于大模型的交互可以简化为问答式聊天的场景交互，使得`RAG`成为知识问答， 任务 辅助（`Copilot`，使用工具+多轮对话）等的核心架构。

![](img/b3cfdad90fa2dd24a7ea65dc8dee8bf6.png)

## Agent

要说`RAG`是`LLM`应用到场景的一种妥协形态，那么`Agent`就是真正迈向`AGI`的变革式的新方案。不论是`RAG`还是进阶的`Copilot`，其本质是为了提高人类效率，是既有业务模式上的体验增强，其每一步都需要和人类协同完成。

![](img/63f7caf8cfc421067b1018d7aea492ca.png)

而`Agent`则是为了替代人而出现，给定一个既有目标或复杂任务，让机器自己去思考如何分解完成，而整个过程无需人类参与，甚至到了`Muti-Agent`阶段，`Agent`可以有效分工协作进而替代一个组织，完成更为复杂的任务。公司运营将更多通过使用 `AI` `Agent` 和工具进行，而不全是人类员工。这种`AI+`员工的新模式将对未来组织形式产生深远的影响。

![](img/cb244d9c959cfddea7f37d44f776e7fc.png)

可以看到，`Agent`与`RAG`的本质区别在于`RAG`等`LLMChain`的解决问题的核心流程是人工确定的，`LLM`在过程中只起到局部作用，而`Agent`的整个解决问题的流程都是由`AI`自主确定的，`LLM`在此期间起着决定性作用，没有了`LLM`那么这个应用将无法工作，可以说`Agent`才是真正的高纯度`AI-Native`的范式，甚至可以说是真的`AI APP`的编程范式。

### 何为Agent

`Agent`并不是一个新概念，早在前人工智能时代就有软件智能体的概念，是人类认知上最符合人类认知的智能形态，比如游戏中的`NPC`，利用构造行为树，使得`NPC`能够根据环境自动的完成观察，攻击，回血等动作。就像之前提到的那样，到了`AI`时代，有了`LLM`的加持，`Agent`被当作是走向`AGI`梦想的一个关键形态。

![](img/139a869e4b92522e1708f3a2823ce52a.png)

`Agent`的智能程度和其采用的技术直接相关，从早期规则，再到状态机，后来的行为树，最后到了大模型，特别是`ChatGPT`的发布，关于`Agent`的实现研究有了大规模明显的增长。而其本质在于大模型技术特有的智能涌现，让`Agent`实现人类预期的智能成为一种可能。

作为基于`OpenAI`大模型接口，最早实现`Agent`的框架`Langchain`，它在其官方文档这么介绍`Agent`：

> Agent
>
> The core idea of agents is to use an `LLM` to choose a sequence of actions to take. In chains, a sequence of actions is hardcoded (in code). In agents, a language model is used as a reasoning engine to determine which actions to take and in which order.
>
> https://python.langchain.com/docs/modules/agents/

![](img/b9ee8e9b74c0adfc9e83d8d7eb99fbe6.png)

可以看出，它的解释是与其`Chain`做比较，就如前文所讲，一个任务的规划本质上是一个处理流编排的过程，而是不是`Agent`关键在于这个流程是人定义的，还是大模型来指定的。另一个关键问题是，这样一个流程是根据实际执行的过程结合外界反馈动态执行的，还是一次性的生成静态执行，这体现了`Agent`的智能程度和处理外界复杂情况的鲁棒性。这里需要区分另一个概念：超自动化（`RPA`），而他们之间的核心便是`AI`和人之间主导权的问题，以及整个流程是否能够随着数据反馈自我进化。

> 超级自动化是使用人工智能 (`AI`)、机器学习 (`ML`)、自然语言处理 (`NLP`)、流程挖掘和机器人流程自动化 (`RPA`) 等先进自动化技术生态系统的过程。它旨在通过自动化业务流程来增强人类知识，使企业从高效的决策和生产中受益。

`Agent`并不是算法，而是一种基于`LLM`的工程实现，其核心依托于`LLM`的能力，通过外在的Prompt来激发大模型的规划推理等智能能力，从而达到一种前所未有的效果，这也是我们将它放在Prompt这一张介绍的原因。但需要明确的`LLM`并不是全部，`Agent`是一种工程架构实现系统，包含着其他的构成部分，不能简单割裂看待。

### Agent的架构

在复旦大学《The Rise and Potential of Large Language Model Based Agents: A Survey》论文中，一个完整的基于`LLM`的`Agents`系统，包含了三个模块，大脑（`Brain`），感知（`Perception`）和行动（`Action`）。大脑模块承担着记忆、思考等基本任务，以及决策。感知模块感知和处理来自外部环境的多模式信息，行动模块使用工具和影响周围环境。

一般来说，`Agent`的工作流程为：首先，感知模块，类似人类的感觉系统，如眼睛和耳朵，感知外部环境，然后将多模式信息转换为可被`Agent`理解的表达。随后，作为控制中心的大脑模块参与信息处理活动，如思考、决策和记忆和知识的存储操作。最后，动作模块与人体肢体相对应，执行在工具的帮助下执行，并对周围环境产生影响。通过重复上述过程中，`Agent`可以不断地获得反馈并与环境交互。

#### 1）大脑负责记忆（回话信息及知识）存储，以及决策、推理、规划。

在 这个 框架中，“ 记 忆 ”存储了`Agent`的相关知识及 过去的观察、想法和行动的序列，可参考人类分为短时记忆和长期记忆，短时记忆以上下文会话为主，一般作为上下文内容提交给大模型，而长时记忆以知识内容为主， 包含于语言知识 、 常识 和专业领域知识，通常存储在外部存储中，如向量数据库中，按需检索 。而在 记忆存储时面临两个挑战，一是记忆容量有限，短时记忆（会话 历史） 的长度 突破了模型的上下文窗口大小导致记忆的截断 ， 二是长期记忆 检索困难， 由于大量的历史信息 导致提取相关主题的 记忆信息变得困难，导致在处理当下任务时无法有效回应。

![](img/0e4cc56cecf0a28623d6a5a37b1da898.png)

对于第一个挑战，即提高记忆容量上，可以从提高大模型的上下文长度，总结提炼记忆内容，利用向量等数据结构压缩记忆。对于记忆检索，当`Agent`与其环境或用户交互时从内存中检索最合适的内容。这样可以确保`Agent`访问相关且准确的信息以执行特定操作，这里的记忆检索过程是一个自动的行为，而这一行为通常考虑三个指标：近期性，相关性和重要性，而其最终召回的结果由这些指标加权排序获得。另外，也有类似于交互式记忆的方式是，即用户通过操纵记忆信息，从而对齐记忆和用户期待。

推理和规划是`Agent`大脑的另一个重要能力，它们都是大模型智能涌现的结果，而这些能力的激发方式便是前面提到的prompt技术，特别是以`cot`为代表的高阶Prompt技术。

除此之外，`Agent`大脑还应包含“举一反三”的迁移泛化能力。这其中涉及到了微调阶段训练集未见到的任务的处理能力，少量示例的上下文学习以及不断更新迭代技能的持续学习能力。
