
## 12.1 RAG 工作流程 （RAG Workflow）

+   用户提交问题。系统可能会对问题进行改写或扩充，以便更好地进行搜索。

1.  检索阶段 （Retrieval Phase）：

+   系统激活检索组件，在外部知识库（数据库、文档库）中搜索相关信息。

+   **核心技术**：这一步依赖于将文本转化为向量表示（Vector Representations），计算查询与文档之间的相似度。

1.  信息提取 （Information Retrieval）：

+   系统检索出一组相关的文档片段（Chunks）。这些片段是基于相关性评分选出的。

1.  响应生成 （Response Generation）：

+   将检索到的信息作为**上下文 （Context）**，连同原始问题一起喂给 LLM。

+   LLM 结合自身的预训练知识和新提供的上下文生成回答。

1.  结果交付 （Response Delivery）：

+   向用户输出最终答案。这个答案不仅基于模型记忆，更基于实时的外部数据。

## 12.2 检索模型：稀疏与稠密 （Retrieval Models）

检索的质量决定了 RAG 的上限。目前主要有两种检索机制：

### 12.2.1 稀疏检索器 （Sparse Retriever）

+   **原理**：基于关键词匹配 （Keyword matching）。

+   **机制**：在数据库中筛选包含与查询词相似关键字的文档（如 TF-IDF， BM25 算法）。

+   **优势**：简单、高效，特别适合大规模数据库的快速查找（Quick lookups）。

+   **劣势**：无法理解语义，对同义词或隐含意义处理能力弱。

### 12.2.2 稠密检索器 （Dense Retriever）

+   **原理**：基于向量表示 （Vector representations）。

+   **机制**：将查询和文档都转换成高维向量（Embeddings）。通过计算向量之间的距离（如余弦相似度）来衡量相关性。

+   **优势**：能够捕捉上下文相关性 （Contextually related），即使没有关键词重合也能找到语义匹配的文档。

+   **劣势**：计算量大，需要专门的向量数据库支持。

## 12.3 基础设施：向量数据库 （The Vector Database）

**为了支持稠密检索**，我们需要一种新型数据库——向量数据库。

+   **核心功能**：专门用于存储、索引和查询非结构化数据的向量嵌入 （Embeddings）。

+   **混合搜索**：**现代向量数据库**（如阿里云 AnalyticDB for PostgreSQL）通常支持结构化数据与非结构化向量数据的混合查询。

+   **运算能力**：支持向量相似度搜索（欧几里得距离、余弦相似度等）、向量聚合与算术运算。

## 12.4 生成器架构模式 （Generator Models in RAG）

根据检索器如何增强生成器，RAG 的基础架构可以分为四类：

1.  基于查询 （Query-based）：

+   **机制**：最常见的方法。检索到的 `Top-k` 文档片段直接作为提示词上下文 （Prompt Context） 喂给生成器。

+   **优点**：简单，可解释性强。

+   **缺点**：受限于上下文窗口大小（Context Window Limits）。

1.  **基于潜在表示 （Latent representation-based）**

+   **机制**：检索操作发生在嵌入空间 （Embedding space）。生成器直接与检索到的潜在向量交互，而不是处理原始文本。

+   **优点**：更紧凑，节省 Token 预算。

1.  基于对数 （Logit-based）：

+   **机制**：检索结果直接影响生成模型输出层的概率分布 （Logits）。模型会根据检索内容增加某些 Token 生成的概率。

+   **优点**：对生成过程有精细的控制。

1.  推测式 （Speculative）：

+   **机制**：使用一个轻量级模型（通常由检索引导）先起草 Token，再由大模型进行验证或修正。

+   **优点**：提高吞吐量，降低延迟。

# 第十三章：AI 智能体 （AI Agents）

如果说 LLM 是一个聪明的“大脑”，RAG 是给大脑配了一座“图书馆”，那么 AI 智能体 （AI Agent） 就是为这个大脑装上了“手脚”和“记忆”。智能体是一个超越了单纯文本生成的复杂系统，它能够理解用户的高阶目标，自主规划并执行一系列操作来完成任务。

## 13.1 智能体的核心架构 （The Agent Architecture）

一个功能完备的 LLM 智能体通常由五个核心模块构成一个循环系统：

1.  **提示 （Prompt）**：用户的初始请求或高阶目标。

1.  **大脑 （Brain）**：作为中央协调器（Coordinator）的 LLM。

1.  **规划 （Planning）**：将复杂任务分解为一系列可执行的子任务。

1.  **记忆 （Memory）**：存储过去的交互历史、学习经验和世界知识。

1.  **行动 （Action）**：调用外部工具（Tools）来执行计划并与真实世界互动。

## 13.2 智能体的大脑：LLM 核心模块 （The "Brain"）

作为智能体的“大脑”，LLM 不仅负责生成文本，更重要的是进行决策和协调。一个精心设计的 Prompt 是激活大脑的关键。

### 13.2.1 人设 （Persona）

+   **定义**：为智能体设定一个角色、风格和背景。这决定了智能体如何与用户互动。

+   **构建方法**：

+   手工制作 （Handcrafting）：灵活，但依赖人工。

+   LLM 生成 （LLM-Generation）：利用 LLM 的创造力生成人设。

+   数据对齐 （Dataset Alignment）：基于真实世界的数据集进行微调。

### 13.2.2 指令 （Instructions）

+   **定义**：清晰、无歧义的任务指南，确保智能体准确高效地执行任务。

+   **作用**：将用户的自然语言请求转化为机器可理解的操作步骤。

## 13.3 规划模块：从思维链到思维树 （The Planning Module）

规划能力是智能体区别于普通聊天机器人的核心。它负责将一个模糊的目标（如“帮我规划一次旅行”）分解为具体的步骤。

+   思维链 （Chain of Thought， CoT）：

+   **机制**：单路径推理。模型一步一步地思考，形成一个线性的推理过程。

+   **特点**：简单有效，适用于大多数逻辑推理任务。

+   思维树 （Tree of Thoughts， ToT）：

+   **机制**：多路径推理。模型同时探索多个不同的推理路径，并评估哪条路最优。

+   **特点**：更强大，能解决需要探索和回溯的复杂问题。

## 13.4 记忆模块：短期与长期 （The Memory Module）

记忆使得智能体能够从经验中学习，并保持行为的一致性。

### 13.4.1 短期记忆 （Short-term Memory， STM）

+   **实现**：通常通过上下文窗口 （Context Window） 实现。

+   **特点**：存储当前对话的上下文，但容量有限，对话过长会被遗忘。

### 13.4.2 长期记忆 （Long-term Memory， LTM）

+   **实现**：通常利用外部向量存储 （External Vector Store）。

+   **特点**：存储智能体的核心知识、用户偏好、过去的行为等。可以被快速、可扩展地检索。

### 13.4.3 记忆的存储格式与操作

+   **四种格式**：自然语言、数据库、嵌入向量、结构化列表。

+   **四种操作**：

+   **存储 （Store）**：归档新经验。

+   **检索 （Retrieve）**：提取相关记忆。

+   **更新 （Update）**：根据新信息修正记忆。

+   **修剪 （Prune）**：移除过时或不重要的记忆。

## 13.5 行动模块：连接真实世界 （The Action Module）

**行动 （Action）**，也常被称为**工具使用 （Tool Use）**，是智能体将计划转化为实际结果的关键。

+   **机制**：智能体的大脑（LLM）决定何时、如何调用外部工具（如 API）。

+   **工具示例**：

+   **信息获取**：调用搜索引擎 API、股票数据 API。

+   **软件操作**：调用日历 API 安排会议、调用邮件 API 发送邮件。

+   **物理世界**：控制智能家居设备。

## 13.6 学习要点总结

1.  **从被动到主动**：智能体（Agent）标志着 AI 从单纯的“文本生成器”进化为能够感知环境、自主规划并执行任务的“行动者”。

1.  **五脏俱全**：一个完整的智能体架构由 **大脑 （LLM）**、**规划 （Planning）**、**记忆 （Memory）**、**行动 （Action）** 和 人设 （Profile/Prompt） 五大模块协同工作。

1.  **思维的深度**：规划模块通过 **思维链 （CoT）** 和 **思维树 （ToT）** 技术，赋予了 AI 将复杂抽象目标拆解为具体可执行步骤的能力。

1.  **记忆的扩展**：为了突破上下文窗口的限制，智能体引入了 长期记忆 （LTM），通常利用向量数据库来存储和检索过往经验，确保持续学习和行为一致性。

1.  **工具的力量**：行动模块是智能体的“手脚”，通过调用 API（如搜索、日历、计算器），AI 打破了数字世界的壁垒，产生了实质性的产出。

# 第十四章：AI 算力基础设施 （AI Infrastructure & GPU Acceleration）

随着大模型参数量从数亿迈向万亿级别，AI 对算力的需求呈现指数级增长。传统的 CPU（中央处理器）已无法满足深度学习庞大的并行计算需求。本章将探讨如何构建高效、弹性且极具性价比的 AI 算力底座，重点解析阿里云的异构计算 （Heterogeneous Computing） 体系。

## 14.1 AI 时代的算力挑战 （Compute in the Age of AI）

### 14.1.1 模型规模的爆发

自 2018 年以来，预训练模型的规模发生了质的飞跃。

+   **趋势**：从早期的 GPT-1 到现在的万亿参数模型（Trillions of Parameters），模型体量增长了数千倍。

+   **后果**：今天的 AI 不仅能力更强，也变得更加“耗电” （Power-hungry）。训练一个大模型需要消耗惊人的计算资源和电力。

### 14.1.2 为什么需要云端 GPU？

对于企业而言，自建大规模 GPU 集群面临着成本高、维护难、扩展性差的问题。云端 GPU 实例（如阿里云 ECS）提供了以下核心价值：

+   **弹性 （Elasticity）**：按需取用，应对突发流量。

+   安全性与可靠性 （Security & Reliability）：多区域容灾，企业级安全保障。

+   无形成本 （Unseen cost benefits）：省去了硬件维护、电力和运维团队的隐性成本。

---

## 14.2 异构计算家族 （Heterogeneous Compute Family）

为了应对不同的 AI 工作负载，现代云平台提供了多种计算架构的组合，统称为异构计算。

### 14.2.1 计算架构谱系

1.  **GPU （图形处理器）**：

+   **特点**：大规模并行计算能力。

+   **用途**：深度学习训练（Training）与推理（Inference）、视频渲染。

1.  **FPGA （现场可编程门阵列）**：

+   **特点**：硬件可重构，低延迟。

+   **用途**：逻辑设计验证、特定算法加速。

1.  **ASIC （专用集成电路）**：

+   **特点**：为特定任务定制，能效比极高（如 NPU）。

+   **用途**：高频推理场景。

1.  **EAIS （弹性加速计算实例）**：

+   **特点**：将 CPU 和 GPU 解耦，通过网络连接。可以为普通的 CPU 实例“外挂”一个 GPU 加速器。

---

## 14.3 性能黄金三角 （The Golden Triangle）

在构建顶级 AI 基础设施时，单靠堆砌 GPU 是不够的。阿里云提出了“黄金三角”架构，从计算、网络、存储三个维度消除瓶颈。

### 14.3.1 计算：AIACC 加速器

+   **全称**：Apsara AI Accelerator。

+   **作用**：这是一个软件加速引擎，专门用于优化基于主流框架（如 `TensorFlow`， `PyTorch`）的训练和推理任务。

+   **效果**：在不增加硬件投入的情况下，仅通过软件优化即可显著提升性能（如 NLP 训练效率提升 700%）。

### 14.3.2 网络：SCC 集群

+   **全称**：Super Computing Cluster （SCC）。

+   **作用**：提供低延迟 （Low latency） 的节点间通信。

+   **意义**：在大规模分布式训练中，多台机器之间需要频繁交换参数。SCC 通过 RDMA 技术（如 RoCE 网络）确保网络不会成为拖慢整体训练速度的短板。

### 14.3.3 存储：CPFS 文件系统

+   **全称**：Cloud Parallel File System。

+   **作用**：提供高吞吐量 （High throughput） 的并行文件存储。

+   **意义**：训练数据往往是海量的小文件（如亿级图片）。CPFS 确保 GPU 在训练时能瞬间读取到数据，避免“计算等数据”的情况。

---

## 14.4 核心技术详解：AIACC 与 cGPU （Core Technologies）

在硬件之上，两项关键的软件技术决定了资源利用率和性价比。

### 14.4.1 AIACC：压榨硬件潜能

AIACC 是阿里云自研的 AI 加速引擎，它通过统一的加速框架，对深度学习任务进行图优化、算子融合和通信优化。

+   **价值**：让同样的 GPU 跑得更快。

### 14.4.2 cGPU：虚拟化切片 （Compute Slicing）

在推理场景中，一个强大的 GPU 往往性能过剩。cGPU 技术允许将一块物理 GPU 切分成多个虚拟切片。

+   **隔离性**：支持 **显存隔离** 和 **算力隔离**。不同容器（Docker）之间互不干扰。

+   **灵活性**：用户可以灵活分配显存大小（如切分出 1/4 个 GPU 给某个小服务）。

+   **成本优势**：多个轻量级业务共享一张卡，大幅降低成本。

---

## 14.5 学习要点总结

1.  **算力即权力**：大模型时代，GPU 集群的规模和效率直接决定了模型迭代的速度。

1.  **木桶效应**：高性能计算不仅仅是买最贵的 GPU，还需要配套的高速网络（SCC）和并行存储（CPFS）来组成“黄金三角”，缺一不可。

1.  **软硬结合**：硬件决定了性能的上限，而软件（如 AIACC）决定了你能发挥出多少性能。

1.  **降本增效**：通过 EAIS（外挂 GPU）和 cGPU（切分 GPU）技术，企业可以根据实际负载极其精细地管理算力资源，避免大炮打蚊子。
