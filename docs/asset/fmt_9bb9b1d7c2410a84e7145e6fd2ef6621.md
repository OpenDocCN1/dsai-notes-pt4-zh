### 问题 3: 远程访问失败 - VPS 部署无法连接

**症状：**

+   本地能访问 `http://localhost:18789`，但远程无法访问
+   浏览器显示 “连接被拒绝” 或 `ERR_CONNECTION_REFUSED`

**根本原因：**

OpenClaw 默认只监听 `127.0.0.1`（本地回环地址），不接受外部连接。这是安全设计，防止未授权访问。

**⚠️ 安全警告：**

将 Gateway 暴露到公网是极其危险的！2026 年 1 月发生过 42,000 个暴露实例被发现的安全事件。

**安全的解决方案：**

方案 A: 使用 SSH 隧道（推荐）

```
# 在本地机器上运行
ssh -L 18789:localhost:18789 user@your-vps-ip

# 然后在本地浏览器访问
http://localhost:18789
```

方案 B: 使用 Tailscale/WireGuard VPN

```
# 1. 在 VPS 和本地都安装 Tailscale
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up

# 2. OpenClaw 保持监听 127.0.0.1
# 3. 通过 Tailscale IP 访问(如 100.x.x.x:18789)
```

方案 C: 反向代理 + 认证（生产环境）

```
# Nginx 配置
server {
    listen 443 ssl;
    server_name openclaw.yourdomain.com;

    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    # 基础认证
    auth_basic "OpenClaw Access";
    auth_basic_user_file /etc/nginx/.htpasswd;

    location / {
        proxy_pass http://127.0.0.1:18789;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

**❌ 不安全的做法（切勿使用）:**

```
# 不要这样做!
gateway:
  host: "0.0.0.0"  # 暴露到所有网络接口
  auth: "none"     # 2026.1.29 版本后已移除此选项
```

### 6.1.3 权限配置问题

#### 问题 1: 文件系统权限不足

**症状：**

```
Error: EACCES: permission denied, mkdir '/home/user/.openclaw'
Error: EACCES: permission denied, open '/home/user/.openclaw/openclaw.yaml'
```

**根本原因：**

+   OpenClaw 需要在用户目录创建配置文件和数据目录
+   当前用户对 `~/.openclaw` 目录没有写权限
+   在 Docker 中运行时，容器内外的 `UID/GID` 不匹配

**解决方案：**

**场景 A: 本地安装**

```
# 修复目录权限
sudo chown -R $USER:$USER ~/.openclaw
chmod -R 755 ~/.openclaw

# 或删除后重建
rm -rf ~/.openclaw
openclaw onboard  # 重新初始化
```

**场景 B: Docker 部署**

```
# docker-compose.yml
services:
  openclaw:
    image: openclaw/openclaw:latest
    user: "${UID}:${GID}"  # 使用宿主机的 UID/GID
    volumes:
      - ./openclaw-data:/home/openclaw/.openclaw
    environment:
      - HOME=/home/openclaw
```

```
# 启动前设置环境变量
export UID=$(id -u)
export GID=$(id -g)
docker compose up -d
```

场景 C: 使用 `openclaw doctor` 自动修复

```
openclaw doctor --fix

# doctor 会自动:
# - 检查目录权限
# - 创建缺失的目录
# - 修复配置文件权限
```

#### 问题 2: 系统命令执行被拒绝

**症状：**

```
SYSTEM_RUN_DENIED: approval required
SYSTEM_RUN_DENIED: allowlist miss
```

**根本原因：**

OpenClaw 的安全机制：

+   **Approval 模式** - 危险命令需要人工确认
+   **Allowlist 模式** - 只允许白名单中的命令

**理解执行模式：**

```
# ~/.openclaw/openclaw.yaml
agents:
  defaults:
    tools:
      system_run:
        mode: "approval"  # 需要确认
        # mode: "allowlist"  # 仅白名单
        # mode: "yolo"  # 自动执行(危险!)
        
        allowlist:
          - "ls"
          - "cat"
          - "grep"
          - "git"
```

**模式对比：**

**解决方案：**

**方案 A: 批准单次执行**

```
用户: "帮我列出当前目录文件"
OpenClaw: "需要执行命令: ls -la, 是否允许? (yes/no)"
用户: "yes"
OpenClaw: [执行命令并返回结果]
```

**方案 B: 添加到白名单**

```
# 编辑配置文件
agents:
  defaults:
    tools:
      system_run:
        mode: "allowlist"
        allowlist:
          - "ls"
          - "cat"
          - "grep"
          - "git"
          - "npm"
          - "python3"
          # 支持通配符
          - "docker ps*"
          - "kubectl get*"
```

方案 C: YOLO 模式（仅限测试）

```
# 启动时临时启用
openclaw gateway --dangerously-skip-permissions

# 或在配置中
agents:
  defaults:
    tools:
      system_run:
        mode: "yolo"
```

**⚠️ 安全提醒：**

+   生产环境**永远不要**使用 `yolo` 模式
+   白名单中避免包含 `rm`、`sudo`、`chmod` 等危险命令
+   定期审查 `~/.openclaw/logs/` 中的命令执行日志

## 6.2 API 调用常见错误

### 6.2.1 Rate Limit 限流处理

#### 问题: 429 Rate Limit Exceeded - 最常见的问题

**症状：**

```
⚠️ API rate limit reached. Please try again later.
HTTP 429: rate_limit_error
Error: Too many requests
```

**根本原因：**

Anthropic API 有严格的分层限流机制：

为什么 Agent 特别容易触发限流？

一个简单的任务可能触发多次 API 调用：

```
用户: "帮我分析这个文件"

实际 API 调用:
1. 读取文件内容 (file_read)
2. 分析代码质量 (第1次 LLM 调用)
3. 运行 linter (shell_exec)
4. 解析 linter 输出 (第2次 LLM 调用)
5. 生成报告 (第3次 LLM 调用)

总计: 3 次 API 调用,消耗约 15,000 tokens
在 Tier 1 下,连续 4 个这样的任务就会触发限流!
```

[citation](https://blog.laozhang.ai/en/posts/openclaw-rate-limit-exceeded-429) [citation](https://www.reddit.com/r/AI_Agents/comments/1r70lq9/openclaw_broke_down_after_just_4_messages/)

---

**立即解决方案（按优先级）:**

方案 1: 等待 Token Bucket 补充（60 秒）

```
# 最简单的方法 - 等待 1 分钟
# Anthropic 使用 Token Bucket 算法,每分钟补充配额

# 或重启 Gateway 清除冷却状态
openclaw gateway restart
```

**方案 2: 检查当前状态**

```
# 查看限流状态
openclaw models status

# 输出示例:
# anthropic: cooldown active (resets in 45s)
# openai: quota exhausted (daily limit reached)
```

方案 3: 配置 Fallback 模型

```
# ~/.openclaw/openclaw.yaml
agents:
  defaults:
    model: "claude-3-5-sonnet-20241022"
    fallback:
      - "gpt-4o"           # 第一备选
      - "gemini-2.0-flash" # 第二备选
      - "deepseek-v3"      # 第三备选
```

当主模型限流时，OpenClaw 自动切换到备选模型。

[citation](https://blog.laozhang.ai/en/posts/openclaw-rate-limit-exceeded-429)

**长期解决方案：**

方案 A: 升级 Anthropic Tier

```
# 1. 查看当前 Tier
# 访问 https://console.anthropic.com/settings/limits

# 2. 充值以升级 Tier
# Tier 1 → Tier 2: 消费 $5
# Tier 2 → Tier 3: 消费 $40
# Tier 3 → Tier 4: 消费 $200

# 3. Tier 4 的容量是 Tier 1 的 80 倍!
```

**方案 B: 实现指数退避重试**

```
# 配置重试策略
agents:
  defaults:
    retry:
      max_attempts: 3
      initial_delay: 1000  # 1秒
      max_delay: 60000     # 60秒
      multiplier: 2        # 指数增长
```

方案 C: 使用 OpenRouter（无 Tier 限制）

```
# OpenRouter 提供相同模型,但没有 Tier 限制
providers:
  openrouter:
    api_key: ${OPENROUTER_API_KEY}
    base_url: https://openrouter.ai/api/v1
    models:
      - "anthropic/claude-3.5-sonnet"  # 通过 OpenRouter 访问
```

**方案 D: 分布式负载**

```

providers:

      - ${ANTHROPIC_API_KEY_1}

      - ${ANTHROPIC_API_KEY_3}
    load_balance: "round_robin"  # 或 "random"
```
