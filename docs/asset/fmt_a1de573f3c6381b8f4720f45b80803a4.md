
在推理环节，需要注意的是指定 `os.environ["OMP_NUM_THREADS"] = "8"`，OpenMP是一个跨平台的多线程实现，主线程(顺序的执行指令)生成一系列的子线程，并将任务划分给这些子线程进行执行。这些子线程并行的运行，由运行时环境将线程分配给不同的处理器。由于平台虚拟化技术和处理器信息暴露的不同，实际可使用 CPU 也许与直接获取的信息不同，当前我们在 `lscpu` 打印后看到的是 32核心，

![](img/d35f093a430597f234ce5baebc2192c9.png)

但我们可以看到启动时显示的是 8 核处理器，

![](img/37c031b8b45616516ba28a563b3bb05b.png)

[也许这会对 OpenMP](https://www.intel.com/content/www/us/en/docs/onemkl/developer-guide-windows/2023-0/improving-performance-with-threading.html) 默认值造成一定的影响，注意到英特尔 oneAPI 文档中提到：By default, Intel® oneAPI Math Kernel Library uses the number of OpenMP threads equal to the number of physical cores on the system.，故我们需要设定恰当的值让程序运行达到最佳速度。

在推理结束后，我们还需要对输出信息进行适度解码，跳过聊天模板区域；如果你不这么做，你可能会看到输出中仍存在输入的聊天模板。

![](img/eff921306fa66b160ee3cf7a6f8451c4.png)

除此之外，我们还会利用 `gradio` 以及 `streamlit` `python`前端框架实现对 Qwen2 的可交互式部署，具体内容你可以[直接参考代码中的内容](https://www.gradio.app/docs)；如果你[不熟悉，推荐你与大模型对话写作](https://docs.streamlit.io/)搞懂每一行的具体作用（可以通过消融不同组件来实现对每一个模块的深入理解）。或者你可以参考对应的官方文档，`gradio` 官方文档、`streamlit` 官方文档。

为了更高性能的部署服务，也许你还可以尝试使用 [VLLM 部署来观察吞吐量的提升](https://github.com/intel-analytics/ipex-llm/tree/main/python/llm/example/CPU/vLLM-Serving)，这里推荐参考 `VLLM` 部署官方文档进行操作。
