Dify 作为一个开源的大型语言模型（LLM）应用开发平台，区别于 LangChain 这类单触点（Single Touchpoint）产品，具有更多的交互点和更复杂的集成需求。作为更高代次的多触点（Multi-Touchpoint）服务层，它需要在不同的接口和平台上提供高度的兼容性和一致性，以确保各种不同的系统和应用能够无缝集成和交互。

![](img/eda76f73f47bb54d7e05ed67aee1668c.png)

随着 2024 年将成为多模态发展的关键时期，保持行业领先地位意味着必须适应和快速响应不断变化的技术趋势。我们深知，要更好地服务于开发者，就必须在保持底层架构的稳健基础上，赋予其更高的灵活性、可扩展性和协作能力。因此，我们对 Dify 的底层架构进行了全面重构，转向更为模块化的设计。新架构使各个组件能够独立进行开发、测试和部署；同时支持水平扩展，以便应对多样化的应用场景而无需依赖官方的升级；保持 API 的一致性，确保不同触点之间能够更加无缝地兼容。

我们为 Dify 在行业中第一个跨出这一步而感到无比激动，在这个关键时刻我们留下的第一个脚印 ——

## Dify Beehive 架构

![](img/64e74115d135900409262fe23fd68bef.png)

正如它的名字一样，Beehive 架构像蜂巢的六边形结构一样将各个环节模块化，独立而相互协同，灵活且可扩展，使得整个架构在维护和升级时更加灵活，允许单独对模块进行调整而不影响整体结构，这里涵盖了构建 LLM 应用所需的关键技术栈，包括对数百个模型的支持、直观的 Prompt 编排界面、高质量的 RAG 引擎以及灵活的 Agent 框架，并同时提供了一套易用的界面和 API。这为开发者节省了许多重复造轮子的时间，使其可以专注在创新和业务需求上。

Beehive 架构的高度集成性也反映了蜂群的协作特点，不同的模块和组件紧密协作，共同完成复杂的任务。这种协作能力是 Dify 一直所追求的 AI 普世性，让非技术人员可以参与到 AI 应用的定义过程中。

在接下来的迭代中，Dify 将陆续实现更多能力的模块化，以加强 Dify 的灵活性、可拓展性，具体包括：

### RAG 引擎组件模块化

我们将对 RAG 引擎的多个环节进行模块化处理，包括 ETL、Embedding、索引建立、数据召回等。开发者可以根据自己的需求自定义各个环节所需的工具、模型和策略等，从而为开发者提供更高的灵活性和定制化能力。

### Tools 扩展

除了内置工具外，Dify 将能够加载符合 OpenAPI Specification API 标准的工具，并与遵循 OpenAI Plugin 标准的工具实现互通。这一扩展将大大增强 Dify 的工具集，使其能够适应更广泛的应用场景和用户需求。

### Workflow 灵活配置

Dify 将支持更灵活的工作流配置，使开发者能够根据自己的业务流程和需求定制化工作流。这一特性将使 Dify 成为一个适用于不同行业和场景的多功能工具，能够更好地满足不同业务需求。

伴随这次重构，我们推出了第一个服务模块 Model Runtime，它是重构计划的开始，也是提升灵活性和扩展性的重要一环。

![](img/73ac7fdd2d21c6099a34f0b033780480.png)

在 0.4.0 版本发布前，虽然 Dify 已经支持上百种主流的商业模型和开源模型(本地部署或基于 MaaS )，包括：LLM、Text Embedding、Rerank、Speech2Text、TTS 等。但由于 Dify 依赖于 LangChain 复杂且灵活性较低的框架，开发者通过 Dify 接入新的模型，将面临一些挑战，例如需要侵入式开发、缺乏标准化的接口规范，以及处理前后端使用的不同编程语言等问题。

为此，`Runtime` 简化模型接入流程，支持灵活的模型供应商配置，实现模型的可插拔性开发，这意味着开发者能够以更快的速度接入更多的模型。

## Runtime 简化模型接入流程

![](img/2feb981ea606d3b40187ccb032c672c4.png)

### 主要技术革新有：

+ **统一的接口：**所有模型类型都有一个简洁、统一的接口。无论是文本嵌入还是推理模型，都可以以一致的方式访问，让接入模型的过程更加简单高效。

```
# 我们以 Anthropic 的大语言模型举例，所有模型都继承于与之对应的模型基类class AnthropicLargeLanguageModel(LargeLanguageModel):        # _invoke() 是一个用于与所有模型调用的通用入口点。    # 以 LLM 类为例，调用会返回生成文本。    def _invoke():        # 实现调用的具体逻辑，包括处理输入/输出转换、流式传输、token 计数...            # ... 其他函数
```

+ **使用 YAML 简化配置：**通过定义的 DSL ，我们以声明性方式配置模型供应商和模型，使代码库结构更加清晰。这使得添加新模型的方式更加标准化，供应商和模型参数变得更加易读、易懂。

```
provider: anthropicdescription:  en_US: Anthropic’s powerful models, such as Claude 2 and Claude Instant.  zh_Hans: Anthropic 的强大模型，例如 Claude 2 和 Claude Instant。supported_model_types:- llm#...  credential_form_schemas:  - variable: anthropic_api_key    label:      en_US: API Key    type: secret-input# ... 其他变量
```

+ **前端独立：**现在模型可以在后端完全定义和配置，无需前端变动。这样模型逻辑与 UI 分离，使代码更模块化，加快了开发周期。
