
## 测试场景 1：初始状态 - 简单问候

### 预期行为
- `skills_loaded: []` (空)
- 可见工具: 2 个 (仅 Loaders)

### [SkillMiddleware] 第 1 次模型调用

```
skills_loaded: []
过滤后工具 (2个): ['skill_data_analysis', 'skill_text_processing']
工具数量变化: 6 → 2
已将过滤后的工具传递给模型
```

### AI 响应

目前我有两个技能加载器可用：

1. `skill_data_analysis` - 加载数据分析相关工具
2. `skill_text_processing` - 加载文本处理相关工具

这些是技能加载器，不是直接的功能工具。当您需要具体功能时，我会先调用相应的加载器来获取具体工具。

例如：
- 如果您需要文本摘要或提取关键词，我会先调用 `skill_text_processing`，然后获得具体的文本处理工具
- 如果您需要进行数据分析，我会先调用 `skill_data_analysis`，然后获得相应的数据分析工具

请问您需要什么帮助呢？我可以根据您的需求加载相应的技能工具来为您服务。

从上面的测试可以看到，Middleware 的日志显示 `skills_loaded: []`，所以模型只能看到 2 个 Loader 工具。这正是我们期望的行为！

现在让我们测试核心功能：当用户请求数据分析时，观察工具的动态加载过程。

```
print("=" * 60)
print("测试场景 2：动态加载数据分析技能")
print("=" * 60)
print("\n预期行为:")
print("   1. 第一次调用: skills_loaded=[] → 2 个工具")
print("   2. AI 调用 skill_data_analysis → 加载数据分析技能")
print("   3. 第二次调用: skills_loaded=['data_analysis'] → 4 个工具")
print("   4. AI 使用 calculate_statistics 完成任务")
print("\n" + "-" * 60)

# 重置 Middleware 计数
skill_middleware.call_count = 0

# 构造输入 - 使用 HumanMessage 对象而不是字典格式
from langchain_core.messages import HumanMessage

test_input = {
    "messages": [HumanMessage(content="我有一组销售数据 [150, 200, 180, 220, 190]，请帮我计算统计信息")],
    "skills_loaded": []  # 初始状态：没有加载任何技能
}

# 调用 Agent
result = agent.invoke(test_input)

print("-" * 60)
print("\n最终状态:")
print(f"   skills_loaded: {result.get('skills_loaded', [])}")

print("\nAI 响应:")
for msg in result.get("messages", []):
    if msg.__class__.__name__ == "AIMessage" and msg.content:
        print(msg.content)
```

## 测试场景 2：动态加载数据分析技能

### 预期行为
1. 第一次调用: `skills_loaded=[]` → 2 个工具
2. AI 调用 `skill_data_analysis` → 加载数据分析技能
3. 第二次调用: `skills_loaded=['data_analysis']` → 4 个工具
4. AI 使用 `calculate_statistics` 完成任务

### [SkillMiddleware] 第 1 次模型调用

```
skills_loaded: []
过滤后工具 (2个): ['skill_data_analysis', 'skill_text_processing']
工具数量变化: 6 → 2
已将过滤后的工具传递给模型
```

### [SkillMiddleware] 第 2 次模型调用

```
skills_loaded: ['data_analysis']
过滤后工具 (4个): ['skill_data_analysis', 'skill_text_processing', 'calculate_statistics', 'generate_chart']
工具数量变化: 6 → 4
已将过滤后的工具传递给模型
```

### [SkillMiddleware] 第 3 次模型调用

```
skills_loaded: ['data_analysis']
过滤后工具 (4个): ['skill_data_analysis', 'skill_text_processing', 'calculate_statistics', 'generate_chart']
工具数量变化: 6 → 4
已将过滤后的工具传递给模型
```

### 最终状态
`skills_loaded: ['data_analysis']`

### AI 响应

根据您提供的销售数据 `[150, 200, 180, 220, 190]`，我为您计算了以下统计信息：

#### 📊 统计结果汇总
- **数据个数**: 5 个数据点
- **总和**: 940.0
- **平均值**: 188.0
- **中位数**: 190.0
- **最小值**: 150.0
- **最大值**: 220.0
- **标准差**: ≈ 25.88

#### 📈 数据分析解读
1. **销售趋势**：平均销售额为188，最高销售额为220，最低为150，显示销售存在一定波动。
2. **数据分布**：中位数（190）略高于平均值（188），说明数据略向右偏，但整体分布相对均衡。
3. **波动性**：标准差约25.88，表示销售额围绕平均值的波动幅度适中。
4. **业绩表现**：最高值220比平均值高出约17%，而最低值150比平均值低约20%，建议关注低销售额日期的原因。

您是否需要我为您生成这组销售数据的可视化图表（如柱状图或折线图），以便更直观地查看趋势变化？

从测试结果可以清晰地看到动态工具过滤的工作过程：

1. 第一次模型调用：`skills_loaded: []`，模型只能看到 2 个 Loader 工具
2. AI 决策：发现需要数据分析功能，调用 `skill_data_analysis`
3. 技能加载：`skills_loaded` 更新为 `['data_analysis']`
4. 第二次模型调用：`skills_loaded: ['data_analysis']`，模型看到 4 个工具
5. 任务完成：使用 `calculate_statistics` 计算统计信息

这就是 Claude Skills 的核心价值：模型在每次调用时只看到相关的工具，大大减少了 token 消耗和错误率。
