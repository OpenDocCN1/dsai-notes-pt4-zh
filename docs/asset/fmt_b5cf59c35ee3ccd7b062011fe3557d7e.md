# 第一章：Vibe Coding 概念认知篇

## 1.1 什么是 Vibe Coding？

Vibe 在英文里翻译就是“氛围”“感觉”的意思。所以 Vibe Coding，直译过来其实就是“氛围编程”或者叫“沉浸式编程”。但这里的“沉浸”不仅仅是让你沉浸在一个有仪式感的编程环境里，更重要的是它颠覆了我们以往写代码的方式。

| Vibe Coding 发展简史 | | |
| --- | --- | --- |
| 时期 | 事件 | 关键背景/意义 |
| 2010 年代初 | Bubble、Airtable、Retool 等无代码工具出现 | 无代码工具降低编程门槛，让非技术人员可通过可视化操作实现简单功能，为 Vibe Coding 奠定“低门槛创作”基础 |
| 2017 年 | 机器学习模型爆发（被称为“AI 之年”），AlphaGo Zero、Transformer 等技术突破 | AI 能力从“特定任务”转向“通用推理”，为后续自然语言驱动的代码生成提供算法支持 |
| 2021 年 | GitHub Copilot 上线（首个大规模商用 AI 结对编程工具） | AI 首次深度介入代码生成流程，开发者可通过自然语言注释触发代码补全，模糊“编码”与“描述”的边界 |
| 2024 年 | Cursor 的 `Composer` 功能上线，标志 Vibe Coding 正式诞生 | `Composer` 支持“自然语言指令生成完整代码逻辑”，无需手动编写核心代码，定义了“以意图为中心”的编程范式 |
| 2025 年 | Lovable、Bolt、Replit 等工具普及，Vibe Coding 进入“人人可用”阶段 | 多平台竞争推动工具轻量化、场景化，非技术用户可通过“说需求”直接生成实用工具（如自动文件整理、待办清单） |

「vibe coding」这个概念最早是由 Karpathy（OpenAI 联合创始人、曾任特斯拉人工智能和自动驾驶部门（Autopilot）负责人）提出的，简单说就是通过对话让 LLM 编写代码，而你只需要沉浸在解决问题的「氛围」中，同时忽略生成的代码细节。

![](img/c7d153a1e9fe05ecadbe84889825e79c.png)

想象一下，你想装修自己的房子。

+ 传统编程：就像是你必须亲自学习成为一名建筑师、水管工、电工和木匠。你需要精确地计算每一块砖的尺寸，了解每根电线的规格，亲自画出复杂的施工图纸，然后一砖一瓦地把房子盖起来。这个过程非常专业、严谨，但对新手来说，门槛极高。

+ Vibe Coding：则像你是一位业主，聘请了一位经验丰富、善于沟通的室内设计师（也就是 AI）。你不需要告诉他具体的施工参数，你只需要向他描述你的“Vibe”（感觉）：

+ “我想要一个‘侘寂风’的客厅，色调要柔和，以米白和原木色为主，光线要充足，家具要少而精，给我一种宁静、放松的感觉。”

设计师（AI）听懂了你的“Vibe”，就会自动为你生成专业的设计图纸、施工方案，甚至列出材料清单（也就是代码）。你只需要确认方案是否符合你的预期，然后让施工队（电脑）去执行就好了。

所以，Vibe Coding 的核心就是：使用自然语言（就是我们平时说的话）向 AI 描述你的需求、目标和感觉（Vibe），由 AI 自动生成可执行的代码来完成任务。

在这个过程中，你关注的是“做什么”（What）和“为什么做”（Why），而将繁琐的“怎么做”（How）交给了 AI。

> 这种方式为什么流行

1. 效率极高：你省去了大量纠结底层逻辑、调 bug 的时间，把精力全放在“到底要什么”上；想法细节全让 AI 帮你补全和落地。

2. 零门槛入门：不用是编程高手，小白都能玩得转。思路全靠主观感受+即时调整，老少咸宜，非常适合快速试错、产品原型验证、可视化 demo。

3. 沉浸式开发：你不被代码绊住，全身心沉浸在“创作”和“表达”本身。心路小宇宙全开，遇到“哪里不对劲”还可以迅速修正，流程顺滑地飞起。

## 1.2 Vibe Coding 的核心：人与 AI 的“对话式编程”

Vibe Coding 的本质是一场高质量的人机对话。你扮演“产品经理”的角色，提出需求；AI 扮演“程序员”的角色，实现需求。这场对话的质量，直接决定了最终产出的代码质量。

### 核心区别：Vibe Coding vs 传统编程 vs 普通 AI 代码补全

| 对比维度 | 传统编程 | 普通 AI 代码补全 | Vibe Coding |
| --- | --- | --- | --- |
| 核心主体 | 开发者手写全部核心代码 | 开发者为主，AI 做单行/片段补全 | AI 为主，开发者做全局管控与意图传递 |
| 入门门槛 | 需先掌握语法、数据结构、框架等全套基础知识 | 需具备成熟的开发能力，仅提升编码效率 | 0 基础可快速落地项目，边实践边补基础 |
| 工作流程 | 需求→手写代码→调试→迭代 | 需求→手写核心代码→AI 补全片段→调试 | 需求→意图拆解→AI 全流程生成→校验→对话式迭代 |
| 效率提升 | 基准线 | 提升 30%-50%编码效率 | 全流程效率提升 300%-1000%，尤其适配中小项目快速落地 |
