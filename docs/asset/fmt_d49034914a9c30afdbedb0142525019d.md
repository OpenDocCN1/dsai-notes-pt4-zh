### 4.3 不同场景最优`Coding Plan`选择（精准匹配，实测验证）

#### 场景1：个人轻度使用（每日1-2小时，简单任务：文件整理、简单脚本、文案生成）

首选：`阿里云百炼Lite版`（首月7.9元）＞`火山方舟Lite版`（首月8.9元）

理由：首月成本低至个位数，月1.8万次请求可满足日常使用，完美适配`OpenClaw`，无隐性消费，用完可随时停订；`百炼`性价比略高，模型选择更多，适合新手入门。

#### 场景2：个人高频开发（每日3小时+，复杂任务：代码生成、调试、多工具调用）

首选：`阿里云百炼Pro版`（首月39.9元）＞`火山方舟Pro版`（首月49.9元）

理由：月9万次请求足够支撑高频工具调用（文件/终端/浏览器），多模型切换满足不同任务需求，固定月费比按`Token`计费省80%以上；百炼`Pro`版首月优惠力度更大，稳定性更优，适合长期高频使用。

#### 场景3：专业开发/复杂任务（代码重构、大型项目、多智能体协作、多模态编码）

首选：`智谱GLM Max版` + `阿里云百炼Pro版`（组合使用）

理由：`GLM-5`超大模型处理复杂代码、多智能体协作能力极强，适合核心复杂任务；百炼`Pro`版支撑日常高频使用，兼顾成本与灵活性；若有截图编码等多模态需求，可替换为`Kimi Moderato版`。

#### 场景4：小团队/工作室（3-10人，共享使用，企业级需求）

首选：`腾讯云CodeBuddy`旗舰版（78元/人/月） + `火山方舟Pro版`（49.9元/首月）

理由：`腾讯云CodeBuddy`支持团队共享额度、企业级权限管理，适合团队统一管理；`火山方舟Pro`版补充超大额度，满足团队高频开发需求，成本可控，兼顾安全性与灵活性。

#### 场景5：入门级用户（预算有限，偶尔使用，简单编码需求）

首选：`MiniMax Starter版`（29元/月）

理由：价格最低，无周限额，适合偶尔使用、简单脚本生成等需求，对电脑配置要求低，入门门槛低；缺点是模型能力较弱，复杂任务适配差，不适合高频使用。

## 五、终极省钱方案三：`OpenClaw`精细化配置优化（省60%`Token`，专业实操）

无论采用本地部署还是云端`Coding Plan`，通过`OpenClaw`核心配置优化，均可进一步减少`Token`消耗，延长本地模型运行效率、提升云端额度利用率。以下配置均基于`OpenClaw v1.3.2`版本，所有参数均经实测验证，可直接复制使用，适配所有场景。

### 5.1 核心配置优化（修改`openclaw.json`，必做）

#### 优化1：开启上下文压缩（减少冗余，核心省钱配置）

作用：自动压缩旧对话、冗余工具输出为摘要，保留核心信息，避免全量保留上下文导致的`Token`暴涨，推荐所有用户开启。

```json
{
  "agents": {
    "defaults": {
      "compaction": {
        "mode": "default", // 推荐default（主动压缩），保守选择safeguard（接近上限才压缩）
        "reserveTokens": 20000, // 为AI回复预留的Token空间，避免压缩过度
        "reserveTokensFloor": 20000, // 预留空间最小值，无需修改
        "keepRecentTokens": 40000, // 保留最近40000 tokens的原始对话，兼顾记忆与省钱
        "memoryFlush": { // 压缩前提取关键信息，避免丢失核心内容
          "enabled": true,
          "softThresholdTokens": 30000, // 触发压缩的阈值
          "prompt": "提取会话关键决策、代码变更、用户偏好到memory文件，无则输出NO_FLUSH"
        }
      }
    }
  }
}
```

参数调整建议：日常使用保持默认即可；高频长会话可将`keepRecentTokens`改为30000，进一步节省`Token`；复杂任务可改为50000，保留更多细节。

#### 优化2：开启上下文修剪（清理无效冗余，进阶优化）

作用：轻量级瘦身，自动裁剪过期的工具执行结果、无效对话，尤其适合多工具调用场景，可减少30%以上的上下文`Token`占用。

```json
{
  "agents": {
    "defaults": {
      "contextPruning": {
        "mode": "cache-ttl", // 推荐cache-ttl（基于过期时间裁剪），off为关闭
        "ttl": "4h", // 缓存过期时间，4h为平衡选择（激进选5m，保守选8h）
        "keepLastAssistants": 3, // 保留最近3条AI回复的工具结果，避免丢失关键执行信息
        "softTrimRatio": 0.3, // 上下文使用超过30%触发软裁剪（裁剪长工具输出）
        "hardClearRatio": 0.5, // 上下文使用超过50%触发硬清理（替换为摘要）
        "tools": { // 工具白名单，这些工具的结果不裁剪
          "allow": ["bash", "read"],
          "deny": ["web_search"] // 网页搜索结果可裁剪，节省Token
        }
      }
    }
  }
}
```

两级裁剪策略（实测验证）：

+   软裁剪：上下文`Token`占用超过30%，超过4000字的旧工具结果，仅保留开头和结尾各1500字；

+   硬清理：上下文`Token`占用超过50%，整个旧工具结果替换为「(旧工具结果已清理)」，仅保留核心摘要。

#### 优化3：限制并发与重试（减少无效调用）

作用：避免多智能体并发调用、工具调用失败后反复重试，减少无效`Token`消耗，尤其适合云端调用场景。

```json
{
  "agents": {
    "defaults": {
      "maxConcurrent": 4, // 子代理并发数，推荐4（过多会导致并发调用，消耗翻倍）
      "toolRetry": { // 工具调用重试配置
        "maxRetries": 2, // 最多重试2次，避免无限重试
        "retryDelay": 1000, // 重试间隔1秒，减少频繁调用
        "failFast": true // 工具调用失败后快速返回，不反复尝试
      }
    }
  }
}
```

#### 优化4：设置上下文窗口与历史轮次限制（精准控制`Token`占用）

作用：根据模型能力设置上下文窗口，限制会话历史轮次，避免上下文无限增长，尤其适合本地小模型（上下文窗口较小）。

```json
{
  "agents": {
    "defaults": {
      "contextTokens": 8192, // 与本地/云端模型上下文窗口一致（本地7B模型一般为8192）
      "historyTurnLimit": 50 // 限制会话历史轮次为50轮，超过自动压缩
    }
  },
  "channels": { // 按渠道设置历史轮次限制
    "telegram": {
      "dmHistoryLimit": 50, // 私聊保留50轮
      "groups": {
        "*": {
          "historyLimit": 30 // 群聊保留30轮，减少冗余
        }
      }
    },
    "whatsapp": {
      "dmHistoryLimit": 50
    }
  }
}
```

补充说明：若出现「`Model context window too small`」错误，说明`contextTokens`设置与模型实际上下文窗口不匹配，需根据模型调整（如本地14B模型设为16384，云端`GPT-4o`设为128000）。

#### 优化5：精简技能与工具（减少提示词注入）

作用：`OpenClaw`的`Skill`列表会持续注入提示词，技能越多，提示词越长，`Token`消耗越高，需精简无用技能。

+   查看当前技能：执行`openclaw skills list`，查看所有已启用技能；

+   禁用无用技能：执行`openclaw skills disable 技能名称`，如`openclaw skills disable web_search`（无需网页搜索时禁用）；

+   精简技能描述：编辑技能文件（路径：`~/.openclaw/skills`），删除冗余描述，仅保留核心功能，越简短越省`Token`；

+   按需开启工具：仅开启日常使用的工具（如`bash`、`read`），禁用不常用工具（如`web_search`、`image_generate`），减少工具提示词注入。

### 5.2 常用CLI命令（实时监控与手动优化，必学）

通过CLI命令可实时监控`Token`消耗、手动压缩会话，避免无效消耗，以下为核心命令（实测常用）：

+   `/status`：在聊天框输入，查看当前会话模型、上下文`Token`使用量、最后响应输入/输出`Token`、预估成本（仅云端），实时掌握消耗情况；

+   `/compact`：手动压缩当前会话，立即清理冗余上下文，适合长会话后快速省`Token`；

+   `/usage off|tokens|full`：设置`Token`使用量显示模式，full模式可在每个回复后附加`Token`消耗明细；

+   `/usage cost`：查看本地成本摘要（仅本地模型，用于统计消耗）；

+   `openclaw status --usage`：CLI命令，查看所有会话的`Token`使用情况与提供商配额；

+   `openclaw config get`：查看当前所有配置，确认优化参数是否生效；

+   `openclaw config set 配置项 数值`：快速修改配置，无需手动编辑文件（如`openclaw config set agents.defaults.maxConcurrent 4`）。

### 5.3 进阶优化技巧（专业用户专属，进一步省`Token`）

+   本地模型+云端模型混合配置：设置`models.mode: "merge"`，日常任务用本地模型（零`Token`），复杂任务自动切换到云端`Coding Plan`，兼顾成本与能力；

+   开启模型缓存：在云端模型配置中添加缓存设置，设置心跳间隔为55m，避免重复缓存上下文，减少重复调用消耗；

+   分段读取大文件：避免全量读取大文件（会注入大量冗余`Token`），使用工具的「分段读取」功能，每次读取1000字以内，减少上下文占用；
