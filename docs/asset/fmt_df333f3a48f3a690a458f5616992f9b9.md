## 1 介绍

`gpt-oss-120b` 和 `gpt-oss-20b`——两款先进的开放权重语言模型，能够以低成本提供强大的实际性能。这些模型采用灵活的 `Apache 2.0` 许可证，在推理任务上的表现优于同等规模的开放模型，展现出强大的工具使用能力，并针对在消费级硬件上的高效部署进行了优化。它们采用了强化学习和 OpenAI 最先进的内部模型（包括 `o3` 和其他前沿系统）的技术进行训练。

`gpt-oss-120b` 模型在核心推理基准测试中的表现与 `OpenAI o4-mini` 几乎持平，并且能够在单个 80 GB GPU 上高效运行。`gpt-oss-20b` 模型在常见基准测试中的结果与 `OpenAI o3-mini` 相似，并且只需 16 GB 内存即可在边缘设备上运行，使其成为设备端用例、本地推理或快速迭代的理想选择，无需昂贵的基础设施。这两个模型在工具使用、小样本函数调用、`CoT` 推理（从 `Tau-Bench` 代理评估套件的结果可以看出）和 `HealthBench`（甚至超越 `OpenAI o1` 和 `GPT-4o` 等专有模型）方面也表现出色。

这些模型与 `OpenAI Responses API` 兼容，旨在用于代理工作流，具有出色的指令遵循能力、网页搜索或 `Python` 代码执行等工具使用能力以及推理能力——包括能够针对不需要复杂推理和/或以极低延迟最终输出为目标的任务调整推理工作量。它们完全可定制，提供完整的思路链（`CoT`），并支持结构化输出。

OpenAI认为安全是他们发布所有模型的基础，对开放模型也是。所以OpenAI除了对这两个开源模型进行了全面的安全训练和评估之外，还引入了额外的评估环节，即在OpenAI的“准备框架”（`Preparedness Framework`）下测试经过对抗微调的 `GPT-OSS-120B` 版本。`gpt-oss`模型在OpenAI内部安全基准测试中的表现与前沿模型相当，为开发人员提供了与OpenAI近期专有模型相同的安全标准。更多成果和细节见如下内容。

OpenAI一直与 `AI Sweden`、`Orange` 和 `Snowflake` 等早期合作伙伴合作，探索这两个开放模型的实际应用，从为了数据安全而将这些模型托管在本地，到在专用数据集上对其进行微调。OpenAI期望提供这些一流的开放模型，赋能每个人——从个人开发者到大型企业再到政府——在自己的基础架构上运行和定制 AI。结合 `OpenAI API` 中提供的模型，开发者可以选择所需的性能、成本和延迟来支持 AI 工作流。

## 2 预训练和模型架构

`gpt-oss`模型采用了OpenAI最先进的预训练和后训练技术进行训练，尤其注重推理能力、效率以及在各种部署环境中的实际可用性。虽然OpenAI已经开放了其他模型，包括 `Whisper` 和 `CLIP` ，但 `gpt-oss`模型是OpenAI自 `GPT-2` 以来首次开放权重的语言模型。

每个模型都是一个 `Transformer`，它利用混合专家（`MoE`）来减少处理输入所需的活动参数数量。`gpt-oss-120b` 每个 token 激活 51 亿个参数，而 `gpt-oss-20b` 激活 36 亿个参数。这两个模型分别有 117 亿和 21 亿个总参数。这些模型使用交替的密集和局部带状稀疏注意模式，类似于 `GPT-3` 。为了提高推理和内存效率，这些模型还使用了分组多查询注意模式，每个组的大小为 8。使用旋转位置嵌入（`RoPE`）进行位置编码，并且原生支持高达 128k 的上下文长度。

![](img/8dd7a8765062835f5eb542d3d40712cb.png)

模型的训练数据集为英文居多、纯文本的数据集，并且重点关注 `STEM`、`编程`和常识。使用 `OpenAI o4-mini` 和 `GPT-4o` 使用的标记器超集 `o200k_harmony` 对数据进行了标记，该超集现已开源。

## 3 后训练

这些模型的后训练过程与 `o4-mini` 类似，包括一个监督式微调阶段和一个高计算能力的强化学习阶段。目标是使这些模型与 OpenAI 模型规范保持一致，并在生成答案之前教会它应用 `CoT` 推理和工具使用。通过使用与 SoTA 专有推理模型相同的技术，这些模型在后训练后展现出卓越的性能。

与 API 中的 OpenAI `O` 系列推理模型类似，这两个开放权重模型支持低、中、高三种推理强度，在延迟和性能之间进行权衡。开发者只需在系统消息中输入一句话，即可轻松设置推理强度。

## 4 评估

在标准学术基准上对 `gpt-oss-120b` 和 `gpt-oss-20b` 进行了评估，用来衡量它们在编码、竞赛数学、健康和代理工具使用方面的能力，并与包括 `o3`、`o3-mini` 和 `o4-mini` 在内的其他 OpenAI 推理模型进行了比较。

`gpt-oss-120b` 在竞赛编码（`Codeforces`）、通用问题求解（`MMLU` 和 `HLE`）以及工具调用（`TauBench`）方面均优于 `OpenAI o3-mini`，并匹敌甚至超越了 `OpenAI o4-mini`。此外，它在健康相关查询（`HealthBench`）和竞赛数学（`AIME 2024` 和 `2025`）方面的表现甚至优于 `o4-mini`。尽管规模较小，`gpt-oss-20b` 在同样的评估中也匹敌甚至超越了 `OpenAI o3-mini`，甚至在竞赛数学和健康方面也胜过它。

## 5 思维链（CoT）

OpenAI近期的研究表明，只要模型没有经过直接监督来校准 `CoT`，监控其 `CoT` 就有助于检测不当行为。业内其他人也认同这一观点。秉承 `OpenAI o1-preview` 发布以来的原则，OpenAI此次也没有对两个模型的 `CoT` 进行任何直接监督。OpenAI认为这对于监控模型的不当行为、欺骗和误用至关重要。OpenAI希望发布一个具有无监督思维链的开放模型，让开发人员和研究人员有机会研究和实现他们自己的 `CoT` 监控系统。

开发者不应在其应用程序中直接向用户展示 `CoT`。它们可能包含令人产生幻觉或有害的内容，包括不符合 OpenAI 标准安全策略的语言，以及可能包含模型被明确要求不要包含在最终输出中的信息。

## 6 安全性与最坏情况下的微调

`gpt-oss` 模型利用先进的安全训练方法。在预训练阶段，过滤掉了与化学、生物、放射和核（`CBRN`）相关的某些有害数据。在后训练阶段，使用了审慎对齐和指令层次结构来训练模型拒绝不安全的提示并防御提示注入。

一旦开放权重模型，某些投机者就可能对这些模型进行微调来达成某些恶意目的。OpenAI通过基于专门的生物学和网络安全数据对模型进行微调来直接评估这些风险，像攻击者可能做的那样为每个领域创建特定于领域的非拒绝版本。然后，通过内部和外部测试评估了这些模型的能力水平。就像下面这篇论文中所说的那样，即使利用 OpenAI 领域领先的训练堆栈进行强大的微调，这些恶意微调的模型也无法达到OpenAI 准备框架（`Preparedness Framework`）所规定的高能力水平。这种恶意微调方法已由三个独立专家组审查，他们提出了改进培训流程和评估的建议，OpenAI采纳了其中许多建议。这些过程标志着开放模型安全性的重大进步。这些发现为OpenAI发布 `gpt-oss` 模型的决定提供了依据。OpenAI希望这些模型将有助于加速整个行业的安全培训和协调研究。

为了构建更安全的开源生态系统，OpenAI还将举办红队挑战赛（`Red Teaming Challenge`），鼓励世界各地的研究人员、开发者和爱好者参与发现新的安全问题。挑战赛设立 50 万美元奖金，奖金将根据 OpenAI 和其他领先实验室的专家评审团的评审结果发放。挑战赛结束后，将发布一份报告，并开源一个基于已验证结果的评估数据集，以便更广泛的社区能够立即受益。

## 7 gpt-oss模型如何用？

`gpt-oss-120b` 和 `gpt-oss-20b` 的权重均可在 `Hugging Face` 上免费下载，并采用 `MXFP4` 原生量化。这使得 `gpt-oss-120B` 模型可以在 80GB 内存中运行，而 `gpt-oss-20b` 仅需 16GB 内存。

这些模型已在 `Harmony Prompt` 格式上进行了后训练，并且OpenAI打算开源一个基于 `Python` 和 `Rust` 的 `Harmony` 渲染器，以便于更容易地采用。此外，OpenAI还发布了使用 `PyTorch` 和 `Apple Metal` 平台进行推理的参考实现，以及一系列针对该模型的示例工具。

设计这些模型是为了使其灵活且易于在任何地方运行——无论是在本地、设备上，还是通过第三方推理提供商。为了支持这一点，OpenAI在发布之前就与 `Azure`、`Hugging Face`、`vLLM`、`Ollama`、`llama.cpp`、`LM Studio`、`AWS`、`Fireworks`、`Together AI`、`Baseten`、`Databricks`、`Vercel`、`Cloudflare` 和 `OpenRouter` 等领先的部署平台合作，以便开发者能够广泛使用这些模型。在硬件方面，OpenAI也与 `NVIDIA`、`AMD`、`Cerebras` 和 `Groq` 等行业领导者合作，以确保在各种系统上实现最佳性能。

作为 `gpt-oss` 发布的一部分，微软还将 `gpt-oss-20b` 模型的 `GPU` 优化版本引入 `Windows` 设备。这些模型由 `ONNX Runtime` 提供支持，支持本地推理，可通过 `Foundry Local` 和 `AI Toolkit for VS Code` 获取，从而让 `Windows` 开发者更轻松地使用开放模型进行构建。

对于想要完全可定制的模型并在自己的环境中进行微调和部署的开发者来说，`gpt-oss` 是理想之选。对于寻求多模态支持、内置工具以及与OpenAI平台无缝集成的用户来说，通过OpenAI的 `API` 平台获取模型仍然是最佳选择。OpenAI表示后续也将密切关注开发者的反馈，并可能在未来考虑为 `gpt-oss` 提供 `API` 支持。

## 8 OpenAI为什么要发布开源模型

OpenAI认为 `gpt-oss-120b` 和 `gpt-oss-20b` 的发布标志着开放权重模型向前迈出了重要一步。这些模型在规模上实现了推理能力和安全性的显著提升。开放模型与OpenAI的在线模型相辅相成，为开发者提供了更广泛的工具，以加速前沿研究、促进创新，并在广泛的用例中实现更安全、更透明的 AI 开发。

这些开放模型还降低了新兴市场、资源受限行业以及缺乏预算或灵活性而无法采用专有模型的小型组织的门槛。借助强大且易于获取的工具，世界各地的人们可以构建、创新，为自己和他人创造新的机会。

健康的开放模型生态系统是推动人工智能广泛普及、惠及每个人的重要因素之一。OpenAI也期望开发者和研究人员多多使用这些模型进行实验、协作，并不断突破无限可能。
