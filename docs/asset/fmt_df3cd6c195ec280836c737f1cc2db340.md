
# Stable Diffusion XL 脚本与 Docker 部署指南

## basic.py

这段 Python 脚本主要实现了一个基于 `Gradio` 的交互式图形用户界面（GUI），用于生成和展示由 "Stable Diffusion XL 1.0" 模型生成的图像。"Stable Diffusion XL 1.0" 是一个预训练的模型，用于根据用户的提示生成图像。

以下是这个脚本的主要功能：

1. **加载预训练模型**：脚本首先定义了一个函数 `get_base_pipeline()`，该函数加载了一个预训练的模型 `stabilityai/stable-diffusion-xl-base-1.0`，并将其转移到了 CUDA 设备上。

2. **定义图像生成函数**：然后定义了一个名为 `imagine()` 的函数，该函数接收一些参数（如提示、负提示、宽度、高度、缩放、步数和种子），并使用这些参数和预训练模型生成一个图像。

3. **创建 GUI**：最后，脚本使用 `Gradio` 库创建了一个交互式 GUI。用户可以通过此界面输入他们的提示和其他参数，然后模型会生成相应的图像并在界面上展示出来。界面还包括一些预定义的示例，用户可以通过点击这些示例来快速生成图像。

总的来说，这个脚本的主要功能是提供一个交互式的图形用户界面，让用户可以方便地使用预训练的 "Stable Diffusion XL 1.0" 模型来生成图像。

## refiner-low-vram.py

这个脚本和之前的脚本在功能上是非常类似的，都是创建了一个基于 `Gradio` 的交互式图形用户界面（GUI），用于生成和展示由 "Stable Diffusion XL 1.0" 模型生成的图像。然而，这个脚本增加了一些新的特性和功能，主要的差异如下：

1. **内存清理**：在加载预训练模型之前，这个脚本会先调用一个名为 `gc()` 的函数来清理 GPU 内存。这是一个新的特性，可以帮助防止内存溢出。

2. **更多的预训练模型**：这个脚本不仅加载了 `stabilityai/stable-diffusion-xl-base-1.0` 模型，还加载了 `stabilityai/stable-diffusion-xl-refiner-1.0` 和 `stabilityai/sd-x2-latent-upscaler` 两个模型。这两个模型分别用于对生成的图像进行细化和放大。

3. **图像处理流程**：在生成图像时，这个脚本会先使用 `base` 模型生成一个基础图像，然后使用 `refiner` 模型对这个图像进行细化，最后如果用户选择了 `upscale` 选项，就会使用 `upscaler` 模型对图像进行放大。

4. **输出结果**：这个脚本的输出结果不再是一个单一的图像，而是一个图像的列表。这个列表包含了基础图像、细化后的图像，以及如果用户选择了 `upscale` 选项，还会包含放大后的图像。

5. **用户界面**：在用户界面上，这个脚本增加了一个名为 `upscale` 的复选框，用户可以通过这个复选框来选择是否使用 `upscaler` 模型对图像进行放大。此外，输出结果的展示方式也进行了调整，现在是一个图像的展示区，可以同时展示多个图像。

综上所述，虽然这两个脚本在功能上是类似的，但这个脚本在细节上做了很多改进和优化，使得用户可以更灵活地使用模型来生成图像，并且可以看到不同阶段的生成结果。

## refiner.py

这个脚本与之前的两个脚本在功能上是一致的，它们都使用 `Gradio` 创建了一个交互式图形用户界面（GUI），通过该界面用户可以输入相关参数，然后使用 "Stable Diffusion XL 1.0" 模型生成和展示图像。然而，这个脚本在一些实现细节上做出了调整，主要的异同点如下：

1. **内存清理**：这个脚本没有包含内存清理的函数 `gc()`，这是它与第二个脚本的主要区别。这可能是因为作者认为在这个脚本中，由于预训练模型只加载一次，所以可能不需要频繁地清理内存。

2. **预训练模型的加载**：在这个脚本中，三个预训练模型在脚本开始时就已经被加载，而不是在每次生成图像时重新加载。这是它与前两个脚本的一个主要区别，这样做的好处是可以避免重复加载模型，节省了计算资源。

3. **图像处理流程**：图像处理流程与第二个脚本基本一致。首先使用 `base` 模型生成一个基础图像，然后使用 `refiner` 模型对这个图像进行细化，最后如果用户选择了 `upscale` 选项，就会使用 `upscaler` 模型对图像进行放大。

4. **用户界面**：用户界面与第二个脚本基本一致，包括了各种输入参数的设置，以及输出结果的展示方式。

总的来说，这个脚本在功能上与前两个脚本基本一致，但在实现细节上做出了一些优化，主要是在处理预训练模型的加载和内存清理的方式上。

所以这三个 `.py` 文件分别对应模型的三种运行方式：基本、全家桶、青春版。

## Docker 镜像构建与部署

### Dockerfile 解析

分析一下 `soulteary/sdxl:runtime-xformers` 的 `dockerfile`：`docker/Dockerfile.runtime-xformers`

```
FROM soulteary/sdxl:base

RUN pip install modin[all] xformers

RUN pip uninstall transformer-engine -y

WORKDIR /app

COPY src/with-xformers/*.py ./
```

以下是这段代码的解释：

+ `FROM soulteary/sdxl:base`：这个指令表示基础镜像是 `soulteary/sdxl:base`。Docker 会从这个镜像开始构建新的镜像。

+ `RUN pip install modin[all] xformers`：这个指令表示在新的镜像中运行一个命令，这个命令是 `pip install modin[all] xformers`。这个命令的作用是安装 `modin[all]` 和 `xformers` 这两个 Python 包。`modin[all]` 表示安装 `modin` 包以及它的所有可选依赖。

+ `RUN pip uninstall transformer-engine -y`：这个指令表示在新的镜像中运行一个命令，这个命令是 `pip uninstall transformer-engine -y`。这个命令的作用是卸载 `transformer-engine` 这个 Python 包。`-y` 参数表示在卸载过程中自动确认所有的提示。

+ `WORKDIR /app`：这个指令表示设置新的镜像的工作目录为 `/app`。如果这个目录不存在，Docker 会自动创建它。

+ `COPY src/with-xformers/*.py ./`：这个指令表示将 `src/with-xformers/` 目录下的所有 `.py` 文件复制到新的镜像的工作目录中。这个指令的源路径是相对于构建上下文的路径，目标路径是相对于工作目录的路径。

所以，这个 Dockerfile 的作用是：基于 `soulteary/sdxl:base` 这个镜像，安装 `modin[all]` 和 `xformers` 这两个 Python 包，卸载 `transformer-engine` 这个 Python 包，设置工作目录为 `/app`，然后将 `src/with-xformers/` 目录下的所有 `.py` 文件复制到新的镜像中。

## 运行容器

### 启动命令

```
docker run --gpus all --ipc=host --ulimit memlock=-1 --ulimit stack=67108864 --rm -it -v `pwd`/stabilityai/:/app/stabilityai -p 7860:7860 soulteary/sdxl:runtime
```

+ `docker run`：这是 Docker 的基础命令，用于运行一个 Docker 容器。

+ `--gpus all`：这个参数告诉 Docker 需要使用主机上所有的 GPU。这对于运行需要大量 GPU 资源的深度学习模型非常有用。

+ `--ipc=host`：这个参数设置了容器的 IPC（Inter-Process Communication，进程间通信）模式为 "host"，这意味着容器将使用主机的 IPC 命名空间。这对于一些需要在进程间共享内存的操作（例如 PyTorch 的 DataLoader）非常有用。

+ `--ulimit memlock=-1 --ulimit stack=67108864`：这两个参数设置了容器的资源限制。`memlock=-1` 取消了内存锁定的限制，`stack=67108864` 设置了栈大小为 64MB。

+ `--rm`：这个参数告诉 Docker 在容器退出后自动删除容器。这可以避免在硬盘上留下无用的容器数据。

+ `-it`：这两个参数让 Docker 以交互模式运行容器，这意味着你可以在容器内运行命令，看到命令的输出。

+ `-v `pwd`/stabilityai/:/app/stabilityai`：这个参数设置了一个卷（volume），用于在主机和容器之间共享文件。这里，主机上的 `stabilityai` 目录被映射到了容器的 `/app/stabilityai` 目录。

+ `-p 7860:7860`：这个参数设置了一个端口映射，将容器的 7860 端口映射到了主机的 7860 端口。这样，你就可以通过主机的 7860 端口访问到容器内的服务了。

+ `soulteary/sdxl:runtime`：这是你要运行的 Docker 镜像的名称。

总的来说，这个命令启动了一个 Docker 容器，容器中运行的是 `soulteary/sdxl:runtime` 镜像，这个镜像可能包含了运行 "Stable Diffusion XL 1.0" 模型的所有依赖和代码。在容器启动后，你可以通过主机的 7860 端口访问到容器内的服务。

和之前 LlaMa 模型，容器的初始化过程似乎很快，但是还需要我们选择模型的运行模式才能让模型真正地跑起来

### 三种运行方式

+ 只使用基础方式：`python basic.py`。默认情况下，它会消耗 7.6G 的显存，并在峰值时达到 11G 的显存使用量。此模型提供了基本的 SDXL 绘图功能。

+ 使用 SDXL 全家桶：`python refiner.py`。默认情况下，程序会占用 14G 显存，并且不启用超分辨率功能。如果需要启用超分辨率（`upscale`），则需要额外消耗 6G 显存，总共达到 20G 显存的峰值消耗。该工具提供了图片绘制、精炼优化和分辨率提升三种能力。

+ 使用青春版模式：`python refiner-low-vram.py`。默认情况下，该程序占用 500MB 显存。当不启用超分辨率时，最大显存占用为 8GB；而启用超分辨率后，最大显存消耗可达 16GB。然而，为了减少显存的使用量，需要频繁地从硬盘或内存中读取模型到显存中，并且这种数据交换会增加一定的成本。因此，生成图片所需的时间比前两种方案要长。
