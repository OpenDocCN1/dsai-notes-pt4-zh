## 二、自定义`Agent`的`SystemPrompt`描述指南:

1.首先需要推荐一个神中神`github`项目:`GitHub-x1xhlol/systenm-prompts-and-models-of-ai-tools`,这个项目中逆向了各种`AIIDE`的`Agent`的`SystemPrompt`,大家可以各个都看一下学习一下`AI`大佬们是用什么框架来写`SystemPrompt`的(看不懂英文的,可以翻译为中文之后看内容)

2.其次是在自定义`Agent`的`Prompt`中强烈建议大家写清楚自己启用了哪些`MCP`给这个`Agent`,并且描述这个`MCP`是做什么用的,这样`Agent`在完成任务时调用`MCP`才会更准确(如果果还是不够准确建议大家在描述问题时,直接告诉它应该用哪个`MCP`进行什么操作,相当于描述它在完成这个任务时应该遵从什么工作流~)

```
# MCP Servers
1. tavily-mcp
用途:网络搜索
2. playwright
用途:控制浏览器来验证前端修改是否符合预期
3.context7
用途:获取API最新的官方文档
Sequential Thinking
用途:引导模型通过分步骤、有逻辑地逐步推理来解决复复杂问题的方法,旨在提升思考的条理性
5. Time
用途:获取当前时间
```

最后就是`Trae`的`Agent`我认为应该这么用最爽:

a.首先自定义一个通用任务的`CodingAgent`,这个`CodingAgent`的`SystemPrompt`可以模仿各个`AIIDE`逆向出来的`SystemPrompt`的描述。然后平时完成任务就用这个`Agent`进行辅助编码。

b.对于常用的特定工作流也自定义一个`Agent`,然后在`Agent`的`SysstemPrompt`中写入这个工作流的流程,第一步应该怎么做,第二步应该调用什么`MCP`工具获取什么,然后根据获取的内容去做什么。

C.这样面对不同任务切换不同`Agent`不但可以减少描述需求的时间,还可以让`Agent`的操作更符合你的预期。

注意:一个自定义`Agent`的`MCP`的总`Tools`不要超过40个,`LLM`面临超过40个`Tools`时调用的精准度极速下降!!!

## 四、需求描述技巧:

进行需求描述时应该尽可能地把你当前描述的这个需求相关的代码块引入过来,把相关的放在一起。

![](img/ae8405804756c2f92164d068603922e8.png)

整个任务描述完成后最好点一下输入框右下角的优化`Prompt`,如果发现优化`Prompt`之后的内容不符合你的预期说明你的描述非常的模糊,你应该做的是让你的描述更加的清晰。如果优化`Profmpt`之后的内容非常的符合你的预期那就说明你描述的已经很到位了,这时候发送任务需求的执行结果往往也是最好的

面对复杂需求(需要参考的上下文量特别大时)强烈建议进行以下两总选择:

1.拆分需求,将大需求拆分成各个小步骤来完成,这样不但关联的上下文可以减少非常多,还能让任务执行的精准度和完成度提高非常多(省成本又提升效果的小妙招)

2.使用`Claude4`的`Max`模式,这样模型的上下文量大大的获得了提升,可以更好的理解你的需求内容,不至于让需求关联的上下文丢失掉。但是上下文多了不一定代表任务完成的精准度和完成度就是最好的,且这种方式成本也会更高(适合技术小白和特殊场景以及不差钱的老板使用)

## 五、模型选择推荐

在使用`Trae`进行辅助编码时,发现`Trae`其实并不是每一个模型的回答都适配的特别的好,比如我在使用`GPT-5`时,会发现回复速度非常慢,且`TODOList`没有成功生成过,`LLM`的`TODO`更多只是普通文本的形式展示出来,`Gemini2.5Pro`的回复虽然快一点且正常一点,但是`TODO List`的问题依然存在。目前与`TraeAgent`最搭配的模型还是`Claude4`,通过`SOLO`的固定模型选择`Claude4`我们也不难看出来`Trae`对`Claude4`其实是做了很多优化适配的。

这里希望`Trae`可以对`GPT-5`的响应做一下优化适配,因为`GPT-5`的幻觉更少更适合某些编码场景.(虽然幻觉少了他的创造力也下降了很多)
