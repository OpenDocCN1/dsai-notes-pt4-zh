
# OpenClaw心跳被Claude Code抄作业了，/loop定时任务上线！

> 来源：[https://my.feishu.cn/docx/FKYLdMxysoIcJgxFEKFctCwInZZ](https://my.feishu.cn/docx/FKYLdMxysoIcJgxFEKFctCwInZZ)

用过OpenClaw的人对"心跳"不陌生。

每30分钟Agent自己醒来一次，检查收件箱、处理消息、执行任务。没活干就回一个`HEARTBEAT_OK`继续睡。

这套机制让AI从"你喊它才动"变成了"它自己会找活干"。

现在Claude Code也搞了个类似的东西。

3月7号更新的`v2.1.71`，新增了`/loop`命令。

一句话说清楚：让AI按你设定的时间间隔，自动重复执行一个任务。

本质上就是OpenClaw心跳的官方简配版。

老金我帮你把这两套方案都拆清楚，哪个适合你一看就明白。

## /loop到底怎么用

最简单的用法，一行命令：

```
/loop 5m 检查部署是否完成，有结果告诉我
```

每5分钟检查一次部署状态，有结果直接通知你。

时间间隔支持4种单位：`s`（秒）、`m`（分钟）、`h`（小时）、`d`（天）。

秒会被向上取整到分钟。

底层用的是`cron`（Linux定时任务调度器），最小粒度一分钟。

不写时间间隔也行，默认每10分钟跑一次。

还有一种写法是把时间放后面：

```
/loop 每2小时检查一次构建状态
```

效果一样，自然语言写就行。

你甚至可以嵌套调用其他命令：

```
/loop 20m /review-pr 1234
```

每20分钟自动执行一次代码审查。

对于需要反复检查的任务，这比手动敲命令强太多了。

## 5个让AI自动干活的场景

老金我帮你梳理5个最实用的场景。

### 盯部署状态

部署上线后最烦的就是盯着等结果。

`/loop 5m 检查部署状态` 一条命令搞定。

AI每5分钟自动检查，有结果直接通知你。

### 自动巡检PR

Claude Code创始人Boris Cherny给的例子。

让AI自动监控所有PR（Pull Request，代码合并请求）。

构建出错就自动修，有评论就开个分支去改。

### 每日Slack早报

Anthropic（就是做Claude的那家公司）开发者Thariq Shihipar的用法。

每天早上自动生成Slack（团队聊天工具）摘要。

谁`@`了你、哪些Issue有更新、哪些PR需要review，一目了然。

### 一次性提醒

不只是循环任务，`/loop`还支持自然语言一次性提醒。

比如说"下午3点提醒我推送`release`分支"。

AI会创建一个单次触发的定时任务，执行后自动删除。

### 定时扫错误日志

每隔几小时扫一遍错误日志。

发现能修的Bug，AI直接创建PR提交修复。

相当于给项目配了个24小时值班的初级工程师。

## 底层机制老金帮你理清楚

`/loop`底下是3个工具在干活。

### CronCreate

创建定时任务。

接受标准的5字段`cron`表达式，就是Linux那套定时语法。

### CronList

列出当前所有定时任务。

显示每个任务的`ID`、执行计划和任务内容。

### CronDelete

按`ID`取消某个定时任务。

不想跑了随时停。

几个关键限制必须知道。

### 会话级别

任务只存在于当前Claude Code进程中。

你关掉终端，所有定时任务就没了。

这是最大的限制。

### 3天自动过期

所有周期性任务创建3天后自动删除。

最后触发一次，然后自我销毁。

防止被遗忘的任务无限运行。

### 最多50个

一个会话最多同时运行50个定时任务。

对个人开发者来说够用了。

### 不会打断对话

任务到期时如果AI正在跟你对话，会等当前轮次结束后再执行。

不会突然插进来打断你的思路。

### 错过不补跑

如果任务计划时间在AI忙的时候错过了，空闲后只触发一次。

不会把错过的每一次都补回来。

想完全关掉这个功能也行。

设置环境变量 `CLAUDE_CODE_DISABLE_CRON=1` 就能禁用整个调度器。

## 和OpenAI Codex比怎么样

老金我得说实话。

定时任务这个功能，OpenAI的Codex比Claude Code先出。

Codex的`automations`（自动化任务系统）支持`cron`调度。

结果放在审查队列里，你回头统一看。

甚至在做云端调度，机器关了任务也能跑。

Claude Code的`/loop`目前还是会话级的。

终端关了就没了，重启也不会恢复。

如果你需要持久化的定时任务，有两个选择。

Claude Desktop的Cowork（桌面版协作功能）支持跨重启的定时任务。

只要桌面端开着就行。

社区的第三方工具也在补这个缺口。

`claude-code-scheduler`

支持自然语言调度加`git worktree`（独立工作区）隔离。

跨平台，macOS、Linux、Windows都能用。

### runCLAUDErun

macOS原生客户端。

图形界面管理定时任务，不用敲命令。

### claude-tasks

`TUI`（终端界面）调度器。

支持Discord和Slack通知，还能设用量上限自动跳过任务。

不过`CLI`（命令行）版的`/loop`有个Codex暂时比不了的优势：零配置。

一条命令就能用，不需要额外装任何东西，不依赖云服务。

对部署后盯一会儿、PR提交后监控一下这种临时需求，CLI版刚好够用。

## 和OpenClaw心跳正面对比

前面说了`/loop`是OpenClaw心跳的简配版，到底简配在哪？老金帮你逐条比。

它们解决的是同一类问题：让AI定期醒来检查有没有活要干。

`/loop`是Claude Code原生的`cron`调度，到时间就跑你给的命令。

OpenClaw的心跳是Agent级别的脉冲系统，每30分钟醒来一次，检查收件箱、处理消息、执行任务。

关键区别在三个地方。

### 智能程度不一样

`/loop`到时间就执行，不管有没有活干。

OpenClaw心跳有一套`HEARTBEAT_OK`确认机制。Agent醒来看一圈，没事就回一个`HEARTBEAT_OK`然后继续睡，这条回复直接被吞掉不浪费`token`。有活才真正干活。

### 成本控制不一样

`/loop`每次触发都要调用Claude模型，有成本。

OpenClaw推荐先用规则检查（不花钱），发现真有信号了再调Haiku（便宜模型）总结。能省80%以上的`token`消耗。

### 持久化不一样

`/loop`是会话级的，终端关了全没。3天还自动过期。

OpenClaw的心跳设计就是为了持久运行，跨会话、跨重启都能活。

所以`/loop`更像是Anthropic看到OpenClaw验证了"定期唤醒"这个模式确实有用，然后在官方`CLI`里做了个简配版。

对临时需求够用，但要搞真正的AI自动化流水线，OpenClaw那套心跳系统还是更成熟。

## 同版本其他更新

`v2.1.71`不只有`/loop`，还有几个值得注意的。

语音模式的快捷键可以自定义了。

以前只能用空格键触发，现在可以改成`meta+k`这种组合键。

在`keybindings.json`里设置`voice:pushToTalk`就行。

`Bash`自动放行列表扩充了。

`fmt`、`comm`、`cmp`、`test`、`seq`这些常用命令不再需要手动确认执行。

修了好几个烦人的Bug。

长时间运行后键盘输入卡住的问题修了。

语音模式启动卡5到8秒的问题修了。

`/fork`共享`plan`文件导致互相覆盖的问题也修了。

## 老金我的判断

`/loop`是Claude Code从被动工具变成主动助手的关键一步。

以前是你让它干啥它才干啥。

现在它可以在后台持续帮你盯着事情。

但说白了，OpenClaw的心跳系统早就跑通了这条路。

Anthropic现在做的，是把社区验证过的模式收编进官方。

### 选/loop的场景：

临时盯个部署结果、PR提交后监控一下

零配置一条命令就能用，不想折腾的选这个

能接受3天自动过期和终端关了就没的限制

### 选OpenClaw心跳的场景：

需要Agent长期自动运行，跨会话跨重启

在意`token`成本，需要`HEARTBEAT_OK`那套智能省钱机制

搞真正的AI自动化流水线，不是临时用一下

### 两个都用的场景：

OpenClaw的心跳管长期任务

`/loop`管临时的、一次性的快速需求

两套并存，各管各的

如果你想试`/loop`，确保Claude Code版本是`v2.1.71`或更新。

终端里输入`/loop 5m`加上你想让AI做的事，就能跑起来了。

如果你想试OpenClaw心跳，去官方文档看`Heartbeat`那一节。
