## 负责任 AI 与 GitHub Copilot

负责任的 AI 原则提供了一套关键的指导方针，用于确保人工智能系统的开发、评估和部署过程是安全、可靠且合乎道德的。这些原则将人员及其目标置于系统设计决策的核心，并尊重诸如公平性、可靠性和透明度等持久的价值观。

Microsoft 和 GitHub 确定了六项核心原则，它们从以下方面具体指导了系统开发和实际应用：

1.  公平性 （Fairness）

在系统开发和应用中，公平性要求 AI 系统对所有人都一视同仁，并避免对处境相似的群体产生不同的影响（例如在医疗、贷款申请或就业方面）。

**应用指导和实践：**

+   **数据和模型层面：** 应该审查训练数据，并在多样化的和均衡的数据上训练 AI 模型，以帮助降低偏差，促进公平。

+   **测试和监控层面：** 使用均衡的人口统计样本测试模型。

+   **部署和干预层面：** 跨用户群体监视模型性能，并实施控制措施来替代不公平的模型分数。此外，还可以使用对抗性去偏差方法来缓解不公平带来的影响。

1.  可靠性和安全性 （Reliability and Safety）

为了建立信任，AI 系统必须可靠、安全、一致地运行。安全性侧重于尽量减少意外伤害，包括对个人和社会造成的身体、情感和经济伤害。可靠性则指 AI 系统能够按照预期一致地运行，不会出现不必要的可变性或错误。

**应用指导和实践：**

+   **设计和测试：** 系统需要按设计方式运行，并且其行为必须反映开发人员在设计和测试期间的预见。

+   **稳健运行：** 安全可靠的系统在正常情况下应该是稳健、准确且行为可预测的。

+   **应对意外：** 系统需要安全地响应意外情况，并能够抵御有害操作。

1.  隐私和安全性 （Privacy and Security）

保护用户隐私和数据安全至关重要，旨在阻止滥用和维护用户信任。

**应用指导和实践：**

+   **数据收集和使用：** 在收集用户数据之前必须获得用户的许可，并清楚地说明 AI 会如何使用其数据。

+   **选择权和透明度：** 必须让用户选择是否愿意分享个人数据，并通过明确的提示和政策告知他们，不能秘密收集数据。

+   **数据最小化：** 仅收集 AI 运行所需的数据。一旦使用 AI，就应避免收集额外信息并删除敏感数据。应定期检查数据输入，确保只收集必要的数据。

+   **数据保护技术：** 将个人数据匿名化，例如使用假名化（用随机标识符替换个人详细信息）和聚合（将数据分组成摘要）等方法来保护标识。

+   **加密和访问控制：** 在传输和存储过程中对敏感数据进行加密，使用强加密方法和安全密钥，并使用硬件安全模块 （HSM） 或安全保管库存储密钥。组织应对谁可以访问密钥和模型进行控制，并限制员工对敏感模型和数据的访问。应定期轮换密钥，安全备份密钥，并定期进行安全审核。

1.  包容性 （Inclusiveness）

包容性要求 AI 系统公平、可访问，并成为所有人的得力助手。这意味着 AI 创建者（包括 GitHub）必须主动设计 AI，以涵盖所有人员、社区和地区，尤其是那些历史上代表性不足的社会领域。

**应用指导和实践：**

+   **用户群覆盖：** AI 系统应适用于各种不同的用户和群体，不会对某些人不利。

+   **可访问性：** 确保任何人都可以轻松使用 AI 系统，无论身体能力或心智能力如何（例如为视障人士提供屏幕阅读器支持的界面）。

+   **替代交互模式：** 提供替代性的交互模式，例如语音控制、字幕和屏幕阅读器。

+   **全球和文化适应：** AI 系统应该在全球范围内可用，即使在发展中国家/地区也是如此，不能排除某些地理区域。系统应支持适应不同的语言和本地文化背景（例如支持小众区域方言的语言翻译）。

+   **基础设施适应：** 必须能够在连接和计算资源受限时正常工作，能够脱机工作。

+   **开发团队组成：** 寻求来自不同背景和社区的人们为 AI 系统的发展提供意见。

1.  透明度 （Transparency）

透明度原则强调 AI 系统必须是可理解的和可解释的。透明度对于建立信任、确保问责、促进公平、增强安全和支持包容性至关重要。

**应用指导和实践：**

+   **系统说明：** 通过清晰的验证框架清楚地说明其系统如何运行。

+   **设计选择：** 证明 AI 系统背后的设计选择的合理性。

+   **坦诚局限性：** 坦陈 AI 系统的功能和局限性。

+   **可审核性工具：** 实现可审核性，涉及文档化数据和模型、创建解释界面、使用 AI 调试工具、构建测试仪表板以及启用日志记录和审核功能。

1.  问责 （Accountability）

问责原则规定 AI 创建者应对其系统的运行方式负责。部署 AI 系统的公司必须对其 AI 系统的运行负责。

**应用指导和实践：**

+   **风险管理和监控：** AI 创建者需要持续监视系统性能并降低风险。

+   **治理框架：** 为了缓解 AI 可能带来的风险（如带有偏见的决策或侵犯隐私），必须实施可靠的治理框架，确保 AI 流程的透明度，并纳入人工监督。

## GitHub Copilot 简介

G**itHub Copilot 是**一**款 AI 结对程序员服务，由 **Microsoft 与 OpenAI 协作开发，并由 OpenAI Codex 系统提供支持。它 GitHub Copilot 是一款 AI 结对程序员服务，由 Microsoft 与 OpenAI 协作开发，并由 OpenAI Codex 系统提供支持。它为所有常用编程语言提供 AI 配对程序员，并通过一系列功能集成到开发工作流中，使其成为一个易于访问的 AI 助手。

以下是 GitHub Copilot 的主要功能，这些功能使其不仅是一个编辑器工具，还提高了开发人员的整体工作效率（根据研究，开发人员整体工作效率提高了 55%）：

### 核心代码生成和辅助功能

Copilot 最初和最核心的功能是自动化代码编写，帮助开发人员保持工作流的连贯性：

1.  内联建议 （Inline Suggestions）： 这是 Copilot 最直接的协助形式。在你输入时，Copilot 会分析你的代码和上下文，以实时提供代码补全建议，这些建议在光标前显示为灰显文本。

+   **接受/拒绝建议：** 可以使用 Tab 键或 > (向右箭头) 键接受建议，或继续键入/选择 Esc 键拒绝建议。

+   此功能在处理重复性任务或需要快速样本代码时特别有用。

1.  **注释转代码：** Copilot 利用自然语言处理 （NLP） 将注释转换为代码。你可以在注释中描述所需的功能，当选择 Enter 键时，Copilot 会根据说明生成代码。这种方法适用于快速起草代码，尤其是在任务简单明了的情况下。

1.  多项建议 （Multiple Suggestions）： 对于复杂的代码片段，Copilot 可以提供多个替代方法。开发人员可以循环浏览替代项（例如使用 Alt+] 或 Option+]）来探索不同的编码方法，并选择最合适的方法。

### 交互式 AI 助手和聊天功能

Copilot 将类似于 ChatGPT 的聊天界面引入了编辑器，支持开发人员使用自然语言进行通信，并与 IDE（如 VS Code 和 Visual Studio）进行原生集成。

1.  **Copilot Chat：** 这是一种交互式功能，允许开发人员提出问题或请求代码片段。它深层嵌入到 IDE 中，能够识别开发人员输入的代码和显示的错误消息。开发人员可以：

+   深入分析和解释代码块要执行的操作。

+   生成单元测试。

+   获得针对 bug 的建议修复。

+   **适用场景：** 非常适合探索新的编码概念或在遇到不熟悉的语法时获取帮助。

1.  内联聊天 （Inline Chat）： 此功能直接在代码编辑器中启用上下文特定的对话。你可以使用键盘快捷方式 （Ctrl+I 或 Cmd+I） 打开内联聊天，请求代码修改或解释，而无需切换上下文。

+   **斜杠命令：** 内联聊天支持使用斜杠命令作为快捷方式进行高效交互。例如：

+   /explain：提供所选代码的说明。

+   /suggest：根据当前上下文提供代码建议。

+   /tests：为所选函数或类生成单元测试。

+   /comment：将注释转换为代码片段。

### 代码理解和质量功能

1.  说明 （Explanations）： 开发人员可以使用“解释此”功能来获取代码片段的说明。这对于学习目的以及查看他人编写的代码至关重要。

1.  自动测试生成 （Automated Test Generation）： Copilot 可以为函数或类生成单元测试，从而节省时间和精力，有助于在开发过程中保持代码完整性并捕获 bug。可以使用命令面板选择 “Copilot：生成单元测试” 来触发此功能。

### 集成和企业级功能

1.  对拉取请求 （Pull Requests） 的支持： Copilot 增添了通过 GitHub 应用在拉取请求说明中使用 AI 支持的标记的支持。Copilot 会根据更改的代码自动填充这些标记，开发人员可以查看或修改建议的说明。此功能由 OpenAI 的 GPT-4 模型提供支持。

1.  **命令行接口 （CLI）：** GitHub Copilot CLI 可以编写命令和循环，甚至可以抛出模糊的 find 标志来满足查询，帮助开发人员避免滚动浏览多个页面来记住精确的语法。

1.  企业级功能 （Enterprise）： 对于大型组织，GitHub Copilot Enterprise 提供高级功能，包括：

+   基于内部/专用代码的**个性化代码建议**。

+   基于 AI 的**搜索和跨代码库的文档生成**。

+   对 Copilot 模型进行组织范围的自定义和微调。

+   提供**集中式管理和策略控制**，以及**安全漏洞筛选**、IP 赔偿和企业级安全性、安全和隐私功能。

## GitHub Copilot 提示工程简介

**GitHub Copi**lot 是由大语言模型 （LLM） 提供支持的。它的工作原理是一个动态的、多步骤的过程，涉及用户提示的接收、广泛上下文的收集、安全筛选以及最终使用经过优化的 LLM 生成相关的代码建议。

以下是 GitHub Copilot 使用 LLM 工作的核心原理和流程：

### LLM 的基础作用与优化

**LLM 是人**工智能模型，通过接受大量文本数据的训练，旨在理解、生成和操作人类语言。这些模型基于机器学习和人工智能原理，是具有数百万甚至数十亿个参数的神经网络。

1.  核心作用：上下文感知建议

**GitHub Co**pilot 利用 LLM 提供上下文感知代码建议。LLM 的主要工作是：

+   **理解上下文：** LLM 能够生成上下文相关且连贯的文本。

+   **动态分析：** LLM 不仅考虑用户正在编辑的当前文件，还会考虑 IDE（集成开发环境）中的其他开放文件和选项卡，以生成定制化和相关的代码完成。

1.  LLM 的优化：微调和 LoRA

为了使 LLM 更好地满足特定的编码要求，GitHub 会对其进行微调：

+   微调 （Fine-tuning）： 这是一个关键过程，旨在针对特定任务或领域定制预先训练的 LLM。它涉及在一个较小的、特定于任务的数据集（目标数据集）上训练模型，同时利用从大型预训练数据集（源模型）中获取的知识。

+   **LoRA 微调：** GitHub 采用 **LoRA （低秩自适应）** 微调方法。与传统的完全微调（训练神经网络的所有部件，耗费资源且慢）不同，LoRA 是一种替代方法。

+   **工作原理：** LoRA 不会更改原始模型的所有内**容。相反，它在预**先训练的模型每一层中添加较小的可训练部分。

+   **优点：** 原始模型保持不变，从而节省了时间和资源。这使得 LLM 能够更有效地适应特定的编码要求。

### 上下文限制

**虽然 Co**pilot 能够理解和响应提示，但在操作中必须注意上下文窗口的限制。上下文窗口是指模型为生成建议可以同时处理的周围代码和文本量。

+   **限制范围：** GitHub Copilot 上下文窗口的范围通常从大约 200-500 行代码到多达几千个令牌。

+   Copilot Chat 窗口： Copilot 聊天目前使用 4k 个令牌的上下文窗口运行，提供了更广阔的范围。

用户在创建提示时，应注意这些限制，将复杂问题分解为更小、更集中的查询，或提供相关代码片段，以增强模型提供准确响应的能力。

以下是关于提示工程的“4 S”原则和学习方法如何优化 Copilot 性能的详细说明：

### 提示工程的“4 S”原则如何优化性能

提示工程是制作清晰指令的过程，旨在指导 AI 系统（如 GitHub Copilot）根据项目的特定需求生成符合上下文的代码，从而确保代码在语法、功能和上下文方面都是正确的。

“4 S”原则是创建有效提示的基础核心规则，遵循这些原则可以直**接提高 Cop**ilot 提供的代码建议的准确性和相关性：

1.  **Single（单一）**

+   **优化作用：** 确保从 Copilot 获得准确且有用的答复。

+   **原则内容：** 始终将提示的重点放在**单个明确的任务或问题**上。

1.  **Specific（具体）**

+   **优化作用：** 帮助获得更适用和精确的代码建议。

+   **原则内容：** 确保指令明确且详细。例如，“编写 Python 函数以筛选和返回给定列表中的偶数”就是既侧重于单一问题又非常具体的提示。

1.  **Short（简短）**

+   **优化作用：** 确保清晰度，同时又不会使 Copilot 负担过重或使交互复杂化。

+   **原则内容：** 在具体的同时，保持提示**简明扼要**，即在细节和简洁性之间取得平衡。

1.  **Surround（有上下文）**

+   **优化作用：** 为 Copilot 提供了丰富的上下文，从而产生更有针对性的代码建议。

+   **原则内容：** 利用描述性文件名并**使相关文件保持打开状态**。Copilot 会利用代码编辑器中并行打开的选项卡来获取有关代码要求的更多上下文。

#### 基于 4 S 的高级优化实践

除了遵循 4 S 原则外，还有一些基于这些原则的最佳实践可以进一步增强与 Copilot 的交互，确保生成的代码完全符合项目的特定需求和上下文：

+   **提供足够的上下文（细节）：** 按照“有上下文”（Surround）原则，通过在代码顶部添加注释等方式详细说明你想要实现的目标，为 Copilot 提供更丰富的上下文，使其能够提供更合适的代码建议。

+   **断言和迭代：**** 释放 **Copilot 潜力的关键在于迭代实践。如果第一次提示没有产生完美的结果，应将其视为对话中的一步。用户应清除建议的代码，使用添加的详细信息和示例来丰富初始注释，并再次向 Copilot 提示。

#### 上下文窗口限制的管理

**在使用提示**优化 Copilot 性能时，必须注意上下文窗口（模型为生成建议可以同时处理的周围代码和文本量）的限制。

+   GitHub Copilot 上下文窗口的范围通常从大约 200-500 行代码到多达几千个令牌（token）。Copilot 聊天目前使用 4k 个令牌的上下文窗口。

+   **优化方法：** 创建提示时，应注意上下文窗口限制，将复杂问题分解为更小、更集中的查询或提供相关的代码片段，可以显著增强模型提供准确且有用的响应的能力。

### 学习方法（样本）如何优化性能

GitHub Copilot 依靠使用大量数据训练的 AI 模型。通过在提示中提供示例，可以阐明用户的要求和期望，说明抽象概念，从而为 Copilot 提供更切实的指导，增强其对特定代码上下文的理解。

这些方法根据提供的示例数量，分为零样本学习、单样本学习和少样本学习，它们有效地提高了代码生成的精确性：

1.  零样本学习（Zero-Shot Learning）

+   **优化作用：** 仅依赖于 Copilot 的基础训练来生成代码。

+   **方法：** 无需任何特定示例。例如，用户只需写一条注释描述需求（如创建摄氏度和华氏度相互转换的函数），Copilot 即可根据其预训练的知识生成代码。

1.  单样本学习（One-Shot Learning）

+   **优化作用：**** 通过提供一个示例，**帮助模型生成更能感知上下文的答复。

+   **方法：** 用户提供一个相关函数的示例，然后要求 Copilot 创建另一个类似的函数。

1.  少样本学习（Few-Shot Learning）

+   **优化作用：** 通过提供多个示例，在零样本的不可预测性和微调的精确性之间取得了平衡，增强了模型处理复杂或特定场景的能力。

+   **方法：** 用户在提示中提供多个示例，以指导 Copilot 更好地理解并满足要求。例如，提供多个根据一天中不同时间发送问候语的代码示例。

**总而言之，通过执行“4 S**”原则确保了提示的清晰度、焦点和丰富的上下文，而采用样本学习方法（尤其是单样本和少样本）则提供了具体的期望和要求，这些都有效地指导 LLM （Copilot） 优化其代码生成功能，使其建议更加准确、相关和实用。

开发人员可以通过**聊天界面****（包括专****用聊**天窗格和内联聊天）并结合斜杠命令（Slash Commands）和代理（Agents）来有效利用 GitHub Copilot，从而加速编码、修复 Bug、生成文档和测试等复杂任务。

+   定制专用代码库的聊天对话。

+   将知识库附加到聊天中以提供组织上下文。

在选择定价计划时，应考虑 Business 和 Enterprise 版 是唯一提供更可靠隐私控制的计划。

### 安全功能

GitHub Copilot 允许开发人员和组织在开发和创新时优先考虑安全性、隐私、合规性和透明度。

合同保护 （Contract Protection）

为了帮助组织遵守法律要求，GitHub Copilot 提供以下合同保护措施：

1.  **知识产权 （IP） 赔偿：** **GitHub Copilot** 商业和企业计划包括 IP 赔偿。如果 Copilot 提出的任何建议被质疑侵犯第三方知识产权，GitHub 会承担法律责任。前提是“匹配公共代码”设置被阻止。

1.  **数据保护协议 （DPA）：** GitHub 提供 DPA，概述了为保护数据和确保遵守数据隐私法规所采取的措施。

1.  GitHub Copilot 信任中心： 该中心详细介绍了 Copilot 的工作原理，包括安全、隐私、合规性和知识产权保护。

**数据隐私与策略管理**

+   **隐私控制：** Business 和 Enterprise 版提供更可靠的隐私控制。这些控制措施包括从 GitHub Copilot 分析中排除特定文件、访问详细的审核日志，以及提供 IP 赔偿的功能。

+   **策略管理：** Business 和 Enterprise 版计划允许在组织级别进行全面的策略管理，这有助于确保根据组织的隐私策略处理敏感数据。

+   **数据收集和保留：** 单个订阅者可以选择 GitHub 是否收集并保留他们的提示和 Copilot 建议。

**筛选匹配公共代码**

GitHub Copilot 可以帮助识别并 筛选掉与公开提供的代码匹配的代码建议。此功能对于保持代码库的原创性和安全性至关重要。它能降低将不安全或不合规代码纳入项目的风险。用户可以通过组织或企业的设置将“匹配公共代码”下的建议设置为“阻止”。

### 内容排除

GitHub Copilot 中的内容排除功能旨在通过阻止将**特定文件、目录或**存储库用于代码完成建议来帮助保护敏感信息。

![](img/1ae051d06b7a11efc3da7f43fb6f05ea.png)

**内容排除的配置和范围**

+   **配置方式：** 存储库管理员和组织所有者可以配置内容排除策略。配置可以在存储库的“设置”下的“Copilot”部分中完成，或在组织的“设置”下的“Copilot 内容排除”部分中进行。

+   **适用范围：**** **在组织或存储库中定义的内容排除设置适用于作为 GitHub Copilot Business 或 GitHub Copilot Enterprise 订阅一部分获得许可的所有成员。

**对代码建议的影响**

当内容从 GitHub Copilot 中排除时：

+   代码完成功能在受影响的文件中不再可用。

+   受影响文件中的内容不会用于其他文件中的代码完成建议。

+   受影响文件中的内容不会用于 GitHub Copilot Chat 的响应。

内容排除可以帮助得到更安全且合规的代码建议，但也会 减少 Copilot 整体可用的上下文，这可能会影响建议的准确性和用处。

**内容排除的限制**

在某些情况下，内容排除可能不完全有效：

+   **IDE 限制：** 在某些 IDE 中，使用某些功能（如 Copilot Chat）时，内容排除可能不适用。例如，在 Visual Studio Code 和 Visual Studio 中，使用问题中的 @github 聊天参与者时，不会应用内容排除。

+   **语义信息：**** 如果信息由 IDE 在未排除**的文件中提供，Copilot 仍可能使用排除文件中的语义信息，包括代码中使用的符号或函数调用的类型信息和悬停定义。

+   **策略范围：** 内容排除设置仅适用于配置了排除的组织的成员。访问指定文件的任何其他人员仍可能看到代码完成建议和引用指定文件的 Copilot Chat 响应。

### 故障排除

#### **缺少代码建议**

如果 GitHub Copilot 未在编辑器中提供代码建议，可以尝试以下操作：

+   **检查 Internet 连接：** 确保具有稳定的 Internet 连接，因为 GitHub Copilot 需要可用连接才能正常运行。

+   **更新 Copilot 扩展：** 确保使用最新版本的 GitHub Copilot 扩展。旧版本可能无法与 Copilot 服务器有效通信。

+   **验证 IDE 兼容性：** 确认 IDE 与 GitHub Copilot 兼容。某些 IDE 可能需要特定配置或更新。

+   **查看内容排除：** 如果某些文件被排除在 Copilot 的分析之外，则可能不会显示建议。检查内容排除设置以确保正确配置它们。

执行这些操作通常可解决与缺少的代码建议相关的问题。

#### **内容排除未按预期工作**

如果内容排除功能未能按预期阻止 GitHub Copilot 使用特定文件或目录：

+   **排除项的延迟应用：** 添加或更改内容排除项后，可能需要长达 30 分钟才能在已加载设置的 IDE 中生效。若要立即应用更改，请在 IDE 中重新加载内容排除设置。

+   **排除范围不充分：** 内容排除设置仅适用于配置了排除的组织的成员。

+   **检查状态栏图标：** 如果文件适用于内容排除，GitHub Copilot 图标上会有一条对角线穿过。将鼠标悬停在图标上可查看组织或父存储库是否禁用了该文件的 GitHub Copilot。

+   **特定于 IDE 的限制：** 在某些 IDE 中，使用某些功能（如 GitHub Copilot Chat）时，内容排除可能不适用。

#### 代码建议令人不满意

如果 GitHub Copilot 生成的建议质量不佳，可以使用以下技术来提示 Copilot 提供更好的结果：

+   **提供清晰的上下文：** 确保代码为 Copilot 提供明确的上下文，例如编写描述性注释和使用有意义的变量名称。

+   **使用 Copilot 命令：** **在某些 IDE 中，**可以使用特定命令来提示 Copilot 生成建议。例如，在 Visual Studio Code 中，可以使用 Ctrl+Enter 快捷方式触发 GitHub Copilot。

+   **调整提示长度：** 尝试使用不同的提示长度。有时，提供更长或更详细的提示可以帮助 Copilot 生成更好的建议。

Copilot 的输出质量与你创建的提示是否合理直接相关。对于更复杂的任务，创建清晰、具体的提示至关重要，以确保模型生成高质量的输出。

+   **确保具体和清晰：** **有效的提示**必须具体而清晰，让 Copilot 知道任务的目标和范围。例如，使用以下提示： // Create an API endpoint using the React framework that accepts a JSON payload in a POST request。

+   **提供上下文：** 除了注释或代码，你还可以使用 GitHub Copilot Chat 的聊天选项来向 Copilot 提供上下文和示例。

1.  **第一步（简单）：** 例如，create an HTML form with a text field and button。

1.  **第二步（细化）：** 进一步详细阐述提示以获取更具体的建议，例如：Add an event listen to the button to send a POST request to /generate endpoint and display response in a div with id "result"。

### 识别和创建提示

Copilot 能够从你的输入中识别指令并生成代码建议。在 Python 文件中，Copilot 主要通过以下方式识别你的提示：

+   **使用注释：** 如果你在文件结尾为 .py 等的代码文件中将内容键入作为注释，Copilot 可将其判断为提示或指令。

+   **自然语言输入：** 提示是你键入的自然语言文本，Copilot 会使用该文本根据你键入的内容提供建议。

例如，如果你想要创建一个使用 FastAPI 框架的 Web API，你可以键入以下提示： # Create a web API using FastAPI with a route to products. Copilot 随后可能会生成类似于以下 Python 代码的响应：

```
from fastapi import FastAPI
app = FastAPI()
@app.get(&quot;/products&quot;)
def read_products():
    return []
```

### 提示工程（Prompt Engineering）的最佳实践

Copilot 输出内容的质量**取决于你制作的提示的好坏**。设计有效的提示对于确保实现所需结果至关重要。

### 使用 GitHub Copilot Chat 增强体验

GitHub Copilot Chat 是一个交互式聊天界面，你可以利用它来增强你的提示并与输出进行交互。

+   **引导生成代码：** 你可以使用 Copilot Chat 引导 Copilot 代表你生成代码。

+   **上下文提示：** **如果你需要 GitH****ub **Copilot 根据其他文件提供建议，在使用 Copilot Chat 时可以打开这些文件或使用 @workspace 提示。

+   **询问问题：** 你可以使用 Chat 界面询问与代码相关的问题并获取答案。

### 接受和循环建议

Copilot 可能会建议多个响应，因此你需要循环查看并选择最合适的输出。

+   **接受建议：**** 如果**** C**opilot 返回了建议（以灰色代码显示），你可以按 Tab 键来接受它。

+   **循环查看：**** 如果 Copilot **建议了多个响应，你可以使用 Ctrl + Enter（或 Mac 上的 Cmd + Enter）来循环访问这些建议。

+   **重新措辞：** 如果你未获得所需结果，可以重新组织提示的措辞，或开始编写代码来让 Copilot 自动完成。
