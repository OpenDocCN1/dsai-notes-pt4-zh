
# Microsoft Purview 核心组件与功能详解

> 来源：[https://zsyhjtnsa5.feishu.cn/docx/V1kodOdD7ogmRmx021McetR3neb](https://zsyhjtnsa5.feishu.cn/docx/V1kodOdD7ogmRmx021McetR3neb)

Microsoft Purview 是一套全面的数据治理、风险和合规解决方案，旨在帮助组织管理、保护和治理其整个数据资产。它的核心由以下主要组件和功能构成：数据治理解决方案、数据安全解决方案以及风险与合规解决方案。

## 数据治理解决方案

这些工具旨在帮助组织统一管理、规划和治理分布在本地、多云和 SaaS（软件即服务）环境中的数据服务。

### Microsoft Purview 数据映射 （Data Map）

作为 Purview 治理解决方案的基石，数据映射是一个云原生的 PaaS 服务，它自动扫描并捕获组织数据资产的元数据，构建一个统一的、持续更新的数据资产“地图”。

#### 核心组件

1. **数据源扫描与注册（Data Source Scanning and Registration）**：

   + **定义：** 用于连接和扫描各种数据源的机制。Purview 支持广泛的数据源类型，包括 Azure 服务（如 Blob Storage，Azure SQL，Synapse Analytics）、其他云（如 Amazon S3）、本地数据源（如 SQL Server）以及 SaaS 应用（如 Salesforce）。

   + **自承载集成运行时（Self-Hosted Integration Runtime，SHIR）：** 当需要扫描位于本地网络或私有云中的数据源时，需要部署此代理软件，以安全地在本地执行扫描任务并将元数据传回 Purview 数据映射。

1. **元数据提取与分类（Metadata Extraction and Classification）**：

   + **技术元数据：** 自动从数据源中提取结构性信息，如服务器名、数据库名、表、列、数据类型、分区键等。

   + **分类引擎：** 在扫描过程中，系统会运用内置的及自定义的分类规则（基于敏感信息类型）来识别数据中的敏感信息，并自动为其添加分类标签，例如“信用卡号”或“身份证号”。

1. 数据沿袭引擎 （Data Lineage Engine）：

   + **定义：** 负责追踪和记录数据在其生命周期中的移动和转换过程。

   + **集成支持：** 它可以与 Azure Data Factory、Azure Synapse Analytics 和 SQL Server Integration Services （SSIS） 等数据集成工具紧密集成，自动捕获数据处理活动中的沿袭信息，例如某个数据表是由哪些源表经过哪些转换步骤生成的。

#### 工作机制

1. **注册（Register）：** 管理员首先在 Purview 中注册数据源，提供连接凭据和必要的网络配置（如部署 SHIR）。

1. **扫描（Scan）：** 管理员配置并触发扫描任务。扫描器会连接到数据源，读取其系统目录和元数据。

1. 提取与分类 （Extract & Classify）：在扫描过程中，Purview 会提取技术元数据，并对数据样本运行分类规则以识别敏感信息。

1. 沿袭捕获 （Ingest Lineage）：对于支持的数据处理活动（如 Azure Data Factory 管道执行），其运行时的沿袭信息会被自动推送并整合到数据映射中。

1. 构建图形 （Build the Graph）：所有收集到的元数据、分类和沿袭关系被组织成一个相互连接的知识图谱，这个图谱就是数据映射的核心，为上层的统一目录和其他功能提供支持。

#### 关键适用场景

+ **构建全景数据视图：** 为分散在多云和本地环境中的所有数据资产创建一个集中化的元数据存储库，打破数据孤岛。

+ **自动化数据分类：** 在数据产生或更新时自动识别其中的敏感信息，为后续的数据安全和合规策略提供基础。

+ **根本原因与影响分析：** 当报表或下游应用出现数据问题时，可以通过数据沿袭追溯到问题的源头；反之，在变更数据源结构前，也可以评估该变更会对哪些下游系统产生影响。

#### 最佳实践

+ **分阶段扫描：** 从最关键、价值最高的数据源开始注册和扫描，逐步扩大覆盖范围，而不是试图一次性扫描所有内容。

+ **优化扫描性能：** 合理配置扫描的范围（例如，选择特定的数据库或文件夹）和扫描频率，并为自承载集成运行时分配足够的计算资源，以避免对生产系统造成影响。

+ **自定义与丰富元数据：** 除了自动扫描的元数据，还应鼓励数据所有者和管理员手动添加业务描述、联系人等上下文信息，以提升数据地图的实用价值。

### Microsoft Purview 统一目录 （Unified Data Catalog）

这是一个建立在数据映射之上的、面向业务和技术用户的智能数据目录。它提供了一个类似搜索引擎的界面，让用户可以轻松地发现、理解和信任组织的数据。

#### 核心组件

1. 搜索与浏览 （Search and Browse）：

   + **定义：** 目录的核心功能，允许用户通过关键字搜索、按数据源类型浏览或使用高级筛选器（如分类、敏感度标签、数据所有者等）来查找数据资产。

   + **智能推荐：** 系统可以根据用户的角色和搜索历史，推荐可能相关的数据资产。

1. 业务术语表 （Business Glossary）：

   + **定义：** 一个用于定义和管理核心业务术语及其定义的中央知识库。例如，可以为“活跃客户”、“净收入”等术语创建标准定义。

   + **映射：** 可以将这些业务术语与数据映射中的物理数据资产（如表、列）进行关联，从而在技术元数据和业务语言之间架起一座桥梁。

1. 数据资产详情页 （Data Asset Details Page）：

   + **定义：** 每个数据资产在目录中都有一个专属页面，集中展示其所有相关信息。

   + **内容：** 包括技术元数据（如列定义）、自动检测到的分类、数据所有者和专家的联系方式、业务描述、相关的业务术语以及可视化的数据沿袭。

1. **数据沿袭可视化（Data Lineage Visualization）**：

   + **定义：** 以图形化的方式，直观地展示数据从源头到最终消费端的完整流动路径。用户可以在图上清晰地看到数据的转换过程和依赖关系。

#### 工作机制

1. **索引与呈现：** 统一目录持续索引来自数据映射的元数据，并将其以用户友好的方式组织和呈现。

1. **搜索查询处理：** 当用户输入搜索请求时，目录会在其索引中进行匹配，综合考虑关键字、业务术语、描述和属性，返回最相关的结果。

1. **关联与丰富：** 数据管理员或业务专家可以访问目录，为数据资产添加描述、指定所有者，或将其与业务术语表中的术语进行关联。这些手动添加的信息会进一步丰富数据资产的业务上下文。

1. **沿袭可视化：** 当用户查看某个数据资产的沿袭时，目录会查询数据映射中的图形数据库，并动态生成一个可视化的流程图。

#### 关键适用场景

+ **自助式数据发现：** 使数据分析师、数据科学家和业务用户能够独立地找到他们需要的数据，而无需依赖 IT 部门，从而缩短数据项目的启动时间。

+ **建立统一的业务语言：** 通过业务术语表，确保整个组织在讨论关键业务指标和概念时使用一致的定义，避免因理解偏差导致的错误分析。

+ **提升数据可信度：** 用户可以通过查看数据资产的来源、沿袭、所有者和描述，来评估其质量和可信度，从而更有信心地使用数据。

#### 最佳实践

+ 任命数据管家 （Data Stewards）： 为关键业务领域任命数据管家，负责维护业务术语表、审核和丰富数据资产的元数据，确保目录内容的准确性和高质量。

+ **从用户需求出发：** 在推广目录时，优先收录和完善那些业务用户最常需要或最关心的数据资产的元数据。

+ **推广与培训：** 积极向潜在用户群体推广数据目录的价值，并提供培训，指导他们如何有效地使用搜索、沿袭和术语表等功能。

### Microsoft Purview 数据策略 （Data Policy）

这是一组集中化的云端体验，旨在帮助组织以可扩展、安全的方式管理对数据源和数据集的访问权限，实现了数据治理与访问控制的统一。

#### 核心组件

1. **策略创作体验（Policy Authoring Experience）**：

   + **定义：** 在 Microsoft Purview 治理门户中提供的一个统一界面，允许数据管理员和所有者创建和管理数据访问策略。

   + **策略类型：**

   + **数据所有者策略：** 允许数据所有者直接在 Purview 中授予对特定数据资产（如 SQL 表、存储账户中的文件）的读取或修改权限。

   + **自助访问策略（规划中）：** 未来将支持工作流，允许数据消费者请求访问，并由数据所有者进行审批。

1. 策略发布引擎 （Policy Publishing Engine）：

   + **定义：** 负责将 Purview 中定义的策略安全地分发并应用到各个数据源的访问控制系统上。

1. 策略执行点 （Policy Enforcement Point）：

   + **定义：** 这是位于数据源本身的功能，它接收来自 Purview 的策略，并在用户尝试访问数据时强制执行这些策略。目前支持的数据源包括 Azure Blob Storage、Azure Data Lake Storage （ADLS） Gen2、Azure SQL 数据库等。

#### 工作机制

1. **启用数据源策略管理：** 管理员首先需要在 Purview 中为特定的数据源（例如一个 Azure 订阅下的所有存储账户）启用数据策略管理功能。

1. **定义策略：** 数据管理员或所有者在 Purview 门户中创建策略。策略的核心是定义一个“主体”（Subject，即某个 Azure AD 用户或组）、一个“操作”（Action，如读取或修改）和一个“资源”（Resource，即 Purview 中已注册的数据资产）。

1. **发布策略：** 创建并保存策略后，管理员需要“发布”它。Purview 会将该策略转换为数据源可以理解的格式（例如，Azure 存储的 IAM 角色分配），并将其应用到目标数据源上。

1. **强制执行：** 当被授权的用户尝试访问数据时，数据源的访问控制层会检查来自 Purview 的策略。如果用户的操作符合策略规定，访问将被允许；否则将被拒绝。

#### 关键适用场景

+ **简化多数据源的权限管理：** 无需分别登录到每个数据源的管理界面来配置权限，而是通过 Purview 这个单一平台，集中管理跨多个数据源的访问策略。

+ 基于业务元数据的访问控制（未来方向）： 实现更高级的访问控制，例如“只允许财务部门的员工访问所有被分类为‘财务敏感’的数据”，而无需为每个财务数据源单独设置权限。

+ **数据所有者赋权：** 将数据访问权限的管理责任下放给最了解数据的业务所有者，IT 部门则负责维护平台，实现了治理责任的合理分配。

#### 最佳实践

+ **遵循最小权限原则：** 在定义策略时，仅授予用户完成其工作所必需的最小权限。优先授予读取权限，谨慎授予修改权限。

+ **使用 Azure AD 组：** 将权限授予 Azure AD 安全组，而不是单个用户。这样，当人员变动时，只需在 Azure AD 中调整组成员关系，而无需修改 Purview 中的数据策略。

+ **定期审计：** 定期审查和审计已发布的数据策略，确保它们仍然符合组织的安全和合规要求，并移除不再需要的权限。

## 数据安全解决方案

这些功能旨在帮助保护敏感数据，并管理整个组织数据资产的内部风险。

### Microsoft Purview 信息保护 （Microsoft Purview Information Protection）

Microsoft Purview 信息保护是一个旨在帮助组织发现、分类和保护其敏感信息的统一解决方案。它通过应用标签和策略，确保数据无论存储在何处（例如在设备、应用、云服务或本地），都能得到持续的保护。

#### 核心组件

1. **敏感信息类型（Sensitive Information Types，SITs）**：

   + **定义：** 基于模式的分类器，用于检测特定类型的敏感数据。它们通过正则表达式（RegEx）、关键字、校验和以及其他条件来识别如身份证号、信用卡号、银行账号等结构化数据。

   + **类型：**

   + **内置 SITs：** Microsoft 提供了超过 200 种预先配置的敏感信息类型，涵盖了全球多个国家和地区的常见法规和标准。

   + **自定义 SITs：** 组织可以根据自身业务需求创建自定义的敏感信息类型，以识别专有的数据，例如员工 ID、项目代号或特定的财务报表格式。

1. 可训练分类器 （Trainable Classifiers）：

   + **定义：** 一种基于机器学习的分类工具，擅长识别那些难以通过简单模式匹配来定义的敏感内容，例如合同、简历、源代码或不当言论等。

   + **工作方式：** 通过向分类器提供一批具有代表性的样本文件（“种子内容”），系统会学习并建立一个预测模型，然后利用该模型来识别和分类其他内容相似的文档。

1. 敏感度标签 （Sensitivity Labels）：

   + **定义：** 应用于文档和电子邮件的核心保护措施。它们就像一个可自定义的“印章”，不仅在视觉上标记了内容的敏感级别（如“个人”、“机密”、“高度机密”），更重要的是，它嵌入了相应的保护策略。

   + **绑定的保护措施：**

   + **加密：** 对文件和邮件进行加密，只有获得授权的用户才能访问。

   + **内容标记：** 自动添加水印、页眉或页脚，以醒目的方式提醒用户内容的敏感性。

   + **访问控制：** 限制特定用户或组的访问和操作权限（如编辑、复制、打印等）。

   + **跨容器应用：** 敏感度标签还可以应用于 Teams 网站、Microsoft 365 组和 SharePoint 网站等容器，从而统一控制这些协作空间中的数据共享和访问策略。

#### 工作机制

1. **发现（Discovery）：** 系统首先需要知道敏感数据存在于何处。通过利用数据映射和内容扫描功能，信息保护可以在 Microsoft 365（如 Exchange Online，SharePoint，OneDrive，Teams）、本地文件服务器、第三方云应用和终端设备上扫描并识别数据。

1. 分类 （Classification）：在发现数据后，系统会根据预设的策略自动对其进行分类。

   + **自动化分类：** 策略可以配置为，当内容匹配到某个敏感信息类型或被可训练分类器识别时，自动应用相应的敏感度标签。

   + **手动分类：** 用户在创建或编辑文档/邮件时，可以根据系统推荐或自己的判断手动选择一个敏感度标签。

   + **默认标签：** 管理员可以为所有新创建的内容设置一个默认的敏感度标签，以确保所有数据都具备一个基础保护级别。

1. 保护 （Protection）：一旦内容被贴上标签，标签所附带的保护措施就会被强制执行。

   + **持久性保护：** 这种保护是持久且与文件本身绑定的。无论文件被发送到组织外部、复制到 U 盘还是存储在其他云服务中，加密和权限设置都会随之生效。

1. 监控 （Monitoring）：管理员可以通过 Microsoft Purview 合规门户的活动浏览器和报告功能，全面监控敏感度标签的使用情况、敏感数据的流动路径以及潜在的风险活动。

#### 关键适用场景

+ **满足合规性要求：** 帮助组织遵守如 GDPR、HIPAA、PCI DSS 等数据保护法规，通过自动识别和保护个人身份信息 （PII）、健康信息 （PHI） 和财务数据。

+ **保护知识产权：** 对公司的核心资产，如研发文档、设计图纸和商业计划书等应用“高度机密”标签，通过强制加密和严格的权限控制，防止数据泄露。

+ **安全的内外部协作：** 在与外部合作伙伴共享敏感文档时，可以应用带有特定权限（如禁止复制、打印或转发）的标签，确保数据仅被指定人员用于预期目的。

+ **防止内部数据滥用：** 通过内容标记和与数据丢失防护 （DLP） 策略的结合，减少内部员工无意或恶意的数据泄露风险。

#### 最佳实践

+ **从简开始，逐步扩展：** 先从定义一套简单、易于理解的敏感度标签层级开始，在小范围试点后向全组织推广。

+ **自动化优先：** 尽可能利用自动化标签策略，以减少对用户的依赖，确保分类的准确性和一致性。

+ **加强用户教育：** 对员工进行持续的培训，让他们了解不同敏感度标签的含义以及如何正确使用它们。

+ 与 DLP 和内部风险管理集成： 将信息保护与数据丢失防护 （DLP） 和内部风险管理解决方案相结合，形成纵深防御体系。

+ **定期审查和优化：** 定期审查标签的使用情况和策略效果，根据业务变化和新的风险威胁，及时调整和优化。

### Microsoft Purview 内部风险管理 （Insider Risk Management）

此解决方案通过关联多种信号，帮助组织识别、调查和处理因内部人员（无论恶意或无意）行为而带来的潜在风险，例如知识产权盗窃、数据泄露等。

#### 核心组件

1. 策略模板 （Policy Templates）：

   + **定义：** 提供了一系列预置的、针对常见内部风险场景的策略模板，如“离职员工的数据盗窃”、“机密信息泄露”等，帮助管理员快速启动。

1. 信号连接器 （Signal Connectors）：

   + **定义：** 用于从各种来源收集可能预示风险的用户活动信号。

   + **来源：** 主要信号来自 Microsoft 365 审计日志（如文件下载、邮件发送、权限变更），还可以集成来自 Microsoft Defender for Endpoint（如文件复制到 USB、打印）以及第三方 HR 系统（如离职日期、绩效评估）的信号。



### Microsoft Purview 内部风险管理 （Insider Risk Management）

1. 机器学习与智能分析引擎 （Machine Learning and Analytics Engine）：

定义：这是解决方案的大脑。它会分析和关联来自不同来源的信号，建立用户行为的基线，并识别出异常或具有潜在风险的活动序列。

1. 警报与案例管理仪表板 （Alerts and Case Management Dashboard）：

定义：一个集中的工作区，用于安全和合规团队对高风险活动警报进行分类、调查和采取行动。

功能：提供用户活动的时间轴视图、内容浏览器（用于查看触发警报的具体文件或邮件内容）以及协作工具，以进行高效的案例调查。

#### 工作机制

1. 策略配置：管理员选择一个策略模板或创建自定义策略，定义要监控的用户（可以是所有用户、特定组或即将离职的员工）和要关注的风险活动类型。

1. 信号收集：系统开始持续不断地从配置的信号源中收集相关用户的活动日志。

1. 风险评分：智能分析引擎在后台运行，对用户的每个活动进行风险评分。当一系列活动的累积评分超过策略中设定的阈值时，系统会生成一个警报。

1. 警报分类与调查：调查人员在仪表板中查看警报，可以深入研究用户的活动序列，查看相关内容，并判断这是否是一个真正的风险事件。

1. 采取行动：根据调查结果，调查人员可以升级为案例，与人力资源或法务部门协作，或直接关闭警报。系统还支持与电子数据展示（eDiscovery）等工具集成，以便为法律诉讼保留证据。

#### 关键适用场景

+ 监控即将离职的员工：自动提高对已确定离职日期的员工的监控级别，重点关注他们是否有异常的大量文件下载、向个人邮箱发送附件或将数据复制到外部设备的行为。

+ 防止机密项目信息泄露：针对参与高度机密项目（如公司并购、新产品研发）的团队成员，监控他们与项目无关的共享行为或与外部的异常通信。

+ 识别无意的数据泄露：发现员工可能因疏忽而违反了数据处理规定，例如将包含大量客户个人信息的文件上传到未经授权的个人云存储中。

#### 最佳实践

+ 保护隐私：在配置策略时，可以选择“假名化”选项，隐藏警报中用户的真实姓名，直到调查进入深入阶段，以平衡安全监控与员工隐私。

+ 跨部门协作：内部风险管理不是一个纯粹的 IT 或安全项目，需要与人力资源、法务和业务部门紧密合作，共同定义风险策略和响应流程。

+ 从试点开始：首先针对一个明确且高风险的场景（如离职员工）配置策略并运行，在积累经验和优化流程后再扩展到其他场景。

### Microsoft Purview 数据丢失防护 （Data Loss Prevention - DLP）

数据丢失防护帮助组织检测并防止敏感信息在不经意间被共享、传输或使用到不安全或未经授权的位置，是信息保护策略的强制执行层。

#### 核心组件

1. 策略引擎 （Policy Engine）：

定义：DLP 的核心，用于定义“在哪里（位置）”、“检测什么（条件）”以及“如何响应（操作）”的规则。

1. 位置支持 （Location Support）：

定义：DLP 策略可以应用到的范围。

范围：包括 Exchange Online（电子邮件）、SharePoint Online 和 OneDrive for Business（云端文件）、Microsoft Teams（聊天和频道消息）、终端设备（Windows 和 macOS）、非 Microsoft 云应用以及本地文件共享。

1. 条件 （Conditions）：

定义：触发 DLP 策略的规则。最核心的条件是“内容包含敏感信息”，可以引用敏感信息类型 （SITs）、敏感度标签或可训练分类器。还可以结合其他上下文条件，如“收件人是组织外部的”。

1. 操作 （Actions）：

定义：当策略条件被满足时，系统执行的响应措施。

措施：

+ 阻止：直接阻止邮件发送、文件共享或复制操作。
+ 覆盖：允许用户在提供业务理由后覆盖阻止操作。
+ 加密：自动对发送的邮件进行加密。
+ 审计：仅记录事件而不阻止，用于监控。
+ 通知：通过策略提示（Policy Tips）实时教育用户，或向管理员发送邮件警报。

#### 工作机制

1. 策略创建：管理员在 Purview 合规门户中创建一个 DLP 策略，选择要保护的位置，定义条件（例如，内容包含 5 个以上的信用卡号且接收方在组织外部），并配置相应的操作（例如，阻止发送并通知用户）。

1. 内容深度检查 （Deep Content Inspection）：当用户尝试执行操作时（如发送邮件、上传文件），DLP 服务会实时或近实时地检查内容。

1. 策略匹配：检查引擎将内容与所有激活的 DLP 策略进行匹配。

1. 强制执行：如果内容和上下文满足了某个策略的条件，系统会立即执行该策略定义的操作。例如，在 Outlook 中，用户会看到一条策略提示，解释邮件为何被阻止，并可能提供覆盖选项。

#### 关键适用场景

+ 防止敏感邮件外发：创建策略，阻止包含客户 PII 或财务数据的邮件被发送到公司外部的邮箱地址。

+ 保护云端文档共享：阻止用户将 SharePoint 或 OneDrive 中标记为“高度机密”的文档生成公开的匿名共享链接。

+ 管控终端设备上的数据：防止用户将包含知识产权的文件从公司笔记本电脑复制到个人的 USB 驱动器或上传到未经批准的个人云存储服务。

+ 满足监管要求：实施策略，监控和阻止受 PCI DSS、HIPAA 等法规保护的数据的不当传输，并生成审计报告。

#### 最佳实践

+ 在审计模式下开始：在启用阻止操作之前，先将策略在“仅审计”模式下运行一段时间。这可以帮助你评估策略的影响范围，发现误报，并进行微调，而不会中断正常的业务流程。

+ 利用策略提示教育用户：策略提示是强大的实时培训工具。通过自定义提示信息，可以帮助用户理解公司的安全策略，并引导他们做出正确的决策。

+ 从最敏感的数据和最关键的出口开始：优先为最敏感的数据类型和最常见的泄露渠道（如电子邮件、USB 设备）配置 DLP 策略，然后逐步扩大覆盖范围。

### Microsoft Purview 数据安全态势管理 （Data Security Posture Management - DSPM）

Microsoft Purview 数据安全态势管理 （DSPM） 提供了一套先进的工具，旨在帮助组织全面了解并主动改善其整个数据资产的安全状况。它通过持续发现敏感数据、评估安全风险和提供可行的修复建议，有效减少数据泄露和被攻击的风险面。

#### 核心组件

1. 敏感数据发现与分类引擎 （Sensitive Data Discovery and Classification Engine）：

定义：这是 DSPM 的基础。它深度集成了 Microsoft Purview 的数据映射和信息保护能力，不仅能发现数据存储在何处（跨越 Azure， AWS， Google Cloud 等多云环境），更能精准识别这些数据中包含哪些类型的敏感信息。工作方式：利用敏感信息类型 （SITs）、可训练分类器和敏感度标签，自动扫描并识别个人身份信息 （PII）、财务数据、健康信息 （PHI） 和组织的知识产权。

1. 数据安全态势评估引擎 （Data Security Posture Assessment Engine）：

定义：负责持续分析数据资产的配置、权限和网络暴露情况，以识别潜在的安全漏洞和风险。评估维度：数据暴露：检测敏感数据是否被意外地公开暴露在互联网上。权限分析：识别过度授权的访问权限、休眠权限以及是否存在权限蔓延的风险。安全配置：检查数据存储是否缺少加密、日志记录或其他关键安全配置。

1. 风险与攻击路径可视化仪表板 （Risk and Attack Path Visualization Dashboard）：

定义：一个集中的、交互式的仪表板，用于直观地展示组织整体的数据安全态势。功能：风险评分：量化数据资产的风险级别，帮助安全团队确定修复的优先级。数据风险地图：以图形化方式展示敏感数据在多云环境中的分布及其面临的主要风险。攻击路径分析：模拟并显示潜在攻击者可能如何从一个入口点，通过一系列漏洞或错误配置，最终访问到核心敏感数据，从而揭示隐藏的风险链条。

1. 自动化修复建议与工作流 （Automated Remediation Guidance and Workflow）：

定义：该组件不仅指出问题，更重要的是提供具体的、上下文相关的修复建议。工作方式：针对每一个发现的风险，系统都会提供详细的步骤指导安全管理员如何解决该问题。在某些情况下，它还可以与自动化平台（如 Logic Apps）集成，以触发自动化的修复工作流。

#### 工作机制

1. 连接与发现 （Connect and Discover）：DSPM 首先利用 Purview 数据映射的连接器，自动发现并清点组织在多云和混合环境中的所有数据资产（如 Azure Blob Storage， Amazon S3， SQL 数据库等）。

1. 深度扫描与分类 （Deep Scan and Classify）：系统对已发现的数据资产进行深度内容扫描，利用分类引擎识别和标记敏感数据的位置和类型。

1. 持续监控与分析 （Continuous Monitor and Analyze）：评估引擎在后台持续运行，实时监控数据资产的元数据、配置和访问策略。它将当前状态与一套内置的安全最佳实践和行业基准进行比对。

1. 风险识别与优先级排序 （Identify and Prioritize Risks）：当检测到高风险配置（例如，一个包含大量客户 PII 的存储桶被设置为公开可读）时，系统会生成一个安全洞察 （Security Insight） 或警报。风险会根据数据敏感性、暴露程度和潜在影响进行自动优先级排序。

1. 报告与修复 （Report and Remediate）：所有发现的风险和洞察都会汇总到可视化仪表板中。安全团队可以查看攻击路径，理解风险的根本原因，并按照系统提供的建议来手动或半自动地进行修复。

#### 关键适用场景

+ 防止云端数据泄露：主动识别并修复导致敏感数据暴露在公共互联网上的云存储配置错误，这是云数据泄露最常见的原因之一。

+ 实施零信任数据安全：通过持续发现和移除对敏感数据的不必要或过度的访问权限，强制执行最小权限原则，是实现零信任架构中“数据”支柱的关键环节。

+ 管理“影子数据”风险：发现业务部门可能在未经 IT 部门批准的情况下创建的、存储有敏感数据的“影子”数据资产，并将其纳入统一的安全管控范围。

+ 简化合规审计：为合规团队提供持续的、自动化的证据，证明针对敏感数据的关键安全控制（如访问控制、加密）已经到位并有效运行，从而简化 GDPR， CCPA， HIPAA 等法规的审计过程。

#### 最佳实践

+ 优先保护“皇冠上的明珠”：在部署初期，集中精力使用 DSPM 来识别和加固组织最关键的数据资产（即“皇冠上的明珠”），以快速获得最大的安全价值。

+ 将 DSPM 洞察集成到安全运营中：将来自 DSPM 的高优先级警报和洞察，推送到您的 SIEM（如 Microsoft Sentinel）或工单系统中，以确保它们能够被纳入标准的事件响应和漏洞管理流程。

+ 赋能数据所有者：与其让安全团队成为瓶颈，不如利用 DSPM 的报告，将数据相关的风险通报给相应的业务数据所有者，让他们参与到风险的确认和修复决策中来。

+ 将态势管理视为一个持续的过程：云环境是动态变化的，新的数据资产和配置会不断出现。应将数据安全态势管理视为一个持续的、循环往复的改进过程，而不是一次性的项目。

### Microsoft Purview 合规管理器 （Compliance Manager）

合规管理器是一个帮助组织简化和自动化合规性与风险评估流程的工具。它将复杂的法规要求转化为具体的控制措施和可执行的改进建议。

#### 核心组件

1. 评估模板 （Assessment Templates）：

定义：针对全球、区域和行业的各种法规和标准（如 GDPR， ISO 27001， NIST 800-53， HIPAA 等）的预置模板库。

内容：每个模板都包含了该法规所要求的控制项，并将其映射到 Microsoft 的内置控制措施和组织需要自己实施的控制措施。

1. 控制库 （Controls Library）：

定义：一个集中的控制项存储库。它详细说明了每个控制的目标、Microsoft 的实施细节以及客户需要履行的责任。

1. 改进措施 （Improvement Actions）：

定义：针对每个控制项，系统会提供具体的、可操作的改进建议。这些建议通常链接到 Microsoft 365 或 Azure 中的特定配置页面，并提供详细的实施指南。

1. 合规分数 （Compliance Score）：

定义：一个量化的分数，反映了组织在满足特定法规要求方面的进展情况。分数根据完成的改进措施及其权重动态计算，为管理层提供了一个直观的合规态势概览。

#### 工作机制

1. 选择评估：合规管理员首先从模板库中选择与组织业务相关的法规或标准，并创建一个评估。

1. 自动测试与手动验证：系统会自动测试和验证部分由 Microsoft 管理的技术控制措施的状态。对于需要由组织自己实施的控制措施，合规管理器会生成相应的改进措施。

1. 分配与执行：合规管理员可以将这些改进措施分配给组织内具体的技术负责人。负责人按照指南完成配置后，可以在系统中上传证据并标记为“已完成”。

1. 持续监控与报告：合规管理器会持续监控控制措施的状态。任何配置的变更如果影响到合规性，都会被标记出来。组织可以随时生成详细的报告，用于内部审计或向监管机构证明其合规性。

#### 关键适用场景

+ 简化法规遵从：快速了解像 GDPR 这样的复杂法规对组织的技术和管理提出了哪些具体要求，并获得清晰的实施路线图。

+ 准备外部审计：作为一个集中的证据和文档存储库，极大地简化了为 ISO 认证或行业审计收集证据的过程。

+ 持续的风险评估：从一次性的项目式合规转变为持续的监控和改进，确保持续满足合规要求。

#### 最佳实践

+ 建立跨部门团队：合规性是法务、IT、安全和业务部门的共同责任。建立一个跨职能的团队来共同管理和响应合规管理器中的任务。

+ 自定义模板和控制：除了使用内置模板，还可以创建自定义评估，以满足组织内部的特定策略和控制要求。

+ 定期审查合规分数：将合规分数作为关键绩效指标 （KPI） 之一，定期向管理层汇报，并根据分数变化趋势来调整资源投入和工作优先级。

### Microsoft Purview 电子数据展示 （eDiscovery）

电子数据展示（或称电子发现）是用于响应法律案件、内部调查或监管请求，进行识别、保留、收集、审查和导出电子存储信息 （ESI） 的过程。Purview 提供了两个级别的解决方案：核心版 （Core） 和高级版 （Premium）。

#### 核心组件

1. 案例管理 （Case Management）：

定义：允许法务或合规团队为每个调查或诉讼创建一个独立的“案例”工作区，用于管理与该案件相关的所有人员、数据和活动。

1. 内容搜索 （Content Search）：

定义：一个强大的搜索工具，可以在整个 Microsoft 365 环境中（包括 Exchange 邮箱、SharePoint 网站、OneDrive 账户、Teams 消息等）根据关键字、日期范围、发件人/收件人等条件查找相关数据。

1. 法定保留 （Legal Hold）：

定义：一种特殊的保留机制。当将某个数据源（如一个用户的邮箱）置于法定保留状态时，即使该用户尝试删除或修改内容，其原始版本也会被不可变地保留在后台，以满足证据保全的要求。

1. 高级版功能 （Premium Features）：

+ 保管人管理 （Custodian Management）：简化了识别和管理与案件相关的关键人物（保管人）及其数据源的流程。

+ 高级索引 （Advanced Indexing）：对数据进行更深层次的处理和重新索引，以优化搜索的准确性和完整性。

+ 审阅集与分析 （Review Sets and Analytics）：允许将收集到的数据添加到“审阅集”中，并利用重复数据删除、近乎重复检测、邮件线程分析和主题聚类等分析工具，来大幅减少需要人工审阅的数据量。

+ 光学字符识别 （OCR）：可以从图片或扫描的文档中提取和搜索文本。

#### 工作机制

1. 创建案例：法务团队接到调查请求后，首先在 eDiscovery 门户中创建一个新案例。

1. 识别和保留：确定与案件相关的保管人，并将他们的邮箱、OneDrive 等数据源添加到案例中并置于法定保留状态。

1. 搜索与收集：使用内容搜索功能，在保留的数据源中执行有针对性的搜索，并将搜索结果收集到高级版的审阅集中。

1. 处理与分析 （Premium）：在审阅集中，系统会自动进行去重等处理。调查人员可以使用分析工具进一步筛选和组织数据。

1. 审阅与导出：调查人员在审阅集中对筛选后的数据进行逐一审阅，标记相关或不相关的内容。最后，将标记为相关的数据导出，以交付给外部律师或监管机构。

+ **权限分离：** 使用基于角色的访问控制，确保只有被授权的法务和合规人员才能访问和管理 eDiscovery 案例，保护调查的机密性。

## Microsoft Purview 通信合规性（Communication Compliance）

Microsoft Purview 通信合规性是一个内部风险解决方案，它通过捕获和分析组织内的数字通信（如电子邮件、Microsoft Teams 消息等），帮助组织检测、调查和处理不当或违规的内容，从而最大限度地降低通信风险。

### 核心组件

#### 策略模板（Policy Templates）

+ **定义：** 提供一系列针对常见通信风险的预置策略模板，例如“攻击性、骚扰性和威胁性语言”、“共享敏感信息”以及特定于行业的监管要求（如金融行业的 FINRA 规定）。

+ **自定义策略：** 管理员也可以创建完全自定义的策略，定义自己的关键词、条件和要监控的用户群体。

#### 内容捕获连接器（Content Capture Connectors）

+ **定义：** 用于捕获需要被策略扫描的通信内容。

+ **支持范围：** 原生支持 Microsoft 365 通信渠道，包括 Exchange Online 邮件、Microsoft Teams 聊天和频道消息、Yammer 以及 Skype for Business Online。此外，还支持导入第三方来源（如 Twitter、Slack、Zoom）的通信数据进行分析。

#### 智能检测引擎（Intelligent Detection Engine）

+ **定义：** 这是策略的核心，负责扫描捕获到的内容以识别潜在的违规行为。

+ **检测方法：**

+ **可训练分类器：** 内置和自定义的机器学习模型，用于识别骚扰、威胁、亵渎等复杂的语言模式，而不仅仅是简单的关键字匹配。

+ 敏感信息类型（SITs）和关键字： 检测通信内容中是否包含特定的敏感数据（如信用卡号、项目代号）或自定义的关键字列表。

+ **条件匹配：** 可以基于通信的元数据进行检测，例如通信的大小、方向（内部/外部）或发件人/收件人属性。

#### 调查与补救工作流（Investigation and Remediation Workflow）

+ **定义：** 一个安全的、集中的仪表板，供指定的调查人员和审阅者对策略匹配项（警报）进行审查和处理。

+ **功能：**

+ **警报仪表板：** 集中展示所有待处理的警报。

+ **对话视图：** 以对话的完整上下文来呈现匹配的消息，而不仅仅是孤立的一条。

+ **内容屏蔽与注释：** 在审阅过程中可以屏蔽敏感信息或添加注释。

+ **处理操作：** 审阅者可以对警报进行标记（如“合规”、“可疑”）、解决、上报给其他人员，或通知用户。

### 工作机制

1. **配置策略：** 管理员选择一个模板或创建新策略，定义要监控的用户或组、要扫描的通信渠道，以及触发警报的条件（例如，包含攻击性语言或特定的敏感信息类型）。

1. **近实时捕获：** 系统在后台持续捕获指定用户的通信内容。

1. **内容分析：** 捕获到的每条消息都会通过智能检测引擎进行扫描，与所有激活的策略条件进行比对。

1. **生成警报：** 一旦有消息匹配了策略条件，系统就会生成一个警报，并将其发送到调查与补救工作流的仪表板中。

1. **审查与处理：** 被授权的审阅者登录仪表板，对警报进行分类、调查。他们可以查看消息的完整上下文，并根据组织的流程采取适当的措施，例如升级到人力资源部门或法务部门。

### 关键适用场景

+ **营造健康的企业文化：** 主动检测并处理工作场所中的网络欺凌、骚扰或歧视性言论。

+ **保护敏感信息：** 监控并防止员工通过电子邮件或 Teams 聊天无意或恶意地泄露公司机密、客户个人信息（PII）或知识产权。

+ **满足监管监督要求：** 对于金融、医疗等受严格监管的行业，该工具可以帮助满足法律规定的对员工通信进行监督和存档的要求。

+ **调查不当行为：** 在进行内部调查时，可以作为收集相关通信证据的有效工具。

### 最佳实践

+ **明确目标，精准监控：** 避免创建过于宽泛的“监控所有人所有事”的策略。应针对特定的风险（如新产品保密）和特定的人群（如项目团队）来创建目标明确的策略。

+ **建立严格的审阅流程：** 制定清晰的指导方针，定义谁有权审阅警报、审阅的标准是什么，以及如何处理不同类型的违规行为。利用基于角色的访问控制来严格限制审阅者权限。

+ **保护员工隐私：** 优先使用可训练分类器而非宽泛的关键字列表，以减少误报，避免审查不相关的个人通信。在策略中明确告知员工其公司通信可能会受到监控。

+ **定期优化策略：** 定期回顾策略的运行效果，分析误报和漏报的情况，并根据反馈对关键字列表、分类器或条件进行调整，以提高准确性。

## Microsoft Purview 审计（Audit）

Microsoft Purview 审计是一个基础性的合规与安全功能，它详细记录了在 Microsoft 365 组织中发生的数千种用户和管理员活动，并将这些记录保存在一个统一的审计日志中，以便进行搜索和调查。

### 核心组件

#### 统一审计日志（Unified Audit Log）

+ **定义：** 一个集中的、受保护的存储库，用于收集和存储来自多个 Microsoft 365 服务和解决方案的审计记录。

+ **日志内容：** 每条审计记录都包含事件发生的时间、执行操作的用户或应用、操作的对象（如文件、文件夹、用户账户）以及客户端 IP 地址等详细信息。

#### 广泛的活动覆盖

+ **定义：** Purview 审计能够捕获数千种不同的活动。

+ **涵盖的服务：** 包括但不限于 SharePoint Online，OneDrive for Business，Exchange Online，Microsoft Teams，Azure Active Directory，Power BI，Dynamics 365，Microsoft Purview 解决方案本身（如 DLP 策略变更）等。

#### 审计日志搜索工具（Audit Log Search Tool）

+ **定义：** 在 Microsoft Purview 合规门户中提供的一个图形化界面，允许管理员根据多种条件（如活动类型、用户、日期范围、文件或文件夹）来搜索审计日志。

+ **PowerShell 支持：** 同时提供强大的 PowerShell cmdlet（`Search-UnifiedAuditLog`），支持更复杂的脚本化查询和自动化任务。

#### 审计保留策略（Audit Retention Policies）

+ **定义：** 决定审计日志记录在统一审计日志中保留多长时间的策略。

+ **版本差异：**

+ **审计（标准版）：** 默认保留 90 天。

+ **审计（高级版）：** 提供更长的默认保留期（通常为一年），并允许创建自定义的保留策略，将特定用户或特定活动的审计日志最多保留 10 年。

### 工作机制

1. **默认启用：** 对于大多数 Microsoft 365 订阅，审计功能是默认启用的。

1. **记录生成：** 当用户或管理员在任何受支持的 Microsoft 365 服务中执行一项可审计的活动时（例如，在 SharePoint 中查看文件、在 Exchange Online 中永久删除邮件、管理员重置用户密码），该服务会生成一条详细的审计记录。

1. **日志聚合：** 这条审计记录会被安全地发送到统一审计日志中进行存储和索引。

1. **搜索与导出：** 当需要进行调查时，授权管理员可以使用门户网站的搜索工具或 PowerShell 来查询统一审计日志。搜索结果可以在线查看，也可以导出为 CSV 文件进行离线分析或存档。

### 关键适用场景

+ **安全事件调查：** 在发生数据泄露或账户被盗等安全事件后，通过审计日志可以追溯攻击者的活动轨迹，例如他们访问了哪些文件、修改了哪些权限、发送了哪些邮件。

+ **合规性审计：** 向内外部审计员提供证据，证明组织已经实施了适当的访问控制和变更管理流程。例如，可以提供报告显示“谁在过去 90 天内访问过某个包含财务数据的敏感 SharePoint 网站”。

+ **故障排查：** 当出现意外的配置更改或数据丢失时，可以通过审计日志快速定位是“谁”在“什么时间”执行了“什么操作”导致的。

+ **监控管理员活动：** 对拥有高权限的管理员账户进行监控，确保其所有操作都是经过授权且合规的。

### 最佳实践

+ **熟悉关键活动：** 了解对您的组织最重要的审计活动是什么。例如，`FileAccessed`（文件访问）、`MailItemsAccessed`（邮件项目访问）和 `UserLoggedIn`（用户登录）等都是调查中常用的关键事件。

+ **使用精确的搜索条件：** 统一审计日志的数据量非常庞大。在搜索时，应尽可能使用精确的筛选条件（如具体的文件名、用户和狭窄的时间范围），以加快搜索速度并获得更相关的结果。

+ **考虑高级版审计：** 如果组织有严格的合规要求，需要将审计日志保留超过 90 天，或者需要对关键事件（如邮件访问）进行更深入的取证分析，应评估并启用审计（高级版）。

+ **与 SIEM 集成：** 为了实现更高级的威胁检测和关联分析，建议将 Microsoft 365 审计日志与 Microsoft Sentinel 或其他第三方安全信息和事件管理（SIEM）工具集成。

## Microsoft Purview 数据生命周期管理（Data Lifecycle Management）

Microsoft Purview 数据生命周期管理（原名信息治理）提供了一套工具，用于通过实施保留和删除策略来智能地管理组织内容的整个生命周期，从创建或接收开始，到最终成为记录或被永久删除。

### 核心组件

#### 保留策略（Retention Policies）

+ **定义：** 一种宽泛的、基于位置的策略，用于对整个位置（如所有 Exchange 邮箱、所有 SharePoint 网站或所有 Teams 聊天）中的内容应用统一的保留或删除规则。

+ **工作方式：** 管理员创建一个策略，例如“对所有 OneDrive 账户中的内容保留 5 年”，系统会在后台自动将此策略应用于指定位置的所有内容。

#### 保留标签（Retention Labels）

+ **定义：** 一种更精细的、可应用于单个项目（如一份文档、一封电子邮件）的标记。它允许对不同类型的内容应用不同的生命周期管理规则。

+ **应用方式：**

+ **手动应用：** 用户可以从 Office 应用的菜单中手动选择一个标签应用到文件上。

+ **自动应用：** 可以配置策略，根据内容的敏感信息类型、关键字或可训练分类器来自动应用标签。

+ **默认应用：** 可以为某个文档库、文件夹或邮箱设置一个默认标签。

#### 事件驱动的保留（Event-based Retention）

+ **定义：** 这是保留标签的一项高级功能，它允许内容的保留期限从某个特定业务事件发生之日开始计算，而不是从文件的创建或最后修改日期开始。

+ **示例：** 可以为所有项目合同应用一个“项目结束”保留标签，当项目正式结束时，管理员触发一个“项目结束”事件，所有相关合同的 7 年保留期才开始计时。

#### 处置评审（Disposition Review）

+ **定义：** 在保留期结束后、内容被永久删除之前，可以设置一个或多个阶段的手动评审流程。

+ **工作方式：** 当内容的保留期到期时，它不会被立即删除，而是会出现在一个处置评审仪表板中。指定的评审员会收到通知，来决定是批准删除、延长保留期还是重新标记该内容。

### 工作机制

1. **策略/标签创建：** 管理员在 Purview 合规门户中定义保留策略或保留标签，明确规定保留期限、保留期结束后的操作（删除、不执行任何操作或触发处置评审），以及是否需要将内容声明为不可变的“记录”。

1. **发布与应用：** 保留策略被应用于选定的位置。保留标签被发布到这些位置，然后通过手动、自动或默认的方式应用到具体的内容项上。

1. **后台处理：** 后台的计时器作业会定期检查所有内容，并根据其应用的策略或标签来管理其生命周期。

1. **强制执行：**

+ **保留期间：** 如果一个项目处于保留期内，系统会阻止用户（甚至管理员）永久删除它。文件的副本会保存在一个受保护的位置（如保留库）。

+ **保留期结束：** 当保留期结束后，系统会根据策略设置自动执行删除操作，或将其提交给处置评审员。

### 关键适用场景

+ **满足法规遵从：** 确保财务、法律、人事等类型的记录按照法律法规要求保留足够长的时间，例如，将所有税务相关文件至少保留 7 年。

+ **降低数据风险（可防御性删除）：** 主动并自动地删除那些已经没有业务价值且已超过保留期的旧数据。这可以减少组织的存储占用，更重要的是，减少了在发生数据泄露或诉讼时需要审查和承担风险的数据量。

+ **管理记录（Records Management）：** 将重要的合同、政策或最终报告声明为“记录”，使其在保留期内不可更改和删除，以保证其作为证据的完整性和真实性。

+ **简化项目数据管理：** 使用事件驱动的保留，将项目相关的所有文档的生命周期与项目的结束日期绑定，实现项目数据的批量、自动化清理。

### 最佳实践

+ **规划先于配置：** 在创建任何策略或标签之前，务必与法务、合规和业务部门合作，制定全公司的文件保留计划（File Plan），明确不同类型数据的保留要求。

+ **“保留优先”原则：** 牢记 Microsoft 365 的“保留优先”原则。如果一个文件同时受到保留和删除策略的影响，系统将始终优先执行保留操作。

+ **策略与标签结合使用：** 使用保留策略来设置一个覆盖所有内容的基线或最低保留期限。然后，使用保留标签来处理需要更长保留期或特殊处理（如声明为记录）的特定内容类型。

+ **清晰地向用户传达：** 对用户进行培训，让他们了解保留标签的含义以及何时应该手动应用它们，确保策略能够被有效执行。

## 总结

Microsoft Purview 的核心在于其数据映射，它为所有数据资产创建了统一的元数据视图。在此基础上，统一目录为数据使用者提供了发现、理解和追溯数据的工具。同时，一套强大的数据安全和风险与合规功能，确保组织能够在保护敏感信息和满足监管要求的同时，充分利用其数据资产。通过将这些原本孤立的功能整合到一个统一的平台下，Purview 实现了从数据治理到数据保护再到合规管理的全方位覆盖。
