# NLWeb 处理聊天查询的整体流程和设计理念

> 来源：[https://qianniucity.feishu.cn/docx/SH1tdrlI7oVXAUxZ4oPcqSMfnVg](https://qianniucity.feishu.cn/docx/SH1tdrlI7oVXAUxZ4oPcqSMfnVg)

+   **目标与背景**：
NLWeb 旨在为网站或内容集合（如菜谱、活动、商品、书籍、电影等）提供简单的对话式接口。它利用网站常用的 schema.org 结构化数据，使 LLM 能更好地理解和处理内容。

+   **查询处理流程**：

1.  用户提交查询。

1.  系统并行调用多个 LLM，进行相关性检查、上下文去除、记忆项识别等，得到与站点相关的“去上下文化”查询。部分情况下，查询会被拆分为多个子查询，或直接返回需要补充信息的响应。

+   同时，系统会尝试“快速通道”，直接进入后续步骤以提升效率。

1.  查询被发送到数据库服务（通常是向量数据库），结合嵌入和结构化数据检索相关项，返回 schema.org 格式的 JSON 对象。

1.  检索结果由 LLM 进行打分和生成摘要，筛选出得分高于阈值的前 N 个结果。

+   可选：如有后处理需求（如摘要、进一步问答），会在此步骤进行。

1.  最终结果以指定格式返回给用户。

+   **设计优势**：

1.  查询处理高度依赖 LLM，减少了传统搜索引擎中复杂的专用算法和模型开发成本。

1.  返回的每一项都来自数据库，避免了 LLM“编造”结果，保证了结果的真实性。

1.  支持灵活的后处理和多模型协作，适应不同类型和站点的需求。

+   **补充说明**：

1.  单次查询可能涉及 50 次以上的 LLM API 调用，且调用内容高度定制化。

1.  后处理可能影响结果的真实性，需谨慎测试。

整体上，NLWeb 通过结构化数据和 LLM 的结合，实现了高效、真实、可扩展的对话式内容检索。
