# NLWeb 在对话流程中的控制方式和编程模型，强调“混合模式编程”以兼顾灵活性和可控性。

> 来源：[https://qianniucity.feishu.cn/docx/BpsRdZO6noNjOtxOVIOcMmQHnVd](https://qianniucity.feishu.cn/docx/BpsRdZO6noNjOtxOVIOcMmQHnVd)

主要内容总结如下：

+   **对话流与传统搜索的区别**：
对话式系统的流程取决于用户输入和已知信息。例如，旅游网站在用户未指定地点时会主动询问地点，而电影查询则无需此步骤。
通用大模型（如 ChatGPT）虽能自动澄清问题，但行为不总是可控，难以满足网站对一致性的需求。

+   **传统编程 vs LLM**：
传统编程可精细控制流程，但需手动编码每一步。LLM 拥有丰富知识，但只能通过提示词间接控制，结果难以预测。

+   **NLWeb 的混合模式编程**：
NLWeb 允许网站设计者灵活选择由程序还是模型主导流程。对于需要精确控制的场景（如交易操作），可采用传统模式；对于开放性对话，则更多依赖 LLM。
实现上，Python 代码会对 LLM 发起大量小而精确的调用（如判断查询是否涉及历史内容、是否涉及地点等），但最终由程序决定展示内容。

+   **具体示例**：
以房产类查询为例，系统会用 LLM 判断是否已获得必要信息（如位置、价格区间），若缺失则自动生成要向用户补充提问的内容。

整体而言，NLWeb 通过“混合模式编程”，结合 LLM 的智能和传统编程的可控性，实现了灵活且可靠的对话流程控制。
