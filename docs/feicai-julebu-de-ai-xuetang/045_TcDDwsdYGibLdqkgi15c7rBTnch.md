# 用 Claude Agent Skill 搭建 AI 视频分镜系统——从剧本到 Seedance 2.0 提示词的全流程自动化

做 AI 视频短剧的应该都有体会，难的不是写一条提示词，而是从剧本到一整套连贯镜头的全流程。

一个三分钟的短剧可能拆出二十多条视频提示词。每条提示词背后，你得先理解这段剧情要表达什么情绪、用什么镜头语言，然后确保人物外观和场景光影在所有镜头之间保持一致，最后还要适配 Seedance 2.0 的平台规则——时长限制、文件数量、内容红线。这几件事分别都不难，串在一起就变成了一场手工流水线。

所以我们用 Claude 的 Agent + Skill 功能搭了一个 AI 视频分镜系统。核心思路是把影视前期工作拆成三个阶段——导演分析剧本并"讲戏"，服化道设计人物和场景的参考图提示词，分镜师将讲戏内容翻译成 Seedance 2.0 动态提示词——每个阶段的专业方法论和验收标准写进 Skill，让 AI 按标准执行。你只需要上传剧本、确定视觉风格，剩下的从剧情拆解到可直接复制使用的视频提示词全部自动完成。

整体架构是一个制片人加三个 Subagent：导演负责剧本分析和全程质控，服化道负责人物造型和场景环境的美术设计，分镜师负责编写 Seedance 2.0 提示词。流程按三阶段流水线推进——先拆解剧情锁定叙事结构，再生成参考图锁定视觉基准，最后编写动态提示词。每个阶段完成后导演都会执行两步审核——先审业务质量，再审平台合规——不通过就打回修改，循环直到全部通过。

## 核心功能模块

### 导演讲戏——从剧本到画面的翻译层

这是整套系统的创意起点。导演不是把剧本复述一遍，而是像给演员讲戏一样，把脑海中的画面完整描述出来。

剧本写"她回到空荡荡的家，想起了过去"，导演要把它变成：她推开门，玄关的感应灯没亮，只有客厅窗帘缝透进来一道惨白的路灯光。她没开灯，摸黑走到沙发前坐下，目光落在茶几上那只没洗的杯子上。镜头从她的侧脸缓缓推向杯子的特写，冷白路灯光打在她半边脸上，另一半隐没在暗处。

讲戏的规则是：用具体的物理动作，不用抽象概念；用连续的动作链，让画面"动起来"；镜头运动要有明确方向；光影描述要具体到方向、色温、强度。所有维度——画面内容、人物动作、台词声音、镜头运动、光影氛围——不分条列举，用自然流畅的叙述融合在一起。

这层翻译的意义在于：下游的分镜师不需要理解剧本的叙事意图，只需要把导演描述的画面忠实地转写成 Seedance 2.0 能理解的提示词格式。创意判断集中在导演一个人身上，分镜师专注于技术执行。

### 服化道——锁定视觉基准

Seedance 2.0 支持通过 `@引用` 语法传入参考图片。参考图是保持人物和场景一致性的关键——有了参考图，你不需要在每条提示词里反复描述角色长什么样、场景是什么布局，Seedance 能直接"看到"。

服化道的工作就是为导演清单中的每个人物和场景设计参考图提示词。人物提示词的出图格式是一张图：左半边面部特写，右半边全身正面、侧面、背面三视图设定图，白色背景。场景提示词用宫格图格式——九个以内场景用 3×3 九宫格，十到十二个用 3×4，十三到十六个用 4×4——一张图生成所有场景，然后逐格拆出来作为独立的场景参考图。

所有参考图提示词写入 `assets/` 目录的全局素材库，跨集累积。第二集出现的新角色追加到文件末尾，已有角色换装标注为"变体"，不变的标注"复用"直接跳过。这样到第五集的时候，素材库里已经有了完整的角色和场景资产，分镜师直接引用。

### 两步审核——业务质量与平台合规

每个阶段完成后，导演会执行两步审核。

第一步是业务审核，加载阶段专属的审核 Skill。阶段一审讲戏质量——逐行比对原始剧本找遗漏，脑内预演每个剧情点的画面效果，逐项评分。阶段二审服化道设计——逐个对照导演清单找偏离，预演文生图工具生成出来的效果，检查描述歧义。阶段三审 Seedance 提示词——逐条比对导演讲戏本，预演 Seedance 生成的视频画面，检查动作密度和运镜可执行性。三个阶段用三套不同的验收清单，但审核方法一致：逐项比对上游产物、脑内预演生成效果、按维度评分，平均分低于 8 或任一单项低于 6 即判 FAIL。

第二步是合规审核。Seedance 2.0 和 Gemini 各有内容限制——Seedance 不支持写实真人脸部素材，Gemini 对动漫风格的暴露描写更敏感，两个平台都禁止版权 IP 和政治敏感内容。这些规则写在合规验收清单里，导演逐项检查。

两步审核的反馈合并后一次性交给对应 Agent 修改，避免改完业务问题又被合规打回。

### `@引用` 与节拍密度——适配 Seedance 2.0 的技术约束

分镜师编写提示词时，会在文档头部建立一张素材对应表，把人物和场景参考图分配为 `@图片1`、`@图片2`... 的编号。每条提示词开头声明引用——"以 `@图片1` 中的林薇为主角，场景参考 `@图片3` 的深夜办公室"——Seedance 能直接读取参考图中的视觉信息，提示词只需要描述"变化"：动作、运镜、情绪转变。

平台对每条提示词有输入限制：图片最多 9 张、视频最多 3 个、音频最多 3 个、总文件不超过 12 个。素材对应表是全文档的总映射，可以有几十个编号，但每条提示词内的引用必须在限制以内。

另一个关键约束是节拍密度。AI 视频生成中，每个连续镜头内 1 个动作节拍约等于 2.5 秒屏幕时间。节拍塞得太密，生成的动作就会糊、跳、不自然。5 秒的单镜头塞 2 个节拍刚好，塞 4 个就废了。多镜头段落——比如 15 秒的蒙太奇——节拍分布在各个子画面中，每个子画面各自遵守密度约束，总节拍可以远超单镜头上限。此外，每次 Seedance 生成的前 0.5 秒和后 0.5 秒是安全区，不放关键动作或台词，开头用于场景建立，结尾让动作自然收住。

> 注：这套方案能大幅减少从剧本到视频提示词的手工环节，但不要期待一步到位。生成的提示词是高质量的起点——你仍然需要根据 Seedance 的实际生成效果去调整措辞、修改节奏。另外，服化道生成的参考图提示词需要你用文生图工具（如即梦、Nano Banana Pro）生成实际图片后再投入使用，这一步目前还是手动的。整套流程对模型的理解力和执行力要求很高，建议使用 Opus 或 Sonnet 级别的模型。

## 模型选择说明

这套方案依赖 Claude Code 的 Agent + Skill 功能来实现三阶段自动化流程。三个阶段对模型能力的要求各有侧重：

+   导演分析：模型需要理解叙事结构、准确识别情绪转折和时空断点，然后用具体的物理动作和镜头语言把抽象剧情转化为可视化的画面描述。这一步最考验模型的创意理解力。

+   服化道设计：模型需要将导演的外观关键词展开为完整的视觉设计提示词，同时保持多个角色之间的风格统一。对叙事描述式提示词的写法要求比较高。

+   分镜编写：模型需要同时遵守导演意图、`@引用` 语法规范、节拍密度约束、平台文件限制等多重规则，在忠实还原讲戏内容的同时适配 Seedance 2.0 的技术要求。这一步最考验模型的规则遵循能力。

+   审核环节：模型需要在"脑内预演"时准确判断——这条提示词送进 Seedance 会生成什么样的视频？节拍密度够不够？运镜方向矛盾吗？这要求模型对 AI 视频生成的特性有足够的理解。

建议使用 Opus 或 Sonnet 级别的模型。初次使用可以先用一个短场景跑一遍全流程（一个剧本、两三个剧情点），确认产出质量和平台适配效果，再投入完整项目。
