# **如**何开发 AI Agent 应用 - Google AI Studio + Claude Code 组合开发实战

这期内容解决一个问题：怎么从一个模糊的想法，一路做出一个能跑起来的 AI Agent 应用。不是静态页面，而是从需求收集、快速搭建、到本地迭代、最终跑通的完整流程。

开发 AI Agent 的难点不在于让 AI 写代码，而在于你能不能把想法讲清楚，然后一轮一轮迭代到位。很多人卡在第一步：脑子里有个大概的想法，但说不清楚这个 Agent 具体要做什么、怎么和用户交互、AI 能力怎么串联。

所以我们用两个工具的组合打法：Google AI Studio 负责快速搭框架，几分钟就能出一个能跑的原型；Claude Code 负责后续迭代和细节打磨。另外还配了一个产品经理 Skill，在动手之前先帮你把需求想清楚，生成一份包含完整 AI 系统提示词的 Product Spec 文档——这份系统提示词就是整个 Agent 的大脑，所有 AI 功能怎么执行、怎么串联、怎么和用户交互，都靠它来指挥。

整个流程分四步：需求收集 → AI Studio 搭建 → 下载代码到本地 → Claude Code 持续迭代。这期我们用「广告分镜 AI Agent」作为实战案例，从一句话想法迭代了三十多轮，最终做出一个完整可用的产品。

# **核心功能模块**

**Skill 自动调用机制**

product-spec-builder 不需要手动唤起，用户表达想法时会自动触发。不管是"我想做一个..."，还是"能不能加个..."、"把XX改成..."，系统都能识别并进入对应模式——0-1 模式从零开始收集需求，迭代模式则针对现有 Spec 进行变更。这种自动触发设计让用户不需要记指令，直接说想法就能推进。

**追问式需求挖掘**

产品经理 Skill 的核心不是记录用户说了什么，而是通过追问逼用户把没想清楚的地方想清楚。它会针对模糊描述继续深挖，发现逻辑漏洞直接指出，用户说"随便"或"你看着办"时会给出 2-3 个选项逼你选择。每次追问前还会先上网搜索相关信息，确保问题和建议基于最新知识而不是过时认知。

**AI 优先原则**

这套方案把"用 AI 实现"作为第一性原则。用户提出的每个功能，Skill 都会先考虑能不能用 AI 做、能做到什么程度，主动询问"要不要加个 AI 一键优化"。遇到用户设计的繁琐手动流程，会直接建议用 AI 简化。最终输出的 Product Spec 会明确列出需要使用的 Google AI Studio 能力，以及每个 AI 功能的详细提示词（用途、输入、输出、完整 prompt）。

**系统提示词模板化构建**

AI Agent 的核心是系统提示词，这套方案提供了标准模板结构：角色、任务、技能、AI 功能、总体规则、工作流程、交互规则、初始化。Skill 会基于需求收集阶段获取的信息，按模板自动填充并构建完整提示词，然后给用户确认、修改，直到满意为止。这份提示词最终会写入 constants.ts，成为 Agent 运行的指挥中枢。

**文档驱动 + 变更追踪**

方案强制执行"先更新文档，再实现代码"的原则。Product Spec 是整个项目的需求总账，任何功能变更都必须先反映在文档里。迭代模式下，Skill 会自动检测新需求与现有 Spec 的冲突，指出冲突点并给出解决方案，更新完成后自动追加 CHANGELOG 变更记录。这种设计让需求和代码始终同步，迭代几十轮也不会乱。

**功能完整度检查**

/check 指令会拿 Product Spec 和实际代码做交叉对比，检查两个层面：一是功能完整度（哪些做了、哪些没做），二是 AI 实现一致性（constants.ts 里的系统提示词是否完整、App.tsx 的业务逻辑是否对应、gemini-services.ts 的 API 调用是否匹配）。输出的检查报告会把问题分类列出，方便逐一修复。

**项目状态检测与路由**

主 Agent 启动时会自动扫描项目目录，检测当前进度：有没有 Product Spec、有没有代码文件、有没有配置本地运行。根据检测结果自动路由到对应阶段，告诉用户下一步该做什么。这种设计让项目可中断、可恢复，关掉再打开也能无缝继续。

> **注**：这套方案适合开发基于对话交互的 AI Agent 应用，产出是纯前端项目，本地运行没问题。如果要商业化部署，还需要补充后端能力（用户数据、权限管理等）。另外，用 AI 开发产品是个迭代过程，不要期待一键生成完整可用的东西

# 在 Claude Code 中配置

请按照以下步骤配置开发系统，配置完成后，你的项目结构应该是这样：

```
project/
├── Product-Spec.md                      # 产品需求文档（需求收集后生成）
├── Product-Spec-CHANGELOG.md            # 需求变更记录（迭代时生成）
├── [从 AI Studio 下载的代码文件]         # 项目源代码
│   └── ...
└── .claude/
    ├── CLAUDE.md                        # 项目规则和主Agent配置（必须创建）
    └── skills/
        └── product-spec-builder/        # 产品经理技能包（必须创建）
            ├── SKILL.md                 # 技能包核心配置
            ├── reference.md             # Google AI Studio 能力清单
            └── templates/               # 文档格式模板
                ├── product-spec-template.md
                ├── system-prompt-template.md
                └── changelog-template.md
```

1.  **创建项目规则**

+   在 .claude/ 目录下创建 CLAUDE.md 文件

+   粘贴完整的项目规则内容，包含角色定义、工作流程、指令集

+   确保包含项目状态检测、阶段路由、迭代流程的定义

1.  **创建 Skill 技能包**

+   在 .claude/skills/ 目录下创建 product-spec-builder/ 文件夹

+   创建 SKILL.md 作为技能包核心配置

+   粘贴需求挖掘流程、追问策略、AI 优先原则等内容

1.  **添加能力清单**

+   在 product-spec-builder/ 目录下创建 reference.md

+   粘贴 Google AI Studio 支持的所有 AI 能力（图像、视频、语音、智能增强、数据连接）

+   这是 AI 能力匹配的参考文档，Skill 会根据用户需求从中选择合适的能力

1.  **添加文档模板**

+   在 product-spec-builder/templates/ 目录下创建三个模板文件

+   product-spec-template.md：定义 Product Spec 的格式结构

+   system-prompt-template.md：定义 AI 系统提示词的格式结构

+   changelog-template.md：定义变更记录的格式结构

+   这些模板会严格约束输出格式，确保文档结构统一

**重要配置细节**

+   **Skill 自动调用**：CLAUDE.md 中定义了触发规则，用户表达产品想法或迭代需求时自动调用 product-spec-builder

+   **两种工作模式**：0-1 模式从零开始收集需求，迭代模式针对现有 Spec 进行变更，Skill 会自动检测并进入对应模式

+   **模板约束**：templates/ 中的格式是强制性的，所有输出必须按照模板结构

+   **AI 优先原则**：每个功能都会先考虑能否用 AI 实现，主动建议 AI 增强方案

+   **实时搜索策略**：追问前会先上网搜索相关信息，确保建议基于最新知识

+   **系统提示词构建**：按标准模板（角色、任务、技能、AI 功能、工作流程、交互规则、初始化）自动构建，用户确认后写入 Product Spec

+   **文档驱动开发**：任何功能变更必须先更新 Product Spec，再实现代码

+   **变更追踪**：迭代时自动更新 CHANGELOG，记录每次变更的具体内容

+   **项目状态检测**：启动时自动扫描目录，检测 Product Spec、代码文件、运行配置的状态，路由到对应阶段

+   **功能完整度检查**：/check 指令对照 Product Spec 检查代码实现，输出完整度报告

+   **冲突检测**：迭代时自动检测新需求与现有 Spec 的冲突，给出解决方案

# **核心设计理念**

```
┌─────────────────────────┐
│  product-spec-builder   │ ← 知识层：提供产品经理能力
│  ├─ SKILL.md            │    需求挖掘、追问策略、AI优先原则
│  ├─ reference.md        │    Google AI Studio 能力清单
│  └─ templates/          │    Product Spec、系统提示词、变更记录模板
├─────────────────────────┤
│  CLAUDE.md              │ ← 流程层：控制开发流程
│                         │    定义工作流、指令集、阶段路由
├─────────────────────────┤
│  Main Agent             │ ← 执行层：调度整个开发流程
│                         │    需求收集→Spec生成→代码检查→本地运行
├─────────────────────────┤
│  Google AI Studio       │ ← 搭建层：快速生成原型
│                         │    根据Spec自动生成可运行代码
├─────────────────────────┤
│  Claude Code            │ ← 迭代层：持续打磨产品
│                         │    /check检查完整度→/prd迭代需求→修复代码
├─────────────────────────┤
│  Product-Spec.md        │ ← 文档层：结构化存储
│  Product-Spec-CHANGELOG │    产品需求文档（需求总账）
│  constants.ts           │    变更记录
│                         │    AI系统提示词（Agent大脑）
└─────────────────────────┘
```

**工作流程**

1.  **需求表达** - 用户描述产品想法，自动触发 product-spec-builder

1.  **追问深挖** - Skill 针对模糊、矛盾、遗漏的地方追问，逼用户想清楚

1.  **AI 能力匹配** - 根据功能需求，从 reference.md 匹配 Google AI Studio 能力

1.  **系统提示词构建** - 按模板构建完整的 AI 系统提示词，用户确认后写入 Spec

1.  **Spec 生成** - 输出包含产品说明、功能需求、UI 布局、用户流程、系统提示词的完整文档

1.  **AI Studio 搭建** - 用户将 Spec 丢进 Builder，勾选推荐能力，生成可运行原型

1.  **下载导入** - 下载代码到本地，导入 Claude Code 继续开发

1.  **功能检查** - /check 对照 Spec 检查代码完整度和 AI 实现一致性

1.  **迭代修复** - /prd 进入迭代模式，先更新文档再改代码，保持两边同步

1.  **本地运行** - /run 启动项目，测试验证，继续迭代直到满意

**关键特性**

+   **Skill 自动触发** - 用户表达想法或迭代需求时自动调用，无需记指令

+   **追问式需求挖掘** - 不接受模糊回答，通过追问逼用户把细节想清楚

+   **AI 优先原则** - 每个功能首先考虑用 AI 实现，主动建议 AI 增强方案

+   **实时搜索** - 追问前先上网搜索，确保建议基于最新知识

+   **模板约束** - 严格遵循 templates/ 定义的格式，保证输出规范统一

+   **文档驱动** - 任何变更先更新 Product Spec 再改代码，需求和代码始终同步

+   **变更追踪** - 迭代时自动更新 CHANGELOG，记录每次变更内容

+   **项目状态检测** - 启动时自动扫描目录，路由到对应阶段，支持中断恢复

+   **功能完整度检查** - 对照 Spec 检查代码实现，输出分类报告便于逐一修复

+   **冲突检测** - 迭代时检测新需求与现有 Spec 的冲突，给出解决方案
