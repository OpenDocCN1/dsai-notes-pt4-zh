# **Claude Code 项目记忆管理 - Progr**ess Recorder Agent方案

这套方案主要解决一个问题：用 Claude Code 开发项目时，重要的决策、任务进度、技术约束等信息会散落在对话历史中。随着对话轮次增加，前面确定的内容容易被遗忘或难以查找。

所以我们设计了 Progress Recorder，这是一个专门负责记录的 Subagent。它会自动识别对话中的关键信息，并持续维护一个 progress.md 文件作为项目的核心文档。所有重要信息都会被结构化地记录在这里。

它的识别机制基于语义理解。当你说"决定使用 Next.js"，会记录到 Decisions 区块；说"必须支持 Safari"，会写入 Pinned 约束；提到"完成了认证模块"，会移到 Done 并标注日期。系统还会根据表达的确定性来分类 - "必须"和"可能"会被区别对待，避免把不确定的信息当作确定决策。

一个关键设计是分级保护：Pinned 和 Decisions 一旦写入就不会被自动修改，即使出现新的相关信息也只会在 Notes 中提醒。当 Notes 和 Done 积累过多时，系统会自动归档到 progress.archive.md，保持主文件的可读性。

这个方案适合需要持续几天或几周的项目开发。通过 /recap 命令可以随时回顾项目状态，不用在对话历史中翻找。相当于给 Claude Code 增加了一个轻量但实用的项目记忆能力。

# **核心功能模块**

**/语义识别**

基于语义理解而非关键词匹配，Progress Recorder 会从对话中识别不同类型的项目信息。系统能区分约束条件（"必须支持"）、决策事项（"决定采用"）、待办任务（"需要实现"）、完成标识（"已经完成"）等语义类别。通过分析表达的确定性程度，将信息准确归类到 progress.md 的对应区块中。

**/记忆管理**

所有项目信息按照固定结构存储在 progress.md 中：Pinned 记录关键约束、Decisions 保存历史决策、TODO 管理待办任务、Done 追踪完成事项。每个 TODO 都有唯一 ID（#1, #2...）和优先级（P0/P1/P2），支持 OPEN→DOING→DONE 的状态流转，实现完整的任务生命周期管理。

**/增量合并**

当新信息出现时，系统会执行智能合并策略：相似任务会更新原有条目而非创建重复项；新决策与旧决策冲突时，在 Notes 中记录提醒而不覆盖历史。这种增量合并机制确保信息的连续性和完整性，避免重复记录或丢失历史。

**/归档机制**

当 Notes 和 Done 条目超过 100 条时，系统会自动触发归档流程。历史记录被转移到 progress.archive.md 中永久保存，主文件只保留最近 50 条，保持文档的可读性。归档文件采用只增不删策略，确保完整的项目历史可追溯。

**/置信判定**

系统通过置信度判定避免误记录。只有包含"必须/决定/确定"等强承诺语言才写入受保护区块（Pinned/Decisions）；包含"可能/建议/或许"等弱化词的内容会降级到 Notes 并标注"Needs-Confirmation"。这种机制确保关键决策的权威性，避免把讨论中的想法误作定论。

> 注：这套方案的核心在于大模型对语义的抽取和理解能力，不同模型的效果会有明显差异。Progress Recorder 基于 Claude Code 的 Subagent 功能实现，通过 /record 和 /archive 命令调用。系统会在检测到决策、约束、任务等关键语言时自动触发记录，特别适合需要长期维护、持续数天或数周的项目开发。

# 配置 Progress Recorder 记录系统

请跟着视频中的教学并且按照以下步骤配置 Progress Recorder，让你的 Claude Code 项目具备持久记忆能力。配置完成后，你的项目结构应该是这样：

```
project/
├── CLAUDE.md                      # 项目规则文件（必须创建）
├── progress.md                    # 项目记忆文件（自动生成）
├── progress.archive.md            # 历史归档文件（按需生成）
├── .claude/agents/
│   └── progress-recorder.md       # 记录员Subagent（配置创建）
└── ...
```

## **配置步骤：**

1.  **创建项目规则** - 在项目根目录创建 CLAUDE.md 文件，加入项目记忆规则和指令集

1.  **创建 Subagent** - 使用 Claude Code 的 /agents 指令，选择 "Create New Agent" 创建 progress-recorder

1.  **设置系统提示词** - 将完整的 Progress Recorder 系统提示词复制到 Subagent 配置中

1.  **配置描述信息** - Description 设置为："负责维护项目记忆，记录决策、任务、进度等关键信息"

## **重要配置细节：**

+   **CLAUDE.md** 必须包含项目记忆规则，定义自动触发条件和指令集（/record、/archive、/recap），这是系统识别和执行记录的关键

+   **Subagent 名称** 建议使用 progress-recorder，保持命名一致性便于识别和调用

+   **系统提示词** 必须完整复制，包含所有功能定义、规则和模板，这是系统正确工作的基础

+   **工具权限** 只需要基础的文件读写权限，不需要 web_search 等额外工具

+   **progress.md** 会在首次调用时自动创建，无需手动建立，系统会按照模板初始化所有区块

+   **触发方式** 支持手动调用（/record、/archive）和自动触发（检测到决策、约束等关键语言）

+   **归档阈值** 默认 Notes+Done 超过 100 条时触发，可以在系统提示词中调整

## **验证配置：**

配置完成后，可以通过简单对话测试：说"决定使用 React 开发前端"，然后输入 /record，系统应该会生成 progress.md 并将这个决策记录在 Decisions 区块中。使用 /recap 可以随时查看当前项目状态。

这套配置相对轻量，主要依赖大模型的语义理解能力。一旦配置好，就能为你的项目提供稳定的记忆管理，特别适合那些需要持续开发多天的项目。

# **🎯 核心设计理念**

传统的 AI 对话中，模型会自主判断哪些信息值得记住，通过总结压缩来"记忆"对话内容。这种方式容易丢失用户认为重要但模型忽略的细节。Progress Recorder 改变了这个逻辑：

+   **分级保护机制** - Pinned 和 Decisions 一旦记录就永不自动修改，这些是用户明确的"硬约束"

+   **语义触发规则** - 在 CLAUDE.md 中预定义哪些表达模式必须记录（如"决定使用"、"必须支持"）

+   **手动干预能力** - 通过 /record 随时强制记录，/archive 主动归档，用户完全控制记忆管理

+   **置信度过滤** - 系统区分"必须"和"可能"，只把高置信度的信息写入关键区块

## 🏗️ 系**统架构**

```
┌──────────────────┐
│    CLAUDE.md     │ ← 规则层：定义触发条件和指令集
├──────────────────┤
│ progress-recorder│ ← 处理层：语义识别和文档管理
├──────────────────┤
│   progress.md    │ ← 工作记忆：当前项目状态
│progress.archive  │ ← 历史记忆：完整项目历程
└──────────────────┘
```

## **工作流程：**

1.  **对话监听** - 主代理（Claude Code）在对话中识别关键语言模式

1.  **触发判断** - 根据 CLAUDE.md 的规则决定是否需要记录

1.  **语义抽取** - progress-recorder 分析对话内容，提取结构化信息

1.  **智能合并** - 将新信息与现有记录对比，执行去重或更新

1.  **分级存储** - 根据信息类型写入 progress.md 的对应区块

1.  **容量管理** - 超过阈值时自动归档到 progress.archive.md

## **关键特性：**

+   **增量更新** - 不是每次重写整个文件，而是智能合并新增内容

+   **历史不可变** - Decisions 按时间顺序追加，旧决策永远保留，新决策不会覆盖历史

+   **任务生命周期** - TODO 从创建（#ID分配）到状态流转（OPEN→DOING→DONE）的完整追踪

+   **证据链接** - Done 项目会尽可能关联 commit、PR、文件路径等证据

+   **冲突提醒** - 新信息与 Pinned/Decisions 冲突时，不覆盖而是在 Notes 中提醒
