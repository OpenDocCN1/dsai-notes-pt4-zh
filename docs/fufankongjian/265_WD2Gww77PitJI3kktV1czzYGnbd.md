# AI 接管开源项目 · 自查清单

> 配套视频：《用 AI 编程工具接管一个完全陌生的开源项目》

> 作者：木羽Cheney（VibeCoding 实战课主讲老师） · 赋范大模型技术社区

> 用法：跟着视频操作，每完成一步打个勾，哪步没到位一眼看出来

---

## 阶段一：获取项目源码

| 状态 | 步骤 | 操作要点 | 常见卡点 |
| --- | --- | --- | --- |
| □ | **1.1** | 在 GitHub 上找到目标项目，确认 Star 数、最近更新时间、Issue 活跃度 | 注意：Star 多不等于质量好，重点看最近 3 个月是否有人维护 |
| □ | **1.2** | git clone 项目到本地工作目录 | 确认 clone 的是**主分支**（main/master），不是别人的 fork；如果项目很大，可以加 --depth 1 只拉最新提交 |
| □ | **1.3** | 快速浏览项目根目录的 README.md、package.json 或 requirements.txt | 目的不是读懂，而是确认：这个项目用什么语言/框架？有没有明确的启动说明？需要什么环境前提（Node 版本、Python 版本等）？ |

**阶段一自查**：

+   □ 本地已有完整的项目源码目录

+   □ 我大致知道这个项目是用什么技术栈的（前端框架 + 后端语言 + 数据库）

---

## 阶段二：AI 一句话启动

| 状态 | 步骤 | 操作要点 | 常见卡点 |
| --- | --- | --- | --- |
| □ | **2.1** | 用 AI 编程工具打开项目目录（例如 cd 项目目录 &amp;&amp; claude） | 确认 AI 工具的工作目录就是项目根目录，不是上层或子目录 |
| □ | **2.2** | 给 AI 一句话启动指令，让它分析项目结构、安装依赖、启动服务 | 关键：不要一次给太多指令，就一句话——&quot;帮我把这个项目跑起来&quot;。让 AI 自己判断该做什么 |
| □ | **2.3** | 观察 AI 的执行过程：它是否正确识别了前后端？是否安装了所有依赖？ | **如果 AI 报错**说缺少某个依赖或环境变量，不要自己手动去装，告诉 AI 让它自行解决 |
| □ | **2.4** | 确认前端和后端服务都已启动，AI 给出了访问地址 | 典型输出：前端运行在 http://localhost:3000、后端运行在 http://localhost:8080 |

**阶段二自查**：

+   □ 前端服务正在运行（有明确的端口号）

+   □ 后端服务正在运行（有明确的端口号）

+   □ 如果有数据库，数据库也已正常连接

+   □ AI 给出的访问地址我已经记下来了

**常见问题排查**：

| 问题 | 原因 | 解决方法 |
| --- | --- | --- |
| EADDRINUSE: address already in use | 端口被其他程序占用 | 告诉 AI：&quot;端口被占用了，请换一个端口启动&quot; |
| npm ERR! peer dep 依赖冲突 | npm 版本兼容性问题 | 告诉 AI：&quot;依赖安装报冲突，请想办法解决&quot; |
| ModuleNotFoundError | Python 虚拟环境没激活 | 告诉 AI：&quot;Python 依赖没找到，请创建虚拟环境重新安装&quot; |
| ENOENT: no such file or directory .env | 缺少环境配置文件 | 告诉 AI：&quot;缺少 .env 文件，请检查是否有 .env.example 并帮我创建&quot; |

## 阶段三：项目规则文件

| 状态 | 步骤 | 操作要点 | 常见卡点 |
| --- | --- | --- | --- |
| □ | **3.1** | 创建项目规则文件（如 .claude/rules/project.md） | 不同 AI 工具的规则文件位置不同，确认你用的工具放在哪里 |
| □ | **3.2** | 在规则文件里**只写启动命令** | 这是本期视频的核心教训：rules 文件越少越好。AI 自己看代码就能知道项目结构和技术栈，你不需要替它写 |
| □ | **3.3** | 检查规则文件里是否写了&quot;项目结构描述&quot; | **如果有&quot;**frontend/ 是前端代码&quot;之类的描述，立刻删掉。这些信息 AI 自己能推断，你写了反而可能和实际不一致，导致 AI 越改越乱 |

**阶段三自查**：

+   □ 规则文件已创建

+   □ 规则文件里**只有**启动命令（前端启动、后端启动、同时启动）

+   □ 规则文件里**没有**项目结构描述

+   □ 规则文件里**没有**技术栈说明

+   □ 规则文件里**没有**代码规范说明（这些放到专门的 rules 文件里）

> **为什么"少即是多"？** Claude Code 官方最佳实践明确指出：CLAUDE.md 太长时，Claude 会忽略一半规则。重要指令被噪声淹没，执行质量反而下降。

## 阶段四：浏览器验证

| 状态 | 步骤 | 操作要点 | 常见卡点 |
| --- | --- | --- | --- |
| □ | **4.1** | 打开浏览器，访问 AI 给出的前端地址 | localhost 和 127.0.0.1 通常等价，但某些项目配置了 host 限制时可能不同 |
| □ | **4.2** | 确认页面正常加载，不是白屏或报错页 | 白屏常见原因：前端编译失败但没报错、后端 API 地址配置错误、CORS 跨域被拦截 |
| □ | **4.3** | 点击页面上的核心功能入口，确认交互响应正常 | 此时不急着用完整功能，只确认&quot;页面活着、能点击、有响应&quot; |

**阶段四自查**：

+   □ 浏览器成功打开了项目前端页面

+   □ 页面内容正常显示（不是白屏/404/报错）

+   □ 页面上的按钮/输入框可以正常交互

## 阶段五：模型兼容性确认

| 状态 | 步骤 | 操作要点 | 常见卡点 |
| --- | --- | --- | --- |
| □ | **5.1** | 在 ask 模式下向 AI 确认：这个项目需要什么类型的模型？ | 关键问题：&quot;这个项目调用 LLM 时，是纯文本对话，还是需要图片理解/多模态能力？&quot; |
| □ | **5.2** | 确认项目的 API 协议：是 OpenAI 兼容格式还是私有格式？ | 大多数 AI 开源项目用 OpenAI 兼容 API（/v1/chat/completions），如果是私有格式需要额外适配 |
| □ | **5.3** | 根据确认结果选择合适的模型 | 如果不需要多模态，可选范围更大、成本更低；如果需要视觉能力，模型选择受限 |

**阶段五自查**：

+   □ 我知道这个项目需要**纯文本**模型还是**多模态**模型

+   □ 我知道这个项目用的是 **OpenAI 兼容** API 格式还是私有格式

+   □ 我已经选好了要接入的模型（推荐参考工具包里的《国产模型速查表》）

## 阶段六：接入国产模型 + 最小验证

| 状态 | 步骤 | 操作要点 | 常见卡点 |
| --- | --- | --- | --- |
| □ | **6.1** | 找到模型配置文件的位置（通常在 .env、config.yaml 或项目设置页面） | 让 AI 帮你找：&quot;这个项目的模型配置在哪个文件？需要配置哪些字段？&quot; |
| □ | **6.2** | 配置三要素：Base URL、API Key、模型名（model） | ⚠️ **注意域名**：同一厂商的中国站和国际站域名可能不同，API Key 不互认！（参考《国产模型速查表》中的具体 URL） |
| □ | **6.3** | 保存配置，重启服务 | 有些项目改配置后需要重启才生效，有些支持热更新，看项目说明 |
| □ | **6.4** | 用一条简单的真实问答测试 | **关键****：不能用&quot;**你好&quot;这种话——要用一个能确认模型真正在工作的问题。比如：&quot;请用 50 个字介绍一下量子计算&quot; |
| □ | **6.5** | 检查回答的质量和延迟 | 回答是否合理？延迟是否可接受？有没有返回错误码（401/403/429）？ |

**阶段六自查**：

+   □ 模型配置已填写完成（Base URL + API Key + 模型名）

+   □ 服务已重启

+   □ 发送了一条真实问答

+   □ 收到了**合理的回答**（不是报错、不是空响应、不是 Mock 数据）

+   □ 回答延迟在可接受范围内（通常 3-15 秒）

**常见配置问题**：

| 症状 | 可能原因 | 排查方向 |
| --- | --- | --- |
| 401 Unauthorized | API Key 错误或过期 | 去模型提供商控制台重新生成 Key |
| 403 Forbidden | 账户没有权限或欠费 | 检查账户余额和模型访问权限 |
| 404 Not Found | Base URL 或模型名写错了 | 对照速查表检查 URL 和 model 字段 |
| 429 Too Many Requests | 免费额度超限或并发过高 | 等一会儿再试，或换一个模型 |
| 回答乱码或空 | 模型不支持项目要求的 API 参数 | 检查项目是否用了模型不支持的参数（如 function calling） |

## 全流程完成确认

完成以上 6 个阶段后，做最后确认：

+   □ 项目完整运行中（前端 + 后端 + 模型接入）

+   **□ 核心功**能可用（不只是页面能打开，而是端到端跑通）

+   □ 规则文件干净简洁（只有启动命令，没有废话）

+   □ 我能用一句话描述"这个项目接管完成后能做什么"

> **恭喜！** 你现在拥有的不只是一个跑通的项目，而是一套方法——以后碰到任何 AI 开源项目，你知道怎么用 AI 工具把它接管并跑通。

## 拿走这套方法后，下一步做什么？

1.  找一个你感兴趣的 GitHub 项目，用同样的方法再接管一个

1.  **逐步修改功能**——项目跑通后，让 AI 帮你加功能/改界面/接入其他模型

1.  **加入赋范社区**，和其他小伙伴交流接管经验，遇到问题有人帮你排查
