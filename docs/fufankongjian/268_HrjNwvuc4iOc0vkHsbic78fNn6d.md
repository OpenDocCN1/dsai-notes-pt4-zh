## 04-verify

---

### 为什么最小验证不能跳过？

视频原话：

> "很多人项目跑起来就直接去试功能了，但有一步不能跳——你得确认这个项目在你手里是真的能用。"

**项目跑起来 ≠ 项目可用。** 这两个状态之间有一个巨大的鸿沟，叫做"假可用"。

#### 什么是"假可用"？

| 你看到的 | 实际发生的 | 后果 |

| --- | --- | --- |

| 前端页面正常显示 | 后端 API 返回 500，前端吞掉了错误 | 你以为可用，但任何涉及后端的功能都不work |

| 发消息后收到了回复 | 回复来自项目预设的 Mock 数据，不是真实模型 | 你以为模型接通了，其实根本没走模型 |

| 模型返回了响应 | 响应是空字符串或只有 {} | API 调通了但参数不对，模型拒绝了请求 |

| 第一次问答正常 | 用了缓存，后续换个问题就报错 | 缓存命中掩盖了真实问题 |

| 页面上显示"成功" | 后台日志里全是 `warning` 和 `deprecated` 告警 | 短期能用，但某个警告升级为错误后就崩了 |

这些"假可用"状态有一个共同特点：粗看没问题，但你一旦依赖这个项目做真事就会翻车。

最小验证的目的，就是用最低成本确认——这个项目在你手里，真的能跑通一个完整的业务流程。

### 最小验证三步法

#### Step 1：找到核心功能入口

不是随便点一个按钮，而是找到这个项目最核心的那个功能。

怎么判断什么是"核心功能"？

| 项目类型 | 核心功能 | 入口在哪 |

| --- | --- | --- |

| 问答/聊天类 | 发一条消息，收到 AI 回复 | 通常是主页面的输入框 |

| 文档分析类 | 上传一个文件，得到分析结果 | 通常有"上传"按钮或拖拽区域 |

| 代码生成类 | 输入一段描述，生成代码 | 通常有"生成"或"运行"按钮 |

| Agent 类 | 给一个任务，Agent 自动执行并产出结果 | 通常有"开始"或"运行"按钮 |

| 搜索/RAG 类 | 输入一个查询，得到带引用的回答 | 搜索框 |

**提示词**（让 AI 帮你找）：

```
这个项目的核心功能是什么？用户打开首页后，
最主要的操作入口在哪里？请告诉我具体的 URL 路径和操作方式。
```

#### Step 2：用最简单的输入触发一次完整流程

关键原则：输入越简单越好，目的是验证"管道通不通"，不是测试模型能力。

不同项目类型的最小输入：

| 项目类型 | 推荐的最小输入 | 为什么选这个 |

| --- | --- | --- |

| 问答类 | "请用 50 个字介绍量子计算" | 限定字数，容易判断回答是否合理 |

| 文档分析类 | 一个只有 3 行的 txt 文件 | 够小，排除文件大小/格式问题 |

| 代码生成类 | "写一个 Python 的 hello world" | 最简单的代码，任何模型都能做 |

| Agent 类 | 给一个 1 步就能完成的简单任务 | 排除多步编排的复杂性 |

| 搜索/RAG 类 | 搜索知识库中肯定存在的内容 | 排除"没搜到"导致的误判 |

**为什么不用"你好"来测试？**

"你好"太简单了，很多项目对"你好"有预设的回复模板，甚至不走模型就返回了。你需要一个需要模型思考才能回答的问题，才能确认模型确实在工作。

**提示词**（让 AI 帮你验证）：

```
请用这个项目的核心功能做一次最简单的测试。
发送"请用 50 个字介绍量子计算"。
然后告诉我：
1. 你在哪个页面/接口发送的
2. 收到了什么响应
3. 响应是否像是模型实时生成的（而不是预设数据）
4. 响应时间大约多少秒
```

#### Step 3：验证输出的真实性

**收到回复不等于验证通过。** 你还需要确认三件事：

##### 3a. 输出是模型实时生成的吗？

| 检查点 | 如果是真实模型输出 | 如果是 Mock/缓存 |

| --- | --- | --- |

| 再问一次同样的问题 | 措辞会略有不同 | 一字不差地重复 |

| 换一个完全不同的问题 | 正常回答 | 可能报错或返回固定内容 |

| 检查后端日志 | 有 API 调用记录 | 没有外部请求 |

| 看响应时间 | 2-15 秒（取决于模型） | 瞬间返回（<100ms） |

**提示词**（让 AI 帮你检查）：

```
我刚才的测试收到了回复，但我想确认这个回复确实来自真实的模型调用。
请检查：
1. 后端日志中是否有向模型 API 发送请求的记录
2. 请求了哪个 URL？发送了什么参数？
3. 如果再发一次同样的问题，回复是否会不同（排除缓存）
```

##### 3b. 输出格式正确吗？

| 正常输出 | 异常输出 |

| --- | --- |

| 清晰可读的中文/英文 | 乱码、HTML 标签混入、`\n` 没被解析 |

| 内容完整 | 输出被截断（通常是 `max_tokens` 设置太低） |

| 只有回答内容 | 混入了 JSON 结构、`role: assistant` 等元数据 |

##### 3c. 响应时间合理吗？

| 响应时间 | 判断 |

| --- | --- |

| <100ms | ⚠️ 太快了，可能是缓存或 Mock |

| 2-5 秒 | ✅ 正常（国内 API 直连） |

| 5-15 秒 | ✅ 正常（模型较大或网络延迟） |

| 15-30 秒 | ⚠️ 偏慢，检查网络或模型选择 |

| >30 秒 | ❌ 超时风险，可能需要换更快的模型 |

### 验证结果判断矩阵

| 结果 | 判断 | 下一步 |

| --- | --- | --- |

| 回复合理 + 非缓存 + 格式正确 + 延迟合理 | ✅ **验证通过** | 接管完成！可以开始正式使用 |

| 回复合理但疑似缓存 | ⚠️ 需进一步排查 | 换一个问题再试，检查后端日志 |

| 收到回复但内容是乱码/截断 | ❌ 模型参数问题 | 检查 `max_tokens`、`encoding` 配置 |

| 报错 401/403 | ❌ 认证问题 | 检查 API Key 是否正确、是否过期 |

| 报错 404 | ❌ 地址问题 | 检查 Base URL 和模型名是否正确 |

| 报错 429 | ❌ 限流 | 等一会儿再试，或换免费额度更多的模型 |

| 超时无响应 | ❌ 网络/模型问题 | 检查网络连通性，尝试用 `curl` 直接测 API |

| 返回空字符串 | ❌ 参数不兼容 | 项目可能用了模型不支持的参数（如 function calling） |

### 完整验证提示词（一条搞定）

如果你想让 AI 帮你完成上述所有检查，用这条综合提示词：

```
请帮我对这个项目做一次完整的端到端验证，按以下步骤执行：

【Step 1】找到核心功能入口
- 确认主要操作页面的 URL
- 确认输入方式（输入框/上传/按钮）

【Step 2】发送测试请求
- 发送"请用 50 个字介绍量子计算"。
- 记录响应内容和响应时间

【Step 3】验证真实性
- 再发送一次相同的问题，对比两次回复是否完全一样（排除缓存）
- 发送一个完全不同的问题"Python 的列表推导式怎么用？"，确认也能正常回答
- 检查后端日志，确认有真实的模型 API 调用记录

【Step 4】给出结论
- 项目状态：✅ 可用 / ⚠️ 有问题 / ❌ 不可用
- 如果有问题，具体是什么问题？建议怎么修？
- 响应时间评估
- 输出格式评估
```

### 验证失败的常见原因和解法

#### 原因 1：模型不支持 Function Calling

**症状**：发消息后报错 invalid parameter: `tools` 或 `function_call` is not supported

**解法**：

+ 检查项目代码中是否使用了 `tools` 或 `function_call` 参数

+ 如果是，换一个支持 Function Calling 的模型（如 Qwen-Max、GLM-5、GPT-4o）

+ 或者在项目配置中关闭 Function Calling 功能

#### 原因 2：模型上下文长度不够

**症状**：短问题正常，长对话后报错 `context_length_exceeded`

**解法**：

+ 检查项目是否有对话历史长度限制的配置

+ 换一个上下文窗口更大的模型（如 Kimi 支持 200K、Qwen-Long 支持 1M）

+ 或者在项目配置中减少历史消息保留数量

#### 原因 3：API 格式不兼容

**症状**：报错 invalid request 或返回 HTML 而非 JSON

**解法**：

+ 确认项目期望的 API 格式和你配置的模型 API 格式是否一致

+ 大多数项目期望 OpenAI 兼容格式（`/v1/chat/completions`）

+ 如果模型提供商的接口格式不同，可能需要通过代理/适配层转换

#### 原因 4：网络问题

**症状**：超时、连接被拒绝

**解法**：

+ 用 `curl -X POST [Base URL]/chat/completions -H "Authorization: Bearer [Key]" -H "Content-Type: application/json" -d '{"model":"[模型名]","messages":[{"role":"user","content":"hi"}]}'` 直接测试模型 API 是否可达

+ 如果 `curl` 也不通，检查网络环境（是否需要代理、是否有防火墙）

+ 如果 `curl` 通但项目不通，检查项目的代理配置

### 一句话总结

> **最**小验证 = 一条真实问答 + 确认非缓存 + 检查后端日志。三步做完，60 秒，但能帮你避免"以为可用实则不可用"的尴尬。
