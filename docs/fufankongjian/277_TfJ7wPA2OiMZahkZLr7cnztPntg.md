## 这份设计包是什么

这是一套在真实项目里跑出来的企业级多模态 RAG 后端架构。不是教程用的简化 Demo——它在一个生产级 RAG 系统里实际验证过：40 个知识图谱节点、39 个关联关系、20 + 个 API 端点全部跑通。

你拿到这份包，可以直接按自己的业务替换其中的技术选型或模块，不用从零开始设计。

## 推荐使用顺序

```
01 技术选型清单
    ↓ 明确技术栈之后
02 Bridge-Pipeline 规范
    ↓ 数据接入链路定下来之后
03 Agentic RAG 规范
    ↓ Agent 链路跑通 MVP 之后
04 后端系统架构
    ↓ 四层架构落地之后
05 API 接口规范
    ↓ 接口文档给到前端
06 Plan 模式提示词（随时查用）
```

如果你的项目已经到了某个阶段，可以直接跳到对应文档——每份文档都是独立可读的，不强依赖前一份。

## 怎么替换成自己的技术栈

这套架构基于以下核心假设：

+   数据类型：PDF + 图片 + 纯文本（如果你只有文本，02 和 03 可以大幅简化）

+   后端语言：Python（FastAPI）

+   存储层：轻量验证用纯文件系统 JSON，生产环境替换为 PostgreSQL + Qdrant / Milvus

+   Agent 框架：LangChain 1.0+

**常见替换场景**：

| 替换点 | 替换方向 | 影响范围 |
| --- | --- | --- |
| Qdrant → Milvus | 修改 02 存储配置段 + 05 对应接口 | 低 |
| networkX → Neo4j | 修改 03 图存储段 + 04 存储层说明 | 中 |
| LangChain → LlamaIndex | 修改 03 全文 | 高 |
| 纯文本 → 去掉图片支持 | 02 删除图片分支 + 01 去掉图像 Embedding | 低 |
| JSON 存储 → PostgreSQL | 修改 04 存储层 + 05 状态查询相关接口 | 中 |

## 不适合做什么

+   不是前端方案：前端 PRD 和页面设计不在本包内

+   不是可以直接运行的代码：这是架构规范文档，需要配合实际代码库使用

+   不是通用 RAG 教程：面向有 RAG 开发经验但需要工程化升级的开发者
