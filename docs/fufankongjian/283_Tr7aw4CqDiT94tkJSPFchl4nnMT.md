## 什么是 Plan 模式

Plan 模式是 Claude Code 的特殊工作模式：在这个模式下，Claude 先给出完整的执行计划（步骤分解、文件改动范围、潜在风险），等你确认后才开始实际执行。

**什么时候切换到 Plan 模式**：

+   要做系统级设计（不是改一个文件，而是要新建多个模块）

+   要生成规范文档（先规划文档结构，确认后再写）

+   第一次接入某个外部框架（先分析怎么接，确认方案后再动代码）

+   感觉 AI 可能会乱改文件的时候

**什么时候不需要 Plan 模式**：

+   修复单个函数的 Bug

+   改一个配置值

+   加一个简单的 API 路由

## 一、驱动 Plan 模式设计后端系统架构

这是本期视频里用来让 Claude Code 输出《后端系统架构-v1.0.md》的核心提示词。

```
现在我已经构建了完整的后端 MVP 流程，我需要你帮我开始设计
多模态 RAG 问答系统的后端服务架构。

背景信息：
- 已完成的 MVP 脚本：@src/pipeline/bridge_pipeline.py @src/agent/rag_agent.py
- 现有规范文档：@docs/02-Bridge-Pipeline规范-v1.0.md @docs/03-AgenticRAG规范-v1.0.md

任务：设计一套可工程化的后端服务架构，输出《后端系统架构-v1.0.md》

要求：
1. 采用四层架构：接入层（API）/ 服务层 / 执行层 / 存储层
2. 接入层用 FastAPI，存储层 MVP 阶段用纯文件系统 JSON
3. 此次只输出规范文档，不写代码
4. 文档包含：架构图（ASCII）、各层职责说明、目录结构、核心数据模型、配置说明

请先用 Plan 模式给出文档结构方案，等我确认后再开始写。
```

**关键要点**：

+   @文件名 语法把现有代码和规范文档引入上下文

+   明确说"此次只输出规范文档，不写代码"，防止 AI 直接开始写代码

+   最后一句"先给出方案等我确认"触发 Plan 模式行为

## 二、驱动 Plan 模式设计 API 接口规范

```
基于以下架构文档，设计完整的 API 接口规范：

参考文档：
@docs/04-后端系统架构-v1.0.md
@docs/03-AgenticRAG规范-v1.0.md

任务：输出《API接口规范-v1.0.md》

要求：
1. 覆盖四组接口：文档管理 / 任务管理 / 图谱管理 / QA 问答
2. 每个接口包含：请求方法、路径、参数说明（表格）、请求体示例、响应示例
3. 统一返回格式 { code, message, data, request_id }
4. 错误码定义表
5. 不生成代码，只输出 Markdown 规范文档

先给出接口列表（汇总表），等我确认接口数量和分组后再展开每个接口的详细说明。
```

**关键要点**：

+   "先给出接口列表……等我确认……再展开"——两阶段确认，避免写了 20 个接口你只要 10 个

+   引用已有架构文档，让 AI 基于已有设计推导接口，而不是凭空发明

## 三、驱动 Plan 模式接入 LangChain Agent

```
我需要接入 LangChain Agent 来构建 Agentic RAG 链路。

当前状态：
- 已有的检索函数：@src/search/vector_search.py @src/search/graph_search.py
- 已有的规范文档：@docs/03-AgenticRAG规范-v1.0.md
- LangChain 版本：1.0+（通过 MCP 连接了官方文档）

任务：将现有检索函数封装为 LangChain Tool，初始化 Agent，接入 DeepSeek-V3

要求：
1. 用 @tool 装饰器封装检索函数
2. 用 ChatOpenAI 适配 DeepSeek API（base_url + model 参数）
3. 新增 core/agent/ 目录，不改动现有 search/ 目录
4. 生成 4 个测试用例验证 Agent 可以正常调用工具

请先列出需要新建 / 修改的文件清单，等我确认后再开始写代码。
```

**关键要点**：

+   "不改动现有 search/ 目录"——明确保护范围，防止 AI 重构不该动的代码

+   测试用例要求和实现绑定，不验证就不算完成

## 四、驱动 AI 生成规范文档（MVP 跑通后）

MVP 跑通后立刻让 AI 沉淀规范文档。不要等到"有空了再整理"——有空不会来的。

```
刚才跑通的 Agentic RAG MVP，请帮我基于实际代码生成规范文档。

代码位置：
@src/agent/agent_runner.py
@src/agent/tools/vector_search.py
@src/agent/tools/graph_search.py
@src/agent/prompts.py

任务：生成《AgenticRAG规范-v1.0.md》

要求：
1. 内容基于实际代码，不要写&quot;示例代码&quot;——写实际跑通的配置和参数
2. 包含：架构说明、Tool 规范（函数签名 + 参数说明 + 返回格式）、Agent 推理链路示例（用刚才测试的那个问题）、性能基准（实测数据）
3. 用&quot;文档驱动 AI 协作&quot;的格式：结构化、字段明确、下一个会话直接引用

先给出文档结构（章节标题 + 每章一句话说明），等我确认后再写正文。
```

**关键要点**：

+   "基于实际代码，不要写示例代码"——规范文档要反映真实状态，不是理想状态

+   "用刚才测试的那个问题"——具体化，避免 AI 自己编一个

## 五、纠偏提示词（AI 跑偏时用）

当 AI 开始写你没要求的代码时：

```
停。你刚才开始修改 {文件名}，但我没有要求你改这个文件。
现在只做 {具体任务}，其他文件不动。
```

当 AI 写的规范文档和实际代码对不上时：

```
这份文档里 {具体内容} 和 @{实际文件} 里的实现不一致。
以代码为准，重新对齐文档的 {具体章节}。
```

当 AI 在 Plan 模式下直接开始执行而没给你确认机会时：

```
我说的是先给计划等我确认。现在只需要列出执行步骤，不要开始执行。
```

## 六、Plan 模式使用原则

1.  **先约束后授权**：提示词先说"不做什么"，再说"做什么"

1.  **两阶段确认**：复杂任务先给目录 / 清单，确认后再展开细节

1.  **引用锚定**：用 @文件名 把上下文钉死，不让 AI 凭记忆

1.  **边界明确**：哪些文件可以改、哪些不能动，每次都说清楚

1.  **验收标准随任务**：每个任务末尾加"完成标准是什么"，让 AI 知道什么叫做完
