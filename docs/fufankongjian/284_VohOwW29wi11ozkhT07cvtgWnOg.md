# 多模态 RAG 后端架构自查清单

> 适用场景：企业内部知识库 / 客服智能问答 / 技术文档检索 / 行业资料分析

> 使用时机：自己跑 RAG 后端架构设计之前，逐条对照

> 版本号：v1.0

> 更新日期：2026-04

> 来源：赋范大模型技术社区 · 多模态 RAG 项目实战课

---

## 使用方法

**开始架构设计前**，把这份清单过一遍。没打勾的项目不是"以后再说"——在架构阶段跳过，开发阶段会以 3 倍代价还回来。

---

## ✦ 模块一：技术选型

```
□ 是否明确了以下四个模块各自用什么框架？
  · 文档解析（PDF / 图片）
  · 知识图谱抽取和存储
  · 向量存储
  · Agent 编排框架

□ 每个选型依据是&quot;基于系统需求做的深度调研&quot;，
  而不是&quot;看到别人在用&quot;或&quot;上节课用过&quot;？

□ 是否预留了向量检索链路的接入位？
  （即使本期只先做 KG，向量检索的接口要先定好）

□ 是否明确了 MVP 阶段存储和生产阶段存储的替换路径？
  （MVP 用 JSON 文件，生产替换为 Qdrant / PostgreSQL——知道怎么换）

□ 调用外部框架（LangChain / LlamaIndex 等）之前，
  是否通过 MCP 或官方文档确认了当前版本的 API？
  （不凭记忆写，这类框架迭代快，用旧语法会悄悄报错）
```

---

## ✦ 模块二：架构设计

```
□ 是否明确了四层的职责边界？
  · 接入层：只做路由、参数校验、认证——不做业务逻辑
  · 服务层：只做业务编排——不直接操作存储
  · 执行层：只做计算/推理——不做参数校验
  · 存储层：只做数据读写——不做业务判断

□ 各模块的输入输出是否单独成文（规范文档）？
  （不混在主代码里，下次 AI 开新会话能直接引用）

□ 是否设计了统一的状态机来管理异步任务？
  （Pipeline 处理是异步的，不设计状态机，前端轮询没法做）

□ 是否定义了统一的 API 返回格式？
  { code, message, data, request_id }
  （不统一格式，前端每个接口写一套解析逻辑）

□ 是否定义了错误码表？
  （接口文档没有错误码，联调阶段前端不知道怎么处理异常）
```

---

## ✦ 模块三：规范文档

```
□ 每个 MVP 模块跑通之后，是否立刻沉淀了对应的规范文档？
  （不是&quot;等全部跑通再整理&quot;——越晚整理，遗漏的细节越多）

□ 规范文档是否写给 AI 看的（结构化、字段明确、可被引用）？
  （不是给人看的流水账，是 AI 新开会话时能直接读懂的结构化文档）

□ 后续模块开发时，是否直接 @引用规范文档？
  （不在每次对话里重复解释上下文，直接 @doc 文件）

□ 规范文档里的内容是否和实际代码一致？
  （&quot;理想设计&quot;和&quot;实际实现&quot;不一致是规范文档最常见的问题）

□ 是否有版本号和更新日期？
  （方便判断文档是否过时，多人协作时尤其重要）
```

---

## ✦ 模块四：AI 协作流程

```
□ 涉及系统级设计时，是否先切到 Plan 模式再执行？
  （系统级设计直接执行，AI 会自作主张改你没预期它改的文件）

□ 每次用 AI 写代码前，是否明确说了&quot;不能改哪些文件&quot;？
  （AI 默认会改它认为相关的文件，不说清楚边界就会乱改）

□ 对于复杂任务，是否要求 AI 先给出执行计划再确认？
  （&quot;先列清单等我确认再执行&quot;——两阶段确认，避免白做）

□ 每开一个新会话之前，是否确认了上下文？
  · @规范文档（让 AI 知道架构约束）
  · @相关代码（让 AI 知道现有实现）
  · 这次任务的边界（让 AI 知道做什么、不做什么）

□ 用 AI 生成的代码，是否做了本地运行验证？
  （测试跑通才算完成，不是&quot;生成完了就对&quot;）
```

---

## ✦ 模块五：联调前检查

```
□ API 接口文档是否已给到前端团队？
  （接口文档先行，不要等后端代码写完了再给文档）

□ 每个接口是否有对应的 Mock 数据 / 示例响应？
  （前端可以并行开发，不用等后端接口跑通）

□ 状态码和错误码是否和前端约定好了？
  （前端需要知道 4001、5001 各代表什么，联调时才能正确处理）

□ 文档上传 → Pipeline 处理 → QA 问答 这条核心链路是否端到端跑通过？
  （联调阶段不是第一次测这条链路的时机）

□ 是否有一个简单的健康检查接口（GET /health）？
  （部署后第一件事验活，没有健康检查接口会很麻烦）
```

## 快速判断：你在哪一步

| 当前状态 | 下一步 |
| --- | --- |
| 还没选技术栈 | 先做技术调研，用 Deep Research 生成选型对比 |
| 选好了技术栈，没有规范文档 | 先生成技术选型清单（01 文档） |
| 规范文档有了，MVP 没跑通 | 先跑 Bridge Pipeline MVP，验证数据链路 |
| Pipeline 跑通了，Agent 没接 | 接 LangChain Agent，跑 Agentic RAG MVP |
| MVP 都跑通了，没有架构文档 | 用 Plan 模式生成后端系统架构（04 文档） |
| 架构设计好了，没有 API 文档 | 生成 API 接口规范（05 文档），给前端 |
| 所有文档都有了 | 开始后端代码实现，逐层按架构文档写 |
