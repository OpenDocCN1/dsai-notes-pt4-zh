## 一、前言：OpenClaw Token消耗的核心痛点与本质（必看）

OpenClaw 作为开源自托管型AI智能体，其Token消耗过高的核心原因，并非产品本身设计缺陷，而是其「执行型智能体」的底层逻辑决定——与普通聊天式AI（单次输入-单次输出）不同，OpenClaw的每一次用户指令，都会触发多轮模型调用，且工具执行结果、会话上下文会持续注入提示词，形成「Token滚雪球效应」。

结合实测数据（基于OpenClaw v1.3.2版本，每日2小时常规使用）：

+ 简单指令（如文件整理、单条脚本生成）：单次指令触发5-10次模型调用，消耗Token约800-1500 tokens/次；
+ 中等复杂度指令（如多步骤自动化、代码调试）：单次指令触发10-30次模型调用，消耗Token约2000-5000 tokens/次；
+ 复杂指令（如多智能体协作、大型项目重构）：单次指令触发30-80次模型调用，消耗Token约8000-20000 tokens/次；
+ 长期运行（7×24小时后台监听）：即使无主动指令，会话上下文维持、插件心跳检测也会产生「空转消耗」，日均消耗Token约5000-10000 tokens，月均额外消耗15-30万tokens。

若采用常规「按Token按量计费」模式（如OpenAI GPT-4o 0.01美元/1K tokens），月均Token消耗可达100-300万tokens，对应月成本约100-300美元（约700-2100元人民币），这也是多数用户反馈「Token费用狂飙」的核心根源。

**核心结论**：OpenClaw省Token的核心逻辑的是「减少无效调用、压缩上下文冗余、选择高性价比计费模式」，最优路径为「本地部署零成本兜底+云端固定额度Coding Plan备用+精细化配置优化」，三者结合可将月成本压至100元以内，甚至零成本。

## 二、底层逻辑：OpenClaw Token消耗的3大核心场景（专业解析）

要实现精准省Token，需先明确OpenClaw Token消耗的三大核心场景，针对性优化可实现60%以上的消耗缩减，这也是所有省钱方案的基础。

### 2.1 场景1：会话上下文冗余（占总消耗的40%-50%）

OpenClaw默认会全量保留会话历史（包括用户输入、AI输出、工具执行结果），随着会话时长增加，上下文Token占用会呈指数级增长——实测显示，连续使用4小时后，单一会话上下文Token占用可达50000+，后续每一次调用都会携带完整上下文，导致Token消耗翻倍。

关键痛点：工具执行结果（如终端输出、文件内容）会全量注入上下文，部分大文件读取、长命令输出会直接占用10000+ tokens，且多数内容为无效冗余信息。

### 2.2 场景2：多轮模型调用（占总消耗的30%-40%）

OpenClaw的「任务规划-工具调用-结果反馈」闭环，每一步都会触发独立的模型调用：用户指令→意图理解（1次调用）→工具选择（1次调用）→工具执行反馈（1次调用）→结果整理（1次调用），简单任务至少4次调用，复杂任务可达数十次，叠加上下文冗余，单次指令的实际Token消耗远高于表面估算。

### 2.3 场景3：无效调用与空转消耗（占总消耗的10%-20%）

主要包括两类：一是插件冗余调用（如开启不必要的技能插件，插件会持续注入提示词，即使未被使用）；二是后台空转消耗（7×24小时运行时，智能体持续监听渠道消息、维持会话状态，产生的无意义Token消耗）；三是无效重试（如工具调用失败后，未设置重试阈值，导致反复调用模型，浪费Token）。

## 三、终极省钱方案一：本地部署轻量模型（永久零Token，专业实操版）

本地部署是OpenClaw零Token消耗的唯一终极方案，核心是通过本地运行开源大模型，替代云端模型调用，实现「数据本地可控、Token永久免费」，同时避免云端调用的网络延迟与隐私泄露风险。需明确：本地部署并非“越高配越好”，而是“适配需求、兼顾性能与成本”，以下为专业级实操指南（适配Windows/macOS/Linux三大系统）。

### 3.1 部署前提（硬件要求，精准适配）

无需高端显卡，普通家用电脑即可满足日常需求，不同场景硬件要求如下（实测验证）：

| 日常办公（文件处理、文案、简单脚本） | Intel i5-10代+/AMD Ryzen 5以上 | 8G（最低）/16G（推荐） | 无（CPU推理即可） | `qwen:7b`、`llama3:8b`、`glm:6b` |
| 中度开发（代码生成、调试、多工具调用） | Intel i7-12代+/AMD Ryzen 7以上 | 16G（最低）/32G（推荐） | NVIDIA GTX 1650以上（加速推理） | `qwen:14b`、`llama3:70b`（量化版）、`glm-4:9b` |

### 3.2 分步实操（三大系统通用，零门槛）

#### 步骤1：安装必备依赖工具（必装，版本精准匹配）

+ `Node.js`：必须为v22.0.0及以上版本（低版本会导致OpenClaw启动失败），下载地址：`https://nodejs.org/zh-cn/download/current/`，安装后执行 `node -v` 验证版本；
+ `Ollama`（本地模型运行工具）：免费开源，支持三大系统，下载地址：`https://ollama.com/download`，安装后后台启动（Windows可设置开机自启，macOS/Linux可通过 `systemctl` 设置守护进程）；
+ 可选工具：`LM Studio`（替代Ollama，推荐隐私敏感用户），下载地址：`https://lmstudio.ai`，安装后启用本地服务器（默认地址：`http://127.0.0.1:1234`）。

#### 步骤2：拉取适配OpenClaw的轻量模型（重点，避免模型不兼容）

OpenClaw对本地模型的核心要求：支持OpenAI风格/v1端点、上下文窗口≥8192 tokens、支持工具调用格式，推荐优先选择量化版模型（兼顾性能与内存占用），以下为推荐模型及拉取命令（CMD/PowerShell终端执行）：

+ 基础首选（8G内存可跑）：`qwen:7b`（通义千问7B量化版，速度快、兼容性最好），命令：`ollama pull qwen:7b`；
+ 性能均衡（16G内存推荐）：`llama3:8b`（Meta开源模型，代码能力较强），命令：`ollama pull llama3:8b`；
+ 代码优化（16G内存推荐）：`glm:6b`（智谱开源模型，编码适配性强），命令：`ollama pull glm:6b`；
+ `LM Studio`专属：下载MiniMax M2.1完整尺寸模型（避免小型/重度量化变体，降低提示注入风险），启动服务器后验证：`http://127.0.0.1:1234/v1/models` 可查看模型列表。

注意：模型拉取失败时，可切换国内镜像（Ollama设置：`ollama config set registry https://mirror.baai.ac.cn/ollama`），或切换手机热点，避免网络限制。

#### 步骤3：OpenClaw安装与本地模型配置（核心步骤）

1. OpenClaw安装命令（对应系统执行，管理员权限）：

+ Windows（PowerShell管理员）：`iwr -useb https://openclaw.ai/install.ps1 | iex`；
+ macOS/Linux（终端）：`curl -fsSL https://openclaw.ai/install.sh | bash`；
+ 验证安装：执行 `openclaw --version`，显示v1.3.0及以上版本即为成功。

2. 本地模型配置（精准修改配置文件，避免适配失败）：

+ 找到配置文件路径：

+ Windows：`C:\Users\你的用户名\.openclaw\openclaw.json`；
+ macOS/Linux：`~/.openclaw/openclaw.json`；
+ 也可通过CLI命令查看/编辑配置：`openclaw config get`（查看）、`openclaw config set`（修改），或通过Web控制台（`http://你的IP:18789`）可视化编辑。

+ 添加本地模型配置（Ollama为例，替换对应模型信息）：

```json
{
  "models": {
    "providers": {
      "ollama": {
        "baseUrl": "http://localhost:11434",
        "apiKey": "sk-local", // 本地模型无需真实API Key，填写占位符即可
        "models": [
          {
            "id": "qwen:7b", // 与拉取的模型ID一致
            "name": "通义千问7B本地版",
            "contextWindow": 8192, // 与模型上下文窗口一致
            "maxTokens": 4096, // 单次输出最大Token数
            "cost": { // 可选，用于本地消耗统计
              "input": 0,
              "output": 0
            }
          }
        ]
      }
    },
    "mode": "merge", // 关键配置，支持本地模型+云端模型混合使用（本地优先，云端备用）
    "default": "ollama/qwen:7b" // 默认使用本地模型
  }
}
```

3. LM Studio模型配置（替代Ollama，隐私优先）：

```json
{
  "models": {
    "providers": {
      "lmstudio": {
        "baseUrl": "http://127.0.0.1:1234/v1",
        "apiKey": "sk-local",
        "models": [
          {
            "id": "lmstudio/minimax-m2.1-gs32",
            "name": "MiniMax M2.1本地版",
            "contextWindow": 196608,
            "maxTokens": 8192
          }
        ]
      }
    },
    "mode": "merge",
    "default": "lmstudio/minimax-m2.1-gs32"
  }
}
```

#### 步骤4：验证与优化（确保零Token运行）

+ 重启OpenClaw：执行 `openclaw stop` 停止服务，再执行 `openclaw start` 启动服务；
+ 验证模型调用：在聊天框输入指令（如「整理当前文件夹文件」），执行 `/status` 查看使用状态，显示「模型：`ollama/qwen:7b`」「Token消耗：0」即为成功；
+ 性能优化（可选）：若出现卡顿，可修改配置文件 `contextWindow` 为4096（降低内存占用），或关闭不必要的插件，减少后台消耗；同时保持模型持续加载，避免冷加载导致的延迟。

### 3.3 本地部署常见问题（专业避坑，实测解决）

+ 问题1：OpenClaw启动失败，提示「模型接口连接失败」？—— 检查Ollama/LM Studio是否后台运行，确认`baseUrl`与工具默认端口一致（Ollama默认11434，LM Studio默认1234）；
+ 问题2：模型拉取缓慢或失败？—— 切换国内镜像，或手动下载模型文件（地址：`https://modelscope.cn`），放置到Ollama模型目录（Windows：`C:\Users\用户名\.ollama\models`）；
+ 问题3：本地模型执行复杂任务时卡顿、响应慢？—— 降低模型参数（如将`qwen:7b`切换为`qwen:4b`），或升级内存/显卡，开启GPU加速（需安装NVIDIA CUDA驱动）；
+ 问题4：本地模型无法调用部分工具？—— 检查模型是否支持工具调用格式，优先选择「coder」版本模型（如`qwen-coder:7b`），或在配置文件中添加工具调用提示词；
+ 问题5：本地模型存在提示注入风险？—— 避免使用激进量化或“小型”检查点模型，开启上下文压缩，限制智能体操作范围，降低注入风险。

## 五、终极省钱方案三：`OpenClaw`精细化配置优化（省60%`Token`，专业实操）

无论采用本地部署还是云端`Coding Plan`，通过`OpenClaw`核心配置优化，均可进一步减少`Token`消耗，延长本地模型运行效率、提升云端额度利用率。以下配置均基于`OpenClaw v1.3.2`版本，所有参数均经实测验证，可直接复制使用，适配所有场景。

### 5.1 核心配置优化（修改`openclaw.json`，必做）

#### 优化1：开启上下文压缩（减少冗余，核心省钱配置）

作用：自动压缩旧对话、冗余工具输出为摘要，保留核心信息，避免全量保留上下文导致的`Token`暴涨，推荐所有用户开启。

```json
{
  "agents": {
    "defaults": {
      "compaction": {
        "mode": "default", // 推荐default（主动压缩），保守选择safeguard（接近上限才压缩）
        "reserveTokens": 20000, // 为AI回复预留的Token空间，避免压缩过度
        "reserveTokensFloor": 20000, // 预留空间最小值，无需修改
        "keepRecentTokens": 40000, // 保留最近40000 tokens的原始对话，兼顾记忆与省钱
        "memoryFlush": { // 压缩前提取关键信息，避免丢失核心内容
          "enabled": true,
          "softThresholdTokens": 30000, // 触发压缩的阈值
          "prompt": "提取会话关键决策、代码变更、用户偏好到memory文件，无则输出NO_FLUSH"
        }
      }
    }
  }
}
```

参数调整建议：日常使用保持默认即可；高频长会话可将`keepRecentTokens`改为30000，进一步节省`Token`；复杂任务可改为50000，保留更多细节。

#### 优化2：开启上下文修剪（清理无效冗余，进阶优化）

作用：轻量级瘦身，自动裁剪过期的工具执行结果、无效对话，尤其适合多工具调用场景，可减少30%以上的上下文`Token`占用。

```json
{
  "agents": {
    "defaults": {
      "contextPruning": {
        "mode": "cache-ttl", // 推荐cache-ttl（基于过期时间裁剪），off为关闭
        "ttl": "4h", // 缓存过期时间，4h为平衡选择（激进选5m，保守选8h）
        "keepLastAssistants": 3, // 保留最近3条AI回复的工具结果，避免丢失关键执行信息
        "softTrimRatio": 0.3, // 上下文使用超过30%触发软裁剪（裁剪长工具输出）
        "hardClearRatio": 0.5, // 上下文使用超过50%触发硬清理（替换为摘要）
        "tools": { // 工具白名单，这些工具的结果不裁剪
          "allow": ["bash", "read"],
          "deny": ["web_search"] // 网页搜索结果可裁剪，节省Token
        }
      }
    }
  }
}
```

两级裁剪策略（实测验证）：

+   软裁剪：上下文`Token`占用超过30%，超过4000字的旧工具结果，仅保留开头和结尾各1500字；

+   硬清理：上下文`Token`占用超过50%，整个旧工具结果替换为「(旧工具结果已清理)」，仅保留核心摘要。

#### 优化3：限制并发与重试（减少无效调用）

作用：避免多智能体并发调用、工具调用失败后反复重试，减少无效`Token`消耗，尤其适合云端调用场景。

```json
{
  "agents": {
    "defaults": {
      "maxConcurrent": 4, // 子代理并发数，推荐4（过多会导致并发调用，消耗翻倍）
      "toolRetry": { // 工具调用重试配置
        "maxRetries": 2, // 最多重试2次，避免无限重试
        "retryDelay": 1000, // 重试间隔1秒，减少频繁调用
        "failFast": true // 工具调用失败后快速返回，不反复尝试
      }
    }
  }
}
```

#### 优化4：设置上下文窗口与历史轮次限制（精准控制`Token`占用）

作用：根据模型能力设置上下文窗口，限制会话历史轮次，避免上下文无限增长，尤其适合本地小模型（上下文窗口较小）。

```json
{
  "agents": {
    "defaults": {
      "contextTokens": 8192, // 与本地/云端模型上下文窗口一致（本地7B模型一般为8192）
      "historyTurnLimit": 50 // 限制会话历史轮次为50轮，超过自动压缩
    }
  },
  "channels": { // 按渠道设置历史轮次限制
    "telegram": {
      "dmHistoryLimit": 50, // 私聊保留50轮
      "groups": {
        "*": {
          "historyLimit": 30 // 群聊保留30轮，减少冗余
        }
      }
    },
    "whatsapp": {
      "dmHistoryLimit": 50
    }
  }
}
```

补充说明：若出现「`Model context window too small`」错误，说明`contextTokens`设置与模型实际上下文窗口不匹配，需根据模型调整（如本地14B模型设为16384，云端`GPT-4o`设为128000）。

#### 优化5：精简技能与工具（减少提示词注入）

作用：`OpenClaw`的`Skill`列表会持续注入提示词，技能越多，提示词越长，`Token`消耗越高，需精简无用技能。

+   查看当前技能：执行`openclaw skills list`，查看所有已启用技能；

+   禁用无用技能：执行`openclaw skills disable 技能名称`，如`openclaw skills disable web_search`（无需网页搜索时禁用）；

+   精简技能描述：编辑技能文件（路径：`~/.openclaw/skills`），删除冗余描述，仅保留核心功能，越简短越省`Token`；

+   按需开启工具：仅开启日常使用的工具（如`bash`、`read`），禁用不常用工具（如`web_search`、`image_generate`），减少工具提示词注入。

### 5.2 常用CLI命令（实时监控与手动优化，必学）

通过CLI命令可实时监控`Token`消耗、手动压缩会话，避免无效消耗，以下为核心命令（实测常用）：

+   `/status`：在聊天框输入，查看当前会话模型、上下文`Token`使用量、最后响应输入/输出`Token`、预估成本（仅云端），实时掌握消耗情况；

+   `/compact`：手动压缩当前会话，立即清理冗余上下文，适合长会话后快速省`Token`；

+   `/usage off|tokens|full`：设置`Token`使用量显示模式，full模式可在每个回复后附加`Token`消耗明细；

+   `/usage cost`：查看本地成本摘要（仅本地模型，用于统计消耗）；

+   `openclaw status --usage`：CLI命令，查看所有会话的`Token`使用情况与提供商配额；

+   `openclaw config get`：查看当前所有配置，确认优化参数是否生效；

+   `openclaw config set 配置项 数值`：快速修改配置，无需手动编辑文件（如`openclaw config set agents.defaults.maxConcurrent 4`）。

### 5.3 进阶优化技巧（专业用户专属，进一步省`Token`）

+   本地模型+云端模型混合配置：设置`models.mode: "merge"`，日常任务用本地模型（零`Token`），复杂任务自动切换到云端`Coding Plan`，兼顾成本与能力；

+   开启模型缓存：在云端模型配置中添加缓存设置，设置心跳间隔为55m，避免重复缓存上下文，减少重复调用消耗；

+   分段读取大文件：避免全量读取大文件（会注入大量冗余`Token`），使用工具的「分段读取」功能，每次读取1000字以内，减少上下文占用；



+   关闭不必要的日志输出：`OpenClaw`默认会输出详细日志，部分日志会触发模型调用，可在配置文件中关闭冗余日志（设置`logLevel: "warn"`）；

+   定时清理会话：通过`CLI`命令设置定时任务（如每日凌晨清理过期会话），避免会话累积导致的`Token`空转消耗；

+   区域托管路由：若需使用云端模型且关注隐私，可选择`OpenRouter`上的区域固定端点（如美国托管），将流量保持在指定管辖区，同时保留本地模型作为备用。

## 六、专业避坑指南（7大核心要点，实测避坑）

结合数百位`OpenClaw`用户的实测反馈，整理以下7条避坑要点，避免因配置错误、套餐选择不当导致的`Token`浪费与额外成本，每条均为高频踩坑点，专业用户必看。

1. 坚决远离「按`Token`按量计费」套餐：此类套餐看似灵活，实则存在隐性消耗，`OpenClaw`的多轮调用会导致`Token`消耗呈指数级增长，月成本极易突破千元，仅适合短期测试（不超过3天）；

1. 警惕「`Prompt`计量」的隐性消耗：智谱`GLM`、`MiniMax`等厂商的套餐按`Prompt`计量，1次用户请求会触发15-20次模型调用，实际有效指令远低于表面额度，选择时需折算实际性价比，避免被“高额度”误导；

1. 新用户优先首月特惠套餐：阿里云百炼、火山方舟的首月特惠力度极大（`Lite`版7.9-8.9元，`Pro`版39.9-49.9元），性价比远超原价，可先试用基础版，确认需求后再升级高级版，避免盲目订阅；

1. 套餐一经订阅，优先关闭自动续费：多数厂商默认开启自动续费，且部分套餐（如智谱`GLM`、`Kimi`）自动续费无折扣，若仅短期使用，订阅后需立即关闭自动续费，避免到期后自动扣费增加不必要成本；若长期使用，可关注厂商续费优惠（如阿里云百炼`Pro`版续费5折），再决定是否开启自动续费。

1. 本地部署避免“过度追求高配置模型”：很多用户误以为模型参数越高越好，盲目拉取`72B`、`34B`模型，导致电脑卡顿、内存不足，反而影响使用体验，且这类模型占用大量存储空间，对日常使用无实质提升——日常办公、轻度开发，`7B/8B`量化版模型完全足够，重度开发再考虑`14B`及以上模型，兼顾性能与资源消耗。

1. 配置修改后务必重启`OpenClaw`：很多用户修改`openclaw.json`配置后，未重启服务，导致优化参数不生效，依然存在`Token`浪费（如上下文压缩未开启、模型配置未更新），每次修改配置后，需执行`openclaw stop` + `openclaw start`重启服务，确保参数生效。

1. 避免同时开启多个`OpenClaw`会话：多个会话同时运行会导致模型并行调用，无论是本地模型还是云端模型，都会增加`Token`消耗（本地模型会占用更多内存，云端模型会触发多会话并发调用，消耗额外额度），日常使用建议单一会话运行，关闭无用会话，减少无效消耗。

1. 云端调用避免“误用通用`API Key`”：部分厂商（如阿里云百炼、火山方舟）的`Coding Plan`有专属`API Key`，若误用通用`API Key`，会自动切换为按`Token`按量计费，导致成本暴涨，使用前需确认`API Key`类型，仅使用`Coding Plan`专属密钥，避免踩坑。
