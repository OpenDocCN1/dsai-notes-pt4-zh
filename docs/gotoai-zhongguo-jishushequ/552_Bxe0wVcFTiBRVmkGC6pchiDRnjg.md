
# OpenClaw进化历史

## 第一部分：OpenClaw 核心认知与进化历史

### 1.1 OpenClaw 核心定位与技术架构

+ 核心定义：OpenClaw 是一款开源自托管式AI智能体框架，基于Node.js开发，采用“网关-技能-多模型”三层架构，核心目标是实现“大模型能力与系统级操作的深度融合”，支持本地部署、数据私有化与多场景集成。

+ 核心架构拆解（三层架构）：

+ Gateway层（核心中枢）：负责请求路由、权限管控、技能调度、模型适配，采用微服务架构，支持水平扩展，核心组件包括`Agent Loop`、`Session Manager`、`Permission Controller`。

+ Skill层（功能扩展）：基于标准化接口（`SKILL.md`规范）开发，支持命令行调用、API集成、第三方工具对接，分为官方认证技能与社区贡献技能，采用插件化设计，支持热更新。

+ Model层（能力支撑）：支持多模型适配（OpenAI GPT系列、Claude Opus、Gemini、DeepSeek、智谱等），采用统一的模型调用接口，支持模型切换、`Token`限流与缓存优化。

+ 核心技术栈：Node.js（运行环境）、TypeScript（开发语言）、Express（Web服务）、Docker（容器化部署）、Redis（缓存）、WebSocket（实时通信）、JWT（权限认证）。

### 1.2 OpenClaw 进化历史与技术迭代逻辑（专业视角）

核心逻辑：从“单场景脚本工具”到“企业级智能体框架”，迭代核心围绕「架构标准化、功能模块化、安全体系化、生态规模化」四大方向，以下结合时间轴拆解技术演进细节：

#### 1.2.1 萌芽期（2025.11–2025.12）：原型验证与核心功能落地

+ 2025.11.24（WhatsApp Relay）：初代原型，基于Node.js编写的简单脚本，核心实现WhatsApp与Claude的消息中继，采用单线程架构，无模块化设计，仅支持基础文本交互，本质是“消息转发工具”，未具备智能体核心能力。

+ 2025.11月底（Clawdbot）：首次迭代，新增图片处理、本地文件读写能力，引入`/think`（思考步骤日志）、`/verbose`（详细输出）指令，初步实现“指令解析-任务执行”的闭环，核心技术突破是引入文件系统API与多模型切换逻辑（支持Claude、Kimik2.5），GitHub开源后快速积累开发者社区。

+ 2025.12中旬（多任务突破）：架构升级为“单进程多线程”，支持命令行工具调用（`child_process`模块）、独立会话状态管理（`Session`存储），实现多步骤任务串联，核心技术亮点是引入任务调度逻辑，为后续`Agent Loop`奠定基础，此时项目已具备智能体的核心雏形，但缺乏安全管控与标准化接口。

#### 1.2.2 更名期（2026.01）：品牌合规与架构初步标准化

+ 2026.01.26（商标危机）：因“Clawdbot”与Anthropic“Claude”存在商标近似风险，被迫紧急更名，同步暴露项目初期缺乏合规性设计（商标检索、安全审计缺失），后续迭代中新增“合规性检查模块”。

+ 2026.01.27（Moltbot）：临时过渡版本，核心优化是代码结构重构，将消息处理、模型调用、文件操作拆分为独立模块，为后续插件化架构铺垫，同时修复初代版本的内存泄漏问题，优化会话管理效率。

+ 2026.01.30（OpenClaw 正式定名）：品牌定型，同步完成架构标准化，明确“Gateway-技能-Model”三层架构，定义`Skill`开发的标准化接口（`SKILL.md` v1.0），拿下商标与域名，引入开源协议（MIT协议），完成代码合规性梳理，此时项目从“个人工具”升级为“开源框架”，具备规模化发展的基础。

#### 1.2.3 爆发期（2026.02–至今）：安全加固、功能迭代与生态完善

+ 2026.01.31–2026.02.01（ClawHavoc供应链攻击）：恶意开发者利用ClawHub技能审核漏洞，上传恶意`Skill`窃取用户数据，暴露项目安全管控缺失，后续紧急迭代安全机制：新增`Skill`签名认证、沙盒隔离（`Sandbox`模式）、权限分级管控，引入动态安全审计模块，修复供应链攻击漏洞。

+ 2026.02 版本密集迭代（安全与功能双升级）：

+ v2026.2.13：修复浏览器下载路径漏洞（CVE-2026-26972），优化文件路径校验逻辑，防止路径遍历攻击；

+ v2026.2.15：修复工作目录`Prompt`注入漏洞（CVE-2026-27001），引入`Prompt`过滤机制，强化输入校验；

+ v2026.2.22：修复40+安全漏洞（含XSS、CSRF、RCE潜在漏洞），强化`Sandbox`隔离机制，限制`Skill`的系统权限；

+ v2026.2.23：适配Claude Opus 4.6 API，新增HTTP安全头（`CSP`、`X-XSS-Protection`等），优化模型调用的异常处理逻辑；

+ v2026.2.27：集成xAI Grok网络搜索API，优化Web UI的前后端交互（采用React重构前端），支持批量技能管理。

+ 2026.02.15（创始人移交项目）：Peter Steinberger加入OpenAI，项目移交独立开源基金会，核心技术决策由社区委员会主导，同步制定《OpenClaw技术 roadmap》，明确“企业级适配、多场景集成、安全合规”三大迭代方向。

+ 2026.03 稳定版发布（v2026.3.8）：核心优化包括：修复RCE高危漏洞、引入动态权限审计、实现上下文插件化（支持记忆模块自由插拔）、优化容器化部署方案，新增企业级配置（多团队协作、权限分级、日志审计），此时架构已完全满足企业级部署需求，GitHub星标突破28万，成为开源AI智能体领域的标杆项目。

+ 2026.03至今（生态完善）：ClawHub技能市场实现标准化审核与分发，支持`Skill`收费与商业化，新增企业级部署工具（支持K8s集群部署），适配国内云厂商（阿里云、腾讯云、京东云）的一键部署服务，同时推出OpenClaw SDK，支持二次开发与第三方系统集成。

#### 1.2.4 技术迭代核心总结（专业重点）

+ 架构演进：单线程脚本 → 单进程多线程 → 三层微服务架构，核心是“模块化、标准化、可扩展”；

+ 核心突破：从“消息中继”到“任务执行”，从“无安全管控”到“全链路安全防护”，从“个人使用”到“企业级落地”；

+ 关键技术：`Agent Loop`任务调度、`Skill`标准化接口、沙盒隔离、多模型统一适配、动态权限审计。
