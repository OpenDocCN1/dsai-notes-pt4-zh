## 方案概述

这次要介绍的内容是使用飞书多维表格，实现视频文案采集、与主题仿写，一般就到这里了。

今天我们将前几天分享的视频工作流的方案与其进行结合，真正实现批量化生成视频。

+ 工作流1：读取视频链接采集视频文案，记录至多维表格，同时借助字段捷径，使用AI进行二次创作生成新的标题和文案。
+ 工作流2：视频工作流发布到多维表格，作为字段捷径使用。进一步打通多维表格与视频工作流的联动。

所以核心还是借助多维表格的批量化能力，来提效。

```
async def main(args: Args) -&gt; Output:
    params = args.params
    title = params[&#x27;title&#x27;]
    content = params[&#x27;content&#x27;]
    url = params[&#x27;url&#x27;]
    video_url = params[&#x27;video_url&#x27;]
    #下面增加了超链接，作为演示特殊字段的格式定义
    #懂开发的可参考飞书表格开发文档https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/bitable-v1/app-table-record/bitable-record-data-structure-overview
    records = [{&quot;fields&quot;:{
        &quot;视频链接&quot;: url,
        &quot;标题&quot;: title,
        &quot;内容&quot;: content,
        &quot;下载地址&quot;: video_url,
    }}]
    # 构建输出对象
    ret: Output = {
        &quot;records&quot;: records
    }
    return ret
```

下面是多维表格的模板，可以参考下，主要提取标题和文案，之后利用字段捷径AI能力，进一步改写优化标题，二创文案。

## 工作流2：视频工作流与Coze Bot串联

接下来是如何串联视频工作流。说下思路，目前coze的bot支持发布到飞书多维表格，我们将工作流包装到Bot中，发布成多维表格的字段捷径来使用。

视频工作流部分就不再赘述了，可以翻看之前的两篇文章。

这里展示下发布多维表格的流程细节，只开放了四个参数，方便演示。

如果自用的话很多参数固定在工作流即可。

![](img/f99950fec79d82a6e41e92008851e5e0.png)

提示词部分参考了waytoagi社区的一位小伙伴的案例。

```
## 技能
用户会输入以下4个变量内容，接收后直接传入并调用 xxx。变量内容分别为：
1、创意：{{title}}，必填项。
2、左侧标题：{{left_text}}，默认值：认知觉醒·引爆人生。
3、右侧标题：{{right_txt}}，默认值：个人观点·仅供参考 。
4、文案内容：{{content}}。

## 限制:
- 严格按照调用工作流执行，将工作流的返回结果作为唯一回复，不做任何其它回复。
```

配置好之后，点击发布。

选择飞书多维表格，一开始需要进行授权，按照提示来填写即可。

![](img/c61154885b5c6044bad8f90335ec77c8.png)

我们默认获取工作流返回的视频地址，所以输出数据类型选择文本。

字段就不多说了，是我们工作流所需的输入，对应起来即可。

第三个是上架信息，用来审核使用，按实际填写即可。

![](img/92bfafb048deccd921e285132f1d9e63.png)

配置完成后，点击发布，等待审核通过。

审核通过后，回到我们的多维表格当中，我再次点击新增字段“视频制作自动化”。

点击字段捷径，搜索“视频制作自动化”，名字与你发布的bot对应。

我们可以看到参数信息，包括标题、文案等，与第一环节采集的素材字段对应上。

![](img/8a1d2eaebba52273cbbb5609026be37d.png)

自动更新部分，你可以选择手动，因为所有采集的素材，还是需要人工审核一遍为好。以免最终出来的视频有瑕疵，还得返工，比较费💰。

我这里做了两个字段捷径，分别生成云端渲染的版本和剪映草稿的版本，是不是很方便了。
