## 论文解读

### 2.1 Coconut 研究背景

语言模型（LLMs）通常在语言空间中进行推理，即通过生成自然语言的推理链条（Chain of Thought, CoT）来完成复杂任务。然而，这种方法存在以下问题：

+ 大部分生成的内容仅用于文本连贯性，与实际推理无关。

+ 某些关键 Toekn 需要复杂规划，现有模型难以处理。

+ 语言推理效率低下，尤其是在需要回溯或多路径探索的任务中表现不佳（如复杂逻辑任务）

Coconut 的核心思想是让 AI 的思考过程不必要转换成人类语言，让思考在潜空间进行。在形式上，改作者提出的方法是在模型推理时去掉模型头尾的 LLM head 和 embedding 层，使用中间状态进行自回归，只在输出最终答案时才转成人类语言。这样的方式能够减少 Token 消耗，同时提升推理效率和质量。

### 2.2 CoT 与连续思维链（Coconut）的对比

#### COT（思维链）

**工作机制**：

1. 模型在推理过程中生成一系列 `xi+1`、`xi+2` 等语言标记（tokens），每一步的输出作为下一步的输入。

2. 每个生成的标记都需要通过语言解码（从隐藏状态映射到语言 token）。

3. 这种方式以自然语言的形式表达推理链条（如逐步生成推理步骤）。

**优点**：

1. 推理过程透明，可以直接生成易于理解的语言输出。

**缺点**：

1. 每一步都需要解码为语言标记，增加计算复杂度。

2. 语言标记可能包含不必要的信息，限制了推理效率。

3. 模型无法同时探索多个潜在路径（只能逐步推进）。

![](img/c545d2915f0688ec1a67ebacf2b0229a.png)

#### Coconut（连续思维链）

**工作机制**：

1. 模型在推理过程中直接使用隐藏状态（last hidden state）作为下一步的输入，而不生成语言标记。

2. 推理发生在潜在空间（latent space）中，直到推理结束时才输出最终的答案。

3. 特殊标记 `<bot>` 和 `<eot>` 用来标记潜在推理的开始和结束。

**优点**：

1. 省去了语言解码步骤，减少了推理时生成的 token 数量。

2. 允许模型同时探索多个潜在路径（类似广度优先搜索，BFS），避免过早做出决定。

3. 潜在空间中的推理可以编码多种可能性，逐步排除错误路径。

**缺点**：推理过程不可直接观察，需要额外手段解读隐藏状态。

### 2.3 训练方法

![](img/cfb2224f5614357f148095e752c7d850.png)

研究人员利用了现有的语言思维链作为模型的训练数据，类似于 Chain of Thought（CoT）的格式，其中每个样本包含一个问题（Question）、推理步骤（Step 1, Step 2, ...）和最终答案（Answer）。

训练过程分为多个阶段（Stage 0, Stage 1, Stage 2, ...），每个阶段逐步引入更多的连续思考（`[Thought]`），并移除一个具体的推理步骤（`[Step]`）。

**Stage 0**

+ 输入：`[Question]` `<bot>` `<eot>` `[Step 1]` `[Step 2]` `[Step N]` `[Answer]`

+ 没有引入任何连续思考，直接用原始的推理步骤和答案训练模型。

**Stage 1**

+ 输入：`[Question]` `<bot>` `[Thought]` `<eot>` `[Step 2]` `[Step 3]` `[Step N]` `[Answer]`

+ 在原始序列中加入第一个连续思考 `[Thought]`，并移除第一个推理步骤 `[Step 1]`。

**Stage 2**

+ 输入：`[Question]` `<bot>` `[Thought]` `[Thought]` `<eot>` `[Step 3]` `[Step N]` `[Answer]`

+ 引入第二个连续思考 `[Thought]`，并移除第二个推理步骤 `[Step 2]`。

**Stage N**

+ 输入：`[Question]` `<bot>` `[Thought]` `[Thought]` ... `[Thought]` `<eot>` `[Answer]`

+ 最终阶段，所有推理步骤都被替换为连续思考 `[Thought]`，只保留答案部分用于计算损失。

CoCoNut 的训练目标是在语言推理任务中逐步引入 `[Thought]`，从而让模型获得 “连续思考”（Continuous Thought）的能力。其中分阶段的训练方式能够让模型能够逐步适应更复杂的推理任务，避免直接学习完整推理链条的困难，这种方法训练策略，让模型能够处理复杂的推理步骤。

### 2.4 实验结果

#### 测试对象

1. CoT：使用完整的推理链来训练语言模型，并进行监督微调，推理过程中，模型先生成推理过程再输出回答。

2. No-CoT：LLM 直接生成答案。

3. iCoT：使用语言推理链进行训练，并将 CoT 「内化」。训练过程中，推理链开头的 token 会逐渐被移除，最后只剩下答案。推理过程中，模型直接预测答案。

4. Pause token：模型仅使用问答进行训练，没有推理链。但在问题和答案之间插入了特殊 token，为模型提供了额外的计算能力来得出答案。

5. w/o curriculum：直接使用最后阶段的数据，不进行多阶段训练。

6. w/o thought：使用多阶段的训练，逐渐去除语言推理步骤，但不使用任何连续的潜在思维。这在概念上与 iCoT 相似，但实际的训练过程与 Coconut 保持一致。

7. Pause as thought：使用特殊的 `<pause>` token 来代替连续的思考，并应用与 Coconut 相同的多阶段训练。

#### 基准数据集

1. GSM8k：是一个用于数学推理任务的基准数据集，专门设计来评估大型语言模型在解决小学数学问题上的能力。

2. ProntoQA：是一个用于评估语言模型在问答任务中推理能力的基准数据集，其重点是测试模型在处理复杂逻辑和推理问题时的表现。

3. ProsQA：是一个为测试 Coconut 新建的基准数据集，重点是测试模型的规划密集型任务中表现。

### 2.5 研究案例：BSF 广度优先搜索

![](img/2a9797d14a90789bdbba04334499612b.png)

论文展示一个案例，研究显示了一个案例研究其中 CoT 产生幻觉（一个不存在的边）导致了错误的目标，但 Coconut（`k = 2`）成功解决了这个问题。潜在推理可以避免预先做出艰难的选择，模型可以在后续步骤中逐步消除不正确的选项，并在推理结束时获得更高的准确性。

### 2.6 结论与未来的研究方向

**优势：**

1. **更好的推理能力**：在多项任务中，Coconut 的准确率优于传统的 CoT 方法，尤其是在需要复杂规划和探索的任务中表现尤为突出。例如：在 ProsQA（复杂规划任务）中，Coconut 的表现明显优于 CoT 和其他基线方法。在 GSM8k（数学推理任务）中，Coconut 通过连续思维链有效提升了推理准确率。这表明 Coconut 在需要复杂推理和多路径探索的任务中更具优势。

2. **减少 Token 消耗**：与 CoT 相比，Coconut 在推理过程中生成的语言标记更少（表现在更少的“思维标记”数量），从而显著降低了推理的计算开销。例如，在 GSM8k 任务中，Coconut 生成的标记数量比 CoT 少，但推理能力却更强。效率的提升使得 Coconut 在推理时间和资源消耗上更具优势。

3. **在规划密集型任务中表现突出**：相较于 CoT，Coconut 能够在潜在空间中同时探索多个推理路径（类似广度优先搜索，BFS），逐步排除错误路径，从而提高了规划能力和决策准确性。

**劣势：**

1. Coconut 没有办法做并行计算，训练难度变大

2. 不可解释性，连续 COT 没有可解释的意义

**未来研究方向**

展望未来，有几个有趣的研究方向：

1. 一个可能的方向是使用连续思维对大语言模型进行预训练，而不是从标准预训练模型开始。

2. 另一个方向是优化 Coconut 的效率，以更好地处理多次前向传递的顺序性质。

3. 最后，将潜在思维与标准思维链结合，而不是替代它，可能允许同时获得两种方法的优势。尽管这需要更多的推理步骤。
