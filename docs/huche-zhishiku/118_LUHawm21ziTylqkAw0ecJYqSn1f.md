
# Bug 总是改不好？试试这 5 句“咒语”

> 来源：[https://huchegames.feishu.cn/docx/NWspdaLQSoZkAEx9gm5cOWEpnn4](https://huchegames.feishu.cn/docx/NWspdaLQSoZkAEx9gm5cOWEpnn4)

在使用 Cursor 修改 bug 时，是否经常遇到一个 bug 反复修改却总是改不好，甚至问题范围不断扩大，最终可能导致整个项目崩溃的情况？

当 AI 反复修改 2~3 次仍未解决问题，或者修改涉及的文件和函数范围有扩大的趋势时，此时就不能再使用简单的提示语，比如“报错了”、“你看，又错了”、“如图，报错了”。你需要改变沟通方式。

下面是我根据一些 Up 主的方法摸索并自用有效的 5 个“咒语”：

### 咒语 1：分析原因
请分析一下，导致这个问题出现的原因可能有哪些，一一列举出来给我看看。

### 咒语 2：添加调试代码
请添加一些调试代码，我们先定位下问题可能出现在哪里。

+ 辅助咒语：使用 `godotMCP` 来运行项目，并读取控制台信息。（这句是根据你的具体环境添加，如果不是 Godot 项目，请替换成你的运行/调试方式）

### 咒语 3：对比历史版本
关于【卡牌无法拖动的问题】（请替换成你的具体问题），我在上一个版本 v0.0.0.8 是没有问题的。请阅读 `master` 分支中的 v0.0.0.8 版本代码，对比一下现在的代码，分析两个版本的代码差异，告诉我。

### 咒语 4：详细解释逻辑
请把这个功能的实现逻辑用自然语言详细地告诉我，一步一步是怎么实现的，事无巨细地描述。

### 咒语 5：回退版本
使用 `git` 工具，将版本回退到 XXX 版本（请替换为具体的 commit hash 或分支名），我们重新根据计划进行开发。开发时需要注意 XXXX（在此处说明需要特别注意的地方）。

## 特殊情况：AI 执行额外动作

还有一种特殊情况，就是 Cursor 在执行你的指令时，会擅自增加额外的操作。

举个例子：

你让 AI 把调试用的 `print` 语句都删掉，准备打包发布或开始新的开发任务。结果它在执行时，多说了一句：“同时我也优化了代码结构”，然后开始解释这样做如何使代码更健壮、简洁、清晰等等。

此时一定要提高警惕，千万不要接受这些额外的修改！否则可能陷入无穷无尽的 bug 修改循环。

我的解决方案是：

直接明确且严厉地指出它的错误，例如：“你真不是个东西啊，有没有脑子，别做多余的事情。” 你会发现 AI 会立刻回到正轨，老老实实地执行你最初的指令（比如只删除 `print` 语句）。
