**访谈嘉宾:**

+   Will 保哥 (主持人)

+   David 老师 (软件开发、教育训练、顾问)

+   Caesar (JSDC 核心成员, CymPack 平台产品负责人)

**核心议题:** AI 对软件工程师的影响、工具使用、挑战与未来展望。

一、 AI 工具的使用现状与习惯差异

+   **普遍性与差异性:**

+   AI 工具（如 GitHub Copilot, ChatGPT, Cursor, v0.dev, Aider 等）已被广泛提及，但工程师的使用程度和偏好差异很大。

+   Will 保哥观察到公司内（约40位工程师）AI 使用率存在显著落差，部分人深度使用，部分人使用较少或不使用。

+   **使用方式:**

+   **Will 保哥:** 偏好在 IDE 内使用 GitHub Copilot，避免打断思路，追求效率。

+   **Caesar:** 同时使用多种工具 (ChatGPT, Cursor, bolt.new, v0.dev, Aider)，认为遇到问题时思路已被打断，切换工具是常态。他的流程倾向于：定义问题 -> 使用工具（如 Cursor） -> 若无法解决则切换至 ChatGPT/Claude/Google Search -> 利用工具处理问题期间，切换处理其他任务。

+   **部分工程师:** 宁愿离开 IDE 使用 ChatGPT 获取答案再回来，认为这样更专注；或者觉得 Copilot 的建议干扰思路，甚至关闭自动建议，仅在需要时手动触发。

+   **工具选择困境:**

+   Caesar 指出，工程师常遇到的问题是不知道该问哪个 AI、如何提问 (Prompting)，以及何时该跳出单一工具（如 Cursor）去寻求其他帮助（如 ChatGPT 或 Google Search）。

+   Google Search 使用率下降:

+   Will 保哥和 David 老师都提到，随着 AI 工具的普及，他们个人使用 Google Search 和 Stack Overflow 的频率大幅降低。

二、 资深与初阶工程师对 AI 的态度差异

+   不使用 AI 的原因 (特别是资深工程师):

+   **习惯与偏好:** 习惯了固有的开发模式，觉得 AI 建议不符合自己的编码风格或需求。

+   **代码精准性要求:** 在项目后期，架构和模式固定，需要精准控制代码，AI 生成的代码可能不符合要求或干扰思路。

+   **信任与掌控:** 宁愿自己花时间编写可控的代码，也不愿花费精力去验证和修改 AI 生成的、可能不完全可靠的代码，并为其负责。

+   **干扰:** Copilot 的灰色建议文字可能干扰部分工程师的思考过程。

+   **特定场景限制:** 某些语言 (如特定配置下的 Java) 或公司政策 (如代码重叠或 License 限制) 可能导致 Copilot 效果不佳或无法使用。

+   AI 对不同经验水平工程师的价值:

+   **初阶 (Junior):** AI 可以提供大量帮助，因为他们可能缺乏经验，很多代码写不出来。

+   **资深 (Senior):**

+   若能善用 AI，可以大幅提升效率，将已知要写的代码快速生成 (如 Will 保哥的例子)。

+   AI 可以提供不同的写法思路，开阔眼界。

+   AI 可以处理繁琐任务 (如写正则表达式、单元测试框架、文件生成)，节省时间。

+   **David 老师的观察:**

+   AI 辅助开发已成趋势，身边几乎人人都用。

+   未来 2-3 年，可能没有“非 AI 辅助”的开发模式。

+   AI 的效果因语言、开发内容、个人习惯和公司政策而异，Python 的效果目前非常好。

三、 AI 工具的效率提升与付费意愿

+   **效率提升:**

+   普遍认为 AI (特别是 Copilot) 能显著提升开发效率，调查显示平均在 30%-50% 左右。

+   David 老师认为 AI 能让人找回写代码的乐趣，减少卡顿和挫败感，更快解决问题。

+   Will 保哥和 Caesar 也认同 AI 在写 Side Project、生成文件 (Readme, 技术文档) 方面极大提升了效率和愉悦感。

+   **付费意愿:**

+   **争议点:** 工具是公司该买还是个人该投资？

+   **Will 保哥观察:** 即使公司付费购买，仍有员工不使用或使用频率低。猜测若取消公司付费，大部分人可能不会自费购买，认为提升生产力是公司的事。

+   **Caesar 观点:** 类比自购显示器/键盘，认为提升个人效率、节省时间去做更有价值或喜欢的事，是值得个人投资的。时间比金钱更重要。

+   **David 老师观察:** 用过且觉得有价值的开发者，大多愿意自费购买 (如 Copilot 个人版每月约 10 美元)。

+   **普遍心态:** 台湾开发者可能较追求 CP 值，对付费较为犹豫。

+   **隐藏使用:** 部分员工可能偷偷使用 AI 提升效率，但不愿声张，担心被分配更多工作。导致 AI 的实际效率提升可能被低估。

四、 AI 对软体产业未来的影响与挑战

+   Junior Developer 的挑战:

+   **替代性增强:** AI 在编写基础代码、文件等方面已优于部分 Junior Developer，导致其可替代性增强。

+   **招聘门槛提高:** 部分公司 (如 Salesforce) 已开始考虑减少或停止招聘 Junior Developer，因为现有资深员工+AI 即可满足需求。

+   **红利消失:** 过去几年因疫情等因素造成的开发人力红利正在消失。

+   **学习压力增大:** Junior 需要更主动、更快速地学习，可能需要自费学习 AI 协作等新技能，并积极参与 Side Project 实践。

+   **断层风险:** 若企业普遍不培养新人，未来可能出现人才断层。但决策者可能着眼短期利益，认为 20 年后 AI 或许能完全接管。

+   Senior Developer 的价值:

+   资深开发者的经验、架构能力、问题解决能力、鉴别能力（判断 AI 输出的正确性）变得更加重要。

+   **工作模式的转变:**

+   **一人公司/自雇者兴起:** AI 工具使个人能够处理更多事务，降低创业门槛，自雇模式可能更普遍。

+   **工作定义模糊:** 高效开发者可能短时间完成工作，全职定义可能改变，工作模式更灵活。

+   **技能重心的转移:**

+   从 Programmer 到 Developer: 纯粹的编码 (Programming) 价值下降，需要向具备更高维度思考、能提出解决方案的开发者 (Developer) 转变。

+   **强调高阶能力:** 架构设计、问题定义、解决方案构思、沟通协作、业务理解、流程再造、批判性思维、鉴别能力等变得更重要。

+   **跨界学习:** 工程师可能需要学习 PM 知识、跨语言/框架整合能力。

+   **软实力:** 沟通、表达、将技术概念清晰传达给非技术人员的能力愈发关键。AI 可辅助提升沟通品质。

+   **AI Agent 的未来:**

+   **自动化协作:** 未来可能是 AI Agent 之间直接沟通协作 (如订票、报税)，人只需提出需求。

+   **交互方式改变:** 人机交互可能从键盘鼠标转向更自然的语言对话 (类似 Jarvis)。

+   Software is Dead? 并非软件消失，而是软件的形式和开发模式将发生巨变。编程语言本身可能不再是核心，重点在于定义问题和解决方案。

+   **对现有开发实践的冲击:**

+   Clean Code/TDD/敏捷: 传统上强调的某些实践 (如代码简洁性优于注释、小步迭代、设计涌现) 可能会因 AI 的能力而改变。注释可能变得更重要（作为给 AI 的 Prompt），架构设计可能需要更前置。

+   **沉默成本:** 需要警惕过去的经验和投入（沉默成本）成为接受新模式的阻碍。

**五、 核心观点与建议**

+   **拥抱 AI，但不盲从:** AI 是强大的工具，能提升效率和乐趣，但需具备鉴别能力，理解其局限性。

+   **提升维度，超越编码:** 将重心从底层编码转移到更高层次的问题定义、架构设计、解决方案构思和沟通协作上。

+   **持续学习，适应变化:** 软件行业变化迅速，需保持学习心态，关注 AI 发展，调整学习方向。

+   **关注基础，培养软实力:** 扎实的基础知识（演算法、数据结构等）和软实力（沟通、批判性思维）是未来竞争力的关键。

+   **找回初心，乐在其中:** 尝试将工作与兴趣结合，利用 AI 减少重复枯燥的工作，找回解决问题的乐趣和成就感。

+   **警惕“马农”陷阱:** 避免长期从事重复性、低价值的编码工作，要寻求成长和突破的机会。
