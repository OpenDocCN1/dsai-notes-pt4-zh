## Dario Amodei 主题演讲

+   **开场白**：简短发言，20分钟后会有炉边谈话。

+   **重大发布**：

+   **正式发布 Claude 4 Opu**s 和 Claude 4 Sonnet！ (观众欢呼)

+   这些模型已在所有相关的 Anthropic 产品和服务上线。

+   **模型介绍**：

+   **Opus**：最强大、最智能的模型。

+   **Sonnet**：中端模型，大家熟悉并喜爱的，平衡了智能和效率，已使用约一年。

+   设计理念：针对不同用例和最佳使用场景设计不同模型。

+   Claude 4 Opus 详解：

+   专为编码和 agentic 任务设计。

+   在 Swe-bench, Terminal-bench 等基准测试中达到顶尖水平。

+   基准测试无法完全体现其能力，客户反馈其能自主完成人类需 6-7 小时的任务。

+   即使是 Anthropic 内部资深工程师也对其生产力提升感到惊讶。

+   首次让 Dario 感觉被 AI "愚弄"（以为是人类写的内部总结和文档），因其风格不再有明显的 AI 特征。

+   Claude 4 Sonnet 详解：

+   对许多人来说是 Sonnet 3.7 的直接升级，成本相同但智能更高。

+   许多客户直接从 3.7 切换。

+   在某些编码基准上表现与 Opus 一样好。

+   更精简，更聚焦。

+   特别解决了 Sonnet 3.7 中一些反馈问题，如“过度积极”（over-eagerness，倾向于做超出要求的事），以及一些奖励机制被“黑客利用”（reward hacking）的问题。

+   客户（如 Cursor）反馈其为强大的升级，是顶尖的编码模型，在复杂代码库理解上有飞跃。

+   **未来展望**：

+   将持续改进 Claude 4 系列模型。

+   预计会定期发布次要版本更新，理想情况下比之前更频繁。

+   新模型应该已经可以在所有服务（除免费版可能仅限 Sonnet）上使用。

## **Mike Krieger 主题演讲：深**入 Claude 4 与 API 路线图

+   **感谢 Dario**：宣布了两款新模型。Dario 将在 Q&A 环节回归。

+   **Claude 4 模型详解**：

+   团队非常喜欢这两款新模型，相信大家也会。

+   **构建 Claude 4 的目标**：

+   构建强大的 AI，安全地引入新模型能力。

+   持续推进编码和 AI Agent 的前沿。

+   确保 Claude 成为开发者的虚拟协作者。

+   Opus 4 和 Sonnet 4 实现了这些目标。

+   **混合模型特性**：像 Sonnet 3.7 一样，Claude 4 模型也是混合模型，有两种模式：

+   近乎即时的响应。

+   需要深度推理时的扩展思考。

+   许多客户将深度推理用于非编码和非数学用例。

+   **Opus 4**：

+   擅长理解代码库、规划编辑。

+   在迁移、代码重构等方面非常高效准确。

+   是复杂 agentic 工作流的正确选择。

+   如果其他模型遇到瓶颈，Opus 4 可能会带来惊喜。

+   **Sonnet 4**：

+   擅长日常编码任务、应用开发、结对编程。

+   非常适合高吞吐量用例，完美平衡效率与性能。

+   可视为“永不离线”的编码伙伴。

+   **上线情况**：

+   两款模型今日已上线 [Claude.ai](http://claude.ai/), Claude Code, Anthropic API, Amazon Bedrock, Google Cloud Vertex AI。

+   **AI Agent 的新能力**：

+   模型带来构建 AI Agent 的关键新能力：

+   在推理过程中使用工具（如网络搜索，这是新的）。

+   并行处理多个工具。

+   访问本地文件时，能在会话间保持记忆，随时间积累知识。

+   这些不是增量改进，而是从根本上改变了 AI Agent 的可能性。

+   **关于 "Agent"**：

+   这个词现在很流行（Mike 开玩笑说内部会议多久不提这个词）。

+   今天的重点是“超越炒作的 Agent”。

+   关键在于：正确的底层模型 + 正确的底层平台工具 = AI Agent 能将人类想象力以前所未有的规模转化为有形现实。

+   这对初创公司和开发者尤为重要。

+   Mike 的创业经验（Instagram）：

+   早期小团队面临许多“二选一”的艰难决策（例如，添加视频功能 vs 核心创意，移动应用 vs Web 扩展）。

+   AI Agent 对初创公司的意义：

+   可以并行进行实验，从用户处学习，更快构建产品。

+   能为初创公司创始人提供高阶战略思考（如同拥有 CFO 或产品负责人），即使他们尚未招聘这些职位。

+   这种转变不再是理论，Mike 在日常工作中亲身体验。

+   Amazon Alexa 合作案例：

+   Anthropic 与亚马逊 Alexa 团队合作，探索 Claude 如何成为未来语音助手愿景的一部分。

+   Mike 团队用 Claude 本身构建了一个实践演示，而不是传统的 PPT。

+   挑战：在无法访问 Alexa 实际代码库的情况下，创建核心功能原型，并集成 Claude 的能力，且只有一周时间。

+   Claude 是完成此任务的唯一原因。一个三人团队（旧金山和伦敦）构建了功能原型。

+   Mike 甚至亲自参与了一些前端开发。

+   Claude 现在是亚马逊用于 Alexa Plus 的模型之一，后者已于今年早些时候推出。

+   **AI Agent 的演进观察**：

+   GitHub Copilot (2021)：Mike 称之为他见过最令人震撼的机器学习应用。

+   Artifact (去年夏天)：通过描述就能让 Claude 构建迷你应用或可视化。

+   结论：我们不仅在构建更好的工具，更在创造真正的协作者。

+   **Anthropic 经济学研究**：

+   AI 正在增强而非取代人们的工作，更多是任务而非整个角色。

+   这类似于优秀同事的影响：理解上下文、从经验中学习、知道何时主动何时仅需确认。

+   优秀 AI Agent 的三个核心能力：

1.  情境智能 (Contextual Intelligence)：理解用户和组织的独特上下文，并从经验中持续学习（不只是遵循指令，而是理解“为什么”和“怎么做”）。模型能随时间学习和个性化，获取情境记忆、片段记忆和组织记忆。

1.  长时程执行 (Long-running Execution)：处理复杂的多小时任务，无需持续管理，能按需与其他 Agent 和人类协调。

1.  真正的协作 (Genuine Collaboration)：进行有意义的对话，适应工作风格，并为其行为提供透明的推理。

+   **关键洞察**：真正的 Agent 能力不等于不受控制的行动；自主性不等于“瞎搞”。它意味着智能的自主性，并以清晰的检查点来平衡，保持人类对关键决策的监督，同时授权小型决策。

+   新 API 能力发布 (服务以上三个需求)

1.  代码执行工具 (Code Execution Tool)：

+   今日已在 Anthropic API 上线。

+   为 Claude 提供一个运行代码的环境，使其能作为数据分析师，将原始数据转化为可视化洞察。

+   Claude 不仅能写代码，还能执行代码，看到结果，并迭代优化代码和结果以更好地突出数据模式。

+   现场演示：Claude 分析销售数据，查看特定产品类型的表现（加载数据集、清理、生成探索性图表、实时钻取异常）。

+   与 Claude 4 模型的智能结合时更为强大。

+   这体现了 Agent 能力：接受复杂任务并将其完成。

+   这些模型能处理数小时的任务，节省半天甚至整天工作时间。

+   不仅是代码片段，还能重构整个代码库或从零开始实现复杂功能。

+   进展对比：Claude 3 能代理数分钟工作；Claude 3.7 能自主工作约 45 分钟；Claude 4 能自主工作数小时。Rakuten 案例：Claude 独立运行 7 小时。

1.  Claude Code (编码 Agent)：

+   从研究预览阶段进入正式发布 (General Access)！

+   起源：内部探索性项目 (by Boris)，希望 Claude 能在终端直接辅助编码。

+   最好的创新（如 Artifact, Claude Code）源于这种自下而上的实验。

+   内部上线两天后，使用量垂直上升。

+   Anthropic 内部大多数员工依赖它完成从常规编码到大规模迁移的各种任务。

+   高级编码员同时运行多个 Claude Code 实例，从工程师转变为多个自主 Agent 的管理者。

+   案例：Mike 曾分别在前端和后端仓库运行 Claude Code，后被告知只需在根目录运行，Claude 能自行判断。

+   大多数 Anthropic 开发者日常使用 Claude Code。

+   效果：技术入职时间从 2-3 周缩短到 2-3 天。

+   **新进展**：

+   **Claude Code 直接集成到 VS **Code 和 JetBrains IDE，具有完整的 diff 视图和 agentic 工作流管理。

+   发布 Claude Code SDK：开发者可以在与 Claude Code 相同的核心 Agent 之上构建自己的应用。

+   示例：Claude Code in GitHub。可以在 GitHub Pull Request 或 Issue 中 @Claude，它会响应审阅反馈、修改代码或实现测试覆盖。

+   闭环 (Closing the loop)：Claude Code 正在帮助构建自身，展示了自我改进的力量。

1.  责任与安全 (Responsibility & Safety)：

+   没有责任的 Agent 能力是危险的，尤其对于像 Claude Code 这样能自我改进的产品，以及在有严格安全合规要求的企业环境中。

+   广泛采用 Agent 需要提升模型在保密性、决策和协调方面的辨别力与判断力。

+   架构级安全 (Architectural Safety)：每个功能都融入其中。

+   检查点和控制，而非全权委托。

+   Agent 在重大决策前会暂停，用户可定义哪些操作需人类批准（已内置于模型上下文协议）。

+   对滥用具有鲁棒性（例如，针对提示注入进行严格测试）。

+   设计上透明，有清晰的反馈循环和可观察行为。

1.  可解释性 (Interpretability)：

+   理解 AI 模型内部运作的科学。

+   Dario 最近撰文强调理解 AI 系统如何工作的紧迫性（模型智能与可解释性之间的竞赛）。

+   目标：能给 AI 做“MRI”，了解其思考过程，发现潜在问题（如欺骗），并引导其向正确方向发展。

+   Golden Gate Claude 案例：通过放大 Claude 神经网络内部的“金门大桥”特征，直观展示了可解释性的作用。这有助于未来减少有害模型行为或提升特定领域模型性能。

+   希望可解释性和可审计性成为虚拟协作者工作的基石。

+   平台新特性 (赋能 Agent)：

+   目标：将抽象研究转化为有形的产品能力。

+   AI 模型已能处理数小时的自主工作，且此能力每几个月翻一番。

+   但仅有原始模型能力不够，还需真实世界信息、与现有系统的连接以及成本效益高的扩展。

+   发布四个互联能力，为 Agent 提供上下文并助其扩展：

1.  **模型上下文协议 (Model Co**ntext Protocol, MCP)：

+   今日起可通过 API 直接连接。

+   已被微软、谷歌、OpenAI、Block、Atlassian、Zapier、Linear 等众多公司使用。

+   作为 AI Agent 的通用翻译器和连接器，实现与现有系统的无缝连接。

+   为未来的“Agent 经济”奠定基础。

1.  网络搜索 (Web Search)：

+   赋予 Claude 实时访问当前信息的能力。

+   智能数据增强，使 Claude 能推理时事、市场趋势和新兴技术。

+   与 MCP 结合威力巨大（如搜索内部知识库，再结合网络搜索进行情境化）。

1.  文件 API (Files API)：

+   今日在 API 中可用。

+   简化开发者访问和存储文档的流程。

+   发布 Cookbook 帮助开发者将记忆功能直接构建到应用中。

+   新 Claude 4 模型在“自我管理记忆”方面有显著改进。

+   用 Files API 实现此功能，额外开销很小。Claude 能读写这些记忆文件，并在长时间内保持上下文。

1.  提示缓存 (Prompt Caching)：

+   最受欢迎的 API 功能之一。

+   让客户为 Claude 提供更多上下文、背景知识和示例输出，可降低成本高达 90%，长提示延迟降低高达 85%。

+   **新进展**：响应客户需求，将缓存 TTL（Time to Live）从 5 分钟延长到 1 小时（高级版），这是 12 倍的提升，显著降低长时程 Agent 工作流的成本。

+   **能力叠加效应**：

+   这些 API 功能不是孤立的，而是相互补充，形成连贯的整体。

+   Claude 现在能执行代码、理解系统、访问实时网络信息，为具有完整上下文、能执行长时程任务的 Agent 奠定基础，并使用文件 API 保持记忆和上下文。

+   **未来三大支柱**：

1.  行业领先的 Agentic 工具和应用：让 Claude 能自主处理数小时的工作。

1.  Claude Code 进一步发展：已正式可用，并与 VS Code/JetBrains 集成，提供 SDK。

1.  **高效扩展**：1小时提示缓存优化性能和成本。

+   **持续学习与反馈**：

+   积极听取开发者反馈，MCP 就是一个很好的例子（从内部想法到社区实验再到核心平台功能）。

+   **最终愿景**：

+   创建一个 AI Agent 生态系统，通过反馈循环使其真正对用户有用。

+   未来不是 AI 做人类的工作，而是 AI 帮助人类做超乎常人的工作。

## Kat Wu：Claude Code 演示与更新

+   **自我介绍**：Kat Wu，Claude Code 产品经理。

+   **回顾 Claude Code**：之前作为 agentic 编码工具在研究预览中发布。

+   Claude Code 的新进展：

+   集成 Claude 4 Opus 和 Claude 4 Sonnet，使其更强大。

+   **IDE 集成**：

+   Claude Code 现已集成到 VS Code 和 JetBrains IDE，为数百万开发者带来熟悉界面。

+   可以直接在编辑器中看到 Claude Code 建议的更改 (in-line diffs)。

+   Claude Code SDK 发布：

+   允许开发者将 Claude Code 作为构建模块，用于自己的应用程序和工作流。

+   示例：Claude Code in GitHub。

+   开源 SDK 示例，展示其在 GitHub 中的应用。

+   可以直接在 PR 或 Issue 中 @Claude，它会响应评审反馈、修复 CI 错误、添加新功能。

+   演示：在 Excalidraw (开源白板工具) 中添加表格组件

+   场景：实现一个呼声很高的功能——添加表格组件。

+   提示 Claude Code：添加支持自定义尺寸、拖拽调整大小，并包含 Excalidraw 所有其他样式选项的表格组件。

+   过程：

+   Claude Code 首先创建了一个待办事项列表 (to-do list) 来规划整个问题。

+   开始探索代码库，从当前打开的文件获取上下文。

+   IDE 集成允许内联查看 diff，方便接受或提供反馈。

+   可以选择逐个批准编辑，或使用自动接受模式。

+   Claude Code 工作了 90 分钟（演示为加速版），完成了任务。

+   添加了表格功能，编写了测试来验证更改，并迭代直到 lint 和测试通过。

+   演示了在本地运行 Excalidraw，新表格组件功能正常（创建3x3表格、重新定位、拖拽调整大小、改变边框图案和颜色、添加文本到单元格）。

+   这个复杂任务仅通过一个提示在 Claude Code 中完成。

+   **GitHub 集成演示**：

+   使用 GitHub CLI 为刚才的更改创建 PR。

+   通过在 PR 评论中 @Claude，要求其更新文档。

+   这会触发一个运行 Claude Code 的 GitHub Action。

+   Claude Code 会在 PR 中评论其工作进展，并在完成后提交 commit。

+   同样可以在 GitHub Issue 中 @Claude 来创建 PR。

+   **总结**：

+   Claude Code 现已在所有常用开发场景可用：终端、远程环境（如 GitHub）、IDE。

+   无论是交互式使用还是异步使用，它都是一个多功能的编码 Agent。

## **Michael Gersenhaber：**Anthropic 平台赋能 Agent

+   **自我介绍**：Michael Gersenhaber，API 平台产品负责人。

+   **AI 生成代码的普及**：提问现场多少人使用 AI 生成代码（几乎所有人），多少人其应用核心功能由 AI 驱动（几乎所有人）。

+   **平台愿景**：

+   世界上大多数应用将由已在解决世界问题的人构建。

+   无论经验如何，我们都是软件工程师。

+   编写代码只是开始，还需要快速构建稳定、安全、可维护的 AI 应用。

+   **Anthropic 平台**：一个完整的工具包，用于构建顶尖的 AI 应用和 Agent，已为全球各领域 AI 交付提供动力。

+   **案例**：

+   金融：TurboTax 帮助数百万客户通过联邦税务解释器自信报税。

+   医疗：诺和诺德使用 Claude 在不到10分钟内起草临床研究报告（而非15周）。

+   编码：世界上最好的编码助手运行在 Anthropic 平台。

+   **平台核心**：

+   **模型推理服务**：通过 Messages API 可靠访问 Claude。

+   **基础工具**：如提示缓存，优化性能和成本（超过50%的输入 token 被缓存）。Notion 案例：利用此功能在保持快速响应的同时处理大量上下文。

+   **提示缓存TTL延长**：从5分钟延长到1小时。

+   **构建 Agent 的强大基石**：

+   文件 API (Files API)。

+   代码执行工具 (Code Execution Tool)：让 Agent 能在生产环境中编写并运行自己的代码。

+   **平台组件的组合性**：
