
# 关于 RAG 及效果优化

> 来源：[https://leonzhang.feishu.cn/docx/RNWJdieaMoi97XxN0MhcjYoInGd](https://leonzhang.feishu.cn/docx/RNWJdieaMoi97XxN0MhcjYoInGd)

## 概述

RAG（Retrieval-augmented generation，检索增强生成）是一种为 Gen AI 提供信息检索、文本生成能力的技术，能够让模型回答时，基于知识库内容作答，并提供源引用，减少幻觉。

## 工作流

> 解析与切片、向量存储、检索召回、答案生成

将数据转为 LLM 嵌入并存储在向量数据库，通常是非结构化（通常是文本）、半结构化或结构化数据（例如知识图谱）；用户查询时，文档检索器选择相关文档；再通过提示工程将检索信息输入 LLM；最后 LLM 基于查询和检索文档生成输出。

- 应用场景：常用于 ChatBot 访问公司内部数据、基于权威来源生成回复等。

- 局限性：

  - RAG 无法完全解决 LLM 的幻觉问题，也不能完全消除模型再训练；

  - LLM 可能难以判断自身信息是否充足；

  - RAG 系统可能检索到误导性信息，且面对冲突信息时难以抉择。

## 效果优化

> 三个阶段：解析与切片、检索召回、答案生成

### 准备工作

> 两部分：上传文档格式、内容、语言类型、歧义消除；图片展示；

1. 上传文档

2. 格式。推荐文本格式，如 `markdown`、`doc`、`docx`、`txt` 等，`PDF` 因格式复杂，也建议转为文本文档。

3. 内容。表达清晰、结构合理、无特殊格式。文档的内容排版也会影响 RAG 的效果，各级标题要层次分明、文档中不要有表格或图片。

4. 语言。需与 `Prompt` 语言一致。文档中的专业术语，可进行双语或多语言处理。

5. 消除实体歧义。对文档中相同实体的表述进行统一。例如，“ML”、“Machine Learning”和“机器学习”可以统一规范为“机器学习”。

6. 图片展示。须对图片进行链接化处理，图片 `URL` 须支持公网访问。

```
# 知识库
请记住以下材料，他们可能对回答问题有帮助。
${documents}

# 要求
如果有图片，请展示图片。
```

### 解析与切片

导入知识库的文档会被解析和切片。

1. 尽量保证语义的完整性，避免过多干扰信息。

2. 文档成功导入后，需对文本切片内容进行人工检查和修正。

### 检索召回

知识库越庞大、资料越多，找到最相关、且包含正确答案的文本切片难度越高。

1. `多轮对话改写`：上下文对话内容关联。

2. 为文档`添加标签`，优先检索`标签`。

3. 为文档切片嵌入元数据，如日期信息等。

4. 调整相似度阈值（降低或增加）。

### 答案生成

1. `优化提示词`。

2. `限定输出内容`

3. `添加示例`，即少样本提示（`Few-Shot Prompting`）

4. `切换合适的大模型`。比如垂直场景的垂直大模型的效果，大概率优于通用大模型。

5. `设置回答范围`。比如仅知识库范围，或知识库 + 大模型。

```
# 判断规则：
- 问题和文档匹配的前提是问题中涉及的实体与文档描述的实体完全相同。
- 问题在文档中完全没有提到，请明确告知“根据现有信息，我无法回答这个问题”。切勿编造答案。
```

1. 调整大模型参数。

2. `温度系数`可以控制大模型生成内容的随机性：温度越高，生成的文本越多样，反之，生成的文本越确定。

3. `最长回复长度`：此参数用于控制大模型生成的最多 `Token` 个数。如果您希望生成详细的描述可以将该值调高；如果希望生成简短的回答可以将该值调低。

4. `携带上下文轮数`：此参数用于控制大模型参考历史对话的轮数，设为 `1` 时表示模型在回答时不会参考历史对话信息。
