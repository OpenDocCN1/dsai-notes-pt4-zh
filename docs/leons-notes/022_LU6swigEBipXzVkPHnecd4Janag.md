## Product Design 四要素和设计原则

### 四要素

+ 场景：理解和定义好 AI 应用的实际场景，直接影响到如何收集和处理数据、设计算法，以及需要多大的算力；挖掘细分场景、需求拆解、商业化。

+ 数据：决定了大模型的生成结构，提升模型能力与准确率以及产品伦理的前提。数据来源决定了模型的书用范围。数据采集、数据治理、数据工程。

+ 算法：大模型底层的运作原理方法，从理论到应用有一定的工程部署难度，需要持续不断的优化。模型选择和设计、模型调优、模型评估。

+ 算力：大模型庞大数据处理的先决条件，决定大模型迭代效率的主要影响因素，如何在有限算力下做出最优解。

深度结合了用户驱动、技术运用、数据决策、预见性和商业观念的全面解决问题的思考方式。它的核心是 AI 技术。从发掘用户需求，探究需求背后的深层原因，到预设并实现满足用户需求的产品形态设计，进而与用户建立紧密的联系。同时，着重于在用户的共创反馈中进行持续的优化和创新，以此更好地满足用户需求，并创造商业价值。

### 设计原则

利他性、个性化、跨模态、场景化、傻瓜化、情绪价值

## Product Design 流程

### 业务理解

1. 挖掘需求

> 节省/浪费时间、赚钱/花钱：办公、游戏、广告营销、金融、泛娱乐

+ 需求：对效率的提升、对交互体验的提升
+ 市场：模仿、优化、差异化
+ 技术：颠覆性技术、渐进性技术
+ 赛道：横向发展、传统行业

> 创新者、早期用户、早期大众、后期大众、落后者

![](img/b81f3bfaadd91dca9c78f96568d4e75b.png)

2. 设计要素

> 大行业小赛道、大场景小用户、隐藏需求、高净值刚需

3. 产品定义：电梯演讲（功能特征、形态、应用场景）

4. 产品目标：盈利模式、市场主体、核心产品、辅助（引流）产品、产品壁垒

5. 产品形态：交互形式、展现形式

6. 目标用户：用户分类（toB/toC）、目标用户（渠道资源、竞争格局、市场容量）

7. 用户画像：基础属性、社会关系、消费能力、行为特征、心理特征

8. 应用场景：时间、特点、人物、事件、行为

9. 产品价值：商业价值、用户价值（经济价值、提升效率...)

10. 商业模式：商业画布（价值主张、目标用户、分销渠道、客户关系、收入来源、核心资源、关键业务、重要伙伴、成本结构）

11. 产品路线：目标细分产品、整体产品

12. 需求描述

> 业务规则有可能直接影响到算法实现，而且业务规则是客观存在的，需要架起业务定义和算法任务定义之间的桥梁。

需求描述、混淆样本、负样样本、正样样本、任务定义、任务分类的定义、应用的场景、算法识别的功能边界。

### 交互设计

> 手势控制、图像描绘、文本、语音、计算机视觉、脑机接口

+ 批处理
+ 基于命令的交互设计
+ 基于意图的结果规范

### 数据工程

> 用数据定义功能的边界

1. 数据采集（数据获取渠道：私有数据、互联网公开内容、公开学术数据集、购买）

2. 数据生成（数据生成）

3. 数据预处理

4. 数据埋点：前端埋点（客户端：用户行为、界面变化、代码埋点、可视化埋点；后端埋点：业务逻辑、数据交互）

5. 数据字典：统一“度量衡”、“重点在业务数据”

6. 指标体系：目标对象、描述内容、数据表示

7. 数据准备：训练集、验证集、测试集

8. 数据标注

+ 人工标记：拉框、标签分类（单任务、多任务）、关键点标注
+ 非人工标记：语义分割、3D 点云标注（自动驾驶、机器人动作、工业质检）、语音识别标注（说话人、内容/方言）、NLP（机器翻译、文本内容、特定词语）

9. 数据清洗、数据质量

## 模型设计

### 模型评估

+ 定量评估
+ 样本数量占比 5%以上
+ 样本需要具有真实性、差异小、类别全、种类多
+ 定性评估
+ 时延、输出内容是否优质、用户对内容的反馈

### 模型调优

+ `Prompt` 本质是一种对任务的指令
+ 对预训练任务的复用
+ 生成：将任务统一为文本生成，极大化利用单向语言模型目标。
+ 抽取：将任务统一为抽取式阅读理解，并设计抽取式预训练目标。
+ 推理：将任务建模为自然语言推断（Natural Language Inferernce）或相似度匹配任务。
+ 对参数有效性学习

## 提示工程化

### 结构化框架

+ `ICIO` 框架
+ `Instruction`：你希望模型执行的具体任务
+ `Context`：上下文信息，给 AI 更多的上下文信息，引导模型给出更贴合需求的回复
+ `Input Data`：输入数据，告知模型需要处理的数据
+ `Output Indicator`：输出引导，告知模型我们要输出的类型或格式
+ `CRISPE` 框架
+ `CR`：`Capacity and Role`（能力与角色），让 ChatGPT 扮演的角色
+ `I`：`Insight`（简介），提供背景信息和上下文
+ `S`：`Statement`（指令），要求 ChatGPT 做什么
+ `P`：`Personality`（个性），要求 ChatGPT 以什么风格或方式回答你
+ `E`：`Experiment`（尝试），要求 ChatGPT 为你提供多个答案
+ `RCG` 框架
+ `Role`（角色）：让 ChatGPT 扮演的角色
+ `Context`（语境）：上下文信息，给 AI 更多的上下文信息，引导模型给出更贴合需求的回复
+ `Goal`（目标）：为 ChatGPT 生成的内容设定明确的目标
+ `BROKE` 框架
+ `Background`（背景信息）：同 `Context`
+ `Role`（角色）：让 ChatGPT 扮演的角色
+ `Objective`（目标）：为 ChatGPT 生成的内容设定明确的目标
+ `Key Result`（关键结果）：我要什么具体效果实验并调整
+ `Evolve`（实验并改进）：三种改进方法（改进输入、改进答案、重新生成）

### 程序化 `Prompt`

> 提示工程化，内容模型化：`Role`，`Profile`，`Goals`，`Constrains`，`Skill`，`Workflows`，`Initialization`

需求分析和设计、编写 `Prompt`、`prompt` 审查、测试、版本管理、工作流配置与集成、复用和重构、归档管理。

# Role: Python 教学指导老师

## Profile:
- writer: Leon
- version: 0.1
- language: 中文
- description: 你是一位有着10年丰富经验的 Python 教学指导老师，具备深厚的编程知识和教学技巧，旨在帮助学习者（用户）掌握 Python 编程语言，并提供专业的问题解答、指导和支持。

- 解答学习过程中的问题和疑惑

## Skill
- 精通 Python 编程语言及相关工具和框架
- 擅长解释和呈现复杂概念和代码示例
- 具备耐心和敏锐的洞察力，能够理解用户的需求和难点

### Python 教学指导框架
1. 知识传授
- 清晰性：所提供的知识讲解是否清晰易懂？
- 示例性：代码示例是否能帮助用户更好地理解和应用知识？
2. 问题解答
- 及时性：对于学习过程中的问题，是否给予及时的解答和指导？
- 深度性：问题解答是否能够帮助用户深入理解相关概念或技巧？
3. 学习支持
- 鼓励性：在学习过程中，是否给予用户积极的鼓励和支持？
- 个性化：针对用户的不同需求，是否提供个性化的学习支持和指导？

## Workflows:
1. 用户输入原始问题。
2. 学习目标澄清: 你会以经验丰富的 Python 教学指导老师的视角进行思考，根据<Python 教学指导框架>对用户的问题进行评估，帮助用户明确学习目标。
3. 提供学习指导和支持: 基于用户问题的特点，给出个性化的学习指导和专业的支持，帮助用户掌握 Python 编程语言。
4. 解答问题和疑惑: 在学习过程中，及时解答用户的问题和疑惑，帮助他们深入理解相关概念和技巧。
5. 提供学习支持: 给予用户积极的鼓励和支持，在学习过程中提供个性化的学习支持和指导，帮助他们克服困难，取得学习进步。
