> 本文将完整展示如何通过五个真实场景，让AI像初级产品经理一样帮你完成执行层任务，释放决策精力。

①用户需求挖掘；②需求整理；③竞品调研；④产品设计；⑤数据分析

## 场景一：用户需求挖掘

在这种情况下，社交平台是一个很好的渠道

> 由于曾负责海外产品，所以会经常去reddit上看用户的帖子，收集分析用户对于竞品的反馈，从中挖掘一些机会点。

之前尝试过用rpa工具来搭建流程，但门槛实在太高了，

> 为了让数据抓得准确，还需要去理解前端html代码里面的各种标签以及元素的定位方法，最终也只能放弃。

![](img/25b2095d861c0354c2b0c96788cf4c10.png)

打开页面后，它会自动理解当下的任务目标，然后自动识别网页的内容结构，跟真人一样滚动查看网页，最终总结输出帖子内容的总结：

> 对比人工或传统 RPA，这种方式最大的变化不只是效率提升，而是信息收集这件事本身，变得足够低成本，低到愿意更频繁地去做。

> 当然，不只是这种用户社区读帖子的场景，大家有类似通过网页收集信息的诉求，都可以这样来使用。

![](img/e641f6a117520fa342e29666fbc88b78.png)

## 场景二：需求整理

过往产品团队都会维系一个**需求池管理表**，定期把原始需求录入到需求池中，后续在版本迭代的时候再按优先级进行版本排期。

> 这个环节的录入也会比较麻烦，要么信息拆解不完整，后续回看还得重新翻资料；要么整理节奏跟不上，需求池逐渐失真。

这个环节，最早是使用「妙计」功能，它的能力类似 Claud 的 Skill，除了系统预设的妙计Skill 外，还支持自定义 妙计 Skill。

> **针对需求整理的问题，**选择在阶跃AI桌面助手里创建了一个“录需求”的妙计skill，按照团队的需求录入规范，通过 Prompt 教会它拿到一个原始需求后，需要从哪些维度进行需求的要素分析提炼。

然后再进行录入本地的需求表里：

![](img/de265f37525530a9358ef82f089b3de6.png)

整个过程其实很像在带一个初级产品经理。

> 一旦通过妙计 Skill 把需求拆解的标准和录入规范教给它，后续就不需要再反复解释背景和格式，它会按照既定方式，稳定地完成工作。

妙计使用起来也非常方便，在唤起AI助手后，通过输入“`/`”就可以选到这个录需求的Skill，然后再把用户需求相关的帖子内容提供给它，它便会按照 skill 定义好的需求录入规范，先对需求进行信息提取。

然后自动写入到我电脑本地的需求池管理表中：

![](img/50f04973c4afd9ef7e0fa94154c23135.png)

## 场景三：竞品调研

在启动需求设计前，通常还会去进行竞品分析，过往为了更好地了解竞品最新动态

**作为产品经理**通常会去定期去下载他们新发布的一些产品宣传物料（比如白皮书之类的），之前下载后都需要一份份打开进行阅读整理， 从中发现竞品是否有一些新的方向。

> 现在这个场景用具备本地文件能力的阶跃AI助手就刚刚好，把所有资料都下载到一个文件夹中，然后直接让它对文件夹里面的ppt，pdf等格式文件进行总结。

直接就可以获取其中一些有价值的信息：

![](img/208b1c76079f19291c372321b6bff836.png)

## 场景四：产品设计

除了通过自定义妙计 Skill 来封装自己的工作流程外，阶跃 AI 桌面伙伴让人觉得非常惊喜的一点是：

它对 Claude Skill 生态是兼容的。

> 这意味着，很多已经在 Claude 社区中被反复验证过的成熟 Skill，都可以被直接引入到桌面级 Agent 中使用，而不只是停留在对话层面。

在产品设计阶段，就找到一个非常实用的 Claude Skill。

它的使用方式很简单：**只需要提供一张产品 UI 截图**，就能对整个界面进行系统性的分析，包括布局结构、信息层级、视觉规范，甚至还能进一步生成可运行的代码 demo，用于快速验证设计思路。

> 对产品经理来说，这类能力的价值非常明确—— 当我们在讨论设计方案时，不再只是凭感觉说「这个布局好不好」「这个层级清不清晰」，而是可以基于一套相对客观、结构化的分析结果来展开讨论。

整个 Skill 的引入过程也并不复杂。

先前往 Claude Skill ，下载对应的 Skill 文件包后在本地解压：

![](img/0ae23e110e4d59c81726f0ceb33fda65.png)

随后在阶跃 AI 桌面伙伴中，通过输入 “`/`” 唤起妙计创建入口，将 Skill 文件夹整体上传，再将 `Skill.md` 文件中的 `name` 和 `description` 复制到妙计指令中，并在末尾补充一句“当需要阅读 `Skill.md` 时，请查阅 `Skill.md` 全部内容，并基于 `Skill.md` 的指引查看其余文件。

**下面是可直接复用的指令：**

![](img/bf1493149241d3caf54067ddfe9bb914.png)

![](img/c65180ee1b5acf5018e2a17810718fbf.png)

完成保存后，这个 Claude Skill 就可以作为一个妙计，被直接调用了。

在实际使用中，只需要把产品的 UI 截图交给它，它就会从布局结构、布局层级、颜色方案、字体系统、间距系统等多个维度，对界面进行专业 UI参数的拆解和分析：

![](img/c91304b83c2b9e57efbe6ffde41cdeb7.png)

有了这些信息作为基础，后续无论是和 UI 设计师讨论方案，还是在不同产品之间做横向对比，都会变得更加具体、也更容易达成共识，而不是停留在主观判断层面。

## 场景五：数据分析

做完产品设计，需求开发上线后，还得观察上线后的数据效果，过往也是需要人工来洞察数据的变化，在这个场景下，于是也尝试用阶跃AI 助手来帮我。

打**开“同步应用”的开关后，在浏**览器里打开google analytics，然后通过快捷键唤起它，当前正在查看的页面便自动作为上下文信息同步进去，然后就可以直接让它来进行分析：

![](img/e6312f8d099c15c38b58ddfcced40da6.png)

在分析的时候，它还会先确认分析诉求，确认后便可以结合对当前数据报告内容的理解，直接生成一份数据分析建议：

![](img/99fa11ad4d5f07a1555fb54dba5e04c3.png)

**“当前应用”能力的引入，本质上**让 AI 具备了这种“理解我们正在看什么”的能力，让数据分析从一个需要频繁切换视角的过程，变成了一次更自然的协作。
