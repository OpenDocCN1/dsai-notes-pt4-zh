# Claude Skills：产品经理必读

> 来源：[https://qqs7y1hozd1.feishu.cn/docx/Sh2Ud6Sneoa4tEx10mJcJOyjnLg](https://qqs7y1hozd1.feishu.cn/docx/Sh2Ud6Sneoa4tEx10mJcJOyjnLg)

上周，我陷入了一个繁琐的过程，为利益相关者创建产品路线图演示文稿。你知道这个流程——从 Notion 中提取零散的想法，从多个电子表格中提取数据，从 Slack 线程中收集反馈，然后以某种方式将所有这些内容转换成一个精美的 PowerPoint，使我们的季度计划看起来连贯且具有战略性。

我已经花了两个小时，这时我想起读过一篇关于名为"Skills"的 Claude 新功能的文章。一时兴起，我让 Claude 使用我们的品牌指南创建演示文稿。接下来发生的事情真的让我惊讶。

Claude 不仅仅生成了一个通用的幻灯片。它整合了我需要的结构，应用了与我们公司风格相匹配的格式（我将其保存为自定义 Skill），从我凌乱的电子表格中创建了数据可视化，甚至标记了我时间线中的不一致之处。整个过程可能只花了 15 分钟，而不是通常的 3-4 小时。

那时我意识到：Skills 不仅仅是另一个 AI 功能。它从根本上改变我们可以委托给 AI 的内容，以及我们作为产品经理的工作方式。

### 1、Claude Skills 是什么？（简单解释）

Claude Skills 于 2024 年 10 月正式作为"Agent Skills"推出，并于 2024 年 12 月大幅扩展，它是模块化功能，教 Claude 如何以可重复的、专业化的方式执行特定任务。

将 Skills 视为自定义培训模块。您不必每次都向 Claude 解释相同的过程（“这是我们公司格式化 PRD 的方式"或"这是我们分析用户数据的方式”），而是将这些指令一次性打包到 Skill 中。从那时起，Claude 自动识别该 Skills 何时相关并应用它。

**技术定义**：Skills 是包含指令、脚本和资源的文件夹，Claude 动态加载这些内容以执行专业任务。它们可以包括：

+   包含指令和过程的 Markdown 文件

+   用于复杂操作的可执行代码

+   模板和示例

+   特定领域的知识**
实际应**用：Skills 将 Claude 从通用 AI 转变为了解您的工作流程、您的品牌指南、您的数据分析方法和您的组织流程的专家。

### 2、简史：Skills 如何演变

了解 Anthropic 何时以及为何引入 Skills 有助于解释为什么这在现在很重要：

**2024 年 10 月**：Anthropic 悄悄推出了 Agent Skills 作为测试版功能。最初，它侧重于开发者——通过 API 和 Claude Code 提供。这个想法很简单：让开发者打包专业功能，Claude 可以在相关时调用这些功能。

2024 年 12 月 18 日：重大扩展。Anthropic 使 Skills 在 claude.ai 上可用，为 Team 和 Enterprise 计划引入了组织范围的管理，推出了 Skills Directory，包含来自 Notion、Figma、Canva 和 Atlassian 等公司的合作伙伴构建的 Skills，最重要的是，在 agentskills.io 上发布了 Agent Skills 作为开放标准。

**2025 年 1 月**：Skills 与 Claude 的其他功能集成，如 Memory、Extended Thinking 和新的 Cowork agent。Skills Directory 大幅扩展，自定义 Skills 创建对非技术用户变得更加可访问。

当前状态（2026 年 1 月）：Skills 现在可供 Pro、Max、Team 和 Enterprise 用户使用。您可以使用预构建的 Anthropic Skills（用于 Excel、PowerPoint、Word、PDF），从目录中安装合作伙伴 Skills，或创建针对您的确切工作流程定制的自定义 Skills。

这种演变显示了 Anthropic 的策略：从开发者开始，证明概念，然后向所有人普及。而且它正在发挥作用。

### 3、Skills 对产品经理为何重要

作为 PM，我最初将 Skills 视为"只是另一个功能"。我错了。以下是 Skills 为什么对我们的工作真正改变游戏规则：

#### 3.1 它们解决了"重复解释"问题

您向 Claude 解释过多少次 PRD 格式？还是用户故事结构？还是您公司的优先级框架？每次您开始新对话时，您都在重新教 Claude 您的流程。

Skills 解决了这个问题。创建一个包含您公司格式、必需部分和语气的"PRD 模板"Skill 一次。从那时起，每当您要求 Claude 帮助处理 PRD 时，它会自动加载该 Skill 并遵循您的模板。不再需要复制粘贴说明或"我们这里做事的方式"的链接。

#### 3.2 它们实现了真正的专业化

Claude 擅长一般任务。但产品管理需要领域专业知识。Skills 让您教 Claude：

+   您特定的市场和竞争格局

+   您公司独特的产品开发方法

+   行业特定的术语和框架

+   您组织的决策标准
例如，我创建了一个"用户研究分析"Skill，其中包括我们的特定研究问题框架、我们如何对见解进行分类，以及我们向利益相关者展示发现的格式。现在，当我与 Claude 分享访谈记录时，它会自动应用我们的方法，而不是使用通用的分析方法。

#### 3.3 它们扩展了您的机构知识

这是最重要的。每家公司都有工作流程、最佳实践和部落知识，这些知识存在于人们的头脑中或分散在 Confluence 页面上。Skills 让您封装这些知识，以便始终如一地应用它们。

我们团队为以下内容创建了 Skills：

+   我们如何编写功能规格（使用我们特定的模板和必需部分）

+   我们如何分析 A/B 测试结果（使用我们的统计显著性阈值和报告格式）

+   我们如何构建季度规划文档（使用我们的 OKR 格式和战略框架）

+   我们如何创建利益相关者更新（包含高管真正关心的信息）
这意味着新 PM 可以立即利用机构知识，而不是花费数月时间学习"我们这里做事的方式"。

#### 3.4 它们与您的实际工具集成

通过 Skills Directory 和 MCP（模型上下文协议）连接器，Skills 可以与您实际使用的工具一起工作：

+   **Notion Skills**：根据您的 Notion 工作区结构格式化您的产品文档

+   **Figma Skills**：生成与您团队的 Figma 惯例匹配的设计规格

+   Jira/Asana Skills：按照您团队的特定格式和工作流程创建票据

+   **Slack Skills**：按照您团队的沟通风格起草更新
这不是理论上的。我正在使用一个自定义 Notion Skill，它根据我们团队的模板自动格式化我的会议记录，标记相关人员，并建议将它们归档到哪个工作区。

### 4、Skills 实际上如何工作（不太技术化）

让我在不涉及 API 文档的情况下揭开这个机制的神秘面纱：

**渐进式披露**：当您要求 Claude 做某事时，它会扫描可用的 Skills 以寻找相关匹配。它只加载该特定任务所需的 Skills，防止信息过载。

**自动调用**：您不需要明确说"使用我的 PRD Skill"。Claude 从上下文中识别到您正在处理 PRD，并自动加载相关 Skill。

**可组合性**：多个 Skills 可以一起工作。如果您正在创建产品路线图演示文稿，Claude 可能会同时加载您的"品牌指南"Skill、"路线图模板"Skill 和"数据可视化"Skill。

**执行能力**：Skills 可以包含可执行代码，不仅仅是说明。这意味着 Skill 可以实际执行操作（如数据分析或文件格式化），而不是仅仅给 Claude 关于如何做的说明。

**版本控制**：通过 API 和 Console，您可以管理 Skills 的不同版本，回滚更改，并在流程演变时更新它们。

### 5、真实示例：PM 如何使用 Skills

让我分享我的工作和其他 PM 的具体示例：

#### 示例 1：自动化竞争分析

**问题**：每个月，我花 2-3 小时审查竞争对手的功能、定价变化和公告，以更新我们的竞争格局文档。

**Skills 解决方案**：我创建了一个"竞争分析"Skill，包括：

+   我们的特定竞争对手以及每个需要跟踪的内容

+   我们竞争格局文档的模板

+   评估功能对等性的标准

+   有关如何格式化发现的说明**
结**果：现在我与 Claude 分享竞争对手 URL 或截图，它会以我们的确切格式自动生成分析，标记重大变化，并建议对我们路线图的影响。原来需要 3 小时的工作现在只需要 30 分钟的审查。

#### 示例 2：用户访谈综合

**问题**：在进行 10-15 次用户访谈后，我会花数小时阅读记录，确定主题，并创建综合文档。

**Skills 解决方案**：创建了一个"用户研究综合"Skill，包含：

+   我们的研究问题框架

+   我们如何对用户反馈进行分类（痛点、功能请求、工作流程见解）

+   我们综合文档的模板

+   良好和不良综合的示例**
结**果：我上传访谈记录，Claude 生成遵循我们确切方法的综合文档。它识别主题，引用相关反馈，并根据我们的模板构建发现。我将时间花在解释上，而不是管理工作上。

#### 示例 3：技术规格生成

**问题**：编写工程师真正有用的技术规格需要了解我们特定的架构、命名约定和详细程度。

**Skills 解决方案**：我们的工程团队创建了一个"技术规格"Skill，包括：

+   我们的系统架构概述

+   命名约定和代码结构

+   规格的必需部分

+   良好编写的规格的示例**
结**果：当我描述一个功能时，Claude 生成工程师可以实际工作的技术规格。他们花更少的时间提出澄清问题，我花更少的时间来来回回。

#### 示例 4：利益相关者沟通

**问题**：不同的利益相关者需要不同的信息。高管想要战略影响，工程师想要技术细节，销售想要面向客户的消息。

**Skills 解决方案**：创建了三个 Skills：

+   “高管更新”（侧重于指标、战略影响、风险）

+   “工程简报”（技术实现、依赖关系、工作量）

+   **“销**售赋能”（客户利益、竞争定位、消息传递）
结果：我起草一份全面的更新，然后要求 Claude 使用相关 Skill 为每个受众进行调整。每个利益相关者都以他们期望的格式得到他们需要的内容。

### 6、如何创建你的第一个 Skill

创建一个基本的 Skills 惊人地直接。以下是开始的方法：

#### 步骤 1：识别重复任务

寻找您反复向 Claude 解释的东西。好的候选者：

+   您经常使用的文档格式

+   您始终遵循的工作流程

+   您定期应用的分析方法

+   您重用的沟通模板**
我的第一个 Skil**l：产品路线图演示文稿模板

#### 步骤 2：记录过程

准确写下您希望如何完成此任务。包括：

+   目的/用途

+   分步过程

+   必需元素或部分

+   良好输出的示例

+   要避免的常见错误
对于非技术 Skills，您可以完全用 Markdown 编写。无需编码。

**示例**：我的路线图 Skill 包括我们的演示结构（问题 → 解决方案 → 时间线 → 成功指标）、我们的品牌颜色、必需免责声明以及过去成功路线图的示例。

#### 步骤 3：创建 Skill 文件结构

基本的 Skills 只是一个包含以下内容的文件夹：

+   manifest.json（描述 Skill 的目的和适用时间）

+   instructions.md（您的详细过程文档）

+   examples/ 文件夹（可选，用于参考材料）

+   scripts/ 文件夹（可选，用于可执行代码）
您可以本地创建此内容，或通过 Claude Console 为 Team/Enterprise 计划创建。

#### 步骤 4：测试和完善

开始使用您的 Skill。注意：

+   Claude 是否在您期望时调用它？

+   输出是否与您的期望一致？

+   有哪些边缘情况或变体需要解决？
根据实际使用对您的说明进行迭代。

#### 步骤 5：与团队分享（如果适用）

对于 Team/Enterprise 计划，您可以在全组织范围内配置 Skills。这确保每个人都遵循相同的流程和格式。

### 7、Skills 与其他 Claude 功能的区别

Claude 有几个听起来相似的功能。以下是它们的区别：

Skills vs Projects：

+   **Projects** 提供静态背景上下文，当您在该项目中时始终加载

+   **Skills** 提供仅在相关时加载的动态过程

+   使用 Projects 用于持久知识，Skills 用于可重复流程
Skills vs Custom Instructions：

+   Custom Instructions 广泛应用于您的所有对话

+   **Skills** 是特定任务的，仅在需要时激活

+   Custom Instructions 设置一般偏好；Skills 提供专业过程
Skills vs MCP Connectors：

+   **MCP Connectors** 为 Claude 提供访问外部工具和数据（如 Notion、Slack）

+   **Skills** 教 Claude 如何有效地使用这些工具

+   **它们**协同工作：MCP 提供访问，Skills 提供过程
示例：MCP 连接器为 Claude 提供了对您的 Notion 工作区的访问。Skill 教 Claude 如何根据您团队的特定模板在 Notion 中格式化会议记录。

### 8、高级用例：Skills 发挥强大的地方

一旦您熟悉了基本的 Skills，这里就是它变得有趣的地方：

#### 可组合工作流程

多个 Skills 可以协同工作以处理复杂的工作流程。例如，我的"季度规划"工作流程涉及：

1.  "市场分析"Skill（分析竞争格局）

1.  "用户反馈综合"Skill（总结最近的客户见解）

1.  "OKR 框架"Skill（根据我们的格式构建目标）

1.  "路线图模板"Skill（创建时间线可视化）

1.  “利益相关者演示"Skill（为高管审查格式化）
我只需告诉 Claude"帮我准备 Q2 规划材料”，它就会自动协调所有五个 Skills。

#### 领域专业知识封装

对于专业行业，Skills 可以编码深厚的领域知识。例如，医疗保健 PM 可以为以下内容创建 Skills：

+   HIPAA 合规检查

+   临床试验文档

+   法规提交格式

+   医学术语和标准
Anthropic 现在提供专门针对医疗保健的 FHIR 开发和预先授权审查的预构建 Skills。

#### 团队知识扩展

作为高级 PM，我们可以将我们的专业知识打包到 Skills 中，供初级 PM 使用：

+   “[高级 PM] 如何评估功能”

+   “[高级 PM] 如何构建用户研究”

+   “[高级 PM] 如何编写有效的规格”
这加速了入职，并确保整个团队的一致质量。

### 9、开放标准：为什么重要

2024 年 12 月，Anthropic 做了一些聪明的事情：他们在 agentskills.io 上发布了 Agent Skills 作为开放标准。

**这意味着什么**：您为 Claude 创建的 Skills 不会锁定到 Claude。相同的 Skills 格式适用于采用该标准的任何 AI 平台。

**为什么重要**：您不是在构建特定于供应商的工具。随着更多 AI 平台采用该标准（他们有激励这样做），您的 Skills 变得可移植。您在创建组织 Skills 方面投入的工作具有长期性。

**当前采用**：虽然仍处于早期阶段，但开放标准方法意味着 Skills 正成为跨平台能力，而不仅仅是 Claude 功能。

这类似于 Anthropic 开源 MCP（模型上下文协议），现在正被其他 AI 平台采用。这是很好的策略——创建有用的标准，获得采用，成为领导者。

### 10、潜在的缺点和限制

让我们诚实地谈谈 Skills 不足的地方：

1.  **需要启用代码执行**

Skills 使用 Claude 的代码执行功能。如果您出于安全原因禁用了此功能，Skills 将无法工作。这对于具有严格安全政策的企业来说是一个考虑因素。

1.  **初始设置时间**

创建好的 Skills 需要时间。您需要清楚地记录流程，提供示例，并根据结果进行迭代。ROI 在那里，但不是即时的。

1.  **不理想用于高度动态的流程**

如果您的工作流程不断变化，维护 Skills 就会成为开销。它们最适合相对稳定的流程。

1.  **可能过度依赖**

存在团队在不了解底层流程的情况下依赖 Skills 的风险。初级 PM 可能会使用"功能规格"Skill，而不学习什么构成了好的规格。

1.  **质量取决于说明的质量**

垃圾进，垃圾出。编写不当的 Skill 说明会产生不一致的结果。这需要深思熟虑的文档。

1.  **限于可用计划**

Skills 仅在 Pro、Max、Team 和 Enterprise 计划上可用。免费层用户无法访问它们。

### 11、PM 的隐私和安全考虑

作为产品经理，我们需要考虑安全影响：

**Skills 可以访问的内容：**

+   您对话中的内容

+   您上传或创建的文件

+   MCP 连接的工具（如果获得许可）

+   代码执行环境**
需要小心的地方**：

+   不要在 Skill 说明中包含敏感凭证

+   注意您将哪些机构知识封装到 Skills 中

+   对于 Enterprise 计划，使用组织范围的 Skills 管理来控制访问

+   **在安装之前**从目录中审查 Skills——了解它们的用途
最佳实践：

+   仅从受信任的来源安装 Skills

+   在全组织范围内共享之前审查自定义 Skills

+   适当使用代码执行沙箱

+   遵循您公司的 AI 使用和数据政策
Anthropic 对这些风险明显透明，我很欣赏。他们没有美化赋予 AI 扩展能力的力量（和潜在危险）。

### 15、最后的想法：Skills 作为生产力倍增器

Skills 代表了我们与 AI 交互方式的转变。我们不再将 Claude 视为一个需要持续指导的非常聪明的实习生，而是将其视为一个了解我们工作流程并能半自主运营的专家。

对于产品经理来说，这很重要，因为我们的工作通常是综合信息、遵循流程和与不同受众有效沟通。Skills 使 Claude 在所有三个方面都显著更好。

真正的力量不在于任何单个 Skills——而在于拥有 10-15 个 Skills 来处理您最常见工作流程的累积效应。突然，您不再花数小时在文档、格式化和管理工作上。您花时间在实际需要人类判断的战略思考上。

这完美吗？不。有风险和限制吗？绝对有。但在过去两个月内每天使用 Skills 后，我深信这是多年来我采用的最重要的生产力改进之一。

我们仍然处于早期阶段。随着 Skills 变得更加复杂、更广泛采用且更容易创建，生产力收益只会复合。

如果您是尚未使用 Skills 的产品经理，我鼓励您尝试一下。从一个令人烦恼的重复任务开始。为此创建一个 Skill。看看它是否为您节省时间。

我猜您会在一周内创建您的第二个 Skill。
