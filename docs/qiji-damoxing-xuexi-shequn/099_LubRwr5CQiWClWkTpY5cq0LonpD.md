### Karpathy探讨LLMs的真正用途：语言只是历史遗留，核心在于符号建模

https://x.com/karpathy/status/1835024197506187617

有点悲伤和困惑的是，LLMs（“大语言模型”）和语言的关系其实不大，这只是历史遗留问题。它们其实是用于对符号流进行统计建模的通用技术。更好的名字可能是自回归变压器或类似的东西。

它们并不在乎这些符号是否恰好代表了文本片段。它们同样可以代表图像小块、音频片段、动作选择、分子或其他任何东西。如果你能把问题简化为对符号流的建模（针对任何离散符号集的任意词汇），你就可以“扔给LLM处理”。

事实上，随着LLM技术栈变得越来越成熟，我们可能会看到大量问题逐渐收敛到这种建模范式。也就是说，问题被固定在“下一个符号预测”，只是符号的使用和含义根据不同领域发生变化。

如果是这样的话，也有可能深度学习框架（例如PyTorch及其类似工具）对于大多数问题来说过于通用了。成千上万的操作和层可以随意重新配置，但如果80%的问题只需要使用LLM，这些复杂的配置还有必要吗？

我并不完全认同这个观点，但我认为它有一半是对的。

### Blaho分享：OpenAI o1团队AMA内容总结

https://x.com/btibor91/status/1834686946846597281

我们今天在与OpenAI o1团队的AMA小时中学到的内容总结：

模型名称和推理范式

+   OpenAI o1 代表AI能力的新层次，计数器重置为1

+   “预览版”表示这是完整版模型的早期版本

+   “Mini”代表o1模型的缩小版，优化了速度

+   o - 代表OpenAI

+   o1 不是“系统”，它是一个在给出最终答案前会生成长推理链的模型

+   o1的图标象征着拥有非凡能力的外星人

o1模型的大小和性能

+   o1-mini比o1-preview小得多且速度更快，因此未来会向免费用户提供

+   o1-preview 是o1模型的早期检查点，既不大也不小

+   o1-mini在STEM任务上表现更好，但世界知识有限

+   在某些任务上，特别是与代码相关的任务上，o1-mini表现优于o1-preview

+   o1的输入符号与GPT-4o一样，使用相同的分词器

+   与o1-preview相比，o1-mini可以探索更多的推理链

输入符号上下文和模型能力

+   o1模型即将支持更大的输入上下文

+   与GPT-4o相比，o1模型在处理较长和更开放的任务时不需要像以前那样拆分输入

+   o1可以在提供答案前生成长推理链，与之前的模型不同

+   当前没有办法在推理过程中暂停来添加更多上下文，但正在为未来的模型探索这一功能

工具、功能和即将推出的特性

+   o1-preview 目前不使用工具，但计划支持函数调用、代码解释器和浏览

+   工具支持、结构化输出和系统提示将在未来更新中添加

+   用户未来可能可以控制思考时间和符号限制

+   正在计划启用流式输出，并在API中考虑推理进展

+   o1的多模态功能已内建，旨在在诸如MMMU之类的任务中达到最先进的性能

推理链（CoT）

+   o1在推理过程中生成隐藏的推理链

+   目前没有计划向API用户或ChatGPT展示推理链符号

+   推理链符号被总结，但不能保证完全忠实于实际推理过程

+   提示中的指令可以影响模型如何思考问题

+   强化学习（RL）被用于改进o1的推理链，而GPT-4o无法仅通过提示达到其推理链性能

+   思考阶段看似较慢，因为它总结了推理过程，尽管生成答案的速度通常较快

API和使用限制

+   o1-mini对ChatGPT Plus用户有每周50个提示的限制

+   在ChatGPT中所有的提示计数相同

+   将推出更多API访问等级和更高的速率限制

+   API中提示缓存是一个受欢迎的请求，但尚无时间表

定价、微调和扩展

+   o1模型的定价预计每1-2年降价一次

+   一旦速率限制提高，将支持批量API定价

+   微调已在计划中，但暂无时间表

+   o1的扩展因研究和工程人才而受到瓶颈

+   未来几代模型中，推理计算的新扩展范式可能会带来显著收益

+   逆向扩展目前不显著，但个人写作提示显示，o1-preview的表现只比GPT-4o稍好（甚至稍差）

模型开发和研究见解

+   o1通过强化学习训练以实现推理性能

+   该模型展示了创造性思维，并在诸如诗歌之类的横向任务中表现出色

+   o1的哲学推理和广泛推理能力（例如破译密码）令人印象深刻

+   研究人员使用o1创建了一个GitHub机器人，能够准确通知相关CODEOWNERS进行审查

+   在内部测试中，o1自己给自己出难题来衡量其能力

+   宽泛的世界领域知识正在增加，并将在未来版本中改善

+   未来版本的o1-mini计划使用更新的数据（当前是2023年10月）

提示技术和最佳实践

+   o1从提示风格中受益，尤其是在提供边缘案例或推理风格时

+   与早期模型相比，o1模型对提示中的推理线索更敏感

+   在检索增强生成（RAG）中提供相关上下文可以提高性能；不相关的片段可能会削弱推理能力

总体反馈和未来改进

+   由于处于早期测试阶段，o1-preview的速率限制较低，但会逐步提高

+   正在积极研究改进延迟和推理时间

显著的模型能力

+   o1能够深入思考诸如“生命是什么？”之类的哲学问题

+   研究人员发现o1在处理复杂任务和从有限指令中进行广泛推理的能力令人印象深刻

+   o1的创造性推理能力（如通过自我测验来评估其能力）展示了其高水平的问题解决能力

### 北大对齐团队独家解读：OpenAI o1开启「后训练」时代强化学习新范式

https://mp.weixin.qq.com/s/FXGdJA8OyZvLl89rXJiyAQ

OpenAI o1模型在数学、代码、长程规划等复杂问题上取得显著进展，技术突破的背后离不开强化学习（RL）与后训练阶段（Post-Training）的计算量扩展，以及新扩展律的应用。

1. 后训练扩展律（Post-Training Scaling Laws）

+   **后训练阶段的关键**：OpenAI o1在发布后，凭借强化学习和推理阶段思考计算量的提升，取得了突破性进展。这个新扩展律提出，模型的计算量不再仅与参数量有关，还包含RL探索时LLM推理的计算量。推理和反思的时间同样影响模型最终表现。这意味着在后训练阶段投入足够的算力至关重要。

+   **模型表现**：o1在竞争性编程（Codeforces）中达到了第89百分位，在美国数学奥林匹克竞赛（AIME）中跻身前500名，并在GPQA的物理、生物和化学问题上超越了人类博士水平的准确性。

2. 强化学习与隐式思维链

+   隐式推理（Rationales）：o1的技术突破不仅在于强化学习（RL），还在于模型学习了生成合理推理过程的能力，这种隐式的推理过程对模型解决复杂问题至关重要。

+   **MCTS与STaR的结合**：传统的蒙特卡洛树搜索（MCTS）和强化学习（RL）方法被用于诱导模型生成合理推理过程，而非直接搜索答案。类似于STaR[1]的扩展，o1使用RL和自我引导（Bootstrap）生成合理推理，将这些推理融入训练过程，从而使模型学会如何思考问题。

+   **引入Critic Model**：面对复杂推理任务，模型引入了更强的Critic Model来提供准确的反馈，优化推理过程。这使得模型能够在更复杂的问题上实现更细粒度的监督和奖励。

3. 技术要点

+   **动态推理Token**：o1引入了动态的Reasoning Token来触发“隐式思维链”，使模型在生成答案前能够进行深入思考。这极大地减少了不必要的计算资源消耗，赋予模型更强的推理能力。

+   **推理时间作为扩展维度**：o1模型的性能提升不仅依赖于预训练阶段，更在于Post-Training阶段的RL训练和推理时间的投入。推理时间成为新的扩展维度，为模型提供更强的思考能力。

4. 数据飞轮与未来展望

+   **数据飞轮**：通过自我反思，o1模型不断生成高质量训练数据，形成数据飞轮，促进自我强化和性能提升。

+   Post-Training为突破方向：随着参数规模扩展的边际效益递减，模型性能的进一步提升将依赖于Post-Training阶段的强化学习和推理。o1的发布标志着RL下Post-Training Scaling Laws时代的到来，强化学习和隐式思维链的探索成为大模型未来突破的关键。

### KAN的横空出世，彻底改变了神经网络研究范式！

https://mp.weixin.qq.com/s/l2sNIem5NBAWZ0d26NMcqw

2024年4月，麻省理工学院（MIT）和加州理工等机构的研究人员推出了一种全新的神经网络架构——Kolmogorov-Arnold Network（KAN）。该架构突破了传统神经网络的“黑盒”问题，为神经网络研究带来了全新的透明性和可解释性。

1.  神经网络的局限性与KAN的诞生

+   神经网络目前是AI领域最强大的工具，但其一个基本组件——多层感知器（MLP），一直以来都是“黑盒”，很难解释其内部工作原理。

+   KAN的诞生，源于20世纪数学家Kolmogorov和Arnold的数学思想。他们证明，任何多变量函数都可以转换为一系列单变量函数的组合。然而，由于这些单变量函数的不平滑性，该理论曾被认为在实际神经网络中不可行。

+   MIT研究生Ziming Liu勇敢地重新探讨了KAN，并发现了其新的应用潜力。在导师Max Tegmark的关键建议下，他们尝试了多层KAN架构，成功展示了KAN的可行性。研究团队后来扩展到多达六层的KAN，证明其在处理复杂输出函数时的卓越性能。

1.  KAN的技术优势

+   **不同于MLP的函数拟合方式**：KAN通过使用非线性、可学习的函数作为“边”，而非数值权重，使其在函数拟合上更加灵活和敏感。

+   **可解释性**：KAN不仅能给出预测，还能解释预测的背后原理，揭示物理过程的数学方程。例如，KAN能够准确地表示某个函数，并以更具可解释性的方式连接数据点。

+   **科学任务中的优势**：在科学领域的实际任务中，KAN展现出压倒性优势。它在处理数学的“纽结理论”和凝聚态物理中的Anderson局域化问题上，都比MLP表现更优。

1.  KAN在科学界的影响

+   研究团队展示了三层及多层KAN在科学任务中的应用潜力，为进一步研究铺平了道路。KAN不仅实现了预测，而且解释了预测的原因，这正是MLP难以做到的。

+   在几个月内，KAN引起了AI研究界的高度关注，并激发了多方跟进研究。例如，清华大学团队研究的Kolmogorov-Arnold-informed Neural Network（KINN）在求解偏微分方程方面优于MLP。

+   新加坡国立大学研究人员分析KAN和MLP的性能，指出KAN在科学任务中的可解释性明显优于MLP，而MLP则在计算机视觉和音频处理方面表现更佳。

### 通过减少 Embedding 变异性实现稳定的语言模型预训练

贡献人：

链接：https://arxiv.org/abs/2409.07787

稳定的**预训练对于实现性能更优的语言模型至关重要。然而，由于显**著的计算成本，无法通过在每一步计算梯度方差来跟踪预训练的稳定性。鉴于浅层网络更容易出现梯度爆炸（见第2.2节），我们探讨了**Token Embedding Variability（TEV）作为一种简单且高效的代理方法，用于评估具有预层归一化的语言模型的预训练稳定性。此外，我们提出了Multi-head Low-Rank Attention（MLRA）**架构，通过限制输出嵌入方差的指数增长，从而缓解这种不稳定性，防止梯度爆炸（见第3.2节）。在GPT-2模型上应用MLRA的实验证明，尤其是在更深层的模型中，稳定性得到了提高，困惑度（perplexity）降低。

### OneEdit：一种神经-符号协作知识编辑系统

贡献人：

链接：https://arxiv.org/abs/2409.07497

自人工智能诞生以来，知识表示一直是其核心目标。符号知识图谱（Knowledge Graphs, KGs）和神经大型语言模型（Large Language Models, L**LMs）都可以**用**于表示知识。KGs 提供了高度**准确和明确的知识表示，但在可扩展性方面存在问题**；而LLMs则提供了广**泛的知识覆盖，但训练成本显著，并且在精确和可靠的知**识操作方面存在**困难。为此，我们引入了OneEdit，一种用于协作知识编辑的神经-符号原型系统，利用自然语言实现易用的知识管理，结合KG和LLM的优势。OneEdit由三个模块组成：1.  解释器（Interpreter）：负责与用户进行自然语言交互；2.控制器（Controller）：管理来自不同用户的编辑请求，利用KG进行回滚以处理知识冲突，并防止有害知识攻击；3.编辑器（Editor）：利用控制器的知识对KG和LLM进行编辑。我们在两个新的KG数据集上进行了实验，结果表明，OneEdit能够实现优越的性能。

贡献人：

本文介绍了Kolmogorov-Arnold Networks（KAN），作为迁**移学习**中传统线性探测方**法的增****强。线**性探**测通常应用于预训**练模型的最**后一层，其局限在于**无法对数据中的**复杂关系进行建模****。为了****解决这**一问题，我们提出用KAN替代线性探测层，K**AN利**用基于样条的表示来近似复杂函数。在本研究中，我们将KAN与在ImageNet上预训练的ResNet-50模型集成，并在CIFAR-10数据集上评估其性能。我们进行了系统的超参数搜索，重点优化KAN的灵活性和准确性，主要关注网格大小和样条度数（k）。结果表明，KAN在多种配置下持续优于传统线性探测，实现了准确性和泛化能力的显著提升。这些发现表明，KAN在迁移学习中提供了比传统线性探测技术更强大和适应性更高的替代方案。

### **衡量神经架构训练效率的框架**

贡献人：

链接：https://arxiv.org/abs/2409.07925

在**神经**网**络系统开发中，衡**量效率是一个开放的研究问题。本文提出了一个实验框架，用于衡量神经架构的训练效率。为了展示我们的方法，我们分析了卷积神经网络（Convolutional Neural Networks, CNNs）及其贝叶斯等效模型（Bayesian Convolutional Neural Networks, BCNNs）在MNIST和CIFAR-10任务上的训练效率。我们的结果显示，随着训练的进行，训练效率呈下降趋势，并且在给定的神经模型和学习任务下，不同的停止标准会导致训练效率的变化。我们还发现，训练停止标准、训练效率、模型规模之间存在非线性关系。

### GPU渲染之路：从图形引擎到内核驱动(三、用户态图形驱动层)

https://zhuanlan.zhihu.com/p/651364842?utm_psn=1818309623779827712

1.  **图形系统分层结构：**

+   **应用层：** 包含各种图形应用，如游戏、模拟器、设计工具，通过下层服务和硬件实现交互和图形渲染。

+   **跨平台层：** 包括图形引擎和工具（如Unity、Unreal Engine、bgfx），提供跨平台支持以及高级功能（物理模拟、光照、动画等）。

+   **用户态图形驱动层：** 涉及操作系统和图形API（如OpenGL、DirectX），为开发者提供与图形硬件交互的接口。用户态驱动在不直接与硬件交互的情况下，通过API函数将渲染任务下发给硬件驱动。

+   **内核态驱动层：** 连接操作系统与硬件，负责硬件初始化、资源管理、设备指令转换等。

+   **硬件层：** 包括GPU、显示器和输入设备，负责执行并行计算和图形渲染。

1.  **图形编程历史：**

+   早期图形编程需要直接与硬件交互，难以移植。为此，70年代出现了图形API的雏形，80年代ISO发布PHIGS标准，解决跨平台绘图问题。OpenGL在90年代出现，使得图形编程跨平台化、标准化。

+   **GPU的诞生：** 随着图形处理需求激增，NVIDIA在1999年发布了GeForce 256，开启GPU专门负责并行计算的时代，提高了图形渲染效率。

1.  **GPU驱动体系：**

+   **用户态图形驱动：** 在用户态与图形API（如OpenGL、Vulkan）进行交互，实现了API标准，并将其转化为硬件指令。核心工作在GPU厂商开发的硬件驱动程序中完成，以OpenGL为例，通过gl_context结构体和dd_function_table函数表调用特定GPU的驱动实现。

+   **Mesa3D：** 是OpenGL的一种开源实现，它将应用程序的API调用转换为适合各类硬件的平台操作。Mesa3D分为API实现层、核心部分、硬件驱动和Gallium3D架构，最终通过抽象工厂模式，将OpenGL的API调用转化为底层GPU驱动操作。

1.  **OpenGL的渲染过程：**

+   glFlush、glBegin、glVertex2f、glEnd等API的调用路径中，经过了用户态驱动的函数表选择，将渲染指令封装成批处理缓冲区（batchbuffer），通过Linux的ioctl机制调用内核态驱动，提交给GPU执行。

+   Mesa3D中的OpenGL初始化过程通过_mesa_initialize_context函数创建gl_context结构体，绑定dd_function_table中的驱动函数，如Intel显卡的intel_glFlush方法，负责具体的硬件操作。

1.  **多线程渲染和并行编程：**

+   多线程渲染可分为两部分：一是CPU侧的并行渲染指令下发；二是GPU侧的渲染指令执行，由GPU的内置调度策略实现。

1.  **GPU通用计算：**

+   CUDA/OpenCL对标Direct3D/OpenGL，属于用户态驱动范畴，提供了在GPU上进行通用计算的接口，与图形驱动体系处于同一层级。

1.  **AI与存储：** 包括存储在AI技术与应用中的使用、数据中心架构、互连技术、生成式AI，以及AI与机器学习技术等，重点探讨了如何为AI提供更高效的存储支持（AIML-101至AIML-303系列）。

1.  CXL（Compute Express Link）： 涉及CXL Fabric管理、CXL内存池化与分层、CXL在AI领域的应用等（CXLT-102至CXLT-302系列），反映出CXL在存储领域的重要性以及其对未来数据中心架构的潜在影响。

1.  **计算型存储：** 探讨了计算型存储的应用案例、未来发展方向及相关技术创新（COMP-102至COMP-202系列），强调了在数据密集型任务中存储与计算一体化的趋势。

1.  **数据中心与冷存储：** 涉及超大规模应用、企业级存储（DCTR系列）和冷存储市场趋势及技术解决方案（COLD系列），反映了对不同数据生命周期存储策略的探索。

1.  **SSD技术：** 包含闪存和内存控制器技术、SSD在计算型应用中的角色、优化SSD性能与寿命、功耗优化以及新型接口和形态等（SSDT-101至SSDT-304系列）。探讨了在SSD固态盘领域，性能、可靠性和能效的提升方向。

1.  **内存技术：** 覆盖了新型内存、面向AI的内存解决方案、异构性能解决方案（OMEM系列），以及DRAM技术的未来发展方向（DRAM-101至DRAM-103）。

1.  **数据安全：** 聚焦AI和ML攻击、量子密码技术及设备安全等（DSEC系列），强调了数据安全在存储和计算领域日益重要的角色。

1.  **测试与标准化：** 涵盖NVMe设备测试、通用测试方法、UCIe（Universal Chiplet Interconnect Express）技术机会与益处，以及各类存储技术标准的推进（TEST、UCIC、SPOS系列）。

### 为基础模型合成更多样的训练信号（自奖励/自博弈/自交互）

https://zhuanlan.zhihu.com/p/719720736?utm_psn=1818303376141709313

现有的强化学习（RLHF）在大模型对齐方面取得了进展，但面临扩展性问题和高标注成本。近期研究聚焦于自奖励（Self-Rewarding）、自博弈（Self-Play）和多轮对话策略，以解决这些瓶颈。以下为技术要点：

1.  **自奖励：** 提出了让模型自身生成奖励信号的方法，以减少对人工标注的依赖。通过“LLM-as-Judge”提示，模型能够在迭代训练中自我评估并提升指令遵循能力。实验表明，自奖励模型（如对Llama 2 70B进行三次迭代微调）在多个排行榜中超越了其他模型。

1.  **AI反馈的RL：** RLAIF通过使用现成的LLM生成偏好数据来训练奖励模型，展示了在摘要生成和对话生成任务中与RLHF相当的性能。直接RLAIF（d-RLAIF）直接使用LLM作为奖励信号，规避了陈旧性问题，显著提升了策略性能。通过AI反馈替代人工标注，成本降低至十分之一。

1.  **自博弈微调（SPIN）：** 利用自对抗机制，模型通过与自身生成的实例对弈实现自我提升。该方法在没有额外人类数据的情况下，迭代性地优化模型，使其在指令遵循任务上超越现有直接偏好优化（DPO）方法，充分挖掘人类标注数据的潜力。

1.  **多轮对话：** ArCHer框架引入了层次化多轮强化学习，结合高层价值函数和低层逐字策略，优化多轮任务。实验中，该方法在样本效率和扩展性上优于现有的单轮RL方法，适用于更大规模的模型和更长时程任务。

### 如何看待 OpenAI 发布 o1 系列模型？将带来哪些变革？

https://www.zhihu.com/question/666991594/answer/3624853121?utm_psn=1818208312212213760

OpenAI o1的发布再次证明了强化学习（RL）在大模型推理能力提升中的潜力。o1模型的成功并不在于扩大模型规模或引入新的架构，而在于通过RL优化思维链（Chain-of-Thought），使模型具备更强的慢思考能力。这种方式绕过了仅依赖预训练的路径，实现了推理能力的质变。

值得注意的是，o1的两种版本（preview和mini）揭示了一个重要事实：推理能力并不一定与模型规模成正比。o1 mini借助GPT-4o mini，在狭窄领域的推理和逻辑问题上几乎能与o1 preview媲美。这个结果暗示了小模型也有可能通过强化学习优化，达到足够强大的推理能力。对于中小AI公司和学术界来说，这意味着不需要巨大的计算资源，也能实现高效推理的模型训练。

o1的推出还暴露了AI推理框架的新需求。AI推理的关键已不再仅是模型本身，而是如何优化推理过程的执行效率。现阶段，推理中的“慢思考”模式带来的时间与成本问题，将给AI基础设施带来新的优化方向。例如，如何在硬件层面加速复杂推理过程，将成为AI芯片和推理引擎公司新的竞赛领域。

o1模型也对行业内关于模型对齐（alignment）的价值进行了再定义。强化学习不仅用于提升推理能力，也用于模型对齐，以确保模型输出符合人类的价值观和偏好。o1的思维链隐藏机制表明，模型在“思考”过程中产生的中间结果，虽然不对用户开放，但在AI系统对用户的行为追踪和反馈中扮演了重要角色。未来，这种内嵌的思维链可能成为监控和优化AI行为的关键工具。

### vllm v0.6.0代码走读（一）--Batch scheduling multiple steps ahead

https://zhuanlan.zhihu.com/p/718546972?utm_psn=1818048659889192960

vLLM v0.6.0的发布带来了2.7倍的吞吐量提升和5倍的延迟降低。主要的技术优化集中在多步调度（multi-step scheduling）和大量的CPU优化，并支持Pipeline并行（PP）。Llama 3.1也得到了支持，并即将支持chunked prefill和prefix caching。

多步调度通过参数--num-scheduler-steps设置，开启后自动启用V2版本的block manager。需要注意的是，multi-step无法与speculative decode和chunked prefill共用。调度过程从llm_engine step开始，首先判断是否还有剩余步骤，通过属性remaining_steps（num_steps - current_step）计算。

multi-step执行过程中，execute_model由新的MultiStepWorker执行，prepare_input环节先获取execute_model_req的数据进行广播，如果是multi-step的首个步骤，则缓存worker输入和模型输入。模型执行过程基于缓存的frozen_model_input，实现对状态和数据结构的更新。

runner层面沿用了原先的GPU executor，但在multi-step中使用了新的worker类来实现。具体到worker执行的逻辑，主要包括prepare_input、execute_worker、和runner->execute_model三个步骤。其中，prepare_input会生成或变更ModelInputForGPU类型的对象用于输入数据处理。_prepare_model_input_tensors函数则负责缓存和状态信息的更新。

在multi-step执行阶段，每一步都进行模型推理。多步执行还会在每个step中更新seq_lens，通过CUDA并行操作来实现DECODE阶段的+1操作，从而保证数据流的正确性和同步。

由于改动较大，本文着重介绍了多步调度的核心逻辑，异步逻辑将在后续进行详细探讨。

### 当我们讨论看具身智能的时候，我们希望教机器人做些什么

https://zhuanlan.zhihu.com/p/719349307?utm_psn=1818657938560147459

在过去半年中，SLAM技术在实际应用中的比重开始下降，相关领域开始转向空间计算、无图智驾和具身智能。具身智能最早由图灵提出，旨在实现机器人应对物理世界的复杂性，体现出通用性。当前，通用性离不开强大的算力和数据支持，但是否这是实现通用人工智能的唯一途径值得思考。

神**经符号****学（N****eural****-Sy**mbolical AI）是提出的一种新的研究方向。当前机器人算法面临四个问题：1. 泛化性：现有算法的泛化能力有限，难以适应新环境。2. 黑箱性：数据驱动模型的内部机制难以理解，错误决策可能导致灾难性后果。3. 标签密集性：复杂的机器人动力学需要大量数据标注。4. 次优性：各个模块的独立训练可能导致误差累积，导致次优解。

神经符号学试图通过让机器人学习抽象概念和符号知识来克服这些问题。在此背景下，神经符号学的**推理框架出现，但在**机器人领域的具体应用还处于初期。为了更好地解决上述问题，提出了命令式学习（IL）。

**命令式学习（IL）**是一种自监督的神经符号学习框架，通过双层优化（BLO）方法，将符号推理模型与数据驱动模型结合，实现**两者的相****互学习。****IL的特**点在于它能在没有标签的情况下，通过类似梯度下降的迭代方法进行优化。IL框架由三个模块组成：1. 神经系统：从传感器数据中提取高级语义属性；2. 推理引擎：利用物理、逻辑、几何等符号过程进行推理；3. 记忆模块：存储机器人的经验和知识。整个框架通过双层优化公式，将神经系统与推理引擎对齐，从而学习生成可行的语义属性或谓词。
