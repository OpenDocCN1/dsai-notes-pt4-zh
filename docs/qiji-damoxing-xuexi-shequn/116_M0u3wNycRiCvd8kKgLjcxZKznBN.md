### 斯坦福alphaXiv讨论平台上线

贡献人：

https://mp.weixin.qq.com/s/U1x1fNltB9KGbINLtf4gDg

斯坦福大学学生最近创建了 alphaXiv 平台，用于在 arXiv 论文之上进行精准的讨论。用户可以通过将 arXiv 论文链接中的 arXiv 替换为 alphaXiv 直接在论坛上打开相应论文，并针对论文中的具体段落和句子发表问题和评论。论文作者可以在平台上与读者互动，回答问题。此外，用户可以对评论进行回应、点赞或反对。这一新型交流平台受到了图灵奖得主 Yann LeCun 的赞扬，并且已经帮助一些论文作者，如《KAN or MLP: A Fairer Comparison》的一作 Runpeng Yu，进行了有效的交流。网友认为 alphaXiv 推动了学术协作和交流，使研究变得更加容易。

链接 https://alphaxiv.org/

### 大语言模型：通过重复采样扩展推断计算

贡献人：

链接：http://arxiv.org/abs/2407.21787v1

摘要：增加用于训练语言模型的计算量显著提高了它们的能力。然而，在推理方面，我们通常将计算量限制为每个问题仅有一次尝试。本文探讨了将推理计算作为另一种扩展维度的可能性，通过增加生成的样本数量。在多个任务和模型中，我们观察到覆盖率 - 由任何尝试解决的问题比例 - 随着样本数量增加而增加了四个数量级。在编码和形式证明等领域，所有答案都可以自动验证，这些覆盖率的增加直接转化为更好的性能。当我们将重复采样应用于SWE-bench Lite时，DeepSeek-V2-Coder-Instruct的问题解决比例从使用一个样本的15.9％增加到使用250个样本的56％，超过了使用更强大的前沿模型的一次尝试的43％，单样本的一流技术。此外，使用当前的API定价，用五个样本放大更便宜的DeepSeek模型比支付来自GPT-4o或Claude 3.5 Sonnet的单个样本更划算，并解决更多问题。有趣的是，覆盖率与样本数量之间的关系通常是对数线性的，并可以用指数化的幂律进行建模，这表明存在推理时间扩展定律。最后，我们发现在没有自动验证器的领域，从许多生成物中识别正确的样本仍然是未来研究的重要方向。当解决来自GSM8K和MATH的数学文字问题时，LLama-3模型的覆盖率可以在10,000个样本下增长到超过95％。然而，常见的从样本集合中选择正确解决方案的方法，如多数投票或奖励模型，在几百个样本之后就达到了瓶颈，并且不能完全根据样本预算进行扩展。

### 衡量重要性：内在距离保持作为嵌入质量的稳健度量

贡献人：

链接：http://arxiv.org/abs/2407.21590v1

无监督嵌入是许多机器学习应用的基础，但它们的评估仍然是一项具有挑战性的任务。传统的评估方法通常依赖于外部变量，比如在下游任务中的性能，这可能引入混淆因素并掩盖嵌入的真实质量。本文介绍了内在距离保持评估（IDPE）方法，这是一种基于原始空间和嵌入空间中数据点之间马氏距离保持的新颖评估嵌入质量的方法。通过一个简单的示例，我们展示了外部评估方法的局限性，突出了它们如何可能导致关于嵌入质量的误导性结论。IDPE通过提供一个任务无关的度量，衡量嵌入如何保留原始数据的内在结构，来解决这些问题。我们的方法利用高效的相似性搜索技术，使其适用于大规模数据集。我们将IDPE与建立好的内在指标如可信度和连续性，以及外部指标如平均排名和平均互倒排名进行了比较。我们的结果表明，IDPE在各种情况下提供了更全面、更可靠的嵌入质量评估。我们使用IDPE评估了PCA和t-SNE嵌入，揭示了它们的性能与传统度量所未能捕捉到的见解。这项工作通过提供一个健壮、高效且可解释的嵌入评估方法，为领域做出了贡献。IDPE专注于内在特性，为寻求开发和评估各种机器学习应用的高质量嵌入的研究人员和从业者提供了一个有价值的工具。

### **大规模协作学习**

贡献人：

链接：http://arxiv.org/abs/2407.21319v1

合作在人类智能发展中起着关键作用；而且，它也是人工智能（AI）最近革命性进步的基础，这些进步是由基础模型推动的。具体来说，我们揭示了基础模型的训练可以被解释为一种大型合作学习（缩写为大学习），在这种学习中，大量学习个体/任务合作以从数据的多种预测角度接近数据的独特本质，利用一个通用模型。所呈现的大型学习因此统一了基础模型的大多数训练目标，使它们的基本假设同时暴露出来。我们设计了定制的模拟来展示大型学习的原则，基于这一原则我们为基础模型的成功提供了学习视角的合理解释，以及有趣的附带产品。此外，我们揭示大型学习是升级传统机器学习范式的新维度，对为相关应用赋予新生机非常有价值；作为一个说明性的例子，我们提出了BigLearn-GAN，这是一个具有多功能数据采样能力的新型对抗训练基础模型。源代码请访问https://github.com/YulaiCong/BigCooperativeLearning。

### 具有泛化值函数逼近的可处理且可证明高效的分布式强化学习

贡献人：

链接：http://arxiv.org/abs/2407.21260v1

分布式强化学习通过有效捕捉环境随机性来提高性能，但其有效性的全面理论理解仍然难以捉摸。在本文中，我们提出了一个关于分布式强化学习在有限的周期性马尔可夫决策过程设置中以一般价值函数逼近的后悔分析。我们首先引入了一个关键概念——贝尔曼无偏性，通过统计函数动态规划实现一个易于处理且可学习的更新。我们的理论结果表明，用有限数量的矩函数来逼近无穷维回报分布是学习统计信息的唯一方法，其中包括非线性统计函数。其次，我们提出了一个经过证明有效的算法 $\texttt{SF-LSVI}$，实现了一个后悔上限为 $\tilde{O}(d_E H^{\frac{3}{2}}\sqrt{K})$，其中 $H$ 是水平， $K$ 是剧集的数量， $d_E$ 是一个函数类的误导维数。

### 通过滑动生成和自洽性提高大语言模型在总结中的忠实度

贡献人：

链接：http://arxiv.org/abs/2407.21443v1

尽管大型语言模型（LLMs）在各种任务中展示出了令人印象深刻的性能，但它们仍然受到所谓幻觉的事实不一致问题的困扰。例如，LLMs偶尔会生成与源文章不符的内容，并且倾向于提取出现在上下文开始和结尾的信息，特别是在长文本摘要中。受这些发现的启发，我们提出通过督促LLMs更公平、更忠实地处理整篇文章来改善它们在摘要中的忠实度。我们提出了一种新的摘要生成策略，名为SliSum，它利用滑动窗口和自一致性的思想。具体来说，SliSum将源文章分成重叠的窗口，并利用LLM为窗口中的内容生成局部摘要。最后，SliSum使用聚类和多数投票算法聚合所有局部摘要，以生成更忠实的整篇文章摘要。广泛的实验表明，SliSum显著改善了包括LLaMA-2、Claude-2和GPT-3.5在内的各种LLMs在短文本和长文本摘要中的忠实度，同时保持了它们的流畅性和信息量，而无需额外的微调和资源。我们进一步进行定性和定量研究，探讨了SliSum为何有效以及SliSum中超参数对性能的影响。

### **LLMs的经济有效幻觉检测**

### 适应性大语言模型的预训练数据检测：通过意外的token

贡献人：

链接：http://arxiv.org/abs/2407.21248v1

摘要：随着大型语言模型(LLMs)的广泛应用，人们对其不透明的训练数据引发了隐私、安全和版权方面的担忧，这带来了检测预训练数据的问题。本文提出了一种自适应预训练数据检测方法，该方法减轻了对LLMs的直接记忆能力的依赖，并有效地增强了识别能力。我们的方法适应性地定位输入中的“惊喜token”。如果智能体对某个token的预测是“确定但错误”的，这意味着概率分布的香农熵较低并且正确token的概率也较低。通过使用惊喜token的预测概率来衡量惊喜程度，检测方法基于一个简单的假设，即对于模型来说，看到已见数据比看到未见数据更不惊喜。该方法无需访问预训练数据语料库或额外的训练，展现了与现有方法相比的稳定增强，在各种基准和模型上进行了多种实验，在某些情况下最大提升达到了29.5\%。我们还引入了一个基于全新框架开发的新基准Dolma-Book，该基准利用了模型训练前后收集的书籍数据进行进一步评估。

文章首先介绍了流水线并行性的概念，它使得在多个 GPU 上训练大型模型成为可能。以 Huggingface 的 BLOOM 模型为例，说明了如何在 384 个 GPU 上进行分布式训练。接着，详细讨论了朴素模型并行性的实现和存在的问题，如低 GPU 使用率、通信和计算不交织、高内存需求等。为了解决这些问题，提出了 GPipe 算法，它通过将小批量拆分为微批量，提高了 GPU 的使用效率，并减少了内存需求。然而，GPipe 仍然存在一些低效之处，如通信和计算的交织、管道气泡和内存需求等。PipeDream 算法进一步改进了 GPipe，通过交错不同微批的前进和后退过程，减少了内存需求。文章还分析了流水线并行性的通信量，并与数据并行性进行了比较。最后，介绍了如何将流水线并行性与数据并行性相结合，以及如何在 ShallowSpeed 库中实现 GPipe。

### vLLM源码之框架执行

贡献人：

https://zhuanlan.zhihu.com/p/710927181?utm_psn=1802246024821104641

vLLM 的整体架构包括 LLMEngine、区块管理器、KV Cache 等组件，它通过调度器按顺序更改每个请求中请求的提示的生成顺序，并实现了内存和 GPU 资源的高效管理。在内存不足时，vLLM 通过将中间计算过程交换到 CPU 内存的方式，稳定地管理这些过程。LLMEngine 是核心类，它提供了 add_request () 和 step 两个方法，用于在线和离线两种方式中添加和执行请求。

在初始化过程中，LLM 类会创建并加载模型，并且初始化 KV Cache。generate () 函数用于生成句子，它接受的参数包括 prompts、sampling_params 等，用于指定生成所需选项。SamplingParams 类定义了多种采样参数，如 n、best_of、presence_penalty、frequency_penalty 等，以控制生成过程。

LLMEngine 的执行流程涉及缓存初始化、队列管理、step 执行等环节。其中，step 执行了两个步骤：调度程序通过 Scheduler.schedule () 从队列中获取序列，并准备缓存块以应用 PagedAttention；然后通过 Worker.execute_model () 执行模型转发，生成并保存下一个标记。

调度器负责根据优先级和内存管理，对需要一次性处理的大量请求进行整理，并通过 Slot Swap Out 机制，确保有足够的内存空间来处理高优先级的 SequenceGroup。Block Manager 则负责管理逻辑块和物理块之间的映射表，以及引用计数管理，实现了类似操作系统虚拟内存的逻辑。

### 大模型微调（二）：Reward Modeling for Alignment
