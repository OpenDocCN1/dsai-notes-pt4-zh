### GitHub上超1亿开发者可直接访问全球顶级大模型，构建AI应用

贡献人：

https://mp.weixin.qq.com/s/1pbb3OuHnD-W3DQ0JPQH_g

GitHub 最近推出了一个名为「GitHub Models」的新功能，这标志着该平台不仅仅是一个代码托管平台，而是开始向 AI 工程师的全新时代迈进。该功能允许开发者在一个交互式的沙盒环境中免费试用多种知名的 AI 大模型，包括微软的 Phi-3、OpenAI 的 GPT-4o、Meta 的 Llama 3.1、Cohere 的 Command R+ 和 Mistral AI 的 Mistral Large 等。未来几个月，GitHub 还计划添加更多类型的模型，如语言、视觉等。开发者可以轻松地将这些模型集成到自己的项目中，无论是在 Codespaces 还是在 VS Code 开发环境中，都大大降低了部署 AI 模型的门槛。此外，GitHub 提供了与 Azure AI 的无缝集成，使得从开发到生产部署成为一条龙的服务。GitHub 还保证了用户隐私和数据安全，确保模型提供者无法访问用户的提示或输出数据，也不会用于训练或改进模型。不过，个人用户使用这些模型时会有一定的使用限制，例如每天最多可以访问 150 次，每分钟不超过 15 次，每次请求最多处理 8000 个 token，输出最多 4000 个 token。

### 特斯拉Dojo：埃隆·马斯克打造AI超级计算机的大计划详解

贡献人：

https://techcrunch.com/2024/08/03/tesla-dojo-elon-musks-big-plan-to-build-an-ai-supercomputer-explained/

Tesla Dojo 是 Elon Musk 为 Tesla 设计的 AI 超级计算机，旨在训练其 “全自动驾驶”（FSD）神经网络。Musk 认为，Tesla 不仅仅是一家汽车制造商，还是一个 AI 公司，通过模拟人类感知来实现自动驾驶车辆。与其他自动驾驶技术公司不同，Tesla 依赖于仅使用摄像头收集的视觉数据，并利用先进的神经网络处理数据，做出快速决策。Dojo 的开发是为了处理全球 Tesla 车辆收集的大量视频数据，并运行数百万次模拟来训练 FSD。Tesla 自己研发了 D1 芯片，专为 AI 工作负载优化，以减少对 Nvidia GPU 的依赖，这些 GPU 昂贵且供应有限。尽管如此，Tesla 仍然在短期内使用 Nvidia 硬件来训练其 AI。Dojo 的目标是通过部署多个 ExaPOD 来扩展，并且有计划开发下一代 D2 芯片以解决信息流的瓶颈。Musk 认为 Dojo 是 TeslaAI 训练计划的关键，并可能为 Tesla 创造新的业务模式。预计 Dojo 将在 2024 年 10 月达到 100 exaflops 的总计算能力。Tesla 已经开始在纽约的吉 Gaussian 工厂投资建设 Dojo 超级计算机中心。此外，Tesla 还在其奥斯汀吉 Gaussian 工厂预留了空间用于水冷的超级计算机集群。

### 云基础设施收入在本季度接近800亿美元

贡献人：

https://techcrunch.com/2024/08/02/cloud-infrastructure-revenue-approached-80-billion-this-quarter/

根据 Synergy Research 的报告，云基础设施市场在本季度的收入达到了 790 亿美元，较去年同期增长了 141 亿美元，增幅为 22%。这标志着连续第三个季度同比增长超过 20%，其中人工智能是增长的重要驱动力。尽管去年出现了一些小问题，但市场继续增长，预计在四年内市场规模将翻一番。

在市场中，Microsoft 智能云（包括 Azure）的收入为 285.2 亿美元，略低于预期，但 Azure 的增长率为 30%。亚马逊的云服务收入为 263 亿美元，增长了 19%。谷歌云首次超过 100 亿美元，同比增长了 29%。市场份额方面，亚马逊占 32%，Microsoft 占 23%，谷歌占 12%。尽管 Microsoft 在上个季度失去了约两个百分点的市场份额，但仍然以快速的速度增长。

其他公司如甲骨文和 Salesforce 也有所增长，三巨头（亚马逊、Microsoft、谷歌）占据了超过 73% 的市场份额。Synergy Research 的数据显示，市场的增长很大程度上得益于人工智能的兴起。

### Gemma 2：在实用大小上改进开放语言模型

贡献人：

链接：http://arxiv.org/abs/2408.00118v1

在这项工作中，我们介绍了 Gemma 家族的新成员 Gemma 2，它是一种轻量级的最先进的开放模型，参数规模从 20 亿到 270 亿不等。在这个新版本中，我们对 Transformer 架构应用了几种已知的技术修改，比如交错局部-全局注意力和组查询注意力。我们还使用了知识蒸馏来训练 20 亿和 90 亿模型，而不是下一个 token 预测。由此产生的模型在其大小方面提供了最佳性能，并且甚至提供了与两到三倍大小的模型竞争性的选择。我们把所有模型发布给社区。

### 纠正大语言模型中的负偏见通过负注意力分数对齐

贡献人：

链接：http://arxiv.org/abs/2408.00137v1

摘要：在二元决策任务中，如是非问题或答案验证，反映了用户在特定问题上寻求确定性的情况。我们观察到语言模型在复杂推理任务的二元决策中呈现负面偏倚。基于此，我们提出了负注意力分数（NAS）来系统地量化负偏倚。在NAS的基础上，我们确定了[关注负面](https://github.com/ysw1021/NASA%7D%E4%B8%8A%E6%89%BE%E5%88%B0%E3%80%82)令牌的注意力头，验证了它们与负偏倚的关联。此外，我们提出了负注意力分数对齐（NASA）方法，这是一种参数高效的微调技术，用于处理提取的具有负偏倚的注意力头。实验结果表明，NASA显著减少了负偏倚引起的精度和召回之间的差距，同时保持了它们的泛化能力。我们的代码可在\url{https://github.com/ysw1021/NASA}上找到。

### Clover-2: 精准推断用于轻量级规范解码

贡献人：

链接：http://arxiv.org/abs/2408.00264v1

大型语言模型（LLMs）经常因自回归解码的要求与当代GPU架构之间的不一致而效率低下。最近，逆向轻量级推测解码因其在文本生成任务中显著提高效率而受到关注。本文提出Clover-2，Clover的高级版本，一个基于RNN的草稿模型，旨在实现与注意力解码器层模型相当的精度，同时保持最低的计算开销。Clover-2增强了模型架构，并结合了知识蒸馏来提高精度并改进整体效率。我们使用开源Vicuna 7B和LLaMA3-Instruct 8B模型进行实验，结果表明Clover-2在各种模型架构上超越了现有方法，展示了其有效性和稳健性。

### **非卷积图神经网络**

贡献人：

链接：http://arxiv.org/abs/2408.00165v1

重新思考基于卷积的图神经网络（GNN）-它们在表达能力上受限、过度平滑和过度压缩，需要专门的稀疏内核来进行高效计算。在这里，我们设计了一个简单的图学习模块，完全不包含卷积算子，被称为\textit{带有统一内存的随机游走}（RUM）神经网络，其中一个RNN合并了随机游走终止于每个节点的拓扑和语义图特征。通过关联RNN行为和图拓扑的丰富文献，我们理论上表明并在实验中验证了RUM减弱了上述症状，并且比Weisfeiler-Lehman（WL）同构性测试更具表现力。在各种节点和图层分类和回归任务中，RUM不仅取得了竞争性表现，而且具有鲁棒性、内存效率、可扩展性，并且比最简单的卷积GNN更快。

### 自动M3L：具有大型语言模型的自动多模式机器学习框架

贡献人：

链接：http://arxiv.org/abs/2408.00665v1

自动机器学习（AutoML）提供了简化机器学习模型训练的可行途径。然而，现有的AutoML框架往往局限于单模态场景，并需要大量手动配置。最近大型语言模型（LLMs）的进展展示了它们在推理、互动和代码生成方面的出色能力，为开发更自动化和用户友好的框架提供了机会。为此，我们介绍了AutoM3L，这是一个创新的自动多模态机器学习框架，利用LLMs作为控制器自动构建多模态训练流程。AutoM3L理解数据模态，根据用户需求选择适当的模型，提供自动化和交互性。通过消除手动特征工程和超参数优化的需求，我们的框架简化了用户参与，并通过指令实现了定制化，解决了之前基于规则的AutoML方法的局限性。我们在涵盖分类、回归、检索任务的六个不同多模态数据集以及一套全面的单模态数据集上评估了AutoM3L的性能。结果表明，与传统基于规则的AutoML方法相比，AutoM3L实现了竞争性或优越的性能。此外，用户研究突显了我们框架的用户友好性和可用性，与基于规则的AutoML方法相比。

### TensorCore架构

Tensor-003 TensorCore 架构是一种专为深度学习优化的硬件架构，它通过采用并行计算技术，显著提升了矩阵运算的效率。该架构支持混合精度计算，能够在不牺牲精度的前提下，加速深度学习模型的训练和推理过程。技术细节上，TensorCore 通过其独特的设计，能够同时处理大量的小数据块，实现高吞吐的并行计算。此外，它还对内存带宽和数据访问模式进行了优化，减少了数据传输的瓶颈，进一步提高了计算性能。在实际应用中，这种架构已经被证明在图像识别和自然语言处理等领域具有显著的性能优势，为 AI 计算提供了强大的硬件支持。

### vLLM FP8(W8A8)也来了，综合性能和易用性，如何选择现有大模型推理框架？

贡献人：

https://www.zhihu.com/question/658712811/answer/3581997127?utm_psn=1803062496090783745

vLLM FP8 (W8A8) 的推出为大模型推理提供了新的选择。在性能方面，FP8 格式通过减少数据的位宽，有效地提高了计算效率和内存利用率。技术细节上，W8A8 指的是权重使用 8 位浮点数，激活函数也使用 8 位浮点数，这样的精度降低对模型的精度影响有限，但能显著提升推理速度。此外，推理框架的选择不仅要考虑到性能指标，如延迟、吞吐量，还要考虑硬件兼容性、易用性和社区支持。TensorRT、ONNX Runtime 等主流框架各有特点：TensorRT 在 NVIDIA 硬件上具有优异的性能；ONNX Runtime 支持多种硬件和编程语言；OpenVINO 适用于 Intel 硬件；TVM 和 MLIR 提供了更灵活的优化选项；Paddle Lite 则专注于移动和边缘设备。技术细节选择推理框架时，应根据项目需求、硬件环境和开发团队的技术栈进行全面评估，并通过实际应用中的性能测试来确定最佳选择。

### 语言模型记忆上限的缩放定律

贡献人：

https://zhuanlan.zhihu.com/p/712434959?utm_psn=1802827340084031488

作者通过实验发现，语言模型的记忆能力与其参数数量成正比，但存在一个比特复杂度的上限。在充分训练的情况下，模型的参数容量比可以达到 2 比特 / 参数，这意味着一个 70 亿参数的模型可以存储所有维基百科和课本的知识。实验还显示，不同架构的模型在记忆容量上有所不同，GPT-2 在 1000 次曝光下的容量比为 2 比特 / 参数，而 LLaMA/Mistral 则较低。此外，量化算法对模型记忆的影响也进行了探讨，结果表明 int8 量化不会影响模型记忆，但 int4 量化会降低容量比。最后，作者提出了缩放定律，即模型的峰值容量比率 R (F)≥2，且存在一个最大容量比 Rmax (F)≤1.8，这为选择合适大小的模型以存储特定量的知识提供了参考。

### 理解LLM中的函数调用及其与RAG的区别

贡献人：

https://www.npi.ai/blog/understanding-function-calling-in-llm-and-its-difference-to-rag

函数调用在大型语言模型（LLMs）中是一种高级功能，它允许模型根据用户提示选择和执行相应的函数，以及传递适当的参数。这种能力使得 LLMs 能够产生结构化的数据输出，如 JSON 对象，进而与外部系统和数据库交互，执行实际任务。Function calling 使得 LLMs 不仅能够理解自然语言，还能与现实世界的 API 和工具进行交互，从而实现复杂的操作和数据处理。

与此同时，Retrieval-Augmented Generation（RAG）是另一种增强 LLM 能力的技术。它通过从外部数据源检索相关信息来丰富文本生成，提高模型在特定领域的准确性和信息的时效性。RAG 通过索引和存储文档片段的向量形式，在向量数据库中进行快速检索，并将这些信息融入到模型的输出中，从而提升了生成文本的质量。

两种技术的关键区别在于，函数调用侧重于执行具体的操作和实时数据处理，而 RAG 侧重于通过外部知识的检索来增强文本生成的上下文和准确性。在实际应用中，函数调用适用于需要与外部系统交互的场景，如聊天机器人、数学问题求解和 API 集成，而 RAG 更适合于需要大量知识检索和应用的领域，如客户支持系统和知识密集型应用。

![](img/a3ff5c0472efb5d969fd0b630f2858b8.png)

### Byte-Pair Encoding 分词算法速读

贡献人：

https://zhuanlan.zhihu.com/p/701869443?utm_psn=1803412992689332226

Byte-Pair Encoding（BPE）是一种高效的文本分词算法，广泛应用于自然语言处理领域。它通过统计文本中最频繁的连续字节对，逐步合并这些对以形成更大的词汇单元，从而构建一个适应特定语料库的词汇表。BPE 算法的优势在于其简单性和计算效率，能够在保持较小词汇表的同时，有效地处理未知词汇和大规模数据集。在实际应用中，BPE 常用于机器翻译、文本摘要等任务，提高了模型处理文本的准确性和速度。技术细节上，BPE 算法首先初始化一个字符级的词汇表，然后迭代地将出现频率最高的符号对替换为一个新的符号，直至达到预设的词汇表大小或迭代次数。这种动态的词汇表构建方式，既能捕捉到语言的复杂性，又能避免维护一个过于庞大的词汇表带来的计算开销。

### 基于性能计数器的GPU功耗与性能优化模型

贡献人：

https://zhuanlan.zhihu.com/p/712637189?utm_psn=1803413448194940928

本文揭示了基于性能计数器的 GPU 功耗与性能优化模型的构建和应用。该模型通过监控 GPU 性能事件计数器，实时评估处理器功耗，并据此进行动态性能与功耗预测。具体而言，模型利用性能计数器如 VALUInsts、SALUInsts 等来跟踪 GPU 的计算和内存操作，进而估算 GPU 的动态和静态功耗。文章详细介绍了 AMD iGPU 和 NVIDIA GPU-1 在该模型中的应用实例，包括性能计数器的选择、模型的建立步骤以及准确性评估。此外，文章还讨论了 DVFS 技术在 GPU 功耗优化中的关键难点，如负载模型的精确性、电源管理策略的实时性以及跨 VF 等级的功耗预测。

### 大模型推荐系统：进展与未来

贡献人：

https://zhuanlan.zhihu.com/p/712417197?utm_psn=1802755814928297985

文章深入探讨了大模型在推荐系统中的应用及未来发展。大模型通过预训练获得丰富的语义表示能力，能够提升推荐系统的个性化和多模态融合处理能力。在推荐系统中，大模型的应用包括利用其强大的文本理解和生成能力，以及通过 In-context Learning 和 Tuning 等技术进行推荐任务的优化。文章指出，大模型推荐系统的进展主要体现在：1) 利用大模型的架构和预训练知识，如 BERT4Rec 和 SASRec，提升推荐质量；2) 通过大模型的泛化能力，实现跨领域推荐；3) 利用大模型的生成能力，进行个性化内容生成和推荐解释。

然而，大模型在推荐系统中也面临挑战，包括如何降低推理延迟和成本、如何评估推荐效果、以及如何处理数据偏见和隐私问题。未来的研究方向将包括开发更高效的模型架构、探索更加精细的用户行为建模方法、以及实现更好的推荐解释和社会责任考量。
