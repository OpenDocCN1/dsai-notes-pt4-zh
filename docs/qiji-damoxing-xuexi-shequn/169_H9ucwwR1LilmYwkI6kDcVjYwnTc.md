https://x.com/Etched/status/1805625693113663834

## 论文

### `FineWeb`：规模化提炼网络中最优文本数据

贡献人：

链接：http://arxiv.org/abs/2406.17557v1

摘要：大型语言模型（`LLM`）的性能严重依赖于其预训练数据集的质量和大小。然而，像`Llama 3`和`Mixtral`这样的最先进的开放`LLMs`的预训练数据集并不公开，并且很少有人知道它们是如何创建的。在本研究中，我们介绍了`FineWeb`，这是一个来自96个`Common Crawl`快照的15万亿 token 数据集，比其他开放的预训练数据集产生了表现更好的`LLMs`。为了推动如何最好地筛选高质量的预训练数据集的理解，我们仔细记录并消融了`FineWeb`中使用的所有设计选择，包括对去除重复和过滤策略的深入研究。此外，我们还介绍了`FineWeb-Edu`，这是从`FineWeb`中筛选出的包含1300亿 token 的教育文本集合。在`FineWeb-Edu`上预训练的`LLMs`在`MMLU`和`ARC`等需要知识和推理的基准测试中表现出显著更好的性能。除了我们的数据集，我们还公开发布了我们的数据筛选代码库以及在我们的消融实验中训练的所有模型。

![](img/da7ab225e703436403a26b477ad5e586.png)

### `LLM-ARC`：利用自动推理批评者改善`LLM`

我们介绍了`LLM-ARC`，这是一个神经符号框架，旨在通过将它们与自动推理评估器(`ARC`)结合，增强大语言模型(`LLMs`)的逻辑推理能力。`LLM-ARC`采用了`Actor-Critic`方法，其中`LLM` `Actor`生成声明性逻辑程序以及测试语义正确性，而自动推理评论员评估代码，运行测试，并对测试失败进行反馈以进行迭代细化。使用`Answer Set Programming (`ASP`)`实现的`LLM-ARC`在测试复杂逻辑推理能力的`FOLIO`基准上获得了新的状态-of-the-art精度88.32%的结果。我们的实验显示`LLM-ARC`相对于仅使用`LLM`的基线有显著改进，突显了逻辑测试生成和迭代自我细化的重要性。我们通过完全自动化的自监督训练循环取得最佳结果，其中`Actor`受到端到端对话跟踪和评论的训练。我们讨论了潜在的增强措施，并提供了详细的错误分析，展示了`LLM-ARC`在复杂自然语言推理任务中的稳健性和效果。

![](img/5fbc234885a7ce847f42c689dd3f913d.png)

### 长文智能体: 为大语言模型提供具有挑战性的长篇指令考试

贡献人：

链接：http://arxiv.org/abs/2406.17588v1

大语言模型（`LLMs`）的长上下文能力是近年来的热门话题。为了评估`LLMs`在不同场景中的表现，出现了各种评估基准。然而，大多数这些基准侧重于识别关键信息以回答问题，这主要需要`LLMs`的检索能力，这些基准只能部分代表`LLMs`的推理性能来自大量信息。与此同时，虽然`LLMs`经常声称有32k、128k、200k甚至更长的上下文窗口，但这些基准未能揭示这些`LLMs`实际支持的长度。为了解决这些问题，我们提出了`LongIns`基准数据集，这是一个具有挑战性的基于指令的长上下文考试，建立在现有指令数据集的基础上。具体来说，在我们的`LongIns`中，我们引入了三种评估设置：全局指令和单任务（`GIST`）、本地指令和单任务（`LIST`）以及本地指令和多任务（`LIMT`）。基于`LongIns`，我们对现有`LLMs`进行了全面评估，并得出以下重要发现：（1）表现最佳的`GPT-4`在我们的`LongIns`中的16k上下文窗口评估表现不佳。（2）对于许多现有`LLMs`的多跳推理能力，在短上下文窗口（小于4k）仍需要大量努力。

### `Math-LLaVA`：为多模态大语言模型引入数学推理

贡献人：

链接：http://arxiv.org/abs/2406.17294v1

大型语言模型(`LLMs`)展示了令人印象深刻的推理能力，特别是在文本数学问题求解方面。然而，现有的开源图像指导微调数据集中，每幅图像包含有限的问题答案对，未能充分利用视觉信息，以增强多模式`LLMs`的数学推理能力。为了弥补这一差距，我们通过收集40,000张高质量图像，结合24个现有数据集的问题答案对，并合成32万个新对，创建了`MathV360K`数据集，改善了多模态数学问题的广度和深度。我们引入了`Math-LLaVA`，一种基于`LLaVA-1.5`的模型，经过`MathV360K`微调。这种新颖方法显著提高了`LLaVA-1.5`的多模态数学推理能力，在`MathVista`的小型测试中实现了19点增长，并与`GPT-4V`有可比性的性能。此外，`Math-LLaVA`展现出增强的泛化能力，在`MMMUBenchmark`上显示出实质性的提升。我们的研究强调了数据集多样性和合成对于推动`MLLMs`数学推理能力的重要性。https://github.com/HZQ950419/Math-LLaVA。

## 训练模型算力的单位：FLOPs、FLOPS、Macs 与 估算模型（FC, CNN, LSTM, Transformers&&LLM）的FLOPs

贡献人：

`https://zhuanlan.zhihu.com/p/649993943?utm_psn=1788246624348291072`

文章深入探讨了在深度学习中用于评估模型算力需求的三个关键指标：FLOPs、FLOPS 和 Macs。FLOPs 代表浮点运算次数，是衡量模型计算量的标准；FLOPS 是每秒浮点运算次数，用于描述硬件性能；Macs 表示乘加累积操作次数，常常与 FLOPs 混淆，但实际上一次 Macs 约等于两次 FLOPs。

在技术细节方面，文章详细阐述了不同模型类型的 FLOPs 计算方法。全连接层（FC）的 FLOPs 计算依赖于输入、输出和权重矩阵的维度；卷积神经网络（CNN）的 FLOPs 还需要考虑卷积核的大小和通道数量；长短期记忆网络（LSTM）的 FLOPs 则与隐藏层维度和词向量维度相关。对于 Transformers 和大型语言模型（LLM），文章指出其 FLOPs 计算涉及到多头注意力和前向传播层的矩阵乘法，并提供了计算参数量和 FLOPs 的具体公式。

此外，文章强调了反向传播在计算 FLOPs 时的影响，指出反向传播的计算量通常是前向传播的两倍。最后，文章指出，尽管 FLOPs 是评估模型复杂度的重要指标，但实际的训练时间和性能还受到其他因素的影响，如硬件配置、并行计算能力和软件优化等。通过对这些技术细节的深入分析，文章为深度学习模型的性能评估和资源分配提供了宝贵的见解。
