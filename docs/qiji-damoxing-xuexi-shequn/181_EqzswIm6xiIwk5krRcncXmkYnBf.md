### 手机流畅运行470亿大模型：上交大发布LLM手机推理框架PowerInfer-2，提速29倍

https://mp.weixin.qq.com/s/vylZp7MG7TA3pQKOBWbYRQ

苹果一出手，**在手机等移动设备上部署大模型**不可避免地成为行业关注焦点。然而，目前在移动设备上运行的模型相对较小（苹果的是3B，谷歌的是2B），并且消耗大量内存，这在很大程度上限制了其应用场景。即使是苹果，目前也需要与OpenAI合作，通过将云端GPT-4o大模型嵌入到操作系统中来提供能力更强的服务。这样一来，苹果的混合方案引起了非常多关于数据隐私的讨论和争议，甚至马斯克都下场讨论。既然终端侧本地部署大模型的方案既让手机用户享受到AI强大的智能，又能保护好自己的隐私安全，为什么苹果还要冒着侵犯隐私的风险选择联手OpenAI采用云端大模型呢？主要挑战有两点：

+   **手机内存不够大：**按照大模型的Scaling Law法则，模型参数越大，能力对应的也就越强，这就意味着能力更强的模型对内存的要求越高。

+   **手机算力不够强：**即使勉强把通过量化等手段把模型塞进手机了，推理速度也慢，适合的应用场景也就非常有限了。

为**了解决上述挑战，上海交大IP**ADS实验室推出了面向手机的大模型推理引擎（目前论文已在arxiv公开）：PowerInfer-2.0。

### Percy Liang倡议：“开放权重模型”不是“开源模型”，对于开放科学，我们真的需要开源模型

https://x.com/percyliang/status/1800650546208035123

我们应该称像Llama 3、Mixtral等模型为“开放权重模型”，而不是“开源模型”。要成为开源模型，代码和训练数据需要公开（好的例子有：GPT-J、OLMo、RedPajama、StarCoder、K2等）。权重就像exe文件，称其为开源是荒谬的。

为什么会有这种混淆？首先，因为我们对AI开放性的标准太低。前沿模型的现状是API访问，所以当我们能够获取权重时会欢呼。

此外，开源有两个好处：透明性（能够理解）和可扩展性（能够修改）。对于软件，要实现这两点需要开源。对于AI模型，仅通过权重进行微调就能实现一定的可扩展性，因此对很多人来说已经足够了。

但对于开放科学，我们真的需要开源模型。如果不了解训练数据，如何解释测试准确性？如果不知道数据来源，如何理解模型的能力？虽然开源权重模型有很大启发作用，但我们也有可能在不明确的基础上构建整个领域。

### MixEval：从LLM基准混合中得出众包的智慧

贡献人：

链接：http://arxiv.org/abs/2406.06565v1

摘要：评估大型语言模型(LLMs)具有挑战性。传统基于真实标准的基准测试未能捕捉真实世界查询的全面性和细微差别，而LLM作为评判标准存在评分偏见和有限的查询数量。这两者随着时间可能变得不可信。用户面向评估，如Chatbot Arena，提供可靠的信号，但成本高且速度慢。本文提出了MixEval，一个通过巧妙混合现成基准来建立高效、金标准LLM评估的新范式。MixEval桥接了(1) 来自网络挖掘的全面且分布均匀的真实用户查询和(2) 高效且公正评分的基于真实标准的基准，通过将从现有基准中提取的类似查询与来自网络挖掘的查询进行匹配。基于MixEval，我们进一步构建了MixEval-Hard，为模型改进提供更多空间。我们基准的优势在于(1) 与Chatbot Arena具有0.96的模型排名相关性，源于高度公正的查询分布和评分机制，(2) 快速、便宜且可重现的执行(仅需MMLU时间和成本的6%)，以及(3) 通过快速稳定的数据更新管道实现的动态评估。我们为我们和现有LLM基准进行了广泛的元评估和分析，加深了社区对LLM评估的理解，并指导未来研究方向。

### **简单有效的遮蔽扩散语言模型**

贡献人：

链接：http://arxiv.org/abs/2406.07524v1

摘要：尽管扩散模型在生成高质量图像方面表现出色，但先前的研究报告了扩散模型与自回归（AR）方法在语言建模中存在显著的性能差距。在这项研究中，我们展示了简单的掩蔽离散扩散比之前认为的性能更好。我们应用了一种有效的训练方法，提高了掩蔽扩散模型的性能，并推导出一个简化的Rao-Blackwell化目标，进一步改善了性能。我们的目标具有简单的形式--它是传统掩蔽语言建模损失的混合体--可用于训练仅编码器语言模型，其可接受高效的采样器，包括可以半自回归地生成任意长度文本的模型，就像传统语言模型一样。在语言建模基准测试中，经过现代工程实践训练的各种掩蔽扩散模型实现了扩散模型中的最新技术水平，并接近了自回归困惑度。我们在https://github.com/kuleshov-group/mdlm上发布了我们的代码。

### Samba：简单的混合状态空间模型，用于高效无限上下文语言建模

贡献人：

链接：http://arxiv.org/abs/2406.07522v1

在这项工作中，我们提出了Samba，一种简单的混合架构，将Mamba（一种选择性状态空间模型）与滑动窗口注意力机制SWA逐层组合。Samba能够有效地将给定序列压缩成递归隐藏状态，同时通过注意力机制确切地回忆记忆。我们将Samba扩展到38亿参数，32兆训练标记，并展示Samba在各种基准测试中明显优于基于纯注意力或SSM的最新模型。经过训练后，Samba可以有效地从4K长度的序列外推到256K上下文长度，并且在最多100万上下文长度下显示出改进的标记预测能力。作为一个线性时间序列模型，与分组查询注意力的Transformer相比，Samba在处理128K长度用户提示时拥有3.73倍的吞吐量，并在生成64K标记时具有3.64倍的加速。Samba的示例实现可以在https://github.com/microsoft/Samba公开获取。

### Skywork-MoE: 混合专家语言模型训练技术深入探讨

贡献人：

链接：http://arxiv.org/abs/2406.06563v1

在这份技术报告中，我们介绍了在开发Skywork-MoE时实施的训练方法论，这是一个具有1460亿参数和16个专家的高性能混合专家（MoE）大型语言模型（LLM）。它是从我们的Skywork-13B模型的预先存在的密集检查点初始化的。我们探讨了回收利用与从头开始训练初始化之间的比较有效性。我们的研究结果表明，选择这两种方法之间应考虑现有密集检查点和MoE训练预算的性能。我们强调了两种创新技术：门控逻辑规范化，这可以改善专家的多样性，以及自适应辅助损失系数，允许对不同层进行辅助损失系数的调整。我们的实验结果验证了这些方法的有效性。利用这些技术和见解，我们在我们的SkyPile语料库的精简子集上训练了我们的回收利用的Skywork-MoE。评估结果表明，我们的模型在广泛的基准测试中表现出强大的性能。

### 自动过程监督改善语言模型中的数学推理

贡献人：

链接：http://arxiv.org/abs/2406.06592v1

复杂的多步推理任务，如解决数学问题或生成代码，即使对于最先进的大语言模型（LLMs）也仍然是一个重大障碍。使用Outcome Reward Model（ORM）验证LLM的输出是一种标准的推理时间技术，旨在增强LLM的推理性能。然而，对于具有冗长或多跳推理链的推理任务，其中间结果既没有得到恰当奖励也没有受到惩罚，这仍然证明是不足够的。过程监督通过在推理过程中分配中间奖励来解决这一限制。至今，用于收集过程监督数据的方法要么依赖于人类注释，要么依赖于每步蒙特卡洛估计，二者都昂贵且无法扩展，从而阻碍了这种技术的广泛应用。为了应对这一挑战，我们提出了一种新颖的分治式蒙特卡罗树搜索（MCTS）算法OmegaPRM，用于高效收集高质量的过程监督数据。该算法通过二进制搜索迅速识别出“思维链”（CoT）中的第一个错误，并平衡正负例，从而确保了效率和质量。因此，我们能够收集超过150万个过程监督注释来训练一个过程奖励模型（PRM）。利用这种完全自动化的过程监督以及加权自一致性算法，我们提高了经过调整的Gemini Pro模型的数学推理性能，达到了在MATH基准上的69.4%成功率，比51%的基本模型性能提高了36%。另外，整个流程无需任何人类干预，使我们的方法在财务和计算成本上比现有方法更具成本效益。

### LLMs是经典还是非单调推理者？从泛化中学到的经验

贡献人：

链接：http://arxiv.org/abs/2406.06590v1

最近关于LLMs推理的学术研究提供了令人印象深刻的表现，并能灵活适应机器生成或人类反馈。非单调推理对于人类认知在现实世界中导航至关重要，但仍是具挑战性且研究不足的任务。本文研究了七种最先进LLMs在一个抽象推理任务和一个常识推理任务中的非单调推理能力，涉及常见的泛泛之谈，如“鸟会飞”，以及例外情况，“企鹅不会飞”。虽然LLMs展现出与人类非单调推理能力相符的推理模式，但它们不能在添加支持性例子（“猫头鹰会飞”）或不相关信息（“狮子有鬃毛”）时保持对泛泛之谈的真实条件的稳定信念。我们的发现突显了将人类推理行为归因于LLMs的陷阱，以及评估一般能力，同时一致的推理仍然难以捉摸。

### LLM推理后端性能大比拼，来自BentoML团队的深度评估！

贡献人：

https://zhuanlan.zhihu.com/p/702786191?utm_psn=1783946498251231232

BentoML 团队对 Llama 3 LLM 模型的推理后端进行了深入的性能评估，涵盖了 LMDeploy、vLLM、TensorRT-LLM、MLC-LLM 和 Hugging Face TGI 等主流推理后端。性能测试基于 A100 80GB GPU 实例，考察了不同并发用户数（10、50 和 100）下的 Time to First Token (TTFT) 和 Token Generation Rate。结果显示，LMDeploy 在 8B 模型的 token 生成率方面表现最佳，vLLM 则在 TTFT 上有优势。对于 70B 4-bit 量化模型，LMDeploy 和 TensorRT-LLM 在高并发下展现了优异的性能。此外，文章还对推理后端的硬件限制、模型支持、开发者体验和概念进行了详细的阐述，并提供了针对不同模型和场景的最佳实践建议。这些评估和建议对于开发者在选择合适的推理后端时提供了宝贵的参考。

### 用 KV 缓存量化解锁长文本生成

贡献人：

https://mp.weixin.qq.com/s/Iqr7UMVk9vW6tMuRK6AIOg

Hugging Face 推出的 KV 缓存量化技术，通过对自回归语言模型的键值缓存进行量化，显著提升了长文本生成的内存效率和速度。该技术基于 KIVI 论文的理论，采用按通道量化键缓存和按词元量化值缓存的方法，以最小化对生成质量的影响。在 transformers 库中，通过设置固定大小的余留缓存以原始精度存储键值对，并在达到最大容量时进行量化，来优化内存使用。实验结果表明，量化缓存可以在不明显降低模型准确性的前提下，大幅度减少内存占用。此外，该技术支持不同精度的量化后端，如 quanto 和 HQQ，并且可以与其他优化技术如权重量化相结合，虽然可能会牺牲一定的生成速度。通过这种方式，KV 缓存量化为在有限资源下进行高效的长文本生成提供了有效的解决方案。

![](img/ca1e83c2ce28f3d36f5a8d7d1b981037.png)

### 从源码分析 vllm + Ray 的分布式推理流程

贡献人：

https://mp.weixin.qq.com/s/KZzTUOsmSSGowNM9f8fpDw

文章揭示了 vllm 与 Ray 结合实现大型语言模型分布式推理的技术细节。在 Kubernetes 集群上，通过准备模型、部署 vllm 应用以及启动服务，实现了模型的分布式部署。核心流程包括构建 LLM 引擎、初始化 Ray 集群、设置环境变量、初始化设备以及加载模型等步骤。分布式推理过程中，通过 tensor 并行和流水线并行技术，实现了模型权重的分布式加载。特别是，当--tensor-parallel-size大于 1 时，会触发 ray 的分布式部署，进而通过 AllReduce 机制保证不同 GPU 间的同步。模型加载流程涉及到了 Megatron-LM 算法，该算法支持 Transformer 层的自注意力和 MLP 部分的并行计算。

### 拟人机器人双臂协调控制方法设计

### einsum is all you needed
