## 第一个重点：如何完成网页自动化采集

这里我们会用到的工具有：

cc当中的playwright mcp

Playwright mcp就是一个浏览器自动化操作，让cc装上这个mcp，它就可以自己打开浏览器，然后在浏览器上去执行某些操作

### 第一步：安装playwright mcp

最简单的做法：直接和cc说你要安装这个playwright mcp 然后它就会帮你去完成了。（能够让cc去做的，我们绝对不自己做，训练自己使用ai的能力）

> 注意事项：

1.  想要让cc用playwright mcp来操作浏览器，我用的是mac，mac可以不做其他操作就能实现这一点，如果是windows，好像是需要带图形界面的linux才行，具体我不太懂，有懂的圈友可以在评论区解答一下

1.  安装的时候，要让cc 将playwright mcp安装到配置文件当中，这样子，当你关闭终端下次再打开时，就不需要再重新安装，具体怎么判断：在cc的输入框，输入/mcp 看看是否有出现mcp工具列表，如果出现了，说明成功安装到配置文件当中了。

### 第二步：完成📕账号的登陆

cc用playwright进行浏览器操作时，它是会打开一个全新且独立的浏览器，也就是说，你的任何网页的登陆信息都没了， 需要重新登陆，而想要采集📕上的笔记，就需要登陆，所以第一步是登陆

那么登陆，我们就需要给cc提供一个称为「cookie」的东西，你可以简单理解为登陆凭证，cc依靠这个才能记住📕的登陆信息

更具体的作用，可以自行问一下AI哈，这里不是重点，所以就不详细介绍了。

怎么获得cookie，我们也让cc去完成，我们的任务就是扫码

具体步骤如下：

1.告诉cc打开一个浏览器实例，然后导航到📕首页，然后暂停等待，30秒之后检查从网页上找到用户头像来验证是否登录成功，如果找到头像，则代表登录成功，那么则开始获取cookie

2.在打开的浏览器上进行扫码登录，等待cc继续执行

3.如果顺利，前面两步就能完成cookie的获取，然后你让cc将cookie信息写入到一个文档当中，之后，比如你打开一个新的终端，或者新的会话，就可以让cc读这个文档，它就知道怎么打开已登录📕的浏览器

虽然上面这个方法能够找到笔记位置了，但是呢，又遇到个问题，就是无法去获取到足够数量多的笔记

原因是什么呢？就是它这个index  它是笔记在懒加载的过程中逐渐出现的，比如首屏只有15条笔记，那么index最多=15。    如果你要获取更多的笔记，那就需要往下滑，让网页加载更多的笔记，这样index的数字才会继续增加

那为什么说会无法获取到足够多的笔记呢，原因是cc在模拟滚动往下滑的时候，幅度太大，导致index直接出现了断层。

比如第一屏 到index=15。 然后cc往下滑幅度太大，页面上找不到index=16 17   而是直接定位到了index=25 大概这样的位置

出现断层就会导致cc无法继续往后采集

所以我给出的解决方法是：「减少“模拟滚动”的幅度，让它小幅度滚动」。这样就不会出现“断层”的情况出现了。

## 第二个重点：怎么储存采集到的笔记数据

这一点的话，其实在我的第一篇文章当中是有讲到的，我用的是飞书多维表格

> tips：最近飞书多维表格独立出来了，不一定要在飞书上使用了，说明飞书的潜力无限呀

想了解详细的话，可以直接看我的这个文章

[如何用AI编程实现📕自动化](https://ec2mz96esm.feishu.cn/docx/VOxMdJeRJoznWgx4laucH1Iyneb?from=from_copylink)

采集到的笔记数据可以让cc直接写入到我们的飞书多维表格当中

核心需要四个东西：

+   APP ID：相当于你要访问的飞书应用的 “身份证编号”

+   APP SECRET ：类似 “密码”，和 APP ID 配合

+   APP TOKEN ：像是 “通行令牌”，有了它，在一定时间内可以顺畅地在应用里做操作，不用每次都重新输密码验证。

+   Table ID：就是飞书多维表格的 “具体地址”，告诉系统你要把数据写到哪个表格里 。

都在我的第一篇文章里有讲

除了飞书多维表格，也有其他的储存方法，比如数据库等，这个就看自己的习惯了。

## 第三个重点：如何从采集的笔记中找出爆款模版

核心做法其实就是把收集到的大量笔记数据都发送给AI，让它根据这些笔记数据来提炼爆款笔记的共性。

比如，发送50个标题给AI，让AI从这些标题当中提取以下这些：

+   高频词汇有哪些

+   爆款标题的风格是什么样的？

+   爆款标题的结构是什么样的？

+   再进一步，可以基于提炼出来的爆款标题结构等，然后AI帮我们进行二创/发散思维等

+   还能将这些过往的爆款标题向量化，转化成标题知识库，让AI能够给予这些历史爆款爆款标题来写笔记。

> 可以想象自己是在搭建积木，非常自由，发挥自己的想象力，然后通过工作流Agent来实现自己的想法。

这个第三步的实现方式还是比较多的，coze  n8n  或者只靠cc都是能实现的

但其实对新手比较友好的方式是学习coze/n8n这类工作流

我觉得理由很简单，这类工作流平台将A**I都转化为**一个个节点，然后可以让用户直接「可视化」调用

也就是能够看到完整的AI执行任务的流程，然后就更容易知道哪里有问题，是提示词有问题，还是大模型参数设置得有问题。

而如果通过cc直接在自己的网站上去接入大模型，那么就要去代码里找这些参数然后调整，其实对于还不习惯看代码的新手是挫折性比较强的。

### 第四步：和cc讨论工作流。

在讨论之前，你可以自己先用画图软件画一个大致的流程图，思考以下这几个最基本的问题：

+   准备如何触发整个工作流（手动/定时/http请求等）

+   你的数据从哪里来？（数据库/飞书等）

+   你的数据需要处理吗？（去掉空的/异常的/去重等）

+   你的数据格式需要标准化处理吗？（方便后续分析，如让AI更容易理解你的数据结构）

+   你要对数据做什么处理？（比如加入AI节点，然后你要让AI帮你分析什么？）

+   数据的最终输出形态是什么？（json格式/纯文本/报告等）

+   数据要到哪里去（最终的输出结果要保存到哪里去？）

这套流程其实比较接近“数据分析”流程，以前在BI公司实习过，对这套流程还有些印象哈哈哈。

举个例子：我要分析爆款笔记标题的高频词/结构/风格

我当时就拒绝了这个选项，让cc要保留，并且还要增加一个关于表情符号的分析，众所周知，📕标题中的表情符号意义大于其他平台，所以我还要让ai帮我分析表情符号出现的频率，以及出现位置分析。

这个就是关于数据标准化处理的，所以还是很有必要思考这一点的。

+   APP ID：相当于你要访问的飞书应用的 “身份证编号”

+   APP SECRET ：类似 “密码”，和 APP ID 配合

+   Table ID：就是飞书多维表格的 “具体地址”，告诉系统你要把数据写到哪个表格里 。

# AI编程与n8n、coze之间关系的思考

**说实**话，我其实有段时间一直在思考一个问题，就是：“我能熟练用AI编程了，好像对我来说，我需要什么工具，我已经能实现自己供给了。包括像工作流、在工作流当中接入AI，我其实也能自己实现。我还需要用n8n、coze这类工作流平台吗？”

后来我想清楚了，这个不是二选一的问题，而是1+1的问题。

用什么技术来解决我们的需求不是重点，重点在于「如何高效/快速解决我们的问题」

所以肯定是自己习惯用什么，就用哪个

如果是我的话，我会用cc来搭建我需要的前端后端，然后把一些工作交给n8n，比如调用大模型来分析内容，这个最大的好处就是我能够将我创建的大模型可视化。我就能很方便管理我的大模型

以及，我还有个思考，如果我们搭建起了多条n8n工作流

我们是不是可以创建一个「调度大脑」，让AI来基于场景来决定要调用哪些工作流来解决问题，是不是也可以呢

这些都是一些不完整的思考，后续还会再进行更多的思考，等我以后的分享，兄弟们！

总的来说，我觉得：

「n8n能够保下限，cc能够保上限，两个结合，上限和下限都得到了保证」

本文更偏向于带你如何去使用cc来赋能做其他的事情，让你看到cc能做到什么程度。我一直坚信，在AI时代，先相信，就能做到，fighting！
