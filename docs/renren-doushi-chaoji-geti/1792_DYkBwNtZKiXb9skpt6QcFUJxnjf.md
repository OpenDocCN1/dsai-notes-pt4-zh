# 一、何为结构化Prompt

先来说说Pr**om****pt**，Prompt就是我们向GPT表达 诉求，借助GPT完成某项任务。而在复杂任务场景下，我们需要将复杂的 诉求 有条理的、清晰的向GPT表述，但这个表达的过程并不简单，需要一定的章法，而“结构化Prompt”就是一种不错的章法。

“结构化Prompt”是指，**将****复杂的诉求进行分类****整理**形成模块、并使得模块间具有清晰的逻辑关系，这种具备清晰逻辑结构的Prompt称之为“结构化Prompt”。

目前主流的“结构化Prompt”表达有：JSON、Markdown、Yaml、XML等。在看示例之前，我们先聊几个概念：

1.  KV结构，既Key - Value，比如 “姓名: 菠菜” 就是标准的KV结构，Key为“姓名”，Value为“菠菜”

1.  List结构，可以理解为1个Key对应多个Value，比如“爱好: 写代码、看电影”

1.  从属结构，表示模块的从属关系，比如组员从属于组长。

接下来看一下各数据格式的示例：

## JSON格式

```
{
    // KV结构，&quot;角色&quot;为Key，&quot;资深HR&quot;为Value
    &quot;角色&quot;: &quot;资深HR&quot;,
    // List结构，可以理解为一个Key对应多个Value
    &quot;人物背景&quot;: [
        &quot;在互联网公司，从事了15年的HRBP工作&quot;,
        &quot;主要负责产研相关工作&quot;,
    ],
    // 从属结构，&quot;内容&quot;、&quot;发言稿格式&quot; 为 &quot;任务&quot; 的子模块，&quot;内容&quot; 与 &quot;发言稿格式&quot; 为并列关系
    &quot;任务&quot;: {
        &quot;内容&quot;: &quot;主持校招生培训计划启动会，需要写一篇发言稿&quot;,
        &quot;发言稿格式&quot;: [
            &quot;开头要是：亲爱的破局公司的伙伴们&quot;,
            &quot;结尾要是：全体HRBP敬上&quot;,
        ]
    }
}
```

## Markdown格式

```
&lt;!-- 
Markdown的没有太明显的KV与List区分，但却有类似的表达
比如下边的&quot;角色&quot;与&quot;人物背景&quot;，&quot;角色&quot;类似KV、&quot;人物背景&quot;类似List

Markdown的从属关系如下，n个# 的会从属于上边临近的 n-1个#
而数量相同的# 则属于并列关系
比如下边的&quot;任务&quot;的子模块有&quot;内容&quot;、&quot;发言稿格式&quot;，而&quot;内容&quot;与&quot;发言稿格式&quot;为并列关系
--&gt;

# 角色
- 资深HR
# 人物背景
- 在互联网公司，从事了15年的HRBP工作
- 主要负责产研相关工作
# 任务
## 内容
- 主持校招生培训计划启动会，需要写一篇发言稿
## 发言稿格式
- 开头要是：亲爱的破局公司的伙伴们
- 结尾要是：全体HRBP敬上
```

## Yaml格式

```
# Yaml的KV结构
角色: 资深HR
# Yaml的List结构
人物背景:
    - 在互联网公司，从事了15年的HRBP工作
    - 主要负责产研相关工作
# Yaml的从属结构
任务: 
    内容: 现在你需要主持校招生培训计划启动会，需要写一篇发言稿
    发言稿格式:
        开头要是: 亲爱的破局公司的伙伴们
        结尾要是: 全体HRBP敬上
```

## XML格式

```
&lt;!-- XML的KV结构 --&gt;
&lt;角色&gt;资深HR&lt;/角色&gt;
&lt;!-- XML的List结构 --&gt;
&lt;人物背景&gt;
    &lt;背景1&gt;在互联网公司，从事了15年的HRBP工作&lt;/背景1&gt;
    &lt;背景2&gt;主要负责产研相关工作&lt;/背景2&gt;
&lt;/人物背景&gt;
&lt;!-- XML的从属结构 --&gt;
&lt;任务&gt;
    &lt;内容&gt;现在你需要主持校招生培训计划启动会，需要写一篇发言稿&lt;/内容&gt;
    &lt;发言稿格式&gt;
        &lt;格式1&gt;开头要是：亲爱的破局公司的伙伴们&lt;/格式1&gt;
        &lt;格式2&gt;结尾要是：全体HRBP敬上&lt;/格式2&gt;
    &lt;/发言稿格式&gt;
&lt;/任务&gt;
```

# 二、为何GPT更能理解结构化Prompt

在实际的使用GPT过程中，我们发现结构化Prompt更能让GPT理解，并且GPT的表现也更加稳定，这是为何？我觉得有两点非常核心的原因：

## 设计“结构化Prompt”的过程，就是将你的思考结构化的过程

之**前参加**过**李忠秋**老师的线下课《结构思考力》，收益颇多，推荐大家去学习。《结构思考力》就是教你如何将一件事想清楚并讲清楚。而“结构化Prompt”恰恰就是这样一个过程。只有自己将事情想清楚了，并清晰的表达出来，GPT才能更加精准的理解你的诉求。

## GPT更理解程序化的数据结构

其实JSON、Markdown、Yaml、XML等都是由程序员创造出来的，用于描述复杂数据结构的数据格式，并且经常会在程序中使用。而GPT在训练学习的时候加入了Github（最大的程序员开源社区，有着几乎全世界最优秀的代码）中所有的代码，所以GPT对于代码的理解以及代码所涉及的数据格式的理解，都是超强的，这也是为什么结构化Prompt不仅可以描述复杂的诉求，同时还会让GPT的表现更加稳定的重要原因之一。

# 三、不同流派的结构化对比

就实际效果来说，无论你是JSON、Markdown还是Yaml、XML，都可以让GPT的表现稳定，且都能实现绝大多数的功能诉求。而他们的差异点更多的是在应用场景的不同而已。

| 结构化格式 | 适合人群 | 优点 | 缺点 |
| --- | --- | --- | --- |
| JSON | 程序员 | 1.  程序员最常用的数据格式，人人都会 | 1.  对于非程序员出身的小伙伴来说，学习成本较高 |
| Markdown | Prompt设计者 | 1.  入门快，学习成本低，只需要学会&quot;#&quot;、&quot;-&quot;即可满足绝大多数场景 | 1.  从属关系表达不够直观，需要数&quot;#&quot;个数 |
| Yaml | 程序员 | 1.  也是程序员常使用的数据格式之一，JSON平替 | 1.  对空格数有比较严格的要求 |
| XML | 暂不推荐 | 1.  学习成本相对较低 | 1.  格式相对冗余、复杂，不利于Prompt编写效率 |

综上所述：如果你是程序员，建议你使用JSON、Yaml。若你是Prompt设计者建议你使用Markdown、Yaml。
