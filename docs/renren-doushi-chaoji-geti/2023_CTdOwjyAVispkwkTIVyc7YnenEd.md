![](img/ec45125cad4012093f4073751b26b35c.png)

## 一、优惠券的生命周期

+   创建：由运营同学在后台申请创建优惠券；

+   投放：由运营同学把优惠券投放在活动中，优惠券和活动一般不分离；

+   领取：一般指用户主动在活动页面领取或者运营主动对用户账户进行充值；

+   使用：用户在购买商品的时候使用优惠券，优惠券被使用。

下面我们来看下优惠券应该怎么设计？

## 二 、优惠券的基本属性

![](img/36fa5c2abc39c3711216a8348379f35d.png)

### 1. 优惠券类型

**1）按使用范围分**

通用券、单品券、跨品券，这类优惠券主要是电商平台使用的较多，一般平台通用券即可。

**2）按使用功能分**

+   无门槛

用户使用的时候没有门槛，不管商品价格多少都可以抵用。这种更容易吸引新用户，但是考虑到成本，这种优惠券面额都相对较低。

+   满减

用户使用的时候有一定的门槛，消费金额必须满足规定的金额才可以使用。举例：满100元减5元，订单金额达到100元才可以使用。

对于有些平台的商品价格差异比较大，满100元减5元的优惠可能无法吸引用户，需要30元、50元甚至面额更高的优惠券，这时候我们的运营人员可能会申请多张优惠券，但是这样操作就比较麻烦了。

这时候引入了阶梯优惠券的概念，比如满100-5，满500-30，满1000-100，一张优惠券设置不同的满减门槛，根据用户购买商品的价格给予不同额度的抵扣，达到哪个门槛使用哪个金额，提高了用户的购买力。

一张优惠券的作用达到了多张优惠券的作用，并且也防止了红包的滥发。

+   折扣

主要是打折使用，比如原价上打7折，设置的时候也需要设置下最高抵扣金额。

举例某商品20元，给了用户一张5折券，这时候用户只需要支付10元，公司亏损10元；某件商品100元，用户用了5折券后只支付了50元，公司亏了50元，如果设置最大抵扣金额，比如20元，即使打了5折，用户享受的优惠最大也只有20元。

### 2. 优惠券面额

**固定面额 **：是多少就发多少。

**浮动面额 **：金额不确定，有可能是5元，有可能是10元，根据算法计算，个性化金额。

**活动时间 **：这个指的是优惠券投放的时间，在这个时间段可以投放，并不是指券可使用的时间，举例：活动时间设置的是4月25日到5月3日，指的是这段时间优惠券可以发放，但具体这段时间是否可使用需要看优惠券设置的使用时间，两者的概念不一样，不要搞混。

**有效期 **：主要指的是优惠券的使用时间

+   固定有效期：使用的具体时间，具体5月1日到5月7日可用；

+   动态有效期：指领取X天后生效，有效X天。

**发放限制 **：

+   库存设置：设置优惠券的库存

+   券每日领取上限：券每日发放的库存

+   个人每日领取上限：控制每个人的领取次数

+   设备号领取上限：防止同一设备薅羊毛，主要针对大额优惠券

**发放对象 **：主要针对不同类型的用户或者不同等级的用户发放优惠券

**投放和使用渠道 **：针对拥有多渠道平台投放优惠券的公司，可以设置在某个单平台投放或者使用，同时也可以选择在A平台（APP）投放但是只能在B平台（微信）使用。根据运营的需要，可以设置在不同的渠道进行使用。

**特殊条件 **：主要针对一些项目的特殊使用条件，举例：机票指定航司、航班，火车票指定坐次，用车指定车型等等。

**使用时间 **：在优惠券的有效期上有加了一层条件，比如：仅限某个时间点可使用、仅限每周几使用等等

**券状态 **：

+   未使用：正常未使用

+   已使用：优惠券已被使用

+   已占用：优惠券被占用，一般在提交订单未支付的时候会被占用

+   已过期：优惠券到期

+   已作废：特殊原因被废弃

## 三、优惠券的后台设计

上面已经比较全面的介绍了红包的基本属性，已经可以大致搭建一个优惠券的后台了，但光是这么简单的功能肯定是不满足我们的实际使用需要，所以再给大家分享下后台还需要哪些基本功能。

![](img/a5f9eaa5c482cb31e11b49cc4f53a2d3.png)

+   数据看板：包括优惠券的发放、使用量、人数、金额、优惠券使用率等等，数据看板的作用是为了数据分析，为了指导我们后面的方向；

+   优惠券申请：主要包括优惠券的配置以及优惠券的查询；

+   审批列表：对于申请的优惠券需要有固定的人员（上级领导、公司财务等）进行审核；

+   优惠券工具：主要神对特殊情况需要对优惠券进行补发以及作废；

+   领取查询：查询用户账户领取的优惠券。

总结：优惠券的类型虽然千差万别但是本质都是一样的，并且优惠券的投放最终都需要考虑运营的成本，并且需要重视每次的效果回收，只有不断的进行测试打样，才能选出适合自己平台的优惠券类型。
