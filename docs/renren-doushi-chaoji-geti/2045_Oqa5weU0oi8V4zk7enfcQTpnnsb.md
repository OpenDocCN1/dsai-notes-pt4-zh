# **起源，「1931」**

「**产品经理」这个概念来源于一位1925年刚从哈佛毕业的年轻**人，他叫Neil McElroy，毕业加入宝洁后被分派到广告部门。 随后，他发现消费者购买商品的动机是不尽相同的，在香皂市场可以做很多的人群细分，并使用多品牌战略。

![](img/569b7d3141cc52a4744d28b65aade032.png)

Neil McElroy（先后成为宝洁副总裁、艾森豪威尔时期的国防部长）

1931年5月13日，他发布了著名的“Brand Man” memo，提出「一个人负责一个品牌」的概念。

“Brand Man”将负责品牌的产品营销以及对消费者的需求保持关注，并持续改进产品，这个角色被称为Product Manager，Neil也成为了现代商业意义上的第一位产品经理。

![](img/f50068a38c541afa9dd42987fe252a4e.png)

(a) 了解你的用户并且去发现他们的问题；

(b) 开发产品解决他们的问题；

(c) 获得授权与支持；

(d) 制定销售策略推动产品售卖；

(e) 跟踪产品指标、迭代，并实现盈利；

随后产品管理制度逐渐在越来越多的行业得以推广和应用，在互联网、科技行业取得了广泛的成功。

**移动设备的普及促使平台产品高速发展，同时也弱化了商业行为**的物理限制，为产品经理提供了更大的舞台。

![](img/abb47924c20d3e0e78b2c86e14050eca.png)

# **成长的烦恼**

产品经理最核心的能力是什么？是「解决问题」的能力， 所以 不论做什么工作、什么岗位，拥有产品思维都是非常有必要的。

**1）产品经理的经典 逻辑**

**「目标>>问题>>解决方案」**

**首先，定义清晰的目标。 **确保这个目标就是产品战略上的重要目标，并且用一句话就能描述清楚；

其次，做目标到问题的分解，推导路径要严谨，逻辑要严密。 最终分解出来的问题互斥且整个问题的集合是完整的（MECE原则）；

**最后，明确了要解决的问题，再设计具体的**解决方案，并协调研发与测试资源进行开发。

2）优秀                产品经理的四项基本素质

![](img/44ee1fda9731c85187b0d2088e0cde9c.png)

**创业精神： **产品经理需要ownership，拥有很强的责任感，不断培育自身的领导力，把交付用户价值看做一件非常重要的事情。

**终身学习： **学习不是机械地记忆，重点在于不断「思考>>实践>>总结」，重视迭代认知水平与沉淀方法，持续提升专业能力。

**善于联想： **联想代表了产品经理输入多元信息之后的「思维整合与延展能力」，这对产品经理的「好奇心」有很高的要求，要基于已知信息在抽象层面展开想象，突破固有的认知，交付创新产品。

![](img/2316c6da262ef073a371e55b11d7c2d0.png)

例：博朗T3收音机和iPod

**善于决断： **PM必须拥有决断能力，决断意味着「敢于面对风险」，才有机会「抓住窗口期」。有创业经验的人都知道，相比窗口期来说个人能力微不足道，一旦错失窗口期，即使再投入十倍的人力、资本，也难以翻盘。

**3）产品经理的成长模型**

王诗沐使用「操作系统+CPU+信息获取」的模型，比喻人的成长模式。 人通过阅读、实践、交流等各种方式从外部「获取信息」；「思维方式」就像操作系统，搭建出各式各样的应用，代表人的「能力和方法」； 通过调取CPU的计算资源，即「人的脑力」来解决各种各样复杂的现实问题。

**这个过程中获取的信息越多，沉淀的能力和方法越多，计**算资源开发得越多，能解决的问题就越复杂。

![](img/608adc7d70adbf024d1a479e60f6afdc.png)

最难的是「打破思维的路径依赖」。 因为信息可以大量获取，能力和方法可以持续沉淀，但思维方式确实是最难突破、迭代的。

长期固化的思考框架会自成信息茧房，严重削弱个人的成长意识，让人在快速的变化的环境下，无法持续保持「判断能力」的有效性。这也让躬身入局、终身学习者有机可乘。

随着竞争的加剧，现代人力资源追寻的T型人才对能力的横截面以及核心能力的专业度都有着很高的要求。而能力项从「入门」走向「精通」却是一个无限精进的过程。

即便把范围缩小到互联网领域，也有产品、运营、技术、销售、设计、PMO、战略等很多门类。

**想**要培养多元能力模型，需要产品经理有足够优秀的抽象思维，将不同知识与信息的关系从「无序」发展至「网状」结构，给「创新与联想」打下坚实基础。

![](img/d4e0248dcfdb711228883f25b18b2c3e.png)

# **能力的拼图**

**产品经理的发展阶段分为「基础期」>>「资深期」>>「顶**级期」。 进阶 过程中需要培养三类能力：

**洞察能力**

+   基础的【用户研究、业务分析，逻辑能力】；

+   资深的【逆向思维与抽象能力】；

+   顶级的【商业思维、经营思维、营销思维】。

**架构能力**

+   基础的【交互设计、信息架构】（逻辑清晰，保障基础体验）；

+   资深的【产品架构】（化繁为简，高效地满足用户需求）；

+   顶级的【业务架构、战略设计】（整合内外部资源，参与市场竞争）。

**可选能力： **UI设计、编程、算法。

![](img/7d2c32e3dd4f97bdfb57770cc05c1e25.png)

**想**要成为「产品负责人」，需要同时具备「自上而下」和「自下而上」两种思考方式，将战略与战术紧密地结合起来。 避免战略无法落地，战略战术脱节，甚至没有战略的情况。

![](img/48e0a422f689da6a09587cc7d502c73b.png)

除此之外，「产品负责人」还需要逐步培养3个方面的能力：

**商业嗅觉及推理能力： **对产品扩张、商业化的敏锐感觉，以及推导出为何能获得更大的发展、如何能发展壮大；

**业务架构及创新能力： **规划、实施复杂的业务架构，通过产品、运营、市场的多维度布局来打通用户对产品特性的认知；

**善于沟通及领导能力： **鼓舞、带领团队向战略方向前进，克服非常之困难，完成非常之突破。

**其中「商业嗅觉」主要源自天赋，绝大多数人都不具备，后**天通过刻意的练习，可以一定程度得到培养。

# **实践的方法**

**1）如何向本质思考？**

**跳出思维惯性。 **这是思考本质的第一步，而「保持好奇心」是跳出思维惯性的最佳方式。

**一层一层，往下多提问题。 **只有持续不断地提出问题、勤加思考，才有机会思考出问题的本质。比如：兴趣电商只是短视频平台在早期阶段的形态，还是直播电商的终局？兴趣电商对货架电商是纯零竞争和还是总体有增量？发力兴趣电商是否会让短视频平台竭泽而渔？...

**日常实践并与人交流。 **保持广泛涉猎、让大脑思考更多题材，我们的CPU“计算”能力就会增强；同时，由于不同背景的人看问题的视角各不相同，与他人交流也是打破思维惯性、拓展视野的绝佳方法。

**2）用户研究的方法**

常见的用户研究方法分为「定性研究」和「定量研究」，并不复杂，初步掌握上手易，长期实践积累难。具体的形式有：

**① 深入访谈： **用大白话说，就是找典型目标用户聊天。切勿小看这个陪聊的事情，它是产品经理了解用户的最佳途径，没有之一。做访谈需要与用户交流，最重要的就是要有共情、共鸣、共话题。

王诗沐：访谈音乐产品用户，你不能只知道陈奕迅、周杰伦，而不知道新裤子、二手玫瑰，否则你将无法与非主流音乐爱好者产生共鸣；访谈摄影爱好者，你不能没用过Nice、In、Instagram、Tumblr、FaceU，否则你压根不知道现在流行的“姿势”“贴纸”是什么；

**② 焦点小组： **由一名主持人和一组用户（通常不超过八人）在一个主题下进行的访谈，通常会持续2~3个小时。

+   **优势>>信息量大： **相比于对一名用户深入访谈，焦点小组的优势在于能一次性拿到更多类型用户的信息，而有时候，用户之间发生意见的碰撞，也会产生更多的价值。

+   **风险>>从众反应： **但这种方法是一把双刃剑，在任何群体里都没办法忽略成员之间的影响，焦点小组有可能使用户说出“假话”：为了面子、为了与别人一样、为了隐私而隐藏自己的真实想法。

+   **应对>>尝试控场： **因此主持人需要暗中控制小组，让每个成员都能真实地发表自己的意见，避免出现少数用户频繁地阐述自己的观点，而其他用户只是简单地附和，这是焦点小组经常遇到的不利局面。

**③ 问卷调查： **通过问卷调查实现的一种定量研究。

**④ 可用性测试： **请用户实际使用产品或Demo，观察用户在使用过程中遇到的障碍，由此来发现产品可能存在的问题并提出改进意见。

**⑤ 留置研究： **它与可用性测试的区别在于，可用性测试是在现场时间段内进行的，而留置研究则是用户在实际场景里长时间使用中得出的，用户在这一过程中记录自己的使用感受、回答调研问题等，对产品的反馈会更加完善与真实。

王诗沐：“在网易云音乐诞生之前，我用定性访谈加定量问卷的方法，研究了用户发现音乐的方式。因为我本身对书籍、影视、音乐比较了解，对音乐行业也有所研究，所以对产品的雏形有了一些基本思路，大致想让网易云音乐从发现音乐的方式起步。研究后发现，当时不同用户群经常使用的发现音乐的方式虽然不同，但大体集中在以下六种方式上。对整体用户而言，依赖程度从高到低依次如下。”

![](img/865611032de55dedbcb9d3220954d1d3.png)

**3）深入场景，成为用户**

通过问卷、访谈等方式获得到用户的需求后，无法直接产出产品方案，**因**为创造性的想法往往不会直接来自用户。 这就要求产品经理持续接近用户，深入场景中积累对用户需求的感知和体察，依靠这些感知和体察，去设计产品解决方案。

王诗沐：网易云音乐的跑步FM功能，在跑步完成后用户需要什么样的结果页面，使其分享到朋友圈会感到满足？市场上也没有很好的案例供我们参考，因此我们只能去想喜欢跑步的用户在这个场景下会是什么样的反应，比如：

● 用户跑了半小时，跑了五六公里，听了八九首歌，跑步结束之后他想看到什么？

● 用户分享跑步FM的内容到🛰️朋友圈的动机是什么？如果用户同时使用跑步App和跑步FM，什么会使他分享跑步FM的内容到朋友圈？

● 如果用户坚持跑步，坚持使用跑步FM，他坚持的动力是什么？我们能提供什么额外的东西让他坚持？

**4）产品需求评估流程**

![](img/7b3bdfc25e90d49defab9e778f7ad976.png)

需求分析的常规流程可以分为2个阶段：

**① 收集需求： **需求的收集、分类梳理是一个尽可能获取足够多信息的过程。搜集需求并非让用户告诉我们要做一个什么具体的功能，而是搞清楚当前产品没有解决的需求点是什么。

**② 评估需求： **需**求有真伪，也有优先级，过滤无效需求，**从一堆需求反馈中抽象出共性，并设计合理的解决方案，考验产品经理对业务的理解深度、逻辑能力以及抽象思维。 在持续满足需求的过程中如何保持产品的核心体验不受损，也非常考验产品架构能力。

王诗沐：FM非常懒人化，不需要用户动脑，不合口味的话切歌即可，对于运动、驾车等持续的场景电台是很好的产品模式。但听FM的用户越来越多，歌单的播放人数就会下降，优质内容提供者获得的满足感会下降，进一步影响到整个歌单系统的供需平衡，而歌单系统对于网易云音乐来说是UGC的核心。因此在对待FM场景时，云音乐团队是非常谨慎的。

![](img/bfff64400ff235d5873413a380390913.png)

**5 ）产品架构：信息→业务**

产品经理着手架构设计，由浅入深依次为「信息架构>>产品架构>>业务架构」，PM逐渐从信息交互的设计者→商业模式的设计者，其所需要面对的问题复杂程度也呈指数级增长。

![](img/df32271a44728c4615e596a468d1506c.png)

由于产品功能之间是有关系的，非孤立的存在，架构设计不应该仅考虑单一的功能与系统，需要站在整体系统层面上思考。

通常情况下，产品架构设计需要重视3个关键点：

**① 用户容易理解： **如果用户理解不了一个产品，即便其拥有很多优点，也没什么用。易于理解，需要产品架构符合用户的认知和预期，它应该是结构清晰、合乎逻辑、合乎用户认知的。

有明确目标的用户，能够高效找到所需功能，快速上手产品；

目标不确定的用户，能够通过浏览逐渐发现自己需要的功能，逐渐理解产品。

**② 高效、易用： **由于组织分工与绩效驱动，大型产品往往堆砌了很多功能，这些功能需要大量的流程来支持。产品经理应当不断追求简练的架构，解决众多流程之间的兼容与连接问题，保证产品在各种场景下都是高效的、易用的，持续地带给用户良好的体验（例：淘宝，下单>>支付>>退款/退货>>仲裁>>评价）。

**③ 扩展性强： **优秀的产品架构能低成本、快捷地支持功能扩展。相反，差的架构甚至没有扩展能力，新功能只能重新开发，浪费人力和时间。「扩展性强」通常与架构简练有关，功能模块通用性强，从而能支撑更多的功能。

从结构上讲，耦合程度越高的产品系统，扩展性越弱。所以当设计一个产品系统时，需要考虑各个模块的耦合程度，评估是否要做扩展性强的设计。

王诗沐：最典型、最值得深入学习的例子可能就是🛰️。🛰️的产品架构扩展性非常强，用户使用的直观感受就是即便有这么多功能，还是相当简练的。这一方面与🛰️产品的极度简练与克制有关，更重要的一方面是其对长远业务的深度思考，想得特别清楚后倒推出所需的产品架构，因而🛰️的布局很稳健，架构的扩展性很强，能支撑产品很长时间的发展。
