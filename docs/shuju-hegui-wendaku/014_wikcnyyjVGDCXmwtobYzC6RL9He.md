
# 隐私政策更新和灰度测试的时间先后

> 来源：[https://docs.feishu.cn/docx/RA5cd72mmofUOXxCJpWccuYxnqe](https://docs.feishu.cn/docx/RA5cd72mmofUOXxCJpWccuYxnqe)

**问：**功能更新后，告知（或告知+同意）用户隐私政策更新的时机——需要区分灰度、全量吗？因为灰度和全量有时间差，如果灰度时就告知（或告知+同意）的话，部分用户还无法用到新功能；如果全量时再告知（或告知+同意），已经有部分用户用上新功能了。

**答1：**我们都习惯先灰度，以防万一可以尽快回滚。像隐私政策这种不会实质阻断交易的发布，灰度比例可以缩小。逻辑点在于你们评估对这个发布对业务体验的影响有多大。

**答2：**大家对灰度的定义不同，我们灰度只能内部用户方向，支付宝灰度是面向用户的。而且你的考虑里面漏了一点，隐私政策的生效时间，其实就算不考虑灰度，我们发布隐私政策更新都是有个生效时间的，一般性都是发布时间的后面几天。

**答3：**“建议”也不是强制。我怎么感觉司法部/最高院也没有这个精力专门去管这件事。所以从这点来看，其实不管有没有灰度，你都可以在发布后更新隐私政策，反正还没生效。这个时差对应法律效力和内容更新的关系，先梳理清楚再说。灰度只是一个插曲。
