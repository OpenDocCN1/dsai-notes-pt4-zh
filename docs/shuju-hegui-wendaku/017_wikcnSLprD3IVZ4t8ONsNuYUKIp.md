# 更新隐私政策后需要重新同意隐私政策吗

> 来源：[https://docs.feishu.cn/docx/RBoRdkRyNog4Owx6IBZcnDHJnkQ](https://docs.feishu.cn/docx/RBoRdkRyNog4Owx6IBZcnDHJnkQ)

**-问：**换设备登录同一个账号以后，隐私政策是还要重新签署吗？ 如果用户在设备A上使用某个应用时，授权了位置权限；那么在设备B上登录该用户账号，这个应用的敏感位置权限还需要重新再次授权吗？

**-答1：**账户注册时，完成了明示同意，就不需要重新授权。

**-追问：**那换设备登录时的确认点击动作算啥，只是从安全系数角度做的设置吗？

**-答2：**好像实务中都是让app扫码确认身份。

**-答3：**扫一扫有很多原因，不一定都是基于对已有的协议、政策的再次确认。也有可能是基于便利。在更换设备的情况下，像金融和游戏两种不同的业务，对身份验证的要求肯定不一样。我建议你确定一下具体的应用或者起码对品类进行举例，以便于核实具体的合规要求。你上面还提到了应用的敏感位置权限，这里就又会有其他的问题会出现。因为如果是新设备、重新下载、重新使用、这甚至还有可能涉及到分发平台或者对代码的合规的审查这一些东西，甚至还需要考虑技术侧的东西。比如内部处理用户数据这一块，Device ID变化的情况下咋处理。或者直接说不重新勾选的时候，API传参都卡bug了，你这Device ID不一样，跑不动了，当然一般不会出这么低级的错误就是了。另外涉及到敏感位置权限，一般这种离不开跟第三方的SDK打交道。得看产品在运营的地区的对这块的合规的要求。只要你能把pm搞定就行，毕竟多多少少会影响点用户体验。

**-答4：**用户体验跟用户教育成本有关，大家都这么搞，教育边际成本为0 ，就不会有用户体验的问题。

**-答5：**还有一个就是，对产品的忍耐程度的问题。如果产品的质量越高或者越具备垄断地位，那么即便你设置再多的一些不合理的障碍，用户也还是会接受的。
