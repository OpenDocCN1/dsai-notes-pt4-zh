
# SDK个人信息查阅复制

> 来源：[https://docs.feishu.cn/docx/EusEdu0jBoXJsIxsWpMcUul1n46](https://docs.feishu.cn/docx/EusEdu0jBoXJsIxsWpMcUul1n46)

## 讨论问题

**问：**关于周某和唯品会的诉讼中，一二审法院对于SDK收集个人信息的观点，大家怎么看？唯品会有提供义务吗？

相关阅读：（1）周某诉唯品会侵犯个人信息查阅权、复制权，法院这样判；（2）这起信息复制权案，注定是只振动金融业的蝴蝶。

## 法院裁判观点

### 一审法院

> 一审法院：关于周某所列清单中的“第三方SDK从唯品会公司收集到的其个人信息”。根据《唯品会隐私政策》中“您授权我们收集和使用您个人信息的情形——为您提供安全保障”条款约定“我们还可能在应用程序中嵌入我们合作的第三方合作伙伴开发的应用安全类的软件工具开发包（在本隐私政策中简称“SDK”）收集您的设备信息、服务日志信息……”可见，唯品会公司有向SDK共享用户信息的可能。至于第三方SDK实际收集了周某的何种信息，虽然附件一第三方SDK目录中列明了可能嵌入的第三方SDK名称、用途以及收集个人信息类型，但实际内嵌于唯品会APP中的第三方SDK以及该SDK实际收集的用户具体个人信息，用户是无法查阅的。

### 二审法院

> 二审法院：第三方SDK收集的个人信息，是指唯品会公司合作伙伴通过在唯品会APP中嵌入SDK收集的用户个人信息。唯品会公司主张并未参与该类信息的收集、上传、储存过程，根据现有证据亦未能显示唯品会公司收集了上述信息，故周某要求唯品会公司向其披露第三方SDK收集的个人信息，依据不足，本院不予支持。

## 审理焦点与思考

一审法院的裁判理由是基于共享，二审法院是基于唯品会主张没有收集且没有证据举证证明SDK有收集，两个审理的焦点至少有：（1）数据处理者或者共享数据处理的认定：（2）举证责任分配。

以及我个人认为对隐私政策中唯品会所做说明和承诺的解读。还有一点就是数据处理者对于第三方SDK的监督义务和向个人信息主体提供个人信息复制文本的义务之间有无关联。还有：基于这个案例，后续在隐私政策中声明自己对于SDK提供个人信息的有关免责说明，是否可以和有必要？以及如何保证声明有效？

**答1：**免责声明这个东西，感觉有些自欺欺人。该有的责任免不了，不该有的责任不需要声明，也就是做一个澄清。

**答2：**支持二审观点。

**答3：**隐私政策里不能有免责声明部分的。

**答4：**那可以说明第三方收集个人信息，向第三方询问索要？免责说明不准确。

**答5：**我感觉要求披露SDK的相关信息，也是此意图。SDK有收集的个人信息情况，可以直接向SDK方要，反正我负责披露所有SDK的情况，说明一下可以的吧，

**答6：**这个监管不认可。因为监管管不过来那么多sdk，所以他把责任转嫁到app宿主头上。

**答7：**同意不等于民事法律行为。

**答8：**纯粹个人观点：不能因有了共享清单或收集清单名义，将app与sdk二者的内部合作关系推至外部用户端，默认用户知晓该向哪一方索要信息，反而是拔高了用户寻求个人信息保护和行权的门槛、举证责任倒置也有点摆设了。
