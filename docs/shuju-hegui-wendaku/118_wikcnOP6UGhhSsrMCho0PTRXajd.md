# 双清单SDK如何披露

> 来源：[https://docs.feishu.cn/docx/V0rGdLeiVopIVTxyeupcUNnnn7v](https://docs.feishu.cn/docx/V0rGdLeiVopIVTxyeupcUNnnn7v)

**-问**：请教一下，工信部要求的“双清单”，其中“已收集个人信息清单”要求“应简洁、清晰列出APP（包括内嵌第三方软件工具开发包SDK）已经收集到的用户个人信息基本情况，包括信息种类、使用目的、使用场景等”，这里面，不收集个人信息的SDK是否也需要列出呢？还是所有内嵌的SDK都要列出？只看字面意思似乎前者即可，但看实践已经开始有全部列出的实践了，同时写上收集的个人信息种类是“无”。还有，为啥我看了几个例子，大家都把内嵌SDK收集个人信息的情况列到“第三方共享个人信息清单”中了？工信部要求是列在“已收集个人信息清单”中啊……SDK难道不是自行向用户索要权限和收集个人信息的吗，还需要APP共享给SDK……？微信、京东、平安银行、启信宝都是这样，我开始怀疑自己的理解能力了……

**-答1：**之前对比过一些传统金融机构和互联网平台，有些列得很细，有些粗一点。

**-答2：**你看一下清单内容 ，SDK收集的 也算App里面。第三方共享清单 是共享到外部场景 不仅是SDK 。

**-答3：**分三清单是不是更好一些（并列sdk清单）。

**-答4：**现在一般加上应用权限清单是3清单。

**-答5：**所以流程是skd收集→app：填写但收集清单；sdk／app→外部：填写共享清单吧。

**-答6：**有个事情你要知道。很多时候，所谓的监管尺度取决于他用的是哪家的检测引擎和规则。。并不是真正监管对某项的检测要求很高。所以很多时候所谓看不懂的做法。其实就是最粗糙，最保底的做法。

**-答7：**39家基本都是把sdk列入第三方共享清单里了，只是有些会增加表头区分本机采集还是接口传输，这是不是意味着监管对这种做法实际上是认可的？

**-答8：**委托处理和共享是不同的合规要求，如果是委托收集不需要单独同意，但是共享的话，理论上每一个sdk都应该单独同意，如果没有做到，不合规。所以sdk都列入第三方共享清单是会增加义务的。

**-答9：**如果在第三方共享清单中增设共享方式中说明与第三方关系呢（共同处理，委托处理，对外提供）。毕竟清单的作用是告知。我觉得核心问题还是判断sdk是否属于第三方。如果在宿主通过sdk采集信息的情况下，该sdk仍然属于监管定义下的第三方，那都列入第三方共享清单应无疑义，但宿主仍需披露与该sdk的法律关系；反之则应列入已收集清单。

**-答10：**你这么说也对，个保法里没有【共享】的定义，但是35273里【共享】的定义就是个保法里的【向他人提供】，一般人比较难区分。义说清楚，不管是同一张表分三种方式列明，还是分三张表，能准确区分就很厉害了。检测机构在扫App的过程中常常发现隐私政策里列的SDK和实际应用的SDK是不完全匹配的，更不用说对SDK进行准确区分了。

**-答11：**这点上合规和检测机构的立场感觉是一致的，都希望能做到据实披露。

**-答12：**第三方的SDK独立收集个人信息，不通过APP共享给SDK，这时候放在哪个清单里啊。感觉工信部通知原文并未涵盖此点。

**-答13：**我们最近也在做双清单，看同业和头部都放进第三方共享清单里，我们也打算照做了。
