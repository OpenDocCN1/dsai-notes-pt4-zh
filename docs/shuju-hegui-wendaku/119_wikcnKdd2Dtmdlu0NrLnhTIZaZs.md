# 有赞SDK注册双账户问题

> 来源：[https://docs.feishu.cn/docx/XOBcdn878oQ6vwxDu8TccVMsnzf](https://docs.feishu.cn/docx/XOBcdn878oQ6vwxDu8TccVMsnzf)

**-问**：有些APP是基于有赞SDK的版本上开发的，在APP上注册后，会关联注册一个有赞的账号，这个怎么向用户说明，如果到时候想把用户从有赞迁回来，如何向用户说明，另外此类用户是属于有赞的用户。还是自己的用户？管理责任在谁。看有赞的隐私协议后就更晕了 ，估计网信办 和 工信部都没有想到会有这么多的场景。很可能出现合规但违法的场景。

**-答1：**同样问题，还有猫库啥的...这些Sasa开发平台的产品..

**-答2：**弱弱请教 有赞 猫库的SDK开发平台和《网络安全标准实践指南—移动互联网应用程序(App)使用软件开发工具包(SDK)安全指引》这里面说的开源SDK有什么关联或区别哈～

**-答3：****有赞业态**比较丰富，也有SaaS产品的电商软件，还有上面提到的原生技术框架给第三方封装成自己的商城。在这个场景是，有赞是作为PaaS平台了，第三方开发者在有赞云上开发出各自SDK。

-答4：我很多情况下只能说如果做了充分的提示，从合规的层面上可能挑不出毛病来，不过从法律层面，深究可能还真有解释不清的情况

**-答5：**这类关联注册的，注册一直是合规头疼的地方。我没看过你们的模式，但是一般来说，你们应该是数据控制者，第三方登录的是数据处理者，所以数据迁移不是什么困难的事情。困难的反而是怎么解释要多方关联注册。

**-答6：**有一个类似场景，移动电信联通手机号一键登录的，同时会注册2方的用户。

**-答7：**一键登录更特殊点。与其说注册，不如说在快速登录注册前提下，加强了登录效率和安全性。用户反而更好接受。

**-答8：**一键登录不同呀，现有运营商注册 再有应用注册。上面的案例 应该类似 电子签的流程。应用注册中需要在第三方注册。那么在应用注册流程中就分：应用注册、明示告知、三方注册、三方发送注册确认通知、告知用户已注册。

**-答9：**SaaS就是这样的，本质是云服务。

**-答10：**这个场景，还原下就是app在进行一键登录本地后，还会增加一道输入手机号码，这样用户信息留存在app么。

**-答11：**一键登录流程 运营商会取本机电话号码 ，识别、取号、展示、确认、完成。

**-答12：**不用你输入，一键登录只能是当前手机号。双卡双待的就是主号。其实他主要功能就是确认手机号码真实性。而不是通过短信验证码来确认。其他注册流程没有差别。

**-答13：**双卡双待，识别的是当前数据流量号。

**-答14：**区别于人事SaaS：如Moka，财务SaaS：如金蝶云，电商SaaS因为各种原因吧：直面c端，淘宝京东教育太好了，国内牌照管制原因，要么被当成平台，要么当成SDK，目前也是摸着石头探合规。
