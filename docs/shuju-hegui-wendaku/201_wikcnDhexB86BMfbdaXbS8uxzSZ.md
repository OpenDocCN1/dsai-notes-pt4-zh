# 提供无需手机号账户服务的合理性

> 来源：[https://docs.feishu.cn/docx/Ox6vdihKloMmzBxb7VZcO3I1nnc](https://docs.feishu.cn/docx/Ox6vdihKloMmzBxb7VZcO3I1nnc)

**-问**：**请问同一**APP中提供需要手机注册的账号服务(实名)和不需要手机号注册的账号服务(非实名)，这个要求合理嘛？比如通过邮箱注册。

**-答1：**是不是实名注册都能使用，但是使用一**些功能时，必须要实名**（**例如发帖等）。为了用户数、D**AU等指标，产品更希望不是实名注册也能用。

**-答2：**邮箱注册也是个人信息吧，只是识别能力不如身份证手机号，**很多场景也**不是非要实名才能提供**服务，比如营销，娱乐啥**的，所以我也觉得是收集个人信息的注册用户。

**-答3：**是的，我理解也是注册用户。

**-答4：**感觉细了说是**强实名****（手机****/身份证/姓**名/**其他敏**感信息）、弱实名（邮箱/可能🛰️支付宝账号也算？）、非实名纯浏览（应该还会监控设备信息这些吧？）的几种模式。应该还是综合分析app的现有功能、各种功能使用各种个人信息的必要性来看吧，整体细化肯定是便于合规的。我想着比如非实名浏览的游客模式，咱们也能有盈利点（比如广告推送导流），这个应该是搞游客模式除合规目的之外的考虑点吧。但也要考虑成本，转化率太低也不划算。

**-答5：**相关法规也有**实名制要求**。

> 网络运营者为用户办理网络接入、域名注册服务，办理固定电话、移动电话等入网手续，或者为用户提供信息发布、即时通讯等服务，在与用户签订协议或者确认提供服务时，应当要求用户提供真实身份信息。用户不提供真实身份信息的，网络运营者不得为其提供相关服务。

> 《网络安全法》第24条

> 互联网信息服务提供者应当按照“后台实名、前台自愿”的原则，要求互联网信息服务使用者通过真实身份信息认证后注册账号。

> 《互联网用户账号名称管理规定》第5条

我理解，**实名制是**基于注册账号的升级。在产品中根据角色分配相应的权限：游客、注册用户、实名制用户、未成年用户。每一个角色 都有对应的权限。游客仅限：浏览咨询 和app 站内全局广告；注册用户：使用不需要实名制的功能；实名制用户：几乎所有的功能；未成年人：功能缩小到可以使用的功能。鉴于目前主流的 第三方登录 、手机号码注册。已经在注册中完成了实名制。同时，对于大陆居民来说邮箱注册不再成为习惯 。对于面向大陆的用户采用区分实名制、非实名制意义不大。
