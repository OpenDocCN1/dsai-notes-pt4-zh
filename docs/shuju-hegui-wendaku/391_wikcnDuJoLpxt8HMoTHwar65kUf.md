
# 黑名单用户识别的告知

> 来源：[https://docs.feishu.cn/docx/XSNndviCJofoAcxvLjCcRMZ9npd](https://docs.feishu.cn/docx/XSNndviCJofoAcxvLjCcRMZ9npd)

问：淘宝此类平台把用户拉进黑名单或者封号，是不是也需要通过个人信息进行识别啊，甚至会用到身份证号什么的。不过淘宝和京东的隐私政策好像没有涉及。

答1：电商买东西，商家要把信息给到快递公司这种，我理解算的。而且很多app的逻辑其实不是给到第三方，而且有一个让你自己填写的界面，然后可以从地址簿调去地址联系方式，从而便捷填写。逻辑还是稍有不同。具体情况具体分析吧。

答2：不用，可以用去标识化数据识别。比如哈希摘要。而且就算没有，也没侵犯用户隐私。因为没有关联数据，就一个手机号或者身份证，其实也无法识别用户。

答3：哈希算法是去标识手段，去标识后的乱码仍然是个人信息。举个例子，如果将这些代码打包出售，是有价值的。其他公司根据用户手机号码及相同的哈希算法，算完之后撞库就好。因此，可能会不符合，删除个人信息相关要求。

答4：加盐值后基本没法碰了。但是企业还是可以的。外部是没法了。

答3：现在联邦学习是不是解决这个撞库的技术问题

答4：以我粗浅的理解，貌似关联不大。主要是解决不交换个人信息的前提下，多方联合建模的问题。

答5：淘宝封号会根据设备信息 去做关联封号

答6：首先 `hash` 是散列 不可逆，因为撞库风险需要用加盐或者慢速散列 如 `bcrypt`。其次 海外监管很早期，对标准散列作为安全技术的使用效果进行了否定，比如下面这个链接：

（1）https://www.davinci.idv.tw/news/1058；

（2）https://meowtechlaw.com/2021/11/25/10-misconceptions-about-anonymization/

再者 传统对称非对称加密 与散列之前，不是对等替代关系，也不是所有的哈希都要加盐。关于淘宝使用设备信息，进行业务安全保障措施 限制登录和冻结账号，在隐私政策中有披露，存疑的可以直接通过隐私政策中链接发起咨询。关于区块链 基于环签名 秘态查询 可控匿名技术 多个能力，可以实现防止个体删除 等多种安全和隐私能力。
