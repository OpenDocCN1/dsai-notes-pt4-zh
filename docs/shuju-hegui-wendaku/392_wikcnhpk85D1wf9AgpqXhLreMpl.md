# 告知的颗粒度

> 来源：[https://docs.feishu.cn/docx/DOObdwv0BoWpFCxrT6TcKWVfnHZ](https://docs.feishu.cn/docx/DOObdwv0BoWpFCxrT6TcKWVfnHZ)

**-问**：关于授权内容要细到哪个颗粒度，大家有没有什么看法？举例，平台要给第三方导流，可能要提供客户的各类信息，比如姓名、手机号、邮箱、地址、身份证、银行卡信息（有多个字段）、交易信息（多个字段）等等。直接写“您的身份信息、联系信息、交易信息”就可以呢，还是要更细的颗粒度？

**-答1：**如何理解个保法下“个人信息的种类”，这也是个玄学。某些监管方的极端偏好是告知时需要具体到“字段”且不能“等”、不能写“类”信息，按照35273附录中的颗粒度来写都不够。业务侧则对如此高精细度的披露可能会感到很棘手，比如业务活动中对个别字段可能不时有调整、但又够不上需要重新获取同意的程度，或者目前场景下也难以穷尽列举各种技术参数（严格意义上都是“个人信息”）……只能兼顾平衡一下监管需求和业务需求了，且确保对敏感个人信息能准确披露到字段比较稳妥。

**-答2：**同业现在没有颗粒度更细的。不用 等。隐私政策和单独同意都没有到字段及其定义。影响客户体验。

**-追问：**现在有类似的处罚或通报案例吗？认为披露不够细的。关键有些字段吧，光看名字都不太理解是个啥玩意。

**-答3：**数据处理协议原则上也要细化类型到字段。大机构(银联 国开行 百行征信)之流就连数据安全条款都不让添加完全。11月银保监各局将报送整改报告和经典案例，到时候看看合规口径。

**-追问：**这个原则咋落地呢，所需字段是根据业务需求变化的，只能想到把字段范围写宽点，变化的时候双方邮件确认一下。

**-答4：**比如征信机构，外数采的时候实际上是把已有的数源带过去换签，合同附件会有字段类型。但回到隐私政策或授权书没法细化。银企 银政 银税等等都不会落实字段。实际上是各自法务都不懂，写个范围差不多了。
