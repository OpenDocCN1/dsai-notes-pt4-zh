
# 用户申请撤回同意时后端数据的处理

> 来源：[https://docs.feishu.cn/docx/Lu6UdzPu0oVis9xAL5ac9JCKnjc](https://docs.feishu.cn/docx/Lu6UdzPu0oVis9xAL5ac9JCKnjc)

## 问：用户申请撤回同意后，这个用户的后端数据，一般怎么处理比较合适呀？

### 答1：个保法不是说这种情况应当删除嘛，那就一段时间内删除？

### 答2：如果有法律法规规定不能删除的，不用删。不然就物理删除，后端系统在逻辑上增加数据缺省下的兼容。还可以加密，加完把密钥丢掉删掉，间接达到删除的效果。

### 答3：可以用《个保法》第47条最后一款。具体是否技术上可行，让技术人员自行判断吧。

> 删除个人信息从技术上难以实现的，个人信息处理者应当停止除存储和采取必要的安全保护措施之外的处理。

## 追问：如果技术说有交互不能删，法务怎么处理呢？

### 答4：让他们自行评估，领导签字，承担法律风险即可。

### 答5：撤回同意是不是一般就注销账户了。在产品设计上，增强用户“注销账号”“撤销同意”的损失感，让用户在一定程度避免注销账号。毕竟注销账号可是真正的意味着一位用户要离开了自己的平台。可以适当把入口藏得深一点。

1、注销账户后，用户的所有权限全部锁定，释放相关的用户名与手机号。对于平台而言，数据依旧存在，只是将用户锁定了。

2、电子商务法的要求，保存三年的交易信息。其实平台基本不会对用户的信息进行删除，都是默默的躺在数据库里，毕竟对数据库进行删除工作要慎重。删了`uid`的映射关系就好了。而且删映射关系也可以不是立马删，因为用户的这个行为可能是一时冲动。
