# 投标对外提供员工个人信息

> 来源：[https://docs.feishu.cn/docx/Rrk3dUhTdopZNkxtCqVcCgmYnof](https://docs.feishu.cn/docx/Rrk3dUhTdopZNkxtCqVcCgmYnof)

**-问：**公司HR问投标项目后续可能频繁发生，是否可以在员工入职时（或在职员工）统一安排签署个人信息使用授权？比如授权提供个人信息以便于公司经营范围内的各项招投标项目。还是需要按照具体事项一事一议，单独授权？按照个保法，我觉得最好一事一议，但是HR和业务想一劳永逸，直接搞个规章制度或者签个授权书，一揽子解决。

**-答1：**能弄个制度已经非常规范了，每次签感觉很麻烦，可以在对外提供时再补封邮件落实告知义务吧。

**-答2：**《个保法》里基于人力资源管理的目的处理，是可以作为处理个人信息的合法性事由的。但是仍然需要进行告知，这些告知可以在入职的时候签一份总体告知，或则在员工守则里说明。入职后，有一些非基于人力资源管理目的的使用员工个人信息的需求，就要再次告知+同意。这些就单独做。

**-答3：**参考**42574**的关于单独同意的做法吧。

**-答4：**还有一个比较双保险的做法，做完规章制度+入职时期的同意授权后，根据投标项目的具体开展的，上OA时，提交资料，直接OA流程里嵌入单独同意授权的。

**-答5：**这种对外招标，算人力资源管理么？我觉得不算吧。

**-答6：**因投标里用到的资料，身份证、毕业证、社保流水等比较敏感的信息了，单独授权同意会更保险一些。

**-答7：**这不算人力资源管理的范畴吧，现在对于人力资源管理本来就是很狭窄的解释。

**-答8：**人力资源管理这条不稳妥，实践中被推翻的可能性大大有。既然做了，就告知+同意，反正都要签或勾选。

**-答9：**招投标要的信息属于商业运营过程的需要用到的信息，资质证照（毕业证，身份证、社保流水等）流水，OA告知和单独邮件通知回复或者线下签文件后，都比较常见。

**-答10：****一次性的告知是**没法做到完全合规的，因为要告诉接收方。每次投标接收方不同。

**-答11：**这**里的需求链路万变不离：需求方（投标部门）-法务（咨询）-**人事部门（落地）。概括式授权和逐个授权的区别在人事部门的执行难度上，那么要么让需求部门推动人事部门，要么就选择牺牲法律风险，降低人事部门难度，增加法务部门风险水位线。所以我会觉得走两条路都可以，核心在能拿到结果以及自身法务能接受这个风险。

**-答12：**有点好奇，为啥投标还要社保证明。

**-答13：**社保证明的，不少建工类项目需要。

**-答14：**毕竟合同可以造假，**社保很难造假**。

**-答15：****政府**项目和国企类的招投标，一般都要求相应实施人员具备特定**资**质，拿社保资料是为了避免投标人拿第三方人员的资质来凑数。GDPR刚出来不久时还在某外企做合规，这类员工信息的招投标使用和运营外宣使用的授权就搞得贼复杂和心累，还是得联合了HR和销售等业务部门做了纸质件的授权。

**-答16：**就像我去推行签署全员廉洁协议，HR就有不乐意的，无非增加工作量了，怕得罪人了，问能不能发个公告就行了。不行！

**总结：**业务便利性和合规性之间的妥协。
