# 委托处理的认定

> 来源：[https://docs.feishu.cn/docx/K6HOd33vJoZCw7xoMb6cKW6Mnbg](https://docs.feishu.cn/docx/K6HOd33vJoZCw7xoMb6cKW6Mnbg)

**-问：**我们为B端商家提供快递服务，收件人的姓名、电话、收件地址的数据也是商家那边给到我们的。现在商家无法导出这些信息，要求我们导出，这是不是也会存在一个个人信息提供的问题。我问到的信息是，商家那边也能看到这些信息，但是无法导出。其实这些个人信息不导出，也不影响我们的快递收发。

**-答1：**合同范围内互相传输而且还是商家自己的客户应该问题不大。

**-答2：**行使一下审计权，看看数据接收方拿到这些数据都干嘛了，请提供数据明细和这段时间的处理情况说明。

**-答3：**如果他是委托方，是不是有权利要求归还。

**-答4：**我觉得要分情况看：（1）如果快递公司拿到用户数据后，后面和用户无触达，快递公司始终没拿到过用户单独给他们的授权，那快递公司就单纯是为了实现快递运输这个目的下的一个受托方，听委托方的；（2）但如果快递公司通过小程序或者app触达了用户，快递公司又变成了独立的个人信息处理者，他接受数据是基于共享关系，这种情况下，快递公司要再把数据回传回去，就没那么简单了…我举个极端例子：商家留存个人信息的时间要满足最小必要，那讲道理当一个订单结束掉+无客服售后+超出了法律规定的电商订单留存的信息，这个信息是不是就要删掉了？假如快递公司基于对快递物流面单信息保存的时限规定，留存相关信息的时间是超过商家可以留存的期限的，在这个时间差里，快递公司不能基于商家要求，就再把数据回传回去吧。

**-答5：**商家和平台之间应该有协议限制了商家的权限吧，导给他平台会不会来argue。我感觉如果是平台上的商家的话，从个人信息授权的角度看，一般是用户把信息授权给了平台，平台再提供给商家，这个过程里面会限制商家一定的处理权限，所以一定程度上商家应该算受托处理者。即使快递直接跟商家合作的话，数据的传输一般还是通过平台系统传的，感觉快递公司算转委托的受托处理者。所以回传应该不算提供，但是突破了平台给商家的权限，可能有平台方面的风险。不过快递一般会也会和平台签协议，可以看看有没有限制条款。

**-答6：**为啥平台里的商家是受托处理者？感觉这个逻辑不太通啊！商家是为了销售和快递自己的产品而获取并使用用户个人信息，平台和商家应该都是信息处理者吧？虽然平台在将用户信息提供给商家的时候会有限制，但是这应该不改变商家可以自行决定信息处理目的和方式的本质吧？平台里的商家也是用商家自己的隐私政策，并不是平台的隐私政策会涵盖商家的个人信息处理吧？

**-答7：**这个问题其实非常值得讨论，虽是小处着眼于隐私政策和个人信息处理，大处却是平台经济模式下的各方责任划分，是关系平台经济模式发展的根本问题。关于平台与平台上的运营者（一般指平台B端用户）之间的个人信息处理身份，大部分还是认为构成“独立处理者”模式、非受托处理/共同处理，否则平台责任边界失控、平台经济模式发展有碍，但是在不同行业和业务下的落地情况确实有差别。1. 主流应用商店平台与平台上的运营者执行“各自独立处理者”的模式比较清晰彻底：平台上的APP开发者必须在提包时提供开发者自身的隐私政策——该文件和平台方的隐私政策完全是相互独立的两个文件。APP用户、APP开发者和应用商店平台方，即平台经济上的多边交易方都不会认定平台上的单个运营者是“受托方”或与平台是共同控制者。2. 也逐步有小程序平台要求开发者要有自己的隐私政策（类似对APP的要求），即明确“各自独立处理者”模式。但如果木有的话，也并不意味着一定就无法提审上架或下架。3.从C端用户感知来看，电商平台等其他平台对“各自独立处理者”模式有些模糊不清（自营的另说）。在35273的2017版曾经在正文中举例写“服务平台与平台上的签约商家为共同个人信息控制者”，但这个表述在2020版更新时被彻底删除。可自行体会这一变化。4. 对于本身就是做B端服务的SDK方等这种“平台方”，本身并不与C端交互，不是平时多说的“多边交易”平台。这种SDK多为受托处理者、C端用户无感知，也是正常的。要发展健康的平台经济，法律上的核心难点之一就是界定平台责任边界，而这个边界划分其实是动态地走平衡木：一方面，要求平台方承担合理责任、以更有效和更经济的方式维护平台良好生态，甚至越大的平台要承担的责任越多（此处自带BGM流行曲：“守门人”立法）；但另一方面，也不能要求平台方的责任边界无限扩充，无论是公法or私法领域，无论是知产保护or数据合规方面。
