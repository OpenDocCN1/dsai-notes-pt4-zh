# 有赞账户绑定的理解

> 来源：[https://docs.feishu.cn/docx/UHl8dA7tcoP1f7xBIHlcuOtlnrb](https://docs.feishu.cn/docx/UHl8dA7tcoP1f7xBIHlcuOtlnrb)

**-问：**今天和有赞的人沟通下来 有赞的这个账户绑定也没单独同意 几个协议放在一起的。我们使用的服务场景是在有赞的有赞微商城开设一个店铺，和我们的小程序账号进行绑定  ，并使用有赞的平台卖东西。

**-答1：**因为电商会存在需要提供信息给商家的场景，所以会有单独分开的授权。

**-答2：**有赞对自己的定位是电商服务平台？icp证我记忆里是不是都没有？

**-答3：**有，不是平台。有兴趣的一起论证下SaaS电商服务软件是否是电商平台。我很好奇的一点事，为啥会认为一个提供SaaS服务的软件服务提供者是电商平台呢？是外观主义还是京东淘宝固有思维？财务的金蝶云，人事的北森软件，都是SaaS，没有类似是否是平台定义这样的疑问。

**-答4：**因为电子商务法。

**-答5：**我们是使用了有赞提供的所谓标准化SAAS服务、直接开了我们名义的小程序。在平台属性有待讨论的前提下，用户注册时一定要用户及品牌商户同意有赞的会员协议及隐私政策，且授权的内容超过我们理解的服务所必须的范围、跟我们与有赞本身签署的采购服务协议比也多了很多隐性的东西，我们是觉得有强制的嫌疑的。我们的真实体验是，合同有效期内最初的小程序版本只是同意我们的政策，后期在我们也不知道的情况下，C端消费者注册登录入口莫名变成了还得同意他们的协议跟政策。

**-答6：**这大概是平台的基本逻辑，品牌只是入驻，通过平台可以拥有自己的会员（有时候店铺会员甚至不是品牌会员啊）。

**-答7：**SaaS的法律地位，具有极强的场景特殊性，很难一概而论。这个依赖于资金流、协议留、信息流、数据流等，以及SaaS本身的商业模式、未来业务方向等。最终再去看到底是代运营提供方、软件技术提供方、数据技术提供方、存储空间提供方，还是交易平台服务提供方、信息服务提供方、营销服务提供方等等。实际上，现在很多电商类的SaaS服务商都会综合提供上述服务中的一种或多种。

**-答8：**独立数据处理者，受托处理，不构成数据处理者，三种情况都有，需要结合法律关系分析。其实也说明了其中的监管风险。
