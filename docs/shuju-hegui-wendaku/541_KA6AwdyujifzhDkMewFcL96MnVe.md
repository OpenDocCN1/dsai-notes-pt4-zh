
# 文件加密是去标识处理吗

> 来源：[https://docs.feishu.cn/docx/YGTadLBNboORCjxsd5gcCwOxnue](https://docs.feishu.cn/docx/YGTadLBNboORCjxsd5gcCwOxnue)

### 问
个人信息的去标识化按理解是对个人信息，即数据进行去标识化（如加密、抑制、假名或者泛化等操作）吧。如仅仅是对载有个人信息的文件（如Word 或者Excel）进行加密，应该不属于去标识处理的吧

### 答1
加密不属于，实际上去标识化都很难真的实现。去标识化要求不能还原。加密如果可以解密也属于可以还原？

### 答2
加密属于去标识化方式。如果是图片，视频。那么加密后，我可以认为是去标识化了。文档虽然同理可证。。但是总觉得怪怪的。

### 答3
我理解去标识化的对象是数据本身，仅仅文件加密的话，不构成去标识化。

### 答4
信安角度来看加密encryption和去标识化/假名化pseudonymization是不同的概念。虽然两者指向的都是confidentiality，性质是不同的。个保法follow的是GDPR标准。

### 答5
去标识欧盟定义=中国=Iso 美国不认匿名化。各法地域，定义有区别。Iso 定义，包括加密，这个算安全风险削减措施。法律归法律谈 安全归安全谈。之前我简单整理过，供参考：

● 中国：

去标识化：通过对个人信息的技术处理，使其在不借助额外信息的情况下，无法识别或者关联个人信息主体的过程。注：去除标识符与信息主体关联性的过程。

匿名化：通过对个人信息的技术处理，使得个人信息主体无法被识别或者关联，且处理后的信息不能被复原的过程。

分析： 中国的去标识化、匿名化与欧盟几乎相同，在技术层面去标识化包括了匿名化技术。

● 新加坡：

去标识化：去除如姓名、地址、身份证号码等能够直接识别到个人的标识符，而间接标识符处理不在去标识化的定义中。

匿名化：将个人数据转换成不能用于识别任何个人的数据，包括阻止重识别的技术和措施，没有限定对象为直接标识符还是间接标识符。

分析：新加坡本身对个人数据的定义范围较小，去标识化是匿名化的第一步，且匿名化没有强制要求不可逆，可理解为以使用场景区分基于identity mapping table要求的去标识化。

● 美国：

去标识化：去识别化是指无法合理链接以推断有关特定人的信息的信息。对于被视为去识别化的数据，企业必须采取某些措施来确保信息不会被链接回个人——包括公开承诺不会重新识别信息，并根据合同要求去识别化信息的任何接收者也这样做。

匿名化：因对去标识化的困惑而不使用匿名化。

分析：“链接和推断”及“采取某些措施来确保信息不会被链接回个人“，且企业与第三方均不可做重识别。非常接近匿名化“不可逆“的要求。

● 欧盟：没有去标识化、匿名化定义，借用ISO定义

去标识化：去除或者降低个人识别信息与数据主体之间联系的过程。

匿名化：数据控制者或者其他合作方对个人信息进行不可逆的改变，使个人信息不能再直接或者间接的识别到个人信息主体的过程。

分析：去标识化包含了匿名化技术。同样对个人信息要求“不可逆”。切片看问题。对外传输 属于数据处理行为，看数据本身和接收方，接受方是可以拿到明文数据，法律层面的问题。文件加密只是将接触数据的人做限定，这是安全风险的控制措施。
