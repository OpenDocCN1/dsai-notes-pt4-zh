
# 隐私计算可以解决安全问题吗

> 来源：[https://docs.feishu.cn/docx/AjIqdRW3ooWidex6HrzcvwJynlb](https://docs.feishu.cn/docx/AjIqdRW3ooWidex6HrzcvwJynlb)

## 问
我国数据安全法律法规体系中，除《民法典》外，未使用“隐私”一词，“隐私计算”何以被认为是解决数据安全问题的路径？

## 答1
我觉得，这个问题的问法措辞有点不严谨，“隐私计算”（尽管我倾向于用“隐私增强技术PET”这类表述，姑且还是随大流叫“隐私计算”吧）的焦点的不是解决数据安全问题，而是个人信息保护问题（或者叫“隐私保护”）。尽管二者有很多交集，但还是有一些区别。前者重点在于数据的防泄漏、防篡改、防丢失等，而后者一方面只关注数据中跟个人信息有关的部分（隐私计算只能解决个人信息保护领域的一些问题，而不是解决通常意义上的数据安全问题），另一方面后者比较多地关注个人信息主体权益保障（或者叫“隐私权利”）。

当然，隐私计算、“数据可用不可见”等概念也涉及了一些数据安全、数据防泄漏相关的内涵，但前者更多的是从“主动、预防”“尊重用户隐私”“最小化”“以用户为中心”等的个人信息保护（隐私设计PbD）相关理念和原则出发，即便涉及了数据安全的一些内容，那也是配合实现前者的一些措施。

此外，“隐私计算”是一个“法门”，但好像不是“不二法门”，个人信息保护的有效实施依赖于各种管理的、流程的、技术的“法门”组合在一起共同努力。目前很多企业因各种原因，尽管尚未应用“隐私计算”，但也通过其他各种“法门”去尽力去实施了个人信息保护工作并基本满足了当前的合规要求和业务需求。

隐私计算、隐私增强技术的确可以解决一些隐私保护、个人信息保护领域的问题，但不是万能的，真要用起来，有一些门槛（成本），也要看应用的场景，不能生搬硬套，有多大脚，穿多大鞋。

业界确实有一些“唯技术论”的人群，认为这个领域所有的问题都可以通过代码、技术来解决，甚至有一点近乎于迷信的地步。虽然我也算是个技术人，但我不认为在这个领域仅凭技术就能解决所有问题。

还有一点：国内与数据安全、数据保护相关的法规体系中只有《民法典》提到了“隐私”这个概念，而其他法规标准没提。对此，我认为国外数据保护相关法规中所说的“Privacy”不能完全等同于国内的法规语境下的“隐私”。虽然国内《数安法》《个保法》等数据安全相关法规中未直接提及“隐私”这个词，但在其中高频提到了“个人信息”“个人信息保护”等表述，我认为这类表述与国外讲的“privacy protection”的内涵比较接近。

一些术语和表述因不同国家和地区文化、传统、用语习惯等差异，可能在翻译之后仍然不能100%表达出原汁原味的意思，需要考虑一下因地制宜。Privacy computing直接翻译成“隐私计算”的话，也有点奇怪，隐私如何能被计算呢？
