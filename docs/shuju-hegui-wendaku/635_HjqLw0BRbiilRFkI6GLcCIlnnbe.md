# AIGC前端对话留存

> 来源：[https://docs.feishu.cn/docx/Bj2LdqY9WoiknLxk0ihcpZtQnUe](https://docs.feishu.cn/docx/Bj2LdqY9WoiknLxk0ihcpZtQnUe)

**-问：**现在关于AIGC生成内容，有必须提供给用户查看历史对话记录的要求嘛？业务正在做类似的功能，在考虑要不要优先做这个。我看好多AIGC工具都会做这个，但我目前没看到法规或标准对这个的明确要求。感觉优先级可以不高把。

**-答1：****后台有就满足合规要求**了，前台有是用户体验的事儿，但我觉得是基础功能吧，找不到对话历史算怎么个事儿呢。

**-答2：**目前没有吧，可以根据产品功能来弄。比如只存过去一周。正好问个技术上的问题，大模型的上下文理解是有时间限制的吗？比如我同一个对话，7天之后再去问，好像就不再调取上文了。

**-答3：****我感**觉这个蛮看模型功能，似乎都是可以设置的。有些按照客户意愿可以分多个对话框（可以选择把所有历史记录作为input对新问题进行综合前述性的输出），有些只有长串的一个对话框（这种情况下通常就不会把历史记录作为背景对output产生影响）。

**-答4：**有分文字存储大小和上下文响应时长两种。主要看模型自身的能力，简单说时长越长，文字越多，理解能力越大。也就是占用算力越大，所以各家会做一定限制，但不统一的。

**总结：**

1.前端历史对话留存是用户体验的事儿，而非合规要求。

2.上下文理解的时间限制，看模型能力，也看产品设计。
