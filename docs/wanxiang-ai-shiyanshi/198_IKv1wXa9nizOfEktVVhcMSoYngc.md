# 第一章：Vibe Coding 概念认知篇

## 1.1 什么是 Vibe Coding？

Vibe 在英文里翻译就是“氛围”“感觉”的意思。所以 **Vibe C**odi**ng，直译过来**其实就是“氛围编程”或者叫“沉浸式编程”。但这里的“沉浸”不仅仅是让你沉浸在一个有仪式感的编程环境里，更重要的是它颠覆了我们以往写代码的方式。

| #####  Vibe Coding 发展简史 | #####  | #####  |
| --- | --- | --- |
| ##### **时期** | ##### **事件** | ##### **关键背景/意义** |
| 2010 年代初 | Bubble、Airtable、Retool 等无代码工具出现 | 无代码工具降低编程门槛，让非技术人员可通过可视化操作实现简单功能，为 Vibe Coding 奠定“低门槛创作”基础 |
| 2017 年 | 机器学习模型爆发（被称为“AI 之年”），AlphaGo Zero、Transformer 等技术突破 | AI 能力从“特定任务”转向“通用推理”，为后续自然语言驱动的代码生成提供算法支持 |
| 2021 年 | GitHub Copilot 上线（首个大规模商用 AI 结对编程工具） | AI 首次深度介入代码生成流程，开发者可通过自然语言注释触发代码补全，模糊“编码”与“描述”的边界 |
| 2024 年 | Cursor 的 Composer 功能上线，标志 Vibe Coding 正式诞生 | Composer 支持“自然语言指令生成完整代码逻辑”，无需手动编写核心代码，定义了“以意图为中心”的编程范式 |
| 2025 年 | Lovable、Bolt、Replit 等工具普及，Vibe Coding 进入“人人可用”阶段 | 多平台竞争推动工具轻量化、场景化，非技术用户可通过“说需求”直接生成实用工具（如自动文件整理、待办清单） |

**「vibe coding」**这个概念最早是由 Karpathy（OpenAI 联合创始人、曾任特斯拉人工智能和自动驾驶部门（Autopilot）负责人）提出的，简单说就是通过对话让 LLM 编写代码，而你只需要沉浸在解决问题的「氛围」中，同时忽略生成的代码细节。

![](img/c7d153a1e9fe05ecadbe84889825e79c.png)

想象一下，你想装修自己的房子。

+   **传统编程**：就像是你必须亲自学习成为一名建筑师、水管工、电工和木匠。你需要精确地计算每一块砖的尺寸，了解每根电线的规格，亲自画出复杂的施工图纸，然后一砖一瓦地把房子盖起来。这个过程非常专业、严谨，但对新手来说，门槛极高。

+   **Vibe Coding**：则像你是一位业主，聘请了一位经验丰富、善于沟通的室内设计师（也就是 AI）。你不需要告诉他具体的施工参数，你只需要向他描述你的“Vibe”（感觉）：

+   “我想要一个‘侘寂风’的客厅，色调要柔和，以米白和原木色为主，光线要充足，家具要少而精，给我一种宁静、放松的感觉。”

设计师（AI）听懂了你的“Vibe”，就会自动为你生成专业的设计图纸、施工方案，甚至列出材料清单（也就是代码）。你只需要确认方案是否符合你的预期，然后让施工队（电脑）去执行就好了。

所以，**Vibe Coding** 的核心就是：**使**用自然语言（就是我们平时说的话）向 AI 描述你的需求、目标和感觉（Vibe），由 AI 自动生成可执行的代码来完成任务。

在这个过程中，你关注的是“**做什么**”（What）和“**为什么做**”（Why），而将繁琐的“**怎么做**”（How）交给了 AI。

> **这种方式为什么流行**

1.  **效率极高**：你省去了大量纠结底层逻辑、调 bug 的时间，把精力全放在“到底要什么”上；想法细节全让 AI 帮你补全和落地。

1.  **零门槛入门**：不用是编程高手，小白都能玩得转。思路全靠主观感受+即时调整，老少咸宜，非常适合快速试错、产品原型验证、可视化 demo。

1.  **沉浸式开发**：你不被代码绊住，全身心沉浸在“创作”和“表达”本身。心路小宇宙全开，遇到“哪里不对劲”还可以迅速修正，流程顺滑地飞起。

## 1.2 Vibe Coding 的核心：人与 AI 的“对话式编程”

Vibe Coding 的本质是一场高质量的“人机对话”。你扮演“产品经理”的角色，提出需求；AI 扮演“程序员”的角色，实现需求。这场对话的质量，直接决定了最终产出的代码质量。

### **核心区别：Vibe Coding v**s 传统编程 vs 普通 AI 代码补全

| **对比维度** | **传统编程** | **普通 AI 代码补全** | **Vibe Coding** |
| --- | --- | --- | --- |
| 核心主体 | 开发者手写全部核心代码 | 开发者为主，AI 做单行/片段补全 | AI 为主，开发者做全局管控与意图传递 |
| 入门门槛 | 需先掌握语法、数据结构、框架等全套基础知识 | 需具备成熟的开发能力，仅提升编码效率 | 0 基础可快速落地项目，边实践边补基础 |
| 工作流程 | 需求→手写代码→调试→迭代 | 需求→手写核心代码→AI 补全片段→调试 | 需求→意图拆解→AI 全流程生成→校验→对话式迭代 |
| 效率提升 | 基准线 | 提升 30%-50%编码效率 | 全流程效率提升 300%-1000%，尤其适配中小项目快速落地 |

# 第三章 Vibe Coding 核心基本功

这一部分是 Vibe Coding 的核心，新手必须把这 4 项基本功练扎实，再去做复杂项目，否则会频繁踩坑。

### 3.1 核心能力 1：Vibe Coding 专属 Prompt 工程

Prompt 是你和 AI 沟通的桥梁，也是 Vibe Coding 的核心基本功。新手最常见的错误，就是用一句模糊的话让 AI 写代码，最终结果完全不符合预期。

### 新手万能 Prompt 公式（直接复制套用）

```
【角色定位】：你是一名资深的XX开发工程师，拥有XX年的XX领域开发经验，代码规范、注释完整、兼容性强
【需求背景】：我需要做一个XX项目/功能，用于XX场景，解决XX问题
【核心目标】：1. XXX 2. XXX 3. XXX（分点列出，不超过5条核心目标）
【输出规范】：1. 代码使用XX语言/框架，版本为XX 2. 代码必须添加完整的中文注释 3. 按模块拆分代码，标注每个文件的名称和作用 4. 提供完整的运行步骤和依赖安装说明
【约束条件】：1. 不得使用XX不兼容的依赖包 2. 必须适配XX环境 3. 代码必须可直接运行，无缺失内容 4. 不得出现安全漏洞
【验收标准】：实现XX功能，满足XX要求，可通过XX方式验证
```

### 新手 Prompt 正反案例对比

| 错误 Prompt（新手高频踩坑） | **正确 Prompt（套用公式）** |
| --- | --- |
| 帮我写一个 Python 爬虫 | 【角色定位】：你是一名资深的 Python 爬虫开发工程师，拥有 5 年数据爬取开发经验，代码合规、反爬处理完善、注释完整 |

### 新手 Prompt 核心技巧

1.  **具体永远比模糊好**：不要说「好看的页面」，要说「适配移动端的简约风格，主色调为蓝色，页面宽度 1200px，分为头部导航、轮播图、内容列表、底部 footer 四个模块」；

1.  **给 AI 明确的边界**：必须告诉 AI「不能做什么」，比如不能用冷门依赖、不能写死配置、不能有 SQL 注入漏洞，避免 AI 产出不可用的内容；

1.  **分场景优化 Prompt**：写脚本、做前端、开发后端、做架构设计，需要不同的 Prompt 模板，附录中会提供全场景模板，新手可直接复用。

## 3.2 核心能力 2：任务拆解能力

任务拆解，就是把一个复杂的大需求，拆分成一个个「可独立实现、可独立验证、可独立迭代」的小模块，这是 Vibe Coding 处理复杂项目的核心能力。

### 新手任务拆解万能步骤

以「做一个个人博客网站」为例，拆解步骤如下：

1.  **顶层需求拆解**：先把大需求拆成核心阶段，比如：需求梳理与架构设计 → 前端页面开发 → 后端接口开发 → 数据库设计 → 前后端联调 → 测试 → 部署上线；

1.  **阶段内模块拆解**：把每个阶段拆成独立模块，比如前端页面开发，拆分为：首页设计与开发 → 文章详情页开发 → 分类页面开发 → 关于我页面开发 → 响应式适配；

1.  **模块内步骤拆解**：把每个模块拆成可直接给 AI 提需求的小步骤，比如首页开发，拆分为：头部导航栏开发 → 轮播图组件开发 → 文章列表组件开发 → 分页功能开发 → 侧边栏分类组件开发；

1.  **逐个实现，逐个验证**：完成一个小步骤，就验证一次功能是否正常，没问题再进入下一个步骤，避免一次性写完所有代码，出现问题无法定位。

### 新手拆解核心原则

+   每个最小单元的需求，必须能一句话说清楚核心目标；

+   每个单元实现后，必须有明确的验证方式，比如「运行代码，能成功把数据写入 Excel」；

+   拆解顺序必须符合开发逻辑，先做底层，再做上层，先做核心功能，再做优化迭代。

## 3.3 核心能力 3：代码理解与校验能力

新手最致命的坑：AI 写了代码，自己完全看不懂，出了问题完全不知道怎么解决。Vibe Coding 不是让你完全不用懂代码，而是让你不用从零手写代码，你必须能看懂代码、能校验对错、能定位问题。

### 新手代码理解与校验 4 步法

1.  **先让 AI 解释代码**：拿到 AI 生成的代码，先不要运行，直接问 AI「请逐行解释这段代码的作用，标注核心逻辑、依赖包、函数的作用，以及可能出现的风险点」，先建立对代码的整体认知；

1.  **校验核心逻辑是否符合需求**：对照你的需求，看 AI 的代码是否实现了核心目标，有没有遗漏需求，有没有不符合约束条件的内容；

1.  **分步运行验证**：不要一次性运行整段代码，先运行核心逻辑，验证功能是否正常，再逐步添加其他功能，出现问题可以快速定位；

1.  **异常场景测试**：比如代码是做数据统计的，就测试空数据、异常格式数据，看代码会不会报错，有没有做异常处理，保障代码的稳定性。

### 新手快速看懂代码的技巧

+   不用纠结每一个语法细节，先搞懂代码的整体流程、输入输出、核心函数的作用；

+   遇到不懂的语法，直接问 AI「这个语法是什么意思，有什么作用，给我举一个简单的例子」，边做边学，效率远高于先啃语法书；

+   让 AI 给代码画一个流程图，直观理解代码的执行逻辑，快速掌握核心原理。

## 3.4 核心能力 4：对话式迭代开发能力

Vibe Coding 的核心是「对话」，而不是一次性 Prompt。99%的情况下，AI 第一次生成的代码，都不会 100%符合你的预期，需要通过持续的对话迭代，不断优化完善。

### 新手对话式迭代万能流程

1.  **初稿生成**：用标准 Prompt，让 AI 生成第一版代码，实现核心功能；

1.  **问题反馈**：运行代码后，把报错信息、不符合预期的地方，完整地反馈给 AI，不要只说「代码报错了」，要说「运行代码后，出现了 XX 报错，报错信息是 XXX，我的运行环境是 XX，我已经做了 XX 操作，麻烦帮我定位并修复问题」；

1.  **精准提修改需求**：不要说「把页面改好看一点」，要说「把首页的文章列表卡片，改成圆角 8px，添加 hover 阴影效果，标题字体大小改为 18px，行高 1.5，卡片之间的间距改为 20px」；

1.  **持续优化迭代**：功能实现后，再提优化需求，比如性能优化、兼容性优化、代码规范优化、用户体验优化，逐步完善项目；

1.  **固化迭代结果**：每完成一次迭代，让 AI 更新完整的代码，标注修改的地方，避免版本混乱。

### 新手迭代对话高频避坑点

+   反馈问题必须完整：报错信息、运行环境、你做过的操作，必须全部给 AI，否则 AI 无法精准定位问题；

+   一次只提一个核心修改需求：不要一次给 AI10 个修改点，容易导致 AI 顾此失彼，改了 A 坏了 B；

+   上下文管理：迭代过程中，不要频繁切换对话窗口，同一个项目放在同一个对话里，让 AI 保留完整的上下文，避免重复沟通。

## 3.5 Vibe Coding 专业名词解释篇

和 AI 对话时，它偶尔会蹦出一些专业名词。这里用大白话给你解释一下，让你能和它无障碍沟通。

+   编程语言 （Programming Language）

+   **大白话**：指挥电脑干活的“官方语言”，比如 Python， Java， C++。它有严格的语法规则，就像法律条文一样。

+   **Vibe Coding 关系**：你用中文下命令，AI 负责把你的命令翻译成这些“官方语言”。

+   **脚本 （Script）**

+   **大白话**：一个写满了一系列指令的小文件，让电脑按顺序执行，通常用来完成一个特定的自动化任务。我们用 Vibe Coding 生成的大部分都是这种脚本。

+   **例子**：一个自动重命名文件的 .py 文件就是一个 Python 脚本。

+   库 / 包 （Library / Package）

+   **大白话**：别人已经写好的“工具箱”，里面装满了解决特定问题的工具（代码）。你不需要自己造轮子，直接拿来用就行。

+   **例子**：处理 Excel 就用 pandas 库，处理图片就用 Pillow 库。

+   **API (Application Pr**ogramming Interface)

+   **大白话**：一个程序或服务（比如天气网站、地图服务）开放出来的“点餐菜单”。你按照菜单上的格式去“点餐”（发送请求），它就会给你上对应的“菜”（返回数据）。

+   **例子**：你想写个程序获取今天的天气，就需要调用天气网站的 API。

+   终端 / 命令行 （Terminal / Command Line）

+   **大白话**：一个用纯文字和电脑交互的“黑窗口”。你可以通过打字来下达命令，比如运行一个脚本 （python your_script.py）。

+   **Vibe Coding 关系**：这是你运行 AI 生成代码的主要阵地。

+   **变量 （Variable）**

+   **大白话**：一个用来存放数据的“贴了标签的盒子”。你可以随时往里面放东西，或者看里面是什么。

+   **例子**：age = 18 就是创建了一个叫 age 的盒子，里面放了数字 18。

+   **函数 （Function）**

+   **大白话**：一段封装好的、可以重复使用的“代码积木”，用来完成一个特定的操作。你可以给它取个名字，需要的时候喊它的名字就行。

+   **例子**：可以写一个叫 send_email 的函数，每次需要发邮件时，直接调用它，而不用重复写发送邮件的逻辑。

+   Bug / 调试 （Bug / Debugging）

+   **大白话**：Bug 就是代码里的错误，像小虫子一样。调试（Debugging）就是找到并修复这些错误的过程。

+   **Vibe Coding 关系****：Vibe Coding **中最重要的调试技巧就是：复制错误信息，丢回给 AI。

# 第四章：Vibe Coding 实现流程篇

掌握 Vibe Coding 的过程，就像学习一套魔法咒语，它不需要你天赋异禀，只需要你遵循固定的施法步骤。下面，我将用一个超接地气的案例，带你走完完整的“施法”流程。

> **【案例背景】**

> 小明是一名大学老师，他收到了学生们交上来的期末作业，文件名五花八门，比如：“张三-数据结构作业。 docx”、“李四的作业。docx”、“数据结构-王五。zip”、“赵六数据结构。docx”.

> **他想写一个程序，把所有文件名**统一修改为“课程名-姓名-学号。docx”的格式（假设学号需要从一个名单 Excel 里查找）。

我们来看看，如何用 Vibe Coding 五步解决这个问题。

## **第一步：定义需求与目标**

这是最关键的一步，也是完全不需要技术的一步。在和 AI 对话前，先和自己对话，用笔和纸或者备忘录，回答以下三个问题：

1.  **我的最终目标是什么？**

+   清晰回答： 我想把一个文件夹里所有学生的作业文件名，都改成“数据结构-姓名-学号。后缀名”的统一格式。

1.  **我手头上有什么？（输入）**

+   清晰回答：

+   一个存放着所有作业文件的文件夹，路径是 D:\期末作业。

+   一个 Excel 文件，名叫 学生名单.xlsx，里面有两列：“姓名”和“学号”。

1.  **我期望得到什么？（输出）**

+   清晰回答： D:\期末作业 文件夹里的文件名被修改。例如，“张三-数据结构作业。docx” 变成 “数据结构-张三 -2023001.docx”。

当你能清晰地回答这三个问题时，你的“Vibe”就已经非常明确了。这就好比你告诉设计师：“我有一个 100 平的毛坯房（输入），想要一个两室一厅的现代简约风（输出），最终目标是温馨舒适（目标）。”

## **第二步：挑选合适的 AI 工具**

施展魔法需要魔杖，Vibe Coding 也需要强大的 AI 工具。目前市面上有很多选择，对于新手，我推荐从以下几个开始：

+   ChatGPT （GPT-4o/4）：综合能力最强，代码生成质量高，理解复杂需求的能力首屈一指。

+   **Kimi Chat**：国内出品，对中文语境的理解非常好，尤其擅长处理长文本（比如你把一大段资料丢给它分析）。

+   **Claude Code**：代码能力同样出色，有时在解释代码逻辑方面比 ChatGPT 更细致。

+   **文心一言/通义千问**：国内大厂出品，也在快速迭代，可以作为备选。

对于我们这个案例，任何一个主流 AI 模型都能胜任。我们以大家最熟悉的 ChatGPT 为例。

## 第三步：编写高质量的 Prompt

Prompt 就是你向 AI 下达的指令，也就是你的“咒语”。咒语念得好不好，直接决定了魔法的效果。一个好的 Vibe Coding Prompt，通常包含以下几个要素，我称之为 “R-T-G-S-I-O-C”模型：

+   **R （Role - 角色扮演）**：让 AI 扮演一个专家。

+   **T （Task - 任务背景）**：告诉 AI 它需要做什么，以及为什么要做。

+   **G （Goal - 明确目标）**：清晰地描述最终要达成的、可衡量的结果。

+   S （Steps - 具体步骤/规则）：如果任务复杂，可以拆解成一步步的指令。

+   I （Input - 输入说明）：明确告知 AI 你的原始数据是什么样的。

+   O （Output - 输出格式）：明确告知 AI 你希望得到的结果是什么样的。

+   C （Constraints - 约束条件）：告知 AI 有哪些限制或需要特别注意的地方。

现在，我们用这个模型来为小明的需求编写“咒语”：

---

（这是一个可以直接复制使用的 Prompt 模板）

```
**[R - 角色扮演]****
你是一位精通 Py****thon 的文件处理****专家。
[T - 任****务背景]
我是一名大学老师****，需要整理学生的期末****作业。学生提交的文件**名格式不统一，我需要你帮我写一个 Python 脚本来批量重命名这些文件。
[G - 明确目标]
最终目标是：将指定文件夹内的所有作业文件名，都修改为“课程名-姓名-学号.原后缀名”的格式。
[I - 输入说明]
作业文件都存放在一个文件夹里，路径为 D:\期末作业。
原始文件名中包含了学生的姓名，但位置不固定，可能是“张三-数据结构作业.docx”或“数据结构-王五.zip”等。
我有一个名为 学生名单.xlsx 的 Excel 文件，它和脚本放在同一个目录下。这个 Excel 文件有两列，第一列是“姓名”，第二列是“学号”。
[S - 具体步骤/规则]
脚本需要读取 学生名单.xlsx 文件，将姓名和学号的对应关系存起来。
脚本需要遍历 D:\期末作业 文件夹里的每一个文件。
对于每一个文件，从它的文件名中提取出学生姓名。
根据提取到的姓名，去查找对应的学号。
生成新的文件名，格式为：“数据结构-姓名-学号.原后缀名”。例如，如果文件是“李四的作业.docx”，姓名是“李四”，查到学号是“2023002”，那么新文件名就是“数据结构-李四-2023002.docx”。
执行重命名操作。
[O - 输出格式]
我不需要你输出别的东西，只需要提供一段完整的、可以直接运行的 Python 代码。请在代码中添加详细的注释，解释每一部分的作用，方便我这样的新手理解。
[C - 约束条件]
如果文件名中找不到学生名单里的姓名，请不要修改该文件，并在控制台打印一条提示信息，告诉我哪个文件无法处理。
请使用 Python 的标准库或常用的第三方库（如 pandas 读取 Excel），并告诉我需要安装哪些库。
```

把这段精心构造的“咒语”发送给 AI，它就会开始为你“发送”代码了。

## **第四步：运行与修正代码**

AI 会很快返回一段 Python 代码。别怕，你不需要逐行看懂。你需要做的是：

1.  **准备环境**：

+   AI 会告诉你需要安装 Python，并可能需要安装一个叫 pandas 的库。

+   **安装 Python**：访问 Python 官网 （python.org） 下载并安装，安装时记得勾选 "Add Python to PATH"。

+   **安装 pandas**：打开电脑的“命令提示符”或“终端”，输入 pip install pandas 然后回车。

+   **准备文件**：在电脑上创建一个文件夹，比如 C:\MyScript，把 AI 生成的代码保存为 rename_files.py，再把 学生名单.xlsx 文件也放进去。

1.  **运行代码**：

+   在 C:\MyScript 文件夹的地址栏输入 cmd 并回车，打开终端。

+   输入 python rename_files.py 然后回车。

1.  **观察结果与处理错误**：

+   **完美情况**：程序运行，D:\期末作业 文件夹里的文件都被成功重命名。

## 第六章 新手必看的常见坑与解决方案

## 6.1 认知坑（90%的新手都会踩）

1.  **错误认知**：Vibe Coding 会让程序员失业，学了 Vibe Coding 就不用学编程基础了

**纠正**：Vibe Coding 不是淘汰程序员，而是让会用 AI 的程序员淘汰不会用 AI 的程序员。新手可以用 Vibe Coding 快速入门，但想要走得远，必须边实践边补编程基础，比如语法、数据结构、计算机网络、安全等知识，否则永远只能做简单的小项目，无法驾驭复杂项目。

1.  **错误认知**：Prompt 写得越长越好，越详细越好

**纠正**：Prompt 的核心是精准，而不是冗长。无关的信息会干扰 AI 的判断，新手只需要按照万能公式，把核心信息说清楚即可，避免冗余信息。

1.  **错误认知**：AI 生成的代码都是对的，可以直接上线使用

**纠正**：大模型会出现幻觉，生成的代码可能有 bug、安全漏洞、逻辑错误，甚至会生成不存在的依赖包和 API。任何 AI 生成的代码，必须经过校验、测试，才能上线使用，尤其是商用项目。

### 6.2 操作坑（新手高频踩坑）

| **常见坑** | **解决方案** |
| --- | --- |
| 一次性给 AI 太复杂的需求，生成的代码完全不可用 | 严格执行任务拆解，把大需求拆成最小单元，逐个实现，逐个验证 |
| Prompt 模糊，需求不明确，AI 生成的内容不符合预期 | 套用万能 Prompt 公式，明确角色、需求、目标、规范、约束、验收标准，具体永远比模糊好 |
| 长对话上下文混乱，AI 遗忘之前的需求，乱改代码 | 定期让 AI 总结项目进度和核心信息，复杂项目分模块分对话开发，做好版本管理 |
| 出了报错只说「代码报错了」，不提供完整信息，AI 无法修复 | 反馈报错时，必须提供完整报错信息、运行环境、复现步骤、已做的排查操作 |
| 不做版本管理，AI 修改后代码出问题，无法回溯 | 用 Git 做版本管理，每完成一个模块就提交一次版本，做好更新记录 |

## 6.3 安全与法律坑（必须重视，避免踩红线）

1.  **代码泄露风险**：不要把公司的核心代码、商业机密、敏感信息（比如数据库账号、密钥、用户数据）上传到公有 AI 工具，否则会造成严重的数据泄露。企业用户建议使用私有化部署的 AI 编程工具，个人用户不要在代码里写死敏感信息。

1.  **开源协议合规**：AI 生成的代码可能会引用开源代码，商用时必须注意开源协议，比如 GPL 协议的代码，商用时需要开源自己的代码，避免侵权。

1.  **版权问题**：目前全球范围内，AI 生成代码的版权归属还没有完全统一的法律规定，商用项目建议对 AI 生成的代码进行人工审核和修改，形成自己的原创内容，避免版权纠纷。

1.  **合规开发**：不得用 Vibe Coding 开发黑客工具、爬虫工具爬取非公开数据、赌博/色情等违规软件，否则会触犯法律，承担相应的刑事责任。
