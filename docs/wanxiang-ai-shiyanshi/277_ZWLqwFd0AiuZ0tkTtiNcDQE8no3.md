# **一、n8n 简介**

## **1、企业简介**

n8n 是一个开源的自动化工作流平台，专为技术团队设计，提供代码灵活性和无代码速度的结合。其母公司 n8n 是一家下一代工作流程自动化工具提供商，提供了一个免费的基于节点的开放式工作流自动化工具，该工具可以自行托管，扩展并与第三方 Web 应用程序或自定义内部工具一起使用以自动化重复性任务。n8n 为 200 多种不同的应用程序提供了 API 连接器，用户可以通过可访问的源代码添加自己的或扩展现有的连接器，除了使业务流程自动化之外，该产品还可用作低代码产品或服务的后端。

n8n 的发展速度堪称“火箭式上升”。2025 年 8 月 8 号，德国柏林，n8n 公司刚刚完成新一轮融资，估值直接从四个月前的 3.5 亿美元涨到 23 亿美元，相当于增长了将近 6 倍。今年 3 月，n8n 刚完成了一轮 5500 万欧元的融资，彼时公司估值才 3 亿欧元。不到半年，新的资金又涌入市场，带头的是 Accel，Meritech Capital 也有望参与，预计总共能募集到数亿欧元。这个速度让不少业内人士直呼意外，很大一部分原因，是 n8n 的业务增长快得惊人。去年一年，这家由 Jan Oberhauser 在 2019 年创立的 AI 自动化平台，年经常性收入涨了 5 倍，ARR 目前已经突破 4000 万美元。沃达丰、Delivery Hero 等大客户的加入，也进一步带动了 n8n 的活跃度。

## **2、团队信息**

n8n 由 Jan Oberhauser 于 2019 年 在德国柏林创立。Jan 的背景比较特别，他曾在影视视觉效果行业工作过。这段经历让他发现，很多自动化工具依赖性强，业务人员遇到工作流问题时往往需要等待工程师开发定制解决方案，无法自主解决问题。正是这个痛点促使他萌生了创建一款更灵活、透明的自动化工具的想法，并最终诞生了 n8n。

n8n 的团队成长速度比较快：在 2020 年初完成首轮融资后，迎来了首批四位团队成员。截至 2025 年初的信息显示，n8n 的团队已经扩展到拥有 80 多位成员。n8n 团队推崇 “公平代码”（Fair-Code）模式。这意味着源代码可以免费使用、修改和分发。此外，团队非常重视社区建设。他们鼓励用户分享工作流程、贡献代码，并在此基础上进行开发，这使得社区能自然壮大。

这些团队负责系统的稳定、自动化和高效运行，n8n 是理想的运维自动化工具。

+   典型场景：

+   自动化运维任务： 自动重启服务、清理日志文件、扩容云服务器、创建和管理监控仪表盘等。

+   事件响应与告警： 接收来自监控系统（如 Prometheus， Datadog）的告警，并自动触发一系列操作，如创建工单、发送通知到 Slack/Teams、呼叫值班人员等。

+   成本优化： 在非工作时间自动关闭开发环境的云资源以节省成本。

+   典型场景：

## 1、选择合适的部署方式

官方推荐使用 Docker 部署自托管版，根据实际测试，n8n 的 Docker 镜像在环境适应性上极高。几乎可以在包括群晖 DSM 或极空间在内的任何可运行 Docker 的地方一键部署。

但在不同环境下部署，可能适合不同的应用场景：

#### 本机 PC 部署（没有公网 IP）

**适应场景：**

1，无需引入外部服务的本地批处理；2，快速体验、学习上手；

**局限：**

n8n 无法对公网上的第三方服务进行回调，也不能提供 Webook 给第三方服务唤起。

#### NAS 部署

**适应场景：**

你有 NAS，不想花服务器的钱，又想体验 n8n 的全功能；

**局限：**

难以让 n8n 与真网服务进行通信（如 Google）

> 如果你 n8n 的运行环境不能访问 Google 或 OpenAI，建议使用 CloseAI 或 WildCard 代理。支持免科学访问 OpenAI 和 Anthropic 的所有模型，支付宝付款，按量付费。

#### 服务器部署

**适应场景：**

你最应该用在日常使用过程中的部署模式；

可以使用 n8n 的所有功能；

7*24 小时稳定在线；

如果服务器在“外面”，可以直连 GPT / Gemini 等 API 而无需额外配置。

**局限：**

1，你需要独立运维一个服务器（建议使用 1Panel）

2，你需要付出一个服务器的钱（推荐使用 CloudCone，在性能方面如果你不是让 Workflow 一直跑，一般 2v2GB RAM 的服务器就够用了，一年的成本只有 30 刀左右）

## 2、节点（Node）

![](img/15eaf44c32fef5e8ed6c009475fe051c.png)

n8n 的核心是**节点（Nodes）**，它们是构建自动化工作流的基本模块。简单来说，每个节点都代表一个特定的操作或服务。通过将不同的节点连接起来，用户可以创建复杂的数据流和自动化任务。

**n8n 节点的主要功能：**

1.  **数据提取（Extract）：**

+   节点可以从各种来源（如 Webhooks、API、数据库、文件等）获取数据，作为工作流的起点。

1.  数据处理和转换（Transform）：

+   节点可以对数据进行处理、转换、过滤或操作。

1.  **数据加载和发送（Load）：**

+   节点可以将处理后的数据发送到不同的目标服务或平台。

> 以下是一些重要且常用的节点分类及具体节点：

### 核心基础节点

+   Start：工作流的起点，可设置触发方式（如手动触发、定时触发等）。

+   Function：允许编写自定义 JavaScript 代码处理数据，实现复杂逻辑运算。

+   IF：条件判断节点，根据设定的条件将数据分流到不同分支。

+   Merge：合并多个分支的数据流，支持按顺序或关键字合并。

+   Set：设置或修改数据字段的值，用于格式化数据结构。

### 数据处理节点

+   Split In Batches：将大量数据分批处理，避免因数据量过大导致流程阻塞。

+   Filter：根据条件过滤数据，只保留符合要求的条目。

+   Sort：对数据按指定字段进行排序（升序 / 降序）。

+   Aggregate：对数据进行聚合计算（如求和、平均值、计数等）。

+   CSV：处理 CSV 格式数据，支持解析 CSV 内容或生成 CSV 文件。

### 集成与通信节点

+   HTTP Request：发送 HTTP/HTTPS 请求（GET/POST 等），与外部 API 交互。

+   Email（如 Gmail、Outlook）：发送、接收或处理邮件，支持附件操作。

+   Slack/Discord：与团队沟通工具集成，自动发送消息或获取频道内容。

+   Database（如 MySQL、PostgreSQL、MongoDB）：连接数据库，执行查询、插入、更新等操作。

+   File（如 Local File、Google Drive、Dropbox）：处理本地或云端文件（上传、下载、删除等）。

### 自动化触发节点

+   Cron：按定时规则触发工作流（如每天凌晨 3 点执行）。

+   Webhook：通过接收 HTTP 请求触发工作流，常用于实时响应外部事件。

+   Watch Folder：监控指定文件夹，当有文件新增 / 修改时触发流程。

+   GitHub：监听 GitHub 事件（如代码提交、Issue 创建）触发自动化操作。

### 第三方服务节点

+   CRM 类（如 Salesforce、HubSpot）：同步客户数据、创建销售线索等。

+   电商类（如 Shopify、WooCommerce）：处理订单、库存更新等操作。

+   支付类（如 Stripe、PayPal）：处理支付通知、退款等流程。

## 3、工作流（Workflow）

由多个节点连接成的自动化流程。n8n 工作流（Workflow）是 n8n 的核心功能，它是一个可视化的、由一系列节点（Nodes）串联而成的自动化流程。工作流旨在将不同的服务、应用程序和数据源连接起来，实现数据的自动化流转和任务的自动执行。节点是工作流的基本构建块，负责数据的输入、处理、转换和输出。

节点可以分为两大类：

+   触发器节点（Trigger Nodes）： 它们是工作流的起点。例如，当接收到 Webhook 请求、接收到新邮件或达到预定时间时，工作流就会被触发并开始运行。一个工作流通常只能有一个触发器节点。

+   常规节点（Regular Nodes）： 它们在工作流运行中执行具体任务，如从 API 获取数据、更新数据库记录、发送通知、处理图像等。

## 4、触发器（Trigger）

![](img/d1312ecedbc04fd218ff1ba0b52c4d96.png)

在 n8n 工作流中，**触发器节点**是整个流程的起点。它的主要作用是监听特定事件，一旦事件发生，它就会启动并运行整个工作流。一个工作流可以有多个常规节点，但通常只能有一个触发器节点。

n8n 提供了多种类型的触发器，以适应不同的自动化需求：

1.  基于事件的触发器（Event-based Triggers）：

+   **Webhook：** 这是最常用的一种触发器。它会生成一个唯一的 URL，当外部服务（如 Stripe、GitHub、Trello 等）向这个 URL 发送 HTTP 请求时，工作流就会被触发。这非常适合实现实时的数据同步或响应外部事件。

+   Gmail、Slack、Trello 等应用触发器： 这些触发器专门用于监听特定应用程序中的事件。例如，当 Gmail 收到一封新邮件时，或 Trello 上新增一个卡片时，工作流就会被触发。

+   RSS Feed Reader： 当指定的 RSS 订阅源有新文章发布时，工作流会被触发。

1.  基于时间的触发器（Time-based Triggers）：

+   **Cron：** 这个触发器允许你使用标准的 Cron 表达式来定义工作流的执行时间。你可以设置工作流每分钟、每小时、每天、每周或在特定的日期和时间运行。这非常适合执行定期任务，如每日报告生成、数据备份等。

+   **Interval：** 这个触发器可以设定一个固定的时间间隔来运行工作流，例如每 5 分钟、每 30 分钟或每小时。

最后，企业面临日益复杂的业务流程和人力成本上升压力，促使企业寻求自动化解决方案，AI 工作流平台能够将传统需要 90 天的对账流程压缩到 3 天，从根本上重构了业务运营模式。

## 2 技术架构与演进

### 2.1 核心技术栈

AI 工作流平台的技术架构已经演变为多层次、多模块的复杂体系。其核心主要包括以下组件：

+   **感知层**：负责数据采集和信号转换，包括屏幕抓取、图像识别、OCR 与计算机视觉技术，确保机器人"看得见"物理和数字世界的信息。2025 年的先进平台已支持多模态数据输入，能够同时处理文本、图像、音频和视频数据，为后续分析提供丰富素材。

+   **决策层**：这是 AI 工作流的"大脑"，由规则引擎、工作流引擎和机器学习模型构成，决定下一步做什么。现代决策层融合了大语言模型（LLM）的推理能力、检索增强生成（RAG）的知识管理能力和强化学习（RL） 的优化能力，能够处理非结构化决策过程。以某头部券商的 AI 研究员系统为例，该系统每小时可产出 20 页覆盖 A 股 4000+标的的分析报告，自动识别财报异常，效率远超人工分析师。

+   **执行层**：通过 UI Automation、API Hook、消息队列等技术负责最终执行动作，完成"去点、去填、去提交"等操作。2025 年的执行层最大进步是实现了 API 与 UI 自动化的无缝融合，既能通过 API 获取结构化数据，也能在缺乏 API 接口的遗留系统中通过 UI 自动化进行操作，大大扩展了自动化范围。

### 2.2 架构演进路径

AI 工作流技术架构经历了三个明显的发展阶段：

1.  **第一代**以"录制-重放"为核心，把人在 GUI 上的操作录成脚本，再由机器人简单重复，缺乏灵活性和适应性。

1.  **第二代**加入了"流程编排"能力，让机器人可以在多个应用之间跳转，比如从 SAP 拉数据、去网页校验、再写回 Oracle，实现了跨系统协同。

1.  **第三代**嵌入 AI 能力：OCR 读发票、NLP 读邮件、机器学习判断异常。2025 年，90%的 RPA 厂商已整合大模型技术，生成式 AI 与工作流自动化的融合成为行业主旋律。

### 2.3 关键能力突破

2025 年，AI 工作流技术在几个关键领域取得了显著突破：

+   **长上下文理解**：突破了 100 万字壁垒。GPT-4o 支持 128K 上下文窗口，Claude 3.5 实现 200K tokens 处理能力，国内模型如 DeepSeek-R1 通过稀疏化注意力机制，在 671B 参数规模下实现 500K tokens（约 75 万字）的长文本理解，可直接处理整本书籍或代码库的解析任务。某法律 Agent 能够一次性分析 500 页合同文档，自动识别风险条款并生成修改建议，准确率达 92%。

+   **多模态融合**：成为 AI Agent 的核心竞争力。例如，"超模态文创生成引擎"赛题中的优秀项目能够实现文本→图像→3D 模型→视频的全链条生成：通过 CLIP 模型实现文本-图像对齐，Stable Diffusion 生成初始图像，NeRF 技术将 2D 图像转换为 3D 模型，最后通过 Sora 生成动态视频片段。某参赛项目仅用 30 分钟就完成了"赛博朋克风格的未来城市"从概念描述到 4K 视频的全流程创作。

+   **自主进化机制**：使 AI Agent 具备持续学习能力。通过"人类反馈强化学习（RLHF）+环境交互学习"的双循环机制，Agent 能够从用户反馈和实际任务执行中不断优化策略。微软的 AutoGen 框架支持多 Agent 协作进化，某物流调度 Agent 在 3 个月实际运营中，通过与仓储 Agent、运输 Agent 的交互学习，使配送路径优化率从初始的 65%提升至 89%。

## 3 主流平台与生态对比

### 3.1 平台定位与战略方向

2025 年的 AI 工作流平台市场形成了四类主要玩家，每类都有其独特的价值主张和目标用户：

+   **开源社区驱动型（n8n）**：以 n8n 为代表，完全开源的工作流自动化平台，拥有活跃的全球开发者社区。其 GitHub 仓库拥有 45K+星标，每月有数百个贡献者参与开发。这种开源模式确保了平台的持续创新和技术领先性，特别适合技术实力雄厚且需要高度定制化的企业团队。

+   企业级 AI 优先型（Dify）：Dify 致力于成为企业级 AI 应用开发的完整技术栈，其设计理念是将复杂的 AI 技术简化为易用的开发工具。它提供 LLMOps 完整生命周期管理，从模型选择、应用开发、部署监控到性能优化的全流程支持。这类平台特别适合需要构建知识密集型 AI 应用的组织，如智能客服、文档分析、决策支持系统等。

+   商业化成熟型（Make.com）：Make.com（原 Integromat）作为商业化产品，经过多年的市场验证和持续优化，在产品稳定性、用户体验、客户服务等方面都达到了企业级标准。其商业模式确保了持续的研发投入和技术支持，适合追求稳定性和可靠性的企业用户。

+   **大厂生态赋能型（Coze）**：Coze 作为字节跳动旗下的 AI 应用开发平台，背靠强大的技术实力和生态资源。它不仅拥有先进的 AI 技术支持，还能够无缝集成字节系的各种产品和服务，为用户提供完整的 AI 应用解决方案。这类平台适合需要快速部署且希望利用生态资源用户。

### 3.2 技术构深度解析

各平台的技术架构选择直接影响其性能、扩展性和适用场景：

+   **n8n **基于 Node.js 构建，采用事件驱动的架构模式，天然支持异步处理和高并发场景。其核心采用工作流引擎设计，每个节点都是独立的处理单元，支持热插拔和动态扩展。这种设计使得 n8n 能够轻松处理复杂的业务逻辑和大规模的数据处理任务。

+   **Make.com **采用云原生架构，基于微服务和容器化技术构建，能够自动进行负载均衡和弹性扩展。其全球 CDN 网络确保了世界各地用户都能获得优秀的访问速度和稳定性。这种架构适合全球化企业和需要高性能保证的应用场景。

> **新人学习 8 条建议**

1.  🌱 先从“云”开始，再考虑“自托管”

+   怎么做：不要一开始就纠结于如何在服[务器或 Docke](https://www.n8n.cloud/)r 上部署。直接访问 n8n.cloud 注册一个免费试用账户。云版本让你在几分钟内就能开始构建第一个工作流，完全免去了初期繁琐的环境配置困扰。

+   为什么：这能让你将全部注意力集中在理解 n8n 的核心概念和工作原理上，快速获得正反馈，建立学习信心。

1.  🎯 理解最核心的三个概念：节点、连接、工作流

+   节点 （Node）：这是 n8n 的基石。每个节点代表一个操作（如从 Google Sheets 读取数据）或一个触发器（如收到一封新邮件）。把它想象成一个乐高积木。

+   连接 （Connection）：节点之间的箭头定义了数据流动的方向和顺序。一个节点的输出会成为下一个节点的输入。

+   工作流 （Workflow）：由节点和连接组成的完整自动化流程。

+   为什么：透彻理解这三点，你就掌握了 n8n 80% 的设计哲学。

1.  🚀 从“模仿”开始，动手复现简单案例

+   [怎么做](https://n8n.io/workflows)：不要空想。去 n8n 官网的 模板库，找一个看起来有趣的简单模板（例如“定时发送天气邮件到邮箱”或“同步 Trello 卡片到表格”），然后亲手照着做一遍。

+   为什么：这是最快的学习方式。你会直观地看到数据如何从一个节点传递到另一个节点，如何配置凭证，以及如何测试和调试。

1.  🛟 善用“HTTP Request”和“Function”节点

+   HTTP Request 节点：这是 n8n 的“瑞士军刀”。当官方没有提供某个应用的专用节点时，你几乎总是可以通过调用该应用的 API 来实现连接。这是你解锁无限可能的关键。

+   Function 节点：当内置节点无法满足你的数据处理需求时，你可以用 JavaScript 或 Python 代码在这里编写自定义逻辑，比如数据转换、计算或过滤。

+   为什么：掌握了这两个节点，就意味着你不再受限于官方集成的应用，能够解决 99% 的复杂场景问题。

1.  🔐 第**一时间学好“凭证”管理**

+   怎么做：在创建第一个需要登录第三方服务（如 Gmail、Notion、Slack）的节点时，仔细了解 n8n 的凭证管理方式。它是如何安全地存储你的 API Key、OAuth 令牌等敏感信息的。

+   为什么：安全和权限是自动化的基础。一个好的习惯从一开始就要养成。

1.  💡 拥**抱社区和文档**

+   [社区论坛](https://community.n8n.io/)：n8n 拥有一个非常活跃和友好的 社区论坛。这是你遇到问题时寻求帮助的第一选择。提问前先搜索，很大可能别人已经遇到并解决了同样的问题。

+   官方文档：n8n 的 [官方文档](https://docs.n8n.io/) 写得非常详尽，是查询节点用法、配置说明和最佳实践的权威来源。

+   为什么：你不是一个人在战斗。善于利用现有资源是工程师最重要的能力之一。

1.  📖 学**习“错误处理”和调试**

+   怎么做：故意在工作流中制造一个错误（比如输错一个 API 密钥），然后观察 n8n 是如何报告这个错误的。学习如何使用“调试模式”来查看每个节点接收和输出的详细数据。

+   为什么：自动化流程难免会出错。一个健壮的工作流必须能优雅地处理异常，而不是默默失败。学会调试是你从新手走向进阶的必经之路。

1.  🧗 保**持耐心，从简单到复杂**

+   怎么做：不要试图第一个工作流就构建一个“全公司数据中台”。从自动化一个你日常工作中重复、枯燥的小任务开始（比如每日数据备份、信息聚合、消息通知）。

+   为什么：积累小成功会带来巨大的成就感，这是维持你学习热情的最佳燃料。复杂性是建立在熟练度之上的。
