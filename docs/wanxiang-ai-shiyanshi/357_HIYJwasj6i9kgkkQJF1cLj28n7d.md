前两天我**在朋友圈看到一**个创**业的朋友发吐槽："**用 NanoBanana Pro 生成的 PPT 虽然看起来很高级，但风格一眼就能看出是 AI 生成的，拿去给客户汇报总觉得不够专业。"他说上次用这个 PPT 给投资人路演，对方第一句话就是"你们这个是 AI 生成的吧？"气氛一下子就尴尬了。配图是他生成的一份商业计划书，说实话，我确实一眼就看出来了——那种 特定插画风格 、 偶然看不清的小字 点缀的版式，确实有很强的 AI 生成感。虽然比起传统 PPT 模板美观多了，但你很难说这是为某个特定品牌、某个特定场景量身定制的作品。

![](img/f1400381850013d7e894ad2ccf4caf9e.png)

说实话，**我自己也有**过类似的失望时刻。上个月我想用 AI 工作流给一个活动设计海报，我在提示词里写得很详细：主题是"科技与人文"，风格要温暖、有亲和力，目标受众是 30-45 岁的知识工作者，上传了我们的 logo 和设计参考。结果 AI 给我生成的海报，看起来确实很"高大上"——特定插画风格、未来感字体，但问题是，这个风格完全不是符合我们 品牌规范 的设计；

**这**让我想起了一个更深层的问题： 为什么 AI 明明见过成千上万的优秀设计案例，却总是生成这种"实习生水平"的作品？如何让 AI 生成符合我企业设计规范的设计？

你可能会说，AI 已经很厉害了，能根据描述生成图像、写代码、做设计，这已经是巨大的进步。但问题恰恰在这里——AI 确实学会了"做设计"这个动作，但它没学会"做专业设计"这件事。就像一个刚入行的实习生，知道界面要有按钮、要有导航栏、要用点颜色，但不知道这个按钮应该用企业的品牌色、这个导航栏要符合无障碍访问标准、这些间距要遵循 8px 网格系统。

AI 缺的不是"设计能力"，而是"设计规范"。

传统的解决方式是什么？给 AI 一个超级详细的提示词，把所有规范都写进去：用什么颜色、什么字体、什么间距、什么组件……但问题来了，这样的提示词可能要几千字，不仅写起来累，还会消耗大量的 token（AI 处理信息的"计价单位"），而且每次对话都得重新输入一遍。更要命的是，当团队的设计规范更新了，你得把所有用过这个提示词的地方都改一遍。

这就像每次做菜都要从头背一遍菜谱，费力又低效。

但一个最朴素的好奇心驱使我去研究了一下：像 Anthropic 这样的顶尖 AI 公司，他们的员工可不傻，不可能满足于让 AI 一直停留在"实习生水平"。那他们在想什么办法呢？

2025 年 10 月，Anthropic（也就是** Claude** 的开发商）给出了答案： Skills 。

说实话，当我第一次听到这个名字时，心里还有点疑惑——"Skills"听起来像是个很宽泛的概念，难道只是给 AI 增加几个新功能？但研究过技术文档和实际案例后，我发现这个技术的野心比我想象的大得多。

**Skills 不是在教 AI"做设计"，**而是在教 AI"像专业设计师一样思考"。

它的核心思路是：把专业设计师的经验、流程、规范封装成一个个可复用的"技能包"，让 AI 从"通用助手"秒变"行业专家"。就像你给一个新员工发了一本详细的操作手册，里面不仅有具体步骤，还有为什么要这样做、遇到特殊情况怎么处理、公司的标准是什么……这样他就不用每次都问你，也不会犯那些新手常犯的低级错误。

更重要的是，这个"技能包"可以随时更新、随时分享、随时调用，而且几乎不增加 AI 的负担——技术上叫"渐进式加载"，我后面会详细跟你解释这是怎么做到的。

从我看到的数据和案例来看，Skills 的效果确实有点震撼。比如 AWS 的开发团队在他们的 Kiro IDE 中使用 Skills 技术后，AI 对企业组件库的利用率从 0% 直接飙升到 80-90% ，开发时间从数小时缩短到数分钟。

这些数字背后的意义是什么？ AI 终于开始理解"专业"二字了。

![](img/020d8560e48b01850174b1047926595a.png)

今天这篇文章，我会尽量用通俗的语言，和你分享一下我对 Skills 技术的理解和感受。我会从三个层次展开：

+   第一，Skills 到底是什么？它的技术原理是怎样的？为什么能做到既强大又高效？

+   第二，这个技术背后藏着什么产品哲学？它和传统的 Prompt、和最近很火的 MCP 协议有什么本质区别？

+   第三，Skills 会如何改变设计行业？设计师的角色会发生什么变化？我们能抓住什么机会？

在回答这些问题之前，我想先从最基础的地方开始——Skills 到底是个什么东西。

# Skills 到底是什么？一个"技能包"如何让 AI 变专业

先给不太了解技术细节的朋友稍微解释一下，Skills 不是某个设计工具的新功能，而是 Anthropic（Claude 的开发商）在 2025 年 10 月推出的一项底层技术—— 它本质上是一种把专业知识、流程、规范封装成"技能包"的方法 。

你可以把 Skills 理解成给 AI 配备的"操作手册合集"。就像你入职一家新公司，HR 会给你一堆文档：员工手册、设计规范、品牌指南、组件库说明……这些文档告诉你"我们公司怎么做事"。传统的做法是，每次你要让 AI 帮你做设计，都得把这些规范重新复制粘贴一遍，告诉它"记住，我们的主色是 #3B82F6 ，字体用 Inter，按钮圆角 8px……"

**但 Skills 的逻辑完全不同。 它把这些规范做成一个个**独立的"技能包"，AI 只需要安装一次，以后每次对话都会自动遵循这些规范。 就像你把驾驶技能学会了，以后开车就不用每次都从头学方向盘怎么转、油门怎么踩。

更厉害的是，Skills 用了一个特别聪明的技术架构，让这个过程既高效又省资源。

三层架构：AI 的"渐进式学习法"

这里要稍微讲点技术原理，但我尽量用人话说。

AI 处理信息是要花钱的，专业术语叫"消耗 token"。你可以把 token 理解成 AI 的"计价单位"，就像去菜市场买菜，有的按斤卖、有的按个卖。传统的方式是什么？你每次对话都要把所有设计规范、组件库说明全部输入一遍，可能要消耗上万个 token。

Skills 的解决方案是：三层渐进式加载。

想象一下你整理衣柜的过程：

**第一层：标签 **（元数据） 你给每个收纳盒贴上标签——"冬季外套"、"运动装"、"正装"。这些标签只占很小的空间，但能让你快速知道每个盒子里装的是什么。Skills 的第一层也是这样，AI 启动时会加载所有 Skills 的"标签"（名称和简短描述），每个 Skill 只消耗大约 100 个 token。这样即使你装了 50 个 Skills，也只用 5000 个 token，几乎可以忽略不计。

**第二层：操作指南 **（指令文档） 当你需要穿正装时，才会打开"正装"那个盒子，看看里面有哪些衣服、怎么搭配。Skills 的第二层也是这样，只**有当 AI 需要使用某个 S**kill 时，才会加载详细的操作指南，这部分通常不超过 5000 个 token。关键是， 用到才加载，不用就不占资源 。

**第三层：详细资料 **（脚本和模板） 如果你要参加特别正式的场合，可能还要翻出搭配手册、参考图片、护理说明。Skills 的第三层也是这样，包含可执行的代码、详细的模板、参考文档，只在真正引用时才加载。

![](img/30afdbabf915792c966e82f3d983300a.png)

这三层架构带来的效果是什么？ **传**统方式可能要消耗 10,000+ 个 token，Skills 只需要 500 个 token，效率提升了 95%。 而且你可以给 AI 安装几十个 Skills，几乎不影响性能。

**从"通用模板"到"专业定制"**

说了这么多技术细节，你可能会想：这跟我前面说的"AI 生成的设计太模板化"有什么关系？

关系大了。

传统的 AI 设计工具，本质上是在一个"通用大脑"里做设计。它见过成千上万的设计案例，但这些案例都是混在一起的——科技公司的蓝色系、时尚品牌的粉色系、金融机构的深色系……AI 会从这些案例里提取"共性特征"，生成一个"大多数情况下看起来还不错"的设计。这就是为什么你总觉得 AI 生成的东西"似曾相识"—— 因为它确实是从无数案例中提取出来的"平均值" 。

![](img/be856f7539778c5dde1a089a99d8e99a.png)

但 Skills 的逻辑完全不同。 它是在给 AI 安装"专业大脑"。 当你为 AI 配备了"某公司设计规范 Skill"后，它就不再是一个"什么都懂一点"的通用助手，而是变成了"深度理解这家公司设计语言"的专业设计师。

举个具体例子。假设你是一家金融科技公司的设计师，公司有一套严格的设计规范：

+   主色是深蓝色 #1E3A8A ，不是那种互联网公司常用的亮蓝色

+   字体必须用 Arial，因为要考虑国际化和无障碍访问

+   按钮圆角是 4px，不是现在流行的 12px 大圆角

你把这些规范封装成一个 Skill，以后每次让 AI 帮你做设计，它就会自动遵循这些要求。生成的界面不再是"通用的科技感"，而是"你们公司的专业调性"。 从"流水线产品"变成"量身定制"，差别就在这里。

更重要的是，当公司的设计规范更新了（比如主色从深蓝改成墨绿），你只需要更新这一个 Skill 文件，所有使用这个 Skill 的 AI 对话都会自动应用新规范。不用再一个个去改提示词，也不用担心遗漏。

![](img/2048548f4af2175aa7cc04aa410dc5f3.png)

这就是 Skills 的核心价值： 让 AI 从"见多识广的通才"变成"深耕某个领域的专家"。 而这个转变，对设计行业的影响可能比我们想象的要深远得多。

# 技术背后的产品哲学——AI 如何"学习"专业知识

**说完了 Skills 是什么、怎么**工作的，我想聊聊更深层的东西： 这个技术背后藏着什么样的产品哲学？它和我们之前用的那些方法有什么本质区别？

一个震撼的真实案例：设计组件库利用率从 0% 到 90%

在深入讨论之前，我想先分享一个让我"整个人有点愣住"的案例。

AWS 的开发团队在他们的 Kiro IDE（一个面向企业的 AI 开发环境）中使用了 Skills 技术。他们遇到的问题是这样的：公司有一套完整的组件库，包含几十个精心设计的 UI 组件——按钮、表单、卡片、导航栏等等。这些组件都经过严格测试，符合无障碍访问标准，也符合公司的品牌规范。

但问题来了，当开发者让 AI 帮忙生成**界面代码时，AI 基本不会**用这些组件。 组件库的利用率接近 0% 。AI 生成的都是最基础的 HTML 标签和 CSS 样式—— <div> 、 <button> 、 padding: 16px ……看起来能用，但完全没有遵循公司的设计系统。

![](img/d478267100c5e6a6cdbcc2d54fb410a4.png)

这就像你公司花大价钱请设计师做了一套精美的 PPT 模板，结果新来的同事完全不用，每次都从空白页面开始做，字体、配色、版式全是自己随便搞的。

传统的解决方式是什么？在每次对话里告诉 AI："记住，我们有这些组件，你要优先使用它们。"但这种方式效果很差，因为 AI 需要理解每个组件的用途、参数、使用场景，这些信息加起来可能有几万字，全部塞进提示词里根本不现实。

**AWS 团队用 Skills 技术做了什么？他们把**每个组件封装成一个独立的 Skill。 每个 Skill 里包含：

+   这个组件是干什么的（比如"企业级表单输入组件"）

+   什么场景下应该用它（比如"需要用户输入文本信息时"）

+   怎么调用它（具体的代码示例和参数说明）

+   设计规范（圆角、间距、颜色等）

结果呢？ 组件**库利用率从 0% 飙升到 80**-90% 。这是什么概念？相当于一个从来不看公司规范的实习生，突然变成了严格遵循标准的资深员工。AI 生成的代码不再是基础的 HTML/CSS，而是直接调用企业的标准组件。更关键的是， 开发时间从数小时缩短到数分钟 。

说实话，当我看到这个数据时，第一时间对"醍醐灌顶"这个词有了画面感。这不仅仅是效率提升，而是 AI 终于开始理解"什么是专业标准"了。

Skills vs 传统 Prompt：从"重复劳动"到"持久能力"

这个案例让我开始思考一个更本质的问题： Skills 和传统的"写详细提示词"到底有什么区别？

表面上看，两者都是在告诉 AI"应该怎么做"。但深层逻辑完全不同。

传统 Prompt 是什么？ **它是一次性的、消耗性的指令。 **就像你每天早上都要跟实习生说一遍"记得用公司抬头的信纸、落款写总经理办公室、字体用宋体小四号"。每次都要说，每次都要消耗时间和精力，而且你一旦忘了说某个细节，他就会出错。

Skills 是什么？ **它是持久化的、可复用的能力。 **就像你把这些要求写进《员工手册》，新员工入职时看一遍，以后就自动遵循。你更新手册，所有人都同步更新；你离职了，手册还在，新来的经理也能继续用。

具体到技术层面，区别更明显：

| **维度** | **传统 Prompt** | **Skills** |
| --- | --- | --- |
| **持久性** | 每次对话需重复输入 | 安装一次，持续生效 |
| **Token 成本** | 10,000+ tokens/次 | 500 tokens/次 |
| **维护成本** | 规范更新需改多处 | 更新一个文件即可 |
| **团队协作** | 难以共享和版本管理 | 团队共享 |
| **能力扩展** | 添加新规范需重写 | 新增 Skill 自动发现 |

**但更重要的差异在产品哲学层面。 传**统 Prompt 是在"控制" AI，Skills 是在"教育" AI。

你用 Prompt 时，本质上是在每次对话里"遥控" AI："往左转、减速、加油门、注意前面有坑……"你必须时刻盯着，生怕它出错。

你用 Skills 时，是在给 AI"驾校培训"："这是方向盘、这是刹车、遇到红灯要停、看到行人要让……"培训完之后，它就可以相对独立地驾驶，你只需要告诉它目的地。

![](img/74dc363808a5f1e6c59eb994c4a88942.png)

Skills vs MCP：内部流程 vs 外部工具

聊完 Skills 和传统 Prompt 的区别，我还想对比一下最近很火的 MCP（Model Context Protocol，模型上下文协议）。因为很多人会把这两个技术混淆，觉得它们是竞争关系。

说**实话，当我第一次看到 Skil**ls 和 MCP 的介绍时，也有点搞不清楚："这俩到底有啥区别？"但研究下来发现， 它们解决的根本不是同一类问题 。

MCP 是什么？它是一个标准化的接口协议， 让 AI 能够连接和调用外部工具、数据源、API 。比如你想让 AI 帮你查 GitHub 上的代码、读取数据库里的数据、调用天气 API……这些都需要通过 MCP 来实现。它的核心是"去做"——连接外部世界，获取实时信息，执行具体操作。

**Skills 是什么**？它是一套内部的指令和流程， 教 AI"如何做" 。比如你想让 AI 生成符合公司规范的文档、遵循特定的设计原则、按照既定的 SOP 执行任务……这些都是通过 Skills 来实现。它的核心是"怎么做"——封装专业知识，规范工作流程。

**打个比方 **：MCP 是给 AI 装上"USB 接口"，让它能连接鼠标、键盘、U 盘、打印机；Skills 是给 AI 写"操作手册"，告诉它鼠标应该怎么用、键盘有哪些快捷键、打印文档的标准流程是什么。

所以它们不是竞争关系，而是互补关系。一个面向外部世界，一个面向内部能力；一个解决"能做什么"，一个解决"怎么做好"。

![](img/a6ff1b2f36d6a3514338a5ccd0c430ce.png)

说**到这儿，我**想起 Anthropic 官方在 2025 年 11 月发布的一篇博客，专门讲他们为什么要做 frontend-design Skill 。他们发现了一个很有意思的现象，叫做" 分布收敛 "。

什么意思？ **就像你**去餐厅点菜，如果不知道自己想吃什么，服务员推荐的永远是"招牌菜"——因为这是最安全的选择，不会出错，但也不会让你惊喜。AI 也一样，没有明确指导时，它就会选择"最安全的设计"——Inter 字体、紫色渐变、白色背景，因为这些在训练数据里出现频率最高。

![](img/d9c19da8acbc4b55970a0f8b80a06295.png)

所以当你让 AI 构建一个网页而不给任何指导时，它几乎总是会生成 Inter 字体、紫色渐变、白色背景、最少的动画。这不是 AI 偷懒，而是它基于统计规律在做"最保险"的选择。

**这就是为什么所有 AI 生成的设计都有"AI **味"——因为它们确实来自同一个统计中心。

Anthropic 的解决方案就是 frontend-design Skill，专门从四个维度打破这个"通用陷阱"：字体排版（推荐 JetBrains Mono、Playfair Display 等有特色的字体）、动画效果（添加微交互和过渡动画）、背景处理（使用大气背景和纹理）、主题风格（提供多种预设主题）。

**A**I 真正变得"专业"，不是因为它能调用更多工具，而是因为它学会了如何打破统计平均值，做出有特色的专业设计。 这就是 Skills 技术最核心的产品哲学。

# 设计师的角色正在改变——从工具使用者到流程架构师

**说了这么多技术和产品哲学，回到最**开始的问题： Skills 会如何改变设计行业？作为设计师，我们应该如何应对这个变化？

2026 年：Skills 元年

在回答这个问题之前，我想先聊聊一个重要的时间节点。

**202**5 年 10 月，Anthropic 正式推出 Skills；两个月后，Figma、Notion、Canva、Cloudflare 等巨头宣布合作；又过了一个月，Google 也加入战局。短短三个月，Skills 从一家公司的技术创新变成了行业标准。

这意味着什么？ Skills 不再是某一家公司的专有技术，而是正在成为行业标准。 就像当年的 USB 接口、蓝牙协议一样，当多个巨头都开始采用同一个标准时，这个标准就会快速普及，并且深刻改变整个行业的玩法。

所以有人说， 2026 年是 Skills 元年 。这不是夸张的营销话术，而是对一个技术拐点的准确判断。

![](img/3e90ebbc82951ef3da428e884b2752b7.png)

设计规范的数字化转型：从文档到可执行代码

那这个拐点会带来什么变化？我认为最直接的影响是： 设计规范正在从"参考文档"变成"可执行代码"。

你想想传统的设计规范是什么样的？一份几十页的 PDF 文档，里面写着"主色是 #3B82F6 "、"标题用 32px"、"卡片间距 16px"……设计师看完这份文档，然后在设计工具里手动实现。如果规范更新了，需要重新通知所有设计师，希望他们下次记得用新的标准。

但 Skills 把设计规范变成了什么？ 变成了 AI 可以直接理解和执行的"代码"。 你把规范封装成一个 Skill，AI 就会自动遵循；规范更新了，AI 立即同步。设计规范从"软约束"变成了"硬标准"。

这个转变看似技术性的，但背后的意义很深远。 它意味着设计规范不再是"知识"，而是"能力"。 知识需要人来学习、理解、记忆、执行；能力可以被封装、复用、传递、升级。

更重要的是，这让设计系统（Design System）真正"活"了起来。以前的设计系统是一堆静态的文档和组件库，需要设计师主动去查阅、去调用。现在的设计系统可以通过 Skills 主动参与到设计过程中——AI 知道什么时候应该用哪个组件、什么场景下应该遵循什么规范、遇到特殊情况应该如何处理。

设计系统从"参考书"变成了"智能助手"。

**设计师的新竞争力：知识工具化**

说到这儿，你可能会有点担心：AI 越来越专业，设计师的价值在哪里？

说实话，这个问题我也想过很久。但看完 Skills 的技术逻辑和实际应用后，我的看法是： 设计师的核心竞争力正在发生转移——从"执行设计"转向"封装经验"。

什么意思？

传统的设计师能力模型是什么？你要会用 Figma、懂配色理论、熟悉版式规范、能快速出图……这些都是"执行层"的能力。你的价值体现在"我能做出好看的设计"。

但在 Skills 时代， **更稀缺的能力是：你能不能把自己的设计经验、审美判断、**行业洞察封装成可复用的 Skills？ 这是一种"元能力"——不是做设计，而是"教 AI 怎么做设计"。

举个例子。一个资深的金融行业 UI 设计师，他做过几十个金融产品的界面，积累了大量经验：

+   金融产品的界面要传递"安全感"和"专业性"，所以配色要稳重

+   数据展示要清晰，不能用花哨的可视化

+   关键操作要有二次确认，防止用户误操作

这些经验都在他脑子里，是隐性知识。但如果他能把这些经验结构化地封装成一个"金融 UI 设计 Skill"，那他的价值就从"我能做好金融产品设计"提升到了"我能让 AI 做好金融产品设计"。

前**者**的价值是线性的——你一天能做多少工作，就创造多少价值。

后者的价值是指数级的——这个 Skill 可以被团队的所有人使用，可以被用在所有项目中，可以持续迭代升级。 一个人一天能做 2 个设计，但一个 Skill 可以让 10 个人同时提效，相当于你的能力被放大了 10 倍。

你的经验不再只是个人资产，而是变成了团队的能力放大器。 这种"知识工具化"的能力，会成为未来设计师最重要的竞争力之一。

![](img/a21df0d9ac0e7eda190d5d3df250c134.png)

当 AI 比你更懂规范时，你的价值在哪里？

但这也带来一个更深层的问题： **当** AI 通过 Skills 真的掌握了所有设计规范、流程、最佳实践，甚至比大多数设计师还要"专业"时，设计师的不可替代性在哪里？

我想起《哈佛商业评论》的一项研究，斯坦福团队发表了一篇文章，题目叫《别让生成式 AI 限制你的创造力》。里面有一个很有意思的发现：许多用户和团队在使用 ChatGPT 时，只是简单接受了第一个建议就停止了探索。AI 给了一个方案，用户觉得"还不错"，就直接用了，没有进一步思考"还有没有更好的可能性"。

这个现象在设计领域可能会更明显。当 AI 生成的设计"看起来已经很专业"时，设计师很容易失去追求"更好"的动力。

比如你让 AI 设计一个登录页面，它给了一个"看起来很专业"的方案——居中布局、品牌色按钮、清晰的表单。你觉得"还不错"就直接用了。但如果你再多想一步，可能会发现：这个页面可以加一个"忘记密码"的快捷入口、可以用插画增强品牌记忆点、可以优化移动端的输入体验…… AI 给的是"及格线"，但你的价值在于突破到"优秀线"。

但真正顶尖的设计师，他们的价值从来不在于"遵循规范"，而在于"打破规范"——在合适的时候。

举个例子。苹果的设计为什么被认为是行业标杆？不是因为他们严格遵循了某套设计规范，而是因为他们知道什么时候应该遵循规范、什么时候应该打破规范。iPhone 的设计打破了当时手机行业的很多"规范"——没有实体键盘、没有手写笔、屏幕占比极大……但正是这些"打破"创造了新的标准。

AI 可以学会遵循规范，但很难学会何时打破规范。 这需要对用户的深度理解、对行业趋势的敏锐洞察、对设计本质的哲学思考。这些"跨越规则"的创造力，才是人类设计师最宝贵的价值。

所以我的答案是： **当 AI 越来越专业时，设计师不应该在"专业性"上和 AI** 竞争，而应该在"创造性"上拉开差距。 让 AI 负责执行层的专业工作，让自己专注于创意层的突破性思考。

**我们能抓住什么机会？**

说了这么多，落到实际行动上，我们能抓住什么机会？

我觉得有三个方向特别值得关注：

第一，学会创建和管理 Skills。

这听起来有点技术化，但其实门槛没那么高。创建一个 Skill，本质上就是把你的经验结构化地写下来——什么场景下应该怎么做、为什么这样做、有哪些注意事项……用 Markdown 格式组织成文档就行。

你可以从最简单的开始——比如把你最常用的 3 条设计原则写下来："什么场景下用什么""为什么这样做""有哪些注意事项"。然后去 GitHub 搜索 ui-ux-pro-max，看看别人是怎么组织 Skill 文档的，照着格式改一改，你的第一个 Skill 就完成了。

如果你是设计师，可以把自己最擅长的领域（比如 B 端产品设计、品牌视觉设计、动效设计）的经验封装成 Skill。

社区里已经有很多成功案例了。比如有位拥有 8 年产品设计经验的设计师，把自己的设计原则、决策流程、最佳实践封装成了一个 Skill，专注于功能性强、数据密集的界面设计，特别适合 B 端产品、数据看板、企业应用。

更厉害的是社区爆款 ui-ux-pro-max Skill ，在 GitHub 上有 16.8k 星标。它提供了一个"设计智能数据库"——57 种 UI 风格、95 种配色方案、56 种字体组合、24 种图表类型、98 条 UX 指南，全部可搜索、可调用。这个 Skill 让 AI 从"不知道有哪些设计选择"变成了"知道什么场景用什么设计"。

**这不仅能提升你的个人效率，还能提升**你的影响力。 未来的设计圈，可能会像程序员圈一样，出现"Skill 开发者"这个新角色 ——他们专门研究如何把行业知识封装成高质量的 Skills，然后分享或售卖给其他人。

**第二，重新定义自己的工作流。**

Skills 的出现，意味着很多重复性的、规范性的设计工作可以被 AI 高效完成。你需要重新审视自己的工作流：哪些环节可以交给 AI？哪些环节必须自己亲自把关？

比如，初稿设计、多轮迭代、规范检查这些可以交给配置了 Skills 的 AI；但创意构思、用户洞察、设计策略这些核心环节，还是需要你的深度参与。

说实话，当我看到一个真实案例时，整个人有点愣住。有个开发者用 Cursor 配合 frontend-design Skill， 5 分钟就完成了一个完整的塔罗牌 H5 应用 ——包含 5 个页面（首页、每日抽牌、牌阵占卜、塔罗百科、占卜历史）、过渡动画、背景效果、响应式布局。这在传统开发流程里，一个熟练的前端工程师至少需要 4-6 小时，如果算上设计师出图、前后端联调，可能要一整天。整体效果完全是成熟前端工程师的水准。

这个案例的关键不是"AI 能做设计"，而是"配备了专业 Skill 的 AI 能做专业设计"。 把时间从执行层解放出来，投入到思考层。 这是 AI 时代设计师最重要的工作方式转变。

**第三，建立你的"能力护城河"。**

什么是能力护城河？就是那些 AI 短期内很难学会的能力。比如：

+   **对特定行业的深度理解 **（比如医疗、教育、金融）——比如你是做医疗产品设计的，可以多花时间去医院观察医生和患者的真实使用场景，这些一手洞察是 AI 学不来的

+   **跨学科的知识整合 **（设计+心理学+商业+技术）——比如学点认知心理学，理解用户的注意力机制和决策模式，这能让你的设计更有说服力

+   **对文化和审美的敏锐感知**

+   **与客户、用户的沟通协作能力**

这些能力不容易被封装成 Skills，也不容易被 AI 快速掌握。 投资这些能力，你就能在 AI 浪潮中保持不可替代性。

回到开头朋友圈那条吐槽： NanoBanana Pro 生成的 PPT"一眼 AI"，拿去给客户汇报不够专业。

现在你应该明白了，这个问题的本质不是 AI 能力不够，而是 AI 缺乏"你的专业知识"。如果你能把自己的行业经验、设计标准、品牌调性封装成一个 Skill，AI 生成的内容就不再是"通用模板"，而是"量身定制"的专业作品。

Skills 技术的出现，让"AI 味"从技术问题变成了选择问题。 你可以选择继续用通用的 AI，生成千篇一律的设计；也可以选择用 Skills 武装的专业 AI，生成真正符合你需求的作品。

![](img/672d04f1a7ec832871d8371a79aa6f43.png)

Skills 技术的出现，正在重新定义设计师的价值：从"会做设计"到"会教 AI 做设计"，从"执行者"到"架构师"。这不是让设计师焦虑的理由，而是摆脱重复劳动、专注于创造性工作的绝佳机会。

2026 年是 Skills 元年，也可能是设计行业新时代的起点。你准备好了吗？
