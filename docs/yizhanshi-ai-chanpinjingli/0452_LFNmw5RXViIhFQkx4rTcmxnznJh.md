## 为什么我们需要微调模型呢？

在该小节中，我们将会介绍模型微调的基本内容以及与提示词工程的差异，希望能够给大家带来微调模型最基础的认识。

### 什么是微调模型

在了解怎么来微调模型之前，我们其实心里是不是都有一个疑问，为什么我们需要微调模型呢？模型是不是非得微调才能正常使用呢？

实际上，微调模型的目的其实就是将一个有一定语言能力的模型变成一个特定使用场景的模型，比如将只会词语接龙的模型`GPT-3`通过各种方式调整为我们熟知的`ChatGPT`，又比如说将强大且通用的`GPT-4`调整为专用于代码纠错的`GitHub Copilot`以及将用于常规诊断的模型`PCP`变成专业的心脏病查询的专家（`Cardiologist`）以及皮肤病的专家（`Dermatologist`）。

假如我们直接使用通用的模型来解答一些特制化的问题，那么我们很有可能得到一些没有什么意义的答案。而假如我们想要使得那些有基本语言能力的基座模型变成我们想要其成为的样子，那么微调必不可缺。

以下面这个例子，当我们问一个专业的医学问题的时候，一个没有经过微调的预训练模型可能无法给我们一些很好的回复（`Probably acne`——可能有问题）。但是当我们对模型加入了皮肤病（`Demoatology`）的数据进行微调后，模型会更有效的回答我们的专业问题（详细的回答了出现的问题）。因此，从这两者显著的差异也就能够看出微调的重要性。

另外，对于我们微调而言，很重要的一点就可以让其能够学会某些特定的内容。比如我们去年其实有很多的笑话就是问文心一言或者星火大模型等等这些国产的开源闭源大模型，有一个很大的问题就是它们经常会说自己是由`OpenAI`训练出来的模型。显然这些国产的开源大模型肯定不是`OpenAI`训练出来的，产生这个问题最主要的原因就是它们用了`OpenAI`模型生成的数据来训练他们自己的大模型。这个问题也常被称为是幻觉（`Hallucinations`）。

那为了解决这个认知问题，我们就需要对模型进行微调。具体做法就是加入很多关于问你是谁然后回答我是`XXX`大模型的数据集，从而让大模型在遇到类似问题的时候不会还继续回答我是`OpenAI`训练出来的，进而能够保持模型的一致性（`Consistent`）。

### 微调模型及提示词工程的对比

一般来说，假如我们希望对模型进行调整，我们有三种方式。一种就是我们通过调整自己输入给大模型的话来让其跟随我们的指令完成任务，这也被称为是提示词工程。还有一种就是我们说的微调，通过特有的领域标注的语料库来对任务进行微调，从而使其从模型参数层面上完全改变。最后还有一种就是`RAG`（检索增强搜索）的方式，来将语料库与微调或者提示词工程结合，使得模型在输出前先考虑一下语料库里相关的内容再进行输出。

那在这门课中也是对比了提示词工程的优劣之处。

`Prompting`（提示词工程）

+   **优点：**

+   **不需要数据来开始**：你可以直接用提示词来引导模型生成结果，而不需要提前准备或输入大量数据。

+   **前期成本较低**：设置提示词的成本较低，不需要进行复杂的训练过程。

+   **不需要技术知识**：只需要知道如何编写提示词即可，不需要深入的技术背景。

+   可以通过检索增强生成（`RAG`）连接数据：`RAG`技术可以帮助模型在生成过程中访问外部数据，增强回答的准确性。

+   **缺点：**

+   **可处理的数据较少**：提示词的作用有限，模型只能处理少量数据或简单的任务。

+   **容易遗忘数据**：提示词可能无法有效地保留上下文信息，导致模型忘记之前的信息。

+   可能产生幻觉（`Hallucinations`）：模型可能会生成与提示无关或错误的信息。

+   **`RAG`可能失败或获取错误数据**：检索增强生成的成功率依赖于数据质量和检索算法的准确性。

`Finetuning`（微调）

+   **优点：**

+   **几乎可以适应无限量的数据**：通过微调，模型可以学习并处理大量且复杂的数据。

+   **学习新信息**：微调让模型在特定领域中获得更深入的知识，适应特定任务。

+   **纠正错误信息**：通过微调，模型能够减少生成错误信息的概率，提高准确性。

+   **在使用较小模型时，后续成本更低**：微调后的小模型可以在生产环境中更高效地运行，降低长期成本。

+   **也可以使用`RAG`**：微调后的模型同样可以结合`RAG`技术来增强数据访问能力。

+   **缺点：**

+   **需要更多高质量的数据**：微调的效果依赖于大量且高质量的训练数据。

+   **前期计算成本较高**：微调需要大量的计算资源，特别是在训练过程中。

+   需要一些技术知识，尤其是数据处理：微调的过程涉及到机器学习和数据科学的技术，可能需要专业知识。

总的来说`提示工程（Prompting）`更适合一般的、简单的项目，如原型设计或侧项目，尤其在没有大量数据或技术资源的情况下。而微调（`Finetuning`）则适合特定领域的应用，如企业级、生产环境下的使用场景，尤其在处理大量数据或需要高精度的任务时更为有效。

### 为什么我们需要拥有自己的大语言模型

除此之外，假如我们想拥有自己的`LLM`，想让其为我们自己的某些特定的工作。比如说我一个常见的任务就是角色扮演任务，我希望其能够扮演嬛嬛或者八戒来与我进行对话，那这些可能对于面向于通常任务的大语言模型而言是比较难的事情，因为其内部没有太多的相关数据，而我们输入给大模型的数据又不能够太多。但是这对于微调而言是完成可能做到的，我们只需要准备好高质量并找到一个性能不错的开源大模型，比如`InternLM-20B`，即可开始微调。

在课程中也总结了在特定的任务下微调自己的大语言模型与未经过微调的基础模型（`Base Model`）或仅通过提示工程（`Prompt Engineering`）使用的模型相比之下的优势。具体对比如下：

+   **性能（Performance）**

+   阻止幻觉（Stop hallucinations）：通过微调，模型可以深入学习特定领域的数据，从而减少生成错误信息的可能性。这意味着在医疗、法律等高风险领域，微调模型可以大大提升决策的准确性。

+   提高一致性（Increase consistency）：微调后的模型能够更一致地输出符合预期的答案，特别是在处理重复性或结构化任务时，如财务报表生成或客户支持自动化。

+   减少不相关信息（Reduce unwanted info）：在需要简洁和精确的场景中，如生成产品描述或技术文档时，微调有助于模型减少生成多余的、无关的内容，提高内容质量。

+   **隐私（Privacy）**

+   内部部署或虚拟私有云（On-prem or VPC）：微调模型可以部署在内部服务器或虚拟私有云中，确保数据不离开组织的控制范围，适用于对数据敏感度要求极高的行业，如金融服务或政府机构。

+   防止数据泄露（Prevent leakage）：在高度监管的环境下，微调模型可以帮助组织避免数据外泄的风险，确保合规性，如在处理客户个人数据时严格遵循`GDPR`等法规。

+   无数据泄露（No breaches）：通过对模型和数据的严格控制，组织能够更好地保护其核心业务数据不被外界非法访问。

+   **成本（Cost）**

+   每次请求的成本更低（Lower cost per request）：随着模型的专用性提升，每次生成请求的计算成本也随之下降，适合大规模、频繁使用模型的企业，例如电商平台的产品推荐系统。

+   增加透明度（Increased transparency）：微调模型使得成本和性能更加透明，企业可以更好地控制和预测模型的运营费用，优化预算分配。

+   更大的控制权（Greater control）：微调赋予企业对模型的更多掌控权，能够根据需求调整模型的性能，如为特定客户群体提供定制化的体验。

+   可靠性（Reliability）

+   控制正常运行时间（Control uptime）：通过内部部署和微调，企业能够更灵活地管理模型的运行时间，确保关键服务的稳定性，如金融交易平台的实时数据分析。

+   降低延迟（Lower latency）：微调后的模型可以更好地适应本地环境，从而减少数据传输和处理的延迟，提升用户体验，特别是在实时应用中，如在线游戏或视频会议平台。

+   内容审核（Moderation）：微调模型可以根据企业的需求定制化内容审核标准，自动过滤或标记不符合政策的内容，这在社交媒体平台或在线社区管理中尤其重要。

总的来说，微调后的大语言模型在性能、隐私、成本和可靠性方面优于未微调的基础模型或仅靠提示工程的模型。微调能提高模型的准确性和一致性，保护数据隐私，降低运营成本，并增强模型的可靠性，适应高要求和定制化的场景。

## 我们什么时候需要对模型进行微调呢？

在该小节中，我们将从预训练模型出发，一步步的拓展到具体需要模型微调的场景，那就让我们开始学习吧！

### 预训练模型是什么

一般而言，模型微调的对象都是我们上一门课程所提到的预训练模型。那对于预训练模型的训练而言，其实基于大量的无标注的语料库以及最流行的`Transformers`的算法来训练模型做词语接龙的事情。从更深入的来说就是预测下一个词是什么，比如说我输入“我爱”，那模型会根据上下文和场景接”你“这个字。在预训练模型训练完后，我们得到的是一个有知识也懂一点点语法的模型。

这里我们所说的大量的无标注的语料库其实包括了很多内容，比如说我们平时阅读的书本，还有就是包括了互联网上所有的文本内容。可以说，假如没有这几十年来在互联网上留下的文本内容，就不可能有今天的大语言模型出现。

### 预训练模型存在的问题

但是对于预训练的模型而言，有几个问题是显而易见的。首先就是通常来说，由于预训练模型需要花费大量的算力资源，因此一般都是由较大的公司（比如说`OpenAI`和`Google`）进行训练而成。虽然`Meta`开源了`LLaMA`这样的预训练大语言模型，但是具体如何训练以及用了哪些数据、哪些方法来训练，这些其实都并没有进行开源。因此预训练模型的训练其实是一件非常困难的事情。

并且当我们真正的去使用预训练的大语言模型的时候，我们通常会发现一个很大的问题就是预训练大语言模型经常会答非所问。比如说我问墨西哥的首都在哪里（`"What is the capital of Mexico"`），那大语言模型的回复竟然是匈牙利的首都在哪里（`"What is the capital of Hungary"`）。这一看就毫无关系对吧，而这对于预训练模型而言是非常普遍的现象。这个问题其实困扰了学术界非常之久，直到2022年`OpenAI`推出了`ChatGPT`并发布了相关的论文后，人们才慢慢开始明白如何解决这个问题。

### 如何解决预训练模型输出的问题

其实产生这个问题的主要原因是我们训练的数据都是一些没有标注过的数据，因此什么样的回答都有可能会出现。比如大语言模型假如读取我们考试的试卷，这里面都是问题而没有正确答案和回复。当其学习到了这部分内容，看到了一个问题了以后，那默认下一个接的内容那就还是一个问题。因此假如我们希望能够解决这部分的问题，就一定要教会大语言模型“说人话”，只有这样才能真正的为我们所用。

因此，在经过预训练后，我们就应该通过一些标注好的数据来对模型进行微调。其实所谓标注好的数据就是一问一答的数据。对于预训练模型而言，其所需要的数据其实就长这样：

```
input: None
output: xxx,xxx,xxx.
```

其实就是我们没有限制我们输入的内容是什么，而是直接告诉我们你可以这样来进行输出。在这个情况下模型自然也就不懂得在我们问问题的时候给出正确的回复。而我们所谓的标注好的数据其实就是长得这样：

```
input: 请问你叫什么？
output: 我叫李剑锋。
```

对于微调所需要的数据而言，很显然我们添加了提问的这个过程，并且对应的`output`也是正确的内容，这其实也就是我们标注过的数据，也就是一个完整且准确的对话对。

对于微调模型而言，我们所需要的数据其实比起预训练而言是少得多的。在基座模型有了基本的语言能力之后，我们只需要再用上高质量的对话对就能够让大语言模型拥有很多的“说人话”的能力了。但是微调并没有改变大语言模型做词语接龙的本质，只不过其接龙得更像正常人说话罢了。

而微调的训练其实也分为很多类，其中就包括了全量微调（所有的参数都发生改变）、部分微调（某些层中的参数发生改变）以及参数高效微调（额外训练一个层加到原模型上）等等。当然参数量改变越大其需要的算力资源自然也就更多，因此我们也需要根据自己的软硬件情况酌情选择。

### 模型微调的作用

不知道大家有没有思考过，微调能够为我们做什么呢？在该课程中总结了两小点，首先最主要的其实就是行为的变化（比如说回复的语气，角色扮演），第二个就是知识的获取，就是专业知识。

那微调能够使模型的行为发生变化，主要体现在以下几个方面：

+   **学习更一致地响应**：通过微调，模型可以在处理类似输入时表现得更加一致。就比如我同样问“中国的首都在哪里”，模型会回答“中国的首都在北京”而非是回答“匈牙利的首都在哪里”。

+   **对某些任务更加的专注**：微调可以帮助模型更好地聚焦于特定任务，例如自动化内容审核从而保证输出是符合我们社会的风序良俗的，避免被坏人所利用。

+   **在某些能力上变得更强**：微调可以激发模型的潜力，使其在特定任务（如对话生成）中表现得更加出色。

微调还可以帮助模型获取和整合新的知识：

+   **增加对新概念的理解**：通过微调，模型可以学习并理解新的领域或概念，提升其知识广度。我们在训练的数据集上也未必一定要给其对话对，而是继续向预训练时候一样给予一些新的知识，从而让其进一步拓展学习一些新的知识。

+   **纠正旧的错误信息**：微调还能更新模型中的过时或错误的信息，提高其回答的准确性。比如国产模型修改模型认为自己的`OpenAI`训练出来的一样，就是给予很多正确的回复使其改变认知。

### 微调的任务及流程

那在微调任务中，明确任务目标和输入输出关系是成功的关键。微调任务主要分为两大类：提取任务和扩展任务。在提取任务中，模型接收输入文本，并生成较少的输出文本。这类任务通常涉及“阅读”能力，如关键词提取、主题分类、路由规划、代理任务（如计划、推理、自我批评、工具使用等）。这些任务旨在从复杂的输入中提取出关键信息，因此需要模型具备精确的理解和筛选能力。

相对地，扩展任务则是输入较少的文本并生成更多的输出内容，体现了模型的“写作”能力。此类任务包括对话生成、邮件撰写、代码编写等场景，要求模型不仅能够理解输入内容，还能扩展和发展出更丰富的输出。这种任务需要模型具备较强的创作和表达能力，能够在输出中融入更多的上下文信息和细节。

我们在微调前一定要明确自己的任务，因为假如不够清晰的任务很有可能让模型陷入混乱，不知道到底该输出很长还是很短。总之，微调任务的设计需要根据具体的应用需求进行合理分类和定义，确保任务的明确性和目标导向，从而使得模型在不同的任务类型中都能发挥出最佳效果。

假如我们要微调的话，我们的流程可以如下所示：

+   **识别任务**：首先，通过提示工程（`Prompt Engineering`）在大型语言模型（`LLM`）上识别出可能需要优化的任务。这一步骤的目标是确定哪些任务可能从微调中受益。

+   **评估任务表现**：接下来，观察大型语言模型在这些任务上的表现，找出模型表现还算可以（`~OK`）但还不够理想的任务。这些任务是微调的理想候选，因为它们有改进空间。

+   **选择一个任务**：在识别出多个潜在任务后，选择其中一个作为微调的目标任务。这一步骤的关键是专注于一个任务，确保微调的精确性和有效性。

+   **收集数据**：为了对选定的任务进行微调，需收集大约1000个输入和输出的数据对，这些数据的质量应明显优于模型当前的表现（即“比`~OK`更好”）。这些数据将用来指导模型的进一步训练。

+   **微调小型模型**：最后，使用这些高质量的数据对一个小型语言模型进行微调。通过这一步骤，模型将针对特定任务优化其性能，并在实际应用中表现出更高的准确性和有效性。

## Instruction Finetuning

大语言模型微调有很多种类型，但是其中很重要的是指令微调。指令微调是一种特殊的语言模型微调技术，旨在提高模型理解和执行特定指令的能力。其主要目标是训练模型理解并执行各种自然语言指令。这些指令可能包括任务描述、问题或命令。通过这种方式，模型学会了更好地理解人类意图并产生相应的输出。

我们所输入的提示词其实就是指令中的一种，因此其实就是强化模型听懂人话并输出合适内容的能力。一些具体的案例就包括了将原本的预训练大模型`GPT-3`调整为能够正常对话的`ChatGPT`。

那对于指令微调而言，其所需要的训练数据一般由"指令-响应"对组成。例如：

+   指令：`"总结以下段落的主要观点"`

+   响应：[相应的总结]



那由于互联网这么多年来的累计，我们其实可以从大量的渠道获取到这类的信息，比如在贴吧、知乎这种我们就能够得到一问多答得回复，又或者我们利用🛰️、🐧等聊天工具里得私聊一问一答，也能够得到大量得数据。

那即便我们找不到一些合适得数据，其实我们还有一种很合适的方法就是由AI来为我们生成数据。一般来说，由于是要模拟人类的语言来生成数据，因此我们都会选择最强的模型（GPT-4o或者Claude 3.5 Sonnet) 来进行生成。

那生成的方式也不难，其实就是给出一段需要何种类型对话的介绍，然后设计一个提示词的模板，传给模型，就可以让其为该场景生成数据了。然而需要注意的是，一般我们不会在大语言模型搭建的Web界面去获取数据，因为这样过于低效。我们一般都需要通过大语言模型公司提供的接口然后设计一套自动化采集的流程来实现数据的生产。

当然设计这样一个提示词模板并通过API接口让模型能够很好的理解你的意思也是一件不那么容易的事情，但是GitHub上其实有大量的开源项目帮助我们完成，因此我们也可以在借鉴前辈的基础上完成自己定制化的模型。

在经过指令微调后模型不仅可以执行它在微调数据集中明确学习的任务，还能将这种执行指令的能力泛化到新的、未见过的任务中。这种泛化能力使得模型在面对各种不同类型的指令时都能给出恰当的回应，大大提高了模型的实用性和灵活性。

微调这个任务总体分为三大步骤：

+   数据准备：将收集到的数据进行处理，使其能够符合模型微调训练的格式与大小。

+   训练：调整参数使得训练出来的模型效果更好。

+   评估：评测整体模型的能力，确保微调后的模型能够满足需求。

在后面的课程里也将深入的对这部分内容逐一讲解。

# Data Preparation

对于模型训练而言，高质量的数据是至关重要的。想象一下，如果我们用垃圾食品喂养一个孩子，他能健康成长吗？显然不能。同理，AI模型也需要"优质食材"来茁壮成长。那么，什么是AI的"优质食材"呢？

首先，是高质量的信息。就像我们追求食品的新鲜度一样，AI需要准确、可靠、有深度的信息。陈旧的数据、错误的知识，就像变质的食物，只会让AI"消化不良"。其次，多样性至关重要。想象一下，如果一个人从小到大只吃白米饭，营养会全面吗？显然不会。AI也一样，它需要"五谷杂粮"——多样化的主题、不同的观点、各种文化背景的数据，才能全面发展"智力"。

再者，真实性不可或缺。就像天然食材比人造食品更有营养，来自真实世界的数据比人工生成的数据更有价值。这些真实数据包含了语言的细微差别和现实世界的复杂性，能让AI更好地理解和适应我们的世界。最后，数量也很重要。就像人需要定量的食物摄入才能维持健康，AI也需要足够多的数据来学习和成长。数据量不足，就像营养不良，会限制AI的"体格发展"。相反，如果用"垃圾数据"喂养AI会怎样呢？低质量、单一、虚假或稀少的数据，就像垃圾食品，可能会导致AI"发育不良"。它可能会产生偏见，无法处理复杂任务，或在现实应用中表现糟糕。

在了解了什么样的数据是好的之后，我们就可以来看看我们具体如何来对这些数据进行处理。我们以做菜的案例来举例。假如我们要做一顿AI模型大餐，首先，我们需要收集原材料，也就是指令-响应对。想象一下，这就像是在菜市场精心挑选新鲜的蔬菜和肉类。每一对指令和响应都是独特的食材，它们包含了丰富的信息和知识。有些可能来自真实的人类对话，有些则可能是专家精心设计的问答集。这个步骤决定了我们"菜品"的基本风味，所以选择优质、多样的"食材"至关重要。

接下来，我们要把这些食材组合在一起，就像把各种配料放入锅中。这个步骤叫做连接对，有时还需要加入一些"调味料"——也就是提示模板。这就像是在烹饪时加入独特的香料，让整道菜的口感更加丰富。提示模板可以帮助AI模型更好地理解和处理信息，就像香料能让食物的味道更加突出一样。那在实际操作中就是除了`input`和`ouput`以外，还额外添加一个名为`template`的信息来告诉模型一些背景的知识，从而使其更好的进行理解。

第三步是最技术性的部分：分词、填充和截断。这个过程就像是把食材切成大小均匀的块，确保它们能被均匀烹调。在AI的世界里，这意味着将文本转化为模型可以理解的格式。有些句子可能需要"切短"（截断），而有些则需要"填充"以达到统一长度。这个步骤确保了我们的"数据大餐"每一口都恰到好处。

最后一步是将处理好的数据分成训练集和测试集。这就像是将做好的菜分成两份：一份用来品尝和调整口味（训练集），另一份用来给美食评论家最终评判（测试集）。训练集帮助模型学习和改进，而测试集则用来评估模型的表现，确保它不仅能应对见过的情况，还能处理新的挑战。

当我们完成这些步骤后我们就可以获取到直接能够用于训练的数据集了！

# Training Process

在准备好数据集后，我们就可以把数据集放到神经网络中进行训练了。那训练大语言模型其实和训练传统的神经网络区别不是很大，也就是添加训练数据集，并用`input`的问题来询问模型，并让模型来回答问题。然后我们就可以利用模型的回复与实际数据集中`output`的差距来计算出`Loss`的值。然后通过反向传播的方式更新参数。

我们也可以从代码的角度来看看这个过程

那对于大语言模型的训练参数而言，有几个重要的超参数需要重点考虑：

1.  学习率（Learning rate）： 学习率是最重要的超参数之一。它决定了每次参数更新的步长大小。如果学习率太大，模型可能会错过最优解；如果太小，训练可能会非常缓慢。选择合适的学习率对模型的收敛速度和最终性能至关重要。

1.  学习率调度器（Learning rate scheduler）： 这是一种动态调整学习率的机制。随着训练的进行，学习率调度器可以根据预设的规则或模型的表现来调整学习率。常见的策略包括:

+   步进式衰减：在特定的epoch后降低学习率

+   指数衰减：学习率按指数函数逐渐减小

+   余弦退火：学习率按余弦函数周期性变化

1.  优化器超参数（Optimizer hyperparameters）： 不同的优化算法（如`SGD`、`Adam`、`RMSprop`等）都有其特定的超参数。例如：

+   动量（`Momentum`）：用于`SGD`优化器，帮助加速收敛并减少振荡

+   `Beta1`和`Beta2`：用于`Adam`优化器，控制一阶矩估计和二阶矩估计的指数衰减率

+   `Weight decay`：一种正则化技术，用于防止过拟合

这些超参数的调整对模型的训练过程和最终性能有着重要影响。通常，研究人员会使用网格搜索、随机搜索或更高级的超参数优化算法（如贝叶斯优化）来寻找最佳的超参数组合。

在大语言模型（LLM）的训练中，由于模型规模庞大，计算资源需求高，超参数的选择变得更加关键。合适的超参数设置可以显著提高训练效率，缩短收敛时间，并最终提升模型性能。

此外，对于LLM的微调过程，这些超参数的选择可能需要根据具体任务和数据集进行调整，以达到最佳的迁移学习效果。因此，理解和掌握这些超参数的作用，对于成功训练和优化大语言模型至关重要。

# Evaluation & iteration

那在训练完成以后呢，我们其实就还需要对训练好的模型进行评估。最常见的评估方式其实就包括以下三种：

1.  人工评估（Human Evaluation）： 这是最可靠但也最耗时和昂贵的方法。人工评估通常涉及专家或训练有素的评估者对模型输出进行直接判断。评估者可能会根据各种标准（如准确性、流畅性、相关性等）对模型的回应进行评分。尽管这种方法可能存在主观性，但它能捕捉到机器难以量化的微妙之处，如语言的恰当性或创造性。

1.  测试套件（Test Suites）： 测试套件是预先设计的一系列测试用例，用于评估模型在各种任务和场景中的表现。这些测试通常包括：

+   高质量的测试数据，确保评估的准确性

+   涵盖广泛的场景，测试模型的泛化能力

+   包含模型在训练中未见过的数据，评估其处理新情况的能力

1.  测试套件可以自动化执行，提供客观、可重复的评估结果。然而，设计全面而有代表性的测试套件本身就是一项挑战，假如大语言模型在训练过程中就已经把题目放进去了，那它在该测试上的成绩肯定相对而言比较高。因此也经常会出现榜首的模型能力反而没有后面好的情况发生。

1.  Elo排名（Elo Rankings）： Elo排名系统最初用于国际象棋评级，现在被应用于AI模型的比较。我们经常听说的大语言模型斗兽场就是此类型。在这个系统中：

+   模型被视为"选手"，通过彼此之间的"对战"来确定排名

+   每次"对战"后，模型的排名会根据结果和对手的强度进行调整

+   这种方法允许对多个模型进行相对比较，而不需要绝对的评分标准

1.  Elo排名的优势在于它可以持续更新，随着新模型的加入自动调整排名。然而，它主要反映模型之间的相对表现，可能无法完全反映模型在特定任务上的绝对能力。

在实践中，这些方法通常被结合使用，以获得对模型性能的全面评估。研究人员和开发者需要根据具体需求和资源来选择合适的评估方法组合。

除此之外，与Test Suites类似，LLM Benchmarks也是评估大语言模型性能的综合测试套件。它包含多种评估方法，旨在全面衡量模型的各项能力。Test Suites和Benchmarks虽然都用于评估模型性能，但有着明显的区别。Test Suites通常是更为全面和细致的测试集合，针对特定模型或应用定制，包含大量测试用例以覆盖各种场景，用于持续验证模型功能和诊断具体问题。而Benchmarks则是高度标准化的评估框架，专注于代表性任务，提供简洁的综合分数，便于不同模型间的直接比较。Benchmarks通常是公开的、行业通用的，更新频率较低以保持一致性，而Test Suites可能是内部保密的，会随需求变化频繁更新。在实践中，两者常结合使用，以全面评估模型性能并进行有效比较。 Co

通过上面的各种测试，我们可能知道了模型大概的评分如何。但是测评本身不是目的，测评真正的目的是帮我们找到大语言模型中存在的问题，从而能够在后续的训练中进一步优化我们的模型。

那在分析问题的过程中，我们首先需要深入了解基础模型的行为特征是很重要的。这有助于判断问题是源于基础模型还是微调过程。假如是基础模型出现问题，那我们可能要回到微调前预训练的步骤先解决，再去考虑进行下一步的微调。

假如发现预训练模型没啥问题，那我们可能要考虑的就是是不是数据层面出了问题。比如说我们发现模型有时候可能会写错别字，那我们就需要看看是不是数据里面有很严重的拼写错误。又比如说可能输出过长以及内容重复，那我们也需要看看数据集中是否存在问题。然后我们解决这部分的问题后重新进行训练。

这种错误分析方法强调了系统性地识别和解决模型输出中的问题的重要性。通过仔细分析这些错误，研究人员和开发者可以更有针对性地改进模型，无论是通过调整训练数据、优化模型参数，还是改进后处理步骤。这个过程不仅有助于提高模型的整体性能，还能帮助我们更深入地理解模型的行为和局限性。

# 后续：一些在开始训练前的思考…

在实际项目中，微调的任务可能像以下的步骤这样展开：

1.  确定你的任务： 这一步需要你深入思考并明确定义模型要完成的具体任务。例如，如果你在开发一个问答系统，你需要决定它是开放域还是针对特定领域的。你要考虑输入会是什么样的，期望的输出格式如何，以及如何定义任务的成功标准。在这个阶段，仔细考虑任务的各种边界条件和可能遇到的特殊情况也很重要，这将帮助你在后续步骤中做出更好的决策。

1.  收集与任务相关的输入/输出数据： 一旦明确了任务，下一步就是收集相关的数据。这可能涉及多个来源，包括公开的数据集、公司内部的历史数据、专家标注的数据，甚至是通过用户交互收集的实时数据。关键是要确保你的数据集具有足够的多样性和代表性，能够覆盖任务可能遇到的各种情况。高质量、全面的数据集是成功训练模型的基础。

1.  如果数据不足，生成数据： 在很多情况下，现有的数据可能不足以训练出理想的模型。这时，你可以考虑多种方法来扩充数据集。数据增强技术如同义词替换或回译可以创造更多的变体。利用现有的大语言模型生成额外的样本也是一个选择。你还可以设计规则来自动生成数据，或者组织众包来创建更多的人工标注数据。无论采用哪种方法，都要注意保持生成数据的质量和真实性，确保它们能真正帮助提升模型性能。

1.  微调一个小型模型： 从一个相对小的模型开始是个明智的选择，比如参数在400M到1B范围内的模型。选择一个合适的预训练模型作为起点，然后决定使用全参数微调还是像LoRA这样的高效微调方法。设置合适的学习率、批次大小等超参数也很重要。在这个阶段，进行多次实验，比较不同设置下的效果，能帮助你更好地理解模型的行为和性能边界。

1.  调整提供给模型的数据量： 这一步涉及进行一系列的数据规模实验。你可以从一个小的数据集开始，然后逐步增加数据量，观察模型性能的变化。这将帮助你理解数据量和模型性能之间的关系，找到最佳的平衡点。同时，也要考虑数据质量和数量之间的权衡，有时少量高质量的数据可能比大量低质量的数据更有价值。

1.  评估你的LLM： 全面评估模型性能是crucial。使用各种评估指标，如准确率、F1分数、BLEU等，根据任务的性质选择合适的指标。对于生成任务，人工评估可能更为重要。深入分析模型在不同类型输入上的表现，进行详细的错误分析，找出常见问题和失败模式。这些洞察将指导你后续的优化工作。

1.  收集更多数据来改进： 基于评估结果，有针对性地扩充数据集。重点收集模型表现欠佳的案例，增加难例和边界条件的样本。考虑引入一些对抗样本来提高模型的鲁棒性。持续更新数据集以反映最新的使用场景也很重要，这能确保模型与实际应用保持同步。

1.  增加任务复杂度： 随着模型性能的提升，可以逐步提高任务的难度。这可能包括引入需要多步推理的问题，或者要求模型同时处理多个相关任务。你可以增加输入的长度或复杂性，要求更高质量或更详细的输出。加入一些约束条件或额外要求，如控制输出的风格，也是提高任务复杂度的好方法。

1.  增加模型大小以提升性能： 如果小模型的性能遇到瓶颈，可以考虑使用更大的模型。评估更大模型带来的性能提升，同时权衡增加的计算资源成本。可以探索模型压缩技术如知识蒸馏，或者考虑优化模型架构，比如使用混合专家模型。选择合适的模型大小需要平衡性能、效率和资源限制。

在整个过程中，保持迭代和实验的心态至关重要。每一步都可能需要多次尝试和调整。同时，要持续关注模型在实际应用中的表现，及时收集用户反馈，不断优化模型和整个系统。这是一个循环往复的过程，随着你对任务和模型的理解深入，你可能需要回到前面的步骤进行调整。通过这种系统化的方法，你可以逐步提升模型性能，最终达到预期的效果。

除此之外，在大语言模型的应用中，任务复杂性与模型规模的匹配至关重要。任务可以大致分为提取类和扩展类：提取类任务如关键词识别、主题分类等，通常只需要较小的模型；而扩展类任务如对话生成、代码编写等，则往往需要更大的模型来处理。这是因为扩展类任务需要生成更多的原创内容，对模型的能力要求更高。此外，任务的组合也会影响所需的模型规模。当模型需要同时处理多种任务或执行更通用、更灵活的操作时，通常需要更大的模型来支持。

那对于模型微调所需要的资源，在这门课程中也有提及。

另外随着技术的发展，越来越多更加轻量化微调的方式也被推出来。PEFT（Parameter-Efficient Finetuning）是一系列旨在高效调整大型语言模型的技术，包括加法方法、适配器、软提示、选择性调整和基于重参数化的方法。这些技术通过不同的方式（如增加少量参数、调整特定层或使用提示）来优化模型性能，同时最小化计算资源的使用。这些方法往往有重叠和交叉，反映了它们在实践中的灵活应用和持续创新，目标是在保持模型质量的同时提高微调过程的效率。

PEFT中，其中比较最出名的就是LoRA（Low-Rank Adaptation of LLMs）。LoRA是一种高效的大型语言模型微调技术，它通过在部分层中引入少量可训练的低秩矩阵来适应新任务，而不是调整全部模型参数。这种方法大大减少了可训练参数数量和GPU内存使用，同时保持了接近全参数微调的性能和相同的推理速度，使得模型能够快速、高效地适应各种新任务，而无需每次都调整所有参数。
