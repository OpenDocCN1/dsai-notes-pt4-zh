## 核心知识点复盘

### 产品发布的门槛与成本

+   **无需服务器的产品**：如纯前端工具、本地音视频处理。这类产品部署门槛低，成本几乎为零。

+   **需服务器的产品**：涉及云端备份、社交、数据库存储。用户量增加会直接导致服务器成本上升。

### 部署方案：GitHub + Vercel

+   **优势**：代码版本管理自动化、自动构建部署、对初学者免费且稳定。

+   **局限性**：Vercel 主要针对前端项目，后端或复杂全栈项目需额外配置。

### 标准化部署流程

1.  **环境准备**：注册 GitHub 与 Vercel 账号，安装 GitHub Desktop。

1.  **本地检查**：在上传前确保代码本地运行无误。

1.  **代码托管**：建立 GitHub 仓库并推送代码。

1.  **上线发布**：在 Vercel 中导入项目完成自动化部署。

## 学习心得

+   从“本地玩具”到“全球产品”的跨越： 以前代码只在自己的电脑上跑，通过本课掌握了 GitHub + Vercel 的链路后，任何灵感都可以在几分钟内变成全球可访问的链接。这种“交付感”是 Vibe Coding 闭环中最重要的环节。

+   **版本管理即“后悔药”**： 进阶作业要求发版 3 次，这让我深刻理解了 GitHub 的核心价值——不仅仅是存代码，而是记录产品的演进过程。发版记录（Releases）让每一次功能迭代都有迹可循，即便写出 Bug 也能快速回滚。

+   **AI 辅助 Debug 提效**： 在部署过程中遇到构建错误（Build Error）是常态。学会将 Vercel 的报错日志直接丢给 AI 分析，比自己盲目修改效率高出数倍。
